# Условия вложенной записи и владение XML-путями

## Исправления

- Условия канонической XML-формы common читают поля самого common,
  а не поля внешнего объекта. План сохраняет область условия; генератор
  обращается к существующей записи через заимствованный `RecordInput`.
  Повторный разбор XML/YAML и копия данных не требуются.
- Составной объект использует общий `xml_ownership::overlaps`, который
  различает атрибуты и элементы. Убран второй алгоритм проверки пересечений,
  ошибочно запрещавший атрибут контейнера рядом с вложенным элементом.
- Общий запускатель сгенерированного Rust вынесен в поддержку тестов.
  Матрица условий расширена в существующем тесте, отдельные однотипные
  тестовые функции не добавлены.

## Проверки

Прошли 103 проверки: связывание (85), условия записи (1, включая исполнение
сгенерированного Rust), входы строк (10), последовательности (7).
Архитектура Rust, отсутствие новых дублей и `git diff --check` проверены.

Большая проверка `generate_collection` раньше не доходила до исполнения:
сначала теряла область условия, затем ошибочно отвергала соседние XML-пути.
После исправлений обнаружены устаревшие части её проверочного кода:
поток событий без namespace-контекста и чтение YAML null как текста.
Обновлены интерфейс потока и сравнение null без ослабления проверок.
Ожидание сборки source-record дополнено пустым состоянием базовой ссылки:
XML не содержит ни ссылки, ни уведомления; `borrowed-base.yaml` задаёт
для этого `empty`, а `base-reference-state.yaml` — пустой YAML-скаляр.
Все 1536 сочетаний форматированного текста прошли: журнал
`/tmp/nkdk-record-condition-runtime-evidence.log` содержит `COMPOSITE 1536`.
Большой тест затем остановился на отдельной проверке валидации: `Entries: {}`
принимается, хотя старый договор и TS-проверка требуют текст либо признак
форматирования. Ожидание ошибки оставлено; полный `generate_collection`
не считается прошедшим. Следующий шаг — отдельно проверить взаимодействие
`present`, значения по умолчанию пустой коллекции и ограничения `text-or-flag`.
Нельзя исправлять это простым разрешением пустой записи в тесте.

## Границы

Это исправление общих механизмов, не приёмка нового полного владельца.
Флажок FormattedI8nText снят до восстановления проверки пустой записи.
DynamicList и FormAttribute остаются отдельными
задачами основного плана.


Дополнительно проверено отсутствие записи: условие common над её полями
не вызывается для отсутствующего значения. Обе стороны преобразования
отсутствующей записи проверены в той же матрице; конвертер не создаёт ошибку
`value.missing`. Условия от параметров и входов остаются независимыми.
Синтетический пример со скалярными полями и коллекцией теперь различает
обычный порядок из декларации и исходный другой порядок: для второго
проверяются автоматическая аномалия и восстановление XML. XML-фикстуры
не изменялись.


## Исправление обязательности текста

Причина локализована в декларации: отсутствующее поле text получало пустую
последовательность, поэтому present был истинным. Ограничение text-or-flag
теперь использует exists для проверки наличия перевода; общая семантика
present и обработчики Rust не менялись. Регрессия сначала воспроизведена
на focused formatted-1 (invalid YAML accepted: Заголовок: {}). После изменения
прошли все 9 formatted-records, включая отрицательные примеры {}, ложный
признак без текста и Текст: [], а также положительные примеры текста и
истинного признака без текста. Большая матрица проверяется отдельно.

Большая матрица после исправления декларации завершила исполнение всех
проверок, включая отклонение пустой записи. Следующий этап — Clippy — выявил
929 повторных предупреждений из небольшого числа шаблонов генерации.
Исправлены генерация неиспользуемых проверок коллекции, недостижимый код
чтения пометки, заимствование строки, вложенные условия QName и оформление
условий выражений. Для коллекции без ограничений лишняя функция больше
не создаётся. Предметные условия в Rust не добавлены. Самопроверка
универсальности выполнена; независимое ревью не проводилось.
