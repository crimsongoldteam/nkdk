# Живые запросы номеров колонок из YAML формы

Добавлена декларация rust/declarations/objects/form-public-column-requests.yaml.
Она читает обычный путь Реквизиты → имя → Колонки / ДополнительныеКолонки,
извлекает имена и запрашивает номера в существующем общем механизме.
Второй полный контекст формы и частный обработчик в Rust не создаются.
Прочие свойства игнорируются только при подготовке индекса; обычное
преобразование остаётся строгим. Порядок выбранных коллекций сохраняется.

## Проверенные случаи

- Обычный YAML с обоими видами колонок; контрольный снимок содержит только имена,
  порядок и вложенность, без типа и посторонних настроек.
- Запросы совместно с прежними идентичностями сохраняют номера 1 и 2.
- Новое имя не получает занятый номер: при прежних 1/2 и резерве 7 оно получает 3.
- Одни резервы 1/2/7 без прежних именованных идентичностей дают новые 3 и 4.
- Резервы другого владельца не влияют на текущую форму.
- Пустое имя таблицы получает позиционный адрес до построения именованного.
- Повторяющиеся имена таблиц используют существующий декларативный индекс
  порядка групп; обе группы и исходные id сохраняются общим !xml/raw.

Последний случай проверяется по адаптированному XML с готовыми сведениями о
номерах, а не по уже записанному YAML с !xml/raw. XML-фикстуры не изменены.
Сам общий механизм аномалий не содержит новых условий по объектам.

В декларации form-id-reservations добавлены условия наличия необязательных
полей: отсутствующее поле не является резервом. В ограниченном проверочном
каталоге из общего договора выбирается пространство номеров реквизитов,
поскольку прочие пространства требуют своих объявленных распределителей.
Их общие ограничения компилятора не ослаблялись.

## Проверка и границы

Пакет form-columns содержит 17 случаев, включая прежние 10. Выбранные 44
декларации прошли через тот же AOT-компилятор; общий компилятор и runtime
преобразования не менялись. Clippy выбранного проверочного исполнителя прошёл.
Для контрольных снимков добавлено snapshotYAML с существующим строгим
сравнением событий: оно сохраняет порядок, повторы, типы и теги. Старое
snapshotFields не ослаблено. Новых отдельных функций юнит-тестов не добавлено:
общая матрица связей расширена для дополнительных входов выражения.

Полный реквизит формы и основная команда пока не приняты. Источник запрашивает
номера только колонок; номера самих реквизитов подготавливаются отдельно.
Остаются подключение источника к настоящим файловым маршрутам и сохранённым
снимкам, чтение уже записанных аномалий повторных групп из YAML и совместная
приёмка всего владельца. Флажки полных объектов не изменены.


Продолжение: порядок групп из YAML и сохранённые повторы

Добавлен `form-public-group-modes.yaml`: обычная форма YAML даёт индекс
именованных или позиционных групп. Пустое имя и повторное имя выбирают
позиционный адрес существующим выражением `one`. Публичные запросы колонок
получают этот индекс как объявленную зависимость. Обычный экспорт, пустая
таблица и резервы проверены без XML-источника порядка.

Сохранённая аномалия повторной таблицы проверяется отдельным YAML-примером
`tests/migration/fixtures/form-repeated-table.yaml`; ожидаемый XML берётся
независимо из неизменённого `mixedColumns.xml` с явно повторённой группой.
Проверяется не только round-trip, но и точное значение `positional` в индексе.
Это выявило две общие ошибки: вложенный аварийный читатель повторно читал
неотобранные поля исходного YAML, а факты брались только из сокращённого
смысла, в котором осталась одна таблица.

Общий отбор теперь фильтрует `$значение` по объявленным полям, сохраняя `$xml`
и неизвестные ключи оболочки для строгой проверки. Повторный читатель при
ошибке YAML получает отобранный документ. Если поток содержит `!xml/raw`,
источник фактов восстанавливает XML и читает факты из него. Этот дополнительный
путь применяется только к сохранённой форме; обычное чтение остаётся потоковым.
Предметных веток для формы или колонки в Rust нет.

Запускатель проверяет снимки после подготовки зависимостей и поддерживает
независимые `expectedFacts`. Все 19 случаев и узкий Clippy прошли. Публичные
аномалии не означают, что завершены полный FormAttribute, номера реквизитов
или настоящее файловое преобразование формы с историей. Эти флажки не меняются.


Совместимость с историей: проверка настоящего сканирования резервов выявила
запрет любого условия у наблюдаемого атрибута. Теперь разрешено лишь отсутствие
условия либо проверка присутствия того же самого резервируемого поля. Это
условие истинно для найденного атрибута; условие от другого поля по-прежнему
запрещено и проверяется отрицательной матрицей. Файловая подготовка обычных,
базовых и исторических номеров снова проходит, без изменения XML-фикстур.

2026-10-07, совместная нумерация реквизитов и колонок

реквизитам запрашивает номер реквизита перед номерами его обычных и дополнительных
колонок. Используются прежние общий счётчик и составление адресов; новых
обработчиков в Rust нет. Прежний источник только колонок сохранён как отдельный
договор, а полная нумерация имеет собственный вход.

Проверены свежие номера 1/2/3, резервы, сохранённый номер реквизита 9,
несколько реквизитов (независимые адреса при общих номерах) и пустое имя
с позиционным адресом. Ожидания индексов заданы явно, включая соседний реквизит
и его колонку. Профиль `form-attribute-identity.yaml` проверяет старое свойство
id и регистрацию FormAttributes; массовый переносчик получает его рядом с
профилем колонки. Восстановление id отдельно проверено на ограниченной
проекции имени/id, с готовыми и историческими номерами и с отличающимся XML-id.

2026-10-07, повторные реквизиты из публичного YAML

Добавлен `form-public-attribute-modes.yaml`. Декларация имён использует прежнее
выражение `one`: единственное непустое имя даёт именованный адрес, пустое или
повторное — позиционный. Источник читает сохранённый `!xml/raw` тем же общим
механизмом восстановления XML, поэтому учитывает оба исходных реквизита,
даже когда в `$значение` осталась одна запись.

Публичные запросы колонок, совместных номеров и порядка дополнительных групп
получают этот индекс через объявленные входы. Один и тот же адрес применяется
к реквизиту, обычным колонкам и дополнительным группам; одинаковая таблица G
в двух повторных реквизитах получает разные области ключей.

Два новых YAML-примера проверяют обе позиции с независимыми ожидаемыми
номерами; XML колонок берётся из прежнего mixedColumns.xml с явно изменёнными
номерами/именем таблицы, сам XML-файл не менялся. Теперь 31 случай проходит
