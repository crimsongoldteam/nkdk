# Приёмка UUID

`common.uuid` принят как общий договор собственного идентификатора. Декларация
сохраняет XML-текст, а при экспорте YAML получает значение из подготовленного
индекса по компоненту, владельцу, виду и имени. Вклад в индекс описан декларативно.
Создание идентификатора остаётся обязанностью подготовки операции; повторный
контрольный экспорт ничего не создаёт и не изменяет снимок.

Проверены 572 записи существующего корпуса, 179 связей с основной конфигурацией
и восстановление девяти значений перечислений. Дополнительная матрица проверяет
получение индекса непосредственно из XML, публикацию того же значения при
экспорте YAML, верхний регистр, произвольный исторический текст, пустой атрибут,
повторный экспорт и отсутствие атрибута при имеющемся значении в индексе.
Последний случай сохраняется общим `!xml/raw`, без UUID-обработчика аномалий.
Собственный идентификатор не превращается в обычное YAML-поле или ссылочный тег.

Лексическая проверка формата UUID не добавлена: существующий импорт принимает
текст, а пустой атрибут отличается от отсутствующего. Общая подготовка уже
проверяет стабильную генерацию, повторное использование готовых значений и
запрет генерации при неоднозначном или неготовом индексе. Неподготовленный индекс
остаётся ошибкой подготовки операции, а не аномалией исходного XML.

Новых обработчиков и изменений компилятора не потребовалось. Расширена проверка
границы XML ↔ индекс ↔ YAML в существующей матрице `identity.rs`; низкоуровневые
проверки генератора не дублировались. Четыре Rust-теста, Clippy и проверка новых
дублей прошли. Полная сборка владельцев и публикация внешних файлов проекта
принимаются отдельно; этот флажок не означает завершения всех владельцев.
