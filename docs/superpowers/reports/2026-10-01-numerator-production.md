# Полное подключение нумератора к рабочей операции

Нумератор собран из параметров существующих `rules.ts` в YAML-декларации.
Общий переносчик проверяет, что все исходные свойства представлены: имя,
UUID, синоним, комментарий, принадлежность, связь с основой, состояние
расширения и пять свойств номера. Частного обработчика нумератора в
операции Rust нет.

Рабочие файлы:

- [Декларации](../../../rust/declarations/objects/complete-scalar-owners.generated.yaml).
- [Регистрация операции](../../../rust/operations/complete-scalar-owners.routes.generated.yaml).
- [Генератор полного объекта](../../../tools/rules-migration/src/complete-scalar-owner.mjs).
- [Генератор регистрации](../../../tools/rules-migration/src/complete-scalar-owner-route.mjs).

## Раздельная сборка

Подключение восьми регистраций к прежнему единому пакету создавало
35 686 210 байт Rust при пределе 33 554 432. Предел не увеличен.
Теперь общая политика сборки разделяет функции по списку исходных файлов:
основной пакет и пакет полных объектов. Каждый использует одинаковую
нумерацию регистраций, схемы входов и индексов, описания ресурсов и план
подготовки фактов. Готовые функции остаются предварительно скомпилированными.

Общий каталог проверяет совпадение редакций деклараций и отсутствие
двойной регистрации преобразования. Подпись вычисляется при сборке,
проверяется один раз при работе. Внутренние операции получают общий
`PreparedInputs`, не разбирают YAML-декларации и не интерпретируют выражения.

Замер размера до заключительной уборки дублей: основной пакет 31 152 506
байт, дополнительный — 4 615 453. Ограничения 32/8 МиБ сохранены.
Это ограничение размера отдельных единиц компиляции; нового измерения
пиков памяти и выигрыша скорости в данном блоке нет. Строгая общая подпись
пока может требовать пересборки обоих пакетов после изменения декларации.
Цель 10× по скорости и памяти этим результатом не подтверждается.

## Проверяемые договоры

Общая проектная операция проверена на пяти исходных нумераторах CF и
четырёх CFE, включая собственные и заимствованные. Исходные XML неизменны;
экспорт после повторного чтения YAML сравнивается по структуре XML,
включая отсутствие элементов, порядок и состояния расширения.

Из новых YAML создаются собственный объект CF, собственный объект CFE и
заимствованный объект CFE. Два экспорта сохраняют UUID, связь заимствованного
объекта содержит UUID настоящей основы, собственный её не получает.
Изменение boolean в текущем YAML основы меняет отдельную диагностику
`base.value.changed`, без повторного импорта XML и изменения снимка UUID.

Отсутствующее свойство в XML заимствованного объекта сохраняется через
автоматическую аномалию: общий механизм выбора теперь допускает отсутствие
исходного дерева. Пустой старый YAML-эталон такую форму терял; проверяется
сохранённая аномалия и точное восстановление исходного XML.

Нативная проверка раздельной генерации использует два источника с разными
индексами и значениями, подготовку входов в одном пакете, проверку потребителя
в другом и общий план зависимостей. Проверяет устойчивость подписи при
перестановке исходников и её изменение при правке незапущенного правила.
