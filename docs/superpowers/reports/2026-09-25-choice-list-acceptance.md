# Приёмка ChoiceList

`ChoiceList` описан [одной YAML-декларацией](../../../rust/declarations/common/choice-list.yaml): повторяющийся `xr:Item` проецирует вложенное типизированное значение `MetadataValue`; `xr:CheckState` восстанавливается из объявленного нуля. У `xr:Presentation` пустой элемент является обычной формой экспорта 1С. Его отсутствие в старых XML-примерах сохраняется как автоматически выведенная аномалия свойства.

[Rust-проверки](../../../rust/crates/compiled-rules/tests/choice_list.rs) охватывают три прежних XML-примера, три неизменённые формы e2e, повторы, отсутствие и пустой `ChoiceList`, создание XML из YAML без референса, неверный `CheckState`, пустой элемент среди повторов и неизвестный тип значения. Для исходных XML проверяются оба направления и доказательство восстановления. Аномалия остаётся на `СписокВыбора`; корень документа не получает `!xml`.

[Проверка схемы](../../../rust/crates/rule-compiler/tests/schema.rs) подтверждает, что тип массива и типизированные элементы выводятся из тех же деклараций. Для вложенных сокращённых переводов и рекурсивного значения используется общий построитель схем; отдельной схемы `ChoiceList` в Rust нет.

Общий сборщик объявленной коллекции теперь при невозможности прочитать вложенную пометку или спроецировать повреждённый элемент отказывается от уточнения отдельных строк и сохраняет XML на границе свойства-коллекции. После этого проверка обратного восстановления обязательна. Частных проверок имени `ChoiceList` или формы в Rust нет. Полная форма-владелец принимается отдельно.
