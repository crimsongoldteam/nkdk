# Сохранённая идентичность независимого источника

Добавлена общая декларативная привязка `snapshot.storage: external`. Источник
импортирует UUID из XML и сохраняет небольшой YAML через существующую публикацию
внешних источников. Следующий запуск читает этот сохранённый YAML; полный
преобразователь владельца и пакет его сведений не нужны. Значения реквизитов
получаются отдельно из текущего первичного YAML.

Поставщик выбирается по регистрации декларации, XML-каталогу и компоненту.
Не добавлены условия по именам common или прикладных объектов. Обход привязок
поддерживает составные строки, профили компонентов и выбор вариантов. При
выборе сначала подготавливается условие, затем только выбранная ветвь. Один
источник читается один раз на подготовку данного владельца. Это не отдельный
интерпретатор деклараций: привязки маршрутов передают входы готовым Rust-функциям.

Усилена существующая интеграционная проверка приложения. XML импортируется
источником, прежний XML удаляется, пакет сведений владельца отсутствует; экспорт
продолжает получать прежний UUID. Проверены неиспользуемая ветвь без поставщика,
неизвестное хранилище, повреждённый и отсутствующий сохранённый источник.
Первый запуск падал на неподдерживаемом `storage`, затем проверка прошла.
Исходные XML-фикстуры не изменены.

Привязка источников восьми семейств и приёмка через полную проектную операцию
ещё не завершены. Для расширения нельзя просто читать основной реквизит с UUID
основы: существующая проекция перекрытия адресована UUID владельца расширения.
Следующая сборка маршрутов должна согласовать обе идентичности декларативно,
с проверкой удаления и перекрытия местного реквизита. Наличие этой привязки не
означает полной приёмки `InputByStringFields` или владельцев.

Это видно на неизменной фикстуре `СправочникПолный`: UUID основы —
`f8ffca12-d09d-4111-ba91-67077462df5b`, UUID расширения —
`542adf1f-4330-4661-960a-353a2b037e9c`. Кандидатный корпус передаёт UUID
расширения обоим источникам вручную. Рабочие маршруты должны получить эту связь
из сохранённой идентичности и `ExtendedConfigurationObject`, а не повторить
подготовку примера вручную или добавить условие по типу объекта в Rust.

Прошли 50 Rust-тестов приложения, Clippy, три архитектурные проверки,
форматирование, проверка изменений и поиск новых дублей. Полный `pnpm test`
трижды прошёл функциональные проверки, но завершился с кодом 1 из-за лимитов
времени неизменённых TS-тестов. Первые два запуска превысили лимит файла
импорта расширения (3,13 и 3,17 с); отдельно он прошёл за 2,17 с, а в третьем
общем запуске — за 1,56 с. Третий запуск превысил лимиты других интеграционных
файлов и отдельных тестов. Лимиты не повышены, проверки не отключены.
Во время диагностики наблюдались фоновая нагрузка других приложений и около
2,1 ГБ подкачки. Это возможное влияние среды, не доказательство причины
каждого превышения. Общий временной барьер остаётся непройденным; не выдавать
функциональную успешность за полностью зелёный запуск.

Самопроверка общности
выполнена; независимое ревью не проводилось. Скорость преобразования и пик
памяти в этом блоке не измерялись; цель 10× остаётся неподтверждённой.
