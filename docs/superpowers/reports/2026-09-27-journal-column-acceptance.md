# Приёмка графы журнала документов

Для `MetadataDocumentJournalColumn` уже существовали [строка и коллекция YAML-деклараций](../../../rust/declarations/objects/metadata-journal-column-rows.yaml), автоматически выпущенные из `rules.ts`. Повторная проверка показала, что они покрывают собственные поля графы, UUID, ссылки, имя как ключ YAML, состояния основной конфигурации и расширения. Частных обработчиков графы в общем Rust-ядре нет.

[Rust-проверка](../../../rust/crates/probe-journal-columns/tests/columns.rs) использует реальные XML основной конфигурации, собственных и заимствованных граф расширения. Во всех трёх вариантах XML → YAML → XML восстанавливает графы без `!xml`; проверяются ссылки, индексирование, UUID и вклад в индекс идентичностей. Неверное значение индексирования сохраняется как аномалия и восстанавливается вместе с соседними данными. Полный заимствованный журнал также проверяет сборку этих граф в составе владельца.

Прежняя незаполненная строка чеклиста ожидала проектную операцию журнала. Это противоречило принятому разделению: самостоятельный common принимается по собственному договору, а полная операция владельца — отдельно. Декларация и проверка существовали до этой записи; 27 сентября повторно выполнен адресный Rust-тест. `pnpm type-check`, архитектурные проверки и поиск новых дублей прошли. В отдельном повторе 3166 интеграционных тестов rules прошли без функциональных ошибок, но контроль длительности нескольких старых файлов завершился ошибкой и прервал полный `pnpm test`. Пороги и тесты не изменялись.
