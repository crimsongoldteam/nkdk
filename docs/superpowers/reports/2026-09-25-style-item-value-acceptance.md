# Приёмка common `StyleItemValue`

`rust/declarations/common/style-item-value.yaml` задаёт три непересекающихся варианта по XML `xsi:type` и YAML `Вид`: `Color` ↔ `Цвет`, `Font` ↔ `Шрифт`, `Border` ↔ `Рамка`. Значения обрабатываются уже принятыми декларациями `common.color`, `common.font` и `common.border`. Признак `Вид` для рамки общий компилятор добавляет и удаляет на границе вложенной записи; её поля в декларации выбора не повторяются.

Проверка `tagged_style_value_reuses_nested_color_font_and_border_declarations` использует неизменённые e2e XML-файлы `ЭлементСтиляЦвет.xml`, `ЭлементСтиляШрифтВсеСвойства.xml`, `ЭлементСтиляРамка.xml`. Для каждого проверены XML → YAML, проверка YAML, YAML → XML без исходного XML-референса и доказательство восстановления. Отдельно проверены неизвестный `xsi:type`, отсутствие `Value`, пустой `<Value/>`, неверные высота шрифта и ширина рамки. Проверка YAML отвергает неизвестный `Вид` и лишнее поле варианта; запасной вариант XML больше не превращает ошибочный YAML в обычный цвет.

Неверная вложенная ширина выявила ограничение быстрого чтения плоской записи с вложенным тегом `!xml`. Общий завершающий механизм для владельца с одним свойством теперь, только когда созданный им YAML содержит `!xml/` и его чтение завершается `yaml.unsupported-form`, сохраняет исходный XML на границе этого свойства. Поэтому неверная рамка даёт `Значение: !xml/raw` и восстанавливается без потери XML. Обычные рамки остаются смысловым YAML. Исправление не добавляет условия по имени рамки или `StyleItemValue` в исполнителе.

Приёмка относится к common-договору. Рабочее включение полного владельца `metadataStyleItem` проверяется отдельно. Проверки: матрица `nkdk-probe-scalars` и наборы `nkdk-rule-compiler`/`nkdk-conversion-core`, Clippy, архитектурные правила и поиск новых дублей относительно `2af2f299ed8241eac78d4db46b4a8421efe2f8f7`.
