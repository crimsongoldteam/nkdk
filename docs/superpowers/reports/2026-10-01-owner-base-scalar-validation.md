# Сравнение скаляров владельца с основой — 2026-10-01

## Что реализовано

Перечисления и boolean нумератора сравниваются с основной конфигурацией тем
же декларативным механизмом, что и точные числа. ТипНомера,
ДопустимаяДлинаНомера, ПериодичностьНомера и КонтрольУникальности выбираются
из исходных правил, без списка специальных свойств в Rust. Общее выражение
приводит значение к точной записи: decimalText, enumText либо true/false.

Обычное контролируемое значение, отличающееся от основы, даёт ошибку
base.value.changed; уведомление — предупреждение, разрешённое изменение
не сравнивается. Отсутствующее свойство основы даёт base.property.missing.
Сравнение не теряет путь свойства и серьёзность сообщения.

## Разделение стадий

В реальном заимствованном XML КонтрольУникальности=true при false в основе,
ПериодичностьНомера=Nonperiodical при Year. Оба различия обнаруживаются
при проверке полного YAML; исходный XML отдельно преобразуется обратно
без потерь. Нельзя считать корректность преобразования доказательством
согласованности объекта с основой.

Новые межфайловые ограничения включены в автоматически получаемое
представление `.validation` той же полной декларации. Отдельных ручных
правил преобразования или проверки объекта нет. При прямом добавлении
этих ограничений в обратимую запись компилятор смешивал проверку проекта
с чтением XML и возвращал ошибку сравнения. Этот общий недостаток не объявлен
исправленным; проверочное представление следует существующей отдельной
стадии projectState validation. Не применяем !xml для обхода такой ошибки.
Проектный маршрут ещё должен подключить обе стадии.

## Исправление компилятора

Общий доступ к полю варианта принимал текст, boolean и числа, но отвергал
перечисление. Теперь перечисление получает тот же заимствуемый текстовый
доступ, что и текст. Регрессия сначала падала при генерации Rust, затем
прошла: выражение enumText проверяет значение внутри варианта и XML-оболочки
с атрибутом; преобразование и диагностика проверены отдельно. В компиляторе
нет условий по нумератору или именам его свойств.

## Источник принадлежности для проектного подключения

Полный источник идентичности дополнен принадлежностью из ObjectBelonging.
Он использует существующее перечисление: Собственный / Заимствованный.
Отсутствующий элемент XML означает Native по исходным rules.ts. Снимок
сохраняет принадлежность явно вместе с UUID, поэтому выбор профиля может
выполняться по данным снимка, без чтения XML в оркестраторе.

Не создаём второй словарь принадлежности и особое преобразование в boolean:
обычная YAML-запись существующего перечисления достаточна для выбора.
Проверочный исполнитель сопоставляет ожидаемые поля снимка с реальным
результатом snapshot_fact_source; значения UUID берутся из XML-примеров,
принадлежность проверяется для основного, собственного и заимствованного
объекта. Это источник данных будущего маршрута, не готовый маршрут.
