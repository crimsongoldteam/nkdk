# ChildSubsystemNames: общая декларация и первый владелец

Список дочерних подсистем описан одной YAML-декларацией
`common.child-subsystem-names`: повторяющийся XML-элемент `Subsystem`
соответствует последовательности имён в YAML. Специального Rust-обработчика
нет; порядок и повторные имена сохраняются.

Переносчик распознал единственное исходное свойство `subsystems` у
`MetadataSubsystemRules` и выпустил кандидат с вложенным XML-путём
`ChildObjects/Subsystem`. Существующая пара XML/YAML подсистемы служит
независимым эталоном; дополнительно проверены три элемента с повтором,
отсутствующий и пустой контейнер, явный пустой список YAML, обратное
преобразование без XML-референса. Исходные фикстуры не менялись.

Дополнительная проверка подтвердила, что пустой `<Subsystem/>` и пустой элемент
среди обычных имён проходят Rust round-trip без `!xml/raw`: пустая позиция
остаётся в YAML как `""`, порядок соседей не меняется. Полный объект
`MetadataSubsystem` всё ещё не собран в рабочем Rust-маршруте, поэтому
общий флажок остаётся пустым: кандидат свойства не является полной приёмкой
владельца.

Дополнение 25 сентября: common и владелец теперь принимаются по отдельным
границам, как ранее согласовано для `FillValue`. Повторный прогон 19 проверок
коллекций включил существующую пару подсистемы, пустые элементы, повторы,
отсутствие и обратное преобразование без XML-референса. Собственный договор
`ChildSubsystemNames` принят; флажок common установлен. Полная сборка
`MetadataSubsystem` по-прежнему не принята и остаётся задачей владельца.
