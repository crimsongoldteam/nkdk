# Settings.parameters: проверка всей коллекции


## Текущее состояние

Все 12 сценариев параметров проходят, включая полную коллекцию из семи строк,
повтор и неверные значения. Подтверждено сохранение смыслового YAML и исходного
XML. Дополнительно прошли обе проверки профилей Settings и пять проверок QName:
выбор QName учитывает смысловой вариант и номер вхождения; отсутствующее
значение отличается от nil → null без ложной аномалии.

Исправлена паника при уточнении коллекции, у которой сохранён XML, но нет
смысловых строк. Запись QName теперь использует общий вывод отсутствия,
канонической формы и патчей вместо досрочного выхода.

Это приёмка преобразования параметров, а не всей формы. Полное подключение
владельца и адресация индекса yamlPath ещё не приняты. Следующее предметное
семейство — AppearanceFields; общие проверки текущего блока завершены.
Журналы: /tmp/nkdk-dcs-all-context.log, /tmp/nkdk-qname-nil-green.log.

## Добавлено

Семейство `dynamic-list-parameters` использует существующий генератор
`dcsParameterCase` и общий запускатель. Каждый запуск собирает только нужные
декларации; обходной частный конвертер не создавался. Источники индексов —
реальные StyleItems из e2e и словарь FoldersAndItemsUse.

К прежним примерам добавлены вся коллекция из семи параметров в исходном
порядке и повтор первого параметра. XML-фикстуры не изменены; ожидания YAML
взяты из соответствующей e2e-фикстуры. Проверка повторов требует восстановления
исходного XML, а не только наличия пометки.

## Исходный результат до исправления

- Отдельный параметр СТипом проходит.
- Вся коллекция не проходит: смысловой YAML сохраняет лишь Параметр1,
  остальные строки не отображаются. Временная диагностика показала 7 строк
  после XML-чтения: проблема возникает позже. Диагностика удалена из кода.
- Отдельный Параметр1 тоже не проходит прежнее ожидание: возникают вложенные
  raw-пометки. Обычная строка ФормаВыбора превращается в n0:ФормаВыбора.
- Повтор параметра не проходит XML round-trip: в восстановленном XML
  встречаются n0:true и n0:Items вместо исходного текста. Ошибку нельзя
  исправлять принятием фактического результата как нового эталона.
- Статическая проверка показала, что выбор вариантов объединяет признаки
  QName всех альтернатив. Нужно проверить выбор признака для действующего
  варианта при проекции и сохранении XML; принадлежность пути сама по себе
  недостаточна. Это направление исправления, не доказательство единственной
  причины всех расхождений.

Первая попытка запуска через общий collections-check остановилась ещё при
импорте посторонней фикстуры: Missing fact provider: metadata.resource-fingerprints.
Новый узкий запускатель не импортирует эти несвязанные примеры.

Первая узкая сборка: 118 деклараций, 50,26 с. Последующая проверка другого
примера с тем же набором использовала готовую сборку (0,14 с). Это не замер
скорости преобразования. Журналы: /tmp/nkdk-dcs-whole-family.log,

10 проверок запуска семейств и сборки коллекций прошли; новых дублей нет.
Полный pnpm test в этом блоке не запускался. Settings.parameters, DynamicList
и FormAttribute не объявляются принятыми.

## Исходный следующий шаг

На небольшом выборе текст/QName воспроизвести ошибочное добавление префикса,
исправить общую проекцию с учётом действующего варианта и повторить полную
коллекцию. Затем отдельно проверить сохранение всех смысловых строк.
AppearanceFields остаётся следующим предметным блоком: Текст и Формат имеют
сокращения строки, локализованной строки и форматированной строки, отличные
от обычного DesignTimeValue. Одна таблица имён без этих договоров недостаточна.


## Исправление выделения XML, 2026-10-07

`project_property` теперь сохраняет исходный текст и объявления пространств
имён вместо захвата дерева с объединённым QName-признаком. Общий обход
`visit_property_documents` выделяет повторные вхождения по одному; к нему
подключено уточнение строк декларативной коллекции. Нет ветвлений по именам
common/свойств. Старые неиспользуемые функции фильтрации дерева удалены.
Обычный путь чтения деклараций не заменён интерпретатором.

Проверка ядра покрывает обычный текст, QName с наследуемым префиксом,
переопределение префикса, QName без префикса, CDATA/экранирование, повторы
и недопустимый XML в исключённых ветвях. Существующая проверка общих путей
теперь также сравнивает документы повторных вхождений с прежним договором.

Повтор реального Параметр1 показал: смысловая строка теперь `ФормаВыбора`,
а не `n0:ФормаВыбора`; значение `БыстрыйВыбор` сохраняется как `Истина`.
Приёмка Параметр1 и всей коллекции всё ещё падает из-за raw-пометок:
проверка XML и построение патчей по-прежнему объединяют QName-пути вариантов.
Смысловой текст исправлен на стадии проекции; полное исправление QName
и сохранение всех семи строк пока не подтверждены.

Следующий шаг: передавать выбранный вариант и номер вхождения в определение
QName для проверки/патча; союз возможных путей оставить только для буферизации
пространств имён. Затем повторить отдельный параметр, всю коллекцию и повторы.
Минимальный контрпример: в пространстве имён `urn:form` элемент `Value`
с `xsi:type="xs:string"` содержит `Plain`, а соседняя альтернатива декларации
допускает `xs:QName`. Обычный YAML должен содержать `Plain` без raw-пометки;
текущее сравнение ошибочно считает текст именем `{urn:form}Plain`.

Журналы: `/tmp/nkdk-dcs-lexical-rows.log`,
`/tmp/nkdk-dcs-whole-projection.log`, `/tmp/nkdk-projection-core-final.log`.
