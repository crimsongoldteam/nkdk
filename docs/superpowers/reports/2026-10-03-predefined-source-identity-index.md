# Индекс UUID из исходных Predefined.xml

## Изменение

Декларации строк справочника, плана счетов и видов расчёта публикуют соответствие
полного имени и XML UUID в `metadata.predefined-identities`. Планы видов
характеристик и варианты расширения используют строку справочника с существующими
параметрами представления. Вложенные группы проходят
общим рекурсивным механизмом; UUID из проверочного словаря им не подставляются.

Профили оболочек справочника, характеристик, счетов и видов расчёта привязывают вход `identities` к
этому индексу. При генерации подключаемого фрагмента тип входа сохраняется,
а привязка готового индекса остаётся только у объекта-владельца. Это соответствует
существующему ограничению языка: фрагмент получает зависимости, объект отвечает
за их подготовку. Новых полей языка и обработчиков отдельных метаданных нет.

## Выявленная ошибка общей подготовки

Прямой сбор индекса из настоящих XML прошёл. При проверке общего расписания
обнаружилась ложная зависимость XML-подготовки от собственного индекса: прежний
анализ на границе рекурсии объявлял необходимыми все входы.

Анализ теперь находит устойчивое множество зависимостей рекурсивных деклараций
последовательным распространением требований по привязкам. Чтение XML не
требует индекса, используемого только при сокращении/восстановлении YAML.
Обратное направление сохраняет эту зависимость. Непроанализированные формы
выражений по-прежнему считаются требующими всех входов; исключений по именам
Predefined, UUID или объектов в анализе нет.

## Обход вариантов и вложенных записей

Публикация индекса задаётся самой декларацией строки. Общий обход находит
её внутри коллекции, записи или выбора и передаёт сбор только выбранному
варианту. Для вариантов без объявленных фактов отдельные пустые переходы
не генерируются. Вклад самого владельца не считается вкладом каждой строки:
иначе компилятор вызывал бы отсутствующий обработчик строки. Явный обход
коллекции также исключает повторный неявный обход той же области.

## Проверки и границы

Усилена существующая матрица полного файла `contributions.rs`: вместо ручного
словаря все четыре обычных семейства используют
`core::facts::preparation::prepare::<FactCatalog>`. Источник получает только
имя владельца; индекс собирается из XML. Ожидаемые YAML и восстановленные XML
остаются независимыми от декларации. Проверка также различает зависимости
XML-подготовки и обратного YAML-направления.

Матрица переносчика дополнена индексом на владельце: фрагмент получает тот же
тип без объявления самостоятельной подготовки индекса. Первый запуск упал;
после исправления прошли 26 проверок переноса и готовности.

Это ещё не полная приёмка XMLRoot или каталогов. Четыре обычных семейства прошли матрицу с исходным индексом (165,23 с).
Расширение также прошло подготовку исходного индекса, преобразование настоящего
файла, листовых вариантов и восстановление аномалий (728,16 с вместе с прежней
проверкой подключения владельца). Ошибка подключения контекста перед проверкой
имени исправлена общим механизмом: полный контекст теперь готов до собственного
вклада записи. Рекурсивная матрица воспроизвела ошибку и прошла после исправления.
Подготовка индекса через подключение владельца расширения также прошла
(73,21 с после RED): главный XML и внешний файл собирают UUID через общий
FactCatalog, YAML не содержит явных UUID предопределённых записей, обратный
экспорт восстанавливает оба XML без исходных документов. Объявление индекса
остаётся у владельца. Сбор уже загруженной коллекции использует её локальный
договор без признака файлового размещения, как и преобразование.
Маршруты полного приложения проверяются отдельно. Счётчик common остаётся
56/90. Самопроверка универсальности выполнена; независимое ревью не проводилось
по инструкции пользователя работать без субагентов. XML-фикстуры не изменены.


Проверка отдельного файла и подключённого владельца имеет самостоятельные
точки запуска с общей подготовкой деклараций. Сценарии не продублированы:
листовые варианты/состояния относятся к файлу; загрузка документов и исходный
индекс владельца — к подключению. Это позволяет проверять изменение подключения
без повторной сборки большого проверочного набора файла и листовых представлений.

## Потоковая загрузка подключённого XML

Проверка настоящего владельца расширения переведена на потоковую подготовку:
основной XML и Predefined.xml загружаются для текущего источника один раз,
после вклада документ освобождается. Подготовленные входы сохраняют индекс,
а не исходный XML. Усиленная проверка прошла (247,56 с), включая обратный
экспорт без XML-референса и сохранение аномалий. Непотоковая подготовка
сохраняет прежний договор. Это ещё не приёмка маршрута полного владельца.

При проверке приложения обнаружены две причины лишней работы сборки:
неподключённые фрагменты захватывались рабочим каталогом, а анализ входов
для каждого свойства обходил весь Program. Отбор теперь следует импортам
и объявлениям индексов, сохраняя ошибки достижимых зависимостей; монотонный
анализ работает на достижимом графе одной декларации. Прошли 16 внутренних
