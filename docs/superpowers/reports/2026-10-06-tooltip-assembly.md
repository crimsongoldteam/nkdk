# Полная сборка ExtendedTooltip — 2026-10-06

## Результат

Все исходные сериализуемые свойства ExtendedTooltip собираются автоматически
из проверенного `rules.ts`. Служебный тип `runtimeOnly` отдельно учитывается
в отчёте как не сериализуемый. Исключение допускается только для статического
системного перечисления без XML/YAML-пути, значения по умолчанию и другого
поведения; неизвестное свойство не пропускается молча.

Регистрация задаёт ведущую пару name/id независимо от наличия name в
`rules.ts`. Привязка пространства XML-имён передаётся явно месту сборки.
Общие слои не проверяют имя ExtendedTooltip, Font, Title или Events.

Четыре полных примера проверяют минимальную подсказку, все свойства,
форматированный пустой заголовок и подсказку из настоящего e2e файла формы.
Смысл полного результата сравнивается с сохранённым YAML. Необычный порядок
старых XML-фрагментов восстанавливается аномалией; сам e2e-пример не требует
пометки. Префиксы пространств имён могут меняться только на явно указанных
QName-полях; другое пространство имён, имя и обычный атрибут остаются
значимыми. XML-фикстуры не изменены.

Команда `pnpm test:migration-family --family element-assemblies` проверяет
четыре примера с ограниченным набором деклараций. Команда
`pnpm migration:tooltip:working` сохраняет тот же граф в рабочий каталог:
63 автоматически собранные декларации, без второго ручного списка свойств.
`--check` сверяет сохранённый результат; команда
`pnpm test:migration:tooltip:working` прошла все четыре примера через рабочий
каталог. События также повторно прошли все 17 рабочих сценариев.

## Общие исправления, найденные полным примером

- Захваченная коллекция текстовых записей передаётся выражениям как
  заимствованное представление, без ошибочного обращения как к скаляру.
- Условия присутствия и канонической формы специализируются вместе с
  телом записи: параметры общей декларации не просачиваются во владельца.
- Декларация форматированного текста явно разрешает отсутствие целого
  значения. Отсутствующий заголовок не получает ненужную пометку.
- Отсутствие общего XML-атрибута с подразумеваемым смысловым значением
  сохраняется у контейнера. Например,
  отсутствующий formatted записывается у Заголовка через `_formatted: null`,
  сохраняя обычный Текст; синтетическое поле formatted внутри YAML не
  появляется. Окончательное доказательство восстановления выполняет
  владелец контейнера, а не отдельно оторванный атрибут. Явное значение
  атрибута и смысловая пометка сохраняют прежнюю границу поля.

Последнее исправление защищают девять прежних независимых примеров
FormattedI8nText: `pnpm test:migration-family --family formatted-records`.
Ожидаемый результат случая отсутствующего атрибута не изменялся.

Источник name/id с новым пространством XML-имён получает собственный
идентификатор декларации. Общий перенос в рабочий каталог запрещает
молчаливо заменять существующую декларацию с тем же id другим договором;
связи источников индексов и проверочные ожидания сохраняются автоматически.

## Что ещё требуется для полного перехода

Автоматическое подключение 41 свойства, сокращение пустой подсказки и
восстановление name/id из сохранённого контекста реализованы (результаты ниже).
Остаются проверка нового элемента с назначением id и полная сборка владельцев.
Поэтому флажок полного переноса объекта пока не ставится.
Рост скорости 10× и пик памяти этим блоком не подтверждались.

Проверки связей пакетов и самопроверка кода не заменяют независимое ревью
универсальности общих механизмов перед завершением всей ветки.

## Автоматическое подключение свойств, 6 октября

Переносчик распознаёт все 41 исходных свойства (три варианта параметров,
два XML/YAML-договора) через сгенерированный `declared-elements.json`.
Он ссылается на одно относительное тело и выводит входы из его композиции;
компонент, владелец и индексы не прописываются у 41 объекта вручную.
Имя для обычных свойств берётся из собственного поля дочернего элемента.
Заимствованное представление текстового выбора поддерживает такую зависимость
без сериализации. XML-путь задаётся только в месте подключения.

Отсутствующий YAML восстанавливается как `{record: {}}`: используются уже
объявленные значения полей. XML-only override коллекции сохраняет YAML-default
common. Декларация с обязательным полем без default отклоняется компилятором.

Проверки расширены с четырёх до восьми: два вложенных варианта и проекции
исходных свойств ButtonRules/ViewStatusAdditionRules. Ожидания взяты из
прежних фикстур и e2e; исходные файлы не менялись. Эти проекции проверяют
подключённое свойство, а не остальные свойства родителя. Все восемь прошли
ограниченную Rust-сборку. Рабочая генерация теперь содержит 128 деклараций;
те же восемь примеров прошли через рабочий каталог. Повторно прошли все
17 рабочих сценариев Events.

Повторная массовая генерация дала 4833 свойства-кандидата. Это не число
полностью принятых объектов. Она обнаружила устаревшее имя фрагмента
стандартного реквизита, зависящее от хеша кандидата: продвижение принятого
договора теперь сохраняет имя исходного поля при изменении хеша. Сохранённая
рабочая декларация стандартных реквизитов осталась байт-в-байт прежней.

Общий механизм назначения новых id выполнен следующим блоком:
[числовые запросы индекса](2026-10-06-numbered-identities.md). Матрица расширена
до десяти сценариев новой подсказкой и её вложенным размещением.
Остаётся полный маршрут формы, включая все источники занятых номеров и
основную форму. Общий флажок объекта не выставляется до этих условий.

## Ограничение размера рабочего каталога

Проверка дополнительных размещений выявила превышение установленного
предела: один пакет создавал 15 639 089 байт Rust при лимите 8 МиБ.
Ограничитель остановил сборку до запуска `rustc`; предел не увеличен.
Тело и проверочные размещения распределены по двум пакетам элементов
через существующий механизм владения декларациями. Общие функции компилятора,
проверка единства каталога и его внешний интерфейс сохраняются.
Состав файлов по-прежнему формируется автоматически; повторного ручного
описания свойств нет. Полученные размеры: 6 000 840 байт у базового пакета,
4 989 134 и 4 997 864 байта у двух пакетов элементов. Все три укладываются
в прежний предел 8 МиБ. Это размеры кода, а не замер пика памяти `rustc`.
Последовательная пересборка для проверки после изменения компилятора и
состава пакетов заняла 8 мин 24 с; это не замер чистой или локальной сборки.
Все восемь сценариев прошли, следующий запуск Events использовал готовый
каталог (Cargo: 0,21 с). Прежние предупреждения неиспользуемых функций и
таблицы unwind остаются; улучшение общей скорости сборки здесь не заявляется.

независимое ревью всей ветки остаётся отдельным условием её завершения.
