# Полное преобразование нумератора документов

## Результат

Собрана декларация полного XML нумератора: оболочка с версией,
UUID, имя, синоним, комментарий, принадлежность объекта, связь с основой,
все пять скалярных свойств и одна общая история состояний.
Проверены целиком неизменённые XML/YAML основной конфигурации,
заимствованного и собственного нумераторов расширения. UUID и связь с
основой поступают из декларативных источников фактов по реальному XML.
Проверочный исполнитель не передаёт исходный XML как референс экспорта.

Общий сборщик записей теперь переносит ограничения и связи состояний,
проверяет повторные имена договоров и не изменяет исходные фрагменты.
Это расширение сборки данных, а не новый предметный обработчик Rust.
Неизвестное свойство блокирует сборку полного владельца: оно не теряется
и не заменяется аномалией для сокрытия отсутствующего преобразования.

Связь с основой использует существующий borrowed-base.yaml и
common.base-reference-state. Строки состояния этой связи и скаляров
находятся в одной коллекции. Для пустой истории канонический XML не
содержит InternalInfo; явная пустая оболочка сохраняется общим механизмом
при несовпадении исходной формы. Принадлежность собственного объекта
также не добавляется в XML без необходимости.

Порядок YAML основной и собственной конфигурации соответствует общему
русскому порядку ключей; порядок заимствованного объекта соответствует
исходной регистрации свойств. Это две декларативные версии одной сборки.
В Rust не появились ветвления по нумератору или его именам свойств.

## Дополнительные случаи

Уведомление ExtendedConfigurationObject сокращается до
`ОбъектРасширяемойКонфигурации: !проверять`. Его доступность проверяется
по конечному словарю версий, совместно со скалярными состояниями.
Общий сборщик условий совместимости теперь использует тот же resolver
профилей и изменений версий, что и скаляры, вместо второго разбора версий.

Два одинаковых уведомления не сокращаются: они остаются явными строками
`Состояния`, вместе с соседними состояниями чисел и перечислений.
Коллекция разрешает повторы и хранит их порядок, поэтому обычного YAML
достаточно для обратного XML; дополнительный !xml был бы избыточным.
Ожидаемые строки взяты из XML, а не из генерируемой декларации.
Производные примеры создаются только в памяти; исходные фикстуры не менялись.

## Проверки

Проверка новых общих договоров сначала падала: сборщик отвергал
constraints/state-relations, полного владельца ещё не существовало,
а условия совместимости не поддерживали вход с типом enum.
После реализации Node-набор из 11 проверок прошёл.

Все 18 сценариев numeric-owners прошли в Rust, включая 13 прежних
скалярных случаев и пять новых полных случаев. Дополнительная проверка
уведомления значения перечисления в версии 8.3.15 также прошла.
Сборки идут отдельно по сценариям, с одним процессом Cargo; большой
каталог workspace не собирался.

Полный pnpm test завершился с кодом 0. Проверки архитектуры TypeScript
и Rust, поиск дублей относительно 2af2f299ed8241eac78d4db46b4a8421efe2f8f7,
проверка воспроизводимости четырёх генераторов и git diff --check прошли.
XML-фикстуры в git не изменены.

Самопроверка универсальности: изменены только адаптер исходных правил,
сборка декларативных данных и проверочные примеры. Оркестратор и Rust-компилятор
в этом блоке не изменялись. Объект с неподдержанным свойством явно отклоняется
сборщиком; результат не объявляется поддержкой всех владельцев. Это
самопроверка, а не независимое ревью.

## Что ещё требуется для полной приёмки

Проектный маршрут нумератора пока не подключён. Нужно связать его полные
источники идентичности, принадлежности, истории, чисел и версии компонента,
выбор собственного/заимствованного профиля и создание новых файлов.

Преобразование целого XML не доказывает весь проектный контроль значений
относительно основы. Сравнение контролируемых/проверяемых перечислений
и boolean из существующего projectState validation ещё нужно перенести.
В реальной фикстуре заимствованного нумератора CheckUnique=true при
CheckUnique=false в основе, а NumberPeriodicity=Nonperiodical при Year
в основе. Такие исходные файлы можно без потерь преобразовать, но их
межфайловая проверка требует отдельной приёмки. Не считать этот пробел
доказательством, что сравнение этих типов не требуется.

Флажок полного перехода нумератора остаётся пустым до проектной приёмки.
