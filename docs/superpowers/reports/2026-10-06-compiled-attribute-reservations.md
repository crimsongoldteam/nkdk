# Скомпилированные источники занятых атрибутов

Продолжение [общего обходчика](2026-10-06-preserved-attribute-reservations.md).

## Результат

Компилятор создаёт профиль обхода из существующих безусловных вкладов
`reserve: {field: имя}`. XML-представление поля задаёт QName атрибута и элемента
границы; ключ вклада задаёт область и целевой индекс. Новых полей языка,
реестра аномалий и предметных условий в Rust нет.

Отдельная скомпилированная операция `reserve_attribute_source` принимает
обычный XML, уже захваченное дерево, сохранённую поправку или поправку одного
атрибута. Она использует прежний обходчик и `reserve_number`. Номер передаётся
как заимствованная строка; промежуточный XML не создаётся. Смысловые поля
и искусственные имена объектов для неизвестных потомков не строятся.

Несколько областей могут относиться к разным индексам. Столбцы ключа имеют
тот же канонический порядок, что у распределителя. После ошибки источника,
привязки или профиля все индексы этого источника остаются неготовыми, включая
индекс, до которого обход ещё не дошёл.

## Подключение к подготовке

`SourceKind::AttributeReservations { max_depth }` подключает XML-наблюдение
к общему `prepare_streaming_materials` через скомпилированный `FactCatalog`.
Зависимости всех источников завершаются перед публикацией соответствующих
индексов, поэтому поздние занятые номера учитываются при выдаче новых.
Каждый источник загружается отдельно существующим загрузчиком.

Порядок и привязка входов используют один набор зависимостей выражений
области. Смысловые defaults поля не читаются: иначе возникает ложный цикл,
когда такой default использует индекс, который источник должен подготовить.
Настоящий цикл в выражении области по-прежнему запрещает подготовку.
Неверное направление источника отклоняется до загрузки файла.

Обычный `contribute_file` сохраняет точную проекцию объявленных полей.
Новый режим выбирается явно при составлении источников; он не подменяет
обычное преобразование или сохранённый смысловой снимок `Snapshot`.

## Границы автоматического вывода

- Источник состоит только из безусловных прямых резервирований атрибутов;
  смешанные и вложенные смысловые вклады нельзя молча пропустить.
- Области вычисляются из подготовленных входов и выражений без полей источника.
- Один профиль наблюдает один QName атрибута в одном XML-источнике.
- Пути уже размещены. Самый короткий объявленный путь задаёт исходную область
  и должен быть предком остальных. QName концов путей задают границы областей
  на любой глубине; необъявленные потомки наследуют ближайшую область.
- Отдельный источник должен начинаться с объявленного QName границы.
  Для неизвестного корня сохранённого поддерева нельзя угадать унаследованную
  область; операция отклоняет его. Обходчик ядра с явно заданной областью
  сохраняет прежний общий договор.
- Один QName границы не может обозначать разные индексы или разные выражения
  области. Такой профиль отклоняется, а не выбирает случайную ветвь.

Неподдержанный профиль получает `fact.attribute-profile` при выборе этой
операции; существующее обычное преобразование той же декларации сохраняется.
Это ограниченная явно проверяемая возможность, не универсальное автоматическое
преобразование произвольного смыслового источника в наблюдатель всей формы.
Каталог без `reserve` не получает дополнительный сгенерированный код обхода.

## Проверки

В существующую матрицу `rule-compiler/tests/contributions.rs` добавлен один
самостоятельный договор и декларативная фикстура `attribute-reservations.yaml`.
Он защищает вывод настроек, обе области одного индекса и второй индекс,
namespace, неизвестных потомков, XML/дерево/сохранённую поправку, отдельную
поправку атрибута, поздний источник в настоящем порядке подготовки,
отсутствие ложного цикла и обнаружение настоящего. Независимые ожидания:
следующие номера 4/4/3; после одной поправки второго индекса — 2.

Отрицательная матрица включает повреждённый XML, неизвестную границу
сохранённого поддерева, глубину, конфликт QName,
условный профиль, смешанные смысловые вклады и ошибочное направление.
Ожидания заданы вручную; данные не выводятся из проверяемого генератора.
Существующие XML-фикстуры не менялись. Тесты не удалялись и не объединялись.
Первые запуски новых операций и сценария ложного цикла были красными,
затем прошли после реализации.

## Что ещё не закончено

Рабочий каталог полной формы и проектный маршрут ещё не выбирают этот вид
источника. Остаются автоматическое составление всех предметных областей,
подключение сохранённых границ, хранение занятости после повторного открытия
YAML-проекта и приоритеты основной/текущей формы. Проверка сохранённой поправки
в памяти не выдаётся за проверку повторного открытия проекта.

Полный каталог не пересобирался; проверены изолированно скомпилированный каталог
и настоящий общий порядок подготовки. Флажки объектов не меняются. Выполнена
самопроверка универсальности; независимого ревью не было. Цель 10× этим блоком
не измеряется.
