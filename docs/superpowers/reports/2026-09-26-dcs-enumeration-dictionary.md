# Словарь системных перечислений СКД

## Сделано

- Одна декларация `common.dcs-system-enumeration` описывает запись
  `Тип: СистемноеПеречисление`, `Имя`, `Значение` и оба направления поиска.
- Конечный словарь QName-имён генерируется из принятого каталога системных
  перечислений. Проверка актуальности:
  `node tools/rules-migration/src/dcs-enumeration-names.mjs --check`.
- Подготовленные индексы разделяют имя перечисления и код значения; названия
  разных перечислений не смешиваются. Проверочный поставщик фактов объявлен
  обычной декларацией.
- Неизвестный код или пространство имён сохраняется без потери соседнего
  свойства. Отсутствующий входной индекс остаётся ошибкой подключения.
- Общий компилятор обрабатывает QName-атрибуты, не зная про перечисления СКД.
  Дополнительная проверка использует два обычных атрибута, `kind` и `alternate`.

## Проверки и их границы

`dcs_enumerations.rs` сверяет 3501 значение 678 перечислений с сохранённым
корпусом TypeScript: XML → ожидаемый YAML и новый YAML → XML, затем проверяет
неизвестные значения, URI, соседнее поле и ошибку отсутствующего словаря.
Корпус ожиданий не генерируется из проверяемой новой декларации.

Одиннадцать существующих тестов СКД перенесены из `scalars.rs` в `dcs_fields.rs`.
Их данные и сценарии не удалены. Общие помощники вынесены в `tests/support`.
Предел размера проверочных каталогов 8 МиБ сохранён.

Самопроверка универсальности: изменения касаются типов QName, записи,
вычисляемых полей и границ аномалий. В общем Rust-коде нет условий по именам
СКД, конкретным перечислениям или числу их элементов. Это самопроверка,
не независимое ревью.

## Что ещё не закончено

Полный `DcsMetadataValue` не принят. Новый словарь пока подключён к проверочному
владельцу; рабочая сборка должна подготовить те же индексы и связать его с
выбором Field/Primitive и фиксированным SystemEnumeration. Остаются пустые
состояния, объединение режимов и приёмка рабочих владельцев.

Сопутствующая регрессия: JSON Schema отставала от действующего разбора
`scalar` с тегом, `mapping` без ключа выбора и проекции `yaml-text`. Схема
синхронизирована; проверки неправильных сочетаний параметров сохранены и
дополнены. Существующие XML-фикстуры не изменялись.

### 2026-09-26 — объединённый режим Primitive

`common.dcs-primitive-choice` генерируется из принятого `common.metadata-value`
и общей декларации системного перечисления. QName, уже занятые исходными
вариантами, исключаются из словаря дополнительного варианта по URI и локальному
имени. Поэтому специальные формы `ВидСравнения`, `ВидСчета` и
`ВидСравненияКомпоновкиДанных` сохраняются, остальные перечисления используют
`Тип: СистемноеПеречисление`. Все различия находятся в декларациях и их сборщике;
компилятор и исполнитель не знают имён этих типов.

Одна матрица проверяет оба режима Field/Primitive по независимому корпусу
3501 значения, новые YAML, неверные значения и соседнее свойство. Дополнены
случаи nil, строки, похожей на число, и стандартного периода. Nil сокращается
согласно унаследованному договору отсутствия; экспорт восстанавливает xsi:nil.

Общий механизм аномалий выбора исправлен: если raw-конверт не имеет смыслового
значения, его разность рассчитывается относительно XML, полученного именно
из пустого YAML через резервный вариант. Это предотвращает появление лишнего
xsi:nil, когда первоначальный вариант и резервный имеют разные пустые формы.
Перерасчёт применяется только к исключительному raw без смыслового значения.
Обычные значения сохраняют предварительно скомпилированные преобразования.

Приёмка полного `DcsMetadataValue` ещё не завершена. Новый Primitive пока
подключён к проверочному владельцу; прежний `common.dcs-primitive-value`
сохраняет старые входы до подготовки словарей у всех потребителей. Остаются
рабочие владельцы, все режимы и полный договор пустых состояний. Флажок
общего объекта не устанавливается.

Самопроверка универсальности: изменён только общий завершающий шаг выбора;
он оперирует raw-конвертом, резервным вариантом и XML-разностью, без имён
DCS/common. Предметный состав вариантов задаёт сборщик YAML-деклараций.
Матрица расширена внутри существующего теста, отдельные однотипные тесты
на перечисления не добавлены. Подготовка языков вынесена в общий помощник;
существующие сценарии и XML-фикстуры сохранены. Это самопроверка, не независимое
ревью. Проверки на окончательном коде: 54 Rust-теста, архитектура Rust и
TypeScript, отсутствие новых дублей и актуальность сгенерированных YAML прошли.
Полный pnpm test и замеры производительности конвертера не выполнялись.

### 2026-09-26 — Primitive подключён к существующим common и коллекции

`common.dcs-primitive-value` теперь использует `common.dcs-primitive-choice`;
`common.dcs-primitive-values` передаёт те же подготовленные индексы каждому
элементу. Индексы связываются у владельца, типизированные входы передаются
через декларации; в компиляторе и исполнителе условий по именам типов DCS нет.
Обновлены все найденные потребители этих двух common в каталоге деклараций.
Владелец общей матрицы тоже использует public-common, а не обращается к выбору
напрямую. Прежнего отдельного пути Primitive без перечислений больше нет.

Подготовка словарей для проверок вынесена в один помощник с общим поставщиком
фактов; повторная реализация наполнения индексов в каждом тесте не создаётся.
Матрица коллекций расширена перечислением, повторами и неизвестным значением
между двумя корректными значениями. Проверяются обычный YAML для корректных
значений, локальная аномалия, порядок и восстановление исходного XML.
Исходный случай сначала воспроизвёл ошибку: корректный Auto сохранялся как raw;
после подключения деклараций преобразуется в СистемноеПеречисление / Авто.

Полный `DcsMetadataValue` остаётся неотмеченным: ещё не завершены остальные
режимы и автоматическая сборка рабочих владельцев приложения. Подготовка
словарей в проверочном контуре не объявляется готовой инициализацией приложения.

При подключении выявлены и исправлены два общих расхождения обёрток.
Захваченные входы ранее переносились при размещении элемента коллекции,
но не записи: общий `scoped_inputs` теперь используется обоими путями.
Проверка намеренно сохраняет разный порядок входов у владельца и common.
Второе расхождение: отсутствующее значение проекции записи записывалось как
`{}`, хотя пустой объект не является её скалярным значением. Проекция теперь
выводит `null`; для DCS это соответствует существующему `toYAML.ts`, который
сохраняет null. Поэтому public-wrapper для xsi:nil имеет `Значение: null`;
предыдущая проверка прямого выбора с пропуском свойства не считалась приёмкой
публичной обёртки. Изменения относятся к проекции/областям входов, не к DCS.

Итог адресной проверки публичной обёртки: обе матрицы Field/Primitive по
3501 значению, null, стандартный период и неверные значения с соседним полем
прошли. Внутренняя ошибка формы уже помеченной аномалии при XML-импорте
позволяет уточнить границу сохранения до свойства; при обычной валидации
авторского YAML это правило ошибки не подавляет. Ошибки подготовки входов
по-прежнему остаются ошибками инфраструктуры.

Отдельная проверка неверного булева в одиночном владельце Primitive
выявила и подтвердила исправление второй границы уточнения. Исходный XML
сохраняется на границе свойства `Value: !xml/raw`, без фиктивного
`$значение: {}`. Адресная проверка одиночного маршрута прошла.


Уточнение коллекций: первоначальное чтение теперь передаёт неоднозначную
границу повторяющихся XML-элементов существующему уточнению по отдельным
строкам. Ошибка `xml.preservation-shape` больше не прерывает импорт до этого
шага. Окончательный результат по-прежнему проходит проверку восстановления
всего XML. Проверка «Auto, Unknown, Auto» прошла: сохраняются оба обычных
значения, локальная аномалия между ними и порядок строк.

Проверки Primitive выделены в `probe-dcs-primitive-values`: объединённый
пакет параметров DCS достиг 8 418 076 байт при пределе 8 388 608. Предел
не повышен; параметры и коллекции значений собираются независимо.


Самопроверка универсальности: `scoped_inputs` переносит захваченные входы по
связям деклараций и используется записью и коллекцией; имён DCS, Primitive,
перечислений или конкретных полей в нём нет. Уточнение аномалий зависит от
формы записи/коллекции и доказательства восстановления XML. Матрицы проверяют
разный порядок входов, скалярную и полную форму, дополнительное поле, null,
неверные значения и повторяющиеся элементы. Это самопроверка реализации,
а не независимое ревью. Изменения скорости преобразований не измерялись.

не задан. Отрицательная матрица защищает эту границу.

### 2026-09-26 — Primitive: null отдельно от отсутствия

Используется существующее представление: внешняя запись может отсутствовать,
а присутствующая запись может содержать пустое значение nullable-выбора.
Поэтому новый специальный тип null в языке не добавляется. У обычного
Primitive отсутствующее свойство остаётся отсутствующим, а `Значение: null`
создаёт `xsi:nil="true"`. При exportNilValue=true отсутствующее свойство тоже
выводится как nil. false сохраняет обычное поведение. Null не сворачивается
в отсутствие правилом присутствия внешнего свойства.

Общий генератор записей теперь поддерживает условную каноническую форму nil,
как уже поддерживал missing и empty-element. Пространство имён xsi включается
и при отсутствующем теле записи. Никаких имён DCS в этом механизме нет.
Указание отдельного XML-типа в этой форме пока отклоняется: игнорировать его
при генерации нельзя. Переносчик разрешает exportNilValue для Primitive;
для остальных режимов ограничение остаётся до проверки их nullable-договора.

RED→GREEN: отсутствие значения ранее превращалось в лишний raw-конверт;
явное правило присутствия устранило его. Условный nil ранее отвергался стадией
генерации; после общего исправления матрица проверяет `{}` и явный null при
обоих значениях политики. Существующие XML-файлы не изменялись.

Отдельный случай primitive-type-ref.xml (`v8:Type` с текстом `*:Undefined`)
ещё требует сохранения смыслового null, а не только исходного XML. Это
не считается закрытым данным исправлением. Флажок DcsMetadataValue не меняется.


Проверка изменения null/отсутствия: прошли 33 Rust-теста пяти проверочных
пакетов и внутренних механизмов компилятора, 84 теста переносчика, Clippy с
запретом предупреждений, форматирование, три архитектурные проверки и
проверка новых дублей относительно 2af2f299ed8241eac78d4db46b4a8421efe2f8f7.
Самопроверка: генератор различает канонические формы, а не предметные имена;
нового обработчика Primitive в Rust нет. Независимого ревью не было.
Полный TS-набор и замеры производительности не запускались.


### 2026-09-26 — Primitive: условное пустое значение

`common.dcs-primitive-text` описывает XML-тип и исходный текст отдельно от
проецируемого YAML-значения. Только сочетание `v8:Type` с текстом
`непустой-префикс:Undefined` означает null. Такая же строка с `xs:string`
остаётся строкой; другие имена типов не сокращаются. Исходная форма XML
сохраняется общим механизмом аномалий на содержащем свойстве.

Декларация явно задаёт null как пустую форму проецируемого поля. Канонический
nil ограничен отсутствием значения, а не только параметром exportNilValue.
Компилятор поддерживает отсутствующее тело записи при XML nil / YAML null,
проверяемый текстовый default словаря QName и исключает канонические ветви
с условием, уже вычисленным в false. Скалярная проекция передаёт расхождение
контрольного экспорта внешнему свойству: внутри скаляра нет ключа для пометки.
Предметных условий DCS и Undefined в Rust нет.

Приёмка этого изменения выполнена: существующая матрица дополнена
primitive-type-ref.xml, проверками обычной строки и коллекции. XML-фикстуры
не изменены. Это не закрывает весь DcsMetadataValue: остальные nullable-режимы
и полное подключение индексов проверяются отдельно. Флажок не устанавливается.


Дополнение по вложенным составным записям: при экспорте элемента коллекции
его собственная пометка XML ранее читалась, но терялась при использовании
обычной записи в буфер родителя. Исправлен общий путь подготовки: компактные
и составные записи используют один механизм применения пометки своей границы.
Обычные записи продолжают выводиться напрямую; дерево хранится только для
аномалии, через отдельный указатель. Новый независимый признак DCS не вводится.
Матрица теперь требует одну локальную пометку у Undefined между двумя
одинаковыми строками; повторная пометка всей коллекции не допускается.


Проверка блока Undefined завершена: 28 проверок шести Rust-пакетов и
12 внутренних тестов компилятора (всего 40), 84 теста переносчика, Clippy с
запретом предупреждений, fmt, три архитектурные проверки и jscpd прошли.
Отрицательный случай неизвестного XML-типа и локальная пометка null между
повторяющимися строками проверены. Самопроверка универсальности: условия
предметных типов находятся в YAML; подготовка и сохранение границы общие
для компактных и составных записей. Независимого ревью не было согласно
запрету на субагентов. Полный TS-набор и замеры производительности не запускались.

Следующий пункт: null в режимах Color/Font. Добавлена проверка смыслового
null и самостоятельного экспорта без XML-референса; поведение уточняется
в декларациях, а не отдельным обработчиком DCS в Rust.


### 2026-09-26 — Null в режимах Color и Font

Непустое значение и nullable-оболочка разделены декларативно. Оболочка
имеет одно проецируемое поле, XML nil и YAML null означают его отсутствие,
а каноническая форма отсутствующего внутреннего значения — nil. Внешнее
свойство независимо задаёт отсутствие XML/YAML: поэтому отсутствующий цвет
или шрифт не превращается в явно заданный null. В XML nil не добавляется
тип Color/Font: атрибут принадлежит только непустому внутреннему значению.

Общий генератор допускает вложенные проекции записей с их собственными
атрибутами. Структурная проекция сначала формируется как целое YAML-значение;
простой скаляр сохраняет прямую запись. Пометка проецируемого значения
читается как пометка всего значения, а не внешнего ключа свойства.
Невосстановимая внутренняя форма передаётся ближайшей границе свойства.
В Rust нет условий по именам цвета или шрифта.

Переносчик теперь принимает boolean exportNilValue для Primitive, Color и
Font. При true он использует уже проверенное общее правило внешнего свойства
«отсутствует → nil», при false отсутствие сохраняется. Null остаётся
внутренним значением и не сворачивается во внешнее отсутствие. Матрица
проверяет параметры и подключение; общий условный экспорт проверен на Primitive.
Остальные режимы с явным exportNilValue всё ещё отклоняются до их приёмки.
Флажок всего DcsMetadataValue остаётся снятым.


Приёмка блоков Undefined и nullable Color/Font завершена: 40 Rust-тестов
(28 проверок шести пакетов и 12 внутренних проверок компилятора), 84 теста
переносчика, Clippy с запретом предупреждений, fmt, три архитектурные
проверки и поиск новых дублей прошли. Проверены обычные значения, отсутствие,
явный null, локальная аномалия между соседними строками, неверные Font/Color,
неизвестный код/тип/пространство имён перечисления и экспорт без XML-референса.
Самопроверка различает запись с именованными полями и проекцию всего значения;
новых предметных условий в Rust нет. Независимое ревью не проводилось.
Полный TS-набор и замеры скорости/памяти преобразования не запускались.

Остаётся до полного флажка DcsMetadataValue: nullable-договоры остальных
режимов, рабочее подключение индексов и полная приёмка их потребителей.
Эти результаты не означают завершения всего common или миграции проекта.

### Дополнение: внешние nullable-режимы и автоматический перенос

Проверочные владельцы теперь различают отсутствие и `xsi:nil="true"`
для TypeLink, ChoiceParameterLinks, ChoiceParameters, Field, DesignTimeValue
и фиксированных системных перечислений. Для последних приняты обе статические
разновидности из исходных правил: HorizontalAlign и FoldersAndItemsUse.
Неверный nil сохраняется как аномалия свойства, соседние поля не теряются.
Переносчик применяет тот же договор к создаваемым владельцам, а для
SystemEnumeration выбирает nullable-декларацию по имени типа.

После генерации 4482 кандидатных свойств изолированная проекция реального
`dcsParameter.value` со всеми зависимостями и поставщиком словаря прошла
`nkdk-dev declarations compile` и создала 16 Rust-файлов (9 657 987 байт).
Это подтверждает генерацию, но не сборку `rustc` и не полный e2e владельца.
Прошли 84 проверки переносчика, 18 проверок DCS-полей, две проверки словаря
перечислений, Clippy, форматирование, три архитектурные проверки и проверка
новых дублей. Полный `DcsMetadataValue` пока не отмечен в чеклисте:
рабочие владельцы и подготовка индексов в приложении ещё не приняты.

Все девять режимов автоматически сформированного свойства
`MetadataDcsMetadataValue` дополнительно прошли изолированную генерацию
текущим `nkdk-dev` с нужными поставщиками словарей. Объём сгенерированного
Rust по режимам: Color — 4,4 МБ, Field — 1,7 МБ, Parameter — 9,3 МБ,
DesignTimeValue — 1,6 МБ, Primitive — 9,7 МБ, TypeLink — 1,6 МБ,
ChoiceParameterLinks — 1,7 МБ, Font — 0,7 МБ, SystemEnumeration — 0,09 МБ.
Каталоги удалены после проверки. Размеры подтверждают, что общая сборка
этих режимов пока нежелательна; эта проверка не измеряла скорость работы
конвертера и не запускала `rustc` для каждого кандидата.

### Исправление внешнего отсутствия

Сверка с `dcsMetadataValue/toXML.ts` показала ошибку переноса: у шести
режимов с внешней nullable-оболочкой отсутствующий YAML-ключ ошибочно
порождал XML nil даже без `exportNilValue: true`. Теперь отсутствие ключа
остаётся отсутствием по умолчанию и при `false`; при `true` создаётся nil.
Явный YAML null создаёт nil во всех трёх случаях. Это правило выражено
обычной декларацией наличия поля и не меняет Rust-исполнитель по имени DCS.
Матрица переносчика охватывает восемь переносимых режимов и допустимые значения
`exportNilValue`; режим `Parameter` блокируется до проверки кардинальности.
84 проверки переносчика и 25 проверок пяти пакетов DCS прошли до выявления
этого различия; после изменения матрица запущена повторно.
Рабочий маршрут СКД и его поставщики индексов всё ещё не подключены, поэтому
общий флажок `DcsMetadataValue` остаётся пустым.

### Дополнительная проверка Parameter

В исходном TypeScript режим `Parameter` извлекает первый `dcscor:item` из
`ChoiceParameters`; текущая общая декларация преобразует весь список.
Контрольный XML с двумя разными элементами подтвердил расхождение: второй
элемент оказывается в обычном YAML вместо регистрации аномалии.
Универсальная проверка «ровно один элемент» через ограничение на
проецируемую коллекцию сейчас не компилируется (`unsupported_projection_constraint`).
Пробный вариант удалён, чтобы не оставлять нерабочую декларацию. Перед
флажком common нужна общая поддержка кардинальности/ограничения проекции
и повторный round-trip этого случая.
