# Актуальные YAML-значения в источниках фактов — 2026-10-01

Маршрут внешних фактов может задавать `yamlDir`: при YAML → XML источник
читает текущие первичные YAML-файлы этого каталога и получает компактное
представление фактов через ту же скомпилированную декларацию. Старый снимок
не подменяет отсутствующий или изменённый файл. Без `yamlDir` прежний
маршрут сохранённых фактов не меняется; импорт XML также остаётся прежним.

У локального источника `yamlSource: primary` означает чтение текущего YAML
владельца. По умолчанию используется `snapshot`; этот режим нужен для
сохраняемой структуры и неизменных идентификаторов. Разрешённый источник
данных задаётся маршрутом, а имена полей и подготовка вкладов — декларацией.
Рабочая операция передаёт первичный файл в подготовку фактов, не заменяя
его сохранённым снимком после выбора маршрута.

Проверка внешнего источника независимо задаёт старое и новое значение,
меняет YAML повторно и проверяет подготовленный индекс: новое имя доступно,
старого больше нет. Удаление первичного файла или каталога не возвращает
старые данные. Небезопасные пути отклоняются. Локальный источник проверяется
со старым снимком и без снимка; неизвестный режим отклоняется. Старый путь
XML → снимок → факты отдельно сохраняет прежнюю проверку.

Это общий механизм проектной операции; частных веток нумератора в нём нет.
Декларативная проекция значений основы нумератора уже создана из исходных
rules.ts: русские YAML-имена и значения при отсутствии берутся из параметров.
Она не проверяет каноническое сокращение владельца повторно: явно записанное
значение и отсутствие с тем же смыслом дают одинаковые факты. Проверки
сопоставляют исходный YAML основы с XML-источником, затем изменяют boolean
без повторного импорта XML и проверяют все умолчания на пустом YAML.

Сбор скалярных фактов теперь одинаково выделяет объявленные поля из XML и YAML.
Остальные поля остаются для полной проверки владельца; неверный синтаксис
или неверный тип выбранного поля не скрывается. Общая проверка компилятора
содержит вложенное соседнее поле, строгую полную проверку и сохранённую
оболочку !xml/raw; разбор оболочки общий с обычным чтением.

Для полного нумератора ещё нужны UUID основы из источника идентичности и подключение
основной конфигурации к подготовке фактов расширения. Затем — отдельная
проектная проверка, рабочий маршрут и создание новых объектов. Флажок полного
владельца пока не установлен.

Проверено: 26 сценариев numeric-owners, 12 проверок contributions, 34
проверки проектных операций и 11 проверок Node. Clippy изменённых приложения
и компилятора, архитектурные ограничения и поиск новых дублей прошли.
Рабочий каталог после изменения компилятора собран за 4 мин 22 с; текущий
сгенерированный файл — 31 137 162 байта, на 5 269 байт больше предыдущего
сохранённого файла. Ускорение сборки или цель 10× этим этапом не подтверждаются.
Полный TypeScript-набор при параллельной сборке прошёл все проверки значений,
но превысил предел одного теста: 201,29 мс при 200 мс. Повторный полный
запуск без параллельной сборки завершился успешно (`pnpm test`, код 0).


Продолжение: внешние источники поддерживают неизменный UUID из снимка,
направления чтения и явные наборы основы `fromBase`. Общая операция
подготавливает отдельную декларативную проверку и не меняет обратимый
результат по её сообщениям. Новые снимки создаются до их использования
внешними источниками. Проверки проекта: 38 прошли; повторная итоговая проверка тоже прошла. Полный `pnpm test`,
Clippy приложения, 9 проверок Node, архитектурные проверки и поиск новых
дублей завершились успешно. XML-фикстуры не изменены.

Маршрут нумератора получен программно, но рабочее подключение не принято:
его добавление увеличило создаваемый Rust до 35 686 210 байт, выше лимита
33 554 432. Сборка остановилась до тяжёлого rustc. Лимит сохранён, рабочее
подключение убрано; декларации и маршрут остаются кандидатными.
