# Связь плана видов характеристик с объектом основы

В составном кандидате представлены все 65 свойств rules.ts. Полная приёмка
объекта ещё не выполнена, флажок остаётся пустым.

## Что реализовано

Общий адаптер ownerBaseState подключает существующий YAML-договор
borrowed-base к части, которая уже хранит историю состояний. UUID объекта
основы, контроль и уведомление описаны общей таблицей состояний, без нового
преобразователя Rust. История остаётся одной коллекцией: состояния объекта
основы не заменяют соседние состояния длины кода и наименования.

Контекст UUID основы берётся из metadata.base-identities по компоненту и
UUID текущего владельца. Декларативный источник индекса включён в состав
кандидата. Ограничения контроля и уведомления по версии совместимости
выводятся существующим переносчиком реестра допустимых состояний.
Если rules.ts не задаёт YAML-имя runtimeOnly-свойства, используется принятая
общая запись ОбъектРасширяемойКонфигурации.

## Исправление общего компилятора

При составлении объекта правило присутствия состояния наследовалось повторно.
Совпадающее правило ошибочно отклонялось как conflicting_state_presence.
Регрессия добавлена в существующую проверку таблиц состояний и сначала упала.
Связывание теперь разрешает повтор одинакового значения отсутствия и не
дублирует одинаковое условие сокращения. Противоречащий default и неоднозначные
таблицы по-прежнему отклоняются. Названия метаданных в компилятор не добавлены.
Сборщик XML-порядка дополнительно исключает скрытые поля без XML-маршрута;
регрессия state/notice в существующей проверке прошла RED→GREEN.

## Проверки

Native-проверки 4/4: основа, заимствованный объект расширения, собственный
объект расширения и уведомление основы вместе с соседней историей чисел.
Первые три используют старые принятые e2e-примеры; UUID основы извлечён из
неизменной XML-фикстуры. Четвёртый проверяет принятую границу Notify на том же
реальном заимствованном объекте, не изменяя файл фикстуры. Импорт, ожидаемый
YAML и обратное восстановление XML прошли без raw. Сборка узкого набора
43 деклараций заняла 46,61с после добавления ограничений совместимости.

Целый кандидат с замыканием зависимостей также прошёл синтаксическую
проверку и связывание: 237 файлов, 428 развёрнутых деклараций. Большой
сгенерированный Rust-каталог для этого не компилировался.

Проверки связывания Rust: 80/80. Переносчик: 215/215. Поиск новых дублей и
проверка форматирования прошли. Архитектура прошла. Расширенный набор компилятора остановился на ранее
существовавшем падении migrated_parameter_profile_table_reads_e2e_xml:
не объявлено пространство имён schema при восстановлении сохранённого
фрагмента параметра. Оно повторилось при временном снятии текущего
исправления наследования (37,30с); исправление восстановлено. Полный набор
не объявляется прошедшим. Это отдельный открытый дефект.

## Что остаётся

Все 65 свойств подключены, но полный объект не принят: ещё требуются общие
состояния остальных свойств (тип значения, иерархия, допустимая длина кода),
источники и привязки всех входов, профили вложенных коллекций расширения и
полное преобразование владельца с внешними файлами. Наличие всех полей в
кандидате не заменяет эту проверку. Common-чеклист остаётся 56/90.

## Общие состояния булевых значений и перечислений

В ту же историю подключены Hierarchical и CodeAllowedLength. Новый адаптер
ownerStateScalars читает зарегистрированные свойства и использует существующий
декларативный построитель scalar-состояний. Он не выполняет преобразования:
для чтения, записи и проверки компилируются YAML-декларации. Общая коллекция
сохраняет соседние состояния CodeLength, DescriptionLength и объекта основы.

В четырёх существующих примерах расширены проекции неизменённых XML и YAML
фикстур. Исходные ожидания читаются из YAML-фикстур, а не вычисляются новым
конвертером. Проверены обе стороны, round-trip, отсутствие лишних !xml и
экспорт без XML-референса: 4/4. Сборка ограниченного каталога — 37,33 с.

Проверки обнаружили два общих дефекта. При уточнении YAML выбранного варианта
терялся тег выбора: !изменять превращался в обычное значение, после чего
проверка основы ошибочно сообщала base.value.changed. Генератор теперь
восстанавливает объявленный тег после уточнения содержимого варианта.
В старой xmlOrder отсутствует runtimeOnly-ссылка на объект основы. Общий
YAML-договор owner-property-order задаёт её место после имени; явный порядок
rules.ts имеет приоритет. Rust не содержит условия по имени владельца.
Существующая матрица сначала упала на позиции base (62 вместо 4), затем прошла.

Проверки: переносчик 215/215, связывание 80/80, отдельная компилируемая проверка
выбора записи, поиск новых дублей и архитектура прошли. Полная приёмка
владельца остаётся открытой; флажки common и владельца не меняются.
Далее — TypeDescription, включая MultiState, источники контекста и полное
преобразование объектов CF/CFE. Известный независимый дефект пространства
имён DCS пока не устранён; полный набор compiler-tests не объявлен зелёным.

Дополнительно сохранена регрессия на перестановке ссылки основы в конец
Properties: аномалия порядка допустима, но внутри неё должны остаться все
теги !изменять. Контрольный запуск с отключённым восстановлением тегов
прошёл первые четыре случая и упал на пятом с base.value.changed;
восстановленный исправленный генератор прошёл 5/5. XML-фикстура не изменена.
Проверка полной декларации: 245 исходных файлов → 440 развёрнутых деклараций,
синтаксис и связи прошли; большой каталог Rust не компилировался.


Обычный TypeDescription автоматически подключён по регистрации rules.ts к
той же матрице владельца: 5/5 сценариев прошли оба направления, валидацию
и восстановление XML. Сборка ограниченного каталога заняла 40,12 с.
Это не приёмка MultiState.

Следующая проверка записи с состоянием обнаружила общие дефекты компилятора:
после захвата соседнего поля его ограничение попадало в первое свойство,
а буфер выбора варианта терял область пространств имён XML. Исправлено
распределение ограничений по исходному полю; область пространств имён
сохраняется вместе с отложенными событиями. Проверка формы выбора теперь
проходит через проекции записей к списку. Частных условий по имени типа нет.
Матрицы усилены без добавления функций тестов: планировщик 16/16,
связывание 80/80, QName 5/5, низкоуровневые проверки ядра 9/9.
Повторная матрица переносчика — 215/215. Полная приёмка владельца и
MultiState остаются открытыми; быстродействие нового пути ещё не измерено.


Пробная оболочка состояния над записью TypeDescription дополнительно прошла
все пять сценариев этой матрицы (ограниченный каталог, сборка 49,01 с).
Это проверка общего вложения, а не перенос сгруппированного MultiState.
Постоянная компилируемая матрица QName дополнена выбором записи и
переопределением префикса: отключение передачи области пространств имён
воспроизводит ошибку, исправленный путь её устраняет.


Итог проверок этого блока: постоянная матрица QName 4/4, совместная матрица
владельца 5/5, пробное вложение записи 5/5; Clippy ядра и компилятора
(toolchain 1.98.1), форматирование и поиск дублей прошли. Копии области
пространств имён создаются только для событий, читающих QName: конец
элемента и ещё не раскрытый QName-атрибут. Обычные значения их не создают.
Тестовый шаблон запасного варианта вынесен в общий файл.


Устранён ранее мешавший проверкам DCS общий дефект сохранения XML:
писатель получал пространства имён фрагмента, но не его родительского пути.
Восстановление перенесено в общий `Tree::document_at`, который учитывает оба
источника; тот же механизм используется для проекции дочерних документов.
Предметных условий DCS в ядре или генераторе нет. Обычный путь без аномалий
не изменён; замеры его скорости в этом блоке не выполнялись.
Существующий e2e-тест DCS воспроизвёл ошибку до исправления и прошёл после.
Повторная матрица владельца 5/5, ядро и связывание прошли, Clippy и проверка
дублей тоже. Полная приёмка владельца и сгруппированный MultiState остаются
открытыми; флажки чеклиста не изменены.


Дополнительно проверено сокращение одного типа: из CF-примера получена
производная запись с одной строкой `Строка(10)`; исходная XML-фикстура не
изменялась. Обратное чтение такой строки прежде завершалось `yaml.choice-form`.
Общий анализ формы YAML теперь используется и при связывании, и при генерации
выбора: проекция списка наследует разрешённое декларацией сокращение одного
элемента. Вариант, объявленный только с тегом, не получает обычную запись
без тега. Пробная матрица вложения 6/6, связывание 80/80, планировщик 16/16,
QName 4/4, Clippy и проверка дублей прошли. Это по-прежнему не приёмка групп
MultiState и не полная приёмка владельца.

## TypeDescription в общей истории

Пробные оболочки заменены автоматически создаваемыми YAML-декларациями.
Тип значения подключён к той же истории, что длины, иерархия и ссылка основы.
Канонический порядок истории восстанавливается из тегов и сокращается в YAML;
другой порядок остаётся явным. Для свойств с постоянным режимом используется
XML-порядок источника; вычисляемые уведомления сохраняют объявленное место.
Общий построитель истории используется скалярными и составными значениями.

Постоянная матрица теперь содержит 9 сценариев: обычные CF/CFE, уведомление
основы, перестановку поля, одиночный тип, уведомление типа с двумя порядками
истории и неподдерживаемую версию совместимости. Все прошли XML → YAML → XML
и независимые ожидания. При старой версии обычный YAML сообщает нарушение
ограничения, исходный XML сохраняется общим механизмом `!xml/raw`.

Выявлен и исправлен общий дефект записи тега у следующего поля: перед ним
находился разделительный перевод строки, который писатель принимал за пустое
значение. Существующая матрица YAML усилена и прошла 10/10. Переносчик —
215/215, Clippy ядра/компилятора и поиск новых дублей прошли. Ограниченная
пересборка заняла 1 мин 2 с; это не замер скорости самого преобразования.

Корневой Type плана видов характеристик разрешает контроль и уведомление,
но не MultiState. Группы MultiState нужны вложенным реквизитам; их полный
двусторонний договор остаётся следующей задачей. Полная приёмка владельца
не завершена, флажки не изменены, common остаётся 56/90.

## Подключение к полной декларации

Общий сборщик `ownerStateRecords` теперь используется и проверочной матрицей,
и полной сборкой владельца. TypeDescription больше не переносится в полном
владельце вторым обычным полем: его пометки, ограничения версии и вклад в
историю находятся рядом с остальными состояниями. Код преобразования
TypeDescription не копируется в оркестратор.

Существующая проверка подключения сначала обнаружила отсутствие такого поля
в общей истории, затем прошла 5/5. Проверенные ранее девять декларативных
сценариев после выделения сборщика остались побайтно неизменными. Весь
переносчик — 215/215, архитектура — без новых нарушений, дубли — без новых
повторений. Полная декларация с её настоящим источником UUID основы прошла
синтаксис и связывание: 249 исходных файлов. Большой единый Rust-пакет не
собирался; это ещё не полная приёмка XML/YAML владельца.

Параметры common сохраняются у содержимого оболочки, а не у её общего выбора.
Это защищено дополнительным случаем прежней матрицы подключения; ошибка
воспроизведена до исправления. Дополнительные ещё не поддержанные привязки
контекста содержимого блокируют перенос явно и не удаляются молча.
