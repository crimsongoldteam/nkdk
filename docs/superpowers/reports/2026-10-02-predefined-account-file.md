# Предопределённые счета: содержимое XML ↔ YAML

Исходный файл: `e2e/fixtures/xml/cf/ChartsOfAccounts/ПланСчетовВсеСвойства/Ext/Predefined.xml`.
Декларации охватывают имя, код, наименование, вид счёта, забалансовый признак,
порядок, признаки учёта, виды субконто с их признаками учёта, дочерние счета
и UUID через индекс. QName и версия оболочки создаются из `PredefinedRules`
профилем `predefined-account-envelope.yaml`. Данные строки описаны в YAML,
Rust не получает условий по виду счёта, именам свойств или владельцу.

`system.AccountType` используется из общего каталога; его значения не
копируются в новые преобразователи. Проверочный запуск выбирает только эту
декларацию из каталога, сохраняя небольшой размер программы. Английские пути
в ключах признаков и субконто сохраняются по существующему YAML-договору.
Ограничение ключа субконто задаётся декларативным выражением: ссылка на
предопределённое значение плана характеристик с допустимыми именами частей.
Полная проверка существования цели по индексу проекта здесь не принимается.

Ожидаемый YAML и UUID заданы независимо от проверяемого импорта. Добавлен
вложенный случай из тех же неизменённых XML-данных: второй счёт переносится
в дочернюю коллекцию первого в памяти. Его UUID восстанавливается по вложенному
пути индекса. Обратный экспорт без XML-референса проверяет структуру и QName.
Общая матрица содержит 11 обычных случаев справочников, характеристик, видов
расчёта и счетов; по пять отклонений оболочки/булева значения каждого.
Дополнительно проверяются неверный вид цели субконто, неверный текст признака
учёта, лишний атрибут признака и отсутствие вида счёта — для плоского и
вложенного файла. Соседние строки и исходная структура восстанавливаются.

Реальный файл выявил общий сбой чтения: скалярное текстовое поле принимало
атрибут того же элемента за лишнюю XML-форму раньше, чем срабатывал его
объявленный атрибутный слот. Объявленные атрибуты теперь проверяются первыми.
Нейтральный пример коллекции с булевым текстом и ключом-атрибутом прошёл
RED → GREEN; обычные значения обходятся без пометок XML.

Сохранение непреобразуемой строки расширено на любую объявленную XML-запись.
Предыдущая проверка формы «вариант или коллекция» пропускала аномалии
обычного булева текста с атрибутом. Сохранение использует точное вхождение
XML и общий договор диагностик, ошибки входов и конвертера не маскируются.
Обычные строки остаются в своём типизированном представлении; XML сохраняется
только при отклонении. Ограничитель создаваемого кода не ослабляется.

Это приёмка проверочного содержимого файла. Рабочая проектная привязка и
состояния расширения остаются отдельными этапами. XMLRoot без флажка,
common56/90; общую миграцию и цель 10× этот результат не закрывает.

После исчерпания свободного места удалён только воспроизводимый накопительный
кэш `rust/target/debug/incremental` этого worktree и временные результаты
проверочной программы. Также удалены устаревшие дубли исполняемых проверочных файлов; сохранена
последняя версия каждого. Освобождено около 6,8 ГиБ. Исходники, XML-фикстуры
и библиотеки сохранены.

Итоговая проверка: 91 выбранный Rust-тест компилятора и 38 проверок реальных
коллекций/TypeDescription прошли. 13 проверок генератора файловых оболочек,
его проверка воспроизводимости для счетов, строгий Clippy всех целей компилятора,
форматирование и git diff --check прошли. Проверки архитектуры Rust и TS,
проверка новых дублей относительно
`2af2f299ed8241eac78d4db46b4a8421efe2f8f7` и полный `pnpm test` вне песочницы
завершились с кодом 0. Предупреждения о длительности отдельных тестов
остаются предупреждениями, а не подтверждением цели 10×.

Обёртка подготовленного значения сохраняет обычную строку без дополнительного
Box; разрешение Clippy large_enum_variant локально документирует этот выбор.
Все остальные замечания Clippy к созданной обёртке исправлены, без расширения
общих исключений. Независимое ревью всей ветки не проводилось.

Проверка схемы выявила отдельную причину роста памяти: тестовая `jsonschema
0.30.0` разворачивает рекурсивные ссылки в новые поддеревья и сохраняет их.
В ограниченном запуске RSS превышал 1 ГиБ за две секунды даже на старых
малых декларациях. Отсечение неподходящих вариантов схемой не устранило
рост, поэтому экспериментальные изменения схемы отменены.

Обновлена только тестовая зависимость до `jsonschema 0.47.0` и её lockfile.
[История библиотеки](https://github.com/Stranger6667/jsonschema/blob/master/CHANGELOG.md)
описывает устранение повторных узлов рекурсивных ссылок в 0.34.0 и утечки
при освобождении таких проверок в 0.47.0. Полный тот же корпус прошёл за
0,95 с; ограниченный внешний запуск измерил пик RSS 70 448 КиБ. Схема языка
и выполняемый конвертер остались прежними. Ошибка проверки теперь показывает
путь входа и путь схемы без накопления всех больших строк диагностики.

Универсальная оболочка строки также передаёт операции сбора фактов обычному
значению. Непреобразуемая строка не выдаёт выдуманных смысловых фактов.
Проверка вложенных составных строк прошла RED → GREEN.
