# DynamicList: общая граница владельца

Исправлен перенос локальных имён `xsi:type`: объявленное пространство XML по
умолчанию применяется к QName-значению независимо от имени самого атрибута.
Имена с префиксом продолжают использовать его объявление. Частных условий
для DynamicList в компиляторе Rust нет.

Существующее семейство расширено с 8 до 13 сценариев. Новые примеры проверяют
пять исходных булевых свойств вместе внутри Settings, канонические значения
по умолчанию, явно записанные implicit-значения, перестановку полей и неверное
значение с читаемыми соседями. Ожидания взяты из старого data.ts, XML-подмножество
выделено в памяти из неизменного full.xml. Это не приёмка полного списка.

Нативный RED обнаружил общий дефект быстрого пути простых записей: дельты
свойств не восстанавливали порядок всего владельца. Теперь исключительная
дельта документа хранится в зарезервированном месте существующего raw-хранилища.
Она не добавляет поля в каждый обычный объект и не требует изменения декларации.
Чтение оболочки запускается только после отказа обычного чтения YAML;
дерево записи захватывается только после неудачного доказательства восстановления.

При проверке дублей найдена повторная подготовка одного проверочного Rust-примера
для обычного и общего AOT-каталогов. Вынесена в общий тестовый переходник;
оба исходных независимых примера продолжают выполняться.

## Замер обычного пути

Сравнивались оптимизированные release-сборки одного и того же подготовленного
примера до и после включения дельты документа. По 7 чередующихся прогонов,
30 000 операций в каждом, без собственных фоновых сборок во время замера.

| Направление | Медиана до, мкс | Медиана после, мкс | Изменение |
|---|---:|---:|---:|
| XML → YAML | 16,792 | 16,059 | −4,36% |
| YAML → XML | 4,651 | 4,724 | +1,55% |

Диапазоны повторов пересекаются: XML 15,571–17,264 / 15,783–18,264 мкс;
YAML 4,625–4,804 / 4,596–4,886 мкс. Устойчивое существенное замедление
этим замером не установлено. Это небольшой пример в памяти, а не замер
полного проекта, файловой системы или цели 10×. Начальный debug-замер
проводился при проверках и для приёмки скорости не используется.
Сырые результаты: `/tmp/nkdk-list-owner-release-measurements.json`.

## Остаток

Полный DynamicList остаётся без флажка: требуется договор составной ссылки
на основную таблицу, перенос текста запроса в отдельный файл и обратно,
явная сборка YAML-only свойства и учёт исключённого runtime-only свойства.
Прямая ссылка на объект и бинарное копирование ресурса не заменяют эти договоры.

## Проверки

- Нативное семейство DynamicList: 13 сценариев прошли.
- Переносчик и сборка семейств: 67 проверок прошли.
- Общий scalar-record: RED без дельты владельца → GREEN; 12 проверок
  `record_canonical_parameters` / `record_item_inputs` прошли.
- Два прежних примера вложенных аномалий и отсутствующих коллекций прошли
  обычную и общую AOT-сборку после устранения дубля подготовки.
- Clippy для библиотеки компилятора с `-D warnings`, проверка публикации,
  проверки архитектуры TypeScript/Rust прошли; новых дублей относительно
  `91a01277cbd10ccebd70bb0b4e7a32886dcf090f` нет.
- XML-фикстуры не изменялись.

Самопроверка универсальности: обработчик QName не использует имя DynamicList;
дельта документа определяется границей object/record и не проверяет имена
полей либо сочетания предметных типов. Общий регрессионный пример содержит
обычные текстовые поля, а пример DynamicList проверяет их реальное подключение.
Это самопроверка, не независимое ревью.

Заключительный полный `pnpm test` вне песочницы завершился с кодом 0; Rust-сборки одновременно с ним не выполнялись. Журнал: `/tmp/nkdk-list-owner-full-test.log`. Флажок полного DynamicList не установлен.
