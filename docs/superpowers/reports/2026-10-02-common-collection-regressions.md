# Общие коллекции: исправление выявленных регрессий

## Порядок XML-записи

Именованный контейнер и запись непосредственно в него сортировались по пути.
Короткий путь всегда оказывался первым, даже если декларация требовала сначала
дочернее поле. В UserVisible это переставляло Common и Value и создавало лишнюю
аномалию порядка; рекурсивная запись не проходила восстановление YAML.

Общий план компилятора теперь учитывает место самой записи относительно
дочерних ветвей. Каждая ветвь сохраняет общий ранг, поэтому поля общего
контейнера записываются вместе. Имена common и типы метаданных не проверяются,
частные order в YAML не добавляются. Нейтральная проверка защищает пустой путь,
путь родителя и группировку двух полей общего контейнера.

После исправления прежний пакет коллекций дал 24 успешных проверки из 26:
UserVisible и рекурсивная запись прошли. Два оставшихся сбоя исследованы отдельно.

## Два оставшихся договора

У FieldsList единственный пустой элемент обозначает отсутствие значения.
Это уже записано в декларации и соответствует прежнему импорту TypeScript.
Проверка ошибочно требовала другой смысловой результат. Теперь она проверяет
пустое смысловое значение и по-прежнему требует точного восстановления XML.
Фикстуры и сама декларация списка не изменялись.

У ChoiceParameterLinks рабочая декларация ссылалась на обычную строку вместо
уже существующей декларации перевода пути. Поэтому русский путь из e2e
возвращался с английскими обозначениями XML. Восстановлена ссылка на
common.type-link-path с typedXML: true. Отдельные буквальные профили, которые
нужны контекстным преобразованиям, остаются отдельными декларациями;
их генератор уже строит их на основе правильной ссылки. Нового обработчика
или таблицы частных случаев не добавлено.

Итоговые результаты приведены ниже.
Флажки новых common не проставлялись: это исправления существующих договоров.

## Итоговая проверка

Все 26 проверок коллекций, 45 проверок приложения, 16 проверок плана
компилятора и 17 проверок подготовки фактов прошли. Clippy компилятора,
архитектура, проверка формата и поиск новых дублей прошли.
Полный pnpm test после завершения Rust-сборок завершился с кодом 0.
Первый одновременный запуск превысил временной лимит одного LMDB-теста;
при повторном отдельном запуске лимиты не менялись и проверка прошла.
Исходные XML-фикстуры не изменены.
