# Сборка деклараций элементов формы — 2026-10-06

## Результат

`assembleSourceElement` объединяет договор имени/id из регистрации с обычными
свойствами, автоматически перенесёнными из `rules.ts`. Один сборщик обслуживает
все семь проверенных регистраций singleton-элементов. Предметные обработчики
в Rust не добавлены.

`pnpm migration:form-element-assemblies` сохраняет декларации в
`rust/declarations/candidates/form-elements.generated.yaml` и покрытие в
`tests/migration/form-element-assemblies.json`. Режим `--check` проверяет
актуальность исходных файлов, регистраций и обоих результатов. Получено
194 небольшие декларации (243 075 байт), подключены 93 исходных свойства,
15 свойств остаются неподдержанными. Это кандидаты, не полные владельцы и
не подключение всей формы к рабочему преобразованию.

| Регистрация | Подключено свойств | Осталось |
|---|---:|---|
| AutoCommandBar | 4 | childItems |
| TableAutoCommandBar | 4 | childItems |
| ContextMenu | 3 | childItems |
| ExtendedTooltip | 29 | events, виртуальный type |
| SingleSearchControlAddition | 17 | additionSource, contextMenu, extendedTooltip, childItems |
| SingleSearchStringAddition | 17 | additionSource, contextMenu, extendedTooltip |
| SingleViewStatusAddition | 19 | additionSource, contextMenu, extendedTooltip |

Имя/id имеют отдельные входы, чтобы контекст имени родителя не смешивался с
контекстом обычного свойства. Сборщик проверяет соответствие регистрации
исходному объекту, договор отключённого чтения старого name, отсутствие
конфликтующих служебных полей и маршрут размещения. Для элементов коллекции
нельзя автоматически считать itemType XML-тегом: Button и CommandBarButton
имеют общий тег Button; им требуется отдельная проверенная регистрация.

## Общая доработка компилятора

XML-атрибут может иметь декларативное условие выбора обычной формы или отсутствия.
Формы пустого элемента и nil для атрибута запрещены. Если исходный атрибут был
явно записан, а обычный экспорт его опускает, автоматически сохраняется аномалия
формы. Отсутствующий атрибут, который и так восстанавливается отсутствующим,
не создаёт лишнюю аномалию.

Присутствие атрибута запоминается при первом разборе. Дополнительного прохода
по исходному XML для этой проверки нет. Условия превращаются в Rust при сборке;
интерпретатор YAML во время преобразования не используется.

Порядок пары name/id определяется регистрацией идентичности. Старый rules.ts
указывает только name; добавление id после всех остальных свойств приводило к
перестановке атрибутов и лишнему !xml/raw. Это исправлено в сборщике без ослабления
проверки round-trip.

## Дальше

Закрыть events и виртуальный type у ExtendedTooltip, затем автоматически собрать
вложенные singleton-элементы через проверенные связи. Далее общие CommandName,
ButtonParameter, DataPath и AdditionSource, имена из ключей коллекции и семь
вариантов CommandBarChildItems. Полная панель, нумерация новых элементов и полная
форма с её отдельным файлом остаются отдельными условиями приёмки.

## Проверенный договор следующего препятствия: Events

Неизменная `event/__fixtures__/single.xml` содержит
`<Event name="Click">РаспознаваниеДокументаНадписьНажатие</Event>`.
Правило ExtendedTooltip задаёт `click: Нажатие`, поэтому ожидаемый YAML:

```yaml
События:
  Нажатие: РаспознаваниеДокументаНадписьНажатие
```

`multiple.xml` содержит две строки OnChange/Opening; обычная коллекция сохраняет
их порядок. Исходные `types.ts` и `callType.ts` также определяют три режима:
Before → Перед, After → После, Override → Вместо. Это не просто словарь строк:
один ключ события может объединять несколько XML-строк в вложенную YAML-запись.
Обычная строка и запись режимов — разные допустимые варианты значения.

Старый fromXML бросает исключение при повторе одного режима, смешении обычной
строки с режимами и неизвестном callType. По согласованному общему принципу
новая декларация должна задавать нормальные варианты, а механизм сохранения
автоматически фиксировать эти отклонения, включая порядок и повторения. Нельзя
считать события перенесёнными после поддержки только обычной строки из single.xml.
Изолированный перенос Events пока не выполнен; нужен общий обратимый договор
группировки строк, применимый также к другим коллекциям, без обработчика Events
в оркестраторе.
