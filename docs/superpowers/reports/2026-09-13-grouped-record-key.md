# Ключ именованной коллекции внутри группы полей

Генератор теперь умеет вынести поле в ключ YAML-словаря, даже когда оно
хранится вместе с зависимыми скалярными полями составного элемента.
Остальные поля группы записываются обычным способом; их значения по
умолчанию и сохранение аномалий продолжают работать.

Пример: атрибут `token` по умолчанию равен имени. При имени `Первый` и
`token="Первый"` YAML содержит ключ `Первый` без повторения имени и token.
При `token="other"` значение остаётся в теле записи. Если атрибут отсутствовал
в XML, отсутствие сохраняется существующим тегом, а не заменяется значением
по умолчанию при обратном преобразовании.

Расширена существующая матрица коллекций: нормальная группа с совпавшим и
отличающимся атрибутом, отсутствующий атрибут и ошибочное имя. Всего 15
сценариев прошли обе стороны преобразования и проверку YAML. Начальная
проверка воспроизвела отказ компилятора на группе с полем ключа.

Обычный вывод вызывает сгенерированный писатель с номером исключаемого
поля; повторный разбор YAML не добавлен. Существующий путь сохранения
аномалий тоже исключает только ключ, сохраняя остальные поля группы.

Самопроверка универсальности: нет условий по именам предметных объектов,
UUID, common или свойств. Выбор группы и номера поля определяется связанной
декларацией. Независимое ревью не проводилось: действует запрет на субагентов.

Это необходимая часть поддержки служебного XML, но не её завершение.
Отсутствие обычного YAML-сопоставления, группы через ссылки на common и
атрибут предка с глубже расположенным полем остаются отдельными задачами.
Новых полностью принятых объектов нет; common — 19/90.
