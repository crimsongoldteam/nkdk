# Адреса и сохранение вложенного состояния

## Реализованный договор

`yamlField` внутри `logicalAddress.parts` получает настоящее YAML-имя поля
при связывании деклараций. compose не добавляет имя фрагмента, projection
не добавляет техническое поле. Селектор отсутствует в исполняемом Rust:
проверка побайтно сравнивает результат с прежними явными сегментами адреса.
Неизвестное поле и лишние параметры отвергаются при сборке.

Снимок состояния больше не теряет XML-поле, которому нет места в обычном YAML
и которое восстанавливается из индекса. Для такого договора сохраняется
подготовленный XML с внутренним заголовком; обычный YAML и его аномалии
не получают новых служебных полей. Восстановление выполняется через общий
путь снимков. Для вычисляемых значений, не требующих сохранённого состояния,
прежний YAML-снимок сохраняется.

В общих AOT-пакетах таблица имён индексов и переходник ошибок теперь имеют
единственного владельца. Публичные функции явно остаются доступны через фасад.
Это исправляет ранее незащищённое сочетание вложенных вкладов в индекс
с вычисляемым адресом в отдельно собираемом пакете.

## Независимая проверка результата

Нейтральная декларация содержит список, именованную коллекцию и соседнее поле.
Ожидания адресов заданы отдельно от декларации. Проверены:

- одинаковые имена двух строк списка с разными состояниями;
- строковый ключ `"0"` и позиция `[0]`;
- точки, скобки и проценты в YAML-ключе и имени строки;
- поля из compose и прозрачная projection;
- восстановление четырёх значений из снимка без прежних индексов;
- материализация из снимка и обычного сокращённого YAML;
- повтор имени — неоднозначность, а не выбор первой строки;
- отсутствие строк — отсутствие идентичности;
- повреждённый снимок — неполный индекс;
- оба направления обычного преобразования, обычная и общая AOT-сборка.

Первый расширенный прогон нашёл регрессию у предопределённых элементов:
состояние, вычисляемое из принадлежности владельца, ошибочно требовало
XML-снимка. Проверка восстановимости уточнена; прежний реальный договор
внешнего файла снова проходит. XML-фикстуры не изменялись.

## Схема языка

Полный корпус выявил отставание JSON-схемы от уже работающего парсера.
Согласованы внешний файл вместо YAML-ключа, литеральные и полевые сокращения,
`singleton: value` и условия пустых состояний. Взаимоисключение ключа/файла
и отсутствие отдельного `denotes` у полевой проекции проверены отрицательно.
Ошибки вложенной схемы теперь показывают конкретные пути.

предметных имён или условий по common-объектам нет. Независимого ревью не было;

## Дополнительная проверка сокращаемых именованных строк

Матрица вложенного снимка расширена вторым договором: служебное значение
имеет обычный YAML-ключ, но сокращается по собственному индексу. RED выявил,
что одинаковые имена оставляли в YAML-снимке только первую строку; восстановленный
индекс ошибочно возвращал готовое значение вместо неоднозначности.

Выбор XML-снимка для всех именованных коллекций оказался чрезмерным:
две существующие проверки внешних предопределённых данных обнаружили регрессию.
Теперь обратимые именованные коллекции сохраняют прежний YAML-снимок,
а потеря повторов определяется проверкой подготовленного основного XML.
Ошибки чтения/записи не скрываются под сохранением XML. Основной путь
convert_file не менялся; повторная проверка выполняется только при сохранении
или материализации внутреннего снимка. Внешние документы не объявляются
полностью покрытыми сравнением основного XML.

В той же матрице добавлено соединение восстановленного индекса с
OperationIdentity: существующие идентичности остаются заимствованными,
новые именованная и позиционная строки получают независимые эталонные UUID,
повтор имени не разрешает создавать новую идентичность. Эталоны вычислены
независимо по принятому SHA-256-договору, а не из результата Rust-конвертера.

Окончательный результат: полная contributions-матрица40/40, затем повторная
расширенная матрица inline/shared AOT после передачи ошибок и добавления правки
соседа/повторной материализации —GREEN. Clippy компилятора и ядра всех целей,
архитектурные проверки, воспроизводимость6 библиотечных и17 рабочих деклараций,
поиск новых дублей и полный pnpm test —GREEN. Две проверки MCP с внешней
информационной базой остаются штатно пропущенными. XML-фикстуры не менялись.
Новых common-флажков нет:56/90. Стоимость дополнительной проверки внутреннего
снимка отдельно не измерялась; прежние замеры обычного convert_file не являются
замером этой подготовки или полной операции.

## Проверка полной сборки FormAttribute

Первичный emitCandidates по полному FormAttributeRules и актуальному
candidateCatalog, без подключения профилей коллекции, распознаёт12/21 свойство.
Это предварительный этап, а не доказательство готовности полного объекта.

| Свойства | Результат первичного переноса | Что проверять следующим |
| --- | --- | --- |
| id | unsupported-parameters:xmlOnly | Подключение существующего form-attribute-identity.yaml и подготовленного индекса номеров |
| name | owner-name-profile | Существующее восстановление ключа элемента из регистрации коллекции |
| columns, additionalColumns | hidden-scalar-default-required | Передачу существующих деклараций коллекций и контекста в полном сборщике; не применять скалярный путь |
| chart, ganttChart, flowchartContext, spreadsheetDocument, planner | unsupported-common | Доступность и подключение полных деклараций специальных вариантов Settings |

Имя, номер и колонки уже имеют проверенные общие механизмы. Переписывать их
по этому предварительному отчёту нельзя: следующий шаг —полный автоматический
сборщик с профилями восстановления и реальной регистрацией коллекции.
Неизвестные специальные варианты нельзя обходить аномалией отсутствующего
обработчика. Доказательство DynamicList через одно свойство FormAttribute
остаётся отдельным от полной сборки всех его21 свойств.

## Подключение колонок по реальным правилам

Проверка полного emitCollections с существующими профилями сняла блокировки
имени и служебного номера. Остались семь свойств элемента: две коллекции
колонок и пять специальных Settings; отдельно остаются параметры коллекции
реквизитов и её размещение/проектные зависимости. Все пять Settings используют
одну существующую TS-фабрику SettingsFragment со строковым XML-значением.
[Проект общего договора](../specs/2026-10-10-xml-fragment-values-design.md)
подготовлен для согласования, представление fragment ещё не реализовано.

mapCollectionReference теперь сопоставляет fromYAML:false с чтением явно
предоставленной полной декларации коллекции вместо старой сборки дочерних
элементов. Пустой defaultValue:[] соответствует её обычному пустому значению.
Соответствия записываются в parameterEquivalences. Неизвестные параметры,
fromYAML:true, непустой default и выключение toYAML остаются блокировками;
обычный mapProperty без полного коллекционного дескриптора не изменился.

В существующую formColumnCases матрицу добавлены два случая. Их свойства
получены sourceProjection непосредственно из FormAttributeRules, а готовые
обычные и дополнительные колонки подключаются ссылками. Ручного повторения
правил колонок и изменений Rust-движка нет. Нормальный случай проверяет
XML → независимый YAML → XML, а повреждённый ID сохраняется аномалией.
Оба проверяют правку Тип: Строка на Строка(10) с независимым изменением
Length в XML: аномалия ID не должна поглотить изменение соседнего типа.

Нативная проверка33 деклараций прошла оба сценария; сборка заняла14,77с.
65 проверок переносчика, архитектура и поиск новых дублей прошли.
Это подключение двух свойств, а не приёмка всех21 свойств FormAttribute;
флажки common56/90 остаются прежними.

Полный pnpm test после изменений переносчика прошёл отдельно от Rust-сборки;
две проверки MCP с внешней информационной базой штатно пропущены.
Повторный поиск дублей после обновления документов также не выявил новых дублей.
Общий XML-фрагмент остаётся проектом до согласования спецификации.
