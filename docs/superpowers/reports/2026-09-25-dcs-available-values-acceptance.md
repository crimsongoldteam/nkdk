# Приёмка AvailableValues

`common.dcs-available-value` описывает одну строку с необязательными `Значение` и `Представление`; `common.dcs-available-values` описывает их упорядоченный список. Обе стороны преобразования и схема выводятся из YAML-деклараций. Значение повторно использует `common.metadata-value`, представление — `common.dcs-local-string-type`; отдельного преобразователя `AvailableValues` в Rust нет.

На неизменённых XML-примерах `strings.xml` и `nilAndBoolean.xml` проверены XML → YAML → XML, строковые и булевы значения, представление и `xsi:nil`. Строка с `xsi:nil` становится `{}`, а новый YAML без XML-референса восстанавливает `xsi:nil` и булево значение. При неверном булевом тексте общий механизм помечает только соответствующую строку `!xml/raw`; соседняя строка остаётся обычным YAML, исходный XML восстанавливается. Схема списка содержит два необязательных поля строки.

При переносе `AvailableFields` обе матрицы объединены в `rust/crates/compiled-rules/tests/dcs_lists.rs`, проверочный пакет — `nkdk-probe-dcs-lists`. Добавлена регрессия пустого корня `<Root/>`: общая коллекция применяет сохранённую XML-пометку и при отсутствии смысловых строк, поэтому корень восстанавливается.

Проверки: отдельная пробная сборка и её тест, связанные пакеты скаляров и последовательностей, Clippy, `pnpm type-check`, обе архитектурные проверки, `pnpm duplicates -- --base 2af2f299ed8241eac78d4db46b4a8421efe2f8f7` и полный `pnpm test` прошли. В основном e2e-корпусе вхождений `availableValue` нет, поэтому наблюдаемый XML-договор проверен на исходных примерах старого правила; приёмка полного DCS-владельца ведётся отдельно.
