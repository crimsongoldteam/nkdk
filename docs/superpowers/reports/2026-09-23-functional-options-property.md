# FunctionalOptionsProperty: общий договор и перенос кандидатов

Общая YAML-декларация `common.functional-options-property` описывает список
`Item` без предметного обработчика Rust. Пустое вхождение сохраняется как
пустая строка; порядок и повторы не сворачиваются. Отсутствующий и пустой
контейнер проходят общий контрольный экспорт как разные формы XML.

Переносчик распознаёт все три вхождения `FunctionalOptionsProperty` из
`FormAttributeRules`, `FormAttributeColumnRules` и `FormCommandRules` и
выпускает их как кандидатов с ссылкой на одну декларацию. Проверка Rust
сверяет обычный, пустой и повторный элементы и независимый пример из
существующей пары XML/YAML формы обработки. Исходные фикстуры не изменены.

Это ещё не полная приёмка common: кандидаты имеют относительный XML-корень,
полная сборка владельцев не подключена, а проверка существования целевой
функциональной опции пока остаётся в TypeScript. Флажок чеклиста не меняется.

Проверки блока: 65 проверок переносчика, 27 Rust-сценариев коллекций,
`pnpm type-check`, полный `pnpm test`, архитектурные проверки, точечный
Clippy и поиск дублей относительно `0b7e81e2a`.

Отдельно проверен следующий `InputByStringFields`: его сокращение требует
построить список составных ссылок из зависимых длин стандартных реквизитов.
Текущий компилятор не умеет порождать составной элемент внутри вычисляемой
коллекции. Экспериментальное изменение удалено; следующий шаг — общий
типизированный конструктор элемента, затем повторная проверка на одном и двух
стандартных реквизитах. Частный обработчик `InputByStringFields` в Rust не нужен.
