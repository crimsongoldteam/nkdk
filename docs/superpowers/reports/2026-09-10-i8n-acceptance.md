# Приёмка I8nText: декларация и Rust

Дата: 2026-09-10.

## Завершённый договор

Единственный предметный исходник — [i8n-text.yaml](../../../rust/declarations/common/i8n-text.yaml). Из него компилятор получает XML → YAML, YAML → XML, проверки значений и структурную JSON Schema. Выполнение не вызывает TypeScript. Декларация подключена к рабочему каталогу через три [проверочных владельца](../../../rust/declarations/probes); произвольные сочетания параметров проверяются компиляторным набором.

Покрыты все 16 сочетаний preserveEmptyXML, excludeIfEqualNameYAML, skipEmptyToXML и typedXML: отсутствие, пустой контейнер, физический пустой перевод, nil, xsi:type, строка, карта, сокращение имени, иностранные и служебные языки, неизвестные языки, повторы и порядок. Пометки выводятся из структуры и ограничений декларации. Отдельного предметного реестра аномалий нет.

Сохранение формы XML включается только после доказанного расхождения контрольного экспорта. `$xml` содержит необходимые отличия от обычного экспорта; null удаляет указанный атрибут. Окончательный кандидат повторно читается и проверяется. Валидация YAML проверяет оболочку без XML-экспорта. Обычный путь не строит дерево raw.

## Доказательства

- 256 сочетаний профиля и сценария: точное ожидаемое содержимое YAML, принятие пометок и восстановление XML. [Результаты Rust](../../../tests/migration/i8n-rust-acceptance.json) сохраняют исходные хеши и сравнение с [наблюдениями TS](../../../tests/migration/i8n-full-round-trip-observations.json). Ожидания заданы независимо в `matrix_expected`, а не получены из результатов Rust.
- 12 независимых нормативных случаев `i8n-text` проходят через команду корпуса.
- 52 свойства Synonym существующих Catalog/Document из e2e: преобразование в обе стороны, валидация, независимое сравнение XML и проверка неизменности исходных файлов. [Результаты](../../../tests/migration/i8n-e2e-acceptance.json), [воспроизводимая проверка](../../../tests/migration/checks/i8n-e2e.py).
- Проверены лишние и неверно расположенные пометки, повторные ключи, служебный код вместе с неизвестным языком, неверные входы, повреждённая raw-оболочка, изменение сохраняемой формы и структурная JSON Schema обычного/сворачиваемого профиля.
- 126 Rust-тестов workspace, Clippy workspace и сгенерированного кода, fmt, проверки архитектуры и отсутствие новых дублей относительно `8e09a28cf` прошли. Полный `pnpm test` ранее прошёл на этой ветке; в этой порции TS не менялся и полный набор повторно не запускался.

## Зафиксированные исправления относительно TS

В 186 случаях YAML совпадает с наблюдаемым TS побайтно. Остальные 70 относятся к следующим исправлениям:

| Случай | Количество | Результат |
|---|---:|---|
| Пустое первое вхождение и повтор | 16 | Принятые пометки пустоты/повтора, корректная нумерация; перевод не теряется |
| Нарушенный порядок | 16 | Пометка карты выводится из ограничения и принимается на этой границе |
| Совпадение имени с иностранным переводом | 8 | Основной перевод восстанавливается из имени без лишней копии в raw |
| Физический пустой перевод | 8 | Восстановление при skipEmptyToXML без потери исходного узла |
| Пустой контейнер | 6 | Восстановление физической оболочки |
| Типизированная пустая оболочка | 6 | Восстановление оболочки и xsi:type |
| nil | 6 | Восстановление исходного xsi:nil |
| Только совпавшее имя | 4 | Отсутствующий xsi:type записан отличием; смысл восстанавливается из имени |

Все 34 исторических отказа TS при round-trip в этой матрице устранены. Эти результаты реализуют согласованные сохранение исходного XML и исправление ошибок в Rust, не разрешают новые предметные области raw.

## Границы приёмки

Принят двусторонний интерфейс I8nText. Enterprise — отдельная проекция, как ранее определено в спецификации; её исходники сохраняются в машинном реестре для последующего переноса. TS-внутренний помощник создания текста из строки также не является отдельной операцией этого интерфейса. Прикладные владельцы и FormattedI8nText переносятся отдельно; их флажки не закрываются готовностью I8nText.

JSON Schema описывает структуру обычного YAML; контекстные проверки регистрации языков, порядка и пометок выполняет Rust. Неподдержанная структура XML отвергается, а не скрывается через raw. Проверка 52 свойств не является полным e2e-преобразованием проекта. Ускорение 10× и сокращение памяти 10× здесь не измерялись.
