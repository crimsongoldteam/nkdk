# Декларативный профиль FillValue: проверенный объём

`common.fill-value-profile` описывает соседние `Тип` и `ЗначениеЗаполнения`
одним YAML-договором. Переносчик `rules.ts` переносит это условие вместе с типом,
даже если исходные свойства определены в разных фрагментах. Rust-компилятор
использует общие выражения и не проверяет имя `FillValue`.

Отсутствующий YAML для нестрокового реквизита восстанавливает `xsi:nil`.
Явные числовой ноль и начальная дата остаются в YAML: сокращение их до
отсутствия смешало бы `nil` и типизированное XML-значение. Для единственного
строкового типа пустая строка сокращается и восстанавливается как строка.
Пустая фиксированная строка считается допустимым неявным значением до проверки
её длины. Нестандартная XML-форма должна определяться общим механизмом аномалий,
а не отдельным обработчиком этого свойства.

Приёмка этого шага: 40 независимых случаев `FillValue` из существующих e2e
источников прошли XML → YAML → XML без референса и Clippy. Общий набор 169
договоров также прошёл. Проверка генерации декларации реквизитов документа и
42 проверки переносчика прошли. Полный `FillValue` ещё не принят: не завершены
декларации стандартных реквизитов и подключение всех семейств владельцев к
рабочему Rust-преобразованию. Флажок `commonObjects/fillValue` остаётся пустым.
