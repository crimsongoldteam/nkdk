# Декларативный профиль FillValue: проверенный объём

`common.fill-value-profile` описывает соседние `Тип` и `ЗначениеЗаполнения`
одним YAML-договором. Переносчик `rules.ts` переносит это условие вместе с типом,
даже если исходные свойства определены в разных фрагментах. Rust-компилятор
использует общие выражения и не проверяет имя `FillValue`.

Отсутствующий YAML для нестрокового реквизита восстанавливает `xsi:nil`.
Явные числовой ноль и начальная дата остаются в YAML: сокращение их до
отсутствия смешало бы `nil` и типизированное XML-значение. Для единственного
строкового типа пустая строка сокращается и восстанавливается как строка.
Пустая фиксированная строка считается допустимым неявным значением до проверки
её длины. Нестандартная XML-форма должна определяться общим механизмом аномалий,
а не отдельным обработчиком этого свойства.

Приёмка этого шага: 40 независимых случаев `FillValue` из существующих e2e
источников прошли XML → YAML → XML без референса и Clippy. Общий набор 169
договоров также прошёл. Проверка генерации декларации реквизитов документа и
42 проверки переносчика прошли. Полный `FillValue` ещё не принят: не завершены
декларации стандартных реквизитов и проверка всех типов реквизитов на реальных
e2e-проекциях. Флажок `commonObjects/fillValue` остаётся пустым.

Дополнительная проверка компилятора: если для типизированного значения
объявлено условие сокращения YAML, которое генератор ещё не умеет выполнить,
сборка выдаёт ошибку. Ранее такое условие могло молча игнорироваться.

Повторная сверка с `tests/migration/rules-candidates/manifest.json`: из 24
исходных свойств `fillValue` переносчик выпустил 23 кандидата. Единственный
заблокированный — `StandardAttributeDescriptionRules.fillValue`: его
`defaultValue` вычисляет пустую ссылку из списка владельцев справочника;
для расширения действует другое правило. Простое удаление этого вычисления
из кандидата изменило бы экспорт YAML → XML. Кандидаты реквизитов остаются
вне рабочего каталога (`compiled-rules/build.rs` исключает весь каталог
`declarations/candidates`), поэтому число 23 не является числом подключённых
владельцев. Для закрытия флажка нужны декларация этой политики и независимый
round-trip всех типов реквизитов; полная рабочая сборка владельцев теперь
принимается отдельно, по решению разработчика от 2026-09-22.

Дополнительно проверены все 10 применимых видов обычных реквизитов на неизменённых
e2e-парах. Для поля внешнего источника исходный YAML уже содержит `!xml/raw`;
общий Rust-договор сохраняет XML и записывает ту же аномалию с полными именами
пространств имён. Это выявленное различие представления проверяется отдельно.
Ресурс куба не обладает свойством `FillValue`: ошибочное наследование правила
удалено, а сам ресурс исключён из перечня применимых видов. Отсутствие этого
свойства не является аномалией и не требует `!xml/raw`.

Для стандартных реквизитов добавлена короткая декларация явного значения,
общая для `Owner`, `Parent` и `Code`; три независимых e2e-случая прошли
XML → YAML → XML без XML-референса и Clippy. Вычисляемое значение по умолчанию
для `Owner` при основной конфигурации теперь проверяется отдельно: короткий
договор вычисляет пустую ссылку из владельца и восстанавливает XML после
сокращения YAML. Для расширения та же декларация сохраняет `xsi:nil` без
создания пустой ссылки. Другие политики стандартных реквизитов и подключение полного
правила ещё не перенесены. Их нельзя считать закрытыми этими случаями.

Предыдущая выборочная проверка охватила 48 случаев `FillValue` совместно;
обратимое преобразование и Clippy прошли. Случай `Owner` в расширении прошёл
отдельно. Полный `pnpm test`, типы TypeScript, архитектурные проверки Rust и
TypeScript и контроль новых дублей также прошли. Это подтверждает описанный
объём, но не снимает оставшиеся ограничения приёмки common-объекта.

Следующий пакет проверок стандартных реквизитов охватил 17 случаев на
неизменённых e2e-основах. Короткая декларация выводит предупреждение для
запрещённого значения, значения неверного типа, превышения длины текста или
числа и ссылки вне списка владельцев. Для одного владельца пустая ссылка
сокращается, для двух остаётся явной; при отсутствии владельцев исходное
значение сохраняется вместе с предупреждением. Из реального реквизита `Ref`
проверен допустимый `xsi:nil`. Пакет прошёл XML → YAML → XML без референса и
Clippy. Политики пока подаются в договор как входные данные; автоматическая
привязка к декларации владельца и проверка всех политик ещё не закрыты.

Теперь переносчик статически читает общие объявления стандартных реквизитов и
объявления владельца. Тип кода, длины и список владельцев берутся из того же
неизменённого e2e XML, что и проверяемый `FillValue`. Это проверено на
справочнике и документе; дополнительно проверена фиксированная длина кода.
Договор оформлен как повторно используемый фрагмент и составлен с полем имени
стандартного реквизита без частной ветки Rust. Всего 22 случая стандартных
реквизитов прошли XML → YAML → XML без референса и Clippy. Фрагмент включён
в рабочий каталог Rust, но маршруты владельцев к нему ещё не подключены.
Сборка `nkdk-compiled-rules` с ним и без него даёт одинаковые 32 308 543
байта сгенерированного `generated.rs`: невостребованный фрагмент не раздувает
производственный код. До предела 32 МиБ остаётся примерно 1,2 МиБ; при
подключении владельцев потребуется повторный замер и, возможно, сокращение
повторной генерации.

Итоговая отдельная приёмка common-объекта: совместно прошли 66 случаев,
охватывающих 94 свойства, все 10 применимых обычных e2e-семейств и
представителей всех объявленных политик стандартных реквизитов. Оба
направления проверены без XML-референса; Clippy и полный `pnpm test` прошли.
`commonObjects/fillValue` отмечен в чеклисте по согласованному разделению
приёмки. Полные правила владельцев и их маршруты к рабочему фрагменту
проверяются отдельно; этот результат их не закрывает.
