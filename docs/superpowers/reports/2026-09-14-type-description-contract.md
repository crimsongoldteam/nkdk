# TypeDescription: договор переноса и общие ограничения

Статус: точные числа в текстовых шаблонах реализованы; TypeDescription ещё не принят.
Это зависимость StandardAttributeDescription и MetadataCommand в плане полного
родительского перечисления. Исследование не добавляет принятых объектов.

## Что требуется сохранить

| Исходная форма | Смысл YAML и обратное восстановление |
|---|---|
| `v8:Type`, `v8:TypeSet` | Имена типов, простые и составные ссылки; выбор XML-группы зависит от декларации типа и наличия имени объекта |
| `v8:TypeId` | UUID типов, включая повторы; не смешивать с распознаванием имени типа |
| StringQualifiers | Длина и переменная/фиксированная строка: `Строка`, `Строка(20)`, `ФиксированнаяСтрока(20)` |
| NumberQualifiers | Разрядность, дробная часть, знак: `Число`, `Число(15, 2)`, `ПоложительноеЧисло(15, 2)` |
| DateQualifiers | `Дата`, `Время`, `ДатаВремя` |
| Один тип / несколько | Скаляр / последовательность в YAML; порядок и повторы не теряются |
| Пространство имён типа | Имя XML определяется пространством имён и подготовленными данными; исходное написание префикса не является смысловым именем |
| Параметры свойства | allowedTypes, preserveEmptyXML, addTypeDescriptionAttributeToXML, declareTypeNamespaceXML сохраняются при автоматическом подключении |

Квалификаторы в XML общие для соответствующего типа в коллекции, а в YAML
включаются в текст элемента. Поэтому независимая замена каждого XML-узла
таблицей названий недостаточна. Проверка состава типов также относится к
коллекции, а не только к отдельному имени.

Исходный TypeScript различает обработку BinaryDataQualifiers при импорте и
экспорте: импорт их не читает, экспорт для base64Binary добавляет нулевую длину
и Variable. Это требует отдельного примера сохранения формы XML, а не молчаливого
копирования потери данных. Неизвестные типы и несовместимые сочетания в Rust
обрабатываются по принятому договору аномалий, даже там, где старый TS бросает
исключение. Числовые значения не проходят через Number или parseInt.

## Установленные ограничения компилятора

1. `generate/text_pattern.rs::Codec::resolve_parts` первоначально разрешал только
   текст, таблицы текста, boolean и перечисления. Ограничение устранено для
   обычного точного decimal, уже существующего скалярного типа языка.
2. Метод `pieces` первоначально возвращал только заимствованные строки.
   Числовое форматирование создаёт строку, поэтому простого снятия запрета
   недостаточно. Для шаблона с числом реализован массив заимствованных
   и вычисленных частей без копирования обычных текстовых частей.
3. Для составного слота добавлена поддержка вложенного текстового шаблона
   с обеими текстовыми формами. Вложенные ограничения и входы пока явно
   отвергаются при генерации: их нельзя молча потерять. Исключение для
   завершающей текстовой последовательности ещё не даёт общей поддержки
   последовательности внутри слота. Это мешает TypeLink: путь поля плюс суффикс.
4. Поддержка этих слотов сама по себе ещё не решает перенос общих квалификаторов
   к элементам последовательности. Сначала проверить существующие выражения и
   проекции, затем расширять общий механизм только при доказанном пробеле.

Не добавлять ветвления по TypeDescription, TypeLink, именам XML-узлов или числу
их полей в компилятор. Предметные таблицы и условия остаются в декларациях.
Не заменять неподдержанный обычный тип строкой или raw ради приёмки владельца.

## Порядок реализации и приёмки

- [ ] Реализовать независимость XML- и YAML-представлений записи: XML record
  с несколькими дочерними узлами должен поддерживать YAML text-pattern.
  Обычный путь отдельной записи реализован: общий план сохраняет XML-маршруты,
  текстовый декодер заполняет ту же типизированную модель полей, текстовый
  кодировщик пишет строку из этой модели. Промежуточный YAML mapping не строится.
  Подключение общей записи как свойства через `plan/routes.rs::record_usage`
  теперь допускает Mapping и TextPattern. Структурные аномалии компактной
  записи сохраняются оболочкой строки и проверяемым XML-патчем, в том числе
  при размещении внутри свойства.
  Для TypeLink проверить `xr:DataPath` плюс `xr:LinkItem`, типизированный
  DataPath и DCS-форму `dcscor:value`; для TypeDescription — общие
  квалификаторы XML и текстовые элементы YAML. Не создавать промежуточный
  полный YAML mapping ради повторного разбора в строку.
- [x] Поддержать точный decimal в текстовом шаблоне общим механизмом;
  проверить чтение и запись, большие числа, неверный токен, конфликт разделителя.
- [x] Проверить тот же механизм внутри коллекции и при сокращённом шаблоне;
  сохранить заимствование обычного текста, не добавлять повторную сериализацию.
- [ ] Поддержать вложенное текстовое значение с проверяемыми границами;
  применить к TypeLink и параметризованным описаниям типов без частного Rust-кода.
- [ ] Описать общие квалификаторы и их включение в элементы YAML;
  проверить повторы типов с согласованными и конфликтующими параметрами.
- [ ] Выпустить таблицы имён из статических исходных данных, сохранить
  параметры подключения, проверить пространства имён и подготовленные индексы.
- [ ] Подключить TypeDescription в реальные стандартные реквизиты и команды;
  проверить оба направления на e2e и восстановление без XML-референса.

## Перенос тестов

Старые проверки не удаляются. Ниже соответствие групп исходных проверок
будущим данным общей матрицы; оно не означает, что новые проверки уже написаны.

| Источник в commonObjects/typeDescription | Что переносится |
|---|---|
| fromXML.test.ts | Группы типов, повторные UUID, пустое/сложное содержимое, префиксы; проверка однократного чтения остаётся проверкой механизма |
| toYAML.test.ts | Системные перечисления, составные пути, внешние источники данных; исключения для неизвестного заменяются проверками согласованных аномалий |
| toXML.test.ts | Политика имён и пространств имён, параметры свойства, квалификаторы, экспорт изменённого значения без зависимости от референса |
| parseYAML.test.ts | Формы строк и чисел, составные значения; числовые ожидания уточняются по договору точных чисел |

На уровне общего механизма проверять типизированные части и их сочетания один
раз. На уровне свойства — пути, параметры и подключение. Ожидаемые XML/YAML
брать независимо от нового генератора. Нельзя подтверждать корректность только
round-trip: оба направления могут одинаково ошибаться.

## Проверка универсальности

В этом блоке выполнена самопроверка исходного кода, не независимое ревью.
Изменён общий генератор текстовых шаблонов и его потребители в последовательностях.
Числовая часть владеет вычисленной строкой, текстовая заимствует существующую.
Чисто текстовые шаблоны сохраняют массив ссылок. Вложенные текстовые шаблоны
поддержаны без контекстных входов и ограничений; их передача и отдельное
XML-форматирование числового слота ещё не реализованы.

В существующую исполняемую матрицу генератора добавлены восемь случаев:
большое точное число, дробное отрицательное число, неверный токен, конфликт
границы, коллекция с большим числом, неверный элемент коллекции, сокращение
с восстановлением текстового поля и несовпавшее значение этого поля.
Сгенерированный Rust компилируется и выполняет оба направления, проверку YAML
и восстановление XML. Новых функций тестов нет. Проверки архитектуры Rust
и новых дублей относительно 645c02892 прошли.
После поддержки чисел полный набор `nkdk-rule-compiler`: 143 проверки прошли. Clippy для всех целей
этого пакета с `-D warnings`, форматирование и `git diff --check` прошли.
Полный тест проекта и e2e родительского перечисления в этом блоке не запускались.
Полная поддержка TypeDescription и родительского перечисления не заявляется.

Для вложенных шаблонов дополнены существующие матрицы `generate` и
`text_pattern`: вложенное точное число, неверное внутреннее число, конфликт
внешнего разделителя, два элемента коллекции, неверное число во втором элементе
и явный отказ от неподдержанной вложенной проверки. Все четыре функции тестов
этих матриц прошли, включая компиляцию и выполнение сгенерированного Rust.

## XML-запись и текстовая форма YAML

Добавлена `record-text.yaml` для общего договора из двух полей: текста и
точного числа. В существующей исполняемой матрице проверены XML → независимый
ожидаемый YAML `alpha(9007199254740993)`, валидация и восстановление XML из
этого YAML. Отдельная проверка плана защищает сохранение XML-маршрутов при
отсутствии YAML-ключей. Прошли шесть проверок библиотеки компилятора и две
проверки матрицы генерации, Clippy, архитектура Rust и поиск новых дублей
относительно 60a9a9d47.

Этот путь пока не используется декларациями TypeLink и TypeDescription.
Остаются пропуск необязательного суффикса, передача
контекста и вывод отметок нарушенных смысловых ограничений. Нельзя принимать common
по успешному обычному примеру: его набор отклонений пока не защищён.

Общая оболочка `raw::Document` расширена на нетегированные скалярные значения.
В существующем тесте оболочек проверены строка, точное большое число, null
и пустая строка с независимым XML-патчем. Неизвестные и повторные поля оболочки
по-прежнему отвергаются. Оболочка подключена к текстовой записи: патч вычисляется
относительно XML, восстановленного из смысловой строки, и проверяется обратным
экспортом. Если строка не представляет повреждённое значение, смысловая часть
оболочки — null, а XML сохраняется патчем. Это не обычная YAML-форма null.

Проверены неверное число, отсутствующее поле, лишний атрибут, повтор поля,
конфликт разделителя и изменение известного значения при сохранении лишнего
атрибута. Неизвестное структурное содержимое восстанавливается отдельно;
известные поля по возможности остаются доступны для редактирования. Обычный
YAML проходит один разбор, полный разбор оболочки выполняется на исключительном
пути. Новый полный прогон компилятора: 144 проверки прошли.

## Компактная запись внутри свойства

Одна декларация записи используется как корень и как значение свойства.
Размещение меняет XML-пути и границу патча, но сохраняет типы полей и общий
событийный читатель YAML. Обычная строка пишется непосредственно в буфер
владельца; промежуточный YAML-словарь и повторный разбор не нужны.

В существующую матрицу сгенерированного Rust добавлены ожидаемая строка
`Link: alpha(9007199254740993)` и пять отклонений: лишний атрибут, неверное
число, пропуск поля, повтор поля и конфликт разделителя. Лишний атрибут
проверяется также после изменения `alpha` на `beta`. Патч относится к `Link`,
а не к внешнему `Root`; записанный целиком контейнер не создаётся повторно.

Это самопроверка общего механизма, а не независимое ревью. В компиляторе
нет новых условий по TypeLink, TypeDescription или названиям их свойств.
Атрибутные поля с неявным значением теперь поддержаны; прикреплённые
условные XML-атрибуты всей записи, необязательный суффикс, вложенный путь
и смысловые проверки ещё требуют завершения.
Оба common остаются без флажков приёмки.

Проверки этого блока: полный набор `nkdk-rule-compiler` — 144 проверки;
после удаления промежуточного буфера повторно прошла исполняемая матрица
генерации. Clippy `--all-targets --no-deps -D warnings`, архитектура Rust,
поиск новых дублей относительно `2d218021a`, форматирование и `git diff --check`
прошли. Полный `pnpm test`, реальные e2e этих common и замеры 10× не запускались.

## Неявные поля компактной записи

Поле, отсутствующее в текстовом шаблоне YAML, восстанавливается обычным
планом зависимостей из его объявленного YAML-значения по умолчанию. Текстовый
шаблон нумерует только свои части, сохраняя отдельные индексы полей записи;
номер скрытого поля больше не сдвигает значения видимых частей.

В матрице проверен атрибут `revision` перед текстовым и числовым полями:
`current` восстанавливается без аномалии, `older` и отсутствие атрибута
сохраняются как патч. Во всех случаях остаётся смысловая строка `alpha(2)`;
изменение на `beta(2)` сохраняет первоначальную форму атрибута. Условное
исключение видимой части пока явно отвергается: молча игнорировать `omitWhen`
нельзя. Для скобок вокруг необязательного суффикса нужна явная группа частей.
Это расширение не добавляет принятых common в чеклист.

После поддержки неявных полей полный набор компилятора снова прошёл:
144 проверки. Clippy со строгими предупреждениями, архитектура Rust,
проверка новых дублей относительно `7ac54a886`, форматирование и проверка
пробельных ошибок также прошли. Реальные TypeLink/TypeDescription ещё
не подключены этим блоком, их флажки остаются снятыми.
