# Зависимости источника индекса по направлению чтения

Проблема: источник XML объявляет индекс для последующего восстановления
скрытого поля из YAML. Прежний `fact_plan` включает этот индекс в зависимости
импорта, образуя ложный цикл «источник → собственный индекс → источник».

`plan/input_dependencies.rs` определяет входы чтения и проверки источника
по направлению. Учитываются восстановление отсутствующих/пустых значений,
ограничения соответствующей фазы, вклад в индексы и дочерние привязки.
Простой слот может передаваться без чтения; вычисляемая привязка сохраняет
зависимости её вычисления. Специализации, уже использующие область входов
владельца, также сохраняют зависимости.

Новый сгенерированный вход `fact_plan_for_sources` принимает пары
`(EntryId, Direction)`. Потребители по-прежнему зависят от всех привязанных
индексов. Прежний `fact_plan` сохраняет консервативное поведение для вызывающих
сторон, которые не передают направление. Оба используют один построитель
графа, одну проверку циклов и общий бюджет рёбер.

Для ещё не разобранных специальных представлений, сокращений, нормализации
и ресурсов зависимости не отбрасываются: остаются все объявленные входы.
Это может оставить лишнее ребро, но не выдаёт преждевременно готовый индекс.
Условия канонической формы также пока учитываются консервативно.

Проверка скомпилированного Rust использует отдельную запись и словарь двух
объявленных записей. Импорт XML создаёт индекс без готового входного индекса;
независимый экспорт YAML возвращает правильные скрытые идентификаторы.
YAML-источник с зависимостью от собственного ещё не построенного индекса
по-прежнему образует ошибку цикла. Проверен и нулевой бюджет рёбер.
Существующие XML-фикстуры не изменялись; расширена общая матрица генератора.

Совместная проверка добавлена и к автоматически выпущенной коллекции:
имя из ключа словаря, скрытый идентификатор из индекса и сокращение I8nText
работают вместе для двух элементов. Источник индекса получает собственные
объявленные параметры (языки); ранее запускатель всегда передавал ему `{}`.
Запускатель проверяет граф по направлениям и обходит источники в его порядке.
Публикация промежуточных индексов между зависимыми источниками пока не добавлена.

Прошли 207 Rust-тестов, 59 сценариев коллекций, 26 проверок инструмента
переноса, Clippy всего пространства и отдельного каталога миграции,
архитектурная проверка Rust и форматирование. Найденный повтор обхода
ограничений устранён через общий `LinkedConstraint::expressions`, без
исключения из проверки дублей.

Это часть подготовки идентичности, не полная приёмка UUID или семейства
перечисления. Автоматическое описание собственной/базовой идентичности и
публикация зависимых индексов остаются в плане; новых флажков объектов нет.
