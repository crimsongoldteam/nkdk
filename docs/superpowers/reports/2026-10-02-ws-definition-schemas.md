# WSDefinitionSchemas: декларативные файловые маршруты

Договор common перенесён в `fragment.ws-definition-schemas` и рабочую
сборку `resources.ws-definition-schemas`. Одна декларация задаёт оба
направления: `Ext/<полное имя>` ↔ `XSD/<полное имя>`. Копируются исходные байты,
без преобразования содержимого и без новых тегов аномалий. Компилятор не изменён.

Общее перечисление файлов используется также существующей подготовкой
страниц справки. Режимы полного имени и сравнения расширения без учёта регистра
передаются данными; прежние значения по умолчанию сохранены. Повторяющийся
код выбора существующего корня вынесен в одну функцию. Частных условий
по WSReference, XML-корням или common-типам в общих слоях нет.

Проверена единая матрица: отсутствующий каталог, несколько файлов, пустой
файл, смешанный регистр расширения, соседний WSDL, вложенный каталог,
ограничения количества и длины имён, параметры общей подготовки, удаление
XML-каталога до обратного переноса, удаление и добавление текущего XSD.
Новые имена и байты берутся из текущего каталога, ранее подготовленный план
остаётся неизменным.

В e2e нет отдельных `.xsd`. Проверено отсутствие таких файлов у шести
реальных CF/CFE-владельцев. Для положительной проверки побайтного переноса
использованы существующие WSDefinition.xml в временных `.xsd` файлах.
Это проверка непрозрачного копирования, а не реальный корпус отдельных XSD,
проверка схем или загрузки в 1С. Исходные фикстуры не изменялись.
Полная сборка WSReference принимается отдельно.

Проверки Rust: 57 тестов приложения; форматирование; Clippy приложения
с `--all-targets --no-deps -D warnings`. Стилистические предупреждения
сгенерированных зависимостей остаются прежним отдельным ограничением.
Проверки архитектуры rules, общей архитектуры и Rust, а также поиск новых
дублей относительно `2af2f299ed8241eac78d4db46b4a8421efe2f8f7` прошли.
Полный `pnpm test` повторно завершился с кодом 0; сообщения о целевых
10 мс являются предупреждениями и не выданы за подтверждение цели скорости.
Первый прогон под нагрузкой сборки остановился на существующем ограничении
времени XML-worker (290,37 мс), без изменения функционального ожидания.
