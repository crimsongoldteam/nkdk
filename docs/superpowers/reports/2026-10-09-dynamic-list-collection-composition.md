# Совместная декларация коллекций DynamicList

Обычная сборка объекта теперь подключает подготовленные коллекции тем же
`mapCollectionReference`, который используется внутри строк. Поля, входы,
импорты, привязки и пространства XML не имеют отдельного обработчика DynamicList.

`configurationIndexAddressing: yamlPath` сохраняется как требование операции.
Без его выполнения полная сборка блокируется. Проверочный профиль может явно
отложить его, но это не означает приёмку объекта в проекте.

В существующий набор добавлены три сценария: совместные коллекции и внешний
QueryText; отсутствие коллекций; неверное значение при сохранении соседних
полей. Совместный пример взят из неизменённой формы ДинамическийСписок:
10 Field, один CalculatedField, семь Parameter. Ожидания YAML взяты из старой
фикстуры и ранее проверенных семейств, а не из результата нового конвертера.

Подготовленная публикация содержит 40 сценариев и 13 деклараций; повторная
генерация и граф всех зависимостей проверены. Требования трёх коллекций
сохранены и после публикации.

## Проверки

- 65 проверок сборщика/коллекций: пройдены, включая независимое переименование
  и раздельную передачу одноимённых входов разных типов.
- Все 271 проверки переносчика: пройдены.
- Архитектура rules и TypeScript, новые дубли, git diff --check: пройдены.
- Нативные сценарии совместной работы, отсутствия и неверного значения: все три пройдены.
- Общая проверка `pnpm test`: не пройдена; в прежнем режиме rules все 5258 функциональных проверок зелёные, но превышены лимиты времени подготовки и нескольких тестов.

Полный DynamicList остаётся без флажка: этот блок подключает выбранные пять
свойств, а остальные свойства и обязанности проектной операции принимаются
отдельно. Число полностью принятых common-объектов этим блоком не меняется.

Выявлен и исправлен общий пропуск: пустые коллекции не должны создавать
ключ YAML. Обратный договор пустого списка и условие его сокращения
выведены через существующие presence/exists, без специального Rust-кода.

Ограничение сборки: проверочный каталог из 149 деклараций требует 1617
пакетов AOT. Первое компилирование заняло 17 мин 44 с, повторное — 49 с;
после очистки старых файлов запускатель пересобрался за 30 с. Генерация
также остаётся длительной. Это замеры проверочного каталога, а не скорости
конвертера. Нехватка диска при обработке исполняемого файла устранена
очисткой старых файлов сборки; исходные файлы и библиотеки сохранены.

## Устранение накладных расходов проверок

Общий запуск выявил две повторяемые проблемы существующих runtime-тестов:
5,4 с подготовки при лимите 3 с и 73–83 мс в проверке большого XML при
лимите 50 мс. В этом тесте каждый из более тысячи узлов вызывал одинаковый
expect. Теперь все узлы по-прежнему проверяются, результаты проверяются одним
утверждением; время крупного случая снизилось до 45–47 мс.

Для runtime-unit выбран стандартный vmThreads: отдельный VM-контекст для
каждого файла, один worker и ограничение его памяти 256 МБ. Подготовка
снизилась до 162 мс, весь набор unit — до 6,38 с. Все 722 unit и 33
интеграционных теста прошли с прежними лимитами. Интеграционные тесты
сохраняют прежний режим запуска. Возможные особенности встроенных модулей
между VM-контекстами учитываются ограничением применения unit-тестами.

После изменения теста и настройки штатно обновлены inventory, extraction,
collection-links и candidates. Правила преобразования TypeScript и
XML-фикстуры не менялись: 224 сравнения правил совпали, ошибок разбора нет.
Двенадцать проверок операций, прежде упавших на старых хешах, прошли.

Ограничение старого migration:contracts на прямые пути Form устранено.
Построитель проверочных примеров теперь принимает полный относительный
XML-путь: например, Attributes/ConditionalAppearance. Общие оболочки
собираются один раз, соседние поля не захватываются, порядок исходного XML,
атрибуты оболочек, пространства имён и пути QName сохраняются. Пересечение
путей родителя и потомка отклоняется, отсутствующий потомок не создаёт
пустую оболочку. XML-фикстуры не менялись. Проверка на настоящей форме
документа прошла RED→GREEN; все15 проверок выборки зелёные.
Штатные migration:contracts, attachments и families снова выполняются:
275 независимых случаев,556 деклараций;160 готовых включений,6 блокировок.
Это обновление проверочных данных, а не полная приёмка новых объектов.

Проверка vmThreads для rules отклонена: 382,95 с вместо 114,07 с и две
ошибки сравнения ArrayBuffer между контекстами. Эта настройка к rules
не применена. Прежний запуск rules повторён отдельно: все 5258 тестов
прошли функционально, однако ограничения времени остались нарушены.
Поэтому общая проектная приёмка этого блока пока не отмечена завершённой.
Оставшиеся группы проверены отдельно: 3166 интеграционных тестов прошли.
Нативные LMDB-группы функционально прошли, но их запуск остановился на
лимите файла importConfigurationExtension: 7424 мс при лимите 2500 мс.
Воспроизводимость working-family, отсутствие новых дублей и diff--check
подтверждены после обновления снимков.

Повторный адресный запуск fromXMLToYAML.test.ts:143/143 прошли,
файл147 мс, setup16 мс, прежние лимиты соблюдены. Замедление этого файла
в полном наборе зависит от накопленной нагрузки процесса; функциональная
ошибка конвертера этим измерением не обнаружена. Общий порог не изменён.

Заключительная приёмка: повторный полный pnpm test завершился с кодом0
(`/tmp/nkdk-nested-source-project-test.log`). Старые лимиты соблюдены:
5258 unit rules —19,64с, setup1,26с; нативный файл импорта расширения
—1296мс, обе LMDB-группы прошли;3166 integration rules прошли.
Предыдущие отказы по времени сохранены выше как история наблюдений:
этот результат не доказывает постоянство времени на любой нагрузке.
Все272 проверки переносчика,66 архитектурных проверок rules, граф
зависимостей и3 Rust-проверки зелёные; новых дублей нет.
Публикация воспроизводима:13 деклараций и40 проверочных случаев.
Четыре пункта плана этого блока завершены. Полный DynamicList и56/90
common не изменены: остаются остальные свойства и проектные обязанности.
