# Рабочие потребители InputByStringFields

## Результат

Из исходных правил автоматически выделены восемь деклараций свойства и
восемь существующих сочетаний с именем. Все используют те же фрагменты,
common и индексы реквизитов, состояний и числовых значений. В Rust нет
нового обработчика InputByStringFields, вида объекта или отдельного поля.
Эти проекции не являются полной сборкой владельцев.

Две рабочие библиотеки компилируют потребителей заранее; общий интерфейс
проверяет совпадение каталогов и единственность регистрации. Бюджеты
пакетов не повышались: основа 30,17 МиБ (лимит 32), источники 5,10/5,10
МиБ (лимит 8), потребители 5,69/6,18 МиБ (лимит 8).

## Проверки

Матрица 24 реальных CF/CFE читает текущие YAML после импорта и удаления XML,
передаёт подготовленные индексы потребителю и проверяет XML → YAML → XML
и валидацию. Изменение типа реквизита на ЛюбаяСсылка и удаление реквизита
из копии первичного YAML дают !xml/invalid; восстановление Строка(10)
возвращает обычную запись. XML восстанавливается при каждом варианте.
Сохранённые сведения не обновляются при этих правках.

Для сравнения YAML используется уже существующий запускатель событий:
он сохраняет требования к тегам, порядку, повторам и различию пустоты/отсутствия;
!изменять и !изменять null означают одно пустое значение. Фикстуры не менялись.

31 договор с текущими YAML-источниками передаётся в существующий проверочный запускатель
через готовую рабочую библиотеку вместо компиляции отдельного каталога
для каждого случая. Входы и ожидания сохраняются; изменяются только
ссылки YAML-источников на соответствующие принятые проекции. Остальные
XML-сценарии сохраняются в исходном кандидатном наборе из 93 примеров:
XML и текущий YAML имеют разные формы описания типа и не подменяют друг друга.
Два независимых примера DataProcessor не являются InputByStringFields.

Команда: pnpm test:migration:input-by-string:working. Запускатель working-check
принимает любой файл договоров; специального исполнения для common нет.
Обычный режим отдельной компиляции кандидатов остаётся доступным.

## Приёмка

Приняты 14 проверок генерации, 31 рабочий договор и 55 тестов приложения
(45 фактов, один CLI, девять ресурсов), включая матрицу 24 CF/CFE и правки YAML.
Полный pnpm test, проверка типов, три проверки архитектуры, форматирование
и поиск новых дублей прошли. Common отмечен целиком: итог 55/90; полные
владельцы не отмечаются по этой приёмке.

Clippy написанного вручную приложения и компилятора прошёл командой
`cargo clippy --offline --locked -p nkdk -p nkdk-rule-compiler --all-targets --no-deps -j1 -- -D warnings`.
Прогон с проверкой сгенерированных зависимостей обнаружил замечания к стилю
(пустые else, лишние фигурные скобки, возврат временной переменной); его
успешным не считаем. Поведение генерации проверено сборкой и договорами.
Измерения 10× и пика памяти выполнения не входят в эту приёмку.

## Самопроверка универсальности

Компилятор и ядро в этом блоке не менялись. Общий интерфейс выбирает пакет
по зарегистрированному идентификатору, а генератор получает потребителей и
фрагменты из исходных деклараций и связей compose/imports. Подготовка индексов
и рабочий проверочный запускатель не ветвятся по имени common или владельца.
Те же данные проверяются отдельно как простое свойство и сочетание с именем.
Это самопроверка, не независимое ревью.

Весь исходный корпус из 93 сценариев был принят в предшествующем блоке
чтения CFE. Текущая проверка подключения добавляет 31 рабочий сценарий и
матрицу 24 настоящих CF/CFE; XML-сценарии исходного корпуса не объявляются
повторно проверенными рабочим запускателем.
