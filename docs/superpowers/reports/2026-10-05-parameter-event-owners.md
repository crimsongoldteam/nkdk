# Подписка на событие и параметры: полная приёмка

Приняты `MetadataEventSubscriptionRules`, `MetadataSessionParameterRules`
и `MetadataFunctionalOptionsParameterRules`: соответственно 10, 8 и 8 свойств
автоматически собраны из `rules.ts` в YAML-декларации и подключены к рабочему
Rust-каталогу. Все зависимости и источники индексов подключены; неподдержанных
свойств нет. Отдельные обработчики этих объектов в Rust не добавлялись.

Общая таблица файловых владельцев проверяет 49 неизменных XML CF/CFE,
включая 20 новых: подписка — 2/4, параметр сеанса — 3/6, параметр
функциональных опций — 2/3. Для новых объектов проверены независимые YAML,
восстановление XML после удаления источника, контекст расширения и создание
нового объекта со стабильным UUID. Общий маршрут приложения сравнивает
независимые YAML для 31 файла CF и 45 файлов CFE и выполняет обратный экспорт.

Приёмка обнаружила различие пустого значения и отсутствия. `<Source/>`
без объявленного значения по умолчанию означает `Источник: []`, отсутствие
`<Source>` означает отсутствие поля. Если `rules.ts` явно задаёт пустой XML
как значение по умолчанию, его сокращение сохраняется: пустой тип параметра
команды не добавляет поле YAML. Исправлен общий адаптер `TypeDescription`,
зависимые декларации повторно созданы генераторами. Сравнение YAML вынесено
в общий тестовый помощник, используемый быстрой и полной матрицами; новых
тестов на каждое свойство нет. Существующая матрица переносчика защищает оба
варианта пустого значения.

При повторной генерации найден одинаковый общий модуль в двух наборах.
Генератор реквизитов документа ссылается на уже зарегистрированную декларацию,
если идентификатор и содержимое полностью совпадают; конфликт отвергается.
Глобальная проверка повторных идентификаторов остаётся строгой.

Прошли проверки: приложение — CLI 1, факты 46, ресурсы 11; существующая
матрица реквизита справочника — 16 сценариев; переносчик — 222 проверки,
включая 45 проверок преобразования правил; файловая граница — 3 и Clippy;
повторная генерация, архитектура правил, общая и Rust-архитектура, полный
`pnpm test`, поиск новых дублей относительно
`91a01277cbd10ccebd70bb0b4e7a32886dcf090f` и `git diff --check`.
Первый полный прогон остановился в очистке временного каталога теста пакетного
запуска (`ENOTEMPTY`); повтор без изменения кода завершился успешно.
XML-фикстуры и лимиты тестов не изменены. Штатные пропуски тестов полного набора
сохранились.

Актуальные пакеты владельцев создают 4 888 967 и 8 142 490 байт Rust при
неизменном лимите 8 МиБ. Последняя пересборка приложения после изменения
связанных деклараций заняла 5 минут 5 секунд до тестов; это не холодная сборка
и не замер скорости преобразования. Цель 10× этим блоком не подтверждается.
Самопроверка универсальности выполнена; независимого ревью без субагентов
не проводилось. Три флажка выставлены; следующий пакет требует разделения
AOT-каталога до добавления новых профилей.
