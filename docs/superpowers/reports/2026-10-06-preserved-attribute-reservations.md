# Резервирование номеров из сохранённого XML

## Реализовано

Общий Rust-сборщик читает выбранный атрибут из обычного XML, уже читаемого
потока XML-событий, сохранённого дерева, поправки элемента и поправки отдельного
атрибута. Все эти формы передают один набор заимствованных событий. Исходный
XML повторно не создаётся; значения атрибутов не копируются обходчиком.

Профиль задаёт QName атрибута, исходную область, QName границ новых областей
и предел глубины. Потомки наследуют ближайшую область; после выхода из узла
восстанавливается родительская. Одинаковое локальное имя в другом пространстве
имён не меняет область. Предметных имён форм, свойств и пространств в ядре нет.

`TextFactsBuilder::reserve_attributes` передаёт значения прямо в существующий
числовой индекс. Номер проверяет прежний `reserve_number`: исторические
повторы не создают новые записи, неканонический текст не переинтерпретируется.
Ошибка чтения, предела глубины, привязки области или бюджета оставляет весь
целевой индекс неготовым; частичный список нельзя использовать для выдачи id.

У поправки учитываются только явно сохранённые атрибуты. `null` означает
удаление, метаданные `#order` не являются XML-узлами. Неизменённые значения
нужно получать из обычного/сохранённого источника: частичная поправка не
заменяет всю исходную форму. Порядок обхода поправки не задаёт порядок выдачи
новых номеров — резервирование работает с множеством занятых значений.

## Проверки

В существующие матрицы ядра добавлены три самостоятельных договора:

1. Общий обход XML/событий/дерева/поправок: наследование, возврат в родительскую
   область, namespace, повторы, удаления, поправка атрибута и предел глубины.
2. Прямая передача в индекс: непрозрачные потомки и отказ от частично
   подготовленного индекса при ошибке источника или привязки.
3. Независимые ожидания на трёх исходных формах и отдельном примере параметров.

| Исходный XML | Следующие номера: элементы / реквизиты / команды / параметры |
|---|---|
| `e2e/fixtures/xml/cf/CommonForms/ExtendedTooltip/Ext/Form.xml` | 3 / 1 / 1 / 1 |
| `e2e/fixtures/xml/cf/CommonForms/CommandBar/Ext/Form.xml` | 1 / 3 / 2 / 1 |
| `e2e/fixtures/xml/cfe/all-extension/CommonForms/InputField/Ext/Form.xml` | 1 / 2 / 1 / 1 |
| Отдельный XML с параметрами 1 и 2 | 1 / 1 / 1 / 3 |

Для каждого примера проверены обычный XML, захваченное дерево и сохранённая
поправка. Исходные фикстуры не менялись. Пример расширения содержит `BaseForm`:
его номера также резервируются. Проверочный счётчик подтверждает отсутствие
вызовов XML-писателя при обходе. Адаптер существующих XML-событий вызывает
источник ровно один раз.

Прошли все 108 проверок ядра с `test-probes`, Clippy всех целей ядра с
`-D warnings`, проверка архитектуры Rust и поиск новых дублей относительно
`91a01277cbd10ccebd70bb0b4e7a32886dcf090f`. Первые проверки отсутствующих API
были красными, затем прошли. Полный каталог не пересобирался: его генератор
и декларации этим блоком не изменены; это не проверка рабочего подключения.

Полный `pnpm test` прошёл вне песочницы после завершения Rust-проверок
(код выхода 0). Прежние пропуски набора и предупреждения о целевых 10 мс
сохранены. Журналы: `/tmp/nkdk-attribute-core-final.log`,
`/tmp/nkdk-attribute-clippy-final.log`, `/tmp/nkdk-attribute-full.log`.

## Граница результата

Готов обходчик и его связь с индексом. **Автоматическое подключение к полному
маршруту формы ещё не выполнено.** Нужно вывести профиль и привязки из данных
деклараций, вызвать сборщик для сохранённых границ, передать все источники до
публикации индекса и проверить повторное открытие проекта. Наличие номера
внутри `BaseForm` проверено; приоритеты идентичности основной/текущей формы
и общий логический адрес реквизита остаются отдельной задачей.

Флажки объектов не меняются. Нового интерпретатора YAML и частных обработчиков
форм не добавлено. Проверка универсальности выполнена самостоятельно;
это не независимое ревью и не подтверждение целевых 10×.
