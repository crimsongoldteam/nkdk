# Все скалярные состояния выбранного владельца

## Что сделано

Переносчик выбирает помечаемые числа, перечисления и boolean из исходного
реестра состояний, включая общие профили и изменения по версиям.
У нумератора к тому же шаблону подключены NumberAllowedLength,
NumberPeriodicity и CheckUnique. Их состояния, пустые пометки, умолчания
и восстановление InternalInfo проходят через обычные YAML-декларации.
Никаких обработчиков нумератора, названий его свойств или разбора версий
в Rust не добавлено.

Текстовый индекс основы сохраняет точную запись числа, имя перечисления
или true/false для boolean. Булево представление выводится обычным
декларативным условием. Историческое имя индекса
metadata.base-owner-numbers пока сохраняется.

Компилятор исправлен для умолчания проекции булева значения: он выбирает
написание YAML из декларации boolean. Общая проверка покрывает оба значения,
пропущенное поле и явную пометку с произвольными написаниями
Включено/Выключено. Это проверка механизма, а не отдельного объекта.

## Проверки

- Исходная проверка обнаружила отсутствие NumberAllowedLength в сборке.
- Реальная сборка обнаружила отсутствие булева умолчания проекции в компиляторе.
- Проверка полноты сценариев обнаружила отсутствие проверки запрещённых
  пометок новых скаляров собственного нумератора; сценарии добавлены
  программно для всех выбранных скаляров, без отдельного списка свойств.
- Все 13 числовых сценариев с реальными e2e XML прошли, включая дополнительные
  проверки boolean и перечислений у собственного объекта.
- Девять проверок contributions компилятора прошли, в том числе общий
  договор проекционного boolean.
- Полный pnpm test завершился с кодом 0. Проверки архитектуры TypeScript
  и Rust, Clippy с запретом предупреждений, форматирование и поиск новых
  дублей относительно 2af2f299ed8241eac78d4db46b4a8421efe2f8f7 прошли.
- Проверка воспроизводимости четырёх генераторов и существующий составной
  сценарий документа с InputByString прошли.

XML-фикстуры не изменены. Примеры старых версий, посвящённые одному числу,
явно исключают остальные скаляры из проверяемого YAML: это сохраняет
однозначную причину диагностики при расширении состава фрагмента.
Отдельные основные сценарии по-прежнему содержат все выбранные свойства.

## Граница результата

Это принятый общий скалярный фрагмент, а не полная приёмка нумератора.
Числа уже проверяют наличие и сравнение значения основы; такой договор
для вновь подключённых boolean и перечислений ещё нужно завершить.
Также остаются идентичность, имя, синоним, комментарий, принадлежность,
ссылка на расширяемый объект и их совместная история. Проектный маршрут
добавляется после проверки целого XML, а не частичного набора Properties.
Флажок нумератора остаётся пустым.
