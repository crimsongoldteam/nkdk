# Восстановление служебного поля через common

Продолжение [единого плана](../plans/2026-09-13-unified-conversion-plan.md).

## Общий договор

Правило отсутствия скалярного значения может быть описано один раз в common.
Связывание переносит его в область поля владельца, подставляя объявленные
входы и параметры. Это выполняется до проверки полноты XML/YAML-представлений
и построения зависимостей полей. Собственное правило поля имеет прежний
приоритет над правилом common.

Вычисляемое восстановление проверяется тем же механизмом, что и явное
правило поля. Специального обработчика UUID в компиляторе нет. Удалён отдельный
обход выражений для скалярных входов: используется существующая подстановка
привязок. Старые ограничения неподдержанных форм не заменяются успешным
пустым результатом.

## UUID

Добавлены `common/uuid.yaml` и проверочная проекция `probes/metadata-uuid.yaml`.
Common восстанавливает значение по отдельным компонентам ключа индекса:
компонент, UUID владельца, вид объекта, имя. XML-значение остаётся непрозрачным
текстом; ограничения формата GUID не добавлены. YAML-ключ UUID отсутствует
в проекции владельца.

Это ещё не полная приёмка UUID: создание идентификатора нового объекта,
автоматический выпуск всей коллекции и четыре состояния связи с основой
остаются в плане. Чеклист сохраняет 19/90, UUID не отмечается готовым.

## Проверки

- Существующая проверка сгенерированного Rust расширена: явное восстановление
  поля, восстановление из common и тот же common в двух элементах словаря.
  XML-источник не зависит от собственного индекса, YAML-восстановление зависит.
- Матрица идентичности рабочего каталога дополнена девятью существующими
  EnumValue из e2e-инвентаря: независимый YAML-экспорт и отсутствие UUID в
  обычном YAML после импорта. Ожидаемый XML строится из сохранённых данных
  инвентаря, не из результата проверяемого конвертера.
- Все 208 Rust-тестов и Clippy workspace со всеми целями прошли.
- 61 сценарий коллекций и 26 проверок инструмента переноса прошли; новых
  дублей относительно `37acdae1f` нет, архитектура Rust проверена.

## Автоматический выпуск UUID

Инструмент переноса распознаёт исследованный профиль `uuid` с `_uuid` и
`xmlOnly: true`. Он формирует ссылку на common, XML-атрибут без обычного
YAML-ключа, имя из ключевого поля элемента, вид из имени XML-элемента и
типизированные общие входы компонента/владельца/индекса. Коллекция автоматически
получает вклад в `metadata.own-identities`. В отсутствие корня отдельная
проекция свойства остаётся заблокированной; фиктивный XML-корень не создаётся.

Существующая синтетическая матрица дополнена двумя автоматически выпущенными
элементами с UUID и сокращёнными синонимами. UUID не переписан вручную в
проверочный YAML. Проверяются независимый экспорт и контрольный round-trip.

Свежий выпуск по проверенным хешам `rules.ts` сохраняет 0/142 полных связей.
У EnumValue остаются только `extendedConfigurationObject` с `runtimeOnly` и
`collection-owner-contributions-required`. Сам вклад идентичности не закрывает
остальные связи владельца. Полную готовность UUID и семейства это не означает.

После полного прогона добавлена обязательность подготовленной идентичности:
при отсутствии ключа `require` возвращает техническую диагностику подготовки,
а не успешный XML без UUID. Дополнительно прошли целевая матрица identity,
все 61 сценарий коллекций и Clippy этого сгенерированного каталога. Создание
новой идентичности должно заполнить индекс до вызова преобразования.
