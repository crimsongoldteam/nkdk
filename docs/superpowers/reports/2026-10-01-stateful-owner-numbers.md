# Числовые свойства владельцев и состояния XML

Подготовленный индекс `metadata.property-state-membership` подключён к
кандидатным операциям `InputByString` восьми видов владельцев. Индекс читает
полный неизменённый XML текущей конфигурации или расширения; связанные
реквизиты основы по-прежнему читаются отдельным источником по UUID.
Индекс состояний основы не подменяет состояния расширения.

## Декларативный договор

`common.stateful-number` выбирает обычную или изменяемую числовую запись.
Число остаётся точным десятичным. XML-состояние выбирается по ключу
`owner / property / mode`, а YAML-пометка `!изменять` самостоятельно
восстанавливает выбранный вариант. Значение, равное заданному умолчанию,
может быть записано как `!изменять null`. Обратное чтение возвращает точное
значение, а не отсутствие числа.

Владелец декларативно восстанавливает список состояний из пометок.
Порядок вычисляемого списка задан порядком числовых свойств в XML;
список с другим порядком, повторами или отличающимися строками остаётся
явным. Ограничение декларации проверяет согласованность явного списка
и пометки. Отдельные функции для числовых свойств не добавлены.

Составная операция `Name` + `InputByString` задаёт `xmlOrder`: сначала
`InternalInfo`, затем имя и свойства в `Properties`. Это необходимый
порядок физического XML, независимый от порядка вычисления зависимостей.
Прежнее преобразование ожидаемого YAML, удалявшее `!изменять`, убрано.
Удалена также сама возможность такого преобразования в подготовке фикстур:
устаревший параметр `plainNumberExpectation` явно отклоняется. Существующая
матрица проверяет сохранение пустого и заполненного тега на реальных расширениях,
с отобранными строками состояний и без них. Ожидания больше не упрощаются
под возможности неполной декларации.

## Общие возможности компилятора

Зависимое выражение получает заимствованное содержимое выбранного варианта.
Доступ к тексту, логическому и десятичному полям не создаёт копии записи
или второго контекста. Проверяется совпадение выбранного варианта.

Условное умолчание выбранного варианта может конструировать запись с
проекцией в YAML. Сейчас поддерживаются литеральные смысловые поля и
проекция обычного текста или десятичного числа. Скрытые поля участвуют
в сравнении; при восстановлении проверяется, что чтение проекции вернуло
их исходный смысл. Не реализованные вложенные конструкторы и нестандартные
представления явно отклоняются компилятором. Это не универсальная поддержка
всех конструкторов записей.

При сохранении неверного числа исправлен общий путь проекции записи:
структурированная аномалия получает вложенный отступ вместо записи в одну
строку со скалярным свойством. Обычное число по-прежнему записывается прямо,
без промежуточного буфера. Запись без смыслового содержимого больше не
выдаётся за присутствующее значение; проверки выбранного варианта не
применяются к отсутствующему смыслу сохранённого XML.

При широкой проверке также исправлен поиск по строковой проекции индекса:
ключ из перечисления допустим, если индекс ожидает канонический текст.
Явный договор перечисления остаётся строгим. Названия и количество полей
составного ключа должны совпадать, числа и логические значения текстовыми
ключами автоматически не становятся.

Если смысловое значение зависимости отсутствует из-за сохранённого неверного
XML, нельзя доказать равенство соседнего значения вычисляемому умолчанию.
Общий механизм сокращения тогда сохраняет соседнее значение явно. Это
не разрешает угадывать умолчание или скрывать ошибки подготовки индексов:
`input.not-ready`, неверный тип контекста и внутренние ошибки продолжают
передаваться вызывающему слою. Та же проверка используется при запрете
явной записи умолчания в YAML. Пример защищён неверной длиной номера
документа и неизменным списком `ВводПоСтроке`.

Самопроверка универсальности: в Rust не добавлены имена объектов, свойств,
XML-корней или исключения для числа. Выбор варианта, наличие его смысла,
вложенная запись аномалии и сравнение с умолчанием остаются общими операциями.
Повторяющееся сопоставление полей записи вынесено в один помощник и используется
проверками равенства типов, ключей индекса и фиксированных шаблонов.
Это самопроверка, независимое ревью перед слиянием ещё требуется.

## Дополнение: режим «Проверять»

`common.notified-number` добавлен в общий выбор числового значения.
В XML вариант выбирается по `Notify` подготовленного индекса, в YAML —
по `!проверять`. Пустая пометка восстанавливает точное неявное число.
Имена вариантов и теги находятся в YAML, новый Rust-обработчик не добавлен.
Существующая скалярная проекция, условия, выбор, индексы и вывод аномалий
выполняют обе стороны и проверки.

Числовые варианты непересекающиеся: «Изменять» требует `Extended` без
`Notify`, «Проверять» требует `Notify` без `Extended`, обычный вариант —
отсутствия обоих. Противоречащие состояния сохраняются общей аномалией,
а не выбираются по приоритету. Повторные одинаковые строки `Notify`
не меняют выбранный смысл и сохраняются явно в исходном порядке.

Переносчик восьми владельцев теперь выводит строку `Notify` из пометки и
проверяет согласованность с явным списком. Зависимые умолчания и ограничения
длины читают число и из этого варианта. Составной документ получает тот же
договор при автоматической сборке фрагментов.

В корпус добавлены два примера, производные от существующих неизменённых
XML/YAML документа и справочника: заполненная пометка и пустая пометка,
восстановление XML без референса, запрет противоречащего пустого списка
состояний. Источник состояния для этих примеров содержит тот же производный
XML; индекс реквизитов по-прежнему читается из полного исходного XML.
Корпус содержит 56 сценариев; это не заявление о повторном полном прогоне
всех 56 после изменения. Результаты затронутого пакета записываются отдельно.

Контроль исходного значения не является третьим тегом: старый TS связывает
непомеченное значение с договором заимствованного свойства и отдельно
обрабатывает явно записанное XML-умолчание. Поэтому его нельзя заменить
ещё одним числовым вариантом без проверки основной конфигурации,
отсутствия элемента и обратного восстановления. Эта часть пока открыта.


## Дополнение: пустое непомеченное число

Для обычного числового варианта объявлена та же обратимая пустота:
`ДлинаНомера: null` (либо пустое значение после двоеточия при чтении)
означает неявное число свойства, например 9. Это присутствующее число;
отсутствие всего ключа заимствованного свойства означает отсутствие
XML-элемента по декларации владельца. Состояние `PropertyState` при таком
контрольном значении не создаётся. У собственного владельца число, равное
умолчанию, по-прежнему сокращается целиком общим сравнением с умолчанием.

Два дополнительных примера производны от реальных заимствованных объектов
расширения: документ и справочник. В выбранном числовом свойстве оставлено
неявное число, соответствующая пометка изменения удалена из производного
XML и ожидаемого YAML. Остальные свойства, состояния, индексы реквизитов и
основной конфигурации сохраняются. Новых функций Rust нет.

Реестр содержит 58 сценариев. Полный контроль совпадения значения с основной
конфигурацией, все 18 числовых регистраций и полный проектный маршрут ещё
не принимаются этим пакетом. Не путать приёмку обратимого числового
представления с окончательной приёмкой контрольной проверки расширения.

Проверки пакета «Проверять»: 12 отобранных сценариев владельцев прошли

### Сравнение с основной конфигурацией

Кандидатные владельцы получили индекс базовых числовых значений из полного
XML основной конфигурации. Источник выбирается существующей связью UUID;
состояния берутся из локального XML расширения. Индекс содержит каноническую
запись точного числа: равенство не зависит от 11 / 11.0 / 1.1e1 и не округляет
9007199254740993. Для этого добавлено общее выражение decimalText, включая
вклады одиночных записей и коллекций, без условий по предметным именам в Rust.

Контрольное число 9 при базовом 11 теперь закономерно сохраняется через
автоматическую аномалию; предыдущий блок принимал только обратимость его
представления. Число с !проверять остаётся обычным YAML с предупреждением,
с !изменять — обычным YAML без предупреждения. Проверочный исполнитель
различает ожидаемые сообщения чтения XML, экспорта и проверки YAML.

Корпус расширен с 58 до 62 сценариев. Базовый источник пока использует
явно присутствующие XML-свойства; восстановление отсутствующего базового
значения по умолчанию отдельно не принято. Также не приняты все 18 числовых
регистраций, рабочий проектный маршрут, полные владельцы и цели 10×.
XML-фикстуры не изменялись, новые флажки полного переноса не поставлены.

### 2026-10-01 — полный выбор числовых свойств плана счетов

Переносчик больше не ограничивает числовые поля списком стандартных
реквизитов для ВводаПоСтроке. Он выбирает числовые свойства по исходным
декларациям состояний, включая общие профили и изменения версий только
нужного вида владельца. Выбор не меняет версию совместимости; её ограничения
остаются самостоятельным договором.

Таким способом подключены MaxExtDimensionCount (МаксКоличествоСубконто)
и OrderLength (ДлинаПорядка). Оба используют common.stateful-number,
подготовленные состояния и базовые значения, общие ограничения и аномалии.
Нового обработчика плана счетов в Rust нет. В реальном расширении оба
свойства имеют Notify, и этот режим сохраняется при восстановлении XML.

Всего найдено 18 числовых регистраций: 16 подключены в кандидатный маршрут
восьми владельцев. Ещё не подключены periodAdjustmentLength регистра
бухгалтерии и numberLength нумератора документов; у этих владельцев нет
InputByString. Подключение числовых полей не означает полного переноса

### 2026-10-01 — зависимая граница и соседние перечисления

Условные максимумы теперь переносятся автоматически вместе с исходным
переключателем: шесть владельцев используют пять словарей перечислений.
Общая числовая проверка видит значение независимо от состояния «изменять»,
«проверять» или обычного значения. NumberType=Number ограничивает длину 38;
String сохраняет обычный максимум 50. У собственного объекта отсутствующий
переключатель использует исходное умолчание, у заимствованного — подготовленный
факт основной конфигурации, выбранной прежним механизмом связи UUID.

Нумератор проверен на числовой границе 38/39, строковой длине 50 и отсутствии
локального типа. При отсутствии типа в YAML расширения Number получается из
основы: 38 принимается, 39 отклоняется. Неверная XML-длина сохраняется общей
аномалией, соседний тип остаётся читаемым. Ожидания положительных и отрицательных
примеров проверяются отдельно от генератора. Производные примеры создаются
в проверочном наборе; исходные e2e XML не изменены.

Новый оператор enumText превращает значение объявленного словаря в внутреннее
имя для подготовленного текстового индекса. Он проверяется в обе стороны
в существующей матрице вкладов, включая запрет числового операнда; decimalText
по-прежнему сохраняет точные числа. Проекция записи использует объявленное
YAML-имя умолчания перечисления. Все состояния чисел и перечислений выпускаются
из одного YAML-шаблона stateful-scalar, без копий предметных преобразователей.
Порядок полей и сокращённого списка состояний берётся из исходного XML-порядка.

Дополнительная проверка отсутствующего соседнего типа обнаружила две ошибки
общего контекста компилятора: отсутствие терялось при захвате выбора вариантов,
а условие с запасным значением целиком пропускалось из-за отсутствующего входа.
Захват теперь сохраняет отсутствие; проверка варианта отсутствующего значения
даёт ложь. Чтение, защищённое условием наличия, больше не выключает всю проверку.
Это общие изменения для выборов и условий, без имён NumberType/NumberLength
в Rust-исполнителе. Самопроверка универсальности выполнена; независимое ревью
не проводилось, поскольку пользователь запретил субагентов.
