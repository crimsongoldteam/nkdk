# Выбор проектного профиля по снимку — 2026-10-01

## Реализованный договор

Маршрут поддерживает `select: {on: выражение, cases: таблица}`. Один общий
механизм выбирает декларацию владельца и значения входов. Источник выражения
может быть существующей привязкой к снимку фактов. Результат таблицы сохраняет
тип обычного literal; имена всех деклараций проверяются при чтении каталога.
Прежние маршруты с фиксированным именем остаются совместимыми.

Например, Собственный / Заимствованный из снимка нумератора могут выбирать
разные полные декларации и вход adopted=false/true. Эти соответствия будут
записаны в YAML. В Rust нет имён нумератора, ObjectBelonging или его значений.

Проверяется реальный маршрут XML и YAML, а не имитация выбора: два разных
профиля, чтение входа из таблицы, отсутствие подходящего варианта и снимка,
неизвестная декларация, недопустимый тип результата владельца и оператор.
Повторяющаяся подготовка новых тестов вынесена в общие тестовые помощники;
проверка дублей прошла после устранения двух найденных повторений.

## Исправление подготовленных индексов

До запуска новых проверок рабочий каталог не компилировался: журнал и команды
перечисления передавали подготовленные индексы в фрагменты с ключом-enum.
Вывод типа подготовленного индекса правильно превращал enum в канонический
текст, но проверка подключения сравнивала его как обычное поле.

Для ключей индекса теперь сравнивается канонический состав именованных
текстовых столбцов. Тип значения индекса и сравнение обычных enum-полей
остаются строгими. Это соответствует существующему физическому договору
подготовленных фактов; частных изменений журналов и команд не требуется.
Регрессия сначала падала при подключении фрагмента, затем прошла с настоящим
созданием фактов, поиском существующего ключа и диагностикой отсутствующего.

## Границы приёмки

Проверены 31 сценарий операций фактов, включая прежние рабочие маршруты,
и 11 проверок contributions. Профильный механизм принят, но маршрут
нумератора ещё не добавлен и флажок полного перехода остаётся пустым.

Адресация фактов чисел основы исправлена: источник полного владельца
получает настоящий UUID основного объекта из неизменного XML. Полная
декларация разрешает его через metadata.base-identities по компоненту и UUID
заимствованного объекта. История состояний по-прежнему относится к UUID
самого расширенного объекта; эти два контекста не смешиваются.

При переходе проверочного источника на настоящий UUID основы тест сначала
выдал пять base.property.missing вместо двух настоящих расхождений. После
исправления декларативных lookup весь набор из 20 сценариев прошёл,
включая полные XML-преобразования и отсутствие boolean в основе. Node-набор
содержит 13 проверок; реестр источников — 27. Новая проверка подключения
требует, чтобы UUID источника основы отличался от UUID заимствованного объекта.

Осталось собрать эти проверенные источники в рабочий маршрут, подключить
проектную валидацию и создание новых файлов. Полный pnpm test, Clippy
изменённых пакетов, архитектура TypeScript/Rust и поиск дублей прошли.
Широкий запуск Clippy на зависимостях выявил 113 ранее существовавших
предупреждений сгенерированного каталога; они не скрыты. Адресный Clippy
пакетов приложения и компилятора с --no-deps прошёл без предупреждений.

Общая генерация Rust заранее сохраняется; выбор файла не заменяет правила
интерпретацией YAML во время преобразования. Цель ускорения 10× этим блоком
не подтверждается. Самопроверка универсальности выполнена, независимое
ревью не проводилось согласно запрету на субагентов.
