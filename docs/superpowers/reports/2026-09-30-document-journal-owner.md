# Приёмка DocumentJournal на Rust

Все 24 свойства `MetadataDocumentJournalRules` учитываются генератором
`journal-owner-operation.mjs`: он сверяет типы свойств и XML-порядок с
`rules.ts`, собирает одну YAML-декларацию владельца и проектные маршруты.
Графы и источники идентичности также выводятся из исходных правил.

Проектный маршрут `metadata.journal` преобразует журнал вместе с графами,
командами, стандартными реквизитами, формами, макетами, модулями, справкой и
дополнительными индексами. Общая подготовка фактов собирает UUID, связи с
основной конфигурацией и имена внешних ресурсов. Частных обработчиков журнала
в нейтральных модулях Rust нет.

Проверка `declared_project_route_converts_a_component_after_reopening_its_yaml`
сравнивает YAML с неизменёнными e2e-эталонами и восстановленный XML с исходным
для полных каталогов `cf` и `cfe`. Она повторно открывает YAML без XML-референса,
проверяет внешние файлы, создание нового журнала в обоих компонентах с
устойчивыми UUID и восстановление неверного булева значения через аномалию.
Отдельные проверки граф покрывают UUID, ссылки, порядок и отклонения внутри
коллекции. Пробы генераторов защищают автоматический перенос из `rules.ts`.

Полная сборка `Document` и окончательный отказ от TypeScript остаются
отдельными этапами. Скорость и память 10× для готового конвертера этим
результатом не подтверждаются.
