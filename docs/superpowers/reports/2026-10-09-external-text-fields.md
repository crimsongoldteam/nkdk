# Текстовые поля во внешних файлах

Согласованные [спецификация](../specs/2026-10-09-external-text-fields-design.md)
и [план](../plans/2026-10-09-external-text-fields.md).

## Что реализовано

Файловое размещение задаётся в `yaml.fields` вместо ключа YAML. Выражение пути
связывается при компиляции; исполняемый Rust не разбирает декларацию и не знает
имён QueryText и DynamicList. Поддерживается текстовый тип, включая common-ссылку.

XML → YAML возвращает текст отдельным документом. Отсутствующий элемент не
выдаёт файл, пустой элемент выдаёт файл нулевого размера. YAML → XML читает
объявленный файл из подготовленных документов. Исходные XML-атрибуты и повторы
сохраняет общий механизм аномалий; изменение файла не отменяется старым текстом
из XML-дельты. Для неизвестного атрибута дельта содержит атрибут, а не копию текста.

Доказательство восстановления читает новый документ через заимствующее
наложение: полного контекста, индексов и исходных документов не копирует.
Операция приложения читает объявленные файлы один раз, сохраняет их для
валидации передачей владения и готовит результат до публикации. Конфликт пути,
выход из корня и превышение бюджета не оставляют частично опубликованный набор.
Недопустимый UTF-8 и символы, запрещённые XML, дают диагностику с именем файла.

Автоматический перенос `stringRule.externalFile` использует параметры старого
правила. Проверены два реальных QueryText из неизменного e2e Form.xml с
независимыми существующими файлами `.query` и настоящими именами родителей.

## Проверки

- Матрица внешних документов: 3 проверки, обычная и общая AOT-генерация,
  переименование поля/пути/входа, два файла, вложенная запись, отсутствие,
  пустота, атрибуты, повторы, редактирование и читаемые соседние свойства.
- Схема: 30 проверок; подготовленные документы: 6; ресурсы: 1; XML-дерево: 4.
- Словарные ключи коллекций: 12 проверок, включая воспроизведённую ошибку
  отсутствующего контекста в восстановлении строки и её исправление.
- Нативное семейство DynamicList: 37; параметры DynamicList: 14.
- Проверки переноса Node: 74. Повторная публикация `--check` проходит.
- Архитектурные границы Rust/rules/TypeScript и новые дубли проверены.

Общая проверка приложения (`cargo check -p nkdk`) прошла после штатного
обновления подготовленных AOT-модулей. Все пакеты сохранили лимит 16 МиБ;
подпись каталога совпадает. Clippy библиотек с `-D warnings` прошёл.
Файловая матрица проверена на настоящем модуле приложения в отдельном
небольшом тестовом пакете, без компиляции всего каталога в тестовый исполняемый файл.
Полный `pnpm test` вне песочницы завершился с кодом 0: 9767 проверок пакетов
и 346 проверок Node прошли; два существующих сценария подключения к 1С
пропущены. Есть неблокирующее предупреждение о превышении целевых 10 мс
существующим тестом MCP; это не цель ускорения конвертера 10×.
`git diff --check` прошёл; исходные XML-фикстуры не изменялись.

## Скорость

[Исходные замеры](2026-10-09-external-text-fields-performance.json) сохранены.
Сравнены архивная release-версия до изменений и текущая release-версия на
одном неизменном независимом сценарии обычного владельца. Обе версии отдельно
прошли его проверки. Сборки во время замеров не выполнялись; порядок версий
чередовался. Первая серия: 9 групп по 50 000 операций, вторая: 9 по 100 000.

Отношение медиан нового времени к старому:

| Направление | Первая серия | Вторая серия |
|---|---:|---:|
| XML → YAML | 1,018 | 0,958 |
| YAML → XML | 0,992 | 0,994 |

Устойчивое замедление обычного пути не обнаружено. Разница XML меняет знак,
поэтому ускорение на несколько процентов также не заявляется. Проверка
относится к этому владельцу, а не ко всем операциям проекта.

Для настоящего QueryText отдельно измерено преобразование подготовленных
данных: XML → YAML около 11,9 мкс, YAML → XML около 2,6 мкс, по 50 000 операций.
Этот сценарий ранее не поддерживался Rust; архивная версия не является
базой сравнения его скорости. Основной YAML и текстовый файл учитываются
раздельно; `sourceBytes` нативного измерителя относится к основному документу.

На тёплой локальной файловой системе эквивалентное ограниченное чтение
заняло 32,6 мкс как через прежний запрос XML-документов, так и через запрос
подготовленных путей. Подготовка одинакового файла с передачей владения —
176,8 мкс, с заимствованием байтов — 171,0 мкс (медианы пяти групп по 1000).
Это сравнение двух способов IO на одном модуле, а не сравнение полного
конвертера до/после. Файлы не синхронизировались с диском через fsync.

Без объявленных файлов загрузчик возвращается до обращения к файловой
системе; RED→GREEN проверяет это на недоступном пути. Общий бюджет
документов проверяется при обоих порядках подготовки: сначала документы
или сначала установка лимитов.

## Граница приёмки и следующий шаг

Это договор текстового поля и его файловой операции, а не приёмка полного
DynamicList и не подтверждение цели 10×. Флажок полного объекта остаётся снятым.

Начата проверка следующего подключения: `fields`, `calculatedFields`,
`parameters`. Их старые построители регистрируют коллекции с адресацией
`yamlPath`; готовые примеры пока собираются отдельными семейными декларациями.
Для полного владельца нужно автоматически перенести эту регистрацию, её
индексы и привязки входов через общий механизм коллекций. Простого псевдонима
common недостаточно: он не передаст необходимый контекст. Частные обработчики
DynamicList в Rust для этого не добавляются.


Сверка исходных регистраций следующего этапа:

| Свойство | Правила элемента | XML | YAML | Представление |
|---|---|---|---|---|
| fields | DataCompositionSchemaDataSetFieldRules | Field | Поля | список |
| calculatedFields | CalculatedFieldRules | CalculatedField | ВычисляемыеПоля | список |
| parameters | DCSParameterRules | Parameter | Параметры | словарь по name |

Все три регистрации находятся под XML-корнем Settings. Библиотеки элементов
уже опубликованы как common.data-composition-schema-data-set-field,
common.calculated-field и common.dcs-parameter. Следующий блок должен
публиковать и подключать их коллекционные обёртки из этих регистраций,
передавая необходимые входы и адресацию yamlPath; он не требует ещё трёх
обработчиков в Rust.

## Решения при выполнении

- Установленные лимиты документов проверяются при любом порядке подготовки;
  для прямого API сохранены прежние значения по умолчанию. Большие договоры
  должны передать свои лимиты явно.
- Модель сохранена совместимой: ключ и необязательное файловое размещение,
  с проверкой ровно одного размещения. Возможная будущая смена на enum касается
  API модели, не смысла преобразования.
- Валидация получает документы передачей владения. Если будущий валидатор
  требует файлы вне границы преобразования, понадобится общая подготовка
  дополнительных запросов; повторное чтение текущих файлов не добавлено.
- Исправлена публикация временных зависимостей common: исходные сохранённые
  идентификаторы фиксируются до генерации. Без этого переносчик ошибочно
  считал временную зависимость уже опубликованной.
- Одинаковая диагностика и построение XML-дельты вынесены в общий код;
  лимит 16 МиБ не повышен. Обычный путь проверен отдельными замерами.
- Восстановление словарной строки получает заимствованный контекст ключей.
  Независимый пример воспроизвёл ошибку компиляции и прошёл после исправления.
- Подготовленные AOT-модули обновлены штатной генерацией. Цена — одноразовое
  обновление и проверка каталога; устаревшие модули не заменены ручной заглушкой.
- Во время приёмки освобождены старые исполняемые файлы (~1,5 ГиБ), затем
  устаревшие копии библиотечного кеша и лишний debug-кеш (~900 МиБ).
  После удаления библиотек очищены соответствующие отпечатки Cargo;
  цена — повторная сборка затронутого кеша. Исходники и базовые release-замеры
  сохранены.
- Замеры, сделанные одновременно со сборкой, не использованы как основание
  приёмки. Выполнены две независимые серии без фоновых сборок; их разброс
  не позволяет заявлять ускорение всего проекта.
