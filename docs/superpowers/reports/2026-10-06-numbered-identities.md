# Назначение новых числовых идентификаторов, 6 октября 2026

## Результат

Декларации могут запрашивать новый номер через
`allocate: {scope: [component, owner], first: 1}` в `contributions`.
Общий сборщик индекса сначала резервирует все сохранённые номера, затем
выполняет запросы в порядке появления. Например, новый элемент получает `2`,
если другой источник позднее передал сохранённый `1`. До окончания подготовки
преобразователи не видят индекс; после неё используют прежний `lookup`.

Повторные запросы одного ключа объединяются. Сохранённые номера, исторические
повторы разных ключей, точные большие значения и конфликты сохраняются.
При исчерпании диапазона или бюджета весь индекс остаётся неготовым.
Уже известное значение никогда не заменяется автоматически новым номером.

Переносчик автоматически добавляет запросы в декларации источников
регистраций элементов без фиксированного id. Проверено создание новой
ExtendedTooltip как полного тела и вложенного свойства: номер восстанавливается
из подготовленного индекса, без XML-референса и без аномалии для обычных данных.
Автоматическая генерация подключений 41 свойства и кандидатов обновлена.

## Универсальность и границы

Ядро получает номера столбцов, минимальный номер и интернированные ключи;
оно не знает названий форм, элементов и свойств. Один договор генерации
используется для скаляров, составных записей и строк коллекций. Независимая
коллекция из двух строк проверяет тот же механизм с другими именами полей.
Запросы компилируются в Rust; новый интерпретатор и промежуточные XML/YAML
не добавлялись. Это самопроверка по `.agents/declarative-review.md`, не
независимое ревью всей ветки.

**Это не полное назначение номеров формы.** Следующий этап должен собрать все
занятые номера, включая непрозрачный сохранённый XML; подключить пространства
реквизитов, команд и параметров; согласовать приоритеты сохранённых источников
и общей сессии основной/текущей формы. Отдельные проверочные источники не
доказывают работу этого маршрута. Флажок ExtendedTooltip не выставляется.

создание нового элемента — из-за отсутствующего id. После реализации
эти проверки проходят. Дополнительная проверка повторного запроса с большим
минимальным номером обнаружила ошибку объединения; исправление сохраняет
максимум минимумов без изменения порядка первого появления.

- Ядро Rust: 104 проверки, включая пять проверок назначения номеров.
- Компилятор: 117 проверок библиотеки, связывания, генерации и JSON Schema.
  Один прежний игнорируемый тест и одна большая полная сборка исключены;

Это остаётся предварительной компиляцией деклараций. Нельзя ускорять проверку
пропуском генерации, ослаблением ограничителей или использованием устаревшего
каталога. Конкретное изменение сборки в этот блок не входит.

изменённых Rust-файлов и `git diff --check`. Новых полностью принятых объектов
этот блок не добавляет: механизм новых номеров завершён, полный маршрут
формы остаётся отдельным условием.

## Продолжение: занятый номер без имени объекта

Добавлен `reserve`: источник передаёт только номер и столбцы области,
например `component` и `owner`. В отличие от сохранённой идентичности,
резервирование не создаёт ключ объекта в индексе. Это нужно для номеров
удалённых объектов и непрозрачных узлов, которым нельзя придумывать имя.
Получение этих номеров из всей формы остаётся следующим слоем.

Общее ядро хранит занятые номера как `u64`, а столбцы области интернирует
прежним механизмом. Повторы не создают новых записей. Бюджеты строк и текста
распространяются на резервирование; после нарушения индекс не публикуется
частично. Обычные сохранённые значения и `reserve` вызывают одну операцию
проверки канонического номера, без дублирующих обработчиков.

Компилятор проверяет точный набор столбцов области и наличие распределителя
для индекса. Порядок перечисления столбцов несущественен. В модели языка
обычная запись, запрос номера и резервирование представлены тремя вариантами
одного типа: противоречащие сочетания не передаются генератору. Условия,
подстановка фрагментов и зависимости выражений используют прежний путь.
Форма полного ключа выводится из обычных записей/запросов, а не из резервов.

Проверочные ожидания независимы от декларации: после сохранённого `1` и
поздних резервов `2`, `3`, повторного `2` новые строки получают `4` и `5`.
Коллекция читает резервирующий источник из XML и YAML; содержимое сохраняемого
снимка также сверяется. Ядро отдельно проверяет отсутствие выдуманного ключа,
независимость областей и игнорирование неканонического написания при выдаче.
Такие значения остаются в исходных данных без исправления.

Матрица связывания отклоняет неверные столбцы, скаляр вместо области-записи
и резерв без распределителя; принимает пустую глобальную область. JSON Schema
и парсер отклоняют сочетание `reserve` с `value`, `allocate`, `union` или
`duplicates`. Это проверки общего механизма, не дополнительные копии тестов
для каждого свойства формы.

Самопроверка универсальности: в ядре, связывании и генерации не добавлены
имена форм, свойств, XML-узлов или классов common. Оркестратор не изменён.
Новый резерв не требует преобразовывать XML в YAML и обратно для исполнения;
снимок проверяется отдельным существующим маршрутом хранения источника.
Это самопроверка, не независимое ревью.

**Приёмка полной формы по-прежнему открыта.** По существующему
`formXmlIdAssignment.ts` остаётся проверить получение номеров из сохранённых
поддеревьев и удалённых записей, изоляцию соседних форм и четырёх пространств,
приоритет фиксированных/сессионных/сохранённых/текущих номеров и различие
правил основной формы для реквизитов и элементов. Рабочий сборщик не должен
получить ветвления из старого `xmlIdSpaceForNodeName`: эти границы принадлежат
декларациям/данным формы. Флажки объектов не меняются.

### Что подтвердили исходные XML

Просмотрены без изменений все 232 `e2e/fixtures/xml/**/Ext/Form.xml`:
10 583 атрибута `id`, из них 10 100 в пространстве элементов, 410 — реквизитов,
73 — команд по классификации существующего TS. В 61 файле есть номера
внутри `BaseForm`. Идентификаторов параметров в этом наборе не найдено;
это ограничение покрытия, а не основание убрать соответствующий договор.
Все найденные id имеют имя и каноническую целочисленную запись. Случаи
непрозрачных узлов и удалённых записей защищены прежней матрицей TS и остаются
обязательными при подключении Rust.

Конкретные исходные примеры:

- `cf/CommonForms/ExtendedTooltip/Ext/Form.xml`: кнопка `Кнопка` имеет `1`,
  вложенная `КнопкаРасширеннаяПодсказка` — `2`, командная панель — `-1`.
  Два новых элемента после резервирования соседей должны получить `3` и `4`.
- `cf/CommonForms/CommandBar/Ext/Form.xml`: и реквизит `Реквизит1`, и его
  колонка имеют `1`. Исходный повтор сохраняется; следующему новому реквизиту
  этот номер не выдаётся.
- `cf/AccountingRegisters/РегистрБухгалтерииВсеСвойстваОбороты/Forms/ФормаСписка/Ext/Form.xml`:
  `1` одновременно есть у элемента формы, реквизита и команды. Это разные
  пространства, их нельзя объединять в одну область нумерации.

Всего найдено 28 групп повторов в 9 формах при раздельном учёте основной и
текущей части и 231 совпадение между пространствами в 139 формах. Частота не
меняет договор: существующие повторы сохраняются, новые совпадения внутри
одной области не создаются.
