# Корневые XML-атрибуты и выбор цветов

Переносчик теперь выпускает свойства с пустым XML-путём как отдельную
относительную проекцию корня владельца (`root: null`). Это общее правило для
атрибутов, включая UUID и системные перечисления; вложенные поля по-прежнему
группируются по своему первому XML-элементу. Для восстановления UUID из YAML
полный владелец должен предоставить индекс `metadata.own-identities` и свой
вклад в него; относительная проекция этого не обещает.

Число кандидатов выросло с 3928 до 4109: 181 ранее заблокированное свойство
`owner-root-required` стало кандидатом. В том числе это 136 UUID и 45
перечислений. Ни один владелец от этого не стал полностью принят: корневую
проекцию ещё нужно соединить с остальными частями владельца, обеспечить
вклад UUID в индекс и проверить весь объект на e2e. Флажки чеклиста не
меняются.

Проверка `Color` выявила общий пробел языка. В XML стандартный цвет и
пользовательский элемент стиля начинаются одинаково (`style:`), тогда как
в YAML стандартный цвет переводится по словарю, а пользовательский получает
префикс `ЭлементСтиля.`. Нынешний компилятор отвергает пересекающиеся
варианты выбора; перечислить их двумя ветвями нельзя. Нужен общий
декларативный механизм словаря с обратимым оформлением значения, которого
нет в словаре. Частный обработчик `Color` в Rust не добавляется; флажок
`Color` остаётся пустым.

При перепостроении независимых договоров обнаружилось, что относительная
проекция `Properties` документа уже требовала `ownerRoot` и
`containingOwnerName`. Проверочный сценарий теперь извлекает их из того же
исходного XML, когда этого требует декларация; оба документа и весь набор
из 236 договоров прошли. Полный `pnpm test`, архитектурные проверки и
поиск новых дублей также прошли.

всего каталога кандидатов пока останавливается на уже существующей
`index_missing` в `candidate.projection.0aa0a8a235fce1464abc.yaml`:

появится только при сборке полного владельца. Эта проекция не менялась.
