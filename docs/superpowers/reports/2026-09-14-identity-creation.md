# Создание идентичности при подготовке операции

Продолжение [плана](../plans/2026-09-13-unified-conversion-plan.md).

`OperationIdentity` переносит существующее детерминированное вычисление
`configurationIndex/exportRuntime.ts`. 32-байтовое значение операции задаётся
один раз снаружи; подготовленное состояние SHA-256 переиспользуется.
Разделитель, строка области и UTF-8 адрес соответствуют старому алгоритму.
Формат задаётся отдельно: UUID, 128 или 160 бит шестнадцатеричного текста.
Названия областей (`uuid`, `xmlId`, `configVersion`) не зашиты в нейтральный
механизм и передаются вызывающим кодом.

Сохранённая идентичность возвращается заимствованной, включая пустой текст.
Новое значение создаётся только для `Missing`. `Unready`, `Ambiguous` и `Cycle`
сохраняются; неполный индекс не разрешает подмену идентичности новым UUID.
Новая внешняя зависимость не добавлена: используется имеющийся `sha2`.

Контрольные значения получены выполнением исходного TypeScript через
`node --import tsx` с явно заданным значением операции. Матрица покрывает
другой адрес, кириллицу и экранирование, другое значение операции, три формата,
повторный вызов и сохранение существующего значения без копирования.

Рабочая проверка identity дополнена последовательностью: полный предыдущий
индекс → создание отсутствующего UUID → вклад через существующую декларацию
идентичности → новый подготовленный индекс → экспорт common.uuid. Ожидаемый
UUID закреплён исходным TypeScript, а не вычисляется проверяемым Rust-кодом.

Это пока не полная проектная подготовка: автоматический сбор новых адресов,
чтение/публикация сохраняемого индекса и получение случайного значения новой
операции ещё должны быть подключены к операции целиком. Common-чеклист
не меняется; полная приёмка UUID остаётся открытой.

Проверки: 36 тестов conversion-core, целевая рабочая матрица identity,
Clippy conversion-core со всеми целями, архитектура Rust и проверка новых
дублей относительно `37acdae1f` прошли. Полная проектная миграция и выигрыш
10× этим не подтверждены.

## Логические адреса

`LogicalAddress` переносит экранирование `logicalAddress.ts`: `%`, `.`, `[` и
`]` внутри сегмента получают `%25`, `%2E`, `%5B`, `%5D`. Разделители сегментов
и индексы добавляются отдельно. Например, имя `А.Б` в адресе перечисления
даёт `Перечисление.А%2EБ.Значение.В`, а не лишний уровень вложенности.

Адрес собирается в одном буфере без четырёх последовательных строковых
замен. Пустые сегменты и индексы вне прежнего допустимого диапазона
отклоняются до изменения буфера. Генератор идентичности принимает этот
тип, поэтому сборку адреса нельзя случайно заменить склейкой неэкранированных
имён. Предметные названия сегментов должна передавать декларативная композиция;
в общем типе нет имён объектов или коллекций.

Существующая матрица контрольных идентификаторов теперь использует этот
построитель, включая имя с точкой. Отдельная проверка защищает отсутствие
коллизий сегментов, индексы и сохранность адреса после некорректного добавления.
Автоматический выпуск контекста адресов коллекций остаётся незавершённым;
сам построитель не снимает блокировку `collection-owner-contributions-required`.
