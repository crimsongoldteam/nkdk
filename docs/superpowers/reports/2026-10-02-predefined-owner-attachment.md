# Автоматическая привязка Predefined.xml к владельцу

## Договор

Переносчик получает путь внешнего файла и YAML-имя свойства из регистрации
владельца в `rules.ts`. Он превращает отдельно проверенную декларацию файла
в подключаемый фрагмент. Чтение содержимого, восстановление аномалий и
формирование выходного XML остаются в существующем компиляторе и механизме
внешних документов; предметных веток в оркестраторе нет.

Созданы привязки справочника, плана видов характеристик, плана счетов,
плана видов расчёта и справочника расширения. Источники, идентификаторы
и выходные файлы находятся в соответствующих профилях
`tools/rules-migration/profiles/predefined-*-envelope.yaml`.

Переносчик выводит **размещение**. Он не объявляет неподдержанные вычисляемые
`itemRule` перенесёнными: смысл содержимого задаёт отдельно принятая декларация
файла. Проверка `--check` контролирует все выходные декларации, включая фрагмент.
Пустые сегменты, обратные слеши, абсолютный путь и переход `..` запрещены.

## Проверка подключения

Существующая Rust-матрица расширения дополнена отдельной последовательной
сборкой владельца: настоящий XML справочника и его `Ext/Predefined.xml`
подаются как основной и внешний документы. Имя и принадлежность берутся из
XML владельца, а не из заполнения входов тестом. Проверяется выдача YAML
с вложенными элементами и тегом `!проверять`, затем восстановление обоих XML
без референса. Изменение принадлежности в копии входа проверяет сохранение
несоответствующих состояний как аномалий.

UUID в этой проверке остаются явными: входной индекс пуст. Это защищает
привязку документов независимо от подготовки индекса. Полная приёмка требует
ещё автоматического сбора вложенных UUID и подключения к проектному маршруту.
Неперенесённые свойства самого справочника сохраняются существующим механизмом
XML; проверка подключения не считается приёмкой всего справочника.

## Границы

XMLRoot остаётся без флажка, счётчик common — 56/90. Следующий шаг — подготовка
индекса предопределённых элементов из исходного файла с рекурсивными адресами,
затем передача этого индекса через настоящий проектный маршрут.

## Исправление общего механизма

Проверка владельца обнаружила ошибку порядка: внешний документ читался до
основного XML, хотя его привязки обращались к имени и принадлежности владельца.
Маленький независимый тест воспроизвёл `input.not-ready`; после исправления
он проверяет ожидаемый YAML, прямой контрольный экспорт и оба выходных XML.
Основной XML по-прежнему читается одним посещением. Внешние документы читаются
после готовности его полей по существующему расписанию, с заимствованием контекста.
Контрольный экспорт внешнего файла получает тот же контекст.

Обратное направление выявило также необоснованное отключение отложенного
YAML-reader при наличии внешних файлов. Исправление использует одно расписание
готовности полей для всего YAML, независимо от физического размещения XML.
Минимальная проверка дополнена значением по умолчанию из имени владельца:
ошибка повторилась и устранена без отдельного обработчика свойства.

Аномальный вариант дополнительно выявил потерю привязок при переходе к
повторно используемому рекурсивному договору записи. Переход теперь передаёт
существующие привязки, включая вычисляемые булевы значения. Если промежуточная
!xml-форма скрытого поля не читается как обычный YAML владельца, обработка
доходит до существующего восстановления на границе строки. Результат всё
равно принимается только после контрольного восстановления XML.
