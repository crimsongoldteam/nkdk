# Приёмка common Color

Дата: 2026-09-23. Граница приёмки — общий тип `Color` для XML ↔ YAML,
проверки YAML и сохранения аномалий. Это не приёмка полных владельцев форм.

## Договор

- Вся предметная таблица и условия заданы в [`common.color`](../../../rust/declarations/common/color.yaml), словарях системных перечислений и общем индексе типов элементов стиля. У компилятора и исполнителя нет ветки по имени `Color`.
- Стандартный `style:SpecialTextColor` даёт `ЦветОсобогоТекста`. Ссылка `ЭлементСтиля.ПоясняющийТекст` с тем же XML-префиксом разрешается через подготовленный индекс, только если объект существует и имеет тип `Color`. Недопустимое в 1С имя `ЭлементСтиля.SpecialTextColor` не превращается молча в стандартный цвет.
- Словари Windows/Web, абсолютный RGB, `0`, `0:<uuid>`, явный XML `auto` и отсутствие элемента различаются. `auto` и отсутствие сокращаются до отсутствующего поля YAML; пустой YAML создаёт XML без `Color`. Ручная запись `Цвет: auto` отклоняется проверкой YAML.
- Неверные `#oops` и `0:wrong-uuid` получают выводимую из ограничений `!xml/invalid`. Неизвестный префикс невозможно разобрать как смысловое значение; общий механизм сохраняет его через `!xml/raw`. Оба варианта восстанавливают исходный XML и не скрывают соседние поля. Применение `!xml` к классу неверных `Color` согласовано пользователем.
- JSON Schema строится из этой же декларации. Её структурная часть проверяет строковый вид, а признак `x-nkdk-runtime-validation` требует проверять словари, ссылки и ограничения скомпилированной проверкой.

## Независимые проверки

- Пять неизменённых XML-фикстур старого общего типа проверены в обоих направлениях с отдельными ожидаемыми значениями YAML.
- Четыре значения взяты из неизменённого e2e-файла стиля и записаны с независимыми ожидаемыми YAML-значениями в [`color-e2e.json`](../../../tests/migration/color-e2e.json). Проверка подтверждает наличие каждого XML-фрагмента в источнике и оба направления преобразования.
- Подготовка индекса проверена на неизменённых XML-файлах настоящих элементов стиля типов `Color` и `Font`. Отдельно проверены неверный тип и отсутствие элемента стиля, совпадение со стандартным именем, `auto`, raw-ссылки и восстановление аномалии вместе с соседним полем.

Соответствие старых проверок новым:

| TypeScript | Rust |
|---|---|
| `fromXML.integration.test.ts`, `toXML.integration.test.ts`, `fromYAML.test.ts`, `toYAML.test.ts`: пять основных форм | `color_uses_the_five_existing_xml_forms_in_both_directions` |
| Там же: `auto`, отсутствие, `0`, `0:<uuid>` | `color_preserves_raw_forms_and_omits_auto` |
| `toJSONSchema.test.ts`: структурный тип и значения | `color_schema_is_generated_from_the_shared_declaration` и скомпилированная проверка в `color_style_item_checks_the_prepared_name_and_type_index` |
| Проверки `metadataTarget` элемента стиля | `color_style_item_checks_the_prepared_name_and_type_index` на e2e XML типа `Color` и `Font` |

Старые проверки Enterprise остаются в TypeScript и не входят в целевой договор XML ↔ YAML.

## Массовый перенос

Переносчик находит тип `Color` по имени общей декларации, а подготовленный индекс — по общему профилю `StyleItem` / `styleItemType`. Он не содержит ветки, проверяющей имя `Color`. Все 192 статически прочитанные свойства `Color` стали кандидатами с `common.color` и `metadata.style-item-types`: число кандидатов выросло с 4109 до 4301, число заблокированных вхождений уменьшилось с 1767 до 1575. Статус всех остальных свойств не изменён. Сборка их полных владельцев и подключение источника индекса в оркестраторе учитываются отдельно.
