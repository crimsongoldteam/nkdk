# Приёмка StructureItemGroup

[Декларация](../../../rust/declarations/common/structure-item-group.yaml) задаёт одну последовательность и путь к следующему узлу XML-цепочки. Компилятор выравнивает линейную цепочку в YAML-список и строит обратную цепочку без XML-референса. На обычном пути импорт обходит XML-события с переиспользуемым буфером путей; полный XML сохраняется только для обнаруженной аномалии. Компилятор и ядро не содержат ветвлений по имени StructureItemGroup.

[Проверка](../../../rust/crates/compiled-rules/tests/dcs_lists.rs) охватывает исходную XML-фикстуру и все три корневые цепочки из реальной e2e-формы: порядок и значения элементов, обратимость, запись YAML вручную и пустую группировку. Ветвление, лишний элемент, неизвестный атрибут и пустой узел автоматически сохраняются как аномалии. Компилятор проверяет различимость путей; схема YAML получается из той же декларации.

Проверены `cargo test -p nkdk-rule-compiler -p nkdk-conversion-core -p nkdk-probe-dcs-lists`, адресный тест после последнего изменения, Clippy с `-D warnings`, `pnpm type-check`, полный `CI=true pnpm test`, архитектурные проверки и поиск новых дублей. Все команды завершились с кодом 0.

Ограниченный замер выпуска для цепочки дал около 86,8 мкс на XML → YAML и 13,7 мкс на YAML → XML. Он не сравнивает одинаковые полные операции TS и Rust, поэтому цель 10× по скорости и памяти этим замером не подтверждена. Подключение полного владельца СКД остаётся отдельной приёмкой.
