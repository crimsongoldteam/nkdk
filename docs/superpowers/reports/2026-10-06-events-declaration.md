# Декларативные события формы — 2026-10-06

## Что реализовано

`rust/declarations/common/event-bindings.yaml` описывает строку события,
перечисление режимов и два пространства XML-имён. Один общий `groupKey`
превращает последовательность строк в обычный обработчик или словарь
`Перед` / `После` / `Вместо`. Частного обработчика Events в Rust нет.

Переносчик распознаёт все 31 исходные регистрации Events. Словари `items`
переносятся автоматически как постоянные привязки `keyTable`; в Rust это
константные таблицы без создания словаря и передачи его при каждом вызове.
Сборка singleton-элементов содержит 94 перенесённых свойства; 13 свойств
остаются явно неподдержанными. Единственный служебный `runtimeOnly`-тип
ExtendedTooltip автоматически учитывается как не участвующий в XML/YAML,
без угадывания значения. У ExtendedTooltip теперь полный охват исходных
свойств; это не означает приёмку поведения внутри каждого владельца.

Повторы, смешение обычной и групповой привязки, неизвестный режим или имя,
неканонический регистр и перестановка строк сохраняются общим механизмом
аномалий. Допустимый соседний обработчик и соседнее свойство владельца
остаются читаемыми. Пустой `<Events/>` сохраняется как аномалия формы:
смысловая пустота не должна терять сам XML-контейнер.

Старые XML-фикстуры не изменялись. Проверочные проекции реальных cf/cfe
сопоставляются с уже сохранённым YAML; ожидаемый результат не выводится
из нового преобразователя. Проверены и новый YAML без XML-референса,
обратный порядок режимов, пустая коллекция и отсутствие свойства внутри
владельца с самостоятельным соседним полем.

## Границы и проверка универсальности

`groupKey` — структурное правило над тремя разными полями. Компилятор
проверяет текстовый/перечислимый второй ключ и скалярное значение. Словарь
значения без второго ключа пока запрещён: он был бы неотличим от группы.
Постоянные таблицы с маркером `empty` и вычисляемые таблицы пока не поддержаны;
обычный вход владельца остаётся допустимым. Ограничения диагностируются
при сборке, а не маскируются аномалиями исходных данных.

Потоковый читатель не строит дерево YAML. Писатель обычных строк также
обходится без дерева, но пока повторно разбирает уже отрисованную строку
YAML для извлечения второго ключа и значения. Это дополнительная работа:
следующая оптимизация — типизированная проекция полей строки без такого
промежуточного представления, с сохранением общего механизма аномалий.
Рост скорости и выполнение цели 10× этим блоком не заявляются.

Отдельные общие тесты используют несвязанные имена key/axis/payload.
Тот же договор проверен самостоятельно, в составной записи и через
автоматически перенесённое свойство формы. В общих слоях нет проверки
имени Events, callType или ExtendedTooltip. Это самопроверка, не независимое ревью.

Структурная схема описывает строку либо непустую группу с допустимыми
режимами. Проверку ключей динамической таблицы завершает скомпилированная
валидация (`x-nkdk-runtime-validation`). Схема деклараций редактора также
поддерживает `groupKey`. Неизвестные имена теперь сохраняются как аномалии;
старый fromXML/toYAML пропускал их обычными значениями, хотя JSON Schema
старого Events запрещала неизвестные ключи.

Проекция одного свойства не владеет оболочкой пустого файла `<Form/>`.
Пример выявил расхождение восстановления; оборачивание однополевой коллекции
в `with-attributes` также пока диагностируется как неподдержанное сочетание.
Общие возможности оболочки нужно завершить при сборке полной формы.
Эти ограничения не обходились выключением проверки round-trip.

## Рабочий каталог и приёмка

`pnpm migration:events:working` сохраняет пять деклараций проекций и 17
проверочных сценариев; `--check` проверяет актуальность. Рабочая проверка:
`pnpm test:migration:events:working`. Целые формы и элементы этой командой
не объявляются перенесёнными.

При первом подключении обнаружен устаревший каталог: новый файл появился
после начала предыдущей сборки и не входил в её отслеживаемые файлы.
Рабочая сборка теперь отслеживает каждый принятый путь, включая отсутствующий,
и немедленно диагностирует отсутствующий файл вместо молчаливого пропуска.

Полный флажок `forms/commonObjects/event` остаётся снятым. В старом коде есть
ещё собственные регистрации `metadataTargetOccurrences` и исключение Events
из проекции основной формы. Их декларативное подключение и проверка
принадлежат следующему блоку; успешный XML ↔ YAML их не подменяет.
