# Полный файловый владелец WebSocket-клиента

### 2026-10-05 — автоматическое подключение WebSocket-клиента

Генератор полных файловых владельцев получил профиль `MetadataWebSocketClientRules`:
все 17 исходных свойств, декларация и рабочие маршруты созданы автоматически.
Компилятор и общие обработчики преобразования не менялись. Контрольная проверка
сначала обнаружила отсутствующую входную точку штатного каталога.

Проверка файловых владельцев теперь одна общая таблица XDTO и WebSocket:
десять реальных XML основной конфигурации и расширения, экспорт после удаления
исходного XML, копирование внешнего файла, создание нового объекта и устойчивый
UUID. Она выполняется как на небольшом AOT-наборе, так и в штатном приложении.
Сравнение XML и запуск компонента вынесены в общие тестовые помощники; новые
дубли устранены без исключений в настройках проверки.

Небольшой набор прошёл три проверки, включая полные файловые владельцы;
Clippy, 222 проверки инструмента переноса, архитектура Rust и поиск дублей
прошли. Приёмка на полном штатном проекте ещё выполняется; флажок WebSocket
остаётся снятым до её завершения. Исходные XML не менялись.

### 2026-10-05 — одинаковый смысл отсутствия в XML и YAML

Ruling: отсутствующее свойство заимствованного объекта с обычным XML-default
не подставляет этот default ни при чтении XML, ни при чтении YAML. Явно пустой
элемент сохраняет своё прежнее значение. Условия выводятся из исходных
параметров rules.ts, без ветвлений по WebSocket или имени поля в Rust.

Проверка общего правила сначала упала на отсутствующей коллекции, затем прошла
после исправления переносчика. Перегенерирован файловый каталог; остальные
зависимые генераторы подтвердили отсутствие устаревших результатов через --check.
Прошли 222 проверки переносчика, три проверки файловой границы и Clippy,
проверки архитектуры Rust и TypeScript, поиск новых дублей и полный pnpm test.

Старое YAML-ожидание для расширенного WebSocket-модуля уточнено по неизменному
XML: объявлено состояние Extended, файл расширения отсутствует, базовый файл
присутствует. Такое нарушение сохраняется как автоматически выведенная аномалия.
Явно пустая история также сохраняется, когда прежний YAML-эталон её терял.
Полная проверка штатного Rust-каталога ещё выполняется; флажок пока не выставлен.

### 2026-10-05 — WebSocket-клиент принят полностью

В штатном приложении прошли 46 проверок фактов и полных владельцев, 11 проверок
ресурсов и одна проверка CLI. Полный CF/CFE-проект проверен по независимому YAML
и неизменному XML; также проверены реальные байты модуля и отсутствие файла.
Общая матрица файловых владельцев защищает новый объект, устойчивый UUID и
обратный экспорт после удаления исходного XML. Все 17 свойств перенесены
автоматически из rules.ts; флажок WebSocket-клиента выставлен.

Дополнительное уточнение ожиданий: пустая история WebSocket восстанавливается
из обычного договора, отдельная пометка для неё не нужна. Ранее добавленное
ожидание такой пометки снято после полной проверки; прежний пустой YAML-эталон
сохранён. Аномалия отсутствующего расширенного модуля подтверждена исходными
данными и сохраняется. XML-фикстуры, обработчики Rust и ограничения не менялись.

Следующий готовый по составу правил владелец — язык (8 свойств). Для него общий
маршрут должен поддержать плоское размещение YAML параметром профиля; приёмка
языка ещё не завершена и его флажок остаётся снятым. Цель 10× этим блоком не измерялась.
