# Именованные полные записи

Генератор автоматически использует `keyField` из регистрации коллекции:
`record-mapping` поднимает соответствующее поле в ключ YAML, а остальные
свойства берёт из полной декларации элемента. Поддержаны простые и составные
записи с независимым ключом. Обычное чтение потоковое; обычная запись исключает
поле ключа непосредственно сгенерированным кодом, без повторного разбора YAML.

Проверены двенадцать случаев в `test:migration-collections`: массив и словарь,
пустота, повторяющиеся, отсутствующие и запрещённые имена, неправильное значение,
составная запись и вложенное сохранение XML. Ожидания заданы отдельно от
деклараций. Дополнительно проверяется отказ валидации для запрещённого имени,
повторного ключа и попытки повторить имя внутри записи. Границы языка и JSON
Schema проверяются в существующей матрице `rule-compiler/tests/sequence.rs`.

Проверка составной записи обнаружила общую ошибку отступов вложенного YAML.
Она исправлена в генераторе записи. Для восстановления аномального дочернего
свойства добавлено восстановление одной именованной записи с возвращённым
полем ключа. Этот путь вызывается после неуспеха обычного потокового чтения;
как и прежнее восстановление элемента массива, он может разбирать исходный
YAML целиком и не считается быстрым нормальным путём.

JSON Schema описывает тело без поля ключа и помечает необходимость проверки
скомпилированным валидатором. Ограничения над полной записью нельзя исполнять
против одного тела, в котором ключа уже нет. Полный Rust-валидатор получает
восстановленную запись и проверяет исходные ограничения. Если поле ключа уже
несёт отметку аномалии, исходный элемент сохраняется общей аномалией коллекции.
Проверка наличия отметки не создаёт строку тега и не копирует контекст.
