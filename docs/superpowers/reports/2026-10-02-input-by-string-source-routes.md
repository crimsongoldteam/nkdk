# Рабочие источники реквизитов восьми семейств

Переносчик автоматически строит 8 сохранённых источников идентичности
и 32 проектных маршрута: импорт UUID, текущий YAML CF, местные реквизиты CFE,
реквизиты основы в контексте CFE. Каталоги, корни и атрибуты оболочки берутся
из исходных регистраций; поставщики реквизитов — из построенных деклараций.
Таблица фикстур содержит только имена проверочных примеров.

Профиль идентичности общий, без повторного вклада в индекс корней. 24
источника реквизитов и 8 источников идентичности собираются в двух прежних
пакетах. Каждый занимает около 4,78 МиБ сгенерированного Rust при лимите
8 МиБ; основной пакет — около 30,15 МиБ при лимите 32 МиБ. Лимиты не менялись.

Проверка использует неизменные XML/YAML 8 объектов CF и 16 объектов CFE.
Проектная операция публикует идентичность, копии исходного XML удаляются,
затем источники читают текущие первичные YAML. Проверены 8 источников CF
и 24 источника CFE, точные UUID и число источников каждого владельца.
Все реальные имена реквизитов и отсутствующий ключ сравниваются с ранее
принятым корпусом прямых источников. Отсутствие реквизитов у владельца
допустимо; вложенные реквизиты табличной части не подменяют его коллекцию.
Отдельная общая проверка соединения основы защищает разные имена файлов
и видимость изменений YAML основы без повторного импорта XML.

В реальном подключении устранены два общих ограничения компилятора:

- Скалярный источник без вклада в индекс получает режим извлечения полей
  полного XML. Фиктивный индекс и повторные корни не требуются.
- Коллекция сохраняется из полного первичного YAML тем же читателем,
  которым она публикует факты. План источника хранит пару читателей XML/YAML.

Для обоих ограничений независимые проверки сначала воспроизвели ошибку,
затем прошли. Обычное преобразование осталось строгим; правила чтения
посторонних полей не расширились. Частных условий по объектам в Rust нет.
Самопроверка выполнена; независимое ревью без субагентов не заявляется.

Проверки: 52 теста приложения, 17 проверок вкладов компилятора, 10 проверок
генератора, проверка актуальности файлов, Clippy, проверка типов, три проверки
архитектуры, поиск дублей и проверка изменений прошли. Полный `pnpm test` также прошёл с кодом 0 после завершения Rust-сборок;
существующие пропуски сохранены, ограничения времени не менялись.

Это приёмка источников реквизитов. Для полного `InputByStringFields` остаются
проектные привязки сохранённых состояний и текущих числовых значений основы,
затем потребитель, сокращения и аномалии. Флажок common не поставлен;
полные владельцы принимаются отдельно. Скорость преобразования и цель 10×
в этом блоке не измерялись.
