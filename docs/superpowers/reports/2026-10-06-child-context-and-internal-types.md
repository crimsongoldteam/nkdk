# Контекст файловых детей и индексы внутренних типов

Общий файловый сборщик теперь автоматически подключает источники имён
дочерних форм и макетов, а также независимый источник неявных внутренних
типов. В Rust не добавлялись условия по хранилищу настроек, форме или макету.
Преобразования остаются предварительно скомпилированными.

При импорте текстовая проекция читает только объявленные пути и сохраняет
порядок с повторами. Соседние свойства полного XML не превращают эту
независимую проекцию в ошибку. Обычное преобразование остаётся строгим.
При экспорте текущие каталоги с объявленным файлом описания обновляют список:
удалённые имена исключаются, оставшиеся сохраняют порядок и повторы, новые
добавляются устойчиво. Ссылки файловой системы и каталоги без описаний
не включаются; действуют ограничения числа имён и размера путей.

Макеты получают существующую декларацию child-template-resources. Она
переносит XML-описание в Template.xml и сохраняет остальные ресурсы.
Этот же путь определяет файл описания для источника имён. Ранее сделанное
предположение об обязательном Шаблон.yaml исправлено после проверки
зарегистрированного resourceTopology; скрытого запасного поиска в Rust нет.
При переименовании исходного каталога меняются данные маршрута.

Внутренние типы читаются до полного владельца, без зависимости от собственных
индексов. Оба индекса используют реальный UUID владельца. Исходные UUID
сохраняются; новые детерминированно создаются существующим механизмом,
с включением UUID владельца в адрес. Защищены повтор операции, изменение
начальных данных и одинаковые имена под разными владельцами.

Настоящие неизменённые фикстуры хранилища настроек проверяют полный и пустой
списки детей, текущий YAML-каталог без исходного XML, добавление и удаление
форм, маршрут описания макета, исходные внутренние UUID и публикацию обоих
индексов. Проверка универсальности дополнительно переименовывает XML-пути,
поля и каталоги. Не размножались тесты по каждому использующему common полю.

Приёмка хранилища настроек ещё не завершена: требуется файловый маршрут
самих форм, все внешние файлы CF/CFE и проверка полного владельца в штатном
приложении. Его флажок остаётся пустым. Этот отчёт не подтверждает цели 10×
или снижение пика памяти всей сборки.
