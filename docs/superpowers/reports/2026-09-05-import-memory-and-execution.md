## 2026-09-08 — одинаковая подготовка DataPath перед локальным и обычным экспортом

путей сохраняется согласованным raw, включая invalid у смыслового значения.

### Окончательный список ссылок и откат его накопителя

В `worker` окончательный `pendingReferences` теперь берётся из локальных
границ, а не из повторного корневого обхода. Зависимые ссылки (включая
FillValue) извлекаются из окончательного `item` и выбранных в первом проходе
зависимостей `root`. `InputByStringFields` подключён к общему
`metadataTargetOccurrences`; без этой регистрации ссылки ввода по строке
терялись. Дополнительный парсинг/построение XML не добавлен.

Накопитель сохраняет исходные адреса и переименования коллекций через `place`.
При завершении он читает только адреса собранных ссылок, проверяет принадлежность
объектов итоговому YAML и окончательные аннотации. Отменённые записи и изменения
адресного дерева откатываются общим `createXmlImportAttemptJournal`:
`attemptParticipant` передаётся через локальный round-trip в существующий
journal свойства. Вложенный успешный commit не уничтожает undo-записи, пока
внешняя попытка может откатиться. Нет зависимости от GC/WeakRef для освобождения
отменённой ветви. Сильно удерживаются только границы со ссылками; служебные
сведения прочих границ лежат в WeakMap.

Первоначальный Map всех границ отклонён независимым ревью. Промежуточный
вариант с WeakRef также заменён: внутри одного JS job он не гарантировал
освобождения отменённого YAML. Рецензент проверил финальный journal и не нашёл
дефектов в его подключении и rollback после commit. Добавлены отдельные тесты
ошибки другого участника после commit и внешнего rollback после внутреннего

повторяющемуся имени. Аномалия списка не переносится на каждую вложенную ссылку:
семантическая отметка принадлежит точному пути, raw исключает всё поддерево.

### Обнаруженное расхождение и исправление FillValue

`accepted-round-trip.json` содержит `summary.errors=12`, `succeeded=0`:
окончательная проверка YAML отклонила значения Автор у Действий и НастроекДействий.
`accepted-compare.json` честно показывает отсутствие всех 24506 файлов.
Временный runner первоначально считал только ошибку MCP/operation, хотя этот
ответ имел `ok=true`; теперь он также проверяет summary.errors и failed.
Серии accepted-export использовали прежний YAML и действительно завершились
успешно, но не покрывали это новое расхождение.

XML DesignTimeRef сам по себе допускается для ссылочного определяемого типа,
но получившаяся YAML-ссылка на Пользователи не входит в его фактические типы
Сотрудники/АвтоподстановкиДляОбъектов/ПолныеРоли. После удаления корневой проверки
граница реквизита собирала зависимые projectChecks для итогового состояния,
но выполняла только DataPath. Теперь она проверяет зависимые FillValue вместе
с DataPath через validateImportPendingChecks до единственного proof.
addressableRequired и referenceCoverage остаются на прежнем пути первого
прохода через composed validator; их перенос этим исправлением не заявляется. Новое применение
тега не вводится: восстанавливается существующая !xml/invalid-аннотация,
видимая в прежнем импортированном YAML.

Regression в worker.integration.test использует реальный двоичный индекс
определяемого типа и существующей пустой ссылки. Первые две неполные версии
теста проходили из-за отсутствия цели EmptyRef; после включения этой цели
воспроизведена именно потеря проверки типа. RED:
`/private/tmp/nkdk-final-fill-value-red3.log`; GREEN:
`/private/tmp/nkdk-final-fill-value-green.log`. Проверяется аннотация до proof
реквизита и опубликованное YAML, а не только наличие диагностического вызова.
