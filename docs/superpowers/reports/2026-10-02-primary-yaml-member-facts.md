# Факты о реквизитах из текущего YAML

Принят блок чтения первичных CF-данных для `InputByStringFields`. Это не
полная приёмка common и не полная сборка его восьми проектных владельцев.

## Изменения

- Источник именованной коллекции читает полный первичный YAML владельца.
  Общая потоковая проекция выбирает объявленные ключи на уровне документа
  и строки, сохраняя выбранные повторы и пометки; обычные преобразователи
  по-прежнему проверяют неизвестные поля. Второе дерево YAML не строится.
- Представление исходного XML/снимка отделено от первичного YAML типа.
  Первичный источник использует `common.type-description-items` и условие
  допустимости из YAML-профиля; общий список допустимых типов не копируется.
  `recordFactView` допускает явно заданное YAML-представление, сохраняя прежний
  способ развёрнутого представления по умолчанию.
- Отсутствующая именованная коллекция означает пустой набор фактов по
  декларации. Это проверено на настоящем плане видов характеристик, где
  нет корневого раздела `Реквизиты`, хотя есть вложенные реквизиты.
- При проекции записи на коллекцию скрытые поля получают свои объявленные
  значения при отсутствии. Общий механизм проверен независимо от метаданных,
  включая источник фактов, представленный самим списком.
- Запись с аномалией основного скалярного значения не объявляется доступным
  смысловым значением выбора. Зависимые проверки не читают отсутствующее число;
  исходная неверная длина номера и соседний список восстанавливаются.

Преобразования выполняются заранее созданным Rust-кодом. Условий по названиям
метаданных в ядре/компиляторе не добавлено. Фикстуры XML и YAML не изменялись;
проверки изменения данных используют копии строк в памяти.

## Проверки

Корпус `tests/migration/input-by-string-operation.json` содержит 72 сценария:
62 прежних и 10 новых — все восемь CF-владельцев с полным текущим YAML,
удаление строкового реквизита справочника и замена его типа на `ЛюбаяСсылка`.
Оба изменения меняют диагностику `ВводПоСтроке`, без повторного XML-импорта.

Проверка семейства выполнялась малыми каталогами последовательно: 43 случая
прошли до обнаружения ошибки доступности значения, затем 23 — до обнаружения
отсутствующей коллекции, затем последние 6 прошли после исправления. Оба
обнаруженных случая дополнительно проверены отдельно. Это результаты
последовательных проверок, а не один последний успешный запуск всех 72.

- Ядро: 89 проверок; после исправления замечания Clippy потоковое чтение
  повторно проверено 9 тестами `yaml_nodes`.
- Компилятор: 14 `contributions`; усиленный пример проекции дополнительно
  проверен после устранения дублирования подготовки индекса.
- Рабочий проектный путь: 39 тестов приложения `facts`.
- Полный `pnpm test`: код завершения 0; проверки переносчика 184/184.
  Существующие пропуски тестов остались; новые пропуски не добавлены.
- Clippy ядра и компилятора, форматирование, архитектурные проверки Rust/TS,
  `git diff --check` и поиск новых дублей относительно
  `2af2f299ed8241eac78d4db46b4a8421efe2f8f7` прошли.

Начальные неуспешные проверки не считаются успешными: исправлены неподходящее
представление типов, доступность частично разобранного выбора, отсутствие
коллекции, применение фильтра записи к источнику-списку и устаревшая
автоматически создаваемая проекция документа.

## Границы приёмки

Для common остаются первичные YAML расширений с пометками типов, например
`Строка(10)` вместе с `!изменять Булево`, и рабочие проектные маршруты.
Старый XML не должен подменять изменённые первичные данные. Флажок common
оставлен пустым; число полностью принятых объектов не увеличено.

При исследовании обнаружены отдельные неподдержанные сочетания: сырая
оболочка ошибочного значения внутри обязательной скалярной пометки выбора
и некоторые одиночные непомеченные выборы над записью с лексиконом.
Их приёмка этим блоком не подтверждается; они включены в дальнейший план.

Лимиты размера создаваемого кода и последовательная сборка сохранены.
Во время рабочей сборки наблюдался один rustc с RSS около 3,17 ГиБ;
это одиночный снимок, не измеренный пик. Сборка теста приложения заняла
3 мин 20 с, сами 39 проверок — 1,96 с. Скорость XML ↔ YAML и целевой
выигрыш 10× по времени/памяти в этом блоке не измерялись.
