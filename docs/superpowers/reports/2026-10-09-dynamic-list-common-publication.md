# DynamicList: публикация common и проверка свойства владельца

Из всех21 сохраняемых свойств исходного DynamicListRules собирается
`common.dynamic-list`. Готовые коллекции и зависимости используются повторно;
библиотека публикуется прежним инструментом common-family. Индексы задаются
данными существующего реестра, отдельного обработчика DynamicList в Rust нет.

Настоящее свойство FormAttributeRules.dynamicList распознаётся переносчиком
и получает common с переданным parentName. Три примера вложенного свойства
получены из прежних полного/минимального/повреждённого XML и независимых
ожиданий внешнего файла запроса. Другие свойства FormAttribute и проектная
адресация этими примерами не принимаются.

Нативная проверка обнаружила две общие недоработки: наружная запись не
получала текстовые файлы вложенного common и не запрашивала их пути.
Компилятор теперь выводит оба действия по ссылкам на записи и их параметрам.
Перед контрольным восстановлением XML используются уже подготовленные
файлы; промежуточные обработчики передают владение данными без копирования
содержимого. Граф деклараций обходится только при компиляции.

Нейтральный пример проверяет обе стороны преобразования многострочного
текста, пустого и отсутствующего файла, обычных соседних свойств и запрос
пути файла. Проверяются обычная генерация и общие AOT-пакеты. Дополнительные
условия по имени свойства или виду метаданных не добавлены.

Граница: восемь требований адресации по YAML остаются обязанностями операции.
Вычисляемый settingsComposer в YAML не переносится. Флажки полного DynamicList
и FormAttribute остаются снятыми; счётчик принятых common пока56/90.

Проверка вложения обнаружила ещё две общие причины потери данных.
При объединении полей внутренние оболочки сохранения XML теперь передают
смысловые значения; сохранение исходной формы рассчитывается заново для
полной записи. Независимые внешние XML-файлы сохраняют свои границы.
Для связанной коллекции маршрутизация учитывает объявленный путь следующего
элемента вместе с его поддеревом: все четыре группы реального списка остаются
читаемыми в YAML, а не прячутся в сохранённом XML.

Оба случая воспроизведены нейтральными тестами обычной генерации и общих
AOT-пакетов. Полный, минимальный и повреждённый реальные примеры прошли проверку
заново созданного AOT-каталога: 3/3 договора. Диагностические ручные правки
подготовленного кода заменены результатом генератора. Генератор для этого
запуска собран с оптимизацией; режим исполнения конвертера не изменён.
Пересборка подготовленных пакетов заняла 3 мин 17 с; это не замер холодной
сборки всего проекта и не подтверждение цели 10×.

Проверки: 6 целевых Rust-тестов (обычная и общая AOT-генерация), 71 тест
переносчика, воспроизводимость публикации 6 библиотечных деклараций,
Clippy, архитектурные ограничения и отсутствие новых дублей прошли.
Полный `pnpm test` вне песочницы завершился с кодом 0 отдельно от Rust-сборок.
Первый запуск оборвался при почти заполненном диске; после удаления
устаревших сборочных кэшей повторный запуск прошёл без изменения проверок.
Журнал: `/tmp/nkdk-common-list-full-project-test-retry.log`.
XML-фикстуры не изменены. Проверка универсальности выполнена самостоятельно,
без независимого ревью: компилятор опирается на формы деклараций и пути,
а не на имена DynamicList, его полей или объектов 1С.
