# YAML-кандидаты для массового переноса

Команда: `pnpm migration:candidates`. Выходной каталог:
[rules-candidates](../../../tests/migration/rules-candidates/manifest.json).
Рабочие декларации находятся отдельно, в rust/declarations, и не изменяются.

## Результат генерации

- 4109 вхождений свойств получили кандидаты.
- 986 уникальных фрагментов и 933 уникальных проекций.
- 271 существующих common/перечислений подключены как снимки зависимостей.

Проекция — только поддержанные свойства под относительным XML-корнем.
Это не полный Document, DocumentJournal, реквизит или элемент формы.
Пространства имён и оболочка владельца ещё не связаны; полного преобразования
реального объекта здесь нет. Флажки готовности объектов не устанавливаются.

## Сохранённые договоры

Поддержан ограниченный профиль boolean, string, number, SystemEnumeration,
I8nText, FormattedI8nText, MinMaxValue, FieldsList, WebSocketClientHeaders,
XDTOPackages, XDTOTypeName, IndexField, StringOrNumber, UsePurposes и MetadataCommandGroup. MetadataItemLink
поддержан для собственной/общей формы и нумератора документа; остальные
целевые ограничения остаются блокировками. MetadataItemLinks поддержан для
списков документов и «Вводится на основании» с проверенными путями целей.
Для логических свойств различаются неявные XML/YAML значения. Явные значения
с preserveExplicitDefaultXML сохраняются без правила удаления из YAML.
Постоянные minimum/maximum чисел переносятся в общие ограничения декларации;
нарушение сохраняет значение с автоматически выведенной аномалией. Сейчас
переносятся только точно представимые целые границы; зависимые maximumWhen
и неразобранные точные записи остаются блокировками.
Для UsePurposes различаются базовый профиль и профиль с назначением Платформа
по умолчанию. Постоянная стрелочная функция defaultValue извлекается только
при отсутствии аргументов, async, вызовов и внешних ссылок; её происхождение
сохраняется в constantDefaults. Динамические функции не исполняются.
Типизированные входы индексов
переносятся вместе с зависимостями типов. Common подключаются по идентификаторам, не копируются
в каждое свойство. Значения по умолчанию, XML-пути, YAML-имена и известный
xmlOrder записаны в декларации. Для I8nText объявлены входы имени и языков.
Пути с префиксами получают пространства имён из статически прочитанного
FORM_NAMESPACES; источник и соответствия записаны в manifest.json.
Неизвестный префикс блокирует перенос. Пространство имён непомеченной
оболочки владельца не угадывается по этому списку.
Параметр toEnterprise=false не блокирует XML/YAML: направление Enterprise
исключено из согласованного перехода. Такие параметры явно записаны в
excludedParameters у свойства; остальные неизвестные параметры блокируют перенос.
Совпадающее обычное и заимствованное значение по умолчанию подтверждается
в parameterEquivalences; различающиеся значения не объединяются.
Дробные и небезопасные целые значения по умолчанию требуют разбора исходной точной записи.

Проекции разделяются по метке XML-источника (tag) и XML-корню; Metadata и Form
не смешиваются. Общие чистые фрагменты могут использоваться обоими маршрутами.
Фрагменты группируются по исходному объявлению и совместимому XML-корню;
переопределённый состав получает отдельный вариант. Совпадающий состав
используется повторно несколькими владельцами. Происхождение и соответствие
свойств сохранены в manifest.json, а не дополнительными полями языка YAML.

Ранее написанные YAML служат источником зависимостей и не перезаписываются.
Для 720 полей найдены возможные соответствия
в рабочем каталоге по common, YAML-ключу и суффиксу XML-пути. В manifest.json
записаны различия пути, присутствия XML и YAML, параметров, входов и ограничений (до трёх примеров
на поле с полным числом совпадений). Это список для проверки, не доказательство
эквивалентности: границы XML, пространства имён и состав владельцев различаются.
Семантическое сравнение и автоматическая замена рабочих деклараций не выполнялись.

## Повторяемость и защита файлов

Перед генерацией проверяются перечень TS-файлов и хеши снимка извлечения.
Хеши использованного каталога деклараций записаны отдельно. Одинаковый вход
даёт одинаковый набор YAML. При ручном изменении, удалении или появлении
постороннего файла в каталоге кандидатов повторная генерация прекращается.
Изменять можно только собственные ранее неизменённые результаты генератора.

Проверка кандидатов:

`rust/target/debug/nkdk-dev declarations check --dir tests/migration/rules-candidates`

Она проверяет синтаксис и ссылки. Команда declarations compile дополнительно
проверяет генерацию Rust-кода; успешная генерация не заменяет cargo check
полученных исходников и XML/YAML-проверки поведения.

## Дальнейшая работа

Сначала перенести независимые ожидаемые результаты в общий запускатель,
проверить кандидаты в обоих направлениях и связать их XML-контекст с
владельцами. Затем сравнить с уже написанными декларациями и принимать
связанные группы. Пока ни один кандидат не включён в рабочую сборку.
