# Параметры формы: декларации и автоматическое подключение

## Результат

Три поля FormParameter (имя, тип, признак «Ключевой») и именованная
коллекция FormParameters описаны YAML-декларациями. Для преобразования,
проверки и обратного восстановления используются существующие общие
механизмы Rust. Частных обработчиков параметров формы в Rust не добавлено.

Переносчик распознаёт регистрацию FormParameters в обоих исходных правилах
формы. Проверяет допустимые параметры регистрации, учитывает XML-источник
`Form`, имя свойства и пространство имён. Проверка с переименованным
свойством и XML-путём защищает от привязки к конкретному имени.

## Договор и независимые ожидания

- Запись без типа сокращается до `ПараметрБезТипа:`; общий существующий
  режим `emptyRowNull` восстанавливает запись и пустой `<Type/>`.
- Явное `KeyParameter=false` остаётся `Ключевой: Ложь`. Хотя rules.ts
  содержит implicitValueYAML=false, фактические старые функции коллекции
  сохраняют это значение. Отсутствие признака не заменяется значением false.
- Пустая коллекция — `{}`. Порядок различных имён сохраняется.
- Повтор имени сохраняется автоматически через `!xml/raw` коллекции;
  YAML-словарь сам по себе не восстанавливает повторяющиеся XML-строки.
- Неверное булево значение внутри строки сохраняется существующим общим
  механизмом локального XML-дополнения (`KeyParameter: !xml/raw`). Это
  проверенный текущий формат, а не новый обработчик или договор `!xml/invalid`.
  Соседний параметр сохраняется; исходный XML восстанавливается без референса.

При выделении проверочного XML сохраняются пространства имён вложенной
коллекции, объявления префиксов значений QName и пути для их сравнения.
Для скалярных проекций сохранён прежний договор удаления пространства
имён корня. Флаг QName относится к подготовке независимых проверочных
данных; он не меняет исполнение декларации.

## Воспроизводимая проверка

`pnpm test:migration-family --family form-parameters`

12 сценариев: два неизменённых старых XML-примера, явное false, неверное
булево с соседней строкой, пустая коллекция, порядок, повтор имени,
переименование префикса XML Schema, формы загрузки/сохранения в CF/CFE.
Ожидания YAML берутся из старых проверок либо независимых e2e-файлов.
Для реальных форм декларация свойства собирается переносчиком из
ClientApplicationFormRules; это не вручную подключённая копия правила.

## Границы приёмки

Проверяется целая коллекция параметров, но лишь эта часть содержимого формы.
Файловая операция SettingsStorage и полные формы остаются с пустыми флажками.
Следующий блок: командная панель, коллекция реквизитов, затем сборка содержимого
и метаданных формы из двух физических XML-источников с файловыми ресурсами.
Нельзя заменять эту работу копированием исходного Form.xml.

Проверки прошли: 12 AOT-сценариев, 226 проверок переносчика, полный `pnpm test`
вне песочницы, type-check, три проверки архитектуры, Clippy с `-D warnings`,
проверка дублей относительно 91a01277 и git diff --check. Полный набор
сообщает о превышении существующей цели 10 ms одним тестом MCP; код выхода 0.
После привязки отбора фикстур непосредственно к выходу sourceContract повторно
проверены AOT-сценарии и затронутые проверки переносчика. Независимое ревью
не выполнялось: проведена самопроверка по .agents/declarative-review.md,
работа без субагентов по указанию пользователя.
