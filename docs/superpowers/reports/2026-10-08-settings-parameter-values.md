# ParameterValue и SettingsParameterValueCollection: сверка старых договоров

Полная приёмка пока открыта, флажки этих объектов не установлены.

Из исходных TypeScript-фикстур автоматически перенесены восемь независимых
пар XML/YAML в `tests/migration/settings-parameter-legacy.json`.
Сохранены контрольные суммы обоих файлов исходных констант. Конвертеры TS
для построения ожидаемых результатов не запускаются.
Проверки формируются в `tools/rules-migration/src/settings-parameter-cases.mjs`.
Одинаковые режимы используют одну декларацию; каждое семейство собирается отдельно.

## Проверено

- Обычное Field из неизменённого full.xml и системное перечисление Receipt/Приход.
- Primitive: строка "123", точное число 123, короткая и полная запись,
  обратный экспорт и смешанная коллекция с сохранением порядка.
- Старые TypeLink, Parameter, ChoiceParameterLinks, SystemEnumeration,
  оба Color и одиночный DesignTimeValue/LocalStringType.
- Полные словари системных перечислений и существующие факты элементов стиля.

Field теперь использует полный выбор значений из общей декларации, включая
перечисления; написание обычного поля параметра сохраняется без точки фильтра.
Скалярная проекция передаёт исходное событие YAML с признаком кавычек.
Проекции не требуют конструировать заново весь объект.

Для LocalStringType восстановлено прежнее сокращение оболочки. Общий
компилятор сравнивает прочие поля с их объявленными значениями при отсутствии;
служебные значения и сохранённые аномалии исключают сокращение. Писатель
удаляет известную оболочку своего результата без повторного разбора YAML.
Предметных условий по именам типов в Rust не добавлено.

## Остаётся

Старая фикстура fewValues содержит два соседних dcscor:value.
Текущая декларация поля описывает одно значение, поэтому возникает пометка
всей коллекции. Это допустимые данные, и нельзя подменять недостающий договор
аномалией. Нужно выразить кардинальность значений декларативно, сохранив
одиночную форму, порядок, повторы, nil и отсутствие. При этом внутренний
список ChoiceParameterLinks нельзя ошибочно принять за несколько значений
параметра; выбор формы должен учитывать договор значения.

После этого: полная старая матрица, реальные e2e-коллекции, рабочая публикация,
сравнение производительности сокращённого и обычного путей, полные проверки
и только затем машинное покрытие и флажки common. Полные владельцы отдельно.

Приёмка аномального элемента после введения коллекции: если проекция выдала
`!xml/raw` с пустым `$значение: {}` и полной заменой `$xml`, читатель коллекции
восстанавливает элемент как целую сохранённую XML-форму. Это эквивалент короткой
записи элемента только с `$xml`; непустые смысловые данные не отбрасываются.
В одиночной коллекции пометка остаётся на элементе списка под `Значение`,
а не переносится на всю коллекцию параметров. Обратный XML и проверка YAML
проверяются общим запускателем. Распознавание применяется только к помеченному
входу; обычный путь не разбирает YAML повторно.

## Повторное использование тел записей: новый опыт

Выгрузка полного исходника выявила 617 тел записей, в том числе восемь
почти одинаковых тел по 1,18 МБ. Вместо переписывания самого Rust-кода
теперь сравниваем его с учётом локальных имён, сохраняем первое тело
без изменений и публикуем псевдонимы для других подключений.
Имена импортированных автоматов учитываются отдельно от локальных
псевдонимов: разные зависимости, пути, литералы и номера входов
не считаются одним договором. В ядре исполнения нет нового обработчика.

На том же наборе десяти корней Rust сократился с 80 471 725 до
12 861 186 байт, тела записей — с 617 до 99. Генерация стала медленнее:
34,4 с в локальном исходном замере против 62,8 с после изменения.
Это замер генерации, а не сборки rustc и не скорости преобразования.
Внешние файлы автоматов в объём Rust не включены.

Проверки сравнения защищают литералы, номера входов, внешние символы
и цели импортов. Общая нативная матрица расширена двумя независимо
названными владельцами: ноль/один/повторяющиеся элементы, теги и
сохранение исходного XML проверены в обоих направлениях.
Полная приёмка оптимизации, замеры исполнения и регистрация каталога
ещё продолжаются; флажки common пока не изменены.

### Вложенные параметры и передача входов

Добавлен независимый пример с родителем, двумя соседними параметрами и внуком:
`Родитель`, `Первый`, `Второй`, `Внук` должны остаться разными значениями.
Коллекция `Элементы` описана рекурсивно в YAML; пустые дочерние списки сокращаются.
Изначально общий рекурсивный переходник применял объявленную привязку входов
только при завершении чтения YAML, а выбор варианта во время чтения получал
позиции входов родителя. Это вызывало ошибку выбора и повторное чтение внешнего
значения при восстановлении. Привязка теперь применяется и при чтении событий.
Целевой пример прошёл: `/tmp/nkdk-nested-rebind.log`.

Дополнительный общий пример с разными позициями входов удалён: контрольный
запуск показал, что он проходит даже без исправления. Ошибку защищает независимый
пример вложенных параметров, который падал до исправления. Рабочая матрица
дополнена шрифтом и выравниванием,
всего 27 случаев и 20 подготовленных деклараций. Полная приёмка этих двух common
ещё не отмечена: остаются окончательные проверки каталога, схем и редких форм.

старые ожидания не менялись. Это ещё не полная приёмка common или проекта.

Окончательные проверки текущего блока: 23 внутренних теста компилятора,

### Дочерние параметры: нормальная форма XML
