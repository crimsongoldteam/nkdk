# Десять владельцев табличной части: приёмка e2e

Составные декларации `BusinessProcess`, `ChartOfAccounts`,
`ChartOfCalculationTypes`, `ChartOfCharacteristicTypes`, `DataProcessor`,
`ExchangePlan`, `Report` и `Task` собраны автоматически из извлечённых `rules.ts`. Источники
индексов владельцев и форм получены из неизменённых e2e XML; для ссылок на
формы другого объекта прочитаны его заголовок и заголовок формы. Отдельные
источники одной декларации различаются собственным идентификатором.

Все восемь случаев прошли компиляцию, подготовку фактов, независимое сравнение
XML → YAML и обратное восстановление XML без референса. До исправления
обнаружились два класса различий:

| Владелец | `ПутьКДанным` | `ФормаВыбора` |
|---|---|---|
| BusinessProcess | XML-имена сегментов вместо переведённых | краткое имя вместо полной ссылки |
| DataProcessor | XML-имена сегментов вместо переведённых | совпало |
| ExchangePlan | XML-имена сегментов вместо переведённых | краткое имя вместо полной ссылки |
| Report | XML-имена сегментов вместо переведённых | совпало |
| Task | XML-имена сегментов вместо переведённых | краткое имя вместо полной ссылки |

Пример для `ExchangePlan`: эталон содержит
`ExchangePlan.ПланОбменаВсеСвойства.StandardAttribute.Description`, а
текущая декларация выдаёт
`ПланОбмена.ПланОбменаВсеСвойства.СтандартныйРеквизит.Наименование`.
Для `ChoiceForm` XML содержит
`Catalog.СправочникРеквизит.Form.ФормаВыбора`, тип реквизита в YAML —
`Справочник.СправочникРеквизит`; эталонная форма — `ФормаВыбора`, а
текущая декларация выдаёт полную русскую ссылку.

Первое отличие устранено в общей декларации `common.choice-parameter-links`:
`ПутьКДанным` сохраняет XML-написание, когда нет контекста данных формы.
Отдельные полные e2e-проверки `DataProcessor` и `Report` после этого прошли.

Для второго отличия создана декларация `common.type-form-link`, которая
сокращает ссылку на форму при единственном объектном `Тип`. Компилятор
передаёт ей привязанные входы владельца, включая коллекцию `items` соседнего
составного поля. До исправления вызов читал чужой вход и сохранял коллекцию
реквизитов через `!xml/raw`; после исправления краткая форма восстановила
исходную полную XML-ссылку. Пять исходных сценариев теперь проходят без этого тега.

Три плана подключены тем же сборщиком без частных Rust-ветвей. Их правило
`InternalInfo` записано в TS с приведением `as never`, но вычисляет то же
составное имя владельца и табличной части. Переносчик распознаёт эту форму;
план счетов, план видов расчёта и план видов характеристик прошли отдельные
полные e2e-прогоны XML ↔ YAML.

Следующее семейство `document-attributes` также прошло все 15 e2e-сценариев,
включая заполненную `ФормаВыбора` в cf/cfe. Для общего компилятора добавлена
проверка границ входов вместо аварийного завершения и сохранена независимость
декларации ссылки на форму от конкретного владельца.

Два оставшихся владельца, `Document` и `Catalog`, подключены к тому же
сборщику. Все десять владельцев проверены и в основной конфигурации `cf`, и в
расширении `cfe`: всего 20 полных сценариев. Пустой `<ChoiceForm/>` в прежнем YAML расширения местами записан
как `ФормаВыбора: null`; в каноническом YAML он опускается, а при экспорте
восстанавливается. Для стандартного реквизита `НомерСтроки` пустая запись
остаётся явной `{}`, иначе общий механизм исключения пустых значений ошибочно
сохранял бы всю группу как аномалию. Никаких новых `!xml` для этих случаев
не понадобилось.

Декларация табличной части теперь одна на пару `cf`/`cfe`: 20 сценариев
используют десять объявлений владельцев и раздельные источники фактов.
Повторная проверка расширения при совпадающем составе объявлений не запускает
новую сборку Rust (0,02 с после первой сборки пары). У плана обмена набор
зависимостей отличается, поэтому он собирается отдельно. Число объявлений
в семейном каталоге восьми владельцев сократилось с 273 до 218. Объявления
документа и справочника уже находились в каталоге реквизитов документа и
используются повторно без копирования в новый файл.

Вложенные UUID теперь публикуются из уже прочитанных строк табличной части.
Составление коллекции сохраняет вклады фрагментов, а Rust-компилятор исполняет
их после проверки строки. Коллекции документа и справочника, а также
объединённый владелец прошли e2e без отдельного источника XML для вложенных
реквизитов. Коллекция справочника содержит две табличные части и получает
InternalInfo каждой из собственных исходных элементов. Проверка компилятора
с двумя строками подтверждает одинаковые факты для XML и YAML и неготовность
затронутого индекса при ошибке второй строки. Неверное
число `LineNumberLength=bad` автоматически превращается в локальный
`LineNumberLength: !xml/raw` и восстанавливается из YAML; соседний
`Комментарий` остаётся обычным значением. После изменения повторно прошли
12 исходных e2e-сценариев семейства реквизитов документа и три дополнительных:
явный пустой синоним, коллекция справочника и неверная длина номера строки.
Дополнительно из того же неизменённого e2e-каталога справочника взята
минимальная табличная часть без вложенных реквизитов. Она даёт только
`ДлинаНомераСтроки: 9` в YAML и восстанавливает исходный XML без референса.
Итого повторный семейный прогон прошёл для 21 случая: 20 полных пар
`cf`/`cfe` и одной минимальной формы. Также прошли 135 проверок переносчика,
архитектурные проверки и поиск новых дублей относительно
`2af2f299ed8241eac78d4db46b4a8421efe2f8f7`. После обновления
чеклиста и реестра покрытия прошли полный `pnpm test`, `pnpm type-check`,
тесты Rust-компилятора и Clippy.

Частных Rust-ветвей по имени владельца и подмены эталонного YAML нет.
Явный пустой `<Synonym/>` хранится как `Синоним: ""` и восстанавливается.
Физическое имя `LineNumberLength` в аномалии намеренно: смыслового числа
для русского поля YAML нет.
