# Настройки реквизита формы: следующий блок

Исследованы действующие преобразования и неизменённые XML-примеры.
Полный FormAttribute ещё не принят; этот документ фиксирует зависимости
следующего блока, а не отмечает их завершёнными.

## Пять разновидностей с одним договором

`settingsFragment/types.ts` уже объединяет Chart, GanttChart,
FlowchartContext, SpreadsheetDocument и Planner. Их смысловое значение —
строка с XML-содержимым Settings. Это обычное значение свойства в нынешнем
YAML, а не запасной путь `!xml/raw` для отсутствующего преобразования.

| Вид | YAML-свойство | XML-тип | Пространство имён |
|---|---|---|---|
| Chart | Диаграмма | Chart | http://v8.1c.ru/8.2/data/chart |
| GanttChart | ДиаграммаГанта | GanttChart | http://v8.1c.ru/8.2/data/chart |
| FlowchartContext | ГрафическаяСхема | FlowchartContextType | http://v8.1c.ru/8.2/data/graphscheme |
| SpreadsheetDocument | ТабличныйДокумент | SpreadsheetDocument | http://v8.1c.ru/8.2/data/spreadsheet |
| Planner | Планировщик | Planner | http://v8.1c.ru/8.3/data/planner |

Не переносить пять функций в Rust-оркестратор. Нужен один общий договор
содержимого XML с параметризованной оболочкой и декларативным выбором по
полным XML-именам типов. Смена префикса не должна менять выбранный вариант.
Наличие нескольких YAML-свойств одновременно — отклонение от нормального
взаимоисключающего выбора; нельзя молча брать первое, как старый экспорт.

## Проверочные примеры

Источники в `packages/rules/metadata/forms/commonObjects/formAttribute/__fixtures__/`:

- `chartSettings.xml` и `chartSettings.ts`: вложенный ряд, атрибуты линии,
  `v8ui:style` с типом QName и пустые элементы осей.
- `ganttChartSettings.xml` и `.ts`: пустое вложенное `d4p1:chart`.
- `spreadsheetDocumentSettings.xml` и `.ts`: настройки языка, размеры,
  строка и формат; пустые вложенные элементы.
- `plannerSettings.xml` и `.ts`: три числовых поля внутри XML-строки.
- `plannerSettingsWithNil.xml` и `.ts`: `xsi:nil="true"` внутри значения
  сохраняется рядом с обычным текстом.

Ожидаемые смысловые строки брать из существующих `.ts`, не получать из
проверяемой декларации. Сравнение структур XML не заменяет проверку
ожидаемого YAML. Для FlowchartContext отдельно найти реальное поддерево
в e2e; нельзя принять всю разновидность только по пустому Settings.

Для общего механизма проверить: несколько дочерних элементов, текст и
атрибуты, QName и объявленные выше пространства имён, пустое содержимое,
nil, неизвестный тип, ошибочную XML-строку в YAML, экспорт без референса.
Оболочка и значение проверяются отдельно: нельзя потерять атрибуты Settings,
которые не вошли в строку содержимого. Нестандартная исходная оболочка
сохраняется автоматически общей системой аномалий.

## DynamicList — отдельная зависимость

`dynamicList/rules.ts` описывает полноценную запись с собственными common,
перечислениями, вложенными коллекциями и ListSettings. Нельзя выдавать её
за шестую XML-строку, чтобы обойти недостающие декларации. Переносить через
массовый инструмент rules.ts вместе с рекурсивной таблицей зависимостей.

## Порядок реализации

1. Закрыть один общий договор XML-содержимого, проверив ограничения
   существующего языка и AOT-компилятора. Не создавать частные операции
   с именами Chart/Planner в нейтральном runtime.
2. Описать пять оболочек данными и подключить их в Settings-выбор.
3. Перенести зависимости DynamicList стандартным инструментом rules.ts.
4. Собрать весь FormAttribute: прежние скалярные свойства, Type, Title,
   Settings, обычные и дополнительные колонки, имя/id и общие индексы.
5. Проверить настоящий файловый маршрут и сохранение истории номеров;
   только затем отмечать флажок полного владельца.

Скорость выполнения остаётся обязательным ограничением. Для обычного XML
не строить второе дерево содержимого только ради копирования строки;
сначала исследовать возможность работы с диапазоном исходного документа.
Проверка и запись namespace-зависимого содержимого должны быть общими.

## 2026-10-07: ПоляКлюча динамического списка

Добавлена `common.dynamic-list-key-fields`: обычная последовательность текста,
один элемент записывается скаляром, несколько — списком. Отсутствие элементов
даёт пустой список и сокращается в YAML; существующий пустой элемент остаётся
пустой строкой. Порядок, повторы и строка `001` сохраняются. В отличие от старого
нормализатора, пустая строка не теряется и числовая запись не проходит через
число JavaScript. Неизвестный XML-атрибут сохраняется общей аномалией raw.
Нового частного обработчика Rust нет.

`DynamicListRules.keyFields` подключается переносчиком по имени типа из
`rules.ts`. Исправлены два общих ограничения: последовательность может быть
непосредственным ребёнком XML-корня, а не настроенное отдельно свойство
последовательности наследует договор присутствия common без подмены
искусственным «отсутствует». Явные настройки свойства остаются приоритетными.

Матрица `dynamic-list-settings` проверяет настоящий KeyField из неизменённой
фикстуры, список с повторами, числовую строку, пустую строку, отсутствие
списка и неизвестный атрибут. Все 6 Rust-сценариев прошли в обе стороны;
7 проверок общих последовательностей, Clippy и архитектура Rust также прошли.
Это приёмка зависимости; полного Settings, DynamicList и FormAttribute ещё нет.
