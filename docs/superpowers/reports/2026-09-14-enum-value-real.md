# Значения перечисления: рабочая операция Rust

Общий запускатель `pnpm test:migration-collections` теперь автоматически
генерирует декларации MetadataEnumerationValueRules и проверяет полные
EnumValue из `e2e/fixtures/xml/cf/Enums/ПеречислениеВсеСвойства.xml`.
Внутри элементов ничего не отбирается по списку свойств: сохраняются атрибуты,
дочерние узлы и порядок. Убирается только внешнее пространство MDClasses,
как в существующем запускателе кандидатов. Исходные фикстуры не изменены.

Ожидание берётся из целого блока «Значения» соответствующего YAML, включая
оба значения с разными синонимами и комментариями. Проверяется прямой результат
и обратное восстановление без XML-референса. UUID подготавливаются через
автоматически сгенерированный вклад в metadata.own-identities; компонент и UUID
владельца передаются отдельно. Хеши источников проверяются перед генерацией.

Извлечение объявленного профиля cf не меняет общий строгий режим переносчика:
неизвестные runtimeOnly-свойства и неизвестная регистрация остаются блокировками.
Отложенные роли владельца явно возвращаются как ownerRequirements.

## Основная конфигурация и расширение

К тому же запускателю подключены целые коллекции собственного и заимствованного
перечислений расширения. Базовые UUID берутся из проверенного по хешам перечня
исходных XML и подготавливаются существующим вкладом metadata.base-identities.
Оба направления получают новый контекст; обратное преобразование не получает
исходный XML как референс.

Переносчик дополняет результат обычными YAML-декларациями базовой ссылки,
коллекции PropertyState и вычисляемой применимости. Преобразования по именам
EnumValue, Synonym или ExtendedConfigurationObject в Rust не добавлены.
Обычный порядок YAML задаётся YAML-отображением независимо от XML-порядка;
проверки omitWhen участвуют в порядке чтения YAML-зависимостей.

### Исправление прежнего вывода о синониме

Задача про обязательное новое представление `Синоним: !изменять Текст` была
основана на неверном прочтении регистрации. Рабочий
`configurationExtension/propertyStates.ts` пропускает `representation: plain`.
Именно такой режим зарегистрирован для синонима EnumValue. Синоним поэтому
сохраняет обычное представление; избыточная строка Synonym/Extended может
сохраняться общим механизмом исходной XML-формы. Нормальная базовая строка Notify
сокращается таблицей состояний, а не заменяется raw.

### Совместимость YAML-тегов

yaml-rust2 0.11.0 отвергал существующий тег `!проверять` на стадии разбора.
В `third-party/yaml-rust2` сохранена копия этой версии с лицензиями и единственной
правкой сканера: допускаются не-ASCII буквы и цифры короткого тега. Входной YAML
не переписывается, повторного разбора нет. Происхождение и граница изменения
описаны в NKDK-PATCH.md. Архитектурная проверка допускает только этот точный
локальный путь для двух потребляющих библиотек.

### Граница приёмки

Это полное преобразование дочерних элементов в проверяемых профилях, но ещё
не полная приёмка объекта в проектном оркестраторе. Отложенные роли владельца
возвращаются как ownerRequirements; проверка совместимости также остаётся
открытой. Бинарные флажки полного перехода не выставлены; common — 19/90.

## Проверки завершённого блока

- `cargo +1.98.1 test --offline --locked --manifest-path rust/Cargo.toml
  -p nkdk-conversion-core -p nkdk-rule-compiler -p nkdk-compiled-rules -j1`:
  209 тестов прошли. Сборка выполнялась с отключёнными incremental и debug info.
- `pnpm test:migration-collections`: 70 договоров прошли. Среди них три полные
  исходные коллекции, Notify, обе формы отсутствующей базовой ссылки, повторы
  и соседние строки PropertyState в разном порядке.
- `pnpm test:migration-inventory`: 28 проверок прошли.
- Clippy для conversion-core и rule-compiler, включая все их тестовые цели,
  прошёл с `-D warnings`.
- `pnpm test:architecture:rust` и проверка новых дублей относительно `9f989da08`
  прошли. Исходные XML-фикстуры не изменялись.

Полный `pnpm test`, приёмка проектной операции и замеры 10× в этот блок
не входят. В сборке всего каталога есть предупреждение системного линковщика
о размере таблицы разворачивания стека; запускатель кандидатов также выдаёт
предупреждения о неиспользуемых переменных в сгенерированном коде. Они не
скрыты и не объявлены исправленными результатом Clippy двух библиотек.

## Подключение к рабочей операции

Автоматический выпуск сохраняет три связанные декларации в
`rust/declarations/objects/enumeration-values.generated.yaml` и независимые
ожидания e2e в `tests/migration/enum-values-operation.json`.
В рабочем каталоге доступен вход `metadata.enumeration-values`.
Проверка актуальности входит в `test:migration-inventory`: изменения правил
или исходных примеров без повторного выпуска обнаруживаются автоматически.

Матрица в `rust/apps/nkdk/tests/facts.rs` выполняет девять случаев через
`nkdk::conversion::prepare`. Собственные и базовые UUID подготавливает
`nkdk::facts::prepare`; экспорт получает новый подготовленный контекст.
В запрос преобразования XML-референс не передаётся. Ожидания YAML проверяются
отдельно; результат экспорта сравнивается с полным исходным XML элемента.

Это подключение к библиотечному API рабочей операции. Оно не добавляет
автоматическое обнаружение всех файлов проекта в CLI и не заменяет отложенную
проверку совместимости и дополнительных ролей владельца. Бинарная отметка
полной приёмки остаётся снятой.

### Сведения о членах владельца

Из извлечённых ownerFactRole и configurationIndexUidSegment генератор
выпускает два обычных вклада: metadata.owner-members (наличие имени у
владельца и роли) и metadata.owner-member-identities (UUID по владельцу,
сегменту и имени). Общий Rust-механизм индексов не содержит этих предметных
соответствий. Неизвестная роль блокирует выпуск рабочего входа.

Эта проекция предназначена для поиска по имени; она не является переносом
всего двоичного ProjectState TS или его массивов. Порядок исходной коллекции
по-прежнему сохраняется самим преобразованием.

Проверка рабочего приложения после подключения индексов прошла: 9 тестов,
включая девять e2e-вариантов в общей матрице. Ожидаемые имена/UUID членов
владельца получены из отдельного перечня XML-идентичностей с проверкой хешей.
Проверки переноса — 29; повторный выпуск декларации детерминирован.

Clippy приложения (`-p nkdk --all-targets --no-deps -- -D warnings`),
архитектурная проверка Rust и поиск новых дублей относительно `43b75b6a5`
прошли. Предупреждения сгенерированного каталога, описанные выше,
этой проверкой не объявляются устранёнными.
