# `choiceForm`: сокращение ссылки по типу

Каталог `commonObjects/choiceForm` содержит только переходник к общему
определению владельца формы; отдельного правила чтения XML в нём нет.
Существующие `rules.ts` используют имя свойства `choiceForm` 47 раз:
44 ссылки по соседнему `Тип` получают `common.type-form-link`, одна явная
ссылка стандартного реквизита — `common.metadata-form-link`, два поля формы
являются обычными строками. Все 47 распознаются переносчиком из параметров
правил; частного Rust-обработчика или списка исключений по владельцам нет.

Для ссылки `Catalog.СправочникРеквизит.Form.ФормаВыбора` новый проверочный
набор берёт настоящий справочник и его форму из неизменённого e2e-каталога.
При единственном типе `Справочник.СправочникРеквизит` YAML содержит короткое
`ФормаВыбора`; при двух типах или отсутствии типа — полную русскую ссылку.
Все три формы проходят XML → YAML → XML без референса и без `!xml`.
Несуществующая короткая форма отвергается декларативной проверкой индекса.

Та же декларация уже проверена внутри целых табличных частей десяти владельцев
в `cf`/`cfe`: заполненное `ChoiceForm`, пустой элемент и соседние реквизиты
восстанавливаются без предметного Rust-кода. Явная ссылка стандартного
реквизита проверяется общей декларацией стандартных реквизитов; две строковые
формы остаются потребителями принятого `common.string`. Разбор аномальной
формы и XML-состояний наследуется от общего договора ссылок, отдельного
обработчика `choiceForm` нет. Полная приёмка владельцев учитывается отдельно.

Проверки: `pnpm test:migration-family --family choice-form` — 3/3;
`tools/rules-migration/test/emit.test.mjs` — охват 47/47. Полный `pnpm test`,
`pnpm type-check`, проверки архитектуры и поиск новых дублей прошли.
