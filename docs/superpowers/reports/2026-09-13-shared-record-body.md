# Общее тело записи: вложенность, коллекции и зависимые входы

Продолжение блоков 3–5 [плана](../plans/2026-09-13-unified-conversion-plan.md).
Блоки целиком ещё не приняты, флажки объектов не меняются.

## Что изменено

- Тело записи в `generate/value_record.rs` используется вложенным свойством
  и элементом коллекции. Перебор коллекции и размещение свойства остаются
  отдельными операциями, не повторяют генерацию полей тела.
- `plan/routes.rs` готовит использование обычной записи. Отсутствие родителя
  проверяется до восстановления полей: пустая запись и отсутствующая различимы.
- `plan/scopes/captures.rs` сохраняет область полей владельца при привязке
  дочернего входа. Ссылки на вычисленные скаляры помещаются в заимствованный
  массив после входов операции; вложенная запись имеет собственные номера полей.
- Ранний проход специализации больше не теряет привязки коллекций записей.
  Их выражения остаются в области вызывающего владельца до подготовки использования.
- XML/YAML-читатели коллекции сохраняют типизированные состояния элементов;
  завершают их после готовности входов владельца. Обычный путь не сохраняет
  промежуточную сериализацию документа и не копирует индексы на каждый элемент.
- Запись словаря с вынесенным именем использует тот же контекст, что обычная
  запись: синоним восстанавливается из ключа, дополнительные поля не пропадают.
- Восстановление и межполевые ограничения используют эти же привязки.
  Удалена смысловая группировка из `generate/owner_layout.rs`: связанные
  поля не обязаны быть соседями в декларации или в XML. Физическая группировка
  атрибутов и перенос договоров находятся в `plan/records.rs` и `plan/contracts.rs`.
- Вывод аномалий по ограничениям выполняется после завершения всех значений
  записи. Ссылка на поле внутри общего XML-заголовка остаётся локальной;
  связь с другой частью заимствует готовое значение через вход.
- Если исходное поле уже сохранено как аномалия без смыслового значения,
  зависимое сравнение пропускается, как раньше при отсутствии локального поля.
  Явная проверка присутствия может наблюдать такое отсутствие; неподготовленный
  вход операции не становится отсутствующим значением данных.
- Общая обработка аномалий словаря сохраняет повторное XML-поле вместо отказа.
  При вложенности сначала сохраняются различия внутри поля; поправка ко всему
  свойству применяется только если внутренней границы недостаточно.

## Проверочные сочетания

Одна матрица `tools/rules-migration/test/fixtures/unified-record.mjs` дополняет
существующий запуск коллекций. Не создаётся отдельный набор тестов каждого
предметного свойства.

1. Синоним стоит перед именем в декларации и XML; сокращение обратимо.
2. Две вложенные записи используют разные входы языка без смешивания контекста.
3. Дополнительный XML-атрибут сохраняется как аномалия синонима.
4. Отсутствующее исходное имя сохраняется как аномалия имени, без потери синонима.
5. Составление записи с дополнительным булевым атрибутом предка.
6. Та же запись в последовательности и в словаре с вынесенным именем.
7. Язык владельца расположен после коллекции; оба направления работают.
8. Первый вложенный объект отсутствует, второй пуст: значение по умолчанию
   не создаёт первый объект.
9. Служебный атрибут предка восстанавливается из имени в `Properties`,
   в том числе из вынесенного YAML-ключа элемента коллекции.
10. Ограничения связывают разные контейнеры и атрибуты общего заголовка;
    проверены обычное значение, нарушение и повреждённое исходное поле.
11. Атрибут восстанавливается из другого атрибута того же заголовка.

Всего целевой запуск прошёл 38 сценариев, включая прежние 22.
Сохранены проверки независимых XML/YAML-ожиданий, проверки аномалий
и обратного восстановления XML. Прежняя проверка отказа на повторном
поле словаря заменена проверкой сохранения аномалии и доказательством
обратного восстановления — согласно согласованному изменению поведения.

Полная проверка текущего Rust-пространства прошла: 205 тестов. Архитектурные
зависимости проверены; новых дублей относительно `37acdae1f` нет. Clippy по всему
пространству и всем целям с `-D warnings` прошёл. Список атрибутов вычисляется один раз
владельцем и передаётся переходнику значения.

Самопроверка универсальности: физическое размещение не выбирается по имени
объекта или common; ограничения и восстановление используют один механизм
заимствованных входов. Проверены разные контейнеры, общий заголовок, вынесенный
ключ и повреждённый источник. Это самопроверка, не независимое ревью.

## Условия атрибутов составной записи

Условия XML-атрибутов владельца используют те же захваты полей и подготовленные
входы. Генератор атрибутов разделяет привязку common и выполнение уже связанного
выражения; отдельного обработчика владельца для выражений нет. При повреждённом
источнике атрибут восстанавливается общим механизмом сохранения XML, технически
неподготовленный вход по-прежнему не считается аномалией данных.

Матрица расширена до 42 сценариев: условие истинно, ложно, изменён порядок
атрибутов и повреждено поле условия. Первые два дают обычный YAML, последние
сохраняют исходный XML через существующий механизм аномалий. Целевые проверки
компилятора, генерации, коллекций и схемы прошли. Полный прогон 205 тестов
выше относится к коммиту `26ad63d7f`; расширение условий проверено целевым запуском.

## Граница размещения записи

`plan/routes::place_record` размещает запись, сохраняя её XML-оболочку,
атрибуты и область полей. Вложенное свойство и элемент коллекции передают
одну и ту же явную границу тела в генератор; атрибуты прикрепляются к этой
границе, а не к корню всего документа. Поправка XML восстанавливается под
тем же родителем.

На аномальном пути вложенная запись сначала использует существующее
восстановление своих полей. Это сохраняет читаемые имя и булево значение
вместо замены всего объекта исходным XML. В проверочном договоре добавлены
необязательные ожидаемые строки `retainedYAML`, проверяющие сохранение смысла
при аномалии без привязки ко всему содержимому поправки.

Пройдены 46 сценариев: прежние 42, нормальное размещение условной записи
в свойстве и коллекции, лишний атрибут на обеих границах. Полный запуск обнаружил
регрессию существующего `calendar_records`: пустая оболочка кодировалась как
удаление. Исправлен общий `Tree::patch_yaml`: существующий пустой элемент
получает пустой текст поправки; null остаётся удалением. Существующая матрица
`xml_patch` расширена пустой границей и атрибутом обычного элемента, без нового
отдельного набора тестов даты.
Для старой матрицы I8nText исправлено независимое ожидание: существующая пустая
оболочка сохраняется как `$xml: ""`, а не как удаление. Исходные XML и записанные
наблюдения TypeScript не изменены; вся целевая матрица коллекций прошла.

Если поправка не помещается в границу отдельного поля, сохранение поднимается
к содержащей записи только после неуспешного доказательства восстановления.
Другие ошибки передаются вызывающей стороне; неполная декларация не объявляется
поддержанной через этот механизм. Повторная полная проверка текущего Rust-пространства
прошла: 205 тестов. Новых дублей относительно `37acdae1f` нет, архитектурная
проверка прошла. Clippy всего пространства и всех целей с `-D warnings` прошёл.

## Общие XML-контейнеры

Расчёт владения XML-путями перенесён из `link/xml_ownership.rs` в
`plan/xml_ownership.rs`. Проверка ссылок и генератор используют один расчёт;
поиск декларации передаётся заимствованным представлением, без копии каталога.
Чтение записи распределяет события по реальным путям значений, поэтому две
коллекции могут занимать общий контейнер без пересечения элементов.

Для коллекций объявленных записей сохранение выделяет только свой путь.
Восстановление записывает элементы, оставляя общий родительский контейнер
открытым для следующей коллекции. Прежняя запись непосредственных дочерних
элементов делегирует этому же механизму. Чужие ветви и атрибуты общего предка
не разрешаются через поправку коллекции.

Целевая матрица прошла 51 сценарий: добавлены две коллекции в общей оболочке,
аномалия одной коллекции, промежуточный общий контейнер и пустые коллекции.
Специальные скалярные последовательности и собственные заголовки коллекций
пока сохраняют прежний путь; новая поддержка не объявляет их перенесёнными.
Полный повтор Rust прошёл: 205 тестов, затем отдельно прошла новая общая
проверка `xml_shared_routes` на изоляцию поправок и совместную запись ветвей.
Clippy всего пространства и всех целей с `-D warnings`, архитектурная проверка
и проверка новых дублей относительно `37acdae1f` прошли. Всего проверены
206 Rust-тестов; число объектов в чеклисте не меняется.

## Что ещё остаётся

### Автоматический выпуск привязок коллекций

`collection-emission.mjs` больше не отклоняет все входы без разбора:
типизированные индексы проходят через все три декларации с сохранением
импортов типов. Языки передаются коллекции, имя для сокращения I8nText
выбирается отдельно у каждого элемента по исходному `keyField`/`name`.
У FormattedI8nText применяется соответствующее имя входа `name`.
Предметное сопоставление находится только в инструменте переноса;
компилятор и Rust-исполнение не менялись.

Для словарей подтверждён исходный договор ключа без `yaml`:
`metadataCollection/fromXMLToYAML.ts` использует `property.yaml ?? keyField`.
Он теперь выпускается автоматически; ключ убирается из тела элемента
существующим `record-mapping`. Массивы не получают такого исключения.

Прошли 55 скомпилированных сценариев и 26 проверок инструмента переноса.
Новые сценарии защищают передачу одного индекса двум элементам и проверку
отсутствующей ссылки, независимые имена в списке и словаре, переименованный
ключ без `yaml`. Входные XML и ожидания прежних проверок не менялись.
Неподдержанный контекст и невыразимые свойства по-прежнему блокируют выпуск;
полные семейства и новые флажки готовности этим не подтверждаются.

### Незавершённые пункты

- План использования обычной записи пока создаёт временную специализацию;
  полный перенос размещения в подготовленный план и интернирование не завершены.
- Специальные формы присутствия, собственные заголовки коллекций,
  условия атрибутов самой коллекции и рекурсивные формы ещё используют прежние пути или явно
  диагностируются. Наличие такой диагностики не считается универсальностью.
- Для межполевых входов пока заимствуются поддержанные скалярные значения.
  Произвольные составные значения и ещё не
  объединённые специальные представления остаются предметом следующих проверок.
- Вклад элементов в индексы, полный автоматический выпуск семейств и измерения
  остаются последующими пунктами. Ни один новый объект ещё не принят полностью.
