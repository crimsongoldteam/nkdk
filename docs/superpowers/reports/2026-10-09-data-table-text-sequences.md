# Основная таблица DynamicList: составные ссылки

## Результат

`metadataTarget.kind=dataTable` переносится из rules.ts автоматически в общую
YAML-декларацию. Корни передаются исходными параметрами. Ссылка допускает
вложенные объекты, табличные части и завершающую виртуальную таблицу либо Base.
Порядок задаёт декларативный fold; Rust не содержит условий по MainTable,
DynamicList, видам таблиц или названиям common.

Примеры:

- `Catalog.Справочник1` ↔ `Справочник.Справочник1`;
- `Catalog.Товары.TabularSection.Состав` ↔ `Справочник.Товары.ТабличнаяЧасть.Состав`;
- `CalculationRegister.Начисления.BaseБаза` ↔ `РегистрРасчета.Начисления.БазаБаза`;
- `ExternalDataSource.Источник.Cube.Куб.DimensionTable.Измерение` ↔
  `ВнешнийИсточникДанных.Источник.Куб.Куб.ТаблицаИзмерения.Измерение`.

Имена не переводятся: в `Catalog.Table.TabularSection.SliceLast` слова Table
и SliceLast являются именами, а не видами частей.

## Общие изменения

Поток text-sequence поддерживает записи разной длины. Максимальная длина
известна заранее, первая часть выбирается готовым автоматом. Пересечение
первых частей отклоняется при сборке отдельно для XML и YAML. Поток использует
срезы исходной строки, без промежуточного списка строк. Фиксированная длина
сохраняет прежний путь без дополнительного выбора длины.

Вложенные текстовые шаблоны раскрывают литералы при проверке выбора. Контекст
передаётся в запись с фиксированной головой внутри варианта выбора. Fold
различает типизированные варианты элементов; optional-text литералы после
свёртки констант сохраняют свой тип в создаваемом Rust. Повторная подготовка
вариантов сведена к общему помощнику; новых дублей нет.

## Границы совместимости

Русская форма таблицы соответствует восьми независимым ожиданиям старого
parseDataTable. Старый DynamicList data.ts сохранял английскую строку
`Catalog.Справочник1`: побайтовая совместимость этой записи не заявляется.
XML-фикстуры не менялись; проверочные подмножества извлекаются в памяти.

Проверка формы, разрешённых корней и порядка не доказывает существование
цели по индексам проекта. Полные metadataRef/metadataTargets и DynamicList
остаются без флажков. Для полного DynamicList ещё нужны внешний файл запроса,
YAML-only свойство и исключение runtime-only свойства. Common56/90, вложенные27/27.

Скорость полного конвертера и цель10× этим блоком не измерены. Заимствующий
поток не означает отсутствия выделений памяти во всей смысловой модели.

## Проверки

- 30 нативных сценариев семейства: 13 прежних, 10 нормальных таблиц,
  шесть неверных ссылок с читаемым соседом, отсутствие MainTable.
- Общий поток: пять проверок, включая голову, неполную запись, неизвестный
  вариант, неправильную длину и бюджеты.
- Компилятор: 28 проверок record_item_inputs, record_canonical_parameters,
  sequence и text_pattern. Разная длина и вложенный префикс проверены на
  нейтральных Pair/EndStop; пересекающиеся первые части отклоняются.
- 68 проверок переносчика и сборки семейств.
- Рабочая декларация и JSON опубликованы локально общим генератором;
  повторная публикация с --check подтверждает актуальность.
- Самопроверка универсальности: предметные словари, порядок и допустимые
  корни находятся в YAML, общие изменения не проверяют предметные имена.
  Это самопроверка, не независимое ревью.

Заключительные Clippy (`-D warnings`), архитектура TypeScript/Rust,
публикация `--check` и дубли относительно91a01277 прошли. Полный `pnpm test`
вне песочницы завершился с кодом0, без одновременных Rust-сборок;
существующие пропуски проверок загрузки в 1С не означают проверку самой 1С.
Журналы: `/tmp/nkdk-table-full-test.log`, `/tmp/nkdk-table-family-final.log`,
`/tmp/nkdk-table-compiler-final.log`, `/tmp/nkdk-table-duplicates-final.log`.
