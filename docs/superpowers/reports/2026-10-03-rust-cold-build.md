# Ускорение холодной сборки Rust

На рабочем каталоге приложения получены два независимых холодных запуска:

| Запуск | Полная сборка и проверки | Результат |
|---|---:|---|
| nightly-pipeline-cold | 4 мин 31 с | facts45/45, resources11/11 |
| nightly-pipeline-confirmed-cold | 2 мин 48 с | facts45/45, resources11/11 |

Оба target были новыми и пустыми. Собраны все восемь пакетов рабочего
каталога, фасад, приложение и проверочные зависимости. Кэширующие
RUSTC_WRAPPER/RUSTC_WORKSPACE_WRAPPER отсутствовали; измерительная обёртка
запускала настоящий rustc. Разница между запусками показывает влияние внешней
нагрузки; гарантировать такую длительность при любой нагрузке нельзя.

Исходный Cargo Finished test profile был31м46с, без57,58с и1,97с выполнения
тестов. В первом новом запуске каталог компилировался4м02с, проверки
приложения13,73с; общее4м31с уже включает выполнение тестов и служебные
расходы. Это измерение приложения, не всего workspace с кандидатными пакетами.

## Что изменено

- XML/YAML-сканеры в профилях с debug_assertions компилируются один раз.
  Один bodies-архив раньше содержал87438 экспортируемых имён с visit_scoped,
  после изменения2429. Сгенерированные обработчики остаются Rust-функциями.
- Release сохраняет исходное статическое тело XML-парсера. Внутренний макрос
  меняет только сигнатуру; второй копии алгоритма и интерпретатора правил нет.
- Генератор и build dependencies оптимизируются отдельно (opt-level=2).
  Обычный профиль конвертера этим не меняется.
- Два крупнейших тела вынесены в compiled-rules-bodies и bodies-2; общий
  EntryId, схемы индексов, подпись каталога и маршруты фасада сохранены.
- У измерительной обёртки исправлена передача дескрипторов Cargo jobserver.
- Ускоренный режим использует закреплённый nightly-2026-10-02,
  -Zthreads=4 и максимум три задания Cargo. Все пакеты передаются одной
  командой, без ожидания медленного соседа. RUSTC_BOOTSTRAP не включается.
- OUT_DIR содержит generation-sizes.tsv: объём по точкам входа, механизмам
  и исходным декларациям. Ограничения размеров сохраняются.

Для ускоренного режима:
```sh
pnpm build:rust:fast
pnpm test:rust:app:fast
```

Требуется установленный nightly-2026-10-02 (minimal). Обычные build:rust и
test:rust:app, а также рабочий release остаются на Rust1.98.1. Режимы используют
разные target. Подробности: tools/rust-build-profile/README.md.

## Память

В отдельной пересборке трёх наиболее тяжёлых пакетов с готовыми зависимостями
(nightly-memory-confirmation) зарегистрированы максимум3 одновременных rustc.
Консервативная верхняя граница суммы их RSS —8339210240байт (8,34ГБ,
7,77ГиБ). Это сумма индивидуальных пиков для перекрывающихся интервалов,
не непрерывное измерение реального совместного пика.

Первый расчёт перекрытий был неверен: Python3.9/macOS использует отдельную
эпоху time.monotonic() в каждом процессе. Исправлено на системный
CLOCK_MONOTONIC; проверка запускает настоящий дочерний процесс и сравнивает
его времена с родительскими. Старый ложный совместный показатель помечен
непригодным; индивидуальные RSS и длительности того запуска остаются верны.
Поздний опрос ps также не застал компиляторы и не применяется к оценке пика.

## Проверка исполнения

Release-матрица core и Font:101/101. Финальное сравнение выполнялось на
сохранённой исходной программе и новой программе, пять чередующихся пар
запусков; по25 измерений каждой строки, по20000 преобразований в измерении.

| Вариант Font / направление | До, нс/операцию | После, нс/операцию |
|---|---:|---:|
| Absolute XML → YAML | 19706,1 | 19677,9 |
| Absolute YAML → XML | 7951,2 | 7893,1 |
| Стандартная ссылка XML → YAML | 4345,3 | 4303,1 |
| Стандартная ссылка YAML → XML | 1561,2 | 1555,3 |

Замедления этих проверенных путей нет; небольшой выигрыш в пределах шума не
объявляется улучшением всего проекта. Полная цель10× для преобразований этим
замером не подтверждается. YAML-ожидания заданы независимо от генератора;
матрица Font дополнительно проверяет обратный экспорт и аномалии.

Таблица повторена после последней правки генератора: пустая таблица
переопределения входов теперь не создаёт бессмысленный match, что исправляет
строгий Clippy без исключений. Запуски и итог сохранены как
parser-font-verified-*.jsonl и parser-font-verified-summary.json.
Release-проверки Font повторены: 10/10, сборка 28,34с.

Финальная проверка приложения после этих изменений: facts/resources 56/56
(cold-build-final-app-regression; это тёплый прогон, не новый холодный замер).
Также прошли core/Font debug 101/101, Clippy core/compiler/Font со всеми
целями и -D warnings, пять проверок сборщика, pnpm test вне песочницы,
type-check, Rust-архитектура, архитектура rules, общая архитектура и поиск
дублей относительно 2af2f299ed8241eac78d4db46b4a8421efe2f8f7.
Мягкий временной ориентир одного TS-теста не выполнен; функциональный
pnpm test завершился успешно, его пороги не менялись.

Проверки сборщика защищают последовательность команд, непрерывный конвейер
с ограниченным числом заданий, отсутствие RUSTC_BOOTSTRAP, передачу jobserver,
общую эпоху времени и правильный подсчёт перекрытий. Полная матрица
rule-compiler была прервана после завершённых core91 и compiler-lib16:
она запускала множество вложенных сборок; за полный зелёный набор её не выдаём.

## Отброшенные варианты и оставшаяся работа

Точное объединение тел записей уменьшало32,067МБ generated.rs только до30,774МБ
(4%); опыт удалён. Динамический callback в release, затем промежуточная
статическая обёртка показали риск замедления; рабочая версия сохраняет
исходное тело. RUSTC_BOOTSTRAP применялся только в диагностическом опыте.

Стабильный холодный сценарий улучшился до15м13с, но для нескольких минут
требуется отдельный nightly-режим. Он не меняет рабочую release-сборку.
Правка одного YAML по-прежнему может пересобирать лишние пакеты из-за общей
подписи; оптимизация локальной пересборки остаётся отдельной задачей.
Порог2ГБ на каждый rustc из прежнего плана полностью не достигнут.
Неполадки установленного rust-objcopy (отсутствующая libLLVM.dylib) вызывают
предупреждения о снятии отладочных данных, но компиляция и проверки проходят;
это не установлено как причина прежних31минут.

Журналы и результаты находятся в
.superpowers/sdd/2026-09-10-rust-yaml-current/logs/. Флажки common-объектов
этот блок сборки не изменяет.
