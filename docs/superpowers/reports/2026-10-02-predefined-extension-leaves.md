# Состояние предопределённых записей расширения

Проверено содержимое трёх отдельных записей неизменённого файла
`e2e/fixtures/xml/cfe/all-extension/Catalogs/СправочникСПредопределенными/Ext/Predefined.xml`:
`Группа` (`AdoptedNotify`), `Предопределенный2` и вложенная
`Предопределенный3` (`AdoptedCheck`).

Декларация использует один фрагмент содержимого и два варианта состояния.
Обычный вариант получает состояние из принадлежности объекта; помеченный
представляется тегом `!проверять` на всей записи. Состояние не становится
дополнительным свойством YAML. Компилятор не содержит имён этих объектов.

## Что исправлено в общем механизме

Добавлено `form: tagged` для выбора любого YAML-значения целиком: записи,
коллекции или скаляра. Внешний тег снимается перед чтением содержимого;
вложенные теги сохраняются. Проверяется уникальность тегов. При сохранении
XML-аномалии внешний тег принадлежит оболочке `!xml`, чтобы не выводить
два тега на одном значении.

Составной `RecordBody` раньше всегда возвращал `false` из `has_raw`.
Это ошибочно выбирало `AdoptedNotify` для XML с `AdoptedCheck`. Теперь
проверяются оболочка записи и все её составные части. Проверка реального
XML воспроизводила ошибку до изменения и проходит после него.

Общее содержимое каталожной записи выделено в фрагмент. Рекурсивная
коллекция остаётся на записи, чтобы рекурсивная ссылка не становилась
циклом составления фрагментов. Ранее принятые файлы проверяются прежней
матрицей, включая планы счетов, виды расчёта и характеристики.

## Проверки и границы

Для каждой из трёх строк проверены независимый ожидаемый YAML, импорт,
экспорт без XML-референса и структурное восстановление XML. Дополнительно:
собственная запись без состояния, запрет `!проверять` у собственного объекта,
неизвестное состояние с сохранением аномалии на границе свойства.
Исходные XML-фикстуры не изменялись.

Это приёмка отдельных записей, **не всего файла расширения**. Ещё нужны
именованная коллекция вариантов, рекурсивные записи расширения, порядок,
повторы и рабочее получение принадлежности из владельца. Проекция аномалии
на корень документа и пустой XML состояния здесь не приняты. Флажок
`XMLRoot` остаётся пустым; число принятых common — 56/90.

## Завершившиеся проверки

- 93 проверки компилятора; расширенная матрица записей повторно прошла после
  добавления границы свойства для аномалий.
- 91 проверка conversion-core, 26 проверок коллекций, 12 TypeDescription.
- Строгий Clippy компилятора и conversion-core, форматирование и git diff --check.
- Архитектура Rust и оба архитектурных набора TypeScript.
- Проверка дублей относительно `2af2f299ed8241eac78d4db46b4a8421efe2f8f7`.
- Полный `pnpm test` вне песочницы: код завершения 0.

Проведена самостоятельная проверка изменений; независимый агент не
использовался по требованию пользователя. Известное ограничение общего
механизма — проекция прямой скалярной последовательности на корень — не
закрывалось этим блоком. Также при переносе общего ключа требуется проверить
передачу признаков присутствия и аннотаций отдельных составных полей.

## Дополнение: признаки составных полей

После проверки отдельных записей устранены постоянные `false` в общем
интерфейсе присутствия и аннотаций поля составной записи. Дополнительно
`Fields.has_annotation` теперь учитывает сохранённую XML-поправку: иначе
аннотированный ключ мог перемещаться в обычный ключ коллекции с потерей
поправки. Обычные значения сохраняют прежний путь без повторного разбора
XML/YAML. При генерации один план составления используется повторно.

Поведенческая матрица воспроизвела обе ошибки до исправления и проверила
корректный, отсутствующий и неверный XML-атрибут, чтение сохранённого YAML,
соседнее вложенное поле и восстановление XML. Прошли 94 проверки компилятора,
91 проверка ядра, 26 коллекций, 12 TypeDescription и строгий Clippy.
Это необходимая подготовка к общему ключу вариантов, но ещё не поддержка
именованной коллекции вариантов. Флажки объектов не меняются.

После дополнения повторно прошли полный `pnpm test` вне песочницы,
архитектурные проверки Rust и TypeScript, проверка дублей и форматирование.
Независимая проверка кандидата и обратное восстановление XML включены в
новую матрицу. Самопроверка подтвердила отсутствие предметных условий в
нейтральном коде; независимый агент по просьбе пользователя не запускался.
