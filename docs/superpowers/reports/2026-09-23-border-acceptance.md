# Common `Border`: проверка переноса

Дата: 2026-09-23. Граница работы — общий тип рамки XML ↔ YAML. Полные владельцы форм и стилей принимаются отдельно.

## Договор

- [`common.border`](../../../rust/declarations/common/border.yaml) задаёт ссылку `ref="style:<имя>"` ↔ `Имя: ЭлементСтиля.<имя>`, точную десятичную ширину и тип рамки из общего каталога `ControlBorderType`. Предметных веток в генераторе Rust нет.
- Тип элемента стиля проверяется по подготовленному индексу: ссылка должна вести к существующему `StyleItem` с типом `Border`. Неверная ссылка на XML-входе сохраняется как аномалия, а YAML-вход получает диагностическое сообщение.
- Отсутствующая ссылка и `Имя: null` имеют один смысл. Отсутствие всей рамки отличается от ширины `0`. Неверная ширина XML сохраняется на границе атрибута через `!xml/raw`, вместе с соседними свойствами; пользователь согласовал `!xml` для неверных `Border`.
- Пустой `<Border/>` не встречается в проверенных e2e-файлах. Отдельный проверочный случай подтверждает общий договор: при отсутствии смыслового значения YAML хранит физическое имя `Border: !xml/raw` и восстанавливает пустой элемент вместе с соседним полем. Записи `<Border/>` и `<Border></Border>` равнозначны по XML. Пользователь согласовал эту границу сохранения.

## Независимые проверки

- Ширина и тип рамки взяты из неизменённых XML/YAML e2e-примеров `CalendarField`, `LabelField`, `ExtendedTooltip`; тест отдельно сверяет ожидаемые значения в обоих направлениях.
- Подготовленный индекс строится из неизменённого XML `StyleItems/ЭлементСтиляРамка.xml`. Проверяются подходящий тип, другой тип, отсутствующее имя, `null`, нулевая ширина и неверные данные.
- Отдельная декларация с не связанной с рамкой записью проверяет общий вывод составного значения в XML-атрибут. Проверка коллекции подтверждает, что новый код проходит строгий Clippy при генерации вложенных записей.
- Генератор JSON Schema использует ту же декларацию: допускает `Имя: null` и точную ширину, отклоняет строковую ширину и неизвестное значение перечисления. Проверка по индексу остаётся рабочей проверкой, что явно указано в схеме.

## Массовый перенос

Переносчик связывает исходные свойства `Border` с `common.border` через общий профиль записи и вход `StyleItem`/`styleItemType`. Старый скалярный `implicitValueYAML` не действует на значение-запись; его эквивалентность выясняется механически, без ветки по имени `Border`. Все 11 ранее заблокированных свойств стали кандидатами: всего 4312 кандидатов вместо 4301, 1564 заблокированных вхождения вместо 1575. Полные владельцы учитываются отдельно.
