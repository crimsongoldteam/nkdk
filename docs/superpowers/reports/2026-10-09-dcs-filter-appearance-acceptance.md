# Отборы и условное оформление СКД

Полный договор отдельных вложенных частей: сравнение — девять
сериализуемых свойств и явно учтённый runtimeOnly parent; группа — восемь;
Filter — пять; элемент условного оформления — 18; условное оформление — четыре.
Полная схема СКД и её подключение ко всем владельцам принимаются отдельно.

## Преобразования

- Шесть примеров сравнения и 11 примеров дерева/Filter защищают независимый
  XML → YAML, YAML → XML без XML-референса, группы внутри групп, повторы,
  все свойства, неявные значения и локальную аномалию рядом со здоровыми данными.
- Девять примеров оформления защищают минимальный и полный элемент, все
  18 свойств, повтор элемента, оба исходных примера владельца, все четыре его
  свойства, неверное использование и отсутствующий контейнер.
- Пустое YAML-сравнение выбирает сравнение и создаёт Equal. Пустой исходный XML
  без comparisonType сохраняется автоматически как отличающаяся форма XML.
- У оформления отсутствие YAML-поля создаёт исходный пустой контейнер.
  Отсутствующий в XML контейнер сохраняется как аномалия; это не создание
  искусственного элемента коллекции. Необязательный контейнер отбора имеет
  другой договор, также проверенный отдельно.

Исходные XML-файлы не менялись. Пространства имён самостоятельного фрагмента
оформления добавлены в памяти из настоящей e2e-формы: без них v8ui:Color
не является разрешённым QName. Два ожидания приведены к уже принятому договору
DcsLocalStringType: короткий многоязычный текст и !xml/string для xs:string.
Все остальные ожидаемые значения взяты из старых независимых примеров.

## Общие изменения

Рекурсивное значение через compose не является циклом compose. Выбор YAML
использует объявленный запасной вариант только после проверки всех ключей;
поздний ключ «ТипГруппы» выбирает группу. Читатель выбора не хранит второй
экземпляр событий, когда события уже сохраняет вызывающий читатель.

Библиотечная проекция записи не выводит служебное имя item в аномалии.
Проекция целого файлового объекта сохраняет прежнюю маршрутизацию аномалий.
Пропущенные типизированные списки не превращаются в явные пустые массивы.
Постоянный xsi:type и пустой контейнер переносятся общими механизмами из
исходной регистрации, без условий по названию объекта.

Подготовленные индексы принадлежат объекту-владельцу; его фрагменты и
библиотечные значения получают данные через входы. Публикация повторно
использует уже опубликованный идентичный договор. Несовпадающий договор с
тем же именем по-прежнему блокирует публикацию.

## Воспроизводимость и сборка

Рабочие декларации и примеры опубликованы в:

- `rust/declarations/probes/filter-comparisons-working.generated.yaml`,
  `tests/migration/filter-comparisons-working.json`;
- `rust/declarations/probes/filter-trees-working.generated.yaml`,
  `tests/migration/filter-trees-working.json`;
- `rust/declarations/probes/conditional-appearance-working.generated.yaml`,
  `tests/migration/conditional-appearance-working.json`.

Проверка публикации: `pnpm migration:working-family --family <семейство> --check`.
Преобразования: `pnpm test:migration-family --family <семейство>`.
У conditional-appearance используется тот же запускатель договоров с общими
AOT-пакетами. Интерпретатора YAML и отдельных обработчиков объекта нет.

Подготовленный каталог оформления: 128 деклараций; 666 пакетов общих тел
и один фасад, суммарно 34,4 МБ Rust, крупнейший пакет около 2,3 МБ.
Сборка этого каталога завершилась за 70 секунд на двух процессах с debug=0;
это не холодная сборка всего workspace. Обычная команда оставляет один
процесс сборки. Во время наблюдения отдельный rustc занимал около 300 МБ;
это наблюдение, а не измерение максимального расхода за всю сборку.

## Проверки и ограничения

Существующая матрица схем расширена деревом, Filter и оформлением; она
проверяет пустые и вложенные значения и отклоняет неверные значения и чужие
поля. Нейтральные матрицы проверяют рекурсию compose, булево значение выбора,
проекцию коллекции, локальную аномалию записи и оба режима читателя событий.
Перепроверены все 22 примера типизированных значений. Тесты не удалялись.

Прямое создание смысловой последовательности выбора без чтения XML/YAML
остаётся явно неподдержанным; оба преобразования поддержаны.
Цель 10× и скорость release-сборки этим блоком не подтверждаются.

Общая библиотека опубликована отдельно:
`rust/declarations/common/conditional-appearance-family.generated.yaml`.
Имена common.filter, common.filter-item и common.conditional-appearance-items
видны обычному переносчику rules.ts. Для воспроизводимой публикации:
`pnpm migration:common-family --family conditional-appearance --check`.
Проверочные владельцы ссылаются на эту библиотеку, а не содержат её копии.
После публикации общий набор проверок переносчика и публикации прошёл 69/69.

Повторная полная проверка pnpm test прошла. Новый путь общего запускателя,
публичная библиотека и последнее сокращение работы читателя прошли
заключительную Rust-проверку; четыре флажка обновлены.

## Скорость обычного пути

[Сырые release-замеры](2026-10-09-dcs-filter-appearance-performance.json):
пять чередующихся групп по 20 000 преобразований, один исходный Filter,
одна версия компилятора и ядра. Сравниваются старый явный ключ сравнения
и новый запасной вариант; подготовка контекста исключена в обоих случаях.

| Направление | Явный ключ, медиана | Запасной вариант, медиана | Отношение |
|---|---:|---:|---:|
| XML → YAML | 38,53 мкс | 38,65 мкс | 1,0031 |
| YAML → XML | 9,41 мкс | 9,34 мкс | 0,9928 |

Диапазоны XML перекрываются; замедление оптимизированного рабочего пути
на этом примере не обнаружено. Это локальная проверка общего механизма,
не гарантия для всех проектов и не подтверждение цели 10×.
Debug-замеры ранее выявили около 1,5% разницы: дополнительно устранены
копии ключей и разбор значений, не участвующих в выборе варианта.

Штатный путь после публикации общей библиотеки также прошёл 9/9.
Каталог содержит 131 декларацию, 667 пакетов с фасадом, совокупно 34,4 МБ,
крупнейший пакет 2,3 МБ. Этот прогон Cargo занял 3 минуты 15 секунд на одном
процессе параллельно с функциональными тестами; это наблюдение, не отдельный
замер сборки. Последний ограничитель времени pnpm остановил тестовый файл
worker.integration.test.ts (2603 мс), без падения проверок поведения; полный
прогон повторён без параллельных сборок и прошёл с кодом 0.

Итоговая проверка: 48 договоров, 140 Rust-проверок, 69 проверок переноса и
публикации, полный pnpm test, Clippy, архитектура и новые дубли прошли.
Чеклист: 56/90 common и 27/27 вложенных частей. Проверка архитектурного
соответствия выполнена самим исполнителем; независимые субагенты исключены
по просьбе пользователя. Исходные XML не изменены.

Остаются предупреждения о неиспользуемых переменных в сгенерированных
AOT-телах; они не скрыты настройками проверок. Clippy собственных исходников
ядра и компилятора с `-D warnings` прошёл. Этот блок не выполняет PR/слияние
и не принимает весь проект или полную схему СКД.
