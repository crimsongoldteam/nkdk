# UserVisible: таблица ключей и локальные аномалии

`common.user-visible` остаётся YAML-декларацией. Общий `keyTable` получает пары
полного XML-имени и короткого YAML-имени из подготовленного входа. На
неизменённой e2e-форме `Role.Администратор` превращается в
`Администратор`; неизвестная роль сохраняется коротким ключом с
`!xml/invalid`, UUID — с `!xml/uuid`. Пустой и неполный ключи также
сохраняются как аномалии. Обратное преобразование работает без XML-референса.

В `record-mapping` XML-поправка неверного булева текста теперь принадлежит
значению конкретной строки. Соседняя роль остаётся обычным полем YAML, а
атрибут `name` не дублируется при экспорте. Этот механизм применим к любой
декларации с именованной полной записью; ветвлений по `UserVisible` в Rust нет.

Проверены три старых XML-образца, реальная форма cf, неизвестное и пустое имя,
UUID, повтор, чужой префикс, пустой элемент и оболочка, неверное булево значение рядом с обычной ролью. Полная приёмка
common остаётся открытой: подготовленный вход таблицы ролей ещё не связан с
индексом конфигурации в рабочем маршруте всех владельцев. Чеклист и счётчик не
изменены.
