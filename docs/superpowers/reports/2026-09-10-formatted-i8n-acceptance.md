# Приёмка FormattedI8nText: декларация и Rust

Дата: 2026-09-10.

## Завершённый договор

[formatted-i8n-text.yaml](../../../rust/declarations/common/formatted-i8n-text.yaml) описывает признак форматирования, вложенный I8nText, состояния отсутствия, сокращения и ограничения. Из одной декларации получаются XML → YAML, YAML → XML, валидация и структурная JSON Schema. Вложенные правила переводов импортируются из уже принятого I8nText; отдельной предметной функции преобразования или реестра аномалий нет. Декларация подключена к рабочему Rust-каталогу через проверочного владельца; прикладные объекты и формы пока не перенесены.

Статические параметры передаются вложенной декларации через `{parameter: имя}` и подставляются при сборке. XML и YAML читаются одним потоком событий; промежуточного преобразования вложенного документа в строку и обратно нет. Вложенный YAML-reader использует статическую диспетчеризацию. Подробное дерево для сохранения формы создаётся только на исключительном пути.

Отсутствие `formatted` означает false согласно декларации, но отличается от явного `formatted="false"` по форме XML. Согласованный пользователем общий механизм выявляет это при контрольном экспорте и сохраняет `_formatted: null`. Последующая проверка окончательного YAML обязательна. Порядок атрибутов также восстанавливается общим механизмом разницы, без копирования дочернего текста. Новых предметных условий в ядре для этого нет.

## Проверки

- 1536 сочетаний: все 32 профиля пяти параметров × 16 XML-сценариев × true/false/отсутствующий атрибут. Проверены принятие окончательного YAML и восстановление XML; этот набор не является 1536 независимыми побайтными эталонами YAML.
- Четыре независимых нормативных случая FormattedI8nText проходят через рабочую команду корпуса: точный YAML, обратное преобразование, валидация и структурное сравнение XML. Отдельно проверены точные обычные формы и поправка `_formatted: null`.
- [154 свойства неизменённых e2e-фикстур](../../../tests/migration/formatted-i8n-e2e-acceptance.json) с явным `formatted`: оба преобразования, валидация и независимое сравнение XML. Проверка перебирает весь e2e-каталог; используются обычные параметры. Отсутствующий атрибут покрыт матрицей выше.
- Повторно прошли 256 точных ожиданий I8nText и 52 его свойства e2e после изменения общих механизмов.
- Проверены вложенная ошибка с адресом и строкой исходного YAML, неизвестные и повторные поля, ложный признак в YAML, пустая недопустимая запись, повреждение raw, схема и типизация передаваемых параметров. Компилятор отвергает флаг без объявленной семантики отсутствия XML.
- 130 Rust-тестов workspace, Clippy workspace и сгенерированного кода, fmt, проверки архитектуры и отсутствие новых дублей относительно `2f8a7f1a2`. Через команду корпуса прошли все 30 поддержанных случаев семи групп. Полный `pnpm test` ранее прошёл на ветке; в этом слое TS-код не менялся, полный набор повторно не запускался.

Исходные XML и ожидаемые YAML не изменялись. Для исторического `formatted-i8n-without-text` сравнение XML переведено с побайтного на структурное: прежде ожидался фрагмент свойства TS, теперь команда возвращает полный XML-документ с оболочкой Root. Имена, атрибуты, их порядок, порядок детей и содержимое листьев продолжают проверяться; отличие отступов и пролога не считается потерей данных.

## Границы приёмки

Принят интерфейс свойства XML ↔ YAML и связанных проверок, а не полное преобразование проекта. Enterprise исключён по решению пользователя. Структурная JSON Schema не заменяет контекстную проверку языков, порядка и пометок в Rust. Неподдержанная структура отвергается, а не маскируется raw. Цели 10× по времени и памяти здесь не измерялись.
