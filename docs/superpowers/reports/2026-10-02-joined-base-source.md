# Источник основы и контекст расширения

Проверен общий договор `baseSource`: файл основы выбирается по сохранённому
UUID, значения читаются из текущего YAML, входы и адрес проекции остаются
от расширения. Разные имена файлов не требуют изменения обработчика.
Собственный объект расширения с пустой ссылкой не требует основы.

Новая проверка Rust-приложения использует существующие нейтральные источники,
публикует идентичность через импорт, удаляет исходные XML и дважды меняет YAML
основы. Реальная проектная операция видит каждое изменение. Дополнительно
проверены повторный UUID, отсутствующая основа, неверная регистрация,
собственный объект и символическая ссылка вместо текущего YAML.

Первое падение — отсутствие API соединения; отдельная проверка ссылки
воспроизвела ошибочное чтение файла при снятых защитах и прошла после их
возврата. Дублирующая настройка проектной операции в тестах вынесена в общий
помощник; baseline не изменён.

Приёмка этого механизма: 51 тест приложения, Clippy, три проверки архитектуры,
проверка изменений и поиск дублей прошли. Окончательный `pnpm test` прошёл
с кодом 0; прежний прогон размещения не прошёл ограничение времени неизменённого
TS-файла импорта расширения. Лимиты не изменены, проверки не исключены.

Следом генерируются восемь сохранённых источников идентичности и их маршруты.
Это отдельная приёмка на настоящих e2e-данных. Данный результат сам по себе
не означает полного переноса `InputByStringFields` или его владельцев.
Замеров скорости конвертера и пика памяти в этом блоке не проводилось.
