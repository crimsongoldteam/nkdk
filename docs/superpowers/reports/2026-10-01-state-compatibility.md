# Версионные ограничения состояний числовых свойств

## Принятый договор

Разрешённые пометки заимствованного свойства выводятся из существующих
propertyState-объявлений: сначала общие профили и объявление вида объекта,
затем подходящие изменения версий в исходном порядке. Обновление версии
заменяет только указанные части свойства; соседние части сохраняются.
Словарь версий берётся из system.CompatibilityMode. DontUse нормализуется
в 8.3.27, как в исходном договоре TS; неизвестная версия переносчика не
принимается молча. Rust получает обычные декларативные условия по конечному
словарю, без обработчика версии, объекта или конкретного свойства.

Подключены все 18 кандидатных числовых регистраций и их объявленные соседние
перечисления. Ограничения действуют для заимствованных объектов при чтении XML
и проверке YAML. Доступность самих свойств в собственных объектах и полное
проектное подключение остаются отдельными договорами; этот блок их не принимает.

## Проверки границ

Нумератор: пометка «проверять» отклоняется в 8.3.14 и принимается в 8.3.15;
«изменять» отклоняется в 8.3.7 и принимается в 8.3.8. DontUse проверен отдельно.
Ожидаемые коды диагностик заданы независимо от выпускаемых условий.
Переносчик читает ConfigurationExtensionCompatibilityMode из Configuration.xml
того же компонента и записывает источник и его контрольную сумму в проверочный
набор. Отсутствующее значение соответствует DontUse. Подстановка старой версии
в дополнительном сценарии отмечена явно; исходные XML-файлы неизменны.

Реальный XML регистра бухгалтерии с Notify проверяется также в контексте
8.3.14. Числовое свойство становится автоматически выведенной аномалией,
состояние сохраняется явным списком, XML восстанавливается без референса.
Нельзя сокращать строку состояния недопустимой пометкой: иначе после сохранения
аномального числа теряется связь, а восстановление всего владельца расходится.
Условия сокращения и согласованности используют ту же объявленную доступность
пометки. У отсутствующего смыслового значения проверка согласованности не
создаёт дополнительную ошибку. Нового обработчика аномалии в Rust нет.

## Границы результата

Проверочный числовой набор содержит девять сценариев, совокупный реестр с
InputByString — 71. Флажки полной приёмки common и владельцев не меняются.
Версия рабочего проекта должна поступать из его контекста при последующей
интеграции; проверочное чтение Configuration.xml не заменяет этот маршрут.
Базовое отсутствие/умолчание и доступность для собственных объектов ещё
предстоит закрыть. Цели 10× здесь не измерялись.

Прошли девять нативных числовых сценариев и три повторные проверки прежних
владельцев: заимствованный план счетов, сравнение Notify с основой документа

### 2026-10-01: собственные объекты и отсутствие базового числа

Пометки «изменять» и «проверять» у собственных объектов недопустимы.
Обычное значение допускается; у заимствованных объектов доступность пометки
по-прежнему выводится из профилей и изменений версий. Проверка и сокращение
истории используют одно декларативное условие. Недопустимый XML сохраняется
как автоматически выведенная аномалия, с явной строкой состояния.

Отсутствующее числовое свойство в основной конфигурации не заменяется
умолчанием другого свойства. Обычный YAML получает base.property.missing.
Если число из XML невозможно оставить обычным смысловым значением, общий
механизм сохраняет его исходную форму; сокращать соответствующую строку
состояния в этом случае нельзя. При восстановлении не нужен XML-референс.
Проверочный факт, у которого удалён элемент, является копией в памяти;
исходные XML-фикстуры остаются неизменными.

Это не решает отдельно отсутствие базового переключателя типа числа и
проектное подключение контекста. Их приёмка остаётся следующей задачей;
подстановка отсутствующего факта предполагаемым значением запрещена.

Проверки текущего блока: обе собственные пометки отклоняются точным кодом
state.mode.unavailable; производные XML с Notify у собственного документа
и справочника сохраняются как аномалии. Сценарии отсутствующей базовой длины
проверяют отдельно обычный YAML (base.property.missing) и восстановление
XML из YAML с аномалией. Нативный реестр расширен до 11 числовых сценариев.

Итог текущего блока: 11 нативных числовых сценариев, два сценария собственного
Notify, 8 проверок переносчика прошли. Проверены 48 условий доступности
пометок чисел и соседних перечислений в выпускаемых фрагментах.
Повторный полный pnpm test завершился с кодом 0; первый запуск превысил
лимит времени worker.integration во время параллельной компиляции, пределы
не менялись. Проверки архитектуры TS/Rust, cargo fmt, три генератора --check,
поиск новых дублей относительно 2af2 и git diff --check прошли.
