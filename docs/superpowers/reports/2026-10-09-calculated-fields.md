# Вычисляемые поля СКД

Семейство собирается автоматически из прежних `rules.ts` и регистрации
коллекции. Рабочая декларация содержит три записи: элемент со всеми девятью
свойствами, список элементов и оболочку свойства. Общие декларации
подключаются ссылками, их тела не копируются вручную.

Независимые ожидания: два неизменённых XML/YAML-примера динамического списка;
оформление — прежний пример `appearanceCalculatedFieldYAML`; доступные
значения — `nilAndBoolean.xml` и прежнее ожидание `[{}, {Значение: Истина}]`.
Отдельные случаи сохраняют соседей, повтор элемента и неверное булево
значение вместе с читаемыми остальными свойствами. Проверяется также
экспорт ожидаемого YAML без XML-референса и его валидация.

Обнаруженные ошибки переноса:

- Старое имя `CalculatedFieldOrderExpression` означает список, а переносчик
  по сходству имени выбирал декларацию одного элемента. Исправлена таблица
  соответствий, добавлена проверка RED → GREEN.
- Общий путь списка повторялся в поле владельца. Теперь совпадающий путь
  элемента задаётся только самой декларацией списка. Устранено и повторение
  пути доступных значений; это общий механизм, без условий по имени объекта.
- Совпадение путей проверяется по пространствам имён, а не только префиксам;
  дополнительная регрессия прошла RED → GREEN.
- Публикация AOT удаляла старые файлы пакетов, но оставляла пустые каталоги,
  нарушавшие Cargo workspace. Удаляются только пустые родительские каталоги
  снятых с публикации файлов; посторонние файлы сохраняются. Проверка прошла
  RED → GREEN. Старые пустые каталоги убраны, Rust-архитектура проверена.

Изолированный каталог прошёл 6/6 случаев через 407 общих AOT-библиотек.
Проверки переносчика: 251/251. Первая подготовленная сборка — 1 мин 7 с,
пересборка исправленных тел — 26,28 с; это dev-проверка выбранного семейства,
а не замер всего проекта или подтверждение цели 10×.

Рабочая декларация опубликована общим переносчиком и включена в список
источников и владение `bodies-5`. Все 6/6 случаев прошли полный рабочий реестр.
Исправлена ссылка проверочных случаев на пробные поставщики индексов:
теперь используются рабочие `metadata.style-item-type-facts` и
`metadata.system-enumeration-index-source`; регрессия прошла RED → GREEN.
Сам YAML преобразователей от этого не изменился.

В схеме обнаружен общий пробел: текстовый шаблон как элемент обычного списка
не поддерживался, хотя как поле уже поддерживался. Добавлена такая же
структурная строковая схема с `x-nkdk-runtime-validation`, без условий по
именам объектов. Существующая общая проверка расширена: RED → GREEN.
Схема рабочего свойства создана; проверены три независимых допустимых примера
и две неверные структуры. Полная смысловая проверка остаётся в Rust.

Итог: 30/30 проверок схем, Clippy, полный `pnpm test` (включая 252 проверки
переносчика), три архитектурные проверки и отсутствие новых дублей.
Расширенный общий Rust-прогон прошёл первые 32 и 39 проверок, но остановлен
при пересборке старых монолитных тестовых каталогов из-за расхода места;
он не считается полностью пройденным. После остановки затронутый набор схем
пройден отдельно. Самопроверка не является независимым ревью.

Полная dev-сборка рабочего реестра заняла 11 мин 31 с с одним rustc:
общая подпись каталога вызывает пересборку старых пакетов. Это остаётся
ограничением сборки, выбранное семейство отдельно собиралось за 1 мин 7 с.
Граф `bodies-5` содержит 916 общих библиотек; максимальный пакет с обвязкой —
2 296 139 байт, предел 16 МиБ сохранён. Сохранённые замеры 10× не изменены.

Оба вложенных common отмечены в двоичном чеклисте: **19/27 вложенных частей**,
common-каталоги остаются **56/90**. Полная сборка динамического списка и СКД
остаётся отдельной приёмкой. XML-фикстуры и TypeScript-обработчики не изменены.
