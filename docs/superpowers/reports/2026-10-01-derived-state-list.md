# Обратное восстановление состояний из YAML-тегов

Проверочный владелец [tagged-inferred-state.yaml](../../../rust/declarations/probes/tagged-inferred-state.yaml)
теперь преобразуется в обе стороны без переданного извне признака изменения.
XML читает состояние из коллекции, YAML выбирает состояние по тегу и
восстанавливает отсутствующий список через обычное `yaml.default`.

Пример: одна строка `Capacity / Extended` вместе со значением 11 превращается
в `Длина: !изменять 11`. Отдельного `Состояния` нет. Обратное чтение создаёт
ту же строку. `Длина: !изменять` одновременно восстанавливает число 9 и состояние.

Если строки отличаются от вычисляемого списка, сохраняется весь явный список:
соседние строки, их порядок и повторы. Это безопасный первый договор;
сокращение только части такого списка пока не реализовано. Явный пустой список
вместе с `!изменять` отклоняется объявленным ограничением согласованности.

## Общие механизмы

- Между частями записи передаётся номер выбранного варианта. Для `isVariant`
  не копируется полезное значение или коллекция. Чтение полезного значения
  захваченного выбора через другие операции этим изменением не реализовано.
- Коллекция объявленных записей поддерживает условный вычисляемый список
  и `concat` нескольких таких частей
  и сравнение с ним для сокращения YAML. Текст, boolean и точные числа
  сравниваются непосредственно через заимствованные поля хранилища;
  последовательный указатель проверяет объединённые части и конечную длину. Отдельная
  временная коллекция для сравнения не строится.
- Проверка равенства учитывает длину, порядок и все поля строки. Сокращение
  не удаляет исходную XML-форму строки с аномалиями.
- Сокращение без обратного договора отсутствующего YAML не разрешается.
  Старый отрицательный сценарий `omitWhen: true` без обратного чтения сохранён.
- Новые пути работают с конструкциями языка. В Rust нет проверок имён
  `Capacity`, `PropertyState` или `Длина`.

Матрица расширена внутри существующей проверки присутствия: два независимых
тега, все четыре сочетания, совокупный список и обратный порядок; обратное чтение
тега, соседние строки и повторы, отличающийся режим, противоречивый YAML,
независимая строка из текста/boolean/точного числа и постороннее поле владельца.
Числа 9007199254740993 и 9007199254740992 различаются. Лишний XML-атрибут строки
не теряется при совпадении смысловых полей с умолчанием; сохранение проверяется
через аномалию и XML ↔ YAML без референса. Исходные XML-фикстуры не менялись.

## Границы следующего шага

Проверка включает одно свойство и независимого владельца с двумя тегами,
соседним полем и переименованной коллекцией. Совокупный список вычисляется
одним обходом выбранных частей без временного списка для сравнения. В XML
проверочного примера ещё используется `exists`; для массового подключения
нужен общий заранее подготовленный индекс. Не переносить полный обход строк на каждое свойство.
Полную приёмку `InputByStringFields`, `InternalInfo` и проектных владельцев
этот результат не закрывает; флажки объектов остаются прежними. Производительность
конвертера и цель 10× в этом блоке не измеряются.

Проверка универсальности выполняется автором изменений по
`.agents/declarative-review.md`; это самопроверка, не независимое ревью.
