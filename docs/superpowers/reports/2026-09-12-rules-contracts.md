## Что проверяет запуск

Команда из корня: `pnpm test:migration-contracts`.
Отдельная генерация данных: `pnpm migration:contracts`.

1. Для 11 обычных случаев: XML → независимое ожидаемое значение YAML;
   затем независимый ожидаемый YAML → исходная структура XML.
2. Для всех 14: повторное чтение YAML и восстановление XML с заново
   подготовленными входами, без исходного XML-референса; валидация YAML.
3. Для трёх аномалий: тег на точном ключе свойства и восстановление XML.
   Независимые полные YAML-эталоны аномалий пока не перенесены.
4. YAML сравнивается по значениям и типам, без требования одинаковых кавычек.
   Числа не преобразуются в float. Отрицательная матрица отдельно проверяет,
   что соседние большие числа, десятичные дроби и строка вместо числа
   не считаются равными. XML сравнивается по структуре с пространствами имён;
   отступы между элементами несущественны, содержимое элементов сохраняется.

При проверке уточнены два условия запускателя: разные допустимые кавычки YAML
равнозначны; raw без смыслового значения использует физическое XML-имя
(`Turnover`), что уже закреплено тестом raw_property.rs. Рабочий конвертер
для прохождения этих проверок не менялся.

## Организация и ограничения

Данные: `tests/migration/rules-contract-cases.json`; в `pendingRows` указаны
неперенесённые строки выбранных таблиц, в `pending` — оставшиеся группы.
Тестовый каталог: `tests/migration/rules-contract-catalog/`.
Запускатель: `tools/rules-migration/runtime/`, отдельный временный Cargo-проект.
Он переиспользует rule-compiler, conversion-core и загрузчик деклараций.
Существующий nkdk-dev corpus привязан к рабочему каталогу и не исполняет
отдельные кандидаты; поэтому для них нужна отдельная сборка.

Эти 14 случаев не заменяют 5493 регистрации старых тестов. Автоматического
удаления старых проверок нет. Динамические тесты, типизированные скаляры,
отсутствующий основной язык, коллекции, порядок, повторы, даты и полные
владельцы ещё требуют переноса. Для дат сохраняется принятое записанное
время; соответствие кандидатов для дат пока отсутствует.

Проверены четыре матрицы JS-инструмента, отрицательная Rust-матрица сравнения,
14 договоров, Clippy, форматирование, обе архитектурные проверки и новые дубли.
Полный pnpm test и e2e в этом блоке не запускались. Производительность 10×
не измерялась. Новых готовых common или владельцев нет; флажки не добавлены.

boolean-аномалии по-прежнему проверяют тег и восстановление, а не полный эталон.

проверки специально отвергают потерянный тег, удалённое повторение,
перестановку ключей и подмену пустого значения пустой строкой. Разные
кавычки равнозначны; точные числа не преобразуются в float.

Остались другие сочетания параметров I8nText, отсутствие свойства в полном
владельце, остальные семейства коллекций и интеграция на e2e. Старые
тесты сохранены. Готовность объектов остаётся 16/90 common.

## Форматированный текст и точность сравнения

## Собственные и общие формы, нумераторы

Прошли 85 независимых договоров. Добавлены 98 вхождений ссылок на формы
и ссылка на нумератор: 3111 свойств, 714 фрагментов, 689 проекций,
168 зависимостей; 2766 вхождений пока заблокированы.

Общая декларация выбирает собственную или общую форму. Короткое имя формы
ограничено одной частью через `separator: '.'`; это устраняет пересечение
с записью `ОбщаяФорма.Имя`. Владелец и формы берутся из проверенного снимка
e2e с восстановлением всей цепочки родителей, включая внешние таблицы.

Чужой владелец не совпадает с восстанавливаемой пропущенной частью:
такая ссылка сохраняется целиком под исходным XML-именем, без ошибочного
сокращения. Это существующий общий договор text-pattern. Проверены также
общая форма, отсутствие и пустое свойство, существующий и отсутствующий
нумератор. Для обратного преобразования используется независимый ожидаемый
YAML, исходный XML не передаётся; индекс каждый раз собирается заново.

Формы другого типа владельца, дополнительные пути и смешанный набор корней
остаются блокировками. Флажки готовности полных объектов не изменены.

## Физические источники формы и состав свойств

Параметр `tag` сохранён как происхождение XML-источника. Свойства Metadata,
Form и без тега получают отдельные проекции даже при одинаковом XML-корне.
Общие чистые фрагменты могут переиспользоваться; маршрут источника не теряется.

Общий сборщик проверочной проекции объединяет свойства одного источника
в порядке исходного объявления, поднимает зависимости и проверяет входы.
На четырёх существующих парах e2e проверены 39 поддержанных свойств Form:
форма документа, журнала, справочника и критерия отбора. Ожидаемые блоки YAML
взяты из исходных файлов без исправления под результат нового конвертера.
Оставшиеся свойства явно перечислены как исключённые из этой проверки;
полная форма и её дочерние элементы ещё не приняты.

При этом обнаружен и исправлен перенос неявного значения только для YAML:
если отдельное XML-значение по умолчанию не задано, отсутствие YAML не должно
создавать XML-элемент с этим значением. Декларация выражает отсутствие XML
через условную каноническую форму `missing`. Явно записанная исходная форма
при необходимости сохраняется общим механизмом аномалий. Пустые маркеры
не добавлялись в независимые ожидаемые YAML ради прохождения проверки.

Подключён StringOrNumber: числовая строка и типизированное число проверяются
по исходным TS-литералам. Найденная паника при записи атрибута корневого
скаляра исправлена в общем генераторе: корень открывается самим писателем
значения, пустой корень добавляется только при отсутствии результата.
Матрица проверяет обычный атрибут типа и сохранённый дополнительный атрибут.

Итого: 3247 свойств-кандидатов, 761 фрагмент, 736 проекций, 189 зависимостей;
2630 вхождений остаются заблокированы. Проверки ядра и компилятора, Clippy
и поиск новых дублей прошли. Флажки полной готовности объектов не изменены.

Продолжение: прошли 102 договора и 174 декларации. Добавлены два поддержанных
свойства Metadata тех же четырёх форм; они выбираются из отдельного файла
метаданных с оболочкой Form/Properties. Независимый YAML общий для обоих
источников, поля между ними не смешиваются. Полный каталог из 3247 свойств
прошёл генерацию Rust: два файла, 48072241 байт. Проверочный запускатель
прошёл Clippy; это по-прежнему не компиляция всего каталога в итоговый продукт.

## Пути с пространствами имён

из исходного FORM_NAMESPACES, происхождение сохранено в каталоге. Неизвестный
префикс остаётся блокировкой. В существующей матрице проверены отказ при
неизвестном префиксе и перенос пути вместе с его пространством имён.

## Числовые границы

Перенесены девять свойств с постоянными minimum/maximum. Генератор выдаёт
ограничения обычного языка деклараций; Rust-обработчиков по имени свойства
нет. Независимая матрица по исходному правилу descriptionLength плана обмена
и прежнему тесту числовой схемы проверяет 0, 1, 1.5, 25, 250 и 251.
Границы включены, дроби внутри диапазона разрешены, 25 сокращается по default,
нарушение диапазона сохраняется с !xml/invalid и восстанавливает исходный XML.

Прошли 110 договоров. 3327 свойств-кандидатов, 830 фрагментов, 805 проекций,
199 зависимостей; 2550 вхождений ещё заблокированы. Зависимые ограничения
maximumWhen не отброшены и не считаются перенесёнными.

Изолированная проверка сохраняет все ограничения выбранного поля. Если
условие зависит также от другого поля или не имеет определённой границы,
выделение отклоняется. Ограничения других независимых полей не переносятся
в такой тест. Сравнение кандидатов с рабочими декларациями теперь показывает
также различия ограничений, отдельно от присутствия XML и YAML.

Полный каталог прошёл генерацию двух Rust-файлов на 49470250 байт.
Статический анализ также научился читать шаблонные строки с известными
простыми значениями; вызовы неизвестных функций и преобразование объектов
в строки не исполняются и остаются блокировками. Повторное извлечение
подтвердило ключи и порядок у всех 224 объявлений. Описания и maximumWhen
не исчезли из отчёта: до полного соответствия языка свойства заблокированы.

## XML-default без сокращения YAML

Подключены HTTPMethod и режим запуска расширения с noImplicitValueYAML и
preserveExplicitDefaultXML: отсутствие YAML получает XML-default, а явное
значение остаётся в YAML. Проверены совместные свойства двух вложенных методов
HTTP-сервиса на e2e. Для метода по умолчанию независимый обратный вход специально
не содержит HTTPМетод: XML восстанавливает GET. Прямой результат содержит GET;
повторный обратный проход проверяет также этот явный результат.

Неявные логические значения, записанные литералом YAML, разрешаются через
representations.yaml.values самой common-декларации. Отдельного списка русских
слов в переносчике нет. Проверка Metadata четырёх форм теперь включает также
IncludeHelpInContents. Прошли 112 договоров, 3331 свойство-кандидат; 830 фрагментов,
805 проекций, 200 зависимостей, 2546 заблокированных вхождений.

Для string доказана равнозначность одновременно заданных пустых
defaultValueXML и defaultValueXMLRaw: строковый обратный переход сохраняет
значение без преобразования. Это соответствие записано в parameterEquivalences;
оно не распространяется автоматически на I8nText или другие типы.
Подключены ещё 12 свойств и совместная проекция настоящей конфигурации.
Исправлен тестовый контекст: передаются только объявленные входы, неизвестные
входы по-прежнему отвергаются Rust. Прошли 113 договоров; 3343 кандидата,
830 фрагментов, 805 проекций, 200 зависимостей, 2534 блокировки.

## Постоянные значения и назначения использования

Все пять вхождений UsePurposes получили кандидаты: четыре с назначением
PlatformApplication по умолчанию и одно базовое, без такого сокращения.
Проверены оба направления, порядок, повторы, неизвестное значение и общий
объект формы Button из e2e. Для базового профиля одиночное PlatformApplication
остаётся явным списком, как предусмотрено принятой декларацией common.

Извлекатель распознаёт только синхронные стрелочные функции defaultValue без
аргументов, возвращающие литерал или список литералов. Исходный текст, место
и доказательство извлечения сохраняются отдельно от значения. Вызовы, ссылки
на переменные, async и функции других параметров не вычисляются и остаются
блокировками. Это временное средство переноса, не исполнение TS в Rust.

Прошёл 121 договор. Каталог содержит 3348 вхождений, 830 фрагментов,
805 проекций и 201 зависимость; 2529 вхождений заблокированы. Полные владельцы
ещё не приняты, флажки объектов не изменены.

Продолжение: два свойства dateTime подключены к существующему common. Проверены дата, время и значение по умолчанию. Всего 124 случая прошли; 3350 вхождений получили кандидаты. Проверки смещений, пустых состояний и аномалий дат на кандидатах ещё остаются. Новых частных обработчиков Rust для дат не добавлено.
