# Приёмка коллекции GroupItem

Одна [YAML-декларация](../../../rust/declarations/common/group-item-collection.yaml) задаёт выбор между GroupItemField и GroupItemAuto, порядок элементов и путь повторяющегося XML-элемента. Конвертер собирает оба направления из неё и уже принятых деклараций элементов; отдельного обработчика коллекции в Rust нет.

[Пробный сценарий](../../../rust/crates/compiled-rules/tests/dcs_lists.rs) проверяет смешанный порядок, новую YAML-запись, обратное преобразование без XML-референса, листовые коллекции из e2e-формы, локальную аномалию неверного значения и соседние обычные элементы. Совпадение имени поля со значением «[Авто]» разрешается общей логикой выбора: поле записывается картой, чтобы не стать другим вариантом при чтении. [Схема](../../../rust/crates/rule-compiler/tests/schema.rs) принимает обе разновидности и отклоняет неверное перечисление.

Полные StructureItemGroup и владельцы СКД принимаются отдельно: их вложенная цепочка ещё не выражена декларативно. Измерение скорости всего конвертера также остаётся отдельным этапом.

Проверки Rust для компилятора, ядра и пробной DCS-сборки, Clippy, поиск новых дублей и обе архитектурные проверки прошли. Полный набор TypeScript проходил до добавления этой Rust-декларации; повторные прогоны после неё выполнили сами тесты без функциональных ошибок, но завершились ошибкой контроля длительности при повышенной нагрузке: один тест занял 125 мс при лимите 100 мс, затем интеграционный файл — 7,6 с при меньшем лимите. Пороги и тесты не изменялись.
