# `CharacteristicsDescriptions`: декларативный перенос

Общая [декларация](../../../rust/declarations/common/characteristics-descriptions.yaml)
задаёт обе XML-ветви записи и коллекцию без частного обработчика Rust. XML-атрибуты
`from` записываются перед дочерними полями каждой ветви. Отсутствующее
служебное поле восстанавливается как `-1`; другое отрицательное значение
остаётся явным. Значение отбора допускает строку, boolean и ссылку согласно
исходному `rules.ts`. Именные ссылки, `UUID`, `UUID.UUID` и `1:UUID` выбираются
общей декларацией ссылок.
Каталог `rust/declarations/common` читается рабочей Rust-сборкой; для проверки
этого common использована отдельная декларативная проекция реальных владельцев.

[Проверка](../../../tools/rules-migration/src/characteristics-check.mjs) компилирует
необходимые декларации в Rust и сверяет оба направления без XML-референса:
все 10 непустых неизменённых e2e-пар, пустой контейнер, явный пустой список,
отрицательное служебное поле, локальную аномалию неверного поля и три формы
значения отбора. Для обычных значений проверяется отсутствие `!xml/raw`;
пустой физический XML-контейнер восстанавливается общей аномалией формы.
Исходные фикстуры не меняются, их хеши проверяются перед запуском.

Проверка `MetadataValue` на 17 формах исходного набора тоже проходит. Старый
набор для двух значений ожидал `!xml/raw`; теперь поддерживаемая UUID-ссылка
выводится как обычное значение. Поэтому тест требует точного YAML для обычных
случаев, а для ранее аномальных проверяет обратное восстановление исходного XML.
Тесты компилятора, Clippy и поиск новых дублей проходят.

При обновлении чеклиста обнаружена старая несогласованность: заголовок называл
53/90, а сами флажки содержали 51/90. После приёмки этого объекта фактическое
значение по флажкам — 52/90; сводка приведена к ним.
У вложенных частей также исправлена устаревшая сводка: фактически отмечено
14/27.

Приёмка относится к самому common-объекту. Полная приёмка документа,
справочника и других владельцев остаётся отдельно: их остальные свойства и
дочерние коллекции ещё не включены в одну рабочую сборку.

Следующий слой переноса подключил эту декларацию к переносчику `rules.ts`:
все 13 применений `CharacteristicsDescriptions` теперь распознаются одним
общим профилем последовательности с сохранением явно пустого XML. Проверка
17 случаев выше выполняется уже через автоматически построенную проекцию
свойства перечисления; отдельное ручное описание поля для этой проверки
удалено. Полный владелец перечисления пока не принят: в его исходном правиле
17 из 26 свойств стали кандидатами, остальные требуют сборки коллекций,
`InternalInfo`, корня и внешнего модуля.
