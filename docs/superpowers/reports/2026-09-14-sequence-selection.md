# Выбор единственного вхождения — подготовка подключения состояний

## Фактический результат

В `conversion-core::sequence_pattern` добавлен заимствованный выбор элемента
по предикату. Результат различает отсутствие, единственное вхождение и
неоднозначность. При неоднозначности ни одно вхождение не изымается из остатка.
Остаток сохраняет порядок и повторы соседних ключей. Исходный список остаётся
доступным; строки и элементы при выборе не копируются, промежуточный список
не создаётся.

Это только примитив работы с последовательностью. Компилятор деклараций пока
его не вызывает. Подключение `PropertyState`, конечная таблица отношения,
обратная вставка записи и восстановление XML этим изменением не реализованы.
Чеклист объектов не меняется: `ExtendedConfigurationObject` не принят.

## Проверка

Одна матрица проверяет пустоту, отсутствие выбранного ключа, единственное
вхождение в начале/середине/конце, одинаковые и различающиеся повторные
вхождения. Соседние записи имеют одинаковый ключ и разные значения, поэтому
проверка обнаруживает перестановку и потерю отдельных вхождений. Сравнение
адресов подтверждает заимствование исходных элементов.

- До реализации тест завершался ошибкой отсутствующих `Selection` и
  `select_unique`; после реализации прошёл.
- Все тесты `nkdk-conversion-core` прошли; расширенная матрица затем повторена.
- Clippy для `nkdk-conversion-core --all-targets` прошёл после последнего изменения.
- Проверка дублей относительно `37acdae1f` прошла.

Самопроверка: предметных имён и условий в примитиве нет; выбор задаётся
предикатом вызывающего кода. Независимое ревью не проводилось.

## Следующая обязательная интеграция

Прежде чем считать состояние расширения перенесённым, необходимо связать
одну декларативную таблицу с выбором строки, остатком общей коллекции и
источником базового идентификатора. Текущие захваты полей владельца передают
скалярные значения; коллекция требует типизированного доступа. Порядок чтения
по направлениям уже разделён для правил присутствия, но зависимости привязок
входов пока объединены: это нельзя обходить вторым контекстом или фиктивным
XML-полем. Проверка должна охватить настоящие `InternalInfo/xr:PropertyState`,
соседние записи, повторы, порядок и четыре согласованные формы YAML.
