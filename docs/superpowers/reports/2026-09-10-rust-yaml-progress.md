## Вычисляемые presence и обратимый остаток

Presence теперь генерирует конструкторы записей/последовательностей, отсутствие, omitWhen, упорядоченный canonical и normalization. Синтетические профили отдельно проверяют отсутствие, явно пустой список и вычисляемый default. Проверка canonical использует всю последовательность: пустое первое вхождение не скрывает непустой повтор. Нормализация не объявляется восстановлением исходной физической формы: если обычные формы её не воспроизводят, proof явно отказывает.

Если сокращённый кандидат не восстанавливает XML, генератор проверяет полную форму той же карты. В синтетическом профиле одиночный пустой перевод сохраняется обычным ru: "" вместо ошибочного перехода к raw. Этот результат не переносится автоматически на согласованные профили настоящего I8nText: там дополнительно действуют его ограничения и legacy-договор. Исправление уточняет предыдущее описание отказа сокращения. Новый raw не введён.

Keyed shorthand использует один структурный шаблон для обеих сторон: фиксированные prefix/suffix, единственный остаток, absentKeys и when. Существующие строки остатка перемещаются без клонирования; при записи остаток заимствуется. Тот же generated-code test проверяет default+en, маркер отсутствующего основного языка, разнесённый повтор ru и вычисление фиксированного текста общим UTF-16-преобразованием. Неготовое имя и имя без текстового результата делают такой шаблон неприменимым, не превращаясь в пустую строку. Сравнение полного значения с фиксированным конструктором генерируется как сравнение полей без временного Vec и копий строк.

Генерация выражений отделена от генерации диагностик. Всё перечисленное проверяется на синтетических декларациях, не считается завершением полного I8nText. XML-атрибуты, nil, приём/назначение разрешённых аномалий и полный независимый профильный корпус остаются открытыми.

## Аннотации, выводимые из декларации коллекции

Общий механизм Mapping выводит пометки повторных ключей из формы keyed-mapping, а недопустимые значения — из сгенерированных ограничений. Сгенерированный YAML-reader принимает пометки карты и ключа, проверяет точную границу, нумерацию и обоснованность. Непомеченный повтор отвергается. Структурная ошибка, например неготовый вход, не превращается в принятую смысловую аномалию. Important без действующей регистрации отвергается. На синтетических правилах и интегрированном I8nText проверены неизвестные повторные языки, нарушение порядка на карте, лишняя пометка и невозможность принять дочернюю ошибку пометкой карты.

Проверка пользовательского YAML выполняется до раскрытия сокращений. Это сохраняет адрес исходного помеченного языка, когда после чтения добавляется вычисляемый основной перевод. Смысловые строки перемещаются, а не копируются второй полной моделью; сохраняются только результаты диагностики. Повторная проверка окончательного кандидата по-прежнему обязательна. Подробное восстановление raw ещё не подключено.

Для исключительного пути добавлено выделение XML-поддерева с пустыми листьями, атрибутами и повторными детьми, представление его содержимого в YAML и запись обратно через общий XML-writer. ## Проверяемое сохранение формы I8nText и независимый корпус

Сгенерированный конвертер коллекций теперь пробует обычный окончательный YAML, затем полную карту без сокращений. Дерево XML и полное дерево YAML создаются только на исключительном пути; новые предметные raw-области этим изменением не согласовываются.

Следующий блок после FormattedI8nText — простые значения. В общем генераторе реализовано объявленное двустороннее отсутствие скаляра через Option<T>, без подмены false и без предметной ветви boolean. До ответа эта область не включена; текущие проверки требуют явной ошибки. Повторно прошли все 30 поддержанных случаев корпуса.

## М2: параметры скаляров и приёмка MinMaxValue

## Системные перечисления: весь каталог одним семейством

Приняты 678 перечислений и 3501 обратимая пара, включая три таблицы мобильных разрешений из повторного экспорта. Скрипт `tests/migration/checks/system-enumerations.py` сверяет все исходные таблицы, их обратимость, XML-псевдонимы и контрольные суммы; результат хранится в `system-enumeration-tables.json`. Этот реестр учитывает весь каталог отдельно от реестра 90 common. Common по-прежнему приняты девять; системные перечисления отмечены одним пунктом.

Короткая карта `enum` раскрывается в обычную декларацию. `catalog` упаковывает декларации, наследуя только версию формата. Статическая XML-проекция переиспользует смысл и YAML и задаёт типизированную оболочку DCS. XML-псевдонимы принимаются только при чтении; отличие от канонической формы сохраняется общей обратной проверкой. Неполная базовая таблица проекции даёт диагностику компилятора. Особые значения по умолчанию и подавление свойства владельцем не принадлежат таблице перечисления и принимаются вместе с владельцем.

Единая проверка `compiled-rules/tests/system_enumerations.rs` проходит все пары в обоих XML-профилях, проверяет YAML, валидацию и обратное восстановление. Она также проверяет неизвестные варианты, отсутствие обязательного свойства, пустоту, пропущенный/неверный XML-тип и альтернативную запись с сохранённым смыслом. Для отсутствующего обязательного скаляра исправлен общий путь: `$xml: null` сохраняет отсутствие, а не создаёт пустой элемент. В отличие от старых ошибок TS, отклонения XML сохраняются без отдельной декларации аномалии.

Из неизменённого e2e проверены 95 свойств: 89 CheckBoxType, 3 RadioButtonType, 2 типизированных FoldersAndItemsUse и 1 HorizontalAlign. Отчёт `system-enumeration-e2e.json` указывает файлы и контрольные суммы. Это представительские проверки свойств, не полный импорт владельцев; полноту 678 таблиц подтверждает отдельная общая проверка всех пар. Enterprise не реализуется; XML DCS остаётся в договоре.
