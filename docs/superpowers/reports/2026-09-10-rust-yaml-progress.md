## Вычисляемые presence и обратимый остаток

Presence теперь генерирует конструкторы записей/последовательностей, отсутствие, omitWhen, упорядоченный canonical и normalization. Синтетические профили отдельно проверяют отсутствие, явно пустой список и вычисляемый default. Проверка canonical использует всю последовательность: пустое первое вхождение не скрывает непустой повтор. Нормализация не объявляется восстановлением исходной физической формы: если обычные формы её не воспроизводят, proof явно отказывает.

Если сокращённый кандидат не восстанавливает XML, генератор проверяет полную форму той же карты. В синтетическом профиле одиночный пустой перевод сохраняется обычным ru: "" вместо ошибочного перехода к raw. Этот результат не переносится автоматически на согласованные профили настоящего I8nText: там дополнительно действуют его ограничения и legacy-договор. Исправление уточняет предыдущее описание отказа сокращения. Новый raw не введён.

Keyed shorthand использует один структурный шаблон для обеих сторон: фиксированные prefix/suffix, единственный остаток, absentKeys и when. Существующие строки остатка перемещаются без клонирования; при записи остаток заимствуется. Тот же generated-code test проверяет default+en, маркер отсутствующего основного языка, разнесённый повтор ru и вычисление фиксированного текста общим UTF-16-преобразованием. Неготовое имя и имя без текстового результата делают такой шаблон неприменимым, не превращаясь в пустую строку. Сравнение полного значения с фиксированным конструктором генерируется как сравнение полей без временного Vec и копий строк.

Генерация выражений отделена от генерации диагностик. Всё перечисленное проверяется на синтетических декларациях, не считается завершением полного I8nText. XML-атрибуты, nil, приём/назначение разрешённых аномалий и полный независимый профильный корпус остаются открытыми.

## XML-атрибуты, nil и интегрированная декларация I8nText

Общий XML-поток сохраняет атрибуты с расширенными именами и разрешает QName-значения. Proof сравнивает QName по URI/локальному имени только на объявленных путях, игнорирует порядок атрибутов, объединяет соседние текстовые события и сохраняет пробельный текст листьев. Writer не добавляет форматирующий перевод строки внутрь пустого листа. Nil проверяется отдельно; nil с дочерними элементами отвергается.

При сверке интегрированной декларации с TS исправлены значения empty-element/nil, каноническая пустая оболочка и отсутствие ограничения «остаток непустой» для маркера отсутствующего основного языка. Это не отменяет согласованный raw для физического пустого перевода при профиле с маркером. Пользователь явно разрешил расширить when XML-атрибута на значение и объявленные inputs; спецификация и типизация обновлены, callback не добавлены.

Интегрированная декларация теперь проходит реальную генерацию и сборку. Добавлен нейтральный договор проверки границ invalid/important по существующему TS: принимаются только смысловые ошибки точного пути, файла и вхождения. Родительская граница не принимает дочернюю ошибку; структурные ошибки не скрываются. Проверены три сочетания карты/ключа из независимого контракта, отдельное повторное вхождение, обязательность important и отложенная проверка лишнего тега. ## Аннотации, выводимые из декларации коллекции

Общий механизм Mapping выводит пометки повторных ключей из формы keyed-mapping, а недопустимые значения — из сгенерированных ограничений. Отдельных annotations.contract или annotation: invalid в декларации нет. Нумерация учитывает только помеченные вхождения одного ключа: обычное первое значение, invalid у первого дубля и invalid/2 у следующего; если первое значение нарушает ограничение, оно тоже занимает первый номер пометки.

Сгенерированный YAML-reader принимает пометки карты и ключа, проверяет точную границу, нумерацию и обоснованность. Непомеченный повтор отвергается. Структурная ошибка, например неготовый вход, не превращается в принятую смысловую аномалию. Important без действующей регистрации отвергается. На синтетических правилах и интегрированном I8nText проверены неизвестные повторные языки, нарушение порядка на карте, лишняя пометка и невозможность принять дочернюю ошибку пометкой карты.

Проверка пользовательского YAML выполняется до раскрытия сокращений. Это сохраняет адрес исходного помеченного языка, когда после чтения добавляется вычисляемый основной перевод. Смысловые строки перемещаются, а не копируются второй полной моделью; сохраняются только результаты диагностики. Повторная проверка окончательного кандидата по-прежнему обязательна. Подробное восстановление raw ещё не подключено.

Для исключительного пути добавлено выделение XML-поддерева с пустыми листьями, атрибутами и повторными детьми, представление его содержимого в YAML и запись обратно через общий XML-writer. Writer теперь заимствует и динамические имена без утечек строк в static. Смешанное содержимое и разнесённые повторы детей пока явно отвергаются этим поддеревом; применение raw в публичном конвертере ещё не включено.

Запрошено отдельное упрощение авторской записи декларации. Предложены краткие типы, объединение описания полей с XML-путями и вывод стандартного представления; конкретный вариант ещё обсуждается. Действующая грамматика по этому предложению пока не менялась.

При повторной сверке с TS localProof выявлено и исправлено неверное ослабление проверки порядка атрибутов: сортировка удалена из XML-потока. Порядок сохраняется и участвует в проверке восстановления; переименование префикса при том же URI по-прежнему эквивалентно. Более ранняя запись журнала об игнорировании порядка атрибутов этим исправлением отменяется. Повтор расширенного имени атрибута всё ещё отвергается.

## Проверяемое сохранение формы I8nText и независимый корпус

Сгенерированный конвертер коллекций теперь пробует обычный окончательный YAML, затем полную карту без сокращений. Только ошибка сравнения XML допускает сохранение объявленной границы свойства; ошибки структуры и входов не превращаются в raw. Окончательный YAML с `$значение`/`$xml` заново читается и экспортируется тем же XML-writer. Изменение содержимого `$xml` обнаруживается проверкой относительно исходного XML. YAML-валидация проверяет оболочку и смысловые пометки без контрольного XML-экспорта. Дерево XML и полное дерево YAML создаются только на исключительном пути; новые предметные raw-области этим изменением не согласовываются.

Разнесённые повторные XML-дети теперь сохраняются через `#order`; прежнее ограничение выделенного поддерева на такие повторы снято. Смешанное текстовое содержимое пока явно не поддерживается. Пустые листья, текст с пробелами, QName и порядок атрибутов проверены отдельно.

Проверены пять физических XML-состояний для всех 16 сочетаний P/N/S/T. Найдено и исправлено условие декларации: отсутствие смыслового значения проверяется до выбора пустой XML-формы, иначе preserveEmptyXML мог создавать элемент из отсутствующего свойства.

Существующий тест генерации дополнительно исполняет все 12 независимых случаев I8nText из manifest: точный ожидаемый YAML, валидация и проверка восстановления. Исходные XML не изменялись; явно объявленный контекст пространства имён и оболочка для фрагмента Title добавляются только в памяти теста. FormattedI8nText этим набором не покрывается. Основной CLI корпуса пока не подключён к этим профилям, поэтому этап А6 и флажок объекта остаются открытыми.

Создан пользовательский чеклист всех объектов, связанный с главным планом и планом каталога. Он использует только два состояния флажка; промежуточные сведения остаются в этом журнале. По уточнению пользователя весь каталог из 675 системных перечислений учитывается одним пунктом и переносится пакетом через общий механизм.

Проверки слоя: 123 Rust-тестов workspace (включая сборку и Clippy сгенерированного кода), Clippy workspace, fmt, diff --check, проверки архитектуры и отсутствие новых дублей относительно bad9f1aa8. Полный TS-набор ранее прошёл; в этом слое TS-код не менялся. Измерения 10× не проводились.

Единственный исходник I8nText перенесён из тестового примера в `rust/declarations/common/i8n-text.yaml`; тесты компилятора используют этот же файл. Несовпадающие параметры, неизвестный профиль, неверный тип списка языков и отсутствие обязательного входа проверены как ошибки, а не игнорируются.

Вместе с пятью ранее поддержанными группами подтверждены 26 случаев преобразования и валидации. Прошли 124 Rust-теста workspace и Clippy. Это ещё не полный договор I8nText и не FormattedI8nText; флажки объектов остаются пустыми. Следующая незавершённая возможность генератора — вложенная запись с коллекцией и смысловым XML-атрибутом.

Пользователь разрешил сохранение отсутствующего formatted при условии общего вывода аномалий из декларации. Это реализовано проверкой окончательного экспорта и общей разницей `_formatted: null`. Исправлено общее восстановление порядка атрибутов без копирования дочернего содержимого. Объектных ветвей в ядре нет.

## Общая основа отсутствующих скаляров

Следующий блок после FormattedI8nText — простые значения. В общем генераторе реализовано объявленное двустороннее отсутствие скаляра через Option<T>, без подмены false и без предметной ветви boolean. Экспорт сохраняет корень при отсутствии всех свойств. Схема получает необязательность из того же presence. Подключена рабочая декларация boolean; default/implicit и сохранение явного default у владельца остаются незавершёнными, флажок объекта не установлен.
