# Child Template Copy Design

## Контекст

`round-trip-yaml` показывает потерю файлов дочерних макетов отчетов:
`Templates/<Макет>/Ext/Template/Items/<Элемент>/Picture.*`.

Сейчас дочерние шаблоны не разбираются в модель. Обработчик `ChildTemplateNames` копирует
`Templates/<Макет>.xml` в `Шаблоны/<Макет>/Template.xml`, а отдельные внешние файлы макета
подхватывает частично. Из-за этого вложенные файлы внутри каталога шаблона теряются.

## Решение

Пока шаблоны не разбираются, каталог шаблона должен копироваться как непрозрачный внешний каталог.

Правило уровня `ChildTemplateNames`:

- `Templates/<Макет>.xml` хранится как `Шаблоны/<Макет>/Template.xml`;
- содержимое каталога `Templates/<Макет>/...` хранится как `Шаблоны/<Макет>/...`;
- при обратной синхронизации `Шаблоны/<Макет>/...` восстанавливается в `Templates/<Макет>/...`.

Это заменяет частичную поддержку через `externalTemplateFiles` для дочерних шаблонов.
Общий механизм `rules.externalFiles` не расширяется.

## YAML-Контракт

Для дочернего шаблона YAML-каталог выглядит так:

```text
Шаблоны/
  <Макет>/
    Template.xml
    Ext/
      Template.txt
      Template.bin
      Template.xml
      Template/
        ...
```

Все файлы внутри `Ext/` считаются частью исходного шаблона и сохраняются без преобразования.

## Тестирование

Sync-фикстура `ChildTemplateNames` должна содержать вложенный файл:
`Templates/<Макет>/Ext/Template/Items/<Элемент>/Picture.png`.

Тест должен проверить полный цикл:

- fromXML копирует файл в `Шаблоны/<Макет>/Ext/Template/Items/<Элемент>/Picture.png`;
- toXML восстанавливает файл в `Templates/<Макет>/Ext/Template/Items/<Элемент>/Picture.png`;
- восстановленный файл добавляется в `XmlSyncManifest`.

## Вне Границ

Этот пункт не разбирает формат шаблона и не добавляет модельные свойства для элементов макета.
Отдельные внешние файлы общих макетов и файлов форм разбираются другими пунктами.
