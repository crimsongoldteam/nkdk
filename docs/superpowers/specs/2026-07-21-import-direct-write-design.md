# Import Direct Write Design

## Goal

Упростить XML-import: убрать временный каталог `.nkdk/tmp/import/<operation-id>` и отдельный перенос результата импорта в проект. Так как MCP-договор требует отсутствующий или пустой целевой компонент, import может писать результат сразу в целевой каталог.

## Contract

- Core import получает `outputDir` как пустой каталог YAML-компонента.
- Worker второго прохода пишет YAML и generated external files сразу в `outputDir/targetProjectPath`.
- Main после второго прохода копирует внешние файлы XML-выгрузки сразу в `outputDir/targetProjectPath`.
- `Список файлов результата импорта` остаётся как контроль уникальности и источник `projectFiles` для файла индекса.
- При ошибке после частичной записи каталог может остаться частично заполненным; следующая попытка требует очистки каталога вызывающей стороной.
- `preservedTempRoot` удаляется из результата XML-import, CLI/MCP текстов и contracts.

## Architecture Updates

Этапы import меняются:

- Удаляются `Создание временного каталога`, `Перенос результата импорта в проект`, `Удаление временного каталога`.
- `Формирование worker списка файлов результата импорта` становится описанием уже записанных worker-файлов и внешних XML-файлов.
- `Копирование внешних файлов XML-выгрузки` добавляется как main-step после обобщения списка файлов.
- `Вычисление хэшей файлов проекта` для import должно использовать список результата импорта, а не полный обход `outputDir`.

## Restrictions

- XML-фикстуры не менять.
- Core metadata-слои не знают про `cf/cfe/erf/epf`.
- Не добавлять транзакционность и rollback в этой итерации.
- CLI всё ещё принимает `<xmlDir> <yamlDir>`, но желательно добавить проверку пустого `yamlDir`, чтобы не расходиться с MCP.
