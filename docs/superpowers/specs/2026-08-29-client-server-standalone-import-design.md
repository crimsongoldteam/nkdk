# Импорт клиент-серверной базы через автономный сервер

## Контекст

NKDK умеет импортировать конфигурацию и получать список расширений через
автономный сервер `ibsrv`, но `createStandaloneServerSession` сейчас разрешает
только файловую строку подключения `File=...`. Клиент-серверная строка
`Srvr=...;Ref=...` отклоняется до запуска платформы, хотя настройки проекта уже
содержат отдельные параметры СУБД, а `buildStandaloneConfigInit` уже строит
аргументы `ibcmd server config init` для клиент-серверной базы.

Документация 1С и справка `ibcmd` платформы 8.3.27 подтверждают, что автономный
сервер поддерживает клиент-серверный вариант. Конфигурация создаётся по типу
СУБД, адресу сервера, имени базы и, при необходимости, учётным данным СУБД.

Основание:

- [глава об автономном сервере в руководстве администратора 1С](https://its.1c.ru/db/v8325doc/bookmark/adm/TI000000894);
- [обзор автономного сервера на сайте платформы](https://v8.1c.ru/platforma/avtonomnyy-server/);
- локальная справка `/opt/1cv8/8.3.27.2214/ibcmd help server`, перечисляющая
  `--dbms`, `--database-server`, `--database-name`, `--database-user` и
  `--database-password` для `server config init`.

## Цель

Разрешить через автономный сервер следующие читающие операции с
клиент-серверной информационной базой:

- импорт основной конфигурации или одного расширения;
- получение списка расширений.

Частичная загрузка изменений в клиент-серверную базу остаётся запрещённой.

## Границы

В изменение входят:

- создание автономного сеанса для `Srvr`/`Ref` по существующему блоку
  `infobase.database`;
- экспорт основной конфигурации и расширения через созданный сеанс;
- получение списка расширений через тот же сеанс;
- ранний запрет частичной загрузки для сочетания клиент-серверной базы и режима
  `standalone-server`;
- модульные проверки построения сеанса, границы записи и безопасной обработки
  учётных данных;
- обновление документации MCP.

Не входят:

- частичная или полная загрузка конфигурации в клиент-серверную базу;
- изменение формата `.nkdk/project.yaml`;
- получение параметров СУБД из `Srvr`/`Ref` или из реестра кластера 1С;
- создание базы данных или изменение её параметров;
- поддержка web-подключений;
- хранение паролей иначе, чем это уже определено настройками проекта.

## Настройки подключения

`connectionString` продолжает определять тип информационной базы и учётные
данные пользователя 1С. Для `Srvr`/`Ref` в режиме `standalone-server` блок
`database` остаётся обязательным и является единственным источником координат
СУБД:

```yaml
infobase:
  connectionString: 'Srvr="cluster";Ref="production";'
  user: Администратор
  password: secret
  database:
    dbms: PostgreSQL
    server: db.example.local
    name: production
    user: dbuser
    password: dbsecret
  operations:
    import:
      mode: standalone-server
      unresolvedReferences: include
```

Поддерживаемые значения `database.dbms` не меняются: `MSSQLServer`,
`PostgreSQL`, `IBMDB2` и `OracleDatabase`. Для MSSQL отсутствие пользователя и
пароля означает проверку средствами ОС; для остальных СУБД пользователь остаётся
обязательным согласно существующей проверке настроек.

## Создание автономного сеанса

`createStandaloneServerSession` разбирает `connectionString` и выбирает параметры
инициализации:

- для `File` передаёт `databasePath` как сейчас;
- для `Srvr`/`Ref` требует `settings.database` и передаёт его в
  `buildStandaloneConfigInit`;
- остальные типы подключения отклоняет до обращения к файловой системе,
  процессам и сети.

`ibcmd server config init` формирует приватный `config.yaml`. Дальнейший запуск
`ibsrv`, SSH-аутентификация пользователя информационной базы, экспорт и
переиспользование сеанса сохраняют существующий жизненный цикл без отдельной
клиент-серверной ветки.

Строка `Srvr`/`Ref` не передаётся автономному серверу: она нужна NKDK для выбора
режима и идентификации подключения. Сам `ibsrv` подключается к той же базе
напрямую по параметрам `database`.

## Граница операций записи

`PlatformSessionManager.loadPartialConfiguration` до поиска платформы и создания
сеанса проверяет сочетание:

- `mode === "standalone-server"`;
- разобранное подключение имеет тип `server`.

При таком сочетании операция завершается стабильной ошибкой
`unsupported_connection`, объясняющей, что автономный режим пока поддерживает
клиент-серверную базу только для импорта. Проверка выполняется на публичной
границе операции, поэтому запрещённый вызов не создаёт `config.yaml`, не запускает
`ibsrv` и не обращается к СУБД.

Сам объект автономного сеанса также не должен выполнять частичную загрузку для
клиент-серверного подключения. Это защитная проверка для прямого использования
сеанса и для уже открытого читающей операцией сеанса.

## Ошибки и безопасность

- отсутствие `database` для клиент-серверного автономного режима возвращает
  управляемую ошибку настроек или запуска сеанса;
- ошибка `ibcmd server config init` проходит через существующую нормализацию и
  журнал операции;
- пароль СУБД передаётся `ibcmd` отдельным элементом массива аргументов без
  shell-интерпретации;
- существующее скрытие паролей пользователя 1С и СУБД в журнале сохраняется;
- `config.yaml` сохраняет права `0600` на Unix и удаляется при закрытии или
  неудачном запуске;
- отказ частичной загрузки не должен включать значения строки подключения или
  учётных данных.

## Проверки

Модульные тесты фиксируют следующие договоры:

- PostgreSQL с пользователем и паролем создаёт `config.yaml` через ожидаемые
  аргументы `ibcmd` и открывает автономный сеанс;
- MSSQL без пользователя и пароля использует проверку средствами ОС и не
  добавляет пустые аргументы учётных данных;
- отсутствие `database` отклоняется до запуска `ibcmd`;
- импорт и список расширений доступны клиент-серверному автономному сеансу;
- частичная загрузка отклоняется до поиска платформы и запуска процесса;
- частичная загрузка также отклоняется уже открытым клиент-серверным сеансом;
- файловый автономный режим и оба режима агента сохраняют прежнее поведение;
- пароли не появляются в пользовательских ошибках и журнале.

После реализации выполняются тесты изменённых пакетов, `pnpm duplicates --
--base <commit>` и полный `pnpm test`. Реальная проверка с клиент-серверной базой
выполняется при наличии тестовой СУБД и подтверждает импорт основной конфигурации
либо расширения в новый пустой компонент.

## Документация

README должен явно разделять возможности:

- автономный импорт и список расширений поддерживают файловые и
  клиент-серверные базы;
- автономная частичная загрузка разрешена только для файловых баз;
- для клиент-серверного автономного импорта обязателен блок `database`;
- параметры СУБД и правила хранения паролей остаются прежними.

## Критерии готовности

- `nkdk.import_from_infobase` не отклоняет `Srvr`/`Ref` в режиме
  `standalone-server`, если задан корректный блок `database`;
- импорт основной конфигурации и одного расширения использует клиент-серверный
  автономный сеанс;
- получение списка расширений работает через тот же тип сеанса;
- `nkdk.sync_to_infobase` отклоняет клиент-серверный автономный режим до запуска
  платформы;
- файловые подключения и агентный режим не изменяют поведение;
- автоматические проверки проекта проходят.
