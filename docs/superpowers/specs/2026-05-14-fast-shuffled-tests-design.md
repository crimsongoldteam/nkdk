# Быстрый случайный запуск тестов

## Цель

Сделать основной `pnpm test` быстрым для ежедневной разработки, не теряя способ запустить строгую проверку с изоляцией файлов.

Текущий замер показал, что `packages/core` содержит основную массу тестов: 574 файла и 3355 тестов. Обычный запуск `vitest run` в `packages/core` прошел примерно за 190 секунд, при этом суммарное время самих тестовых файлов в отчете Vitest около 10 секунд. Экспериментальный запуск `vitest run --no-isolate` прошел те же 3355 тестов за 6.9 секунды без падений.

## Решение

Основной режим `pnpm test` переводится на быстрый запуск без изоляции файлов и со случайным порядком:

- `--no-isolate` убирает отдельную среду для каждого тестового файла;
- `--sequence.shuffle` перемешивает и файлы, и тесты, чтобы быстрее находить скрытые зависимости от порядка выполнения.

Для строгой проверки добавляется отдельный режим `pnpm test:isolated`, который сохраняет текущее поведение Vitest с изоляцией файлов. Он нужен для диагностики плавающих падений и для случаев, где важна максимальная независимость тестовых файлов.

## Команды

Корневые сценарии:

- `pnpm test` — быстрый основной запуск всех пакетов;
- `pnpm test:isolated` — строгий запуск всех пакетов с изоляцией;
- `pnpm --filter @nakidka/core test` — быстрый запуск `packages/core`;
- `pnpm --filter @nakidka/core test:isolated` — строгий запуск `packages/core`.

Для воспроизведения случайного падения Vitest должен печатать seed. Повторный запуск выполняется с тем же seed:

```bash
pnpm --filter @nakidka/core exec vitest run --no-isolate --sequence.shuffle --sequence.seed <seed>
```

## Границы

Первый шаг меняет только сценарии запуска тестов и не переписывает сами тесты. Если случайный порядок выявит зависимость между тестами, это отдельная правка: либо восстановить очистку состояния в тесте, либо явно оставить такой файл в строгом режиме через отдельный сценарий.

Изменения не затрагивают XML-фикстуры и не меняют логику fromXML/toXML/fromYAML/toYAML.

## Риски

Без изоляции тестовые файлы делят процесс, кэш импортов, глобальные переменные, моки, таймеры и `process.env`. Случайный порядок снижает риск незаметной зависимости, но не заменяет строгую изоляцию полностью.

Если быстрый режим начнет плавать, разбор идет по seed: воспроизвести порядок, найти тест, который оставляет состояние, и добавить очистку в `afterEach`/`afterAll` или локализовать мок.

## Проверка

После реализации нужно выполнить:

- `pnpm --filter @nakidka/core test`;
- `pnpm --filter @nakidka/core test:isolated`;
- `pnpm test`;
- `pnpm test:isolated`.

Если свежий worktree потребует Langium-файлы, перед полным запуском выполнить `pnpm --filter nkdk-language langium:generate`.
