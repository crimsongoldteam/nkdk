# Восстановление XML-default без reference

## Цель

Убрать зависимость преобразования YAML → XML от исходного XML для свойств,
помеченных `preserveFromReferenceXML`. Если свойство отсутствует в YAML,
канонический XML должен восстанавливаться из декларативного правила или
зарегистрированного обработчика типа.

## Границы

- Удалить `preserveFromReferenceXML` из договора `PropertyRule`.
- Удалить все 19 применений этого признака в восьми `rules.ts`.
- Не добавлять значения, признаки присутствия или служебные поля в снимок
  конфигурации.
- Не использовать reference XML для восстановления известных свойств.
- Не изменять существующие XML-фикстуры.

## Архитектура

Общий конвейер YAML → XML больше не выделяет отдельную ветку для
`preserveFromReferenceXML`. Отсутствующее YAML-свойство проходит обычное
преобразование:

1. `defaultValue` или `implicitValueYAML` формирует значение модели, если это
   предусмотрено правилом;
2. `defaultValueXML` задаёт каноническое скалярное значение XML;
3. `defaultValueXMLRaw` задаёт каноническое пустое, `xsi:nil` или составное
   значение XML;
4. зарегистрированный обработчик типа выполняет специальное преобразование.

Reference XML остаётся допустимым входом для других задач синхронизации,
например сохранения неизвестных XML-узлов, но отсутствие известного свойства
в YAML больше не блокирует его экспорт.

## Правила с удаляемым признаком

- `metadataAttribute`: `Indexing`, `FullTextSearch`, `DataHistory`,
  `FillFromFillingValue`, `FillValue` и два варианта `Use`;
- `characteristicsDescription`: четыре поля связей характеристик;
- таблица управляемой формы: `Period`, `TopLevelParent`, `RowFilter`;
- по одному полю в `configuration`, `clientApplicationForm`, `dynamicList`,
  `metadataTabularSection` и `dcsParameter`.

Каждое из этих правил после удаления признака должно либо иметь достаточный
канонический XML-default, либо явно разрешать отсутствие XML-узла. Новые
частные ветвления в общей оркестрации не добавляются.

## Канонизация

Если исходный XML допускает как отсутствие тега, так и явный тег с default,
чистый YAML → XML выбирает форму, заданную `rules.ts`. Структурная форма
исходного XML не является источником истины. Это намеренная канонизация:
результат детерминирован YAML и версией правил.

## Проверки

1. Регрессионный тест общего YAML → XML преобразования: отсутствующее поле с
   `defaultValueXML` экспортируется без reference.
2. Тест `metadataAttribute`: минимальный YAML восстанавливает
   `FillFromFillingValue`, `Indexing`, `FullTextSearch` и `DataHistory`.
3. Проверка исходного кода: в производственных правилах и типе
   `PropertyRule` не остаётся `preserveFromReferenceXML`.
4. Целевые тесты затронутых модулей.
5. Полный `pnpm test`.
6. Повторный round-trip `/Users/nikita/git/round-trip/cf/doc`: массовая группа
   удалений XML-default должна исчезнуть, а число новых расхождений
   канонизации фиксируется отдельно.

## Критерии готовности

- YAML → XML не читает reference для решения, экспортировать ли известный
  default.
- Снимок конфигурации не меняется.
- Все тесты проходят.
- В round-trip отсутствуют массовые удаления `DataHistory`, `Indexing`,
  `FullTextSearch` и `FillFromFillingValue`.
