# Round-trip XML triage batches

## Контекст

`round-trip-xml` сейчас работает вокруг одного первого diff-файла: `round-trip.sh`
запускает `short-round-trip-test`, сортирует изменённые XML-файлы и отдаёт первый
по алфавиту diff. Это удобно для одиночного reproducer'а, но мешает параллельной
работе: пользователь не видит следующие проблемы и не может заранее выбрать
несколько независимых тем для отдельного анализа.

## Цель

Добавить информационный triage-режим, который показывает пачку round-trip
расхождений. Пачка нужна только для анализа и выбора следующих задач. Для каждого
элемента пользователь должен видеть исходный XML-файл, вероятный модуль в
`packages/core/metadata`, вероятное место в коде, категорию расхождения,
краткое описание и релевантный фрагмент diff.

## Не Цель

- Не создавать reproducer'ы для пачки.
- Не создавать ветки, slug, XML/TS-фикстуры или тест-блоки.
- Не предлагать план исправления в triage-режиме.
- Не сохранять очередь ошибок на диск.
- Не менять текущий workflow одиночного reproducer'а, кроме возможности выбрать
  diff по номеру.

## CLI-Контракт

`round-trip.sh` получает два режима поверх текущего поведения:

```bash
./.agents/skills/round-trip-xml/round-trip.sh --diff-index 3
./.agents/skills/round-trip-xml/round-trip.sh --triage --batch-size 5
./.agents/skills/round-trip-xml/round-trip.sh --triage --batch-size 5 --start-index 6
```

Без параметров поведение остаётся прежним: выбирается первый diff.

Индексы 1-based: `--diff-index 1` и запуск без параметров указывают на один и тот
же файл. `--start-index 6 --batch-size 5` означает диапазон 6-10 из
отсортированного списка diff-файлов. Если `--triage` указан без `--batch-size`,
скрипт использует размер пачки `5`.

## Вывод Скрипта

Скрипт остаётся тонким раннером. Он только запускает round-trip, считает список
diff-файлов и печатает выбранные diff'ы. Категоризацию делает AI в `SKILL.md`.

Одиночный режим печатает:

```text
=== DIFF_COUNT ===
<общее число diff-файлов>

=== SELECTED_DIFF_INDEX ===
<номер>

=== SELECTED_DIFF_FILE ===
<относительный путь внутри NKDK_XML_DIR>

=== SELECTED_XML_FILE_ABS ===
<абсолютный путь к XML-файлу>

=== FULL_DIFF ===
<полный git diff выбранного файла>
```

Triage-режим печатает:

```text
=== DIFF_COUNT ===
<общее число diff-файлов>

=== TRIAGE_RANGE ===
<start>-<end>

=== TRIAGE_DIFF ===
INDEX: <номер>
FILE: <относительный путь внутри NKDK_XML_DIR>
XML_FILE_ABS: <абсолютный путь к XML-файлу>
--- DIFF ---
<полный git diff файла>
```

Блок `TRIAGE_DIFF` повторяется для каждого файла в пачке. Если диапазон выходит
за пределы списка, скрипт печатает доступные элементы и не падает. Если diff'ов
нет, сохраняется сообщение о чистом round-trip.

## Поведение Скилла

`SKILL.md` получает отдельный раздел «Triage-пачка». По запросам вроде
«покажи следующие 5 ошибок», «дай пачку с 6-й» или «покажи 10 diff'ов для
анализа» AI запускает скрипт в triage-режиме.

После запуска AI формирует краткий список. Каждый пункт содержит:

```text
1. Catalogs/.../Ext/Form.xml
   XML-файл: /Users/nikita/git/round-trip-source/trade/Catalogs/.../Ext/Form.xml
   Вероятный модуль: packages/core/metadata/...
   Вероятный код: packages/core/metadata/.../rules.ts
   Категория: потеря пустого тега / порядок XML-узлов / лишний default /
              потеря атрибута / потеря xsi:type / потеря id или ссылки /
              неизвестно
   Описание: что именно изменилось при round-trip
   Diff:
   <короткий релевантный фрагмент>
   Сомнения: если модуль или причина неочевидны
```

В ответе путь `XML-файл` должен быть абсолютным локальным путём. Если файл
существует, его нужно оформить как кликабельную ссылку в финальном ответе Codex.

AI может читать кодовую базу (`rg`, `sed`, соседние `rules.ts` и `types.ts`),
чтобы предположить модуль и место в коде, но не редактирует файлы в triage-режиме.
Если причина повторяется в нескольких diff'ах, AI может отметить связь между
пунктами, но не объединяет их в одну задачу.

## Одиночный Reproducer Workflow

Старый workflow остаётся без изменений: один запуск создаёт один изолированный
TDD-reproducer после подтверждения пользователя. Новое дополнение: если
пользователь просит разобрать конкретный номер из triage-пачки, скилл запускает
`round-trip.sh --diff-index N` и дальше следует существующим шагам анализа одного
diff'а.

## Проверка

Реализация проверяется ручными прогонами скрипта:

- запуск без параметров отдаёт первый diff в прежнем формате с новым
  `DIFF_COUNT`;
- `--diff-index 2` отдаёт второй файл из отсортированного списка;
- `--triage --batch-size 5` отдаёт первые пять diff'ов;
- `--triage --batch-size 5 --start-index 6` отдаёт diff'ы 6-10;
- при чистом round-trip скрипт сообщает, что diff'ов нет.

Полный `pnpm test` для изменения скилла не требуется: меняются документация
скилла и локальный shell-runner, а не пакеты `packages/*`.
