# Дизайн: ошибки парсинга NKDK в round-trip-yaml

## Контекст

Полный round-trip `XML -> модель -> YAML -> модель -> XML` для базы `acc` дошёл до двух независимых ошибок парсинга NKDK:

1. `?ПолеДиаграммы ДиаграммаАнализ` не распознаётся грамматикой.
2. `ВидЗанятости(1/0:a917a122-f663-4c45-8de0-fd5104007de3):` не распознаётся как поле с `DataPath`.

XML-фикстуры являются источником истины, поэтому нужно расширить язык NKDK под реальные данные, а не менять исходный XML.

## Решение

### Поле диаграммы

`ChartField` уже поддержан на уровне модели и экспортируется в NKDK как `?ПолеДиаграммы`. Ошибка возникает потому, что терминал `OTHERFIELD` содержит `ПолеДиаграммыГанта`, но не содержит обычное `ПолеДиаграммы`.

Решение: добавить `ПолеДиаграммы` в `OTHERFIELD`.

### Технический DataPath

Обычный `DataPath` в NKDK остаётся прежним:

```nkdk
Должность(Запись.Должность):
```

Дополнительно язык должен принять технический путь платформы в формате:

```nkdk
ВидЗанятости(1/0:a917a122-f663-4c45-8de0-fd5104007de3):
```

Решение: добавить отдельный терминал для такого формата, например `RAW_DATA_PATH`, с регулярным выражением для `число/число:uuid`:

```regexp
[0-9]+\/[0-9]+:[a-fA-F0-9-]+
```

Этот вариант разрешается только внутри скобок в `NameAndDataPath`, рядом с существующим `DataPath`.

## Поток данных

Экспорт в NKDK уже выводит `dataPath` как есть через `formatElementNameWithDataPath`, поэтому для технического пути дополнительных изменений в экспорте не требуется.

Импорт из NKDK должен:

- для обычного `DataPath` возвращать путь через точки;
- для `RAW_DATA_PATH` возвращать строку без изменений.

## Обработка ошибок

Если в скобках указан путь, который не является ни обычным `DataPath`, ни техническим `RAW_DATA_PATH`, парсер должен продолжать выдавать ошибку. Это сохраняет строгий синтаксис и не превращает `DataPath` в произвольную строку.

## Тестирование

Нужно добавить покрытие:

- парсинг NKDK с `?ПолеДиаграммы`;
- парсинг NKDK с `Имя(1/0:uuid):`;
- импорт NKDK с техническим `DataPath` в модель;
- экспорт существующего технического `DataPath` в NKDK в прежнем виде.

После изменения грамматики нужно выполнить:

```bash
pnpm --filter nkdk-language langium:generate
```

Затем проверить целевые тесты, `round-trip-yaml` для `acc`, и перед завершением прогнать полный:

```bash
pnpm test
```

## Границы

В рамках этой задачи не меняются XML-фикстуры и не вводится новый внешний синтаксис с кавычками. Изменение ограничено поддержкой уже встречающихся в реальных данных вариантов NKDK.
