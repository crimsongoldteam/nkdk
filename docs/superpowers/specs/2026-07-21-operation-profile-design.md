# Operation Profile Design

## Goal

Добавить общий механизм профилирования операций NKDK и первым подключить его к XML-import, чтобы видеть распределение времени по этапам из `.agents/architecture.md`.

## Contract

- Профилирование включает одна переменная окружения: `NKDK_PROFILE=1`.
- Совместимость со старыми переменными профилирования не требуется.
- Core выводит машинно-разбираемые строки в stderr с универсальным префиксом `[nkdk-profile-step]`.
- Каждая строка содержит `operation`, `step`, `substep`, `scope`, опционально `worker`, `items`, `bytes`, а также время и память процесса.
- Runner для конкретной операции отвечает за запуск, парсинг `[nkdk-profile-step]` и печать таблицы распределения как у validation-profile.

## Import From XML

Операция называется `import-from-xml`. Верхний этап берётся из архитектуры: `Подготовка импорта конфигурации`.

Подшаги первого включения:

- `Подготовка правил структуры XML-выгрузки`
- `Поиск XML-файлов выгрузки`
- `Формирование и распределение заданий импорта`
- `Инициализация worker`
- `Первый проход worker`
- `Обобщение индекса метаданных`
- `Обобщение фрагментов данных файла индекса конфигурации`
- `Распределение индекса метаданных`
- `Второй проход worker`
- `Обобщение списка файлов результата импорта`
- `Копирование внешних файлов XML-выгрузки`
- `Вычисление хэшей файлов проекта`
- `Формирование данных файла индекса конфигурации`
- `Запись файла индекса конфигурации`

Worker-подшаги:

- `Чтение XML`
- `Парсинг XML`
- `Построение модели`
- `Извлечение данных для индекса конфигурации`
- `Извлечение локального индекса метаданных`
- `Запись YAML`
- `Формирование worker списка файлов результата импорта`

## Output

`import-profile.mjs` печатает:

- режим `source tsx`
- XML-каталог
- YAML-каталог
- число worker
- cold/warm время
- warnings/errors
- peak RSS
- список прогонов
- таблицу распределения по шагам: общее время, главный поток, worker min/avg/max/sum, RSS процесса и worker.

## Restrictions

- Не добавлять фильтрацию операций в `NKDK_PROFILE`.
- Не менять XML-фикстуры.
- Не менять бизнес-логику import: профилирование должно быть наблюдением вокруг существующих шагов.
