# Детальное профилирование обработки файлов при валидации

## Цель

Режим `validation-profile --timing` должен объяснять полное время этапа `processFiles` без ручного анализа журналов. Обычная валидация не должна получать дополнительные сообщения и заметные накладные расходы.

## Измеряемые границы

При `NKDK_PROFILE=1` путь актуализации состояния проекта записывает следующие этапы:

1. В worker: чтение файла, вычисление хэша, сравнение с прежним хэшем.
2. Для изменённого YAML: декодирование UTF-8 и разбор YAML, локальная проверка, сбор сведений файла.
3. В worker: создание и двоичное кодирование пачек результатов.
4. В главном процессе: подготовка задания, ожидание worker, декодирование и применение полученных пачек, применение удалений.

Измерения одной пачки агрегируются внутри worker и главного процесса. Журнал не должен содержать строку на каждый файл.

## Отчёт

`validation-profile --timing` сохраняет существующий общий отчёт и добавляет отдельную таблицу `Обработка файлов Б1–Б4`. Для каждого подпункта она показывает:

- общее время проекта;
- время главного процесса;
- минимальное, среднее, максимальное и суммарное время worker;
- количество обработанных файлов;
- объём двоичных результатов, когда он применим.

В отчёте явно различаются реальное время этапа и суммарное процессорное время параллельных worker: их нельзя складывать как последовательные величины.

## Проверка

- Быстрый тест worker подтверждает наличие новых записей профиля и отсутствие записи на каждый файл.
- Тест обработчика пула подтверждает измерение ожидания worker и применения пачек.
- Тест измерительного скрипта подтверждает порядок и названия строк новой таблицы.
- После сборки выполняется `validation-profile --runs 1 --timing` на временной копии YAML-проекта с внешним пределом 115 секунд.

Функциональный результат валидации, двоичный формат состояния и протокол обычного запуска не меняются.
