# Исправление source-режима round-trip runner

## Цель

Вернуть диагностическому `round-trip-yaml` возможность запускать текущий TypeScript-код MCP без предварительной сборки и корректно находить все XML-конфигурации, включая минимальные каталоги.

## Наблюдаемые дефекты

1. Source-режим запускает `packages/mcp/src/server.ts`, но манифест строит рядом URL несуществующих `worker.js`. Реальные исходные точки worker-ов экспортируются пакетом `@nkdk/rules` как TypeScript-файлы; соседние JavaScript-файлы существуют только в собранном `dist`.
2. Общий helper распознаёт конфигурацию только при наличии хотя бы одного каталога из фиксированного списка. Поэтому каталоги с корректным `Configuration.xml`, например `clean` и `Tester_1_0_10_34_setup1c`, пропускаются.

## Решение

`createMetadataWorkerManifest` будет различать исходный и собранный контекст по URL вызывающего модуля. Для TypeScript-контекста он вернёт URL публичных экспортов `@nkdk/rules/workers/*`; для собранного JavaScript-контекста сохранит существующие соседние имена `preparedYamlProjectWorker.js`, `importFromXmlWorker.js`, `fullSyncToXmlWorker.js` и `worker.js`.

`round_trip_is_config_dir` будет считать каталог конфигурацией тогда и только тогда, когда в его корне существует обычный файл `Configuration.xml`. Список известных каталогов объектов удаляется как неполная эвристика.

## Границы

- Production-сборка MCP и имена собранных worker-файлов не меняются.
- Правила XML/YAML и содержимое конфигураций не меняются.
- Runner по-прежнему диагностирует и не исправляет round-trip расхождения.
- Символические ссылки на каталоги конфигураций продолжают поддерживаться существующим обходом дочерних каталогов.

## Проверки

- Модульный тест манифеста подтверждает URL TypeScript worker-ов для source-контекста и прежние URL JavaScript worker-ов для compiled-контекста.
- Тест helper-а подтверждает распознавание каталога только по `Configuration.xml`, включая конфигурацию без каталогов объектов, и отказ для каталога без корневого `Configuration.xml`.
- После целевых тестов выполняется исходный round-trip для `clean`, затем для конфигураций по возрастанию числа файлов до первого XML-diff.

## Критерий готовности

Source-режим MCP успешно запускает worker-ы из текущего TypeScript-кода, `clean` и `Tester_1_0_10_34_setup1c` попадают в очередь запуска, а собранный MCP сохраняет прежний договор расположения worker-файлов.
