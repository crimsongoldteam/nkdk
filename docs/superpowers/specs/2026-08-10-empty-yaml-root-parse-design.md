# Чтение пустого корневого YAML как объекта

## Контекст

Канонический YAML-экспорт не пишет `{}` для пустого корневого объекта. Такой
объект хранится нулевым файлом. Этот договор уже определён спецификациями
`2026-08-09-empty-yaml-values-design.md` и
`2026-07-01-exclude-equal-name-synonym-design.md`.

Два входа общего YAML-парсера сейчас расходятся:

- `parseWithJsYaml("")` возвращает `{}`;
- `parseDataWithJsYaml("")` возвращает `undefined`.

Full XML sync использует второй вход через `prepareYamlFiles`. Поэтому
нулевой `Свойства.yaml`, созданный штатным XML-импортом, доходит до
`syncToXML` как файл без подготовленных данных и вызывает ошибку
`Подготовленные YAML-данные отсутствуют`.

## Договор

- Нулевой или содержащий только пробельные символы YAML-документ читается как
  пустой объект `{}` обоими входами общего парсера.
- Физическое представление пустого корневого объекта не меняется: сериализатор
  продолжает писать пустой файл, а не строку `{}`.
- Явный `null` и `~` остаются `null` и не смешиваются с пустым документом.
- Синтаксическая ошибка по-прежнему возвращает диагностическую ошибку и не
  маскируется пустым объектом.
- Частные условия по роли файла, metadata-типу или имени `Свойства.yaml` не
  добавляются.
- XML-фикстуры и `rules.ts` не меняются.

## Реализация

Общий быстрый вход `parseDataWithJsYaml` должен использовать тот же результат
для пустого текста, что и `parseWithJsYaml`: `{}` без синтаксических ошибок.
Нормализация выполняется один раз на границе YAML-текста и смысловых данных.
Нижележащие слои получают объект и не обязаны различать нулевой файл и
лексическую запись `{}`.

Локальную нормализацию в full sync или `prepareYamlFiles` не добавляем: она
дублировала бы договор парсера и оставила бы другие потребители быстрого входа
с прежним расхождением.

## Проверки

- Модульный тест общего парсера подтверждает, что `parseMetadataYamlData("")`
  возвращает `{}` без ошибок.
- Тот же тест закрепляет отличие пустого документа от явного `null`.
- Сквозной тест full XML sync использует нулевой `Свойства.yaml` и подтверждает,
  что подготовка задания не выдаёт `Подготовленные YAML-данные отсутствуют` и
  формирует XML владельца.
- Существующие тесты сериализатора продолжают подтверждать, что пустой корневой
  объект записывается нулевым файлом.

## Критерий готовности

XML → YAML может создать пустой `Свойства.yaml`, после чего YAML → XML принимает
его как пустой объект и завершает синхронизацию без ошибки отсутствующих
подготовленных данных. На диске `{}` не появляется, а явный `null` сохраняет
отдельный смысл.
