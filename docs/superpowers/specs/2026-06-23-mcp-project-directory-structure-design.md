# MCP-сервис структуры каталогов metadata-проекта

## Цель

Добавить MCP tool, который отвечает агенту, какие файлы и подкаталоги допустимы
в выбранном каталоге NKDK YAML-проекта.

Сервис нужен как навигационный справочник структуры: агент передаёт корень
проекта и каталог внутри него, а получает допустимую подструктуру от этой точки.
Первая версия не анализирует фактическое содержимое проекта, но оставляет место
для будущей проверки существующих файлов.

## Сценарии

Основные сценарии:

- запросить структуру корня проекта;
- запросить структуру каталога вида metadata, например `Справочник`;
- запросить структуру каталога конкретного объекта, например
  `Справочник/Товары`;
- запросить структуру каталога форм объекта, например
  `Справочник/Товары/Формы`;
- запросить структуру каталога конкретной формы, например
  `Справочник/Товары/Формы/ФормаЭлемента`;
- запросить структуру виртуального каталога, которого ещё нет на диске, если
  путь соответствует правилам metadata-проекта.

## Источник структуры

Новый сервис должен опираться на `packages/core/metadata/project`, а не на
`metadata/validation`.

Используемые источники:

- `metadataProjectSpecs` и `configurationMetadataProjectSpec` — список
  верхнеуровневых видов metadata и корневой конфигурации;
- `classifyMetadataProjectPath` — классификация виртуальных YAML-путей;
- `describeMetadataRuleResources` — описание ресурсов конкретного
  `MetadataItemRule`: YAML, XML, внешние файлы и динамические обработчики.

`metadata/validation/projectFiles.ts` остаётся потребителем общего слоя
`metadata/project` и не становится зависимостью нового сервиса.

## Архитектура

В `@nakidka/core` добавить функцию:

```ts
describeMetadataProjectDirectoryStructure(params: {
  projectDir: string
  directoryPath?: string
  depth?: number
}): MetadataProjectDirectoryStructure
```

Функция:

1. Нормализует `directoryPath` относительно `projectDir`.
2. Проверяет, что путь не выходит за пределы `projectDir`.
3. Принимает существующие и виртуальные каталоги.
4. Определяет структурную позицию каталога по правилам `metadata/project`.
5. Возвращает дерево допустимых дочерних элементов.

MCP-пакет добавляет tool `nkdk.describe_project_structure`, который вызывает
core-функцию через `coreApi` и возвращает стабильный JSON.

## Договор MCP tool

Вход:

```ts
{
  projectDir: string
  directoryPath?: string
  depth?: number
}
```

Правила входа:

- `projectDir` обязателен;
- пустой или отсутствующий `directoryPath` означает корень проекта;
- `directoryPath` может указывать на существующий или виртуальный каталог;
- `depth`, если указан, должен быть положительным целым числом;
- если `depth` не указан, возвращается вся допустимая подструктура от выбранного
  каталога.

Выход:

```ts
{
  ok: true
  projectDir: string
  directoryPath: string
  depth: number | null
  node: MetadataProjectStructureNode
}
```

`depth: null` означает, что глубина не ограничивалась входным параметром.

Узел дерева:

```ts
interface MetadataProjectStructureNode {
  name: string
  kind: "directory" | "file"
  pathTemplate: string
  role: string
  required: boolean
  repeatable: boolean
  description: string
  children?: MetadataProjectStructureNode[]
}
```

`pathTemplate` использует реальные имена для фиксированных файлов и каталогов,
а для повторяемых частей — шаблоны:

- `<ВидОбъекта>`;
- `<ИмяОбъекта>`;
- `<ИмяФормы>`;
- `<ИмяПодсистемы>`.

## Ожидаемая структура

Корень проекта содержит:

- файл `Конфигурация.yaml`;
- каталоги верхнеуровневых metadata из `metadataProjectSpecs`, например
  `Справочник`, `Документ`, `Перечисление`, `Подсистема` и другие.

Каталог вида metadata содержит повторяемые каталоги объектов:

```text
Справочник/
  <ИмяОбъекта>/
```

Каталог объекта содержит:

```text
<ВидОбъекта>/<ИмяОбъекта>/
  Свойства.yaml
  Формы/
```

`Формы` содержит повторяемые каталоги форм:

```text
Формы/
  <ИмяФормы>/
```

Каталог формы содержит:

```text
<ИмяФормы>/
  Форма.yaml
```

Для `Подсистема` дополнительно поддерживается вложенность:

```text
Подсистема/<ИмяПодсистемы>/
  Свойства.yaml
  Подсистемы/
    <ИмяПодсистемы>/
```

## Глубина

Если `depth` указан, он ограничивает количество уровней дочерних элементов.
`depth: 1` возвращает только непосредственных детей выбранного каталога.

Если `depth` не указан, сервис возвращает всю допустимую подструктуру от
выбранного каталога. Для повторяемых участков дерево должно останавливаться на
шаблонных узлах и не разворачивать бесконечную рекурсию. Например, вложенные
подсистемы показываются через один повторяемый шаблон `Подсистемы/<ИмяПодсистемы>`.

## Ошибки

MCP tool возвращает структурированные ошибки:

- `not_found`, если `projectDir` не существует или не является каталогом;
- `invalid_arguments`, если `directoryPath` выходит за пределы `projectDir`;
- `invalid_arguments`, если виртуальный каталог не соответствует допустимой
  позиции структуры;
- `invalid_arguments`, если `depth` меньше `1` или не является целым числом;
- `core_error` для непредвиденных ошибок core-слоя.

## Границы первой версии

Входит:

- структура корня;
- структура верхнеуровневых видов metadata;
- структура конкретного объекта;
- структура форм;
- вложенные подсистемы;
- виртуальные каталоги;
- ограничение глубины.

Не входит:

- сравнение с фактическими файлами проекта;
- отметки `exists` и `missing`;
- рекомендации по созданию файлов;
- редактирование проекта;
- обход XML-каталога;
- полное разворачивание внешних файлов и динамических ресурсов в дерево, если
  их нельзя надёжно вывести без чтения модели.

## Проверки

Нужны тесты core-функции:

- корень возвращает `Конфигурация.yaml` и каталоги из `metadataProjectSpecs`;
- каталог вида metadata возвращает шаблон `<ИмяОбъекта>`;
- каталог объекта возвращает `Свойства.yaml` и `Формы`;
- каталог формы возвращает `Форма.yaml`;
- вложенная подсистема возвращает `Свойства.yaml` и `Подсистемы`;
- виртуальный путь работает без существующего каталога на диске;
- выход за пределы `projectDir` отклоняется;
- `depth: 1` ограничивает дерево первым уровнем.

Нужны тесты MCP:

- договор входа и выхода `nkdk.describe_project_structure`;
- преобразование ошибок core-слоя в `invalid_arguments`, `not_found` и
  `core_error`;
- регистрация нового tool вместе с существующими MCP tools.
