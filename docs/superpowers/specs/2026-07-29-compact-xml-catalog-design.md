# Компактная копия XML-каталога

## Цель

Добавить репозиторный skill, который создаёт компактную копию большого
каталога: XML-файлы сохраняются без изменений, а остальные файлы сохраняют
имена и расположение, но получают нулевую длину.

## Интерфейс

Skill располагается в `.agents/skills/compact-xml-catalog`.

Основная команда:

```text
node .agents/skills/compact-xml-catalog/compact-xml-catalog.mjs <input> <output>
```

Пример:

```powershell
node .agents/skills/compact-xml-catalog/compact-xml-catalog.mjs `
  C:\git\round-trip\cf\erp `
  C:\git\round-trip-compact\cf\erp
```

Оба пути обязательны. Относительные пути разрешены и вычисляются от текущего
рабочего каталога.

## Обработка каталога

Перед изменением файлов скрипт проверяет, что:

- входной каталог существует и является каталогом;
- входной и выходной пути различаются;
- выходной каталог не находится внутри входного;
- входной каталог не находится внутри выходного.

После успешной проверки скрипт полностью удаляет выходной каталог, создаёт его
заново и рекурсивно обходит входной каталог:

- каталоги воспроизводятся в выходном дереве;
- файлы с именем `ConfigDumpInfo.xml` без учёта регистра и на любом уровне
  полностью исключаются из выходного дерева;
- файлы с именем `Template.xml` без учёта регистра и на любом уровне создаются
  с нулевой длиной;
- обычные файлы с расширением `.xml` без учёта регистра копируются
  байт-в-байт;
- остальные обычные файлы создаются с нулевой длиной;
- символические ссылки и другие специальные элементы считаются ошибкой.

Перед удалением выходного каталога обход входного дерева проверяет отсутствие
неподдерживаемых элементов. Это исключает частичное уничтожение ранее
созданного результата из-за заранее обнаружимой ошибки.

Операция предполагает, что входное дерево и родительские каталоги входа и
выхода не изменяются параллельно другим процессом. Межпроцессная блокировка
файловой системы не входит в границы сервисного скрипта.

## Результат и ошибки

При успехе команда завершается с кодом `0` и выводит:

- абсолютные входной и выходной пути;
- число скопированных XML-файлов;
- число обнулённых файлов;
- число исключённых файлов;
- число созданных каталогов;
- исходный и итоговый объём файлов в байтах.

Ошибки проверки или файловой системы выводятся в `stderr`; команда завершается
с ненулевым кодом. Если ошибка возникла после начала записи, частично созданный
выходной каталог не маскируется как успешный результат.

## Структура skill

- `SKILL.md` — условия применения, команда запуска и ожидаемый отчёт;
- `compact-xml-catalog.mjs` — файловая операция и интерфейс командной строки;
- `compact-xml-catalog.test.mjs` — тесты через встроенный `node:test`.

Дополнительные зависимости не добавляются.

## Проверка

Автоматические тесты создают временные деревья и проверяют:

- неизменность содержимого `.xml` и `.XML`;
- исключение корневых и вложенных `ConfigDumpInfo.xml`;
- обнуление корневых и вложенных `Template.xml`;
- нулевую длину файлов других типов;
- сохранение вложенной структуры и пустых каталогов;
- полное удаление лишних файлов из существующего выходного каталога;
- отказ для отсутствующего входа, одинаковых путей и вложенности входа и
  выхода в любом направлении;
- отказ при символической ссылке, если среда позволяет её создать;
- корректность итоговой статистики.

После узких тестов запускается полный `pnpm test` из корня репозитория.
