# String object metadataTarget YAML

## Контекст

Валидация ERP YAML показывает группу ошибок, где строковое поле ссылается на объект метаданных через внутренний model-root. Самый заметный пример:

```yaml
Нумератор: DocumentNumerator.СчетаФактурыВыданные
```

JSON Schema ожидает YAML-представление корня:

```yaml
Нумератор: НумераторДокументов.СчетаФактурыВыданные
```

Правило документа уже описывает ссылку корректно:

```ts
metadataTarget: { kind: "object", roots: ["DocumentNumerator"] }
```

Проблема находится не в `rules.ts`, а в общем переходнике строковых metadataTarget: он применяет YAML-преобразование только для `kind: "member"` и пропускает `kind: "object"`.

## Цель

Подключить существующий механизм `parseMetadataTargetFromYAML` / `formatMetadataTargetToYAML` для строковых свойств с `metadataTarget.kind: "object"`.

После изменения одиночные строковые ссылки на объект метаданных должны:

- храниться в модели во внутреннем виде, например `DocumentNumerator.НумераторПоУмолчанию`;
- экспортироваться в YAML с русским корнем, например `НумераторДокументов.НумераторПоУмолчанию`;
- импортироваться из YAML обратно во внутренний вид;
- отклонять неподдержанные или неразрешённые корни теми же ошибками metadataTarget.

## Границы

Входит в задачу:

- расширить поддержку `metadataTargetString.ts` с `kind: "member"` до `kind: "member" | "object"`;
- покрыть общий путь тестами на строковое свойство с объектной целью;
- обновить YAML-фикстуру `MetadataDocument.withNumerator`, чтобы `Нумератор` использовал `НумераторДокументов.*`;
- проверить, что экспорт документа больше не генерирует `DocumentNumerator.*` в YAML.

Не входит в задачу:

- менять существующие XML-фикстуры;
- добавлять новые правила fromXML/toXML/fromYAML/toYAML;
- менять формат модели metadata: внутри остаются английские model-root;
- решать другие группы ошибок `строка не соответствует шаблону`, например `ПутьКДанным`.

## Архитектура

Существующий общий форматтер metadataTarget уже поддерживает объектные цели:

- `parseMetadataTargetFromYAML` переводит YAML-root в model-root;
- `formatMetadataTargetToYAML` переводит model-root в YAML-root;
- JSON Schema для `kind: "object"` строится на YAML-именах корней.

Нужно убрать локальное ограничение строкового переходника, которое сейчас считает поддержанными только `member`-цели. После изменения `exportStringMetadataTargetToYAML` и `importStringMetadataTargetFromYAML` должны вызывать общий форматтер/парсер для `object` так же, как уже делают для `member`.

## Поток данных

Экспорт:

1. `MetadataDocument.numerator` содержит `DocumentNumerator.НумераторПоУмолчанию`.
2. Правило поля даёт `metadataTarget.kind: "object"` и `roots: ["DocumentNumerator"]`.
3. Строковый переходник вызывает `formatMetadataTargetToYAML`.
4. YAML получает `НумераторДокументов.НумераторПоУмолчанию`.

Импорт:

1. YAML содержит `НумераторДокументов.НумераторПоУмолчанию`.
2. Строковый переходник вызывает `parseMetadataTargetFromYAML`.
3. Модель получает `DocumentNumerator.НумераторПоУмолчанию`.

## Ошибки

Английский root в YAML не нужно легализовать. Если пользователь вручную укажет `DocumentNumerator.X`, импорт должен считать это неизвестным YAML-корнем и вернуть ошибку общего metadataTarget-парсера.

Если поле ограничено конкретными `roots`, например `["DocumentNumerator"]`, то YAML с другим допустимым корнем метаданных должен отклоняться как `disallowed-root`.

## Тестирование

Нужны тесты на двух уровнях.

Общий уровень `metadataTargetString.test.ts`:

- экспорт `DocumentNumerator.НумераторПоУмолчанию` в `НумераторДокументов.НумераторПоУмолчанию`;
- импорт `НумераторДокументов.НумераторПоУмолчанию` в `DocumentNumerator.НумераторПоУмолчанию`;
- отказ для неподдержанного YAML-root;
- отказ для разрешённого YAML-root, который не входит в `roots`.

Уровень документа:

- обновить `withNumeratorYAML`, чтобы `Нумератор` был `НумераторДокументов.НумераторПоУмолчанию`;
- существующие `fromYAML` и `toYAML` проверки документа должны подтвердить round-trip через fixture.

Итоговая проверка:

- точечные тесты для `metadataTargetString` и `MetadataDocument`;
- полный `pnpm test` перед завершением реализации;
- после импорта ERP в YAML повторная валидация должна убрать 28 ошибок `Нумератор: DocumentNumerator.*`.

## Риски

Изменение затрагивает все строковые свойства с `metadataTarget.kind: "object"`, а не только `Нумератор`. Это ожидаемо: такие поля сейчас находятся в том же слепом участке. Риск снижается общими тестами на `roots` и сохранением прежнего поведения обычных строк без `metadataTarget`.

Специальные типы `Picture`, `Color`, `Font`, `Border` уже используют свои обработчики и не требуют изменений.
