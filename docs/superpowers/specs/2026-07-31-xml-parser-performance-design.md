# Ускорение парсинга XML

## Контекст

`importContentFromXML` сейчас выполняет два последовательных преобразования:

1. `fast-xml-parser` с `preserveOrder: true` строит промежуточное упорядоченное дерево;
2. локальный `compress` перестраивает его в объект NKDK и добавляет неперечисляемый
   `Symbol.for("metadata").childOrder`.

Предварительные замеры показали два резерва:

- `jPath: false` сокращает медиану времени на 5000 маленьких XML примерно с
  1071 до 871 мс без изменения разобранного дерева;
- событийный проход `saxes` без NKDK-сборщика быстрее построения упорядоченного дерева,
  поэтому имеет смысл проверить однопроходную сборку итогового объекта.

Проект недавно отказался от патчей `fast-xml-parser`, поэтому новый эксперимент
не должен возвращать патчи или форк зависимости.

## Цели

1. Независимо выпустить безопасную настройку `jPath: false` для текущего
   `fast-xml-parser`.
2. Создать изолированный прототип парсера на `saxes`, который сразу строит
   существующее представление XML NKDK без промежуточного упорядоченного дерева и
   отдельного `compress`.
3. Проверить эквивалентность, время выполнения и peak RSS на малых и крупных XML.

## Вне границ

- автоматическая замена рабочего парсера прототипом;
- изменение публичного договора `importContentFromXML`;
- изменение XML-фикстур;
- нормализация сообщений об ошибках `saxes` под `fast-xml-parser`;
- оптимизация остальных стадий XML-import.

## Архитектура

### Безопасная оптимизация рабочего парсера

В настройки `XMLParser` в `packages/core/xml/import/importer.ts` добавляется
`jPath: false`. Текущие обработчики не используют строковый путь, а локальный
`compress` вычисляет собственный путь независимо от этой настройки.

Изменение выпускается независимо от результата прототипа.

### Изолированный прототип

Прототип размещается в
`packages/core/xml/import/experimental/saxesImporter.ts`, не экспортируется из
`@nkdk/core` и не вызывается рабочим кодом. `saxes` добавляется прямой
зависимостью `@nkdk/core`.

`saxes` отвечает за XML-синтаксис, entity, CDATA, XML PI и атрибуты.
NKDK-сборщик подписывается на события и хранит только стек открытых элементов.
Состояние одного элемента содержит:

- имя элемента и атрибуты;
- накопленный текст;
- уже завершённые дочерние значения;
- счётчики одноимённых детей;
- порядок детей для `childOrder`;
- признак ordered-содержимого `ChildItems`.

При закрытии элемента сборщик формирует окончательное значение и сразу добавляет
его родителю. Полного промежуточного дерева событий не создаётся.

## Договор результата

Прототип должен глубоко совпадать с текущим `importContentFromXML`, включая
неперечисляемые свойства и следующие случаи:

- XML declaration представляется ключом `?xml`, атрибуты имеют префикс `_`;
- namespace-префиксы имён сохраняются;
- entity декодируются, соседние text и CDATA объединяются;
- пробелы текста не обрезаются;
- комментарии игнорируются;
- единственный текстовый узел сворачивается в строку;
- повторяющиеся теги превращаются в массив после второго значения;
- содержимое `ChildItems` остаётся ordered-массивом одноимённых записей;
- пустой элемент становится `undefined` либо `{}` при атрибутах или
  `preserveEmptyElements: true`;
- `_xsi:nil` удаляется по умолчанию и сохраняется при
  `preserveXsiNil: true`;
- обычные объекты получают неперечисляемый
  `Symbol.for("metadata").childOrder` с парами `{ key, index }`.

Некорректный XML должен завершать прототип ошибкой. Совпадение текста ошибки с
`fast-xml-parser` не требуется, пока прототип не используется рабочим кодом.

## Проверка корректности

Существующие проверки договора `importContentFromXML` расширяются так, чтобы
одни и те же случаи выполнялись для рабочего парсера и прототипа. Новые случаи
добавляются только для ещё не защищённых границ договора: XML declaration,
смешанный порядок разных тегов, `ChildItems` и объединение text с CDATA.

Отдельный сценарий сравнения:

1. проверяет все XML-фикстуры репозитория;
2. принимает внешний XML-каталог и выбирает из него детерминированную выборку
   5000 маленьких файлов;
3. принимает отдельные крупные XML;
4. сравнивает перечисляемые данные глубоким равенством, а `childOrder` читает
   через `Symbol.for("metadata")` и сравнивает отдельно на каждом пути;
5. при первом расхождении сообщает файл и путь значения.

Существующие XML-фикстуры не изменяются.

## Измерение производительности

Рабочий парсер с `jPath: false` является базовой линией. Каждый отдельный прогон
запускается в новом процессе, чтобы peak RSS и сборка мусора одного варианта не
влияли на другой. Для каждого набора выполняются три прогона; сравниваются
медиана времени и медиана peak RSS процесса.

Наборы:

- все XML-фикстуры репозитория;
- 5000 детерминированно выбранных маленьких XML из переданного каталога;
- один или несколько крупных XML, включая `Rights.xml` при его наличии.

Прототип считается перспективным при глубокой эквивалентности, устойчивом
выигрыше времени и снижении peak RSS. Минимальный процент ускорения заранее не
задаётся. Результат измерения сам по себе не переключает рабочий код.

## Последовательность результата

1. Добавить и проверить `jPath: false` как самостоятельную оптимизацию.
2. Добавить прямую зависимость `saxes` и изолированный сборщик.
3. Защитить общий договор обоих парсеров.
4. Добавить воспроизводимый сценарий сравнения.
5. Зафиксировать результаты и отдельно решить, нужен ли следующий дизайн для
   замены рабочего парсера.
