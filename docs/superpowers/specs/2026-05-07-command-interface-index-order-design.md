# CommandInterface: временное сохранение порядка Item

## Контекст

Short round-trip для `Catalogs/Валюты/Forms/ФормаСписка/Ext/Form.xml` показал перестановку двух элементов `CommandInterface.NavigationPanel.Item`.

В исходном XML первый элемент не содержит `<Index>`, второй содержит `<Index>1</Index>`. Текущий импорт сортирует элементы по выражению `(Index ?? 0)`, поэтому элемент без `Index` получает сортировочный ключ `0` и может поменяться местами с соседними элементами. После обратного экспорта порядок XML отличается от исходного.

Ранее уже было принято решение хранить `Index` как явное поле модели, а не вычислять его из позиции массива. Однако вопрос доменной семантики `Index` не был закрыт: пока неизвестно, является ли он абсолютной позицией, вставочным рангом внутри командной группы, следом пользовательской настройки или только дополнительным свойством элемента.

## Решение

В этом шаге принимаем узкую временную меру: `fromXML` для `CommandInterface` должен сохранять физический порядок `<Item>` из XML и не сортировать элементы по `Index`.

Правила поведения:

- `fromXML` читает `NavigationPanel.Item` и `CommandBar.Item` в том порядке, в котором они идут в XML.
- `fromXML` по-прежнему сохраняет `<Index>` в `item.index`, если тег присутствует.
- `toXML` остаётся без изменений: порядок массива определяет порядок XML, `item.index` экспортируется в `<Index>` только при наличии значения.
- YAML-импорт и YAML-экспорт не меняются.

Такой подход минимизирует round-trip шум и не делает новых доменных предположений о смысле `Index`.

## Архитектурная оговорка

Это не окончательное решение по `Index`. Мы сознательно выбираем XML-порядок как временный источник истины, потому что он уже присутствует в исходном файле и позволяет сохранить round-trip без дополнительных догадок.

После закрытия текущего расхождения нужно отдельно исследовать реальные XML из нескольких конфигураций и поведение платформы 1С:

- когда платформа пишет `<Index>`, а когда пропускает его;
- относится ли `Index` ко всему списку элементов или только к группе команд;
- может ли `Index` задавать вставку относительно стандартных команд, которых нет в XML;
- должен ли порядок модели совпадать с XML-порядком или с вычисленным пользовательским порядком интерфейса.

До такого исследования код не должен вычислять порядок `CommandInterface.Item` из `Index`.

## Reproducer

Добавляем узкий reproducer в `packages/core/metadata/forms/commonObjects/commandInterface`.

Новая XML-фикстура содержит `CommandInterface.NavigationPanel` с двумя элементами:

- первый элемент без `<Index>`;
- второй элемент с `<Index>1</Index>`;
- порядок элементов в XML должен сохраниться в TS-модели.

Новая TS-фикстура описывает ожидаемый `CommandInterface`: массив `NavigationPanel` идёт в XML-порядке, у первого элемента нет `index`, у второго есть `index: 1`.

Тесты:

- `fromXML.test.ts` добавляет `it("import indexedItemOrderSwap")`;
- `toXML.test.ts` добавляет `it("export indexedItemOrderSwap")`.

Ожидаемое состояние reproducer'а до исправления:

- `import indexedItemOrderSwap` красный из-за перестановки элементов в `fromXML`;
- `export indexedItemOrderSwap` зелёный после калибровки XML-фикстуры, потому что `toXML` уже сохраняет порядок массива и явный `index`.

## Границы

В этом шаге не меняем типы `CommandInterfaceItem`, YAML-представление и правила экспорта `Index`: они уже покрыты предыдущим изменением. Не добавляем общий механизм сортировки коллекций и не пытаемся вывести окончательную семантику `Index`.

Исправление должно быть локальным для `packages/core/metadata/forms/commonObjects/commandInterface/fromXML.ts`.
