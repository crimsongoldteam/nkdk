# Пустые значения YAML без `{}`

## Цель

При экспорте XML в YAML не выводить пустые отображения `{}`. Пустой объект и
отсутствующее YAML-значение считаются одним состоянием и записываются без
лексического значения.

Примеры канонического вывода:

```yaml
Значения:
  МеждуОписаниямиЗатрат:
  МеждуСтатьямиРасходов:
```

Пустой корневой объект записывается как пустой файл. Пустой объект внутри
последовательности записывается как пустой элемент `-`.

## Договор данных

- При уже выполняемом обходе сериализация сохраняет пустые объекты в смысловых
  данных и передаёт их `js-yaml` в исходной форме.
- `{}` и пустое значение намеренно не различаются после YAML round-trip.
- Явный `null`, пустая строка `""`, непустые объекты и массивы сохраняют прежний
  смысл.
- Текст, сформированный штатным сериализатором, не содержит `{}`.
- Чтение пустых значений должно оставаться допустимым во всех местах, где ранее
  допускался пустой объект.

## Реализация

Изменение выполняется в общем YAML-слое, а не в правилах отдельных объектов
метаданных. Уже существующий обход `prepareForDump` использует полученный через
`Object.entries` список и без дополнительного рекурсивного прохода распознаёт
объект без собственных перечислимых полей. Для `dumpValue` и смысловых `data`
сохраняется `{}`.

После `js-yaml` один линейный проход по сформированному тексту заменяет только
канонические формы, которые выводит текущая конфигурация dumper:

- корневой `{}` — на пустой документ;
- `Поле: {}` — на `Поле:`;
- `- {}` — на `-`.

Пустые объекты не добавляются в механизм уникальных маркеров `undefined`, чтобы
не получить повторные проходы по всему документу при большом числе пустых
значений.

Существующий нормализующий проход YAML-парсера преобразует неявное пустое
значение в `{}`. Поэтому проверка схемы и обратное преобразование получают ту же
форму, что до удаления фигурных скобок; частные условия по типам метаданных не
добавляются.

## Проверки

- Модульный тест сериализатора закрепляет корневой, вложенный и массивный случаи.
- Тест подтверждает сохранение различия с явным `null` и пустой строкой.
- Интеграционная проверка импорта перечисления закрепляет вывод пустых именованных
  элементов без `{}`.
- Обратное преобразование подтверждает, что пустые значения восстанавливают тот
  же XML, что ранее восстанавливался из `{}`.
- Проверка производительности подтверждает отсутствие дополнительного обхода
  входного дерева и линейную сложность нормализации текста.
- После целевых тестов выполняются `pnpm type-check`, `pnpm test` и проверка новых
  дублей относительно исходного коммита.

## Границы

XML-фикстуры и правила `rules.ts` не изменяются. Формат `null` и пустых строк не
меняется. Частные обходы сериализации для элемента стиля или перечисления не
добавляются. JSON Schema не меняется: YAML-парсер восстанавливает пустое тело
элемента как `{}` до проверки схемы.
