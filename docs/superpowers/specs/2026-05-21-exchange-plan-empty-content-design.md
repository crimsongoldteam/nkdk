# Exchange Plan Empty Content Design

## Контекст

`round-trip-yaml` показывает потерю нескольких файлов `ExchangePlans/<План>/Ext/Content.xml`.
Эти файлы не являются непрозрачными внешними файлами: `ExchangePlanContent` уже разбирается
в YAML как свойство `Состав`.

Проверка потерянных файлов показала, что они пустые по содержанию:
`<ExchangePlanContent ... version="2.20"/>`.
Это означает, что файл состава есть, но список элементов состава пустой.

## Решение

Пустой `Ext/Content.xml` должен сохраняться в YAML как явное пустое значение:

```yaml
Состав: []
```

Контракт:

- если `Ext/Content.xml` существует и не содержит `Item`, fromXML пишет `Состав: []`;
- если `Ext/Content.xml` отсутствует, `Состав` не добавляется автоматически;
- если в YAML есть `Состав: []`, toXML восстанавливает пустой `Ext/Content.xml`;
- если в YAML нет `Состав`, toXML не создает `Ext/Content.xml` без значения или reference-правила.

## Тестирование

Нужно добавить проверку общего `ExchangePlanContent` для пустого XML:

- fromXML импортирует пустой список;
- toYAML экспортирует `[]`;
- fromYAML импортирует `[]`;
- toXML восстанавливает пустой контейнер `ExchangePlanContent`.

Sync-фикстура `MetadataExchangePlan` должна закрепить пустой `Content.xml` на уровне объекта
или отдельный объект/случай, если текущая фикстура уже покрывает непустой состав.

## Вне Границ

Этот пункт не переводит `Content.xml` в непрозрачный внешний файл и не меняет формат непустого
состава. Непустой `Content.xml` продолжает разбираться в YAML как список элементов `Состав`.
