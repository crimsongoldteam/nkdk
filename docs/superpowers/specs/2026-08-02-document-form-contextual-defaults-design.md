# Контекстные XML-defaults формы документа

## Контекст

Полный YAML round-trip конфигурации `cf/doc` без reference удаляет свойства
формы документа в 33 XML-файлах:

- `AutoTime=CurrentOrLast` — в 33 формах;
- `UsePostingMode=Auto` — в 31 форме;
- `RepostOnWrite=true` — в 31 форме.

Во всех 33 случаях основной реквизит формы имеет тип `DocumentObject`. Во всех
остальных формах конфигурации такой основной реквизит отсутствует и указанные
XML-defaults не встречаются. Владелец формы сам по себе недостаточен: например,
форма списка документа имеет основной реквизит `DynamicList` и не должна
получать свойства объектной формы документа.

Два отличающихся значения `UsePostingMode=Regular` находятся в формах
документов `ЕжедневныйОтчет` и `ЕженедельныйОтчет`. Два значения
`RepostOnWrite=false` находятся в формах документов
`АктОбУничтоженииПерсональныхДанных` и `ИсходящееПисьмо`.

Конфигуратор использует `Auto` как default `UsePostingMode` и `true` как
default `RepostOnWrite`. Действующий YAML-договор уже считает
`CurrentOrLast`, `Auto` и `true` неявными значениями, поэтому проблема
возникает только при восстановлении XML из компактного YAML.

## Цель

Восстанавливать обязательные XML-defaults объектной формы документа без
reference XML и не создавать эти теги у остальных форм. Явные значения,
отличающиеся от defaults, должны сохраняться в YAML и XML.

## Договор

Применимость трёх свойств определяется основным реквизитом формы, а не
владельцем формы. Подход повторяет действующий договор
`UseForFoldersAndItems` для основного реквизита `CatalogObject` или
`ChartOfCharacteristicTypesObject`.

Если YAML формы содержит реквизит с `ОсновнойРеквизит: Истина`, чей
нормализованный тип имеет kind `ДокументОбъект`, отсутствующие YAML-ключи
восстанавливаются в XML так:

| YAML-поле | XML-тег | Неявное значение YAML | XML-default |
|---|---|---|---|
| `АвтоВремя` | `AutoTime` | `CurrentOrLast` | `CurrentOrLast` |
| `РежимПроведения` | `UsePostingMode` | `Auto` | `Auto` |
| `ПерепроводитьПриЗаписи` | `RepostOnWrite` | `true` | `true` |

Если основного реквизита `ДокументОбъект` нет:

- отсутствующие YAML-ключи не создают XML-теги;
- явное присутствие любого из трёх YAML-полей является ошибкой проверки.

Значения `Regular`, `false` и остальные значения перечислений, отличающиеся
от defaults, остаются явными в YAML и экспортируются без изменения.

## Архитектура

Существующую локальную проверку основного реквизита для
`UseForFoldersAndItems` следует обобщить внутри модуля управляемой формы. Она:

1. читает `ОсновнойРеквизит` из сырого YAML реквизитов формы;
2. получает нормализованные kinds типа из уже построенного
   `formDataPathIndex`;
3. отвечает, входит ли kind основного реквизита в переданный набор.

Правила трёх документных свойств используют эту проверку при YAML → XML и
задают соответствующий `defaultValueXML`. Проверка управляемой формы использует
тот же локальный договор применимости и выдаёт диагностику по пути
недопустимого YAML-поля.

Знание о `ДокументОбъект` остаётся в модуле формы. Общие слои
`orchestration`, `validation` и `project`, общие типы правил и параметры
построителей не изменяются. Владелец формы и reference XML не участвуют.

## Поток данных

### XML → YAML

1. `CurrentOrLast`, `Auto` и `true` исключаются как неявные YAML-значения.
2. Отличающиеся значения сохраняются явно.
3. Индекс формы сохраняет нормализованный тип основного реквизита.

### YAML → XML

1. Локальная проверка находит основной реквизит формы.
2. Для kind `ДокументОбъект` правила восстанавливают отсутствующие defaults.
3. Для другого kind или отсутствующего основного реквизита теги не создаются.
4. Явные допустимые значения экспортируются вместо defaults.

## Проверка ошибок

Если `АвтоВремя`, `РежимПроведения` или `ПерепроводитьПриЗаписи` указаны в
форме без основного реквизита `ДокументОбъект`, проверка YAML возвращает ошибку
на соответствующем поле. Ошибка не исправляется молчаливым удалением свойства
и не зависит от каталога владельца формы.

## Тестирование

Существующие XML-фикстуры не изменяются. Следует расширить существующие
проверки договора формы, не создавая дублирующие тесты внутреннего устройства:

1. Форма с основным реквизитом `ДокументОбъект` и без трёх YAML-полей получает
   `CurrentOrLast`, `Auto` и `true` в XML.
2. Явные `Regular` и `false` экспортируются без замены defaults.
3. Форма с основным реквизитом `ДинамическийСписок`, другим типом или без
   основного реквизита не получает документные XML-теги.
4. Явное документное поле в такой форме отклоняется проверкой YAML.
5. Существующий договор `UseForFoldersAndItems` остаётся неизменным после
   обобщения помощника.
6. Выполняются целевые тесты, `pnpm type-check`, полный `pnpm test` и
   `pnpm duplicates`.
7. Повторный round-trip `cf/doc` устраняет группу из 33 файлов. Согласованные
   расхождения `Period`, `TopLevelParent` и `RowFilter` при оценке результата
   игнорируются.

## Вне границ

- Defaults форм отчётов и остальные группы текущего round-trip.
- Выбор документных свойств по владельцу формы.
- Изменение формата YAML или хранение признака присутствия XML-тега.
- Возврат reference XML.
- Изменение существующих XML-фикстур.
