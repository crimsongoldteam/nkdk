# Неизменяемый бюджет теста 50 мс

## Цель

В обычном `pnpm test` не должно быть ни одного теста длительностью более 50 мс. Ограничение обязательно для всех пакетов и не может быть повышено параметром командной строки или переменной окружения.

## Граница теста

Бюджет применяется к длительности отдельного `it`/`test` из JSON-отчёта Vitest:

- `duration <= 50` — допустимо;
- `duration > 50` — ошибка всего тестового запуска;
- времени на `beforeAll`, загрузку модулей и преобразование TypeScript бюджет отдельного теста не касается.

Это сохраняет быстрые и узкие проверки поведения, но не маскирует общую длительность: полный `pnpm test` по-прежнему остаётся обязательной заключительной проверкой.

## Неизменяемый лимит

Проверяющий скрипт экспортирует единственную константу `TEST_DURATION_BUDGET_MS = 50` и не принимает `--max-ms`. Не предусматриваются переменные окружения, конфигурационные файлы или параметры package script, позволяющие изменить лимит.

Скрипт принимает только путь к JSON-отчёту и необязательный список выбранных файлов:

```text
node packages/core/scripts/assert-test-durations.mjs \
  --report /private/tmp/nkdk-vitest-core.json \
  [--files-from /private/tmp/selected-tests.txt]
```

Неизвестный параметр считается ошибкой. Благодаря этому нельзя получить зелёный запуск, передав больший лимит.

## Обязательное подключение

Команда `test` каждого пакета:

1. запускает Vitest;
2. одновременно сохраняет JSON-отчёт с уникальным именем пакета;
3. запускает `assert-test-durations.mjs`;
4. возвращает код `1`, если найдено хотя бы одно превышение.

Корневой `pnpm test` рекурсивно запускает эти package scripts, поэтому та же проверка действует локально и в CI.

Отдельный policy-тест читает `packages/core/package.json`, `packages/platform/package.json` и `packages/mcp/package.json` и проверяет:

- package script `test` создаёт JSON-отчёт;
- после Vitest всегда вызывается `assert-test-durations.mjs`;
- в командах нет `--max-ms` или переменной лимита;
- каждый неинтерактивный script, содержащий `vitest run`, завершает команду тем же проверяющим скриптом; интерактивный `test:ui` в это правило не входит;
- экспортированная константа равна `50`.

## Устранение превышений

Оставшиеся задержки делятся на четыре группы.

### Смешанные сценарии

Полные XML → YAML → XML сценарии, которые одновременно проверяют discovery, преобразование, файловую систему и координацию, удаляются. Они не переносятся в e2e. Их предметное поведение остаётся в прямых тестах преобразователей и coordinator-тестах с явными результатами.

### Schema и registry initialization

Неизменяемые схемы, topology и registry snapshots создаются один раз в `beforeAll`. Отдельный тест проверяет готовый результат или вызов `Check`, а не время глобальной компиляции графа схем.

### Файловые проверки

Тесты используют минимальный объём данных, достаточный для доказательства потоковой записи. Повторные обходы дерева исходников заменяются одним неизменяемым снимком, построенным в `beforeAll`.

### Таймеры и конкурентность

`vi.waitUntil` и реальные задержки заменяются управляемыми обещаниями и освобождением microtask queue. Проверяется число одновременно начатых операций без ожидания интервала опроса.

## Проверка результата

Работа считается завершённой только при одновременном выполнении условий:

1. Полный профиль core не содержит `duration > 50`.
2. `pnpm test` проходит с включённым проверяющим скриптом.
3. Намеренно созданный тест длительностью `50.01` мс приводит к коду `1`.
4. Попытка передать `--max-ms 100` приводит к ошибке неизвестного параметра.
5. Policy-тест подтверждает обязательное подключение ограничения во всех пакетах.
