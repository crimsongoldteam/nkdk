# Contextual Namespace Prefixes Design

## Контекст

Свежий полный round-trip `cf/doc` без опоры на reference выявил 15 лексических расхождений
namespace-префиксов при неизменных URI и локальных именах типов:

- 4 значения `PredefinedItem.Type`: `d4p1` заменяется на `cfg`;
- 11 значений `XDTOValueType`: `d8p1` заменяется на `d6p1`.

YAML уже хранит смысл типа, а не его XML-псевдоним. Возвращать технический префикс в YAML,
reference или configuration index не требуется: статистика всех конфигураций `cf` показывает,
что префиксы полностью определяются положением свойства в XML.

## Установленные правила 1С

Для пользовательских XDTO-пространств имён:

- `XDTOReturningValueType` всегда использует `d6p1` — 116 из 116 найденных случаев;
- `XDTOValueType` параметра всегда использует `d8p1` — 115 из 115 найденных случаев.

Для `Type` предопределённого элемента плана видов характеристик префикс зависит от уровня
вложенности элемента:

| Уровень `PredefinedItem` | Префикс | Найдено в `cf` |
|---|---:|---:|
| корневой | `d4p1` | 1635 |
| дочерний | `d6p1` | 369 |
| третий | `d8p1` | 68 |
| четвёртый | `d10p1` | 4 |

То есть номер префикса начинается с 4 и увеличивается на 2 на каждом уровне вложенности.

## Решение

Префиксы восстанавливаются при формировании XML из структуры свойства и не становятся частью
публичной модели или YAML.

### XDTOTypeName

`exportXDTOTypeNameToXML` выбирает технический префикс по правилу свойства:

- для `xml: "XDTOReturningValueType"` — `d6p1`;
- для `xml: "XDTOValueType"` — `d8p1`;
- встроенные пространства имён продолжают использовать `xs` и `v8`.

Оба XDTO-свойства уже являются единственными потребителями `XDTOTypeName`, поэтому отдельное поле
в `PropertyRule` или новый построитель правил не нужны.

### PredefinedItem.Type

Регистрация `PredefinedItemCollection` использует существующий `mapItemOutput`. Локальный помощник
обходит уже сформированный XML элемента:

1. назначает текущему `Type/v8:Type` префикс `d4p1`;
2. рекурсивно обходит `ChildItems/Item`;
3. увеличивает номер префикса на 2 для каждого следующего уровня;
4. одновременно изменяет ключ `_xmlns:<prefix>` и префикс в `#text`.

Преобразование применяется только к типам пространства
`http://v8.1c.ru/8.1/data/enterprise/current-config`. Остальные типы и квалификаторы не меняются.

Внешний корневой вызов повторно нормализует всё поддерево, поэтому результат не зависит от того,
что вложенные коллекции были преобразованы раньше.

## Архитектурные границы

- Не добавлять XML-префикс в YAML или публичную модель.
- Не использовать reference или configuration index.
- Не добавлять поля в `BasePropertyRule`/`PropertyRule` и параметры общих построителей.
- Не добавлять частные условия в `orchestration`, `validation` или `project`.
- Не создавать новые `fromXML`/`toXML`/`fromYAML`/`toYAML`: изменить существующий
  `XDTOTypeName.toXML` и использовать зарегистрированный `mapItemOutput` предопределённых элементов.

## Проверки

- Табличный тест XDTO: встроенные `xs`/`v8`, пользовательский возвращаемый тип `d6p1`,
  пользовательский тип параметра `d8p1`.
- Тест `PredefinedItemCollection` с четырьмя уровнями элементов: `d4p1`, `d6p1`, `d8p1`, `d10p1`.
- Проверка, что namespace URI и локальное имя не изменяются.
- Целевые тесты обоих common objects, затем `pnpm type-check`, `pnpm test`, `pnpm duplicates`.
- Stryker в этой задаче не запускается.
- Итоговый round-trip `cf/doc` не должен содержать эти 15 расхождений.
