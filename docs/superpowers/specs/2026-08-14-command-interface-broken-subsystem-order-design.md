# Битые UUID в порядке подсистем CommandInterface

## Контекст

В `Ext/CommandInterface.xml` некоторых выгрузок встречаются UUID подсистем,
которых уже нет среди `Configuration/ChildObjects` и XML-файлов. Импорт не
может восстановить для них смысловой путь `Подсистема.<Имя>` и оставляет UUID,
который затем отклоняется схемой и fromYAML.

Такая форма найдена в пяти конфигурациях каталога `round-trip-compact/cf`
без `all`, в том числе в `Tester_1_0_10_34_setup1c`.

## Решение

Зарегистрировать отдельный `BrokenXMLReferenceCarrierRegistration` для
`CommandInterfaceSubsystemsOrder`. Он:

- распознаёт только канонический UUID в обычном XML-элементе `Subsystem`;
- экспортирует такой элемент в YAML как `!xml <UUID>`;
- принимает только тегированный UUID и восстанавливает исходный XML-текст;
- расширяет validation-схему только вариантом `!xml <UUID>`;
- не разрешает обычный UUID и не меняет смысловые ссылки на подсистемы.

`ВидимостьПодсистем` не меняется: её ключи уже являются непрозрачными строками
и не вызывают текущего расхождения.

## Проверка

- XML → YAML ставит `!xml` только на битый UUID в смешанном списке.
- YAML → XML восстанавливает UUID без `xsi:type`.
- Схема принимает тегированный UUID и по-прежнему отклоняет обычный.
- Round-trip `Tester_1_0_10_34_setup1c` проходит текущий блокер.
