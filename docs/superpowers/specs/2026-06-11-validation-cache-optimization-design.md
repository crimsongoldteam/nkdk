# Оптимизация памяти и повторной работы validation

## Цель

Полная validation на большом YAML-проекте не должна падать на стандартном heap Node и должна меньше тратить время на повторную работу. Первый этап не меняет состав диагностик и не вводит параллельную проверку.

## Контекст

Профиль ERP-проекта показал высокий расход памяти и заметную долю времени на YAML/TypeBox/import. Сейчас `ProjectYamlCache` держит `text` и `ParsedYaml` для всех прочитанных файлов до конца запуска. При проверке форм `ownerCache` также загружает владельцев для `ПутьКДанным` и сейчас дополнительно запускает schema validation владельца, хотя для получения полей нужна только импортированная модель.

## Решение

### Освобождение YAML

`ProjectYamlCache` остается единой точкой чтения YAML, но получает явное управление сроком жизни записей. Основной проход `validateProject` освобождает YAML текущего файла после проверки. Записи, которые нужны повторно для владельцев форм, удерживаются через отдельный механизм `retain/release`, чтобы не перечитывать часто используемые `Свойства.yaml`.

Ошибки чтения можно оставлять в кэше: они малы и предотвращают повторные обращения к отсутствующим файлам.

### Owner cache

`ownerCache` перестает выполнять schema validation владельца. Его задача для проверки `ПутьКДанным` — загрузить YAML владельца, импортировать модель и отдать rule/spec/model. Ошибки schema владельца остаются ответственностью основного прохода `validateProject`, который все равно проверяет каждый `Свойства.yaml` как отдельный файл.

Это убирает повторную TypeBox-проверку владельцев и не смешивает диагностику формы с диагностикой файла владельца.

### Object field index

Индекс полей владельца строится один раз на загруженного владельца и переиспользуется в `resolveDataPath`. Это убирает повторные вызовы `buildObjectFieldIndex(owner)` при проверке нескольких `ПутьКДанным` одной формы.

## Границы

- Не добавляем параллельную обработку файлов на этом этапе.
- Не меняем правила `ПутьКДанным`.
- Не меняем XML/YAML-контракт metadataItem.
- Не меняем формат CLI-вывода.
