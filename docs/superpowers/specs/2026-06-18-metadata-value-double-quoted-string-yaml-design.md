# MetadataValue Double-Quoted String YAML Design

## Goal

Явные строковые значения `MetadataValue` должны печататься в YAML как стандартные double-quoted scalars:

```yaml
Отбор.Код: "456"
```

Текущий вид `Отбор.Код: '"456"'` хранит кавычки как часть строкового значения и выглядит как техническая деталь внутренней эвристики. Новый формат должен быть читаемее и ближе к обычному YAML.

## Scope

Изменение применяется ко всем строковым значениям `MetadataValue`, включая `ПараметрыВыбора`, `ЗначениеЗаполнения`, значения списков выбора и другие свойства, которые используют общий обработчик `MetadataValue`.

Обычные свойства типа `string`, которые не проходят через `MetadataValue`, не должны получать новый принудительный режим кавычек.

Старый формат `'"456"'` не поддерживается как отдельный договор совместимости. После изменения актуальные YAML-фикстуры и экспорт должны перейти на новый вид.

## Architecture

Внутреннее модельное значение остаётся прежним:

```ts
{ type: "string", value: "456" }
```

Меняется YAML-представление при экспорте и сохранение сведений о стиле скаляра при импорте. Строковый обработчик `MetadataValue` должен возвращать значение, которое общий YAML-писатель распознаёт как требование напечатать строку в двойных кавычках. YAML-импорт должен помечать double-quoted scalars так, чтобы `MetadataValue` мог отличить строку `"456"` от plain scalar `456` в местах без явного `valueType`.

Это сохраняет границу ответственности: `MetadataValue` решает, что строка должна быть явной, а YAML-слой отвечает за техническое представление quoted scalar средствами библиотеки `yaml`.

## Data Flow

Экспорт:

1. XML импортирует `xs:string` в `{ type: "string", value }`.
2. `exportMetadataValueToYAML` передаёт строковое значение обработчику `MetadataValue.string`.
3. Обработчик возвращает помеченный YAML-скаляр для двойных кавычек.
4. `exportToYAML` печатает его как `"..."`, без добавления кавычек в само значение.

Импорт:

1. YAML-парсер читает документ через узлы `yaml`, а не только через потерявший стиль `parse()`.
2. Double-quoted scalar `"456"` превращается во внутреннюю помеченную строку со значением `456`.
3. `importMetadataValueFromYAML` распознаёт помеченную строку как `{ type: "string", value: "456" }`, даже если правило не передало `valueType`.
4. Plain scalar `456` продолжает импортироваться как число, когда YAML-парсер отдаёт number.

## Error Handling

Существующая строгая проверка `valueType` остаётся источником ошибок. Если правило ожидает строку, YAML-значение импортируется как строка; если правило ожидает другой тип, поведение остаётся прежним и должно падать через `assertValueType`.

Новые помеченные скаляры должны быть внутренней деталью YAML-слоя. Они не должны утекать в публичный JSON-подобный YAML-объект после импорта, кроме случаев, где `MetadataValue` сразу потребляет их для определения строкового типа.

## Testing

Точечные тесты:

- `metadataValue/toYAML`: строковое значение экспортируется в помеченный double-quoted scalar.
- `metadataValue/fromYAML`: double-quoted scalar `"456"` импортируется как строковый `MetadataValue` без `valueType`.
- `yaml/export`: помеченная строка печатается как `"456"`.
- `yaml/import`: double-quoted scalar сохраняет признак явной строки, а plain number остаётся числом.
- `ChoiceParameters/toYAML`: строковый параметр даёт YAML-значение, которое общий экспорт напечатает как `"..."`.
- `ChoiceParameters/fromYAML`: строковый параметр из `"456"` импортируется как `{ type: "string", value: "456" }`.

Интеграционная проверка:

- обновить YAML-фикстуры sync, где встречается старый вид `'"..."'` для `MetadataValue`;
- прогнать точечные тесты затронутых общих объектов;
- перед закрытием задачи прогнать `pnpm test` из корня.

## Non-Goals

- Не менять XML-фикстуры.
- Не вводить объектную YAML-форму `{ Тип, Значение }` для строк.
- Не принуждать все строки проекта печататься в кавычках.
- Не сохранять старый YAML-вид `'"456"'` как поддерживаемый пользовательский формат.
