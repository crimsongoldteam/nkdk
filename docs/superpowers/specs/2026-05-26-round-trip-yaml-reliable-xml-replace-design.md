# Более достоверный round-trip-yaml через замену XML-каталога

## Контекст

Сейчас `.agents/skills/round-trip-yaml/round-trip.sh` выполняет `nkdk sync <yaml-dir> <xml-dir>` прямо поверх исходного XML-каталога. Такой порядок показывает изменения внутри файлов, но может скрыть потерю файлов: если `import` не создал YAML для части XML, старые XML-файлы остаются в каталоге и не попадают в `git diff` как удаления.

Цель изменения - сделать диагностический результат достовернее: файл, потерянный на пути `XML -> YAML -> XML`, должен отображаться в `git diff` как удаленный файл.

## Выбранный подход

Скрипт должен экспортировать XML из YAML во временный XML-каталог, а затем заменять содержимое активного XML-каталога результатом этого экспорта. Это сохраняет текущий интерфейс `single` и `triage`, но меняет способ подготовки XML перед сбором diff.

Порядок для каждого активного XML-каталога:

1. Откатить XML-репо к `HEAD` через `git restore .`.
2. Очистить временный YAML-каталог.
3. Очистить временный XML-каталог для результата `sync`.
4. Выполнить `nkdk import <run-xml-dir> <run-yaml-dir>`.
5. Выполнить `nkdk sync <run-yaml-dir> <run-xml-temp-dir>`.
6. После успешного `sync` удалить содержимое `<run-xml-dir>`.
7. Перенести содержимое `<run-xml-temp-dir>` в `<run-xml-dir>`.
8. Собрать diff через существующий `git diff`.

## Каталоги

Временный YAML-каталог остается как сейчас: `${TMPDIR:-/tmp}/round-trip-yaml/<config>` или значение `NKDK_ROUND_TRIP_YAML_DIR`.

Для временного XML-каталога нужен отдельный служебный корень, чтобы результат `sync` не смешивался с YAML-диагностикой. Подходящий путь по умолчанию: `${TMPDIR:-/tmp}/round-trip-yaml-xml/<config>`. Он очищается перед каждым прогоном и не является пользовательским диагностическим результатом.

## Ошибки

Если падает `import`, активный XML-каталог не изменяется.

Если падает `sync` во временный XML-каталог, активный XML-каталог не изменяется.

Если падает удаление или перенос результата в активный XML-каталог, скрипт останавливается. Это уже стадия применения диагностического результата к XML-репо, поэтому продолжать нельзя.

## Вывод и совместимость

Секции `ACTIVE_XML_DIR`, `YAML_DIR`, `SELECTED_DIFF_FILE`, `SELECTED_XML_FILE_ABS`, `FULL_DIFF` и triage-вывод остаются прежними. Пользователь по-прежнему видит diff в исходном XML-репо, а YAML-каталог остается после прогона для анализа.

Документацию skill нужно обновить: вместо `nkdk sync <tmp-yaml-dir> <xml-dir>` описать `sync` во временный XML-каталог и последующую замену активного XML-каталога.

## Проверка

Минимальная проверка реализации:

1. `bash -n .agents/skills/round-trip-yaml/round-trip.sh`.
2. Пробный запуск `round-trip-yaml` в обычном режиме на доступном XML-репо.
3. Убедиться, что при diff выводятся прежние диагностические секции, а удаленные файлы теперь могут появиться как удаления в `git diff`.

Полный `pnpm test` для этого изменения не нужен: skill является диагностическим и явно запрещает полный тестовый прогон в обычном workflow.
