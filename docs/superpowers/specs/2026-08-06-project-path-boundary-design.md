# Единая граница путей проекта

## Проблема

NKDK использует два разных представления пути:

- нативный путь файловой системы, зависящий от Windows, macOS или Linux;
- переносимый путь внутри NKDK-проекта (`projectPath`), относительный к корню проекта и использующий `/`.

Переход между представлениями реализован независимо в validation, project, projectState и MCP. Проверки выхода за корень отличаются: часть кода отвергает любое имя, начинающееся с `..`, часть проверяет только родительский сегмент, а MCP не везде распознаёт абсолютный путь другой ОС. Из-за этого `projectState` вернул абсолютный путь отсутствующего объекта, а MCP отклонил весь результат validation.

## Принятое решение

В `@nkdk/core` вводится чистый модуль границы путей проекта с тремя операциями:

```ts
parseProjectPath(input, options)
projectPathFromFileSystem(projectDir, filePath, options)
resolveProjectPath(projectDir, projectPath)
```

`parseProjectPath` принимает внешнее переносимое значение, распознаёт разделители `/` и `\`, отвергает NUL, пустые сегменты, `.`/`..` и абсолютные форматы как POSIX, так и Windows, затем возвращает канонический путь с `/`.

`projectPathFromFileSystem` использует нативный `node:path` текущей ОС, проверяет принадлежность пути корню проекта и возвращает канонический относительный путь. Переход на другой диск Windows и выход через родительский каталог считаются ошибкой.

`resolveProjectPath` сначала проверяет переносимый путь, затем безопасно преобразует его в нативный путь внутри указанного корня.

Пустой путь, обозначающий корень проекта, разрешается только явным параметром. Имя сегмента вроде `..backup` остаётся допустимым.

## Границы

Модуль не обращается к файловой системе и не разрешает символьные ссылки. Защита от символьных ссылок остаётся в операциях записи, которые используют `realpath`.

Виртуальные XML-пути, шаблоны resourceTopology и удалённые пути агента Конфигуратора не переводятся на этот модуль: у них отдельные POSIX-протоколы.

MCP сохраняет последнюю защитную проверку возвращаемых `filePath`, но использует тот же переносимый контракт для входных путей.

## Исправление validation

При формировании диагностики отсутствующей ссылки `projectState` преобразует вычисленный абсолютный путь ожидаемого объекта в путь относительно корня проекта. Диагностика указывает, например, `cf/ОбщаяФорма/ВыборКонтрагентаКонтактноеЛицо/Свойства.yaml`; MCP больше не завершает всю validation ошибкой `Core вернул путь диагностики вне NKDK-проекта`.

## Проверка

Граничные тесты модуля покрывают:

- нативные и переносимые пути Windows и POSIX;
- UNC и разные диски Windows;
- абсолютные пути другой ОС во внешнем вводе;
- `../`, `..\`, `.`, NUL и пустые сегменты;
- допустимое имя `..backup`;
- явное разрешение корня проекта;
- прямое и обратное преобразование.

Регрессионный тест `projectState` проверяет относительный путь отсутствующего объекта. Интеграционный тест MCP проверяет, что validation возвращает диагностику вместо `core_error`.
