# Round-trip: Font.ref и ChoiceParameters

Дата: 2026-05-07

Статус: согласована рабочая модель для первых двух расхождений; реализация не начата.

## Контекст

Разбор short round-trip XML -> модель -> XML выявил две независимые проблемы:

- `Font.ref` теряет неизвестные ссылки на шрифты вида `style:Шрифт...`;
- `ChoiceParameters` не различает явное пустое значение `<app:value xsi:nil="true"/>` и отсутствие `app:value`.

Цель этой спеки - зафиксировать принятое решение до сжатия контекста. Следующая тема, `DCSParameter.value`, анализируется отдельно.

## Font.ref

### Наблюдение

Сейчас `packages/core/metadata/commonObjects/font/types.ts` содержит фиксированное соответствие `PrefixedFontsFromXML` / `PrefixedFontsToXML` только для известных ссылок:

- `style:LargeTextFont`;
- `style:SmallTextFont`;
- `style:NormalTextFont`;
- `style:ExtraLargeTextFont`;
- `style:TextFont`;
- системные шрифты.

При импорте XML неизвестная ссылка вида `style:ШрифтЗаголовкаВсплывающейГруппы` не попадает в модель: `fromXML.ts` ищет ее в таблице и получает `undefined`. При обратном экспорте исходный `_ref` теряется.

Поиск по реальным XML показал, что пользовательские `style:*` встречаются, поэтому это не искусственный случай.

### Решение

`Font.ref` должен поддерживать два класса значений:

- известные enum-значения, которые продолжают экспортироваться в читаемый YAML;
- неизвестную XML-ссылку как исходную строку, например `style:ШрифтМикротекста`.

Поведение:

- `fromXML`:
  - если `_ref` известен, использовать существующее enum-значение;
  - если `_ref` неизвестен, сохранить строку `_ref` как есть.
- `toXML`:
  - если `ref` известен, использовать существующее обратное соответствие;
  - если `ref` похож на XML-ссылку, экспортировать ее без изменений.
- `toYAML` / `fromYAML`:
  - известные значения остаются в текущем человекочитаемом виде;
  - неизвестные значения пишутся и читаются как строка `style:...`.
- `toEnterprise`:
  - известные значения остаются как сейчас;
  - неизвестные значения выводятся как исходная строка `style:...`, без искусственного `StyleFonts.style:...`.

### Тесты

Добавить фикстуру с пользовательским style-шрифтом в общий набор `fontYAMLFixtures`, чтобы проверить:

- XML -> модель;
- модель -> XML;
- YAML -> модель;
- модель -> YAML;
- модель -> Enterprise.

## ChoiceParameters

### Наблюдение

Есть две фикстуры:

- `packages/core/metadata/commonObjects/сhoiceParameters/__fixtures__/nil.xml` содержит `<app:value xsi:nil="true"/>`;
- `packages/core/metadata/commonObjects/сhoiceParameters/__fixtures__/withoutValue.xml` содержит `<app:item name="..."/>` без `app:value`.

Сейчас обе формы импортируются в одинаковую модель, где `value` отсутствует. Из-за этого обратный XML не может восстановить явный `xsi:nil`.

Структурный поиск в `/Users/nikita/git/round-trip-source` и `/Users/nikita/git/roundTripElements` по `ChoiceParameters` показал:

- найдено 15 693 `app:item` с `name`;
- найден 331 случай с `<app:value xsi:nil="true"/>`;
- не найдено реальных случаев `app:item` без `app:value`.

Поэтому отсутствие `app:value` в `withoutValue.xml` не подтверждено реальными выгрузками, а канонической пустой формой для `ChoiceParameters` считаем `xsi:nil`.

### Решение

Пустой параметр выбора должен round-trip-иться как явный nil:

```xml
<app:item name="ВыборСчетовГоловнойОрганизации">
  <app:value xsi:nil="true"/>
</app:item>
```

В YAML пустое значение выражается ключом без значения:

```yaml
ВыборСчетовГоловнойОрганизации:
```

То есть это не строковый маркер `"без значения"`, а реальный YAML `null`.

Поведение:

- XML с `<app:value xsi:nil="true"/>` импортируется как явное пустое значение;
- YAML-ключ без значения импортируется как явное пустое значение;
- экспорт такого значения в XML создает `<app:value xsi:nil="true"/>`;
- экспорт такого значения в YAML оставляет ключ без значения;
- XML без `app:value` можно оставить как совместимость на импорт, но не считать канонической формой экспорта.

### Фикстуры

Для реализации нужно обновить XML- и YAML-фикстуры `ChoiceParameters`, чтобы тесты отражали согласованную каноническую форму:

- `withoutValue.xml` должен перестать проверять канонический экспорт без `app:value`;
- YAML для пустого параметра должен использовать ключ без значения.

## Не входит в эту спеку

- Поведение `DCSParameter.value` при `xsi:nil` и `valueListAllowed=true`.
- Общий тип `nil` для всех значений метаданных.
- Изменение публичного YAML-формата для известных шрифтов.
