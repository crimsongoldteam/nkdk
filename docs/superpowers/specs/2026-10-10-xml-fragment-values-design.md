# XML-фрагмент как обычное значение декларации

Статус: проект для согласования. Реализация нового представления ещё не начата.

## Задача и границы

Полный сборщик коллекции FormAttribute с профилями восстановления уже
восстанавливает имя и служебный номер. Из оставшихся семи свойств пять
используют один существующий TS-договор SettingsFragment: содержимое Settings
хранится в YAML строкой с XML. Нужно перенести этот договор один раз,
а различия пяти типов оставить данными деклараций. Это обычное смысловое
значение, а не !xml и не обход отсутствующего обработчика.

| Свойство FormAttribute | Тип в XML | Пространство имён |
| --- | --- | --- |
| chart | Chart | http://v8.1c.ru/8.2/data/chart |
| ganttChart | GanttChart | http://v8.1c.ru/8.2/data/chart |
| flowchartContext | FlowchartContextType | http://v8.1c.ru/8.2/data/graphscheme |
| spreadsheetDocument | SpreadsheetDocument | http://v8.1c.ru/8.2/data/spreadsheet |
| planner | Planner | http://v8.1c.ru/8.3/data/planner |

Источники: forms/commonObjects/settingsFragment/types.ts и регистрации пяти
типов; самостоятельные фикстуры FormAttribute и существующие e2e YAML/XML
PlannerField, SpreadSheetDocumentField и остальных доступных вариантов.
Это не пять новых global common-флажков: перечень90 объектов не меняется.

## Декларация

Добавляется общее XML-представление `kind: fragment` для смыслового text.
Оно означает XML-содержимое текущего элемента, без самого внешнего элемента.
В YAML остаётся строка. Атрибут типа, выбор варианта и внешнее размещение
используют существующие with-attributes, QName и декларативный выбор.

```yaml
format: nkdk-declarations/1
kind: value
id: common.chart-settings
namespaces:
  xsi: http://www.w3.org/2001/XMLSchema-instance
  d4p1: http://v8.1c.ru/8.2/data/chart
  v8: http://v8.1c.ru/8.1/data/core
  v8ui: http://v8.1c.ru/8.1/data/ui
value: {kind: scalar, scalar: text}
representations:
  xml:
    kind: with-attributes
    attributes: [{name: 'xsi:type', value: {qname: 'd4p1:Chart'}}]
    content: {kind: fragment}
  yaml: {kind: text}
```

Пример обычного преобразования:

```xml
<Settings xmlns:c="http://v8.1c.ru/8.2/data/chart"
          xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:type="c:Chart">
  <c:seriesCurId>1</c:seriesCurId>
</Settings>
```

```yaml
Диаграмма: '<c:seriesCurId xmlns:c="http://v8.1c.ru/8.2/data/chart">1</c:seriesCurId>'
```

Префикс c был объявлен на удалённой оболочке. Его связь с пространством имён
должна остаться в строке. Для уже известных префиксов из namespaces декларации
повторные объявления не добавляются. Обычные существующие e2e-строки должны
сохранить договор; иной префикс или новое пространство имён могут потребовать
добавления xmlns к корням фрагмента. Значения атрибутов и текст не переименовывать
по догадке о QName. Дополнительное объявление пространства имён не меняет
текстовое значение, включая QName внутри текста или атрибута.

На экспорт строка читается в области namespaces декларации, вместе со своими
локальными xmlns. Изменённое пользователем содержимое вставляется внутрь
обычной оболочки с правильным типом. Не использовать старый XML для замены
отредактированного фрагмента. Тип сравнивается по пространству имён и имени,
а не по случайному префиксу. Внешние неизвестные атрибуты и отличия формы
обрабатываются существующим общим механизмом аномалий, без отдельных списков
аномалий для Chart и остальных вариантов.

## Выполнение и качество

- При сборке проверять совместимость fragment с text, связывать QName и
  генерировать обычные AOT-вызовы общего Rust-механизма.
- Никаких ветвей по Chart, Planner и именам свойств в нейтральном движке.
- Не строить второе дерево настроек и не преобразовывать XML в промежуточный
  объект или JSON. Использовать существующие потоковые XML-события и область
  имён, сохранить одну строку смыслового значения.
- Пять деклараций различаются данными. Переносчик распознаёт проверенную
  регистрацию defineSettingsFragmentType; произвольные функции не исполняет.
- Неправильно сформированный пользовательский фрагмент даёт диагностику
  валидации, не аварийное завершение процесса и не повреждённый итоговый XML.
- Общая матрица: пустое содержимое, несколько корней, вложенность, смешанное
  содержимое, сущности, локальные xmlns, внешний префикс, QName в значениях,
  правка YAML, неверный фрагмент, соседнее свойство, внешние атрибуты оболочки.
- Параметры пяти регистраций и реальные ожидания проверять отдельными данными
  той же матрицы. XML-фикстуры не менять. Существующие эталоны не получать из
  новых деклараций; XML ↔ YAML и экспорт независимого YAML проверять отдельно.
- Замерить преобразование и подготовку на реальных настройках; сравнение
  namespace-форм делать по смыслу XML. Ускорение сборки не оправдывает
  замедление исполнения. Общий механизм и AOT-код должны оставаться компактными.
