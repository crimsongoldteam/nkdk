# Ускорение построения graph для форм

## Контекст

Полный `nkdk update-graph /Users/nikita/git/erp_nkdk` долго молчит на этапе `buildGraph`.
Диагностика показала, что чтение источников занимает около 3 секунд, разбор `Форма.nkdk`
сам по себе обычно занимает миллисекунды, а основная задержка появляется после импорта
каждой формы.

Текущий код в `importMetadataFileWithGraph` после `buildGraphFromModel` дважды обходит
все узлы графа:

1. чтобы перенести `filePath` визуальных элементов формы с `Форма.yaml` на `Форма.nkdk`;
2. чтобы добавить `filePath: Форма.nkdk` на рёбра, связанные с визуальными элементами.

На большом проекте это даёт квадратичный рост: каждая следующая форма снова просматривает
весь уже накопленный граф.

## Цель

Сохранить текущее внешнее поведение graph payload, но заменить глобальный обход после
каждой формы на выборочный обход только узлов и рёбер текущей формы.

## Решение

Добавить в `GraphBuilder` внутренние методы выборочного обхода:

- `nodesWithPrefix(prefix: string): Iterable<string>` — возвращает только узлы, чей id
  начинается с заданного префикса;
- `edgeEntriesTouching(nodeIds: Iterable<string>): Iterable<{ source: string; target: string; attributes: EdgeAttributes }>` —
  возвращает рёбра, где источник или цель входит в переданный набор.

Для второго метода `GraphBuilder` должен поддерживать индекс входящих рёбер рядом с уже
существующим `outEdgesBySource`. Это позволит находить связи, где визуальный элемент
является целью, без обхода всех узлов графа.

В `importMetadataFileWithGraph` для формы использовать `visualPrefix =
<formNodeId>.Элемент.` и работать только с `graph.nodesWithPrefix(visualPrefix)`.
Для рёбер обработать `graph.edgeEntriesTouching(visualNodeIds)` и проставить им
`filePath: nkdkFilePath` так же, как сейчас.

## Неграницы

- Не менять формат `FileGraphData`.
- Не менять правила fromXML/toXML/fromYAML/toYAML.
- Не менять XML-фикстуры.
- Не переписывать парсер `nkdk-language`: он не является основной причиной задержки.

## Проверка

Нужны тесты на уровне `GraphBuilder` и `importMetadataFileWithGraph`:

- `nodesWithPrefix` возвращает только подходящие узлы и не ломает порядок обхода;
- `edgeEntriesTouching` возвращает исходящие и входящие рёбра для переданного набора
  узлов без дублей;
- форма с `Форма.nkdk` по-прежнему объявляет визуальные элементы в сегменте
  `Форма.nkdk`;
- рёбра, связанные с визуальными элементами, по-прежнему попадают в сегмент
  `Форма.nkdk`;
- полный `buildGraph` на небольшой фикстуре сохраняет прежний payload.

После реализации нужно прогнать точечные тесты пакета `@nakidka/core`, затем `pnpm test`
из корня перед закрытием задачи.
