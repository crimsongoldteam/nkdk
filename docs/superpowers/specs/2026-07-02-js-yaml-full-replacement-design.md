# Полная замена YAML-слоя на js-yaml

## Цель

Полностью заменить библиотеку `yaml` на `js-yaml` для импорта и экспорта YAML-проектов, сохранив текущие пользовательские сценарии: импорт модели, экспорт YAML, валидацию с позициями строк и диагностикой по YAML-путям.

Ожидаемый выигрыш по предварительным замерам на большой конфигурации:

- импорт `js-yaml + быстрый индекс позиций`: около 5.3x быстрее текущего `yaml.Document`;
- экспорт через `js-yaml.dump(JSON_SCHEMA)`: около 5x быстрее текущего `exportToYAML`;
- построение только индекса позиций: около 2.8 с на 336.85 MiB YAML.

## Границы

Входит:

- замена публичных функций `importFromYAML`, `importFromYAMLFile`, `parseMetadataYaml`, `exportToYAML`;
- удаление зависимости `yaml` из рабочего кода и `package.json`;
- добавление `js-yaml` и `@types/js-yaml`;
- новый нейтральный договор для позиций YAML без раскрытия AST конкретной библиотеки;
- миграция валидации и операций, которые сейчас используют `Document`, `LineCounter`, `YAMLMap`, `YAMLSeq` и `Scalar`;
- ручная массовая проверка на пользовательской YAML-выгрузке перед завершением.

Не входит:

- поддержка комментариев, якорей и ссылок как пользовательского API;
- изменение XML-фикстур;
- перенос правил `fromXML/toXML/fromYAML/toYAML` без отдельной причины.

## Архитектура

YAML-слой становится независимым от AST библиотеки.

`ParsedYaml` должен содержать:

- `text: string`;
- `data: unknown`;
- `syntaxErrors` или готовые синтаксические diagnostics;
- `locations: YamlLocationIndex`.

`ParsedYaml` не должен содержать `Document` или `LineCounter`. Общие слои валидации работают через нейтральный договор `YamlLocationIndex`, а не через `yaml.Document`.

Минимальный договор индекса:

- найти позицию корня;
- найти позицию ключа по `YamlPath`;
- найти позицию значения по `YamlPath`;
- найти позицию узла или элемента массива по `YamlPath`;
- найти N-е вхождение ключа для диагностики дублей.

## Импорт

Импорт строится из двух независимых шагов:

1. `js-yaml.load(text, { schema: JSON_SCHEMA })` возвращает JS-данные.
2. `buildYamlLocationIndex(text)` строит быстрый индекс `YamlPath -> position`.

`parseMetadataYaml(text)` объединяет результат в `ParsedYaml`.

Синтаксические ошибки берутся из `YAMLException.mark` и приводятся к текущему формату диагностики. Если `js-yaml` сообщает позицию с нулевой базой, слой адаптера переводит её в текущий формат с единичной базой.

Индекс покрывает текущее подмножество YAML проекта: отступы, отображения, последовательности, однострочные скаляры, строки в кавычках и блочные скаляры. Комментарии, якоря и ссылки не становятся частью поддерживаемого формата.

## Позиции

Текущие потребители позиций переписываются с AST-операций на индекс:

- `diagnosticAtYamlPath` больше не обходит `parsed.doc.contents`, а вызывает `parsed.locations`;
- `typeboxErrorsToDiagnostics` больше не использует `parsed.doc.getIn`;
- `uniqueNameScopes`, `formIndex`, `dataPath`, формы и специальные проверки дублей используют методы индекса;
- helper'ы из `metadata/orchestration/property/position.ts`, завязанные на `YAMLMap/YAMLSeq/LineCounter`, заменяются на функции поверх `YamlLocationIndex` или удаляются.

Если позиция не найдена, поведение остаётся прежним: диагностика указывает `line: 1, col: 1`.

## Экспорт

`exportToYAML` переводится на `js-yaml.dump` с настройками, близкими к текущему формату:

- `schema: JSON_SCHEMA`;
- `indent: 2`;
- `lineWidth: -1`;
- `noRefs: true`;
- без завершающего служебного перевода строки, если он не является частью block scalar.

`ExplicitYAMLString` должен сохранить семантику явных двойных кавычек. Для этого нужен один из вариантов:

- пользовательский `js-yaml.Type` для помеченных строк;
- или локальный предобработчик, который преобразует помеченные строки в значения, сериализуемые double-quoted стилем.

Нельзя считать изменение YAML-форматирования автоматически допустимым.

## Проверка Формата

Перед завершением замены выполняется ручной массовый анализ отличий на пользовательской YAML-выгрузке.

Путь к выгрузке не зашивается в код, тесты или документацию выполнения. Перед выполнением плана агент должен отдельно спросить у пользователя путь к YAML-выгрузке.

Проверка должна:

- загрузить YAML-файлы из указанного каталога;
- экспортировать их текущим и новым путём;
- сгруппировать diff'ы по классам: кавычки, пустые значения, блочные скаляры, порядок ключей, списки, булевы/числа, завершающий перевод строки, прочее;
- проверить обратный импорт нового YAML;
- показать неизвестные или опасные классы отличий отдельно.

Критерий готовности: нет неизвестных классов diff'ов; все принятые отличия описаны; обратный импорт даёт ту же модель; round-trip проверки зелёные.

## Тестирование

Обязательные проверки:

- unit-тесты для `buildYamlLocationIndex` на отображениях, последовательностях, вложенных путях, блочных скалярах, ключах/значениях в кавычках и дублях;
- parity-тесты позиций: новый индекс должен совпадать с текущими ожидаемыми `line/col` в существующих тестах диагностики;
- тесты синтаксических ошибок через `js-yaml`;
- тесты `ExplicitYAMLString`;
- существующие тесты импорта/экспорта YAML;
- `pnpm test` перед завершением задачи.

Массовая проверка на большой пользовательской YAML-выгрузке выполняется вручную после запроса пути у пользователя.

## План Перехода

1. Добавить `js-yaml` и новый YAML-фасад без удаления старого кода.
2. Реализовать `YamlLocationIndex` и покрыть его тестами.
3. Перевести диагностики с `parsed.doc` на `parsed.locations`.
4. Перевести `parseMetadataYaml` и `importFromYAML` на `js-yaml`.
5. Перевести `exportToYAML` на `js-yaml.dump` с сохранением `ExplicitYAMLString`.
6. Запустить массовый diff-анализ на пользовательской YAML-выгрузке после запроса пути.
7. Устранить или явно принять классы отличий.
8. Удалить библиотеку `yaml`, её типы и все импорты из рабочего кода.
9. Запустить `pnpm test`.

## Риски

- `js-yaml` может иначе трактовать некоторые скаляры; используем `JSON_SCHEMA` и parity-тесты.
- Новый dumper может изменить читаемый формат YAML; массовый diff-анализ обязателен.
- Индекс позиций может не покрыть редкий синтаксис; неизвестные случаи должны падать в отчёте, а не молча давать неверные строки.
- Удаление `yaml` затрагивает валидацию, операции и тесты, поэтому миграция должна идти через нейтральный договор, а не через частные условия в общих слоях.
