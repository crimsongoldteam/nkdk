# Приведение тестов metadataEnumeration к стандарту

## Контекст

`packages/core/metadata/appliedObjects/metadataEnumeration` уже имеет базовые `fromXML`/`toXML` тесты с XML round-trip, но YAML-покрытие отличается от стандарта applied object. Сейчас `fromYAML.test.ts` проверяет частные случаи импорта и построения графа значений, а отдельного `toYAML.test.ts`, YAML round-trip, `convertFromXML.test.ts`, `syncToXML.test.ts` и `__fixtures__/sync` нет.

Стандарт берётся из `.agents/skills/_shared/metadata/tests.md` и `.agents/skills/_shared/metadata/io-tests.md`. Референсные соседи: `metadataSequence` и `metadataDocumentNumerator`.

## Цель

Привести тесты `metadataEnumeration` к стандартному набору applied object:

- `fromXML.test.ts` и `toXML.test.ts` остаются по applied object шаблону.
- `fromYAML.test.ts` проверяет импорт YAML в модель и содержит YAML round-trip на уровне parsed object.
- `toYAML.test.ts` проверяет экспорт модели в YAML, включая `undefined`.
- `convertFromXML.test.ts` проверяет XML с диска -> `Свойства.yaml`.
- `syncToXML.test.ts` проверяет YAML с диска -> XML.
- `__fixtures__/sync` содержит XML-источник, YAML-вход и ожидаемую YAML-строку.

Текущие граф-тесты значений перечисления остаются как дополнительное покрытие, но не заменяют стандартные YAML-тесты.

## Границы

В рамках этой работы изменяются тесты и тестовые фикстуры `metadataEnumeration`. Рабочий код не меняется, если новые стандартные тесты проходят.

Если новые тесты обнаружат реальный разрыв в YAML-импорте, YAML-экспорте или синхронизации, правка рабочего кода допускается только точечно и только для восстановления заявленного стандартного поведения. Изменение XML-фикстур `full.xml` и `minimal.xml` не допускается: они остаются источником истины.

## Данные и поток

Основная модель берётся из существующих `__fixtures__/full.ts` и `minimal.ts`. Для YAML нужны ожидаемые parsed object значения рядом с этими фикстурами или отдельный небольшой тестовый YAML, если текущий объект требует особого формата для значений перечисления.

Для IO-тестов создаётся структура:

```text
__fixtures__/sync/
  data.ts
  xml/<Имя>.xml
  nkdk/<Имя>/Свойства.yaml
```

XML для sync можно взять из существующего `full.xml`, не меняя исходную фикстуру. `data.ts` экспортирует строку, полностью совпадающую с `Свойства.yaml`.

## Проверки

Локально запускаются точечные тесты `metadataEnumeration`. Если они зелёные, запускается профильный набор пакета core или весь проект по стандарту, если границы изменений потребуют полной проверки.

Перед закрытием задачи итоговая проверка должна включать `pnpm test` из корня. В свежем worktree перед этим нужно выполнить `pnpm --filter nkdk-language langium:generate`.

## Риски

`MetadataEnumerationValues` имеет специальный YAML-импорт и построение графа. Стандартные YAML-тесты могут показать, что для значений перечисления есть импорт, но нет симметричного экспорта. В этом случае сначала фиксируется тестовый симптом, затем принимается минимальная правка рабочего кода.

Возможны различия между существующим `values.yaml` и будущим `Свойства.yaml` для sync. Истиной для sync считается результат стандартного `convertAppliedObjectFromXML` по выбранному XML-источнику.

## Решение

Выбран подход (А): привести `metadataEnumeration` к стандарту тестов applied object, включая YAML и синхронизацию. Реализацию менять только при падении новых стандартных тестов.
