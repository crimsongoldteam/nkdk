# Диагностика экспорта standard members на конфигурации all

## Цель

Проверить, воспроизводится ли ошибка экспорта стандартных реквизитов на маленькой XML-конфигурации `/Users/nikita/git/round-trip/all`.

## Контекст

Последний профильный коммит `ac6de1019 feat: :sparkles: добавить правила стандартных реквизитов` добавил регистрацию `standardMembers` для прикладных объектов и преобразование DataPath между внутренними XML-именами и YAML-именами.

Предыдущий полный round-trip на большой конфигурации `acc` показал массовые изменения `DataPath` в формах: XML-значения вроде `Список.LineNumber`, `Список.Period`, `Список.Recorder` после цикла стали `Список.НомерСтроки`, `Список.Период`, `Список.Регистратор`. Это похоже на проблему обратного преобразования YAML -> XML.

## Подход

Запустить штатный `round-trip-yaml` только для каталога `all`:

```bash
NODE_OPTIONS=--max-old-space-size=12288 \
NKDK_XML_REPO=/Users/nikita/git/round-trip \
NKDK_XML_DIR=/Users/nikita/git/round-trip/all \
./.agents/skills/round-trip-yaml/round-trip.sh
```

Скрипт сам очистит текущие XML-diff'ы через `git restore .`, удалит временный YAML-каталог для `all`, выполнит `import`, затем `sync`, заменит активный XML-каталог и соберёт итоговые diff'ы.

## Границы

- Не менять код.
- Не создавать fixture, тесты, ветку, commit или PR для исправления.
- Не запускать полный `pnpm test`.
- Не откатывать итоговые XML-diff'ы после диагностики.
- Если `import` или `sync` упадёт, остановиться и сообщить стадию, каталоги и ошибку.

## Анализ результата

Если diff'ы есть, разобрать первый выбранный diff:

- XML-файл и XML-каталог из вывода скрипта.
- YAML-каталог из вывода скрипта.
- Категория расхождения.
- Вероятный модуль и вероятный код.
- Короткий фрагмент diff как источник истины.

Особое внимание уделить diff'ам, где в XML меняются `DataPath`, `ChoiceParameterLinks`, metadata target или ссылки на `СтандартныйРеквизит`.

## Критерии успеха

Диагностика считается успешной, если есть один из результатов:

- `all` проходит round-trip без diff'ов, значит проблема может зависеть от данных большой конфигурации `acc`;
- `all` даёт diff'ы того же класса, значит есть маленькое воспроизведение для дальнейшего исправления;
- `import` или `sync` падает с понятной стадией и путями, значит сначала нужно разобрать сбой диагностики.
