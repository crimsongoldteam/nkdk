# Регистрация commonObjects для импорта форм

## Контекст

После исправления поддержки `SearchStringAddition`, `SearchControlAddition` и `ViewStatusAddition` внутри обычных групп `round-trip-yaml` дошел до следующей ошибки на форме `Catalogs/КонтактныеЛица/Forms/ФормаВыбораЛидов/Ext/Form.xml`:

```text
Cannot read properties of undefined (reading 'ru')
```

Падение происходит в `buttonGroup/toNKDK`, когда экспорт в NKDK форматирует заголовок `ButtonGroup`.

## Причина

`ButtonGroup.title` должен быть модельным `I8nText`:

```ts
{ items: { ru: "Стандартные команды" } }
```

Но в проблемном сценарии он остается сырым XML-объектом:

```ts
{
  "v8:item": {
    "v8:lang": "ru",
    "v8:content": "Стандартные команды"
  }
}
```

После этого `formatDefaultLanguageText` пытается прочитать `title.items.ru`, но поля `items` нет. Ошибка находится не в `ButtonGroup` как элементе формы, а раньше: обработчик `I8nText/fromXML`, который переводит XML-заголовок в модельный объект, не зарегистрирован в этом пути выполнения.

## Решение

Закрепить инвариант: импорт и экспорт форм должны выполняться при зарегистрированных общих metadata-типах из `~/metadata/commonObjects`.

Основной фикс должен быть на границе подсистемы форм, а не в `buttonGroup/toNKDK`:

- подключить регистрацию `~/metadata/commonObjects` перед XML-импортом форм;
- сохранить существующий контракт `formatDefaultLanguageText`: он принимает модельный `I8nText`, а не сырой XML;
- не добавлять разбор XML в форматтер NKDK.

## Проверка

Тест должен воспроизводить ошибку на уровне формы:

- прочитать XML формы с `ButtonGroup`, у которого есть `<Title>`;
- убедиться, что после `readFormFromXML` заголовок `ГруппаСтандартныеКоманды` имеет вид `{ items: { ru: "Стандартные команды" } }`;
- убедиться, что экспорт этой формы в NKDK больше не падает на `Cannot read properties of undefined (reading 'ru')`.

Регрессионный тест должен быть ближе к `clientApplicationForm`, потому что ошибка проявляется в связке XML-импорт формы -> модель -> NKDK.

## Вне границ

- Не менять XML-фикстуры.
- Не учить `buttonGroup/toNKDK` принимать сырые XML-объекты.
- Не менять формат YAML для заголовков.
- Не расширять эту задачу на последующие независимые ошибки `round-trip-yaml`.
