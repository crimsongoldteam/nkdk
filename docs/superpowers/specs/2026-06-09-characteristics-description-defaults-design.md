# CharacteristicsDescription: не материализовать отсутствующие XML-default `-1`

## Контекст

Полный metadata round-trip `XML -> модель -> YAML -> модель -> XML` для `/home/codexwsl/round-trip/acc` после подключения Git LFS проходит `import` и `sync`, но даёт первый diff в `Catalogs/ДополнительныеОтчетыИОбработки.xml`.

В diff появляются теги, которых не было в reference XML:

- `xr:DataPathField`
- `xr:MultipleValuesUseField`
- `xr:MultipleValuesKeyField`
- `xr:MultipleValuesOrderField`

Все четыре тега добавляются со значением `-1`. Вероятный источник - `defaultValueXML: "-1"` в `packages/core/metadata/commonObjects/characteristicsDescription/rules.ts`.

## Цель

Исправить только первый diff текущего `round-trip-yaml`: отсутствующие в исходном XML поля `CharacteristicsDescription` со значением по умолчанию `-1` не должны появляться в XML после полного YAML round-trip.

## Не входит в задачу

- Исправление остальных 13 diff-файлов.
- Изменение XML-фикстур как источника истины.
- Пересмотр YAML-структуры характеристик.
- Добавление новых ручных `fromXML/toXML/fromYAML/toYAML` правил без необходимости.

## Подход

Выбран точечный подход: сохранить чтение `-1` как XML-default, но не материализовать отсутствующий default обратно в XML, если значение не было явно задано в модели/YAML.

Это лучше, чем просто удалить `defaultValueXML`, потому что существующие случаи с явным `-1` должны продолжать читаться как корректное значение. Это также лучше, чем YAML-исключение, потому что расхождение проявляется в XML-выводе, а источник находится в XML-default правилах.

## Архитектура изменения

Основной кандидат на изменение - общий слой экспорта свойств в `packages/core/metadata/orchestration/property/toXML` или близкий к нему механизм, который решает, писать ли свойство с `defaultValueXML`.

Правило для `CharacteristicsDescription` должно оставаться декларативным в `rules.ts`. Если общий механизм уже различает отсутствующее значение и значение по умолчанию, нужно использовать существующую возможность. Если не различает, изменение должно быть минимальным и покрытым тестом на конкретный объект.

## Тестирование

Добавить точечный тест для `CharacteristicsDescription`:

1. Входной XML содержит `xr:CharacteristicTypes` и `xr:CharacteristicValues`, но не содержит четыре default-поля.
2. Цикл `XML -> модель -> YAML -> модель -> XML` не добавляет эти четыре тега.
3. Отдельно убедиться, что явно присутствующие поля со значением `-1` не теряются, если такой сценарий уже поддержан соседними тестами или легко добавляется без расширения задачи.

После изменения прогнать точечные тесты затронутого пакета и повторить `round-trip-yaml` single-режимом, чтобы проверить исчезновение первого diff.

## Риски

Главный риск - общее изменение обработки `defaultValueXML` может повлиять на другие metadataItem. Поэтому предпочтение у локального механизма или уже существующей декларативной возможности, а не у широкого изменения поведения всех default.

Если точечный тест покажет, что общий экспорт не хранит признак исходного отсутствия XML-тега после YAML-цикла, нужно остановиться и уточнить модельное представление: без такого признака невозможно надёжно отличить "значение отсутствовало" от "пользователь явно задал default".
