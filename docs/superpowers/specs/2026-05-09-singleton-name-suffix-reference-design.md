# Сохранение постфиксов имён form-синглтонов из XML-референса

Дата: 2026-05-09
Статус: согласовано

## Контекст

Short round-trip сейчас пересобирает имя некоторых form-синглтонов из имени родителя и канонического русского постфикса. Из-за этого референсный XML вида `СписокExtendedTooltip`, `СписокSearchString`, `СписокViewStatus`, `СписокSearchControl` или `СписокSearchStringContextMenu` превращается в русские варианты `СписокРасширеннаяПодсказка`, `СписокСтрокаПоиска`, `СписокСостояниеПросмотра`, `СписокУправлениеПоиском`, `СписокСтрокаПоискаКонтекстноеМеню`.

Имя синглтона остаётся производным: базовая часть берётся от текущего родителя. Но стиль постфикса должен сохраняться из XML-референса, чтобы round-trip не менял исходный вариант платформы.

## Цели

- Сохранять только постфикс имени синглтона из XML-референса.
- Не добавлять публичное поле `name` в модель синглтонов и не выводить технические данные в YAML.
- Оставить прежнее поведение для новых XML без референса: используется текущий канонический русский генератор.
- Применить решение ко всем form-синглтонам с производными именами, а не только к `ExtendedTooltip`.

## Не цели

- Не сохранять полное старое имя синглтона как источник истины.
- Не менять существующие XML-фикстуры как источник истины.
- Не писать отдельные новые `fromXML`/`toXML` правила для каждого синглтона.

## Список постфиксов

Поддерживаемые пары постфиксов:

- `ExtendedTooltip`: `РасширеннаяПодсказка`, `ExtendedTooltip`
- `ContextMenu`: `КонтекстноеМеню`, `ContextMenu`
- `SingleSearchStringAddition`: `СтрокаПоиска`, `SearchString`
- `ViewStatusAddition`: `СостояниеПросмотра`, `ViewStatus`
- `SingleSearchControlAddition`: `УправлениеПоиском`, `SearchControl`
- `TableAutoCommandBar`: `КоманднаяПанель`, `CommandBar`

Для корневого `AutoCommandBar` формы сохраняется фиксированный вариант имени `FormCommandBar`. У него нет обычного пользовательского родителя, поэтому это отдельный известный вариант имени, а не переименование родительской части.

## Архитектура

Механизм живёт на уровне `registerElementAsType`, потому что именно он связывает singleton-property тип с импортом и экспортом XML. Регистрация синглтона получает описание допустимых постфиксов имени или фиксированных вариантов имени для особых случаев.

При импорте XML в режиме `forReference`:

1. `importSingleElementFromXML` видит исходный `xml._name`.
2. Для зарегистрированных синглтонов определяется известный постфикс, которым заканчивается имя.
3. Найденный постфикс сохраняется на reference-модели служебно и не перечисляется в `Object.keys`.
4. Публичная модель, YAML и typed YAML не получают новое поле.

При экспорте XML:

1. Существующий `toXML` синглтона строит каноническое имя от текущего родителя.
2. Общий helper проверяет reference-модель этого же синглтона.
3. Если в reference-модели есть сохранённый постфикс, канонический постфикс заменяется на reference-постфикс.
4. Если reference-модель отсутствует или постфикс неизвестен, имя остаётся каноническим.

Так сохраняется форма `НовыйРодительExtendedTooltip` вместо полного старого имени `СтарыйРодительExtendedTooltip`, когда reference-синглтон доступен для этого элемента.

## Ошибки и крайние случаи

Если референсное имя не заканчивается ни одним известным постфиксом для данного синглтона, экспорт не угадывает хвост и оставляет канонический русский вариант. Такой случай должен проявиться отдельным round-trip diff и быть разобран отдельно.

Если референса нет, поведение полностью прежнее.

## Тестирование

Нужны тесты на общий helper выбора имени:

- берёт английский постфикс из reference-имени и заменяет только канонический постфикс;
- оставляет каноническое имя без reference-постфикса;
- оставляет каноническое имя при неизвестном reference-постфиксе.

Нужны XML-export тесты для синглтонов:

- `ExtendedTooltip`: `СписокExtendedTooltip`;
- `ContextMenu`: `СписокContextMenu`;
- `SingleSearchStringAddition`: `СписокSearchString`;
- `ViewStatusAddition`: `СписокViewStatus`;
- `SingleSearchControlAddition`: `СписокSearchControl`;
- `TableAutoCommandBar`: `СписокCommandBar`;
- корневой `AutoCommandBar`: `FormCommandBar`.

После реализации надо прогнать узкие vitest-тесты для изменённых модулей, затем полный `pnpm test` из корня worktree.
