# Сохранение пустого XML для I8nText

## Контекст

Полный round-trip XML → YAML → XML не сохраняет явно пустой синоним поля
регистра. Исходный XML содержит:

```xml
<Synonym/>
```

Импорт представляет его как `{ items: {} }`, но экспорт в YAML удаляет
пустой `I8nText`. При обратном импорте отсутствующий `Синоним` получает
значение по умолчанию, сформированное из имени поля. В результате пустой
XML-узел превращается в непустой синоним.

Пустой синоним является пользовательским значением, поэтому он должен быть
явно представлен в YAML, а не сохраняться в снимке конфигурации.

## Цели

- Представлять `<Synonym/>` в YAML как `Синоним: ""`.
- Восстанавливать из `Синоним: ""` пустой XML-узел `<Synonym/>`.
- Отличать явно пустой XML-узел от отсутствующего XML-свойства.
- Применить один договор ко всем существующим правилам синонима, которым
  требуется сохранение пустого XML.
- Дать признаку правила имя, описывающее его назначение.

## Не входит в задачу

- Сохранение пустого синонима в снимке конфигурации.
- Изменение поведения остальных `I8nText`.
- Нормализация строк, содержащих пробелы или переводы строк.
- Совместимость с прежним именем признака `emptyAsRawXML`.
- Изменение существующих XML-фикстур.

## Договор rules.ts

Признак `emptyAsRawXML` переименовывается без совместимости:

```ts
preserveEmptyXML: true
```

Он означает: пустой XML-узел является значимым пустым значением и должен
сохраняться через модель и YAML до обратного экспорта в XML.

Признак остаётся частью общего правила `I8nText`, а не специальным условием
для конкретного типа метаданных. Сейчас он используется только свойством
`Синоним` у трёх общих типов:

- реквизита;
- табличной части;
- поля регистра.

## Различие пустого и отсутствующего значения

Два состояния имеют разный смысл:

- присутствующий `<Synonym/>` — явно пустое значение, которое попадает в
  YAML как `Синоним: ""`;
- отсутствующий `<Synonym>` — значение не задано в XML, поэтому ключ может
  отсутствовать в YAML, а импорт из YAML может применить существующее
  значение по умолчанию.

Строки с пробелом или переводом строки не считаются пустыми. Например,
`<v8:content> </v8:content>` сохраняет строку `" "`.

Поиск по всем конфигурациям в `/Users/nikita/git/round-trip` не обнаружил
`<v8:content/>` или `<v8:content></v8:content>`. Представление
`{ items: { ru: "" } }` возникает при импорте пустой строки из YAML и
является промежуточным состоянием модели, а не наблюдавшейся формой исходного
XML.

## Поток XML → YAML

1. Импорт `I8nText` получает пустой XML-узел.
2. При `preserveEmptyXML: true` он создаёт модель `{ items: {} }`.
3. Экспорт `I8nText` в YAML распознаёт это состояние и возвращает пустую
   строку вместо `undefined`.
4. YAML содержит явный ключ:

   ```yaml
   Синоним: ""
   ```

5. При отсутствии `preserveEmptyXML` существующее поведение пустого
   `I8nText` не меняется.

## Поток YAML → XML

1. Импорт `Синоним: ""` создаёт существующее представление
   `{ items: { ru: "" } }`, где `ru` — язык конфигурации.
2. Проверка пустого `I8nText` считает это значение пустым.
3. При `preserveEmptyXML: true` XML-экспорт возвращает пустой объект XML.
4. XML-сериализатор формирует `<Synonym/>`.

Приводить оба внутренних представления пустоты к одной форме модели в этой
задаче не требуется: они имеют одинаковое внешнее поведение, а дополнительная
нормализация не решает отдельной пользовательской проблемы.

## Границы модулей

- `I8nText` определяет преобразование пустого значения между XML, моделью и
  YAML.
- Конкретные `rules.ts` только включают `preserveEmptyXML`.
- Общая оркестрация не получает условий по именам `Synonym`, типам объектов
  или путям XML.
- Снимок конфигурации не участвует в передаче значения.

## Тестирование

- Модульный тест XML-импорта проверяет
  `<Synonym/>` → `{ items: {} }` при `preserveEmptyXML`.
- Модульный тест YAML-экспорта проверяет
  `{ items: {} }` → `""` при `preserveEmptyXML`.
- Тест без признака подтверждает прежнее исключение пустого `I8nText` из
  YAML.
- Модульный тест XML-экспорта проверяет
  `{ items: { ru: "" } }` → пустой XML-узел.
- Интеграционный тест поля регистра проверяет
  `<Synonym/>` → `Синоним: ""` → `<Synonym/>`.
- Тест подтверждает, что отсутствующий `Synonym` не превращается в явно
  пустой.
- Существующие тесты трёх правил обновляются на имя `preserveEmptyXML`.
- Полный `pnpm test` остаётся обязательной итоговой проверкой.
- Round-trip на `cf/all` подтверждает устранение расхождения с синонимом
  `Ресурс1`; остальные категории расхождений оцениваются отдельно.

## Замена прежнего решения

Этот договор заменяет решение из раздела «Preserve Explicit Empty Synonym
From Reference» спецификации
`2026-05-21-round-trip-yaml-33-diffs-design.md`. Значение больше не должно
восстанавливаться из reference при отсутствии ключа YAML: явная пустота
становится частью пользовательского YAML-договора.
