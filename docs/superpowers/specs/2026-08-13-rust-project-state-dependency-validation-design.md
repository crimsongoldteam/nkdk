# Пакетная проверка зависимостей ProjectState в Rust

## Цель

Перенести следующий изолированный компонент ProjectState на Rust так, чтобы одновременно уменьшить время проверки зависимостей и её пиковый RSS. Публичные интерфейсы `ProjectStateStore`, `ProjectStateDependencyValidator` и формат `project-state.bin` не меняются.

Первый вертикальный слой считается успешным, если на большой конфигурации `/Users/nikita/git/sed_xml/cf` медиана времени `dependencyValidation` и пиковый RSS снижаются не менее чем на 20%. На малых проектах допускается ухудшение не более 5%. Состав, порядок и все поля диагностик должны совпадать с TypeScript.

## Почему не переносим все правила сразу

`validateDependencyDiagnosticBatch` содержит две разные категории логики:

1. универсальную логику ProjectState, полностью определяемую двоичным снимком: готовность компонентов, обход файлов и таблиц фактов, поиск целей и владельцев, группировка проверок;
2. подключаемые правила metadata-runtime: обработчики structured documents, построители путей объектов и значений, а также часть DataPath-семантики.

Копирование второй категории в Rust создало бы две расходящиеся реализации. Поэтому Rust владеет универсальным обходом и решает проверки, для которых ему достаточно снимка. Остальные проверки возвращаются в TypeScript компактными идентификаторами строк и обрабатываются существующими правилами.

## Граница компонента

В `@nkdk/project-state-native` появляется `NativeDependencyValidationPlan`, создаваемый локальным `NativeProjectStateReader`:

```ts
interface NativeDependencyValidationStats {
  readonly filesVisited: number
  readonly checksVisited: number
  readonly nativeDiagnostics: number
  readonly deferredChecks: number
  readonly nativeTemporaryBytes: number
}

interface NativeDependencyValidationPage {
  readonly diagnostics: Uint8Array<ArrayBuffer>
  readonly deferred: Uint8Array<ArrayBuffer>
  readonly nextCursor?: number
  readonly stats: NativeDependencyValidationStats
}

interface NativeProjectStateReader {
  validateDependencyPage(input: {
    readonly projectDir: string
    readonly cursor: number
    readonly batchSize: number
  }): NativeDependencyValidationPage
}
```

`diagnostics` использует существующий формат `EncodedDiagnosticBatch` версии 1. `deferred` — внутренний версионированный little-endian формат с `fileId`, видом таблицы и `rowId`. Он не содержит строк и больших JS-объектов.

Курсор непрозрачен для вызывающей стороны и действителен только для неизменяемого снимка данного reader. Размер страницы по умолчанию — 2 000 проверок. Он ограничивает количество одновременно раскрытых TypeScript-объектов.

## Поток данных

1. Rust проверяет структуру снимка при открытии reader.
2. `validateDependencyPage` обходит очередной диапазон YAML-файлов и таблиц фактов.
3. Rust формирует диагностики универсальных проверок непосредственно в двоичном формате.
4. Для подключаемой семантики Rust записывает только идентификаторы исходных строк в `deferred`.
5. TypeScript раскрывает отложенные строки текущей страницы, вызывает существующий `ProjectStateDependencyValidator` через Rust query port и сразу кодирует полученные диагностики.
6. После завершения страницы её временные массивы становятся недостижимыми. Следующая страница не начинается раньше.
7. Пачки накапливаются по категориям и возвращаются в прежнем порядке: references, owners, dependencies, addressable required, structured documents, readiness. Объединять и копировать их не требуется.

`structuredDocumentValidators` по текущему договору получают весь набор structured-document facts. Поэтому Rust накапливает для них только компактные идентификаторы строк, а TypeScript раскрывает эту категорию один раз после обхода всех страниц. Это сохраняет семантику подключаемых обработчиков; остальные категории остаются строго постраничными.

## Первый переносимый набор

В первом слое Rust отвечает за:

- вычисление готовности базовой конфигурации и списка заблокированных расширений;
- отбор YAML-файлов, которые участвуют в смысловой проверке;
- обход и классификацию `pendingReferences`, `pendingChecks` и `structuredDocuments` без создания JS-моделей;
- пакетное разрешение целей через уже реализованный индекс Rust;
- формирование диагностик готовности, не требующих metadata-регистраций;
- выдачу компактных идентификаторов для остальных случаев.

TypeScript в первом слое сохраняет:

- проверку ограничений найденной metadata-ссылки;
- подключаемые построители путей объектов и значений;
- DataPath и fill value;
- structured-document validators.

Следующий слой переносит `readOwners`, `readDependencyInputs` и `readDependencyOwnerInputs` и уменьшает долю отложенных проверок. Полный перенос DataPath рассматривается только после отдельного измерения.

## Владение памятью

Rust возвращает `Uint8Array`, владеющие полным `ArrayBuffer`. Снимок не копируется: reader удерживает ссылки N-API на исходные `SharedArrayBuffer`. На одной странице одновременно живут только:

- неизменяемый снимок;
- ограниченные рабочие структуры Rust;
- двоичная пачка готовых диагностик;
- не более 2 000 раскрытых TypeScript-проверок.

Полный массив всех `references`, `dependencies` и `owners` больше не создаётся. Для structured documents до следующего слоя сохраняется массив компактных идентификаторов строк, а не раскрытых объектов.

## Ошибки и выбор реализации

Выбор `typescript` или `rust` выполняется до начала проверки. Ошибка Rust, несовместимая версия или повреждённый диапазон прерывают операцию; скрытый переход на TypeScript в середине запрещён. Закрытый reader отклоняет новые страницы.

Переход на TypeScript разрешён только при невозможности загрузить addon до открытия store. Отложенная проверка — часть штатного протокола, а не аварийный откат.

## Проверка корректности

- Общие контрактные тесты запускаются для TypeScript и Rust.
- Дифференциальные тесты сравнивают нормализованные диагностики по порядку и всем полям.
- Отдельные тесты покрывают отсутствие `cf`, заблокированные расширения, найденные/отсутствующие/неоднозначные цели, `!xml`, DataPath, fill value и structured documents.
- Проверяются страницы размером 1, 2 000 и больше общего числа проверок.
- Повреждённый `deferred`, неверный курсор и закрытый reader дают явную ошибку.
- Rust-тесты проверяют границы смещений, переполнения и детерминированность двоичного результата.

## Измерение

Ветка получает отдельный сценарий сравнения dependency validation, который запускает TypeScript и Rust в отдельных процессах на одном `project-state.bin`. Для каждого варианта выполняются пять прогонов; сообщаются медианы времени, CPU и RSS, количество диагностик, их SHA-256 и статистика native/deferred.

Дополнительно выполняется производственный прогон на временной копии `/Users/nikita/git/sed_xml/cf`. Существующий `validation-profile` сейчас ссылается на удалённый пакет `@nkdk/core`; его адаптация к `@nkdk/rules` должна быть отдельным изменением навыка и не входит в production-код этого слоя.

Если порог 20% не достигнут, Rust-реализация остаётся экспериментальной. Следующий перенос выбирается по статистике отложенных категорий, без включения backend по умолчанию.
