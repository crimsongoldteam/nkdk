# HomePageWorkArea YAML Design

## Цель

Реализовать полноценный YAML round-trip для корневого внешнего файла `Ext/HomePageWorkArea.xml`.

Текущее расхождение: при полном `XML -> YAML -> XML` файл `Ext/HomePageWorkArea.xml` удаляется, потому что рабочая область начальной страницы не представлена в YAML и не восстанавливается при `sync`.

## Источники

- `model.xdtobackend_root.res`: у `ConfigurationProperties` есть внешнее свойство `HomePageWorkArea`.
- `model.xdtobackend_root.res`: тип `HomePageWorkArea` содержит `WorkingAreaTemplate`, `Column`, `LeftColumn`, `RightColumn`, `MACommandInterfaceDisplays`.
- `model.xdtobackend_root.res`: элемент колонки `HomePageWorkAreaColumnItem` содержит `Form`, `Height`, `Visibility`.
- `ru-en-map`: `РабочаяОбластьНачальнойСтраницы` -> `HomePageWorkArea`.
- `/Users/nikita/git/roundTripElements/ext/HomePageWorkArea.xml`: компактная фикстура с двумя колонками, видимостью по роли и `MACommandInterfaceDisplays`.
- `/Users/nikita/git/round-trip-source/acc/Ext/HomePageWorkArea.xml`: реальный пример с длинными списками форм и ролей.
- `/Users/nikita/git/clean_cf`: чистая конфигурация без `Ext/HomePageWorkArea.xml`.

## Принятые решения

`HomePageWorkArea` пишется в корневой `Конфигурация.yaml` ключом `РабочаяОбластьНачальнойСтраницы`.

YAML-форма остается близкой к XML, но использует русские ключи и человекочитаемые значения перечислений:

```yaml
РабочаяОбластьНачальнойСтраницы:
  ШаблонРабочейОбласти: ДвеКолонкиПеременнойШирины
  ЛеваяКолонка:
    - Форма: CommonForm.НачалоРаботы
      Высота: 100
      Видимость:
        Общее: Истина
        Роли:
          ОператорОтправкиОтчетностиЧерезПредставителя: Ложь
  ПраваяКолонка:
    - Форма: DataProcessor.ИнформационныйЦентр.Form.ИнформационныйЦентр
      Высота: 10
      Видимость:
        Общее: Ложь
  ОтображениеКомандногоИнтерфейса: Верх
```

Для шаблона `OneColumn` используется ключ `Колонка`.
Для двухколоночных шаблонов используются ключи `ЛеваяКолонка` и `ПраваяКолонка`.
Если в reference был именно `Column`, экспорт должен восстановить `Column`; если YAML явно содержит `Колонка`, экспорт пишет `Column`.

Элемент колонки содержит:

- `Форма` -> `Form`;
- `Высота` -> `Height`;
- `Видимость` -> `Visibility`.

`Форма` использует существующий формат ссылок проекта, например `CommonForm.НачалоРаботы` или `DataProcessor.ИнформационныйЦентр.Form.ИнформационныйЦентр`.

`Visibility` пишется как объект `Общее` плюс словарь `Роли`, по тому же соглашению, что принято для `CommandInterface`.
В YAML роли выводятся без префикса `Role.`, например `Администратор`.
YAML-импорт должен принимать и `Администратор`, и `Role.Администратор`, а XML-экспорт восстанавливает `Role.Администратор`.
Если ключ видимости не является ссылкой на роль, он сохраняется как есть.

Технические идентификаторы и служебные XML-атрибуты не попадают в YAML.

## Перечисления

`WorkingAreaTemplate`:

- `OneColumn` -> `ОднаКолонка`;
- `TwoColumnsEqualWidth` -> `ДвеКолонкиРавнойШирины`;
- `TwoColumnsVariableWidth` -> `ДвеКолонкиПеременнойШирины`.

`MACommandInterfaceDisplays`:

- `Top` -> `Верх`;
- `Bottom` -> `Низ`;
- `None` -> `Нет`.

Если в XML появится неизвестное значение перечисления, YAML должен сохранить исходную строку без потери.

## Default-поведение

`РабочаяОбластьНачальнойСтраницы` является необязательным свойством.
Если в XML-выгрузке нет `Ext/HomePageWorkArea.xml`, YAML-ключ не создается.
Если в YAML нет ключа и нет reference-файла, экспорт не должен создавать новый `Ext/HomePageWorkArea.xml`.

Если YAML-ключ отсутствует, но reference содержит `Ext/HomePageWorkArea.xml`, экспорт сохраняет reference-файл только в сценарии сохранения существующего XML без изменения этой части модели.
Если YAML-ключ присутствует, XML строится из YAML.

## Архитектура

Добавить отдельный rule-driven тип для `HomePageWorkArea`, а не хранить внешний XML как непрозрачный файл.
Тип должен покрывать корневой объект, колонки и элементы колонок через правила, насколько это возможно.

Корневая конфигурация получает внешнее свойство:

- YAML: `РабочаяОбластьНачальнойСтраницы`;
- XML: `Ext/HomePageWorkArea.xml`;
- тип: общий объект `HomePageWorkArea`.

Для `Visibility` использовать тот же подход к выводу ролей, который принят для `CommandInterface`: формат роли должен управляться правилом свойства, чтобы существующие объекты по умолчанию сохраняли текущую полную форму.

`StartPageWorkingArea` из XDTO не вводится в эту работу: текущий diff касается только `HomePageWorkArea`, а отдельной XML-фикстуры для `StartPageWorkingArea` в исследованных данных нет.
Если такой файл появится, его нужно разобрать отдельным расхождением.
