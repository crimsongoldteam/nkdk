# Надёжность сборки standalone validation и проверки архитектуры

## Цель

Восстановить сборку `@nkdk/core` и `@nkdk/mcp`, а также исключить ложные
архитектурные нарушения после переключения или слияния git-веток.

## Установленные причины

### Сборка standalone validation

`generateProjectValidationAjvStandalone.ts` собирается как самостоятельная
точка входа. В отличие от основного `index.ts`, она не вызывает
`registerCoreMetadata()`. Импорт `project/specs.ts` поэтому выполняется до
заполнения реестров и останавливается диагностикой:

```text
Metadata не зарегистрирована перед операцией project/specs
```

### Проверка архитектуры

Файл `.dependency-cruiser-known-violations.json` не потерян. Он намеренно удалён
после устранения всех известных нарушений. Ложные 201 нарушение появились из
кэша dependency-cruiser, созданного до архитектурного рефакторинга.

Текущий механизм отключает кэш только при незакоммиченных изменениях исходного
кода. Чистое переключение или слияние ветки не считается причиной пересчёта,
хотя набор файлов и зависимостей уже изменился.

## Решение

### Самостоятельная точка входа генератора

Генератор standalone validation сам регистрирует metadata перед обращением к
реестрам проекта. Ответственность размещается в точке входа, а не дублируется в
build-скриптах core и MCP.

Защитная проверка `assertCoreMetadataRegistered` сохраняется: другие неверно
подключённые точки входа должны по-прежнему завершаться понятной ошибкой.

### Свежий граф архитектуры

Quality gate всегда запускает dependency-cruiser с `--no-cache`. Проверка
занимает около трёх секунд, поэтому надёжность важнее небольшой экономии времени.
Формат baseline, архитектурные правила и cycle-baseline не меняются.

## Проверки

1. Тест генератора запускает standalone generation без предварительной внешней
   регистрации metadata.
2. Тест построения dependency-графа закрепляет обязательный `--no-cache`.
3. `pnpm --filter @nkdk/core build` и `pnpm --filter @nkdk/mcp build` завершаются
   успешно.
4. `pnpm test:architecture` сообщает ноль новых нарушений.
5. Выполняются `pnpm type-check`, `pnpm test` и проверка новых дублей.

## Вне границ

- возвращение удалённого baseline;
- ослабление архитектурных правил;
- изменение содержимого генерируемых JSON Schema;
- исправление диагностик пользовательских конфигураций.
