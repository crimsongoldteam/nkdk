# Параллелизм round-trip-yaml

## Цель

Сократить длительность полного XML → YAML → XML на больших конфигурациях, не меняя диагностический договор и production sync.

## Решение

- `round-trip-yaml.sh` передаёт `concurrency: 4` как в `nkdk.import_from_xml`, так и в `nkdk.sync_to_xml`.
- Значение остаётся фиксированным: отдельный параметр запуска не добавляется.
- `refreshAndValidate` перед sync сохраняется. Он обнаруживает файлы проекта, сравнивает их с сохранённым состоянием, пересчитывает изменившиеся файлы, обновляет локальные и межфайловые diagnostics, фиксирует согласованное состояние и выдаёт read token для sync-workers.
- `ignoreValidationErrors: true` по-прежнему только разрешает продолжить sync при diagnostics; актуализацию состояния он не отключает.

## Проверка

Существующий тест скрипта расширяется проверкой, что оба MCP-входа содержат `concurrency: 4` и больше не содержат `concurrency: 1`.

Повторный ERP round-trip в границы изменения не входит: функциональный результат не меняется, а полный прогон занимает около 12 минут и оставляет диагностические XML-diff'ы во внешнем репозитории.
