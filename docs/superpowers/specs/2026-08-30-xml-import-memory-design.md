# Сокращение памяти XML-import

## Цель

Удерживать полный XML-import в пределах 4 ГиБ RSS при замедлении не более 10%.

## Наблюдение

Профиль `cf/doc` с четырьмя worker достиг 3936,7 МиБ RSS. Worker 0 удерживал
748 разобранных YAML: 29,9 МБ подготовленного входа и 12,6 МБ сериализованного
выхода занимали 542 МБ heap. Объектное представление увеличило удерживаемый
объём примерно в 12,8 раза.

## Решение

Второй проход после локальной проверки и контрольного XML-экспорта сразу
записывает готовый YAML и публикует его смысловое состояние. После записи
разобранный YAML, аннотации и сериализованные bytes освобождаются.

Третий проход не читает файлы без решений межфайловой проверки. Для редкого
файла с решением он читает уже записанный YAML, применяет `!xml/invalid` или
`!xml/important`, повторно выполняет локальную проверку для построения
окончательного состояния и перезаписывает тот же файл. Список результата
остаётся из второго прохода, поэтому повторных целевых путей нет.

## Ограничения

- XML-фикстуры не изменяются.
- `!xml` не применяется к новым свойствам или классам значений.
- При `NKDK_PROFILE=1` checkpoint после пачки должен показывать нулевое
  удержание тяжёлого входа и output второго прохода.
- Сравнение времени и Peak RSS выполняется на `cf/doc` с четырьмя worker.
