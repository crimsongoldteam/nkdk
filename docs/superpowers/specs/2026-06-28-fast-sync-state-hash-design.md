# Ускорить построение состояния XML-синхронизации

## Контекст

`nkdk init-sync-state <yaml-dir> <xml-dir>` нужен, чтобы создать начальный `.nkdk-sync.yaml` для инкрементальной синхронизации XML. Сейчас команда принимает `yamlDir`, но core-реализация фактически игнорирует готовый YAML-проект: создает временный каталог, заново импортирует XML в YAML, хеширует временный результат и удаляет его.

На большой ERP-конфигурации это делает команду существенно медленнее, чем ожидается. Если пользователю нужен временный импорт, для этого уже есть отдельные команды; `init-sync-state` должен только индексировать уже существующий YAML-проект.

## Цель

Сделать построение `.nkdk-sync.yaml` быстрым и прямым:

- читать файлы из переданного `yamlDir`;
- не выполнять XML -> YAML импорт внутри `init-sync-state`;
- использовать быстрый отпечаток файла вместо `sha256`;
- не добавлять параллельность на первом этапе, чтобы изменение было проще проверить и сравнить.

## Не цели

- Не оптимизировать импорт XML -> YAML.
- Не добавлять кэш по `mtime` или размеру файла.
- Не поддерживать чтение старых `sha256:` состояний. Старый индекс нужно пересоздать.
- Не менять планировщик инкрементальной XML-синхронизации.
- Не добавлять параллельное хеширование в этом изменении.

## Договор команды

CLI-команда сохраняет форму:

```bash
nkdk init-sync-state <yaml-dir> <xml-dir>
```

`yaml-dir` становится единственным источником файлов для индекса. `xml-dir` используется только как каталог записи `.nkdk-sync.yaml`.

Если YAML-каталог отсутствует или не читается, команда должна завершиться ошибкой. Она не должна пытаться восстановить YAML из XML.

## Хеширование

`hashProjectFiles` должен считать быстрый не криптографический хеш содержимого файла. Формат значения в `.nkdk-sync.yaml`:

```yaml
version: 1
files:
  Конфигурация.yaml: xxhash64:<hex>
```

Алгоритм нужен только для определения, изменился файл или нет. Криптографическая стойкость здесь не требуется. Предпочтительный вариант - `xxhash64`, потому что он заметно быстрее `sha256` на больших наборах файлов и хорошо подходит для контрольных отпечатков.

Чтение состояния должно считать корректным только новый формат `xxhash64:<hex>`. Если найден старый `sha256:` индекс, это ошибка состояния; пользователь должен пересоздать `.nkdk-sync.yaml`.

## Архитектура

`initializeXmlSyncState` получает явный `yamlDir`:

```ts
initializeXmlSyncState({
  yamlDir,
  xmlDir,
})
```

Функция вызывает `hashProjectFiles(yamlDir)`, затем `writeXmlSyncState(xmlDir, state)`. Параметры `createTempDir` и `importFromXML` больше не нужны для production-договора и должны уйти из основной реализации.

`hashProjectFiles` остается общей функцией для начального индекса и последующих инкрементальных `sync`. Поэтому переход на `xxhash64` ускорит оба сценария, но без изменения логики diff: сравнение по-прежнему идет по относительным путям и строкам хеша.

## Проверка

Тесты должны покрыть:

- `init-sync-state` передает `yamlDir` и `xmlDir` в core без скрытого импорта;
- `initializeXmlSyncState` строит состояние по существующему YAML-каталогу;
- `.nkdk-sync.yaml` содержит значения `xxhash64:<hex>`;
- `readXmlSyncState` отвергает состояние со старым `sha256:<hex>`;
- `syncConfigurationIncrementallyToXML` продолжает сравнивать состояния и обновлять `.nkdk-sync.yaml`.

Для ручной проверки на ERP:

```bash
nkdk init-sync-state /Users/nikita/git/nkdk-yaml /Users/nikita/git/round-trip/erp
```

Ожидаемый результат: команда не импортирует XML заново, записывает `.nkdk-sync.yaml` в XML-каталог и работает быстрее предыдущего полного прохода.
