# Производительность validation-схем при импорте

## Проблема

После перехода на экземплярный `RuleSchemaRuntime` validation cache стал
компилировать полностью развёрнутые inline-схемы. До разделения пакетов те же
правила экспортировались как граф: корневая схема ссылалась на один экземпляр
каждой общей схемы. Из-за повторного разворачивания компиляция 80 схем выросла
с 0,33 до 6,24 секунды на worker, а холодный e2e-импорт — с 7,2 до 33 секунд.

## Решение

Добавить в экземплярный `RuleSchemaRuntime` экспорт графа из одного или
нескольких корней. Экспорт использует принадлежащий runtime `RuleRegistrySet`,
одну сессию динамических схем и validation-ссылки. Результат содержит корни и
таблицу схем, необходимую `compileValidationSchema`.

`createValidationSchemaCache` будет компилировать этот граф вместо inline-схем.
Legacy fallback останется неизменным до его отдельного удаления. Глобальные
реестры и process-default runtime не возвращаются.

## Проверка

- Тест экземплярного schema runtime подтверждает, что общая property-схема
  вынесена в таблицу и используется через `$ref`.
- Существующие проверки подтверждают эквивалентность validation.
- Профиль точной e2e-фикстуры сравнивает холодный и тёплый импорт, стадии и RSS
  с коммитом до разделения пакетов.
