# Explicit external files round-trip design

## Проблема

При полном XML -> YAML -> XML часть файлов отображается в `git diff` как удалённая. Доказанный пример:

`CommonTemplates/UsnPartnersMergedScheme_v1_1_0/Ext/Template.bin`

Файл существует в XML-выгрузке, а его корневой объект имеет `<TemplateType>BinaryData</TemplateType>`. Сейчас `Template.bin` не представлен в YAML-слое и не добавляется в `XmlSyncManifest` при обратном `sync`. После успешной записи объектов `pruneXmlByManifest` удаляет все файлы в поддерживаемых XML-каталогах, которых нет в manifest, поэтому бинарный макет исчезает.

Та же причина затрагивает другие явно встречающиеся классы внешних файлов: HTML-макеты и их ресурсы, картинки элементов формы, ресурсы справки, XSD рядом с WS-ссылкой и вложенные подсистемы.

## Цель

Поддержать известные классы внешних файлов как явно описанные в `rules` файлы и каталоги, чтобы XML -> YAML -> XML сохранял их и добавлял в `XmlSyncManifest`.

Каждый поддержанный файл должен быть известен правилам: мы не копируем произвольные остатки из XML-дерева без описания в rules.

## Границы

- Не менять XML-фикстуры-источники.
- Не разбирать содержимое бинарных и HTML-ресурсных файлов.
- Не менять YAML-формат основных свойств metadata-объектов.
- Не отключать общий `pruneXmlByManifest`.
- Не вводить универсальное "скопировать всё неизвестное".
- Не моделировать содержимое внешних файлов как YAML-поля.

## Архитектура

Поддержка должна жить рядом с существующей синхронизацией внешних файлов:

- `packages/core/metadata/commonObjects/module/fromXML.ts` и `toXML.ts` уже обслуживают типы `Module` и `Template` для статических путей.
- `packages/core/metadata/commonObjects/childTemplateNames/syncExternalFromXML.ts` и `syncExternalToXML.ts` обслуживают объектные коллекции `Templates/<Имя>/Ext/...`.
- `packages/core/metadata/commonObjects/help/fromXML.ts` и `toXML.ts` обслуживают справку.
- `packages/core/metadata/forms/clientApplicationForm/convertFromXML.ts` и `syncToXML.ts` обслуживают файлы формы.
- `MetadataSubsystemRules`, `MetadataWSReferenceRules` и правила объектов с макетами должны явно описывать дополнительные внешние файлы.

В `PropertyRule` нужно добавить общий способ описывать внешние файлы, которые хранятся рядом с уже известным свойством, например:

- одиночный файл: `xmlPath` -> `nkdkPath`;
- каталог с ограниченным набором файлов: `xmlDir` -> `nkdkDir`, с допустимыми именами или расширениями;
- параметризованный путь от имени объекта, макета, формы или элемента формы.

Все такие файлы копируются байтово через `copyFile`; XML/HTML/bin/xsd/png/bmp/jpg не читаются как UTF-8, если их содержимое не является модельным YAML-значением.

## Поток данных

### Макеты

Для общего макета:

1. XML -> YAML копирует `CommonTemplates/<Имя>/Ext/Template.bin` в YAML-каталог объекта как внешний файл, например `Template.bin`.
2. YAML -> XML копирует этот файл обратно в `CommonTemplates/<Имя>/Ext/Template.bin`.
3. После копирования путь добавляется в `XmlSyncManifest`.
4. `pruneXmlByManifest` сохраняет файл.

Для макета внутри прикладного объекта:

1. XML -> YAML копирует `Templates/<Макет>/Ext/Template.bin` в каталог YAML-макета, например `Template.bin`.
2. YAML -> XML копирует файл обратно в `Templates/<Макет>/Ext/Template.bin`.
3. Путь добавляется в `XmlSyncManifest`.

Для HTML-макета:

1. XML -> YAML копирует `Templates/<Макет>/Ext/Template/*.html` и `Templates/<Макет>/Ext/Template/_files/*` в каталог YAML-макета под `Template/`.
2. YAML -> XML возвращает эти файлы обратно в `Templates/<Макет>/Ext/Template/...`.
3. Все скопированные пути добавляются в `XmlSyncManifest`.

### Файлы элементов формы

Файлы элементов формы хранятся в YAML-каталоге формы по имени элемента, аналогично внешним файлам запросов динамических списков:

- `Ext/Form/Items/<ИмяЭлемента>/Picture.<ext>` -> `Картинки/<ИмяЭлемента>.<ext>`;
- `Ext/Form/Items/<ИмяЭлемента>/ValuesPicture.<ext>` -> `КартинкиЗначений/<ИмяЭлемента>.<ext>`.

Правила конкретных элементов формы должны указывать, что элемент поддерживает `Picture` или `ValuesPicture`. Общий обход формы использует эти правила, копирует только известные файлы, а при YAML -> XML добавляет их в `XmlSyncManifest`.

### Справка

`Help` должен сохранять не только HTML-страницы, перечисленные в `Help.xml`, но и связанные ресурсы:

- `Ext/Help/_files/*`;
- при необходимости языковые каталоги вида `Ext/Help/<lang>_files/*`.

Эти файлы остаются непрозрачными ресурсами справки и копируются байтово.

### WS-ссылки

`MetadataWSReferenceRules` уже описывает `Ext/WSDefinition.xml`. Нужно явно описать дополнительные XSD-файлы рядом с ним:

- `Ext/*.xsd` -> каталог YAML WS-ссылки, например `XSD/*.xsd`;
- YAML -> XML возвращает их в `Ext/*.xsd` и добавляет в manifest.

### Вложенные подсистемы

`ChildSubsystemNames` сейчас описывает имена дочерних подсистем в основном XML, но configuration walker обходит только верхнеуровневые `Subsystems/*.xml`. Для вложенных подсистем нужно добавить явный рекурсивный внешний sync:

- XML -> YAML копирует `Subsystems/<Родитель>/Subsystems/<Дочерняя>.xml` и внешние файлы дочерней подсистемы в YAML-структуру дочерних подсистем;
- YAML -> XML восстанавливает ту же структуру и добавляет все созданные файлы в manifest;
- `CommandInterface.xml` и `Help` дочерней подсистемы проходят через те же правила, что и у верхнеуровневой подсистемы.

## Ошибки

Если внешний файл отсутствует, поведение остаётся прежним: копирование пропускается. Если файл есть, но не соответствует разрешённому правилу, он не копируется и останется кандидатом на удаление при `pruneXmlByManifest`. Это ожидаемое поведение для неизвестных файлов.

Если файл соответствует правилу, но копирование падает из-за файловой ошибки, ошибка должна всплыть как ошибка `import` или `sync`, как и для других внешних файлов.

## Тесты

Добавить точечные тесты:

- для `childTemplateNames`: XML -> YAML и YAML -> XML сохраняют `Ext/Template.bin`, `Ext/Template/ru.html` и файл из `Ext/Template/_files`;
- для `Template` общего макета: внешний `Template.bin` копируется туда и обратно;
- для формы: `Picture.png` попадает в `Картинки/<ИмяЭлемента>.png`, `ValuesPicture.bmp` попадает в `КартинкиЗначений/<ИмяЭлемента>.bmp`, оба возвращаются в `Ext/Form/Items/<ИмяЭлемента>/...`;
- для `Help`: ресурс из `Ext/Help/_files` сохраняется туда и обратно;
- для `WSReference`: `Ext/1.xsd` сохраняется туда и обратно;
- для `ChildSubsystemNames`: вложенная подсистема и её `Ext/CommandInterface.xml` сохраняются туда и обратно.

Проверка полного `round-trip-yaml` остаётся диагностической и не входит в минимальный тест этой задачи.
