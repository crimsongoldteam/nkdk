# Пропуск explicit XML omit при сборе структурных ссылок

## Контекст

XML-import управляемой формы выполняет локальную проверку сформированного YAML.
Во время этой проверки сборщик структурных ссылок преобразует через fromYAML
каждое присутствующее свойство, прежде чем определить, содержит ли оно ссылки.

Для реквизита формы с единственным типом `СписокЗначений` зарегистрирована
XML-аномалия: `ТипЗначения: !xml` означает, что исходный XML не содержал
`<Settings>`. Реестр `explicitXMLProperties` сопоставляет этому значению
действие `omit`, поэтому YAML → XML намеренно не вызывает TypeDescription
fromYAML и не создаёт `<Settings>`.

Сборщик структурных ссылок не учитывает это действие и передаёт пустой `!xml`
в TypeDescription fromYAML. Парсер ожидает содержательное значение с
XML-префиксом и выдаёт ошибку `ТипЗначения: недопустимое значение !xml для
типа`. Из-за этого корректная зарегистрированная аномалия блокирует XML-import.

## Цель

Не преобразовывать при сборе структурных ссылок свойства, для которых
составленный реестр `explicitXMLProperties` выбрал действие `omit`.

Незарегистрированный пустой `!xml` и содержательные варианты TypeDescription
остаются под действующими проверками.

## Решение

`StructuralReferenceRuntime` получает операцию, которая для текущего
metadata-item возвращает множество ключей свойств с выбранным действием
`omit`. Операция принимает:

- `itemType` текущего правила;
- YAML-объект;
- правила его свойств.

Оба адаптера сборщика структурных ссылок — локальная проверка YAML и операции
поиска/переименования ссылок — строят множество через существующий
`collectExplicitXMLPropertyActions`. В множество входят только действия
`kind: "omit"`.

Общий обход вычисляет множество один раз на metadata-item и пропускает
соответствующее свойство до вызова `valueFromYAML`. Остальные действия
explicit XML не меняются:

- содержательный `!xml` TypeDescription продолжает преобразовываться и
  участвовать в сборе ссылок;
- транспортные битые ссылки сохраняют существующую отдельную обработку;
- незарегистрированный `!xml` не получает действия `omit` и не скрывается.

Общий runtime не содержит условий по `FormAttribute`, имени `ТипЗначения` или
типу `СписокЗначений`. Предметное решение остаётся в составленном реестре
правил.

## Поток данных

1. Локальная проверка получает разобранный YAML формы.
2. Сборщик входит в `FormAttribute`.
3. Адаптер запрашивает действия explicit XML для объекта.
4. Реестр возвращает `omit` для свойства `valueType` при
   `ТипЗначения: !xml`.
5. Сборщик пропускает fromYAML этого свойства и продолжает обход остальных
   свойств и вложенных объектов.
6. YAML проходит локальную проверку; при последующем YAML → XML существующее
   действие `omit` не создаёт `<Settings>`.

## Проверки

Существующий тест сборщика структурных ссылок расширяется регрессионным
случаем на настоящих `metadataRules` и `ClientApplicationFormRules`:

- YAML содержит реквизит `СписокЗначений` и зарегистрированное
  `ТипЗначения: !xml`;
- сбор структурных ссылок завершается успешно и не создаёт ссылок для этого
  свойства.

Тест сначала должен падать с текущей ошибкой TypeDescription. После реализации
он проходит без изменения парсера TypeDescription. Существующие тесты
недопустимого пустого `!xml` продолжают защищать строгий договор.

После модульных проверок повторяется round-trip
`Tester_1_0_10_34_setup1c`: XML-import должен пройти дальше прежнего блокера.
Если обнаружится следующее независимое расхождение, диагностика
останавливается на нём согласно `round-trip-yaml`.

## Вне границ

- изменение YAML-представления XML-аномалии;
- добавление нового применения `!xml`;
- канонизация отсутствующего `<Settings>` в пустой элемент;
- изменение TypeDescription fromYAML;
- специальные условия для форм в нейтральных слоях runtime и validation.
