# Единые окончания строк XML

## Контекст

В репозитории XML-файлы хранятся неоднородно: часть записана в индексе Git с LF, часть — с CRLF, а `core.autocrlf=true` дополнительно выдаёт некоторые LF-файлы в рабочую копию с CRLF. Генератор NKDK уже формирует XML с LF, и существующие решения проекта не требуют сохранять CRLF исходного файла.

Из-за различий окончаний строк строковые сравнения XML зависят от операционной системы и могут давать ложные падения тестов.

## Решение

Добавить в корневой `.gitattributes` единственное правило:

```gitattributes
*.xml text eol=lf
```

Правило распространяется только на XML. Остальные типы файлов и пользовательская настройка `core.autocrlf` остаются без изменений.

Все уже отслеживаемые XML-файлы однократно нормализуются до LF. XML-содержимое, кодировка, порядок элементов и пробельные символы внутри строк не меняются; существующие XML-фикстуры остаются источником истины.

## Порядок изменения

1. Добавить `.gitattributes` с правилом для XML.
2. Нормализовать только отслеживаемые `*.xml`.
3. Убедиться, что в индексе Git среди XML больше нет `i/crlf` и `i/mixed`.
4. Убедиться, что XML в рабочей копии выдаются с LF независимо от `core.autocrlf=true`.
5. Проверить diff: допустимы только `.gitattributes` и замена окончаний строк в XML.

## Проверка

- `git ls-files --eol -- "*.xml"` показывает `i/lf w/lf` для всех отслеживаемых XML.
- `pnpm test` проходит на нормализованной рабочей копии.
- `pnpm duplicates -- --base 95ec6424bc9002a6a3fb7be545e80fbf521b9904` не обнаруживает новых недопустимых дубликатов.

Если полный набор тестов выявит содержательные ошибки, не связанные с окончаниями строк, они фиксируются отдельно и не входят в эту задачу.
