# Порядок TextEdit и ChoiceForm в InputField

## Контекст

Round-trip конфигурации Storekeeper меняет порядок соседних свойств обычного
`InputField`: исходный XML содержит `TextEdit`, затем `ChoiceForm`, а текущий
`InputFieldRules.xmlOrder` экспортирует их в обратном порядке.

Проверка всех конфигураций, кроме `all`, обнаружила два обычных `InputField` с
обоими свойствами — в Storekeeper и Cashdesk. В обоих случаях порядок одинаков:
`TextEdit` перед `ChoiceForm`. Обратных случаев нет. Для полей внутри таблиц найдено
12 случаев с тем же порядком; соответствующее табличное правило уже корректно.

## Решение

- Переместить `textEdit` перед `choiceForm` только в
  `InputFieldRules.xmlOrder`.
- Не менять `TableInputFieldRules`, YAML-представление и механизм reference.
- Добавить узкий тест экспорта обычного `InputField`, который проверяет порядок
  двух свойств в результирующем XML без reference.

## Критерии готовности

- Новый тест падает до изменения production-кода и проходит после него.
- Обычный `InputField` экспортирует `TextEdit` раньше `ChoiceForm`.
- Табличное правило остаётся без изменений.
- Целевые тесты, type-check, проверка дублей и полный `pnpm test` проходят.
