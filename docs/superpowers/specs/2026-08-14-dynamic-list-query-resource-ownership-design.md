# Владение файлами запросов динамического списка

## Цель

Устранить два связанных дефекта полного XML → YAML → XML round-trip:

- sync ошибочно копирует внутренний YAML-файл запроса динамического списка в
  XML-каталог как самостоятельный внешний файл формы;
- `round-trip-yaml` не сообщает о созданном файле, потому что собирает только
  изменения tracked-файлов.

После исправления текст запроса по-прежнему хранится в YAML-проекте отдельным
файлом `ДинамическийСписок/<имя>.query`, но при экспорте возвращается только в
`<QueryText>` файла `Form.xml`. Любой новый файл в XML-каталоге считается
round-trip расхождением и отображается runner наравне с изменением или
удалением tracked-файла.

## Наблюдаемый дефект

В Storekeeper файл

```text
ЖурналДокументов/Приемка/Формы/ФормаСписка/ДинамическийСписок/Список.query
```

является файловым представлением свойства `QueryText` в YAML. При sync
fromYAML читает его и восстанавливает `<QueryText>` внутри `Form.xml`, после
чего общий fallback внешних файлов формы повторно копирует тот же файл в:

```text
DocumentJournals/Приемка/Forms/ФормаСписка/Ext/ДинамическийСписок/Список.query
```

В исходной XML-выгрузке такого самостоятельного файла нет. Полученный `.query`
не отслеживается git, а текущий runner вызывает только `git diff`, поэтому
ошибочно сообщает о меньшем числе расхождений.

## Границы

В работу входят:

- декларативное закрепление владения файлами
  `ДинамическийСписок/<имя>.query` за содержимым `Form.xml`;
- сохранение общего fallback для настоящих неизвестных внешних файлов формы;
- обнаружение и показ untracked-файлов в single- и triage-режимах
  `round-trip-yaml`;
- обновление документации runner;
- постоянные регрессионные тесты на узких уровнях и итоговая проверка на
  Storekeeper.

В работу не входят:

- исправление других известных Storekeeper или Tester round-trip расхождений;
- изменение YAML-пути или формата `.query`;
- добавление специальных проверок расширения `.query` в общий sync;
- удаление fallback внешних файлов формы;
- изменение XML-фикстур.

## Топология ресурсов формы

Добавляется общий вид проектного ресурса `assignmentInput`: отдельный файл
проекта, который читается при построении связанного XML-задания, но не имеет
самостоятельного XML-пути. Для запроса формы декларация выглядит так:

```ts
{
  kind: "assignmentInput",
  assignmentProjectPattern: "",
  projectPattern: `${folderName}/{itemName}/ДинамическийСписок/{queryName}.query`,
}
```

Декларация создаётся правилом `ChildFormNames` в контексте дочерней формы,
рядом с её известными ресурсами. Параметр `itemName` обозначает имя формы, а
`queryName` — имя элемента динамического списка и файла запроса. Это не
специальная проверка `.query` внутри sync: связь с заданием задана топологией.

`assignmentInput` входит в обычное обнаружение ресурсов и хэши `.nkdk-sync.yaml`.
Его изменение, добавление или удаление в частичном sync выбирает связанное
задание `Форма.yaml`, но сам `assignmentInput` не входит в `assignments` и `externalFiles`
XML-плана. `PropertyRule.externalFile` по-прежнему читает файл при обработке формы.
Поток данных остаётся таким:

1. XML → YAML извлекает `<QueryText>` в
   `ДинамическийСписок/<имя>.query`.
2. YAML → XML читает `.query` при обработке свойства динамического списка.
3. Прочитанный текст записывается в `<QueryText>` файла `Form.xml`.
4. Обнаружение ресурсов классифицирует `.query` как `assignmentInput`,
   поэтому не планирует его копирование в `Ext`.
5. Остальные файлы формы, для которых нет более точной декларации, продолжают
   обрабатываться существующим fallback.

Если файл `.query` отсутствует, сохраняется действующее поведение
`PropertyRule.externalFile`; новая декларация не вводит отдельного режима
ошибок и не подменяет диагностику свойства.

## Диагностика новых файлов runner

После замены активного XML-каталога runner собирает единый список путей из:

- tracked-изменений и удалений, возвращаемых `git diff --name-only`;
- новых неигнорируемых файлов, возвращаемых
  `git ls-files --others --exclude-standard`.

Список дедуплицируется и сортируется по пути тем же способом для одиночного и
`--all-configs` запуска. Для tracked-файла текст расхождения по-прежнему
формируется через `git diff`. Для untracked-файла формируется unified diff
добавления файла относительно `/dev/null`.

Оба вида файлов проходят существующую фильтрацию известных допустимых
расхождений и добавляются в общие массивы `DIFF_FILES` и `DIFF_TEXTS`. Поэтому:

- `DIFF_COUNT` учитывает новые файлы;
- `--diff-index` может выбрать новый файл;
- triage показывает его в неизменном формате `TRIAGE_DIFF`;
- без `--all-configs` runner останавливается на первой конфигурации с любым
  видом расхождения;
- сообщение `Round-trip чистый: диффов нет` выводится только при отсутствии
  tracked- и untracked-расхождений.

Игнорируемые git файлы не считаются расхождением. Проверка чистоты активного
XML-каталога перед запуском не меняется и по-прежнему запрещает запуск поверх
любых заранее существовавших изменений.

## Проверки

Каждая постоянная проверка защищает отдельный договор:

1. В тесте project projection путь формы
   `ДинамическийСписок/Список.query` классифицируется как `assignmentInput`, а неизвестный
   внешний файл той же формы продолжает классифицироваться через fallback.
2. Интеграционный тест полного sync создаёт форму и `.query`, проверяет текст в
   `<QueryText>` итогового `Form.xml` и отсутствие самостоятельного файла
   `Ext/ДинамическийСписок/Список.query`.
3. Тест `round-trip-yaml` использует временный git-репозиторий с одним
   изменённым tracked-файлом и одним новым untracked-файлом. Он проверяет единый
   отсортированный список и unified diff добавления нового файла.
4. Итоговый запуск `round-trip-yaml` на Storekeeper подтверждает, что двенадцать
   обнаруженных ранее `.query` больше не появляются. Другие известные
   расхождения этой конфигурации не исправляются и не входят в критерий этой
   задачи.
5. Тест частичного sync проверяет изменение, добавление и удаление `.query`:
   во всех трёх случаях выбирается `Форма.yaml` и оба XML-документа формы.

Документация `round-trip-yaml/SKILL.md` заменяет утверждение о сборе расхождений
только через `git diff` на явный договор tracked- и untracked-файлов.

## Критерии готовности

- QueryText проходит XML → YAML → XML без изменения содержимого.
- Sync не создаёт самостоятельные `.query` в XML-каталоге.
- Неизвестные внешние файлы формы по-прежнему сохраняются fallback-механизмом.
- Runner показывает новый неигнорируемый файл как обычное round-trip
  расхождение во всех режимах.
- Целевые, полные и архитектурные проверки проекта проходят без изменения
  XML-фикстур.
