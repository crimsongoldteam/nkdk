# GraphicalSchemaField Edit Design

## Контекст

В полном XML → YAML → XML round-trip у элемента `GraphicalSchemaField` теряется явный тег:

```xml
<Edit>false</Edit>
```

Текущее правило оставляет свойство только во внутренней XML-модели через
`toYAML: false` и `fromYAML: false`. Это сохраняет тег в коротком XML → модель → XML round-trip,
но исключает его из YAML и поэтому не может восстановить тег после полного round-trip.

## Договор платформы

В XDTO-схеме управляемой формы свойство `GraphicalSchemaField.Edit` имеет тип `xs:boolean`,
необязательный XML-тег и значение по умолчанию `true`. Конфигуратор также показывает
`Истина` как значение по умолчанию.

Следовательно, смысловой договор имеет два состояния:

| XML | Конфигуратор | YAML |
|---|---|---|
| тег отсутствует | `Истина` | поле отсутствует |
| `<Edit>false</Edit>` | `Ложь` | `Редактирование: Ложь` |

Явный `<Edit>true</Edit>` семантически совпадает с отсутствующим тегом и при канонической выгрузке
может быть заменён отсутствием тега.

## Статистика конфигураций

Во всех конфигурациях `/Users/nikita/git/round-trip-compact/cf` найдено 28 элементов
`GraphicalSchemaField`:

- явный `<Edit>false</Edit>` — 15;
- явный `<Edit>true</Edit>` — 0;
- тег отсутствует — 13.

Значение нельзя вычислять из соседних свойств. Все 15 явных `false` встречаются при
`ReadOnly=true`, но ещё 6 элементов имеют `ReadOnly=true` без `Edit`. `DataPath` также не даёт
однозначного признака.

В `cf/doc` расхождение проявляется в форме
`DataProcessors/КартаМаршрутаБизнесПроцесса/Forms/Форма/Ext/Form.xml` у элемента
`КартаМаршрута`.

## Решение

Сделать `Edit` обычным смысловым свойством YAML с неявной `Истиной`:

```ts
edit: booleanRule({
  yaml: "Редактирование",
  implicitValueYAML: true,
  toEnterprise: false,
})
```

Удалить `toYAML: false` и `fromYAML: false`. `toEnterprise: false` сохранить: решение относится
только к XML/YAML-представлению формы.

Результат:

- отсутствующий XML-тег не создаёт ключ YAML;
- явный XML `false` создаёт `Редактирование: Ложь`;
- `Редактирование: Ложь` восстанавливает `<Edit>false</Edit>`;
- отсутствующий ключ YAML не создаёт XML-тег, так как означает платформенное значение по умолчанию
  `Истина`.

Отдельные преобразователи, reference, configuration index и правила по `ReadOnly` или `DataPath`
не нужны.

## Архитектурные границы

- Правило остаётся рядом с `GraphicalSchemaField` и не добавляет знания об элементе формы в общие
  metadata-слои.
- Не восстанавливать `<Edit>false</Edit>` по косвенным признакам.
- Не сохранять явный `<Edit>true</Edit>` как отдельное состояние: платформа задаёт ту же семантику
  отсутствующим тегом, а в исследованных конфигурациях такое представление не встречается.
- Расхождение не добавляется в `.agents/restrictions.md`, потому что точный смысловой round-trip
  достижим через YAML.

## Проверки

- Расширить существующий тест правила `GraphicalSchemaField`: `implicitValueYAML: true`,
  `toEnterprise: false`, без `toYAML: false` и `fromYAML: false`.
- Проверить XML → YAML → XML для отсутствующего `Edit` и явного `false`.
- Убедиться, что `Редактирование: Ложь` восстанавливает `<Edit>false</Edit>`.
- Запустить целевые тесты формы, затем `pnpm type-check`, `pnpm test`, `pnpm duplicates`.
- Stryker не запускать.
- Итоговый round-trip `cf/doc` не должен содержать расхождение `Edit`.
