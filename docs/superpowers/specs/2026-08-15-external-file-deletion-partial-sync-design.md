# Удаление внешнего файла при частичной синхронизации

## Цель

Частичная синхронизация должна поддерживать удаление внешнего файла metadata,
связанного с XML-заданием владельца. Представительный случай — удаление модуля
команды при сохранении самой команды и её владельца.

## Подтверждённое поведение платформы

Прямое удаление `Справочник/.../Команды/ПроверочнаяКоманда.bsl` сейчас
останавливается в планировщике с диагностикой «Удалённый внешний файл нельзя
включить в XML-пакет».

Диагностический прогон на копии контрольной точки подтвердил следующий договор:

- в пакет включается XML-задание владельца;
- связанные с этим XML оставшиеся внешние файлы включаются существующим
  механизмом `selection.manifestPattern`;
- удалённый файл в пакет не включается;
- XML владельца является целью загрузки;
- после загрузки и обратной выгрузки удалённый модуль отсутствует.

Передача пустого внешнего файла не требуется.

## Изменение планировщика

Во втором проходе удалений `impactPlanner` обрабатывает внешний файл следующим
образом:

1. Если удаление уже поглощено структурным удалением коллекции или владельца,
   сохраняется текущее поведение.
2. Если у внешнего файла есть связанное XML-задание, планировщик находит его
   текущий ресурс по `assignment.projectPattern` и включает это задание с
   запросом загрузки.
3. Удалённый внешний путь не добавляется ни в `selection`, ни в
   `externalProjectPaths`, ни в ZIP.
4. Если текущее XML-задание владельца отсутствует, формируется точная
   диагностическая ошибка.
5. Внешний файл без XML-задания по-прежнему запрещён: у него нет переносимого
   способа выразить удаление.

Новых признаков в resource topology и общих типах правил не добавляется.

## Совместное изменение владельца

Если владелец уже включён из-за собственного изменения, удаление внешнего файла
использует то же состояние задания. Множества планировщика устраняют повторы,
поэтому состав пакета и `loadTargets` остаются детерминированными.

## Проверки

Модульные тесты планировщика должны подтвердить:

- удаление внешнего файла включает владельца и не включает удалённый путь;
- оставшиеся внешние файлы того же XML-задания сохраняются в пакете;
- совместное изменение владельца не создаёт повторов;
- внешний файл без XML-задания остаётся запрещённым.

После исправления полный автономный partial e2e продолжается с контрольной точки
после `module:object:add:probe`, начиная с `module:command:remove:probe`. Затем
та же матрица выполняется в агентном режиме конфигуратора.
