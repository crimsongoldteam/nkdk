# Ограничение удаления отдельного внешнего модуля

## Решение

Отдельное удаление внешнего модуля пока не поддерживается частичной
синхронизацией. Операция исключается из partial e2e и фиксируется в
`.agents/restrictions.md` до отдельного исследования платформенного договора.

## Причина

Планировщик не может включить удалённый файл в ZIP. Диагностический эксперимент
показал, что загрузка только XML владельца удаляет нужный модуль команды, но
одновременно очищает другие отсутствующие в пакете файловые части объекта:
модуль объекта и модуль формы.

Безопасный минимальный состав пакета пока не установлен. Возможные варианты —
включение полного текущего поддерева владельца либо специальное представление
удаления внешнего файла — требуют отдельного исследования на разных видах
модулей и владельцев.

## Граница сценария

Из декларативной матрицы исключаются отдельные блоки:

- `module:command:remove` — отдельное удаление модуля команды;
- `module:object:remove` — отдельное удаление модуля объекта;
- `module:form:remove` — отдельное удаление модуля формы.

Прежний `module:command:add` заменяется безопасным
`module:command:restore`, который восстанавливает исходный текст переходом
`изменённый → исходный` без удаления файла. Создание модуля команды по-прежнему
проверяется вместе с созданием команды, а отдельное изменение — блоком
`module:command:change`.
Добавление и изменение модулей формы и объекта остаются в матрице. Добавленные
модули удаляются только в одном блоке с формой или прикладным объектом, поэтому
проверяется безопасный вариант удаления файлового подобъекта вместе с владельцем.

План содержит 96 блоков: завершающая пара расширения проверяет сохранение
корневых сопутствующих XML. Изменение HTML-файла справки исключено до отдельного
исследования безопасного состава частичного ZIP с `Ext/Help.xml`; ограничение
зафиксировано в `.agents/restrictions.md`.

## Проверки

- unit-тест матрицы подтверждает отсутствие запрещённой пары и сохранение
  остальных операций модулей;
- текстовые переходы e2e сравнивают `before` после преобразования CRLF и CR в
  LF, а `after` записывается в декларативной LF-форме; бинарные файлы остаются
  побайтово строгими;
- `.agents/restrictions.md` описывает причину и границу ограничения;
- автономный partial e2e продолжается с сохранённой контрольной точки;
- полный агентный прогон использует ту же сокращённую матрицу.
