# Единый список допустимых типов реквизитов

## Контекст

При экспорте `/Users/nikita/git/test-yaml` в XML команда `sync` падает на типе `СправочникСсылка.Контрагенты`: YAML-импорт `TypeDescription` не распознает базу `СправочникСсылка`, оставляет строку в модели как неизвестный тип, а XML-экспорт затем не находит для нее `TypeDescriptionRules`.

Текущий договор YAML для ссылочных типов короче интерфейсных имен 1С:

- `Справочник.Контрагенты`, а не `СправочникСсылка.Контрагенты`;
- `Документ.Заказ`, а не `ДокументСсылка.Заказ`;
- аналогично для перечислений, планов, задач, бизнес-процессов и планов обмена.

Скриншоты 1С показывают, что реквизит документа и реквизит табличной части имеют тот же набор разрешенных видов типов, что уже описан для реквизита справочника.

## Решение

Не добавлять YAML-алиасы с суффиксом `Ссылка`. Каноническим YAML-представлением остаются короткие имена из текущего `TypeDescription`: `Справочник.*`, `Документ.*`, `Перечисление.*` и так далее.

Существующий список `CATALOG_ATTRIBUTE_ALLOWED_TYPES` нужно переименовать в более общее имя `METADATA_ATTRIBUTE_ALLOWED_TYPES` и использовать его для всех обычных реквизитов:

- `MetadataCatalogAttributeRules`;
- `MetadataDocumentAttributeRules`;
- `MetadataTabularSectionAttributeRules`.

Список остается в общем модуле правил реквизитов, потому что он описывает домен `MetadataAttribute`, а не конкретный прикладной объект.

## Поведение

Для реквизитов справочника, документа и табличной части схема должна разрешать:

- примитивы: `Строка`, `Число`, `Дата`, `Булево`;
- служебные типы: `ХранилищеЗначения`, `УникальныйИдентификатор`;
- ссылочные и объектные семейства из текущего списка `METADATA_ATTRIBUTE_ALLOWED_TYPES`;
- внешние источники данных в уже существующем коротком YAML-формате.

Схема должна запрещать строки вида `СправочникСсылка.Контрагенты`, `ДокументСсылка.Заказ`, `ПеречислениеСсылка.Статусы`. Такие значения считаются ошибкой YAML-договора и должны обнаруживаться на `validate`, а не только на `sync`.

## Проверки

Нужно добавить тесты, которые фиксируют:

- реквизит документа принимает `Тип: Справочник.Контрагенты`;
- реквизит документа отклоняет `Тип: СправочникСсылка.Контрагенты`;
- реквизит табличной части принимает `Тип: Справочник.Контрагенты`;
- реквизит табличной части отклоняет `Тип: СправочникСсылка.Контрагенты`;
- существующие проверки реквизита справочника продолжают проходить после переименования списка.

Финальная проверка перед завершением: `pnpm test` из корня рабочей ветки.
