# Коллекции и небольшие составные договоры

| Common | Наблюдаемый договор | Конструкции и существенные проверки |
|---|---|---|
| `choiceList` | xr:Item/xr:Value → список FormChoiceList; пустое одиночное вхождение и пустое среди повторов ведут себя по-разному. | Collection + nested MetadataValue/Presentation; неизменные оболочки; проверить пустой элемент, nil, представление и порядок. |
| `fieldsList` | Field либо xr:Field по параметру; список строк; есть различия пустой карты, пустого списка и отсутствия. | Collection со сменным XML-name и таблицей presence; не унифицировать пустоты до проверки обратимости. |
| `indexField` | Список Field, scalar/array форма XML; одно пустое вхождение даёт пустой список. | Collection<string>; отдельно проверить пустоту, один/несколько элементов и действительный уровень проверки ссылок. |
| `childSubsystemNames` | Список имён с одиночной XML-формой, YAML через базовые string/list операции. | Collection<name>, параметры папки/владельца; пустой список, повторные имена и наличие дочернего объекта. |
| `commonAttributeContent` | xr:Item с объектом метаданных, использованием и условным разделением; YAML список объектов. | Record, enum, reference; условное поле; пустое вхождение и присутствие ConditionalSeparation. |
| `functionalOptionsProperty` | Item-список строк сохраняет в том числе пустой Item. | Collection<reference/string согласно подключению>; отсутствие и пустой элемент различать; не фильтровать пустые значения. |
| `usePurposes` | Набор PlatformApplication/MobilePlatformApplication сокращается до двух русских вариантов; platform-only не выдаётся в YAML. | Конечная таблица «набор ↔ shorthand» + declared default, не произвольный set-converter; проверить только platform, только mobile, оба, дубли и исходный порядок через proof. |
| `userSettingsID` | YAML строка либо boolean-подобное значение; XML выводит только строковый идентификатор. | Union identity/presence directive; нельзя обещать полную обратимость boolean без политики владельца, создающей ID. Проверить применение потребителями. |
| `userVisible` | Общий флаг и значения по ролям; YAML Разрешить/Роли, default общий true опускается; есть UUID/пустые ссылки и адреса ключей. | Record + keyed collection + conditional default + role reference. Проверить общий false, пустую коллекцию, роль/UUID, дубли и аннотации. |
| `webSocketClientHeaders` | Список Ключ/Значение; XML xr:Item и типизированные значения. Порядок и повторные заголовки не сводятся к карте. | Collection<Record>; строки и фиксированные служебные оболочки; проверить отсутствие Key/Value, пустую строку, повтор имени. |
| `xDTOPackages` | Список строк в xr:Item/xr:Value с типом и служебными полями. | Collection со статической оболочкой; проверить пустой список, пустой item, значение без ожидаемого XML-типа. |
| `mobileDeviceCommandBarContent` | Коллекция MetadataValue в xr:Item; пока фильтрует неподдержанные результаты. | Collection<choice>; фиксация потерь через общий proof, а не узаконивание фильтрации; проверить typed варианты и пустые элементы. |
| `inputByStringFields` | Обёртка FieldsList с default по owner YAML и evaluateWhenYAMLMissing. | Параметризованная декларация с вычислением из входов, без callback implicitValueYAML. Проверить сочетания полей владельца, явное [] и отсутствие. |
| `сhoiceParameterLinks` | Названия и DataPath + режим изменения, обычный XML и DCS-профиль. YAML список либо строка со скобками; parser учитывает глубину скобок. | Record/collection + сбалансированная грамматика текстового представления. Простого split(',') недостаточно. Проверить вложенные скобки, незакрытые формы, режим НеИзменять и разные XML-профили. |
| `сhoiceParameters` | Имя → MetadataValue; XML app:item; DCS-профиль; пустой объект/undefined/null являются допускаемыми формами значения; явный FormChoiceList требует wrapper Тип. | Keyed collection с вариантами отсутствия и значений; проверить повтор имён, nil/typed-empty, formChoiceList и namespace. |

Кириллическая первая `с` в двух именах каталогов сохранена намеренно. Реестр должен опираться на точные пути, а не визуально похожие латинские имена.

Нельзя объявить общее поведение «пустая коллекция всегда удаляется»: уже эта группа показывает несовместимые договоры пустого контейнера и пустого item. Поведение присутствия принадлежит подключению/варианту и проверяется отдельно от кардинальности.
