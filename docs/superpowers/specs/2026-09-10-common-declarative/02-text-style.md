## Исправление упрощённого примера из обсуждения

`sequence: preserve` недостаточно: одновременно нужны ожидаемый порядок, фактический порядок и правило диагностики. Уникальность является смысловым ограничением, а не поводом заменить коллекцию словарём. Shorthand допустим только при однозначном восстановлении, включая наличие/отсутствие аннотаций.

Актуальны общие `!xml/invalid` на ключе/карте и нумерация повторных логических ключей. Исторические `!xml/language`, `!xml/order`, `!xml/duplicate` не возвращаются. Raw разрешён по действующему договору на минимальной границе item и назначается механизмом обратимости, не оператором «обойти неизвестный язык».

Служебные коды требуют отдельного условия применимости: `validateLocalizedTextYAMLProperty` в `packages/runtime/metadata/validation/localizedTextYAML.ts` при наличии хотя бы одного `#` или пустого кода возвращается до проверок порядка, зарегистрированности и пустых значений всей карты. Это не отключает структурную схему и остальные механизмы проверки. Напротив, XML-импорт в `fromXMLToYAML.ts` определяет неизвестные языки отдельно для каждого вхождения, исключая только сам служебный код. Обе области применимости нужно явно выразить в одной декларации; предметный смысл служебных кодов ещё предстоит установить.

Канонический порядок проверяется по первым вхождениям уникальных кодов: основной язык первым, остальные — по сравнению строк операторами `<`/`>` JavaScript, то есть по кодовым единицам UTF-16. Rust-сортировка по UTF-8 не объявляется автоматически эквивалентной для произвольного текста; для обычных ASCII-кодов результат совпадает. Проверка уникальности остаётся отдельной.

Структурная схема I8nText сейчас запрещает пустые строки в обычной карте и допускает их в сворачиваемом профиле. При этом строковая форма допускается отдельно. В целевом правиле ограничения принадлежат вариантам представления; нельзя бездумно повесить minLength на весь смысловой текст.

## Внешняя проекция Enterprise

У этих каталогов есть `toEnterprise`. Это отдельная существующая проекция, не стадия XML ↔ YAML. Она учтена, чтобы миграция не потеряла её незаметно; полный договор Enterprise не является условием готовности рассматриваемого двустороннего интерфейса. В дальнейшем её можно выводить из той же смысловой структуры отдельной декларативной проекцией.

[Матрица 256 полных проходов](02-i8n-profile-matrix.md) дополняет атомарные наблюдения проверкой окончательного YAML и контрольного XML. 222 прохода сохранили XML; 34 выявили сбой назначения raw-границы при пропуске пустоты. ## Независимые ожидания FormattedI8nText

В conversion-corpus добавлены formatted-i8n-empty-true, formatted-i8n-primary-true и formatted-i8n-primary-false. XML написан отдельно по действующим fromYAML/toYAML/toXML и fixture data.ts; существующие фикстуры не менялись. Сравнение XML структурное, YAML точное; Rust-прогон ещё требуется.

- `<Title formatted="true"/>` соответствует `Заголовок: {Форматированный: Истина}`: пустая коллекция, объект присутствует. Имя не должно неявно добавлять перевод в этой явно указанной форме.
- Непустой основной перевод при true сохраняет оба YAML-поля, при false — только Текст; XML сохраняет явный boolean-атрибут в обоих случаях.
- Отсутствующий объект, пустая оболочка без атрибута и formatted=false без текста требуют отдельных presence/proof ожиданий. Они не приравнены к примеру true без текста.

`formatted` является смысловым полем. Каноническая with-attributes оболочка для постоянного xsi:type не заменяет его: необходимы отдельное boolean-поле и текстовая коллекция в общей XML-оболочке. Условие YAML запрещает явное `Форматированный: Ложь`, допускает отсутствие признака с текстом и один признак Истина без текста. Вложенные проверки I8nText должны подключаться из общей декларации.
