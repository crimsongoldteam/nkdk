# Скалярные значения, даты и простые составные значения

Исследованы типы, оба направления, схемы и регистрации соответствующих каталогов. Список исходников и существующих тестов приводится в реестре. Ниже «проверить» означает требование к будущему переносу, а не отчёт о выполнении тестов.

Схема исключает implicit, если не включено сохранение явного default. | Типизированная таблица значений; каноническое представление и отдельно принимаемые входные формы; presence/default; пределы принятия некорректного значения. | Оба значения; чужой токен; отсутствие; явный implicit; отличие низкоуровневого допуска boolean от публичной схемы. |

## Следствия для языка

Одной пары «XML-тип/YAML-тип» недостаточно. Нужны смысловой тип, лексическое представление, принимаемые варианты, канонический вариант, ограничения и присутствие. Более терпимый parser не расширяет автоматически публичную YAML-схему. Общая календарная и числовая библиотека допустима как механизм языка; специальная функция конкретного common — нет.

В `boolean`, `string`, `number` уже есть `atomicConversion.ts`: объединённые переходы XML→YAML/YAML→XML выбираются при компиляции правила. Boolean переиспользует неизменяемые результаты, Number заранее вычисляет XML-тип. Это полезный образец устранения промежуточных вызовов, но пока он реализован отдельными функциями. Целевой компилятор должен получать такие специализированные переходы из декларации и сохранять различие смыслового значения и его представления без обязательного выделения объекта для этой пары.

## Реализованная основа присутствия скаляров

Для обычного boolean подключено двустороннее отсутствие, заданное в самой декларации:

```yaml
presence:
  - target: self
    xml: {missing: {denotes: {absent: true}}}
    yaml: {missing: {denotes: {absent: true}}}
```

Общий генератор хранит такое поле как `Option<T>`; пропуск не подменяет false, ноль или пустую строку. XML-экспорт всегда сохраняет корень документа, даже если все поля отсутствуют. Структурная схема делает поле необязательным, не расширяя перечень его допустимых значений. Неизвестный XML-токен и пустой boolean-узел отвергаются, а не молча превращаются в отсутствие. Внутренний TS-переходник, принимающий JS boolean, не расширяет публичный договор YAML: там остаются Истина/Ложь.

Этот механизм не объявляет готовыми default/implicit и сохранение явного значения по умолчанию в правилах владельца. Другие формы presence и ограничения владельца с необязательными скалярами компилятор пока явно отвергает; их нельзя молча игнорировать. Поэтому флажок полного переноса boolean остаётся пустым.

Проверены точные существующие пары boolean, отдельные границы отсутствия/недопустимых токенов и согласованность JSON Schema. Через рабочую команду конвертера проверены 67 свойств e2e: 47 true, 5 false, 15 отсутствующих. Это договор простого значения Server/UseStandardCommands, без сокращений владельца и без полного преобразования проекта.
