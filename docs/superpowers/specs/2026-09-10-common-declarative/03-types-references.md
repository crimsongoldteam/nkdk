# Типы, значения и ссылки

| Common | Наблюдаемое поведение | Целевые конструкции | Проверки и границы |
|---|---|---|---|
| `metadataPath` | Таблицы переводов видов/членов, явный или относительный владелец, сокращение прозрачных сегментов; DataPath использует отдельный контекст стандартных членов. | Декларативная грамматика пути с таблицами сегментов и типизированным индексом; обратное восстановление сокращённых сегментов. | Неоднозначная ссылка, явный/относительный владелец, стандартный член, неизвестный вид. Грамматика пути и его существование — разные ограничения. |
| `metadataRef` | Одиночная MetadataItemLink и список MetadataItemLinks; typed xr:MDObjectRef; у пустого списка отдельное XML-представление. | Reference + collection + XML wrapper + presence. | Empty list против отсутствия; неверный корень, типизированная ссылка, UUID occurrence. |
| `metadataField` | MetadataField/MetadataFields переводят путь члена с учётом owner; XML имеет одиночную/коллекционную оболочку. | Use грамматики member-path; ограничение цели; параметр владельца. | Один/несколько путей, недостающая XML-оболочка, неоднозначность owner. |
| `metadataObjectRefCollection` | Коллекция ссылок, экспорт элементов через MetadataValue с именем XML-типа ссылки. | Коллекция типизированных reference-значений; common MetadataValue как декларативная композиция. | EmptyRef/обычная ссылка, тип элемента и xsi:type, пустой список. |
| `metadataTargets` | Значительная часть каталога — реэкспорт runtime. Здесь остаются materializer, validation handlers, occurrence сборщики, временные ключи. Проверка и переименование работают не только со строковым полем, но и ключами/элементами. | Reference declaration должна породить parse/format, требования к индексу, проверку, вклад зависимости и адрес изменения. Временные YAML-ключи остаются внутренним механизмом. | UUID без lookup, missing/неготовый индекс, ссылки в ключах, вторичная ссылка на базовый регистр расчёта, фильтры целей. |
| `metadataTargetProjectResolvers` | Вклад индекса для Commands, AccountingFlags, ExtDimensionAccountingFlags, Fields, Dimensions, Resources; читает model facts либо YAML. | Декларативная проекция коллекции в индекс: имя/вид/владелец/файл. Подготовка вне конвертации значения. | Коллекция в scalar/list/map форме; одинаковые имена в разных owner; полный набор индексируемых элементов. |
| `xdtoTypeName` | XML QName разрешается через namespace; YAML namespace+name. Экспорт выбирает xs/v8 либо контекстный префикс d6p1/d8p1. | QName как смысловая пара URI+local name; профиль пространства имён передаётся владельцем. | Унаследованный namespace, одинаковый local name при разных URI, отсутствие prefix binding, сохранение допустимой исходной формы. Частное условие по `rule.xml === XDTOValueType` заменить параметром подключения. |
| `typeLink` | XML DataPath+LinkItem; YAML путь с необязательным `(n)`, n=0 подразумевается. Есть отдельная DCS-оболочка. | Record с текстовым шаблоном и обратным разбором; число и ссылка; XML-профиль. | Суффикс, ноль, отсутствие DataPath, вложенные пути и DCS. |
| `typeDescription` | Коллекция Type/TypeSet/TypeId, общие qualifiers строки/числа/даты; scalar/list YAML. Большая таблица видов, AnyRef→AnyIBRef, внешние источники, allowedTypes и совместимость состава. | Union с таблицей QName/видов, грамматики `Строка(n)` и `Число(n,m)`, ограничения состава, объявленные ссылки. Различать declared и effective type. | TypeSet против Type, разные qualifiers, TypeId, запрещённый состав с адресом элемента, namespace aliases, multi-state пустой вариант. |
| `metadataValue` | Размеченный union примитивов, enum, ссылок, fixedArray, formChoiceList, standardPeriod, valueList, AssociatedTable. YAML-синтаксис и quoted-string влияют на выбор типа; значение ограничивается valueType. Отсутствие может экспортировать nil или typed-empty; у FillValue строкового типа есть контекстное исключение. | Общий choice с явно заданными областями выбора/приоритетами, YAML lexical style, рекурсивная collection, record, presence, вход declared type вместо проверки имени поля. | Число и строка «1», строка «Истина», дата и текст, UUID, nullable элементы массивов, явный тип значения списка, ограничения valueType во всех ветвях. |
| `fillValue` | Договор распределён между analyzeItem, register, type semantics runtime и pending project checks. Вычисляются effective type, implicit/invalid/unresolved, допустимые ссылки и owner-specific policy. | Общие match/constraints по разметке типа; набор допустимых альтернатив; декларативное вычисление подразумеваемого значения; подготовка графа DefinedType и ссылочных фактов. | Цикл/отсутствующий DefinedType, составной тип, фиксированная длина, разрядность/дробность/знак, начальная дата, EmptyRef, владельцы, обычный/стандартный реквизит, расширение; Type после FillValue. |

## Требования, которые нельзя спрятать за именем компонента

`resolveDefinedType`, `classifyFillValue`, `parseMetadataPath`, `normalizeSynonym` не становятся декларативными от переименования функции в operation. Для них нужно разложение на общие конструкции и предметные таблицы. Кандидаты: конечный выбор, проверка множества альтернатив, безопасная грамматика строк, проекция/поиск в индексе, обход ссылочного графа с состояниями visited/resolving/resolved. Последний требует отдельного договора ограничений и диагностики цикла; текущая спецификация не выдаёт его за готовую грамматику.

Нынешнее размещение предметной FillValue-классификации в `packages/runtime/.../fillValueSemantics.ts` не является целевой границей: ядро не должно знать 1С-типы. Семантика типов остаётся декларациями common; общий обход графа и числовая/строковая проверка — механизмами языка.

## Составные части MetadataValue

- `fixedArray/*`: реэкспорты обработки рекурсивного массива; один/несколько XML Value, null → xsi:nil.
- `formChoiceList/*`: общий Record Presentation:I8nText + Value:MetadataValue и особый явный вариант внутри массива. Считается отдельным вариантом договора, не пропущенным из-за реэкспорта.
- `AssociatedTable`: отдельная строковая проекция со схемой; не приравнивать автоматически к проверенной ссылке на физическую таблицу.
- `handlers.ts`: существующие функции примитивов должны превратиться в описания форматов, enum и references; точные отличия календарных форматов от общего dateTime сохраняются.

## Связанные источники вне common

Проверять вместе с `packages/runtime/metadata/ruleRuntime/property/fillValueSemantics.ts`, `packages/rules/metadata/validation/projectValidationPendingChecks.ts`, `packages/rules/metadata/validation/projectStateDependencyValidation.ts`, runtime metadataTarget и `packages/rules/metadata/validation/dataPath/`. Нейтральная validation исполняет собранные декларации и не получает новых частных веток common.
