# Предлагаемый общий интерфейс

Это проект языка на основании обзора всех common-каталогов, а не уже реализованный компилятор или 90 законченных деклараций. Имена ключей в примерах предлагаются для обсуждения. Область каждого оператора и ограничения обратимости ниже важнее окончательного написания ключа.

## Четыре части одного договора

1. **Смысловой тип**: допустимая структура и различимые состояния значения.
2. **Представления XML/YAML**: как та же структура читается и записывается; короткие формы определяются через полное значение, которое они обозначают.
3. **Ограничения**: структурные, межполей и по подготовленным фактам; диагностический код, адрес, применимость уже разрешённых аннотаций.
4. **Входы и вклады**: параметры владельца, зависимости от полей/индексов, identities и ресурсы; только через объявленные типизированные связи.

Связь форматов сама по себе не определяет бизнес-валидацию. Ограничения должны быть записаны в том же компоненте, а не автоматически угаданы по XML или примерам.

## Необходимые общие конструкции

| Конструкция | Семантика | Основание в common |
|---|---|---|
| `scalar` | Строка, boolean, число, календарное значение; формат и лексика задаются отдельно. | boolean/number/dateTime |
| `enum` | Одна таблица смысловой вариант ↔ XML ↔ YAML; принимаемые aliases и канонический reverse явно различаются. | Color, StandardPeriod |
| `record` | Поля, их типы, обязательность и вложенность. | Attribute, Border, WebServiceParameter |
| `sequence` | Упорядоченные вхождения, в том числе повторы. Уникальность — отдельное ограничение. | I8nText, headers, fixedArray |
| `choice` | Конечные размеченные варианты, выбираемые по объявленной форме/дискриминатору. | MetadataValue, StyleItemValue, DCS |
| `use` | Ссылка на декларацию с проверяемыми типизированными параметрами. | Все составные records |
| `presence` | Отсутствие, пустой элемент/контейнер, nil и явный default с заданным восстановлением. | String, MinMaxValue, SettingsParameterValue |
| `shorthand` | Короткое представление через полное значение; выбирается только при однозначном совпадении всех значимых полей. | I8nText, Picture, TypeDescription |
| `text-pattern` | Разбираемый и печатаемый шаблон с типизированными слотами, разделителями, escaping и ограниченной вложенностью. | TypeLink, ChoiceParameterLinks, TypeDescription |
| `keyed-mapping` | Проекция sequence<Record> в YAML-ключ/значение без потери occurrence; теги адресуют повторные ключи. | I8nText, ChoiceParameters |
| `keyed-join` | Соединение явно названных коллекций по уникальному ключу с порядком, правилами отсутствия и обратным распределением полей. | ExchangePlanContent, panel/panelDef |
| `canonical-members` | Ожидаемый состав берётся из входной декларации; избыточные элементы сокращаются только при восстанавливаемости. | StandardAttributeDescriptions |
| `reference` | Грамматика пути, constraint вида/владельца, lookup и объявленная проекция зависимости/изменения. | MetadataField, роли, StyleItem |
| `fact-query` | Проекция/поиск в готовом неизменяемом индексе, без скрытого IO. | TypeDescription, языки, owner defaults |
| `graph-expansion` | Ограниченный обход объявленных рёбер подготовленного графа с cache/cycle/missing состояниями. | DefinedType |
| `identity` | Смысловой адрес идентификатора и слот готового значения; генерация происходит операцией один раз. | UUID, InternalInfo, панели |
| `resource` | Декларация соответствия файлов/групп файлов, альтернатив и производных XML-оболочек. | Module, Help, Template |
| `state-relation` | Конечное отношение состояния XML, YAML-значения/тега и профиля cf/cfe/full/adopted. | ExchangePlanContent, PredefinedItem, propertyStates |

Для рекурсивного дерева каждый шаг обязан спускаться в дочернее значение. Для graph-expansion задан visited/cache и предел ресурсов; произвольный while, пользовательская рекурсивная функция и eval запрещены. Лимит не может незаметно обрезать результат: превышение даёт явную ошибку подготовки.

## Выражения и границы

Разрешены структурированные узлы выражений: literal, field, input, присутствие, равенство/сравнение, and/or/not, конечный select/match, составление record/sequence, кванторы над коллекцией, объявленный lookup и шаблон. Строка `input(foo)` из первых примеров обсуждения была поясняющей записью; в целевой декларации ссылки структурированы, без интерпретации строк как кода.

Общие механизмы строки/числа/даты/индекса пишутся в Rust. В них нет ветки по имени common, имени XML-поля владельца, 1С itemType или каталогу Forms. Предметные таблицы допустимых типов, полей и состояний — декларации common/владельцев. Если значение нельзя выразить перечисленными конструкциями, фиксируется недостающая общая конструкция и её договор. Запрещён выход `native: convertI8nText` либо `validator: classifyFillValue`.

## Пример вложенного I8nText

Пример описывает обычные непустые переводы без служебных языков. Профили пустоты/синонима и условия проверки карт со служебными кодами перечислены в карточке I8nText и должны быть развёрнуты дополнительно; этот фрагмент не объявляется полным переносом компонента.

```yaml
version: 1
module: common.i8n-text

inputs:
  languages:
    type: language-registry

types:
  translation:
    kind: record
    fields:
      language: {type: text}
      text: {type: text}

value:
  kind: sequence
  item: {use: translation}

representations:
  xml:
    kind: element-sequence
    item:
      name: {namespace: "http://v8.1c.ru/8.1/data/core", local: item}
      fields:
        language:
          element: {namespace: "http://v8.1c.ru/8.1/data/core", local: lang}
          value: text
        text:
          element: {namespace: "http://v8.1c.ru/8.1/data/core", local: content}
          value: text

  yaml:
    kind: keyed-mapping
    key: {field: language}
    value: {field: text}
    value_constraints: {min_length: 1}
    shorthand:
      kind: scalar
      scalar_type: text
      scalar_constraints: {min_length: 1}
      represents:
        sequence:
          - language: {input: languages, path: [default]}
            text: {slot: scalar}

constraints:
  - id: language-registered
    each:
      field: language
      member_of: {input: languages, path: [registered]}
    diagnostic_at: item-key
  - id: unique-language
    unique_by: language
    diagnostic_at: repeated-item-key

sequence:
  preserve_occurrences: true
  preserve_input_order: true
  expected_order:
    compare: first-occurrence-of-each-key
    first: {input: languages, path: [default]}
    rest: {by: language, comparison: utf16-code-units}
  order_diagnostic_at: collection
```

Скаляр однозначно обозначает один перевод на основном языке. Два одинаковых language не совпадают с этим полным значением и не сокращаются. Иной порядок сохраняется, а не исправляется сортировкой. Подготовленный реестр не пересоздаётся для каждого текста. Поле владельца задаёт оболочку Title/Synonym и профиль I8nText отдельно через use.

Диагностика и теги не одно и то же: эти ограничения порождают диагностические исходы. Существующая таблица разрешённых аннотаций I8nText задаёт оформление при XML-импорте и принятие помеченной ошибки при проверке YAML. Нового глобального правила «любую ошибку пометить invalid» здесь нет.

## Пример выбора сложного объекта

```yaml
version: 1
module: common.style-item-value
value:
  kind: choice
  variants:
    font: {use: common.font}
    color: {use: common.color}
    border: {use: common.border}
representations:
  xml:
    discriminator: {attribute: xsi:type}
    variants:
      font: {qname: v8ui:Font, content: variant}
      color: {qname: v8ui:Color, content: variant}
      border: {qname: v8ui:Border, content: variant}
  yaml:
    discriminator: Вид
    payload: Значение
    variants:
      font: Шрифт
      color: Цвет
      border: Рамка
```

Префиксы xsi/v8ui в этом сокращённом примере должны быть связаны с URI в module imports/namespaces. Реальное сопоставление — URI+local name, не равенство строк префикса. Каждый variant содержит свой вид содержимого, поэтому Font с атрибутами и Color с текстом не требуют вызова разных вручную написанных обработчиков.

## Обратимость и ошибки компиляции

Компилятор отвергает неизвестный ключ/оператор; use без входа; несовместимый тип; необъявленную зависимость; циклическое вычисление полей; неограниченную рекурсию; коллизию XML/YAML-пути; пересекающиеся исключительные варианты без явного договора; неоднозначную таблицу reverse без canonical; shorthand без однозначного восстановления; join без указанной обратной проекции.

Произвольное выражение нельзя автоматически обратить. Вычисляемое сокращение допускается только при явно заданном восстановлении из YAML, входов и разрешённых сведений формы. Для части свойств оно окажется неприменимым, и значение останется явным. Это лучше, чем скрытая копия исходного значения ради успешного proof.

Статическая проверка не является доказательством обратимости любого языка шаблонов. Для допускаемого ограниченного подмножества гарантии описываются конструкцией; остальные случаи требуют ограничения грамматики и контрпримеров. Не обещается решать произвольную эквивалентность программ.

## Исполнение и скорость

Сборка: YAML → типизированное описание → проверка связей/вариантов → специализированный Rust-код преобразований и проверок. JSON Schema — дополнительный результат этого же описания. Нельзя оставить тяжёлый обход декларации на каждое значение.

В операции готовятся объявленные facts/identity/resources. Локальный проход извлекает смысл и проверяет ограничения, сохраняя компактные occurrence и ссылки на входные байты там, где это позволяет время жизни. Текст не прогоняется через JSON и несколько универсальных моделей. Составное значение не обязано иметь выделение памяти на каждый формальный узел декларации.

После смысловых проверок остаётся действующая проверка XML-обратимости. Обзор не изменяет принятый механизм быстрого сравнения и подробного аудита несовпадения; конкретная реализация локального proof должна быть согласована с общей Rust-спекой. Запись YAML завершается после классификации. YAML → XML и отдельная validation переиспользуют те же ограничения/факты, но validation не обязана строить XML или публиковать ресурсы.

У сложных структур учитываются стоимость lookup, временных коллекций, graph-expansion, joins, identity preparation и proof. Замеры проверяют законченные одинаковые операции на e2e и отдельно неудачные/аномальные входы. Скалярный результат 27× не переносится на них автоматически.

## Проверки без размножения тестов

- Один табличный набор на наблюдаемый договор common; по представителю класса и содержательной границе.
- Существующие XML-фикстуры и ожидаемые YAML/диагностики остаются независимыми от генератора.
- Общие операторы проверяются на структурных законах: preservation occurrences/order, encode/decode canonical, shorthand equivalence, inverse join и состояния missing/cycle.
- Примеры отрицательных деклараций: коллизии, неготовый вход, неоднозначный reverse, ошибка типа, запрещённый callback.
- Для I8nText/FillValue/ParameterValue/ExchangePlan/ClientApplicationInterface обязательно отдельное сквозное свидетельство, поскольку сочетание механизмов не проверяется тестами одного примитива.
- Будущие тесты должны различать XML-потерю формы, структурную ошибку YAML и предметную диагностику с точным адресом; не сверять только boolean success.
