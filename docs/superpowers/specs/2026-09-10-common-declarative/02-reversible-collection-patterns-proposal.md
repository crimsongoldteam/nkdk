# Обратимые шаблоны коллекций — предложение к D-12

Статус: подход согласован пользователем 2026-09-10; точная грамматика включена в D-12, реализация и проверка корпуса ещё не завершены. Дополняет единую спецификацию, отдельного языка common не вводит.

## Задача

При имени TestName и основном языке ru полное значение может содержать два перевода: ru = «Test name», en = «Text». В существующем профиле excludeIfEqualNameYAML YAML оставляет только en; ru восстанавливается из имени. Если исходный ru отсутствовал, YAML содержит явный пустой маркер ru и перевод en. Это разные значения, и их нельзя смешивать.

Нынешняя короткая форма описывает только одну строку. Её недостаточно для карты, в которой опущена вычисляемая часть коллекции. Отдельные выражения чтения и записи вернули бы два независимых алгоритма, чего требуется избежать.

## Рекомендуемое решение

Расширить существующий shorthand структурными шаблонами упорядоченных коллекций. Один шаблон описывает фиксированный префикс и один захватываемый остаток; denotes описывает соответствующее полное значение. При обратном направлении компилятор сопоставляет полное значение с той же структурой и находит остаток. Произвольное обращение выражений не выполняется.

Пример отношения без привязки к будущему синтаксису:

| Короткая запись | Полное значение | Условие |
|---|---|---|
| карта остатка | [ru = текст из имени] + остаток | N включён, имя доступно, в остатке нет ru |
| [ru = пусто] + карта остатка | остаток | N включён, остаток непустой и не содержит ru |
| строка text | [ru = text] | Уже действующая короткая форма |

Обычная полная карта остаётся резервной формой. Сокращение выбирается лишь при точном восстановлении последовательности и аннотаций. Если ru стоит после en, его нельзя незаметно перенести в начало. Повторы, исходный пустой перевод и непустой повтор не удовлетворяют условиям сокращения и остаются физическими вхождениями.

## Ограничения первой версии

- Только один захват остатка на шаблон; фиксированные части находятся перед ним или после него. Захват имеет объявленный тип sequence<Record>.
- denotes допускает структурное соединение фиксированных последовательностей и единственного захвата. В фиксированной части — литералы, подготовленные inputs и уже объявленные общие текстовые преобразования.
- Недоступное имя и отсутствие результата текстового преобразования делают этот вариант неприменимым, а не превращаются в пустую строку.
- Запрещены удаление произвольных элементов, сортировка, объединение одинаковых ключей и скрытая нормализация.
- При чтении несколько форм должны иметь доказуемо непересекающиеся условия распознавания. Для двух карт выше это наличие первого пустого ru против полного отсутствия ru. Одного порядка списка недостаточно, чтобы разрешить неоднозначное чтение.
- При записи короткие формы проверяются в объявленном порядке; при невозможности точного совпадения выбирается полная карта. Общий proof дополнительно проверяет XML, поскольку смысловое равенство не гарантирует форму XML.
- Остаток представляется диапазоном вхождений или заимствованным представлением; конвертер не создаёт второй словарь и не копирует все строки. Стоимость сопоставления линейная по числу вхождений, без перебора вариантов разбиения.
- Синтетический маркер не получает адрес исходного физического перевода. Перенос адресов и аннотаций захваченного остатка сохраняет исходную последовательность.
- Новые применения !xml не разрешаются.

## Другие подходы

(А) Общие структурные шаблоны — рекомендуемый вариант: одна запись отношения, ограниченная обратимость, пригодность для других common-коллекций.

(Б) Отдельные выражения чтения и записи в YAML — проще построить интерпретатор, но снова возникают два независимых правила, которые могут разойтись.

(В) Частный оператор сокращения локализованного текста — проще для одного объекта, но нарушает независимость общего runtime от common и не решает задачу универсальной спецификации.

## Проверка после согласования

Сначала зафиксировать точный YAML-синтаксис внутри D-12 и расширить этапы А1–А3. Проверить обычный синоним с иностранным переводом, отсутствующий ru с маркером, пустой физический ru, повторы, ru не первым, недоступное имя и имя без текстового результата. После связывания выполнить эти ожидания сгенерированным Rust-кодом в А6. Наблюдения TS остаются отдельными от независимых ожиданий.
