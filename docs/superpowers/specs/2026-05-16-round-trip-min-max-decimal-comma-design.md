# Round-trip MinMaxValue Decimal Comma

## Контекст

В XML метаданных встречаются ограничения значений с десятичной запятой:

```xml
<MinValue xsi:type="xs:string">0,005</MinValue>
<MinValue xsi:type="xs:string">7,5</MinValue>
<MinValue xsi:type="xs:string">0,01</MinValue>
<MinValue xsi:type="xs:string">0,00</MinValue>
```

Сейчас `MinMaxValue` импортирует текст через `Number(rawValue)`. Для строк с
запятой JavaScript возвращает `NaN`, и round-trip пишет `NaN` обратно в XML.

## Решение

`MinMaxValue` должен поддерживать десятичную запятую как XML-представление
десятичного числа:

- при импорте XML строка с запятой преобразуется в обычное число модели:
  `0,005` -> `0.005`, `7,5` -> `7.5`;
- YAML и модель хранят обычное число, без строкового специального случая;
- при экспорте XML для `xs:string` дробное число пишется с запятой:
  `0.005` -> `0,005`, `7.5` -> `7,5`;
- целые числа пишутся без десятичного разделителя: `1`, `5`, `15`;
- `xs:decimal` остается в каноническом XML-виде с точкой.

Правило экспорта с запятой применяется, когда итоговый XML-тип значения
`xs:string`: либо он задан в `typedXML`, либо взят из `referenceMetadata`.

## YAML

YAML не получает отдельный строковый формат. Пример:

```yaml
МинимальноеЗначение: 0.005
МаксимальноеЗначение: 15
```

Так модель остается удобной для сравнения и обработки как число, а XML-экспорт
берет на себя форматирование для платформенного представления.

## Подводные Камни

Нельзя заменять точку на запятую для всех XML-чисел. Запятая относится только к
`MinMaxValue` с XML-типом `xs:string`; для `xs:decimal` точка остается верной.

Нельзя добавлять дробную часть целым значениям. XML `1` должен остаться `1`, а
не превратиться в `1,0`.

JS-числа могут округлять очень длинные десятичные значения. Для найденных
значений `0,005`, `7,5`, `0,01`, `0,00` это приемлемо. Если в будущем появятся
длинные точные десятичные ограничения, понадобится отдельное сырьевое
представление, но в текущую спеку оно не входит.

## Границы

В рамках этой спеки:

- меняется только поведение `MinMaxValue`;
- XML-фикстуры не изменяются;
- YAML-формат остается числовым;
- `xs:nil` и пустые значения сохраняют текущее поведение;
- остальные числовые типы проекта не получают десятичную запятую автоматически.

## Проверка

Для реализации нужны тесты:

- импорт `xs:string` со значением `0,005` возвращает число `0.005`;
- экспорт `0.005` в `xs:string` пишет `0,005`;
- экспорт целого `15` в `xs:string` пишет `15`;
- экспорт `0.005` в `xs:decimal` пишет `0.005`;
- reference-aware экспорт сохраняет `xs:string` и применяет запятую.
