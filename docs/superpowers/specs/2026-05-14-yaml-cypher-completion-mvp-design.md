# YAML completion from Cypher: MVP

## Контекст

YAML-файлы сейчас обслуживает встроенный `yaml-language-server`. Расширение запускает его и
подсовывает JSON Schema, но не добавляет собственные варианты значений из графа.

В `rules.ts` уже есть механизм `allowedValues: cypherSet({ query })`. Он задуман как общий
источник допустимых значений для валидации и автодополнения. Для MVP считаем, что FalkorDB уже
запущен, граф проекта уже построен и актуален.

Целевой пример:

```yaml
ОсновнаяФормаДляВыбора: Catalog.АктыОтбораПробЗЕРНО.Form.ФормаВыбора
```

При редактировании значения пользователь должен увидеть формы текущего справочника.

## Цель

Добавить минимальное автодополнение значений YAML-полей из `allowedValues: cypherSet(...)`.

Первая версия должна проверить рабочую связку:

1. VS Code вызывает отдельный provider расширения.
2. Provider определяет YAML-ключ под курсором.
3. Provider находит правило этого ключа.
4. Если правило содержит `cypherSet`, provider выполняет запрос к FalkorDB.
5. Результат запроса становится списком `CompletionItem`.

## Не входит в MVP

- Автоматически запускать или обновлять граф.
- Валидировать YAML-значение по `cypherSet`.
- Править или форкать `yaml-language-server`.
- Поддерживать все формы YAML сразу: массивы, record-ключи, вложенные сложные значения.
- Переводить все существующие `referenceScope` за одну задачу.
- Менять XML-фикстуры.

## Подход

Сохраняем вариант (А): отдельный `CompletionItemProvider` в пакете `@nakidka/extension`.
Он работает рядом с `yaml-language-server`, а не внутри него.

Provider регистрируется для языка `yaml` и возвращает свои варианты только когда курсор находится
в scalar-значении свойства. Для всех остальных мест он возвращает пустой список, чтобы стандартное
YAML-дополнение продолжало работать как раньше.

Предметная логика допустимых значений остаётся в `rules.ts`:

```ts
allowedValues: cypherSet({
  query: `
    MATCH (scope {id: $scope})-[:FORM]->(form)
    RETURN form.id AS value, form.name AS label
  `,
})
```

Provider не знает, что такое "основная форма справочника". Он знает только общий контракт:
если у правила есть `allowedValues: cypherSet`, нужно выполнить запрос и показать строки результата.

## Определение правила

MVP поддерживает только `Свойства.yaml` верхнеуровневого объекта.

По пути файла provider определяет тип и имя объекта, например:

```text
Справочник/АктыОтбораПробЗЕРНО/Свойства.yaml
```

Дальше он через существующий реестр графового импорта или соседний helper получает `rule` для
этого вида объекта. По текущему YAML-ключу находится property rule с таким же `yaml`.

Если у найденного правила нет `allowedValues` или значение не является `cypherSet`, provider
возвращает пустой список.

## Параметры Cypher

В запрос подставляется параметр:

- `$scope` — id текущего metadata-объекта в графе.

Для MVP допускается отдельный helper `scopeIdFromProjectPath`, который повторяет текущий формат id
для верхнеуровневых объектов. Его нужно покрыть тестом на пример справочника.

Если фактический формат id отличается от предположения, реализация должна поправить helper под
текущий графовый контракт, а не добавлять особый случай в provider.

## Формат результата запроса

Provider поддерживает такие колонки:

- `value` — вставляемый текст;
- `label` — подпись в списке, если отличается от `value`;
- `detail` — короткое уточнение справа в списке.

Если `value` нет, берётся первая колонка строки. Если `label` нет, в качестве подписи используется
`value`.

Строки без строкового значения пропускаются.

## Ошибки

MVP не должен шуметь при обычном редактировании.

Если FalkorDB недоступен, запрос упал, путь файла не распознан или правило не найдено, provider
возвращает пустой список. Диагностическое сообщение можно записать в Output Channel `NKDK`, но не
показывать пользователю всплывающее сообщение.

## Проверка автодополнения

Автоматические тесты покрывают чистую логику без настоящего VS Code:

1. YAML-текст и позиция курсора дают правильный YAML-ключ.
2. Путь `Справочник/АктыОтбораПробЗЕРНО/Свойства.yaml` даёт правильный `$scope`.
3. Результаты Cypher с колонками `value`, `label`, `detail` превращаются в completion items.
4. Provider с поддельной graph session возвращает варианты только для поля с `cypherSet`.
5. Provider возвращает пустой список, если правило не найдено или graph session бросила ошибку.

Ручная проверка нужна, потому что поведение всплывающего списка создаёт VS Code:

1. Запустить FalkorDB с уже построенным графом `erp_nkdk`.
2. Запустить расширение в Extension Host.
3. Открыть
   `/Users/nikita/git/erp_nkdk/Справочник/АктыОтбораПробЗЕРНО/Свойства.yaml`.
4. В строке `ОсновнаяФормаДляВыбора` стереть значение после двоеточия и вызвать completion.
5. Убедиться, что список содержит формы текущего справочника, например
   `Catalog.АктыОтбораПробЗЕРНО.Form.ФормаВыбора`,
   `Catalog.АктыОтбораПробЗЕРНО.Form.ФормаСписка`,
   `Catalog.АктыОтбораПробЗЕРНО.Form.ФормаЭлемента`.
6. Выбрать вариант и убедиться, что вставлен полный `value`.

Дополнительная ручная проверка: в несвязанном YAML-поле provider не должен добавлять графовые
варианты.

## Тестовый минимум перед завершением MVP

После реализации:

```bash
pnpm --filter nkdk-language langium:generate
pnpm --filter nkdk run build
pnpm --filter nkdk exec vitest run <точечные тесты provider-а>
```

Перед выпуском или закрытием issue нужен полный:

```bash
pnpm test
```
