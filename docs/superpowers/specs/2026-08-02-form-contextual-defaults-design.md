# Контекстные XML-defaults форм документа и отчёта

## Контекст

Полный YAML round-trip конфигурации `cf/doc` без reference удаляет свойства
формы документа в 33 XML-файлах:

- `AutoTime=CurrentOrLast` — в 33 формах;
- `UsePostingMode=Auto` — в 31 форме;
- `RepostOnWrite=true` — в 31 форме.

Во всех 33 случаях основной реквизит формы имеет тип `DocumentObject`. Во всех
остальных формах конфигурации такой основной реквизит отсутствует и указанные
XML-defaults не встречаются. Владелец формы сам по себе недостаточен: например,
форма списка документа имеет основной реквизит `DynamicList` и не должна
получать свойства объектной формы документа.

Два отличающихся значения `UsePostingMode=Regular` находятся в формах
документов `ЕжедневныйОтчет` и `ЕженедельныйОтчет`. Два значения
`RepostOnWrite=false` находятся в формах документов
`АктОбУничтоженииПерсональныхДанных` и `ИсходящееПисьмо`.

Конфигуратор использует `Auto` как default `UsePostingMode` и `true` как
default `RepostOnWrite`. Действующий YAML-договор уже считает
`CurrentOrLast`, `Auto` и `true` неявными значениями, поэтому проблема
возникает только при восстановлении XML из компактного YAML.

Та же причина удаляет отчётные свойства в 29 XML-файлах `cf/doc`. Среди них
25 форм отчётов и четыре общие формы. Во всех формах основной реквизит имеет
тип `ReportObject`, и во всех присутствуют четыре XML-поля:

- `ReportFormType`: 25 `Main`, три `Settings` и один `Variant`;
- `AutoShowState`: 25 `Auto`, три `ShowOnComposition` и один `DontShow`;
- `ReportResultViewMode`: 29 `Auto`;
- `ViewModeApplicationOnSetReportResult`: 29 `Auto`.

Проверка всех 34 322 форм из конфигураций каталога `cf` подтверждает тот же
договор без исключений. Найдено 506 форм с основным реквизитом `ReportObject`:

- `ReportFormType`: 463 `Main`, 31 `Settings`, 12 `Variant`;
- `AutoShowState`: 477 `Auto`, 15 `DontShow`, 14 `ShowOnComposition`;
- `ReportResultViewMode`: 505 `Auto`, один `Default`;
- `ViewModeApplicationOnSetReportResult`: 506 `Auto`.

У каждой из этих форм присутствуют все четыре XML-поля. Форм с основным
реквизитом `ReportObject`, но без них, а также форм с этими полями и другим
основным типом не найдено. Конфигуратор использует `Main` как default
`ReportFormType` и `Auto` как default остальных трёх свойств.

## Цель

Восстанавливать обязательные XML-defaults объектных форм документа и отчёта
без reference XML и не создавать эти теги у остальных форм. Явные значения,
отличающиеся от defaults, должны сохраняться в YAML и XML.

## Договор

Применимость контекстных свойств определяется основным реквизитом формы, а не
владельцем формы. Подход повторяет действующий договор
`UseForFoldersAndItems` для основного реквизита `CatalogObject` или
`ChartOfCharacteristicTypesObject`.

### Форма документа

Если YAML формы содержит реквизит с `ОсновнойРеквизит: Истина`, чей
нормализованный тип имеет kind `ДокументОбъект`, отсутствующие YAML-ключи
восстанавливаются в XML так:

| YAML-поле | XML-тег | Неявное значение YAML | XML-default |
|---|---|---|---|
| `АвтоВремя` | `AutoTime` | `CurrentOrLast` | `CurrentOrLast` |
| `РежимПроведения` | `UsePostingMode` | `Auto` | `Auto` |
| `ПерепроводитьПриЗаписи` | `RepostOnWrite` | `true` | `true` |

Если основного реквизита `ДокументОбъект` нет:

- отсутствующие YAML-ключи не создают XML-теги;
- явное присутствие любого из трёх YAML-полей является ошибкой проверки.

Значения `Regular`, `false` и остальные значения перечислений, отличающиеся
от defaults, остаются явными в YAML и экспортируются без изменения.

### Форма отчёта

Если основной реквизит имеет kind `ОтчетОбъект`, отсутствующие YAML-ключи
восстанавливаются в XML так:

| YAML-поле | XML-тег | Неявное значение YAML | XML-default |
|---|---|---|---|
| `ТипФормыОтчета` | `ReportFormType` | `Основная` | `Main` |
| `АвтоОтображениеСостояния` | `AutoShowState` | `Авто` | `Auto` |
| `РежимОтображенияРезультатаОтчета` | `ReportResultViewMode` | `Авто` | `Auto` |
| `ПрименениеРежимаОтображенияПриУстановкеРезультатаОтчета` | `ViewModeApplicationOnSetReportResult` | `Авто` | `Auto` |

При другом основном типе отсутствующие YAML-ключи не создают эти XML-теги,
а явное присутствие любого из четырёх полей является ошибкой проверки.

Отличающиеся значения остаются явными в YAML: `Настройка` и `Вариант` для
типа формы, `НеОтображать` и `ОтображатьПриФормировании` для автоматического
отображения состояния, `Обычный` для режима отображения результата. Остальные
поддержанные значения перечислений обрабатываются по тому же правилу.

## Архитектура

Существующую локальную проверку основного реквизита для
`UseForFoldersAndItems` следует обобщить внутри модуля управляемой формы. Она:

1. читает `ОсновнойРеквизит` из сырого YAML реквизитов формы;
2. получает нормализованные kinds типа из уже построенного
   `formDataPathIndex`;
3. отвечает, входит ли kind основного реквизита в переданный набор.

Правила трёх документных и четырёх отчётных свойств используют эту проверку
при YAML → XML и задают соответствующий `defaultValueXML`. Проверка
управляемой формы использует тот же локальный договор применимости и выдаёт
диагностику по пути недопустимого YAML-поля.

Знание о `ДокументОбъект` и `ОтчетОбъект` остаётся в модуле формы. Общие слои
`orchestration`, `validation` и `project`, общие типы правил и параметры
построителей не изменяются. Владелец формы и reference XML не участвуют.

## Поток данных

### XML → YAML

1. Документные `CurrentOrLast`, `Auto`, `true` и отчётные `Main`, `Auto`
   исключаются как неявные YAML-значения.
2. Отличающиеся значения сохраняются явно.
3. Индекс формы сохраняет нормализованный тип основного реквизита.

### YAML → XML

1. Локальная проверка находит основной реквизит формы.
2. Для kind `ДокументОбъект` или `ОтчетОбъект` соответствующие правила
   восстанавливают отсутствующие defaults.
3. Для другого kind или отсутствующего основного реквизита теги не создаются.
4. Явные допустимые значения экспортируются вместо defaults.

## Проверка ошибок

Если документное поле указано в форме без основного реквизита
`ДокументОбъект` или отчётное поле — без основного реквизита `ОтчетОбъект`,
проверка YAML возвращает ошибку на соответствующем поле. Ошибка не
исправляется молчаливым удалением свойства и не зависит от каталога владельца
формы.

## Тестирование

Существующие XML-фикстуры не изменяются. Следует расширить существующие
проверки договора формы, не создавая дублирующие тесты внутреннего устройства:

1. Форма с основным реквизитом `ДокументОбъект` и без трёх YAML-полей получает
   `CurrentOrLast`, `Auto` и `true` в XML.
2. Явные `Regular` и `false` экспортируются без замены defaults.
3. Форма с основным реквизитом `ДинамическийСписок`, другим типом или без
   основного реквизита не получает документные XML-теги.
4. Явное документное поле в такой форме отклоняется проверкой YAML.
5. Существующий договор `UseForFoldersAndItems` остаётся неизменным после
   обобщения помощника.
6. Форма с основным реквизитом `ОтчетОбъект` и без четырёх отчётных
   YAML-полей получает `Main` и три `Auto` в XML.
7. Явные `Настройка`, `Вариант`, `НеОтображать`,
   `ОтображатьПриФормировании` и `Обычный` экспортируются без замены defaults.
8. Форма с другим основным типом не получает отчётные XML-теги, а явное
   отчётное поле отклоняется проверкой YAML.
9. Выполняются целевые тесты, `pnpm type-check`, полный `pnpm test` и
   `pnpm duplicates`.
10. Повторный round-trip `cf/doc` устраняет группы из 33 документных и 29
    отчётных форм. Согласованные расхождения `Period`, `TopLevelParent` и
    `RowFilter` при оценке результата игнорируются.

## Вне границ

- Остальные группы текущего round-trip.
- Выбор документных или отчётных свойств по владельцу формы.
- Изменение формата YAML или хранение признака присутствия XML-тега.
- Возврат reference XML.
- Изменение существующих XML-фикстур.
