# Выгрузка конфигурации без ограничения времени

## Контекст

`nkdk.import_from_infobase` выгружает конфигурацию из информационной базы
двумя способами:

- через SSH-агент Конфигуратора;
- через автономный режим `ibcmd`.

Сейчас команда агента ограничена 60 секундами, `ibcmd` — 30 минутами, а
локальный MCP-helper прекращает ждать ответ через стандартные 60 секунд SDK.
Большая конфигурация может выгружаться час и дольше, поэтому любой из этих
пределов способен прервать исправную операцию.

## Цель

Снять ограничение времени с платформенной выгрузки в обоих режимах и
гарантированно останавливать принадлежащий nkdk процесс при отмене
MCP-запроса.

## Границы

Изменение относится к платформенному этапу
`nkdk.import_from_infobase`: подготовке соединения и выгрузке XML.

Тайм-ауты запуска и завершения сохраняются:

- запуск агента и SSH-подключение — 60 секунд;
- штатное завершение процесса — 5 секунд до принудительной остановки;
- подготовка конфигурации автономного режима остаётся ограниченной, потому
  что это короткая операция запуска, а не выгрузка.

Преобразование готового XML в YAML не получает новый механизм прерывания в
рамках этого изменения. Сигнал отмены проверяется между платформенной
выгрузкой и преобразованием.

## Проектное решение

### MCP-слой

Обработчик `nkdk.import_from_infobase` передаёт `extra.signal` из MCP SDK в
сервис импорта. Сервис передаёт сигнал в менеджер платформы и возвращает
безопасную ошибку `operation_cancelled`, если запрос отменён.

Временный каталог операции не удаляется после отмены и возвращается в
`details.temporaryDirectory`, как при других ошибках платформы.

Локальный `.agents/tools/mcp/call.mjs` вызывает инструмент с максимальным
безопасным тайм-аутом Node.js `2_147_483_647` мс (около 24 суток). MCP-сервер
не способен отменить собственный тайм-аут стороннего клиента, поэтому
внешние клиенты также должны разрешать длительные вызовы.

### Менеджер платформы

`PlatformSessionManager.exportConfiguration` принимает `AbortSignal`.
Отмена активной выгрузки:

1. передаётся текущему сеансу;
2. закрывает отменённый сеанс;
3. удаляет его из кэша;
4. не запускает таймер простоя и не позволяет переиспользовать сеанс.

Обычная ошибка команды не меняет существующую политику кэширования, если
сеанс остаётся рабочим.

### Агент Конфигуратора

SSH-команда выгрузки ожидает ответ без таймера. Тайм-аут начального
подключения и ожидания первого приглашения остаётся 60 секунд.

При отмене ожидающая SSH-команда отклоняется с
`PlatformSessionError("operation_cancelled")`, SSH-сеанс закрывается, а
принадлежащий nkdk процесс 1С получает `SIGTERM`. Если он не завершился за
5 секунд, nkdk отправляет `SIGKILL`. Обычное закрытие не по отмене сохраняет
существующий порядок штатных команд `disconnect-ib` и `shutdown`.

### Автономный режим `ibcmd`

Выгрузка запускается без таймера, но с `AbortSignal`. При отмене дочерний
процесс получает `SIGTERM`. Если он не завершился за 5 секунд, nkdk
отправляет `SIGKILL`.

Подготовка `config.yaml` по-прежнему имеет тайм-аут 30 минут и не считается
долгой операцией выгрузки.

## Ошибки и безопасность

- Добавляется публичный код ошибки `operation_cancelled`.
- В ответ не попадают пароли, аргументы подключения и необработанный вывод
  платформы.
- nkdk завершает только процессы, запущенные текущим MCP-процессом.
- Частичная XML-выгрузка сохраняется в каталоге операции.
- Повторный импорт возможен только после очистки или выбора новой пустой
  цели по существующим правилам.

## Проверка

Тесты должны доказать:

1. SSH-команда выгрузки не создаёт таймер ожидания.
2. Тайм-аут запуска агента сохраняется.
3. Отмена агента закрывает SSH и завершает принадлежащий процесс.
4. Отменённый сеанс удаляется из кэша и не переиспользуется.
5. Выгрузка `ibcmd` запускается без `timeoutMs`.
6. Отмена `ibcmd` отправляет `SIGTERM`, а зависшему процессу — `SIGKILL`
   после 5 секунд.
7. MCP передаёт `extra.signal` и возвращает `operation_cancelled` с путём
   временного каталога без чувствительных данных.
8. Локальный MCP-helper не обрывает вызов через 60 секунд.
9. Полный `pnpm test` проходит.
