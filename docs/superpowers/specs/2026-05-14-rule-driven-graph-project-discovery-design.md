# Rule-driven graph project discovery

## Контекст

`update-graph` сейчас читает проект через список каталогов в `packages/cli/src/graph/projectFiles.ts`.
Этот список содержит только `Справочник`, `Документ`, `Перечисление`, поэтому CLI не передает в `buildGraph`
часть объектов, уже зарегистрированных в `packages/core/metadata/graphImport/registerTopLevelGraphImports.ts`.

Цель изменения - убрать ручное дублирование знаний о проектной структуре из CLI. Источником правды для
верхнеуровневых объектов должен быть `registerTopLevelGraphImports.ts`, а остальные проектные файлы должны
выводиться из `rules` соответствующего объекта.

## Требования

- CLI не должен хранить собственный список верхнеуровневых каталогов объектов.
- Верхнеуровневые объекты берутся из регистраций `registerTopLevelGraphImports.ts`.
- Дочерние проектные файлы и каталоги определяются по `rule.properties`.
- Формы являются частным случаем правила, например свойства с `type: "ChildFormNames"` и `folderName: "Формы"`.
- Тот же подход должен применяться к другим свойствам: табличным частям, реквизитам, командам, шаблонам,
  модулям и прочим файлам, если их проектный путь уже описан в правилах.
- Первая реализация не добавляет новые `fromYAML`/`toYAML` правила и не расширяет поддержку объектов,
  которых нет в `registerTopLevelGraphImports.ts`.
- Существующие XML-фикстуры не меняются.

## Дизайн

В `core` нужно выделить общий слой описания проектных источников графа.
`registerTopLevelGraphImports.ts` остается местом, на которое опирается этот слой: из него экспортируется
или через него доступен список зарегистрированных верхнеуровневых описаний (`kind`, проектный каталог, `rule`,
способ импорта модели).

Регистрация графового импорта и обход файлов должны использовать одни и те же описания. Это устраняет два
несвязанных списка: один в `core` для матчинга путей, второй в CLI для чтения файлов.

Для каждого верхнеуровневого объекта обход проекта должен находить:

- `<dir>/<name>/Свойства.yaml`;
- дочерние YAML/NKDK-файлы, которые можно вывести из `rule.properties`;
- парные файлы формы, когда правило указывает коллекцию форм.

Помощник для обхода должен возвращать относительные project filePath в том же формате, который сейчас ожидает
`buildGraph`: например `Документ/Заказ/Свойства.yaml` или `Документ/Заказ/Формы/ФормаСписка/Форма.yaml`.

## Архитектура

Предлагаемый набор единиц:

- `topLevelGraphImportSpecs` или эквивалентный getter в `core`: единый источник зарегистрированных
  верхнеуровневых объектов для графа.
- `discoverProjectGraphFiles(projectPath)`: читает файловую систему и строит список поддержанных файлов,
  используя top-level specs и `rule.properties`.
- `isSupportedProjectGraphFile(filePath)`: проверяет путь тем же механизмом, без ручного списка каталогов.
- `registerFormGraphImport.ts`: определяет владельца формы через top-level specs и правила форм, а не через
  фиксированный массив каталогов.

CLI должен остаться тонким слоем: он вызывает `discoverProjectGraphFiles`, читает содержимое найденных файлов
и передает их в `buildGraph`.

## Поведение при неизвестных файлах

Если файл лежит в проекте, но не выводится из зарегистрированных правил, первая реализация его не читает.
Это сохраняет текущий осторожный контракт: граф строится только из тех источников, которые код уже умеет
интерпретировать.

Если путь похож на поддержанный объект, но регистрация или правило отсутствует, это должно проявляться в тестах
обхода, а не скрываться дополнительным ручным списком.

## Проверка

Нужны тесты на двух уровнях:

- CLI/project files: зарегистрированные в `registerTopLevelGraphImports.ts` типы попадают в список файлов,
  а старый список `Справочник/Документ/Перечисление` больше не является ограничением.
- Core graph import: `parseFilePath`/матчинг форм использует тот же источник правды и корректно определяет
  владельца для форм объектов, у которых формы описаны в `rule.properties`.

Минимальная ручная проверка после реализации:

```bash
pnpm --filter @nakidka/cli exec vitest run packages/cli/src/graph/projectFiles.test.ts
pnpm --filter @nakidka/core exec vitest run packages/core/metadata/graphImport
```

Перед закрытием задачи нужен полный прогон `pnpm test` из корня, если изменения переходят к выпуску.
