# Warning for Dynamic List Type Values in Conditional Appearance

## Контекст

После повторного импорта ERP в YAML команда `validate /home/nikita/git/temp-yaml` показала три ошибки вида:

```text
Не удалось импортировать форму: Некорректный формат цели метаданных
```

Все три случая находятся в формах с `Реквизиты.<Имя>.ДинамическийСписок.УсловноеОформление.Элементы`. Внутри условий есть фильтр, где слева используется поле динамического списка с типовым значением, например `.Тип`, а справа записан объект метаданных:

```yaml
ЛевоеЗначение: .Тип
ПравоеЗначение: Документ.ПоступлениеБезналичныхДенежныхСредств
```

Такое значение справа означает выбранный тип из доступных типов поля слева. Проверить его корректность можно только после анализа текста запроса динамического списка и вывода доступных типов поля. Эту проверку сейчас не реализуем.

## Цель

Заменить ложную структурную ошибку импорта формы на понятный warning:

```text
Проверка значения типа "<значение>" в условном оформлении динамического списка пока не реализована и будет добавлена в будущих версиях
```

Валидатор должен продолжить проверку формы и не скрывать остальные диагностики из-за общей ошибки `Не удалось импортировать форму`.

## Границы

Входит:

- разрешить импорт YAML-значений вида `Документ.<Имя>`, `Справочник.<Имя>` и других объектных ссылок метаданных, когда они встречаются как `MetadataValue ref`;
- при обходе условного оформления динамического списка находить правые значения, которые являются ссылкой на объект метаданных без конкретного значения;
- выдавать warning с координатой `ПравоеЗначение`;
- оставить проверку доступности типа по левому выражению на будущее.

Не входит:

- анализ текста запроса динамического списка;
- вычисление типов колонок динамического списка;
- проверка, что `Документ.<Имя>` действительно входит в допустимые типы `.Тип`;
- изменение XML-фикстур;
- изменение YAML-представления импортированных файлов.

## Поведение

`MetadataValue` должен импортировать объектную ссылку метаданных как ссылочное значение, чтобы форма могла быть прочитана во внутреннюю модель. Это не меняет YAML: строка остаётся такой же, как была после импорта из XML.

Валидация формы должна отличать этот случай от настоящей ошибки структуры. Если значение находится в `Реквизиты.<Реквизит>.ДинамическийСписок.УсловноеОформление` и выглядит как объект метаданных, валидатор добавляет warning о нереализованной проверке.

Если такое значение встретится вне условного оформления динамического списка, поведение должно остаться строгим: не надо глобально превращать все ошибки metadataTarget в warning.

## Архитектура

Изменение делится на два небольших участка.

1. `MetadataValue` YAML import

   В обработчике `ref` добавить поддержку object target. Парсер должен принять YAML-корни метаданных без хвоста значения, например `Документ.ЗаказКлиента`, и сохранить каноническое значение объектной ссылки. Ошибки для legacy model-root YAML вроде `Catalog.СтавкиНДС.PredefinedData.БезНДС` должны остаться ошибками.

2. `validateForm`

   После успешного импорта формы и до/после проверки `ПутьКДанным` добавить сбор warning-диагностик по исходному YAML. Обход должен быть узким: только `Реквизиты.*.ДинамическийСписок.УсловноеОформление.*`, рекурсивно по `Отбор.Элементы`, только поле `ПравоеЗначение`.

Для координат использовать существующий `diagnosticAtYamlPath`, чтобы warning указывал на конкретный YAML-путь.

## Ошибки и предупреждения

Новая диагностика:

- `severity`: `warning`;
- `source`: `structure`;
- `path`: путь до `ПравоеЗначение`;
- сообщение: `Проверка значения типа "<значение>" в условном оформлении динамического списка пока не реализована и будет добавлена в будущих версиях`.

Если импорт формы падает по другой причине, текущая ошибка `Не удалось импортировать форму: ...` сохраняется.
