# Текстовое поле во внешнем файле

Статус: согласовано 2026-10-09; реализация QueryText ещё не начата.
Продолжение переноса DynamicList. Бинарные маршруты common.external-file сохраняются.

## Договор

Декларация поля по-прежнему описывает смысловой текст common.string и XML-путь.
На стороне YAML вместо ключа можно объявить файл. Имя файла вычисляется из
подготовленных входов обычными выражениями языка. Нет обработчиков QueryText,
DynamicList, каталога ДинамическийСписок или расширения query в общем Rust.

```yaml
format: nkdk-declarations/1
kind: object
id: example.external-text-owner
imports: {text: common.string}
inputs:
  parentName: {type: {kind: scalar, scalar: text}}
value:
  kind: record
  fields: [{name: query, type: {use: text}}]
representations:
  xml: {kind: record, fields: [{field: query, path: [Settings, QueryText]}]}
  yaml:
    kind: mapping
    fields:
    - field: query
      file:
        sequence:
        - {literal: ДинамическийСписок}
        - {concat: [{input: parentName}, {literal: '.query'}]}
```

`key` и `file` у одного YAML-поля взаимоисключающие. Начальный договор —
текстовый скаляр: записывается UTF-8 без YAML-оболочки. Иные смысловые типы
не трактуются как текст молча; неподдержанная декларация получает диагностику
при сборке. Переименование поля, XML-пути, каталога, расширения и входа не
требует изменения общего кода.

## Порядок

1. Подготовить относительные файловые пути из входов. Проверить бюджет,
   запрет выхода из каталога и совпадение назначений.
2. XML → YAML: прочитать XML-поле обычным скомпилированным преобразователем;
   выдать текст отдельным документом результата. В основном YAML обычного
   значения поля нет. Проверять восстановление с подготовленными документами
   результата, без повторного чтения XML и без записи временного файла ради proof.
3. YAML → XML и validation: операция читает объявленные файлы в пределах общего
   бюджета и передаёт их подготовленными документами. Преобразователь читает
   текст из них и восстанавливает обычное XML-поле.
4. Операция публикует основной документ и внешние файлы одним подготовленным
   результатом, используя существующую границу публикации. Компилятор и
   conversion-core не выполняют файловый ввод-вывод.

Обмен документами переиспользует FileResult.documents и PreparedInputs,
а не отдельный контекст для QueryText. Существующее document_paths для XML
сохраняется совместимым; новый запрос файлов учитывает направление и входы.

## Отсутствие, пустота и аномалии

- XML-элемента нет → файла нет; файла нет → XML-элемента нет, если normal
  presence самой декларации не задаёт другой смысл.
- Пустое текстовое значение → существует файл размером ноль. Нельзя потерять
  его из-за текущего пропуска пустых documents при подготовке Snapshot.
- Текст сохраняет переводы строк, кириллицу и символы запроса; XML-экранирование
  выполняет обычный XML-писатель. Файл не проходит YAML-скаляризацию.
- Повторы, неизвестные атрибуты и различие XML-форм обнаруживает существующий
  механизм доказательства. Только невосстановимые отличия сохраняются в
  основном YAML общей аномалией; отдельного списка аномалий QueryText нет.
- Неверная кодировка файла не заменяется символами замены. Это файловая
  аномалия с исходными байтами; неполный результат не публикуется как успешный
  XML-экспорт. Сбой IO или ошибка конвертера не маскируется под обычное значение.
- Конфликт двух назначений и выход пути из каталога не приводят к перезаписи.

## Автоматический перенос и проверка

Переносчик узнаёт stringRule.externalFile по данным dir/extension/nameFrom,
а не по имени свойства. nameFrom=parent становится входом контекста; нельзя
подставлять постоянное имя только в проверочном примере. Свойство сохраняет
внешний договор и не считается перенесённым обычным common.string.

Ожидания — исходный XML QueryText, текущий внешний файл и проверенные старые
ожидания. Один общий пример дополнительно меняет поле, XML-путь, имя входа и
каталог; это защищает отсутствие частного обработчика. Матрица: отсутствие,
пустой файл, многострочный текст, кириллица и XML-экранирование, аномалия поля
с читаемым соседом, правка файла перед экспортом, конфликт назначений,
бюджет и неправильная кодировка. Реальные XML-фикстуры не меняются.

Завершение требует нативного преобразования в обе стороны, проверки операции
с файлами, validation, архитектуры, отсутствия новых дублей и полного pnpm test.
Скорость сравнивается в одинаковой release-сборке; новый путь не должен читать
XML второй раз или вносить дополнительную обработку в обычные скалярные поля.
Флажок полного DynamicList ставится только после его отдельной полной приёмки.

Приёмка 2026-10-09: [результат и замеры](../reports/2026-10-09-external-text-fields.md).
Установленные ограничения документов действуют независимо от порядка
подготовки. Пустой список запросов файлов не обращается к файловой системе.
Неизвестные XML-атрибуты текстового поля сохраняются минимальной дельтой,
которая не подменяет последующую правку содержимого файла старым текстом.
Файловый договор принят отдельно от полной сборки DynamicList.


## Вложенные записи

Файл текстового поля принадлежит всей операции преобразования, даже если
поле находится в common, вложенном в другую запись. Ссылки на записи и
составление записей передают подготовленные файлы наружу вместе с YAML;
контрольное восстановление XML получает эти файлы до сравнения. Пустой файл
и отсутствие файла сохраняют прежний смысл на любой глубине. Компилятор
выводит вызовы из деклараций заранее: во время преобразования нет поиска
по графу деклараций и условий по именам common-объектов.
