# Дизайн: убрать полный diff XML-дерева из sync

## Контекст

`nkdk sync` сейчас считает `changedXmlFiles` через `snapshotXmlTree` и `diffXmlTree`: до и после синхронизации читает всё XML-дерево в память как UTF-8 строки и сравнивает содержимое файлов.

На больших конфигурациях это приводит к OOM. Профиль показал, что финальный обход читает не только `.xml`, но и `.bin`, `.bsl`, `.zip`, `.png`; при `small` перед OOM было прочитано около 1.4 GB файлов, а heap вырос почти до 2 GB.

Для `round-trip-yaml` этот отчёт не нужен: результат диагностики всё равно собирается внешним `git diff` после замены активного XML-каталога.

## Цель

Убрать чтение всего XML-каталога из runtime-пути `sync`, сохранив полезный отчёт об изменённых файлах только там, где он действительно нужен: в инкрементальной синхронизации.

## Поведение full sync

`syncConfigurationToXML` больше не считает `changedXmlFiles`.

Полная синхронизация возвращает:

- количество успешно обработанных объектов;
- ошибки;
- применённые миграции, если они были.

CLI `nkdk sync` при full sync не печатает блок `Изменённые XML-файлы`.

## Поведение incremental sync

`syncConfigurationIncrementallyToXML` продолжает возвращать `changedXmlFiles`, но список строится не сравнением содержимого дерева, а по операциям записи и удаления.

Вводится операционный `XmlChangeTracker`:

- перед записью файла проверяет, существовал ли файл;
- `writeFile` или `copyFile` регистрируют `added`, если файла не было, иначе `changed`;
- `rm` регистрирует `deleted`, если файл существовал;
- если файл перезаписан тем же содержимым, он всё равно считается `changed`.

Такой список является отчётом о действиях sync, а не побайтовым diff. Это достаточно для CLI и диагностики инкрементального sync.

## Что удаляем

Из runtime-пути удаляются:

- `snapshotXmlTree`;
- `diffXmlTree`;
- чтение всего XML-дерева ради `changedXmlFiles`;
- fallback на hash/content diff.

Если после чистки функции больше нигде не нужны, их нужно удалить вместе с тестами, которые проверяют побайтовое сравнение дерева.

## Тестирование

Нужно обновить full sync тесты:

- больше не ожидать `changedXmlFiles`;
- проверить, что успешный full sync и миграции продолжают работать.

Нужно сохранить incremental sync тесты:

- `changedXmlFiles` содержит файлы, которые incremental sync записал или удалил;
- `changed` означает факт перезаписи, а не отличие содержимого.

Нужно добавить или обновить CLI-тест:

- full sync не печатает `Изменённые XML-файлы`;
- incremental sync продолжает печатать этот блок, если трекер вернул изменения.

## Не цели

- Не делаем точный побайтовый diff XML-дерева.
- Не используем `git` внутри core.
- Не меняем механизм `round-trip-yaml`: он продолжает использовать внешний `git diff`.
