# Универсальный реестр локальных YAML-проверок

## Цель

Обеспечить единый способ запуска локальных семантических проверок YAML-значения по его property-типу. Первый потребитель — проверка уникальности имён элементов управляемой формы:

- в отдельном `Форма.yaml`;
- во вложенном свойстве `Форма` объекта `ОбщаяФорма`.

## Границы

Реестр обслуживает только локальные диагностики первого прохода. Обработчики не строят проектные индексы, не проверяют ссылки и не создают проверки второго прохода.

Механизм не является расширением JSON Schema и не использует custom keywords TypeBox/Ajv. JSON Schema продолжает отвечать за структуру, а реестр — за правила, зависящие от семантики property-типа и `rules.ts`.

## Архитектура

В validation-слое появляется нейтральный реестр:

```text
property type -> local YAML value validator
```

Регистрация и получение обработчика выполняются по имени property-типа. Общий validation-слой не содержит условий по `ОбщаяФорма`, имени свойства `Форма` или типу `ClientApplicationForm`.

Обработчик получает:

- путь файла;
- разобранный YAML целиком;
- проверяемое YAML-значение;
- базовый YAML-путь этого значения;
- сведения о владельце, достаточные для локальной диагностики.

Обработчик возвращает только локальные диагностики первого прохода. Все пути результата должны учитывать переданный базовый путь.

## Точки вызова

### Корневое значение файла

Validation определяет item type ресурса без частных условий и вызывает зарегистрированный обработчик для корневого YAML-значения с пустым базовым путём.

Для отдельного `Форма.yaml` item type равен `ClientApplicationForm`, поэтому проверка получает тело формы от корня.

### Значение свойства

Существующий обход `rules.ts` первого прохода вызывает зарегистрированный обработчик для каждого фактически присутствующего свойства с известным property-типом.

У `ОбщаяФорма/*/Свойства.yaml` свойство `Форма` имеет тип `ClientApplicationForm`. Поэтому тот же обработчик получает значение формы с базовым путём `["Форма"]`, а диагностики элементов имеют пути вида `/Форма/Элементы/...`.

## Проверка формы

Модуль управляемой формы регистрирует локальный обработчик для `ClientApplicationForm`.

Обработчик использует общий сборщик имён формы, который:

- сравнивает имена глобально в пределах одного значения формы;
- сравнивает без учёта регистра;
- учитывает явные элементы;
- всегда резервирует single-имена;
- рекурсивно резервирует single-имена отсутствующих single-элементов.

Для отдельного `Форма.yaml` сохраняется существующий объединённый обход с проверками DataPath, чтобы не возвращать второй полный обход формы. Для вложенной общей формы зарегистрированный обработчик выполняет локальный обход её значения. Оба пути используют один сборщик и одинаковые правила формирования диагностик.

## Ошибки и изоляция

- Отсутствующее YAML-значение не вызывает обработчик свойства.
- Невалидная структура, не позволяющая определить правило элемента, пропускается локальным обработчиком: структурную ошибку уже сообщает JSON Schema.
- Состояние обработчика создаётся заново для каждого YAML-значения. Имена разных форм никогда не попадают в общий набор.
- Диагностики обработчика относятся к `source: "structure"` и не смешиваются со schema diagnostics.

## Профилирование

Время зарегистрированных локальных проверок учитывается в первом проходе. Существующий показатель проверки уникальности имён формы сохраняется:

- для отдельной формы он измеряет завершающую обработку имён в объединённом обходе;
- для вложенной формы он измеряет вызов зарегистрированного обработчика.

Итоговый профиль не суммирует имена между формами и не трактует общее число validation-диагностик как число конфликтов имён.

## Проверки

Нужны тесты следующих договоров:

- реестр вызывает обработчик по property-типу и передаёт базовый YAML-путь;
- незарегистрированный тип не создаёт диагностики;
- отдельный `Форма.yaml` сохраняет существующее поведение;
- общая форма обнаруживает конфликт с путём `/Форма/Элементы/...`;
- две разные общие формы могут содержать одинаковые имена без конфликта;
- невалидное значение вложенной формы не приводит к аварии локального обработчика;
- compiled standalone validation выполняет тот же локальный обработчик, поскольку он запускается после Ajv.
