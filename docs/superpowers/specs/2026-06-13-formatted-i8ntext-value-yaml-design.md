# Value-Based YAML для FormattedI8nText

## Контекст

В `2026-06-11-form-validation-schema-errors-design.md` зафиксирован общий переход от
вариантов имени YAML-ключа к вариантам внутри значения. Для `UserVisible` этот переход
уже реализован: вместо `РазрешитьИспользование` / `ЗапретитьИспользование` используется
один ключ `Использование` с объектом значения.

Для `FormattedI8nText` старый контракт ещё остался в коде:

- правила содержат `yamlFormatted`, например `ФорматированныйЗаголовок`;
- `toYAML` выбирает между `rule.yaml` и `rule.yamlFormatted` по `formatted`;
- `fromYAML` отдельно читает `yaml[rule.yamlFormatted]`;
- JSON Schema совпадает с `I8nText` и не описывает форматированность.

Старый ключ `ФорматированныйЗаголовок` считается устаревшим и не должен поддерживаться
как совместимость чтения.

## Целевой YAML

Все свойства типа `FormattedI8nText` выгружаются в объектной форме под базовым ключом
из `rule.yaml`. Значение всегда содержит поле `Текст`.

Обычный текст:

```yaml
Заголовок:
  Текст: Обычный текст
```

Обычный многоязычный текст:

```yaml
Заголовок:
  Текст:
    ru: Обычный текст
    en: Plain text
```

Форматированный текст:

```yaml
Заголовок:
  Форматированный: Истина
  Текст: "<b>Заголовок</>"
```

Форматированный многоязычный текст:

```yaml
Заголовок:
  Форматированный: Истина
  Текст:
    ru: "<b>Заголовок</>"
    en: "<b>Title</>"
```

Поле `Форматированный` пишется только для `formatted: true`. Если оно отсутствует,
значение считается неформатированным. Значение `Форматированный: Ложь` не является
целевым форматом и не должно выгружаться.

## Архитектура

`FormattedI8nText` получает собственный YAML-тип и JSON Schema, а не переиспользует
`I8nTextYAML` напрямую:

- `Текст` обязателен и имеет тот же формат, что `I8nTextYAML`: строка для одного
  языка или карта языков;
- `Форматированный` необязателен и допускает только `Истина`;
- лишние свойства запрещены.

`FormattedI8nTextPropertyRule` больше не содержит `yamlFormatted`. Правило описывает
только базовый YAML-ключ через `yaml`.

`toYAML` всегда возвращает `{ [rule.yaml]: { Текст, Форматированный? } }`. Для
получения значения `Текст` используется существующая логика `I8nText`, включая
`excludeIfEqualNameYAML`.

`fromYAML` читает только значение из `rule.yaml`. Если `Форматированный: Истина`,
модель получает `formatted: true`; если поле отсутствует, `formatted: false`.
Старый соседний ключ `yamlFormatted` не читается.

XML-цикл не меняется: `formatted` по-прежнему хранится в XML-атрибуте
`formatted="true"`, а языковые значения остаются в `v8:item`.

## Затронутые Области

Нужно обновить общий объект:

- `packages/core/metadata/commonObjects/formattedI8nText/types.ts`;
- `fromYAML.ts`, `toYAML.ts`, `toJSONSchema.ts`;
- focused YAML/schema-тесты и фикстуры `formattedI8nText`.

Нужно обновить правила и YAML-типы форм, где сейчас используется `yamlFormatted`:

- `ExtendedTooltipRules`;
- `LabelDecorationRules`;
- `PictureDecorationRules`;
- связанные `PartialYAML`-типы и тестовые YAML-фикстуры.

Если поиск найдёт другие активные `yamlFormatted` в `packages/core/metadata/**`, их
нужно перевести на тот же контракт в рамках этой работы.

## Ошибки И Невалидный YAML

`ФорматированныйЗаголовок` и другие ключи из `yamlFormatted` после перехода не входят
в JSON Schema и не импортируются. Такой YAML считается устаревшим.

Пустой объект:

```yaml
Заголовок: {}
```

невалиден, потому что отсутствует `Текст`.

Явное `Форматированный: Ложь` не является целевым форматом. Схема должна принимать
только отсутствие поля или `Форматированный: Истина`.

## Проверка

Focused-проверки:

- `FormattedI8nText.toYAML` выгружает неформатированный текст как `{ Текст: ... }`;
- `FormattedI8nText.toYAML` выгружает форматированный текст как
  `{ Форматированный: Истина, Текст: ... }`;
- `FormattedI8nText.fromYAML` восстанавливает `formatted: false` при отсутствии
  `Форматированный`;
- `FormattedI8nText.fromYAML` восстанавливает `formatted: true` при
  `Форматированный: Истина`;
- JSON Schema принимает новую форму и отвергает пустой объект, лишние поля,
  `Форматированный: Ложь` и старый `ФорматированныйЗаголовок`.

Интеграционные проверки:

- YAML-тесты для `ExtendedTooltip`, `LabelDecoration`, `PictureDecoration`;
- schema registry / form element schema-тесты, чтобы старый ключ не проходил;
- полный `pnpm test` из корня worktree.

## Ограничения

XML-фикстуры не изменяются. Новые правила fromXML/toXML/fromYAML/toYAML для объектов
форм не добавляются без необходимости: изменение должно остаться в общем типе
`FormattedI8nText` и локальных `rules.ts`/типах, где был `yamlFormatted`.
