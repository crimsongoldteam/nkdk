# ClientApplicationForm schema test speed

## Контекст

`packages/core/metadata/forms/clientApplicationForm/toJSONSchema.test.ts` проверяет допустимые значения свойства `НазначенияИспользования`. Для этого тест строит и компилирует JSON Schema всей управляемой формы.

Изолированный замер показал:

- полный тест выполняется около 44 секунд;
- построение полной schema занимает около 4,3 секунды;
- построение и компиляция schema только свойства `usePurposes` занимают около 24 мс;
- узкая schema принимает `МобильноеПриложение` и `ПлатформаИМобильноеПриложение`, отклоняет `Произвольное`.

Причина превышения бюджета — несоразмерный уровень теста, а не проверяемое правило и не холодный кэш.

## Цель

Сохранить проверку реального validation-договора `usePurposes`, не компилируя полную JSON Schema управляемой формы.

## Решение

В существующем тесте:

1. Сохранить проверку регистрации `exportClientApplicationFormToJSONSchema` как type rule.
2. Получать schema через `exportPropertyToJSONSchema` для `ClientApplicationFormRules.properties.usePurposes`.
3. Компилировать только эту schema через `compileValidationSchema`.
4. Проверять два допустимых явных значения и одно недопустимое значение.
5. Удалить проверку `{}` из этой таблицы: необязательность обычных свойств обеспечивается общим `exportPropertiesToJSONSchema` и не является частным договором `usePurposes`.

Production-код, правила формы, общая schema-компиляция и лимиты длительности не меняются.

## Проверки

- Узкий тест `clientApplicationForm/toJSONSchema.test.ts` проходит и укладывается в бюджет файла 1 000 мс.
- Полный `pnpm test` больше не падает из-за этого файла.
- `pnpm duplicates -- --base 644df4636` не находит новых блокирующих дублей.

## Не входит в задачу

- Оптимизация построения или компиляции полной JSON Schema управляемой формы.
- Изменение production validation.
- Ослабление лимитов длительности тестов.
