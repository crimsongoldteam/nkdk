# Диагностика незаимствованной цели расширения

## Контекст

При проверке ссылок внутри расширения валидатор различает две ситуации:

1. целевой объект или его свойство существует в основной конфигурации, но не заимствовано в расширение;
2. целевой объект или его свойство отсутствует и в расширении, и в основной конфигурации.

Сейчас первая ситуация описывается общим сообщением `Ссылка "…" не включена в расширение`. Оно указывает на ошибку, но не подсказывает МСП следующее действие: заимствовать недостающую цель из основной конфигурации. Из-за этого при заимствовании владельца МСП может не заметить, что используемые свойства также нужно заимствовать.

## Цель

Сделать диагностику первой ситуации пригодной для автоматического исправления МСП: явно сообщить, какой объект метаданных отсутствует в расширении и что его нужно заимствовать из основной конфигурации.

## Выбранный подход

Изменить только текст результата `referenceNotIncludedInExtensionResult`:

> Объект метаданных «&lt;каноническая ссылка&gt;» отсутствует в расширении. Заимствуйте его из основной конфигурации

Эта функция уже вызывается только после отдельной проверки наличия цели в основной конфигурации. Поэтому совет о заимствовании не появится для несуществующей цели и не потребует новой ветки в общем validation-слое.

Текст одинаков для ссылки на самостоятельный объект и на его вложенную цель, например реквизит. В обоих случаях каноническая ссылка точно указывает, что именно нужно заимствовать.

## Рассмотренные варианты

### (А) Изменить текст существующей диагностики — выбран

Сохраняет текущие границы и условия проверки, меняет только пользовательское сообщение. Это минимальное изменение с наименьшим риском.

### (Б) Формировать совет в месте проверки основной конфигурации

Позволяет собрать сообщение непосредственно рядом с условием, но дублирует форматирование между ветками для объектов, свойств и значений. Дополнительная связность не дает нового поведения.

### (В) Добавить отдельный вид результата для необходимости заимствования

Делает состояние явным в типах, но требует протянуть новый вариант через несколько слоев ради одной формулировки. Для текущей задачи это избыточно.

## Поведение

| Цель в основной конфигурации | Цель в расширении | Результат |
| --- | --- | --- |
| есть | нет | Новое сообщение с предложением заимствовать цель |
| нет | нет | Существующая диагностика `Не найден объект "…"` или `Не найдена ссылка "…"` |
| есть | есть | Ошибки отсутствия цели нет; выполняются остальные проверки ссылки |

Неоднозначные ссылки, несовместимые типы, запрещенные ссылки между расширениями и фильтры цели сохраняют текущее поведение.

## Изменения в коде

- `packages/runtime/metadata/validation/projectReferenceIndex.ts`: заменить текст в `referenceNotIncludedInExtensionResult`.
- Не менять алгоритм разрешения ссылок, проверку присутствия цели в основной конфигурации и структуру `Diagnostic`.
- Не добавлять частные условия по виду метаданных в нейтральные слои.

## Тестирование

Обновить ожидания в существующих тестах:

- `projectReferenceIndex.test.ts`: одинаковое адресное сообщение для объекта и его свойства;
- `projectStateDependencyValidation.test.ts`: при наличии цели только в основной конфигурации показывается совет о заимствовании, а после удаления цели из основной конфигурации возвращается обычная ошибка отсутствующей ссылки;
- `validateProject.integration.test.ts`: итоговая диагностика проекта содержит новый текст.

Проверки после реализации:

1. целевые тесты трех перечисленных файлов;
2. `pnpm duplicates -- --base 396ef3d7d`;
3. `pnpm test`.

## Границы

- Валидатор не заимствует объекты автоматически.
- Формат YAML и XML не меняется.
- XML-фикстуры не меняются.
- Механизм наследования картинок и других файловых ресурсов не меняется.
- Новая диагностика не используется, если цель отсутствует в основной конфигурации.
