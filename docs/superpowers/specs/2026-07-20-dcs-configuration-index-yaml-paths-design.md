# Адресация DCS-данных в файле индекса конфигурации по YAML-пути

## Контекст

Новый импорт из XML строит Проект и файл индекса конфигурации. Индекс хранит выжимку XML-данных, которые нужны для последующего восстановления XML при синхронизации Проекта обратно в конфигурацию 1С.

После добавления адресации именованных коллекций и переноса `UserSettingsID` в YAML в ERP-импорте остались конфликты индекса на адресах вида:

- `...Свойство.Поля`
- `...Свойство.Отбор`
- `...Свойство.Элементы`

Эти адреса слишком общие: разные вложенные DCS-узлы и близкие коллекции записывают XML-служебные данные в один и тот же логический адрес.

## Принятое решение

DCS-часть индекса конфигурации адресуется по полному YAML-пути.

Правило адресации:

- объектные YAML-свойства добавляют сегмент с именем свойства;
- элементы YAML-массивов добавляют позиционный сегмент `[0]`, `[1]`, `[2]`;
- элементы YAML-словарей добавляют сегмент с YAML-ключом;
- адрес строится от текущего логического адреса владельца XML/YAML-файла;
- для DCS не пытаемся искать смысловой ключ, если путь уже можно построить по YAML-структуре.

Пример:

```text
Справочник.Товары.Форма.ФормаСписка.Атрибут.Список.Свойство.Отбор.Элементы[0].Поле
```

## Что хранится на этих адресах

На DCS-адресах индекс хранит только XML-служебные данные, которые теряются или могут измениться при преобразовании XML → YAML:

- `xsi:type`;
- XML-префикс имени узла;
- факт `xsi:nil`;
- факт явно пустого XML-значения;
- текст XML-значения, если он не выражен отдельным YAML-полем;
- порядок дочерних XML-свойств;
- факт присутствия XML-свойства, когда отсутствие и пустое значение различаются.

`UserSettingsID` в DCS не хранится в индексе: он хранится в YAML как UID-строка.

`uuid` для DCS не предусматривается: в текущих XML-фикстурах DCS не найдено вложенных DCS-элементов с `uuid`.

## Почему не смысловые ключи

Для DCS есть элементы с естественными именами или полями, но не для всех узлов есть надёжный смысловой ключ. Смешивание смысловых ключей и позиционных ключей усложнит правила и может дать неочевидные отличия между похожими DCS-ветками.

В первой версии выбирается единый и предсказуемый договор: адрес равен пути в YAML.

## Ограничения

Позиционная адресация массивов чувствительна к перестановке элементов. Если пользователь переставит элементы массива, XML-служебные данные индекса останутся привязаны к позиции, а не к смысловому элементу.

Это ограничение принимается для первой версии. Если позже появится необходимость сохранять привязку при перестановках, можно добавить отдельный договор смысловых ключей для выбранных DCS-коллекций.

## Границы задачи

В эту задачу не входит:

- изменение YAML-формата DCS;
- хранение полного XML DCS в индексе;
- перенос `UserSettingsID` обратно в индекс;
- поиск или генерация `uuid` для DCS;
- исправление всех round-trip расхождений DCS, не связанных с конфликтами логических адресов индекса.

## Ожидаемый результат реализации

После реализации импорт ERP не должен падать из-за конфликтов индекса на DCS-адресах вида `Свойство.Поля`, `Свойство.Отбор`, `Свойство.Элементы`.

Новые адреса должны указывать на конкретный YAML-узел DCS, а не только на имя свойства-контейнера.
