# Чистый ERP round-trip

## Проблема

Полный ERP round-trip выявил несколько независимых потерь формы XML:

- `DcsAvailableValues` принимал только первый из соседних `dcssch:availableValue`;
- raw-аннотация дополнительной колонки формы привязывалась ко всей колонке, а не к её свойству;
- числоподобная строка внутри `!xml/invalid` превращалась в число при разборе YAML и теряла явное строковое представление на границе worker;
- присутствующий пустой `RootCommandInterface` исчезал, потому что вложенный импорт возвращал `undefined`;
- проверяющий скрипт считал служебный `.nakidka-migrations.yaml` частью XML-договора.

## Решение

### Повторяющиеся доступные значения

Зарегистрировать для `DcsAvailableValues` существующий договор
`xmlImportPropertyBehavior.repeatedXMLNodes`. Структурный обход передаёт все
одноимённые узлы существующему преобразователю, который уже поддерживает массив.

### Дополнительные колонки формы

При входе в `AdditionalColumns.Column` дополнять `rulePath` свойством `columns`.
Тогда доказательство XML-аномалии локализует отличие на конкретном свойстве
колонки и не заменяет raw-снимком всю колонку.

### Явные строки

Для скалярного `!xml/invalid` восстанавливать исходный текст двойной кавычки после
разбора `js-yaml`, а отметки двойных кавычек переносить через worker компактным
списком путей. Само дерево YAML остаётся обычным структурно-клонируемым объектом.

### Пустой корневой интерфейс команд

Зарегистрировать для `RootCommandInterface` существующий договор
`presenceAffectsExport`. Общий импорт вложенного свойства сохраняет `{}`, когда
XML-узел присутствует, но не содержит смысловых полей.

### Служебный файл миграций

Считать `.nakidka-migrations.yaml` reference-only файлом round-trip-навыка и
переносить его из исходного каталога вместе с прочими файлами вне YAML-договора.

## Оставшиеся предупреждения

Три `unresolved_data_path` относятся к исходным ссылкам 1С на форменные или
вычисляемые колонки, которые нельзя доказать только по индексу метаданных. Они
сохраняются без преобразования и не создают XML-расхождений. Одно
`xml_raw_scope_too_broad` сохраняет точный XML большой коллекции предопределённых
счетов, когда доказательство не может локализовать отличие до отдельного элемента.
Это предупреждения о качестве смыслового YAML, а не потери XML.

## Проверка

- регрессионные тесты каждой группы;
- чистый round-trip на `doc`;
- полный ERP round-trip без XML-расхождений;
- `pnpm duplicates -- --base origin/develop`, архитектурные проверки и `pnpm test`.
