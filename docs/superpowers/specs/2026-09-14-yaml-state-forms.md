# Формы YAML для конечных состояний

Дополнение к разделу 8 языка деклараций. Конечное состояние представляется
значением enum; его XML-проекция и получение из связанных данных остаются
отдельными обычными декларативными конструкциями. Это часть общего
`state-relation`, а не специальный обработчик расширяемого объекта.

## Короткая таблица форм

```yaml
yaml:
  kind: states
  values:
    - {value: base-control, form: absent}
    - {value: own-control, form: empty}
    - {value: base-notify, form: empty, tag: проверять}
    - {value: own-notify, literal: "", tag: проверять}
```

`value` ссылается на объявленный вариант enum. Каждая строка содержит ровно
одно из `form` или `literal`. `form` допускает `absent` и `empty`; `literal`
задаёт строку, включая пустую. `tag` — локальное имя смыслового тега без `!`.
Отсутствующему полю нельзя назначить тег. Теги механизма аномалий не могут
быть переопределены этой таблицей.

Один вариант имеет одну каноническую форму; разные варианты не могут иметь
одинаковую пару «форма + тег». Таблица покрывает все варианты. Это проверяется
при сборке. Отсутствующая форма однозначно задаёт восстановление пропущенного
YAML-поля и его сокращение при записи; повторное ручное описание этого
поведения не требуется. Повторное ручное описание YAML-присутствия отклоняется: у одного
поведения должен оставаться один источник. XML-присутствие можно уточнять
существующим правилом.

Пустое поле и строка `""` различаются при чтении и записи. Смысловой тег
проверяется по таблице до передачи в механизм тегов аномалий. Неподдержанный
вход не добавляется в таблицу: действует общий договор регистрации аномалий.
Компилятор выпускает обычное сопоставление Rust; во время преобразования
YAML-декларации не интерпретируются.

## Проверка и границы

Одна общая матрица защищает четыре формы, неоднозначную таблицу, чужой тег
и неправильную форму значения. Интеграционная матрица проверяет обычную
запись и ту же запись внутри коллекции. Названия вариантов и тега в общей
проверке должны быть нейтральными; независимые ожидания расширяемого объекта
берутся из существующих TS-тестов.

JSON Schema передаёт типы обычных значений и необходимость проверки
смысловых тегов рабочим валидатором. Одного JSON Schema недостаточно для
различения тегов или отсутствующего поля после обычного разбора YAML.

Это расширение не выполняет соединение коллекций XML, не подменяет
базовый индекс и не завершает `ExtendedConfigurationObject`. Его полный
договор по ссылке, применимости и соседним `PropertyState` описан в
[исследовании семейства](../reports/2026-09-13-enum-value-dependencies.md).
