# Архитектура тестов для разработки новой функциональности

## Цель

Сдерживать рост тестового набора без потери проверяемых договоров. При добавлении
функциональности ИИ должен сначала переиспользовать и усиливать существующие
тесты, удалять ставшие избыточными проверки и создавать новый тест только для
уникального наблюдаемого поведения.

## Распределение инструкций

`AGENTS.md` содержит короткие обязательные принципы, применимые к любой задаче.
Подробный исполняемый процесс живёт в `.agents/testing.md`; `AGENTS.md` ссылается
на него. Это сохраняет видимость правил и не перегружает главный файл.

## Выбор теста

Перед изменением ИИ находит проверки затрагиваемого договора по импортируемому
символу, соседним тестам и уровню операции. Проверка размещается на самом узком
стабильном уровне, который полностью выражает наблюдаемый договор. Интеграционный
тест добавляется только для взаимодействия между слоями.

Предпочтительный порядок:

1. добавить случай в существующий `it.each`;
2. усилить существующий тест;
3. создать новый тест, если новое поведение нельзя ясно выразить первыми двумя
   способами.

Новый тест сохраняется, только если проверяет уникальный класс входов, границу,
ошибку, межслойное взаимодействие или обнаруживает мутант, не обнаруживаемый
другими тестами. Перестановки одного класса эквивалентности отдельными тестами не
покрываются.

## Процесс изменения

Для нового или изменённого договора ИИ сначала получает падающую проверку, затем
реализует минимальное изменение. После зелёного целевого теста запускается
Stryker для изменённых production-файлов. Содержательный выживший мутант требует
усиления проверки; эквивалентный или несущественный мутант документируется и не
служит причиной для искусственного теста.

Если новая функциональность делает существующие тесты избыточными, ИИ объединяет
или удаляет их в том же изменении. Удаление допустимо, когда оставшиеся тесты
сохраняют наблюдаемые договоры и множество обнаруживаемых мутантов. После
изменения выполняются целевые тесты, `pnpm type-check`, повторный mutation
testing и `pnpm test`.

## Команды проверки

В проекте вводится безопасная обёртка над Stryker:

```bash
pnpm test:mutation -- --report <имя> <production-файл> [production-файл...]
```

Обёртка требует хотя бы один явный файл, принимает только production TypeScript
внутри `packages/`, отклоняет тесты, фикстуры и generated-код и передаёт Stryker
точный список `mutate`. Запуск без списка файлов завершается ошибкой, чтобы ИИ не
начал mutation testing всего репозитория. Имя отчёта соответствует
`[a-z0-9][a-z0-9-]*`.

Отчёт со статусами `Timeout`, `RuntimeError` или `CompileError` считается
недостоверным, и команда завершается ошибкой. Такие статусы не могут служить
доказательством того, что тесты обнаруживают мутант.

Команда сохраняет полный JSON-отчёт в
`reports/stryker/<имя>.json` и HTML-отчёт в
`reports/stryker/<имя>.html`. Для проверки удаления тестов ИИ выполняет:

```bash
pnpm test:mutation -- --report before <production-файлы>
# объединение или удаление избыточных тестов
pnpm test:mutation -- --report after <production-файлы>
pnpm test:mutation:compare -- before after
```

`test:mutation:compare` сначала требует одинаковый production-исходник в обоих
отчётах, затем проверяет, что каждый ранее обнаруживаемый мутант остался
обнаруживаемым. Снижение только общего mutation score недостаточно: сравниваются
конкретные мутанты и их статусы. При добавлении тестов та же команда показывает,
какие содержательные выжившие мутанты стали обнаруживаемыми.

После mutation testing ИИ запускает:

```bash
pnpm type-check
pnpm test
```

Подробная инструкция в `.agents/testing.md` содержит эти команды дословно.

## Защищённые проверки

Автоматическому удалению не подлежат:

- round-trip проверки;
- проверки существующих XML/YAML-фикстур;
- snapshot- и архитектурные проверки;
- регрессионные тесты со ссылкой на issue.

Такие тесты можно изменить или удалить только по отдельному явному решению с
обоснованием сохранности их договора.

## Результат

Для каждой задачи ИИ кратко фиксирует, какие существующие тесты были расширены,
какие удалены как избыточные, какое уникальное поведение оправдывает новые тесты
и как изменилось множество обнаруживаемых мутантов.
