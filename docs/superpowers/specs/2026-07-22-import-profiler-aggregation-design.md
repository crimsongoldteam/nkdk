# Агрегация профиля XML-импорта

## Цель

Убрать запись профиля для каждого импортируемого файла. Профиль должен показывать распределение времени и памяти по этапам без существенного влияния на длительность импорта ERP.

## Решение

| Область | Решение |
| --- | --- |
| Общий профилировщик | Добавить необязательный режим агрегации записей по сочетанию операции, этапа, подэтапа, области выполнения и номера worker. |
| Worker XML-импорта | Включить агрегацию отдельно для первого и второго проходов. |
| Главный процесс XML-импорта | Сохранить текущие отдельные записи: каждый архитектурный подэтап выполняется один раз. |
| Валидация и другие операции | Сохранить текущее поведение. |

## Правила агрегации

| Поле | Правило |
| --- | --- |
| Время | Сумма длительностей всех выполнений подэтапа. |
| Количество элементов | Сумма обработанных элементов. |
| Объём данных | Сумма обработанных байтов. |
| RSS и heap в начале | Значение первой записи. |
| RSS и heap в конце | Значение последней записи. |
| Максимальный RSS и heap | Максимум среди объединяемых записей. |
| Порядок строк | Порядок первого появления подэтапов. |

## Проверка

| Сценарий | Ожидание |
| --- | --- |
| Один подэтап выполняется для нескольких файлов | В журнал выводится одна агрегированная строка. |
| Первый и второй проходы используют одинаковое имя подэтапа | Каждый проход выводит собственную агрегированную строку при своём завершении. |
| Профилирование выключено | Дополнительных вычислений и строк журнала нет. |
| Валидация | Формат и количество существующих записей не меняются. |

## Ограничения

- Агрегация уменьшает объём журнала, но не меняет точки измерения памяти: кратковременный пик между началом и концом отдельного измерения может быть не зафиксирован.
- Общий пик процесса по-прежнему следует дополнительно измерять системным средством `/usr/bin/time`.
