# Создание объявленных записей из смысловых значений

Продолжение общего механизма значений: уже существующие выражения `sequence`,
`record` и `if` должны создавать хранилище коллекции напрямую. Нельзя подменять
создание записи печатью YAML/XML с последующим повторным чтением.

```yaml
presence:
- target: self
  yaml:
    missing:
      denotes:
        if: {input: emit}
        then:
          sequence:
          - record:
              label: {literal: prefix}
              enabled: {input: emit}
              amount: {literal: 9007199254740993}
        else: {absent: true}
```

Пример применяется к объявленной коллекции записей с соответствующими полями.
Тип `amount` — `number` с профилем `decimal`. Число не проходит через двоичное
число с плавающей точкой. Поля конструктора связываются по именам при сборке,
а сгенерированный код использует слоты.

Отсутствие коллекции и существующая пустая коллекция различаются: `absent`
означает первое, `sequence: []` — второе. Правило отсутствия применяется только
к отсутствующему свойству; явно заданный список, в том числе пустой, имеет
приоритет. XML и YAML используют один механизм создания значений, но каждое
направление выбирает своё правило присутствия.

Скалярное хранилище создаётся тем же генератором записи, который создаёт её
читатели и писатели. Общий конструктор получает заимствованные смысловые
слоты и наполняет типизированные поля. Он не зависит от имён предметных объектов,
числа полей, XML-путей или YAML-ключей. Строки и десятичные числа становятся
собственностью итоговой записи; отдельное дерево промежуточных значений
не создаётся. Вычисленные строковые выражения могут иметь временное значение;
устранение его копирования требует отдельного измерения.

Первый исполняемый вариант охватывает записи скалярного генератора: текст,
boolean, точные числа и перечисления, в том числе поля XML-атрибутов. Создание
вложенных записей и коллекций внутри строки должно получить тот же договор
в своих генераторах; пока неподдержанный конструктор отклоняется при сборке.
Наличие этого ограничения не является основанием сохранять нормальные строки
через `!xml` или считать `PropertyState` полностью подключённым.

## Объединение объявленных последовательностей

В восстановлении коллекции `concat` объединяет последовательности одного
объявленного типа. Ветви `if` могут возвращать `sequence: []`, но не `absent`:
пустая последовательность и отсутствие коллекции сохраняют разные значения.

```yaml
concat:
- if: {present: {field: notice}}
  then:
    sequence:
    - record: {name: {literal: ExtendedConfigurationObject}, mode: {field: notice}}
  else: {sequence: []}
- if: {present: {field: neighbor}}
  then:
    sequence:
    - record: {name: {literal: Comment}, mode: {field: neighbor}}
  else: {sequence: []}
```

Компилятор проверяет тип каждого элемента и генерирует добавление записей в один
вектор. Вместимость определяется по верхней границе числа конструкторов;
промежуточные векторы для отдельных ветвей не создаются. Обычное текстовое `concat`
сохраняет прежний смысл. На данном этапе объединение коллекций подключено к
контексту восстановления объявленных записей; это не обещание поддержки любых
вычисляемых последовательностей во всех выражениях.

## Общая коллекция состояний

Каждый смысловой признак читает свою запись через `select`. Одна таблица
`state-relations` задаёт оба направления для признака, а общий конструктор
коллекции собирает записи из восстановленных признаков в объявленном порядке.
Так нормальные соседи сохраняются в соответствующих полях YAML; отдельный
служебный список в YAML не добавляется. Неоднозначность выбора не разрешается
произвольным выбором дубля. Отступления от нормальной записи и порядка сохраняет
существующий механизм доказанного расхождения XML.

Для скрытой коллекции аномалия помещается на физическую границу свойства
(`InternalInfo` в проверочном примере). Она не становится отдельным корневым
YAML-документом при вставке между полями владельца. Нормальные строки не должны
попадать в raw из-за ещё не реализованного свойства: перед полной приёмкой
владельца все зарегистрированные источники должны участвовать в сборке.
