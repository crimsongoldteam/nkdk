# Значения по умолчанию при автоматическом переносе

Дополнение к единой спецификации деклараций. Новых конструкций языка нет.

## Скрытый скаляр

Если исходный rules.ts одновременно запрещает чтение и запись YAML и задаёт
статическое неявное значение скаляра, декларация сохраняет поле в смысловой
модели и XML-отображении, но не добавляет обычный YAML-ключ. Существующее правило
присутствия восстанавливает неявное значение. XML-присутствие и каноническая
форма выводятся тем же способом, что у видимого скаляра с такими параметрами.

Нестандартное или неизвестное XML-значение не теряется: общий механизм
сохраняет его аномалией на границе скрытого свойства. Особых обработчиков по
имени свойства в Rust нет. Односторонний запрет YAML, отсутствие известного
значения по умолчанию и неподдержанные типы не считаются перенесёнными.
Дополнительные правила профиля владельца по-прежнему требуют отдельной сборки.

## Пустой неявный локализованный текст

Для исследованного договора I8nText (`implicitValueYAML: ""`,
`defaultValueXMLRaw: ""`) отсутствие YAML означает отсутствие смыслового текста;
обычный экспорт создаёт пустой XML-элемент. Сокращение описывается выражением
над значением, а не функцией преобразования. Режимы сохранения пустоты,
сокращения по имени, типизации и пропуска пустого XML пока не объединяются
автоматически с этим договором.

Существующий пустой перевод отличается от пустого контейнера. Он сохраняется
обычной отметкой `!xml/invalid` у языка; `$xml` для этих случаев не требуется.
Непустой синоним стандартного реквизита проверяется по исходной YAML-фикстуре.

## Пустая XML-поправка

В действующем договоре поправок `$xml: ""` обозначает существующий пустой
элемент, а `$xml: null` — удаление элемента. Старое ожидание TS для пустого
контейнера не переносится буквально, если оно смешивает эти состояния.
Совместимость `$xml: {}` для старого случая пустого boolean проверяется
отдельным обратным преобразованием; сравнение YAML остаётся строгим.
