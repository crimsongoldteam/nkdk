# Обязательный ОсновнойЯзык В YAML-Конфигурации

## Контекст

В `packages/core/metadata/appliedObjects/configuration/rules.ts` у свойства
`defaultLanguage` сейчас указано:

```ts
defaultValueXML: "Language.Русский"
```

Из-за этого YAML-проект без поля `ОсновнойЯзык` проходит `validate`: отсутствующее
значение восстанавливается как XML-default, хотя в YAML это поле должно быть
обязательным. В проекте `/home/nikita/git/new-test-yaml` файл
`Конфигурация.yaml` содержит только `Имя` и `Синоним`, но `validate` возвращает
`0 error`.

## Цель

Сделать `ОсновнойЯзык` обязательным полем YAML-конфигурации и не маскировать его
отсутствие XML-default значением `Language.Русский`.

После исправления:

- `Конфигурация.yaml` без `ОсновнойЯзык` должен давать ошибку validation;
- `ОсновнойЯзык: Русский` должен проверяться как ссылка на объект языка;
- `ОсновнойЯзык: Язык.Русский` и `ОсновнойЯзык: Language.Русский` должны
  становиться ошибками, потому что корень ссылки задан правилом поля;
- если объекта `Язык/Русский/Свойства.yaml` нет, validation должен сообщать, что
  объект `Язык.Русский` не найден.

## Решение

Убрать `defaultValueXML: "Language.Русский"` из правила `defaultLanguage`.
Поле остаётся `required: true`.

Обязательность нужно проверять на уровне YAML validation, а не через скрытую
подстановку значения в модель. Если общий JSON Schema-экспорт уже умеет учитывать
`required: true` безопасно для проектных `Свойства.yaml`, использовать его. Если
глобальное применение `required` ломает частичные или вложенные схемы форм, добавить
проверку обязательных YAML-ключей в проектный validation-путь для файлов
`Свойства.yaml`.

## Сокращённая Форма Ссылок

Не добавлять частный флаг вроде `allowShortName` в `rules.ts`.

Сокращение `ОсновнойЯзык: Русский` должно опираться на существующий механизм
сокращения ссылок, а не на отдельную приписку для языка. Универсальная точка
изменения - `metadataTargets`: `parseMetadataTargetFromYAML`,
`formatMetadataTargetToYAML` и JSON Schema для metadataTarget-ссылок.

Ожидаемая семантика универсального механизма:

- правило с `metadataTarget` задаёт допустимый корень ссылки;
- если у object-ссылки ровно один допустимый корень, YAML обязан хранить только
  имя объекта без префикса;
- если корней нет или их несколько, YAML обязан хранить полную форму с YAML-корнем;
- импорт YAML канонизирует короткую форму в модельную ссылку, например
  `Русский -> Language.Русский`;
- экспорт YAML пишет короткую форму, когда корень однозначен;
- schema/validation не должны принимать произвольные строки как ссылки: короткая
  форма всё равно должна проверяться через resolver проекта.

Следствия:

- для `metadataTarget: { kind: "object", roots: ["Language"] }` корректно
  `ОсновнойЯзык: Русский`;
- для такого же правила некорректны `ОсновнойЯзык: Язык.Русский` и
  `ОсновнойЯзык: Language.Русский`;
- для `metadataTarget: { kind: "object", roots: ["Role"] }` корректно
  `Администратор`;
- при единственном корне `Role` некорректны `Role.Администратор` и
  `Роль.Администратор`;
- YAML-корень для `Role` в проекте называется `Роль`; корня `Роли` нет, и его не
  нужно упоминать как отдельный поддерживаемый или бывший формат;
- если ссылка может указывать на разные корни, например `Catalog` или `Document`,
  YAML должен писать `Справочник.Товары` или `Документ.Заказ`.

Важно: исправление не должно превращаться в частное условие
`if defaultLanguage then Language`. Механизм должен быть пригоден для других
однозначных `MetadataItemLink`-ссылок.

## Удаление `roleReferenceYAML`

`roleReferenceYAML: "name"` становится лишним частным механизмом и должен быть
удалён после введения общего правила для object-ссылок с одним корнем.

Текущие места использования:

- `rootCommandInterface`;
- `homePageWorkArea`;
- тесты `metadataRef/fromYAML.test.ts` и `metadataRef/toYAML.test.ts`.

Их нужно перевести на обычные metadataTarget-ссылки с единственным корнем `Role`.
Старое поведение, которое пропускало UUID-подобные ключи и строки вроде
`ЛокальныйПуть.НачалоРаботы`, больше не нужно. Такие значения должны становиться
ошибками validation/import, если они встречаются в `Роли`.

## Не Входит В Задачу

- Не менять XML-фикстуры.
- Не добавлять `allowShortName` или похожий частный флаг для `defaultLanguage`.
- Не сохранять `roleReferenceYAML: "name"` как параллельный способ сокращения ролей.
- Не ослаблять validation так, чтобы неизвестные ссылки становились обычными
  строками.
- Не добавлять ручные `fromYAML/toYAML` правила для конфигурации, если поведение
  можно выразить через существующий механизм ссылок.

## Тестирование

Добавить red-green проверки:

1. `validateProject` для `Конфигурация.yaml` без `ОсновнойЯзык` возвращает ошибку
   обязательного поля.
2. `validateProject` принимает:

   ```yaml
   Имя: Конфигурация
   ОсновнойЯзык: Русский
   ```

   если существует `Язык/Русский/Свойства.yaml`.
3. `validateProject` для `ОсновнойЯзык: Русский` возвращает ошибку отсутствующей
   ссылки, если файла языка нет.
4. Явная полная форма `ОсновнойЯзык: Язык.Русский` становится ошибкой после
   включения универсального правила коротких object-ссылок.
5. Для ролей в `rootCommandInterface` и `homePageWorkArea` YAML принимает
   `Администратор`, но не принимает `Role.Администратор`, `Роль.Администратор`,
   UUID-подобные ключи и `ЛокальныйПуть.НачалоРаботы`.
6. Тест на правила конфигурации подтверждает, что у `defaultLanguage` больше нет
   `defaultValueXML: "Language.Русский"`, а `required: true` остаётся.

После точечных тестов запустить `pnpm test` из корня проекта.

## Риски

Глобальное включение `required: true` в JSON Schema может затронуть схемы, которые
используются как частичные вложенные фрагменты. Если такое проявится, обязательность
нужно ограничить проектной validation-границей, не меняя поведение всех схем.

Слишком широкое принятие коротких ссылок может случайно разрешить строки, которые
раньше были ошибками или значениями других доменов. Поэтому короткая форма должна
быть связана с существующим resolver-ом metadata-ссылок и покрыта отрицательными
тестами.
