# Round-trip по нескольким каталогам и зарегистрированным типам

Дата: 2026-05-09

## Цель

Обновить `/round-trip-xml`, чтобы он проверял несколько каталогов XML-репозитория последовательно и останавливался на первом каталоге, где появился хотя бы один diff. Одновременно убрать жёсткую привязку short round-trip к справочникам: обход должен использовать только типы, зарегистрированные в `TopLevelMetadataItemRules`.

## Границы

В первый вариант входят только зарегистрированные корневые прикладные объекты:

- `Catalogs`
- `Documents`
- `DocumentNumerators`
- `Sequences`

`Enums` и другие незарегистрированные типы не входят в задачу. Новые правила fromXML/toXML/fromYAML/toYAML не добавляются.

## Подход

Выбран подход с двумя уровнями обобщения.

На уровне `packages/core/metadata/appliedObjects/configuration/shortRoundTripXML.ts` жёсткий обход `Catalogs` заменяется обходом `TopLevelMetadataItemRules`. Для каждого правила берётся `xmlDir`; если каталог существует, runner читает все XML-файлы верхнего уровня, импортирует объект в обычном и reference-режиме, затем экспортирует обратно через то же правило.

Формы обрабатываются единым вложенным шагом для каждого объекта зарегистрированного типа. После обработки объекта runner ищет `<xmlDir>/<objectName>/Forms/*.xml`, читает форму и reference-форму, затем записывает metadata XML формы и `Ext/Form.xml` обратно в соответствующее место выходного каталога.

На уровне `.agents/skills/round-trip-xml/round-trip.sh` сохраняется совместимость с текущим поведением: если `NKDK_XML_DIR` указывает на конкретный каталог конфигурации, проверяется только он. Если `NKDK_XML_DIR` указывает на каталог с несколькими дочерними конфигурациями, скрипт сортирует дочерние каталоги и проверяет их последовательно.

После каждого запуска short round-trip скрипт смотрит git diff только внутри проверенного каталога. Если diff есть, он печатает результаты для этого каталога и не запускает следующие каталоги. Если diff нет, переходит к следующему каталогу.

## Вывод скрипта

В stdout-протокол добавляется явный контекст проверенного каталога:

- путь XML-репозитория;
- текущий XML-каталог;
- имя или путь каталога, на котором найден diff;
- существующие блоки `DIFF_COUNT`, `SELECTED_DIFF_FILE`, `TRIAGE_DIFF` и абсолютные пути к XML-файлам.

Одиночный режим и triage-режим сохраняют прежнюю форму выбора diff внутри найденного каталога. Индексы считаются по diff-файлам того каталога, на котором скрипт остановился.

## Ошибки

Ошибки обработки одного объекта или формы внутри `shortRoundTripXML` остаются локальными: runner пишет диагностическое сообщение и продолжает обход, как это уже сделано для справочников и форм.

Ошибки окружения в shell-раннере остаются фатальными:

- не задан `NKDK_XML_REPO`;
- `NKDK_XML_REPO` не является git-репозиторием;
- `NKDK_XML_DIR` не существует;
- рабочее дерево `nakidka-core` не чистое.

Перед каждым прогоном shell-раннер восстанавливает XML-репозиторий к `HEAD`, чтобы diff относился только к текущему запуску.
