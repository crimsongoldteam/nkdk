# ExternalDataSource file-item children

## Цель

`ExternalDataSource` должен восстанавливать таблицы, кубы, таблицы измерений, формы и макеты при `XML -> YAML -> XML` без reference. Свойства, которые есть в исходном XML, не должны пропадать только потому, что при обратной сборке нет reference.

Текущая ошибка проявляется на загрузке в 1С: YAML сохраняет ссылки на формы и таблицы измерений, но результирующий XML не создаёт соответствующие дочерние metadata-объекты и файлы.

## Решение

Таблицы и кубы внешнего источника данных становятся отдельными дочерними объектами в YAML-дереве, как другие file-item childCollections. Корневой `Свойства.yaml` внешнего источника хранит только свойства самого внешнего источника и не содержит модель таблиц и кубов внутри себя.

Новый основной формат:

```text
ВнешнийИсточникДанных/ВнешнийИсточникДанныхВсеСвойства/Свойства.yaml
ВнешнийИсточникДанных/ВнешнийИсточникДанныхВсеСвойства/Таблицы/ТаблицаВсеСвойства/Свойства.yaml
ВнешнийИсточникДанных/ВнешнийИсточникДанныхВсеСвойства/Кубы/КубВсеСвойства/Свойства.yaml
ВнешнийИсточникДанных/ВнешнийИсточникДанныхВсеСвойства/Кубы/КубВсеСвойства/ТаблицыИзмерений/ТаблицаИзмеренияВсеСвойства/Свойства.yaml
```

Формы и макеты внутри таблиц, кубов и таблиц измерений используют уже существующий формат форм:

```text
Таблицы/ТаблицаВсеСвойства/Формы/ФормаСписка/Форма.yaml
Кубы/КубВсеСвойства/Формы/ФормаЗаписи/Форма.yaml
```

## Архитектура

В `rules.ts` для `ExternalDataSource` уже есть `childCollections` с `fileItemRule` для `tables` и `cubes`; для кубов так же задан `fileItemRule` для `dimensionTables`. Новое поведение должно быть реализовано в общем слое `orchestration/appliedObject`, а не через специальные правила fromXML/toXML для ExternalDataSource.

Для `childCollections` с `fileItemRule` оркестратор должен:

- при `XML -> YAML` читать отдельный XML-файл дочернего объекта и писать его собственный `Свойства.yaml`;
- при `YAML -> XML` находить дочерние объекты по папкам и собирать отдельные XML-файлы;
- строить строковые ссылки `Table`, `Cube`, `DimensionTable` в `ChildObjects` из найденных дочерних объектов;
- запускать существующие внешние обработчики `ChildFormNames`, `ChildTemplateNames`, `Module`, `Help`, `CommandModule` относительно каталога дочернего объекта.

Это обобщает уже существующий подход `Configuration`: файловое дерево с `Свойства.yaml` является источником списка дочерних объектов в XML. Для вложенных объектов этот подход применяется через `childCollections.fileItemRule`.

`dimensionTableNames` в `MetadataExternalDataSourceCubeRules` больше не нужен как псевдо-формный список. `<DimensionTable>` должен появляться из `childCollections.fileItemRule`, так же как `<Table>` и `<Cube>` для внешнего источника данных. `ChildFormNames` остаётся только для настоящих форм.

Переходно `YAML -> XML` должен принимать старый inline-формат, где `Таблицы`, `Кубы` или `ТаблицыИзмерений` ещё лежат в родительском `Свойства.yaml`. Но `XML -> YAML` должен писать новый формат с отдельными `Свойства.yaml`.

## Порядок

Без reference порядок дочерних объектов строится из каталогов в стабильной сортировке по имени через `localeCompare("ru")`. Если reference передан, порядок существующих имён сохраняется по reference, а новые имена добавляются в конец группы в русской сортировке. Это повторяет поведение `Configuration/ChildObjects`.

Порядок групп в XML остаётся обязанностью правил экспорта XML: свойства объекта пишутся в `Properties`, а дочерние объекты в `ChildObjects` в порядке правил и контейнеров.

## Ошибки

Если в YAML есть ссылка на форму, но нет соответствующего каталога формы, экспорт не должен молча создавать битую ссылку на несуществующий XML-файл и не должен скрыто удалять ссылку. Ошибка должна быть явной на уровне sync, потому что форма является частью выгрузки и должна быть восстановима.

Папка без `Свойства.yaml` не считается дочерним объектом при сканировании имён. Если такая папка явно попала в синхронизацию как элемент коллекции, это ошибка входного YAML. Если дочерних папок нет, соответствующие `ChildObjects` не создаются.

## Проверка

Нужны точечные тесты:

- `convertAppliedObjectFromXML` для `ExternalDataSource` пишет отдельные `Свойства.yaml` таблиц и кубов;
- формы таблицы и куба импортируются в `Формы/<имя>/Форма.yaml`;
- `syncAppliedObjectToXML` без reference создаёт `Tables/<name>.xml`, `Cubes/<name>.xml`, `DimensionTables/<name>.xml`;
- `syncAppliedObjectToXML` без reference создаёт `Forms/<name>.xml` и `Forms/<name>/Ext/Form.xml` для таблиц и кубов;
- `ChildObjects` таблицы, куба и таблицы измерений содержат соответствующие строковые ссылки;
- runner `round-trip-yaml-1c` на `/home/nikita/git/round-trip/all` проходит текущую группу ошибок `Unknown metadata object` по формам ExternalDataSource и `Unknown type name` по таблицам измерений.

## Не входит

Не меняем XML-фикстуры: они остаются источником истины. Не добавляем новые ручные fromXML/toXML/fromYAML/toYAML правила для самих таблиц, кубов, таблиц измерений или форм, если существующий механизм `rules.ts` и external sync может покрыть поведение.
