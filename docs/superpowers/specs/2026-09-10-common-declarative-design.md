# Единые YAML-декларации common-объектов

Статус: исследовательская спецификация, интерфейс предлагается на обсуждение; реализации нет. Пользователь выбрал отдельные YAML-файлы и разрешил последовательное исследование существующих common с постепенной записью результатов. Это не утверждение, что все особенности уже выражены окончательной грамматикой.

Синтаксис и структура деклараций теперь развиваются в отдельной [спецификации языка common и rules](2026-09-10-declaration-language-design.md). Этот документ и карточки ниже сохраняют результаты исследования существующего поведения.

## Цель и границы

Одна декларация общего компонента задаёт смысловое значение, представления XML и YAML, ограничения, зависимости, присутствие и восстановление. Из неё при сборке Rust получаются XML → YAML, YAML → XML и валидация. Произвольные функции, пути Rust-функций, отдельные валидаторы и скрытые обработчики конкретного common запрещены в целевом интерфейсе.

Сохраняются действующие пользовательские форматы и договор регистрации аномалий. Структурные и предметные ограничения описываются вместе с типом; JSON Schema представляет только выражаемую в ней часть, проектная проверка использует объявленные факты. Новые применения `!xml` эта спецификация не разрешает.

Исходная ревизия: `2af2f299ed8241eac78d4db46b4a8421efe2f8f7`, свежий `origin/develop` после fetch 2026-09-10. Предыдущая Rust-ветка используется как контекст, но не как свидетельство полноты декларативного механизма. Прежний подход с именованными предметными функциями common требует пересмотра в этой спецификации; `.agents/architecture.md` не изменяется.

## Как фиксируется исследование

1. Полный список верхних common-каталогов, вложенных частей и файлов исключает случайные пропуски.
2. Каждый компонент получает карточку: существующее поведение, источники, зависимости, необходимые конструкции декларации, значимые проверки и открытые ограничения.
3. Общие конструкции выводятся из карточек, а не из нескольких простых примеров.
4. Наблюдаемое поведение, предложение интерфейса и неподтверждённая полнота явно различаются.
5. Перед реализацией требуется развернуть декларации сложных представителей и подтвердить, что в них не осталось скрытого `convertX`/`validateX`.

## Реестр исследования

Первый обзор всех 90 верхних common-каталогов завершён. Материалы последовательно дополняются в [реестре исследования](2026-09-10-common-declarative/README.md). Машинный перечень содержит файлы и их хеши; наличие файла в перечне означает учёт источника, а не доказательство корректности его будущего переноса.

## Неизменяемые условия

- Полный переход на Rust; TypeScript используется как источник текущего поведения и сравнительных проверок.
- Обычные common не зависят от forms/appliedObjects. Владелец передаёт только объявленные типизированные входы; вся конфигурация и произвольный IO недоступны правилу.
- Отсутствие, пустое значение, nil, default и неготовый факт различаются.
- Повторы и исходный порядок коллекций сохраняются; словарь не уничтожает повторные вхождения.
- Смысловая классификация предшествует проверке обратимости. Контрольный экспорт использует окончательный кандидат YAML и разрешённые факты, без скрытого импортированного значения.
- Невыразимый договор остаётся явным пробелом языка. Недостающий обработчик нельзя маскировать raw, пропуском проверки или специальной функцией common.
- Цели 10× по времени и памяти сохраняются как проверяемые цели. Ограниченный скалярный замер не доказывает их для полного проекта.
- Проверки используют существующие XML-фикстуры. Эталонные результаты не генерируются из той же декларации, которую проверяют.
