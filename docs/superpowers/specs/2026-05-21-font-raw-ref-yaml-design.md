# Дизайн: сохранять raw ref шрифта в YAML

## Контекст

В полном round-trip `XML -> YAML -> XML` для двух общих форм найдено одно и то
же расхождение:

```xml
<Font ref="0" height="10" kind="StyleItem"/>
```

После YAML-цикла атрибут `ref="0"` теряется:

```xml
<Font height="10" kind="StyleItem"/>
```

Текущий YAML выглядит так:

```yaml
РасширеннаяПодсказка:
  Шрифт:
    ВидXML: StyleItem
    Размер: 10
```

Пользовательское решение: не писать в YAML поле `ВидXML: StyleItem`. Название
поля и значение должны быть русскими.

## Причина

`packages/core/metadata/commonObjects/font/fromXML.ts` сохраняет XML-атрибут
`ref="0"` в модель как `ref: "0"`, хотя тип сейчас описывает только известные
перечисления и ссылки вида `style:*` / `sys:*`.

При экспорте в YAML `packages/core/metadata/commonObjects/font/toYAML.ts`
пытается перевести `ref` через известные соответствия. Для значения `"0"`
соответствия нет, поэтому `ref` пропадает. Дополнительно `kind="StyleItem"`
попадает в YAML как техническое поле `ВидXML`.

## Решение

Для полного описания XML-шрифта в YAML использовать русские поля:

```yaml
Шрифт:
  Вид: ЭлементСтиля
  Значение: "0"
  Размер: 10
```

Семантика:

- `Вид` в такой форме описывает XML `kind` через существующее русское
  перечисление `FontTypeToYAML` / `FontTypeFromYAML`;
- `Значение` хранит исходный сырой `ref`, если он есть и не распознан как
  стандартный style/window/sys-шрифт;
- `Размер` продолжает соответствовать XML `height`.

Правила преобразования:

- `toYAML`: если `font.ref` известен как стандартный шрифт, оставить текущий
  человекочитаемый вывод через `Вид`;
- `toYAML`: если `font.ref` есть, но не распознан, писать объект с русским
  `Вид: <FontTypeToYAML[font.kind]>` и `Значение: <font.ref>`;
- `toYAML`: не выводить новое поле `ВидXML` для таких случаев;
- `fromYAML`: читать новую форму `Вид: ЭлементСтиля` + `Значение: "0"` как
  `kind: "StyleItem"` и `ref: "0"`;
- `fromYAML`: оставить чтение старого поля `ВидXML` для совместимости с уже
  созданным YAML;
- `toXML`: продолжать писать `ref` из модели без дополнительной нормализации.

## Совместимость

Поле `Вид` уже используется для известных ссылок на шрифты, например
`ОбычныйШрифтТекста` или `ШрифтДиалоговИМеню`. Это поведение не меняется.

Новая трактовка включается только для словаря, где вместе с `Вид` указано поле
`Значение`. В этом случае `Вид` считается видом XML-шрифта, а не именем
стандартного шрифта.

Старый YAML с `ВидXML: StyleItem` должен продолжать импортироваться, но новый
экспорт должен писать русскую форму.

## Границы

- Не менять XML-фикстуры.
- Не пытаться разрешать `ref="0"` в имя объекта или стиль конфигурации.
- Не переименовывать существующие русские значения известных шрифтов.
- Не убирать чтение `ВидXML` из `fromYAML` в этой задаче.

## Проверка

- Добавить точечный тест `toYAML`: модель с `ref: "0"`, `kind: "StyleItem"` и
  `height: 10` экспортируется как `Вид: ЭлементСтиля`, `Значение: "0"`,
  `Размер: 10`.
- Добавить точечный тест `fromYAML`: новая русская форма восстанавливает
  `ref: "0"` и `kind: "StyleItem"`.
- Проверить, что известные шрифты по-прежнему экспортируются в старом компактном
  виде через `Вид`.
- После исправления проверить выбранный diff через `round-trip-yaml` для
  четвертого и пятого расхождений.
