# Прямая запись двоичных файлов состояния

## Контекст

MCP не поддерживает одновременную работу нескольких процессов с одним проектом. Текущая общая публикация через временный файл дополнительно выполняет `fsync` файла, атомарный `rename` и лучший возможный `fsync` каталога. На текущем этапе гарантии сохранности при аварии ОС или отключении питания не входят в договор, а усложнение и задержка синхронной публикации нежелательны.

## Решение

- Удалить общий помощник `publishFileAtomically` и его тесты.
- Переименовать `writeConfigurationIndexAtomically` в `writeConfigurationIndex` и записывать закодированный индекс непосредственно в `configuration-index.bin` через `writeFile`.
- Записывать `project-state.bin` непосредственно через существующую последовательность `open`, `truncate` и `writev`.
- Не выполнять проверочное чтение, `fsync` файла, `rename` и `fsync` каталога.

## Договор ошибок

Ошибка записи возвращается вызывающей операции. Прерванная запись может оставить неполный целевой файл. Повреждённый `project-state.bin` обнаруживается по формату и контрольной сумме, удаляется и перестраивается холодным проходом. Для `configuration-index.bin` автоматическое восстановление не добавляется; этот риск принят как ограничение текущего этапа.

## Проверки

- Существующий тест записи и чтения configuration index сохраняется под новым именем функции.
- Тесты временного файла, коллизии, `rename` и синхронизации каталога удаляются вместе с отменённым договором.
- Тест сохранения и загрузки `project-state.bin`, а также тесты отбраковки повреждённого кэша продолжают защищать прямую запись и восстановление.
