# Запрет явного синонима, совпадающего с именем

## Контекст

В правилах локализованных текстовых полей уже есть флаг `excludeIfEqualNameYAML`. Сейчас он используется при YAML-экспорте: если значение поля можно однозначно получить из имени элемента, поле не записывается в YAML. Например имя `КакоеТоПоле` соответствует значению `Какое то поле`.

Нужно сделать этот флаг полноценным договором: значение, которое должно быть неявным, не должно явно попадать в YAML ни после импорта из XML, ни при ручном редактировании YAML.

## Границы

- Запрет работает для любого локализованного текстового свойства с `excludeIfEqualNameYAML: true`: как для `I8nText`, так и для `FormattedI8nText`.
- YAML-ключ не важен: это может быть `Синоним`, `Заголовок` или другое имя из `rules.ts`.
- Сравнение использует существующий алгоритм `canConvertToPascalCase`, чтобы `КакоеТоПоле` совпадало с `Какое то поле`.
- Правило не распространяется на локализованные текстовые поля без `excludeIfEqualNameYAML`.
- XML-фикстуры не меняются.

## Поведение

При XML -> YAML импорте текущий путь через модель и `exportMetadataItemToYAML` должен продолжать скрывать поля с `excludeIfEqualNameYAML`, если значение совпадает с именем элемента.

При YAML validation явное совпадающее значение считается ошибкой. Проверка берёт имя текущего элемента из контекста файла или коллекции, обходит правила объекта/элемента, находит локализованные текстовые поля с `excludeIfEqualNameYAML: true`, читает их фактический YAML-ключ и сравнивает значение с именем.

Для синонима самого объекта имя доступно из metadata-пути: файл `Справочник/Товары/Свойства.yaml` проверяется с именем объекта `Товары`. Это относится к обычным прикладным объектам, дочерним объектам и вложенным properties-файлам, где имя владельца выделяется классификацией project path.

Пустой `Свойства.yaml` у metadata-объекта считается валидным и эквивалентным пустому YAML-объекту `{}`. Например файл `Справочник/Договоры/Свойства.yaml` нулевой длины означает, что все значения объекта либо неявные, либо восстанавливаются из имени и reference XML. Имя объекта для таких файлов всё равно берётся из metadata-пути.

Для `Конфигурация.yaml` путь даёт только служебного владельца `Конфигурация`, поэтому при проверке синонима конфигурации нужно использовать фактическое имя из YAML/модели, то есть поле `Имя`, если оно присутствует. Если фактическое имя недоступно из-за синтаксической или структурной ошибки, проверка равного синонима для конфигурации не должна добавлять вторичную ошибку.

Правило пустого файла не распространяется на `Конфигурация.yaml`: поле `Имя` для конфигурации остаётся обязательным в `rules.ts`, поэтому пустой `Конфигурация.yaml` должен оставаться ошибкой validation.

Для многоязычного значения проверяется только язык по умолчанию. Остальные языки не запрещаются только из-за совпадения с именем, чтобы поведение соответствовало текущему `excludeNameFromI8nText`.

Пример для имени `КакоеТоПоле`:

```yaml
Синоним:
  ru: Какое то поле
  en: Some field
```

Такой YAML считается ошибкой из-за `ru`. Правильная запись хранит только отличающиеся языки:

```yaml
Синоним:
  en: Some field
```

Для `FormattedI8nText` применяется та же логика внутри поля `Текст`; признак `Форматированный` не влияет на сравнение:

```yaml
Заголовок:
  Форматированный: Истина
  Текст:
    ru: Какое то поле
    en: Some field
```

Здесь ошибка относится к `Заголовок.Текст.ru`.

## YAML Schema

Schema для конкретного файла должна показывать запрет, когда имя элемента известно из пути или контекста построения схемы. Для такого случая schema исключает значение, равное `splitPascalCase(name)`, у поля с `excludeIfEqualNameYAML: true`. Для `FormattedI8nText` запрет применяется к локализованным значениям внутри форматированного YAML-объекта.

Общая schema по имени типа остаётся общей и не содержит конкретного запрета, потому что при её построении нет имени элемента.

## Ошибки

Диагностика validation:

- `source: "structure"`;
- `severity: "error"`;
- путь указывает на фактический YAML-ключ;
- сообщение объясняет, что поле не нужно указывать, если его значение совпадает с именем элемента.

## Тесты

Нужны точечные тесты:

- `toYAML` продолжает скрывать совпадающее значение для `I8nText` и `FormattedI8nText` с `excludeIfEqualNameYAML`;
- `validateProject` возвращает ошибку для `Синоним: Какое то поле`, когда имя элемента `КакоеТоПоле`;
- `validateProject` проверяет синоним самого объекта по имени из пути, например `Справочник/Товары/Свойства.yaml` использует имя `Товары`;
- для `Конфигурация.yaml` проверка использует поле `Имя`, а при недоступном имени не добавляет вторичную ошибку равного синонима;
- пустой `Свойства.yaml` обычного metadata-объекта валиден и трактуется как `{}`;
- пустой `Конфигурация.yaml` невалиден, потому что `Имя` остаётся обязательным;
- многоязычный YAML с `ru: Какое то поле` и `en: Some field` запрещается только из-за языка по умолчанию;
- аналогичная проверка работает для поля с другим YAML-ключом, например `Заголовок`;
- поле без `excludeIfEqualNameYAML` не получает новый запрет;
- schema конкретного файла отклоняет совпадающее значение, а общая schema по типу остаётся без имени-зависимого ограничения.

## Критерий готовности

Флаг `excludeIfEqualNameYAML` единообразно управляет экспортом, validation и подсказкой schema. Явный YAML не может хранить значение, которое проект уже умеет восстановить из имени элемента.
