# Совместимость MCP с legacy-клиентами

## Цель

Вернуть совместимость `@nkdk/mcp` со всеми legacy-версиями протокола, поддержанными MCP SDK v2, не изменяя modern-договор `2026-07-28` и не создавая отдельные серверы или endpoint.

## Границы

- stdio принимает legacy-handshake `initialize` и modern-handshake `server/discover`;
- локальный HTTP endpoint `/mcp` принимает legacy- и modern-запросы;
- поддерживается весь legacy-набор версий MCP SDK v2, включая используемую Codex версию `2025-06-18`;
- единая фабрика `createNkdkMcpServer` и единый набор tools, resources и prompts сохраняются;
- новые зависимости, параметры CLI и отдельный legacy endpoint не добавляются.

## Архитектура

Встроенная dual-era маршрутизация MCP SDK v2 выбирает семейство протокола по первому handshake. Для stdio `serveStdio` получает `legacy: "serve"`: соединение закрепляется за одним экземпляром сервера и продолжает работу в выбранной era. Для HTTP `createMcpHandler` получает `legacy: "stateless"`: modern-запросы обслуживаются существующим modern-путём, а legacy-запросы — встроенным stateless fallback SDK на том же `/mcp`.

Собственный слой преобразования сообщений не вводится. TypeBox-договоры, регистрация возможностей, cache hints modern-протокола и защита локального HTTP по Host, Origin и Content-Type остаются без изменений.

## Watch-режим

`createMcpWatchHost` должен считать успешным открытием соединения как `server/discover`, так и `initialize`. После обновления worker host повторяет сохранённый запрос открытия с внутренним идентификатором, ждёт успешный ответ и только затем передаёт накопленные запросы новому worker.

Era соединения не меняется при перезагрузке. Ошибка или некорректный ответ на повторный handshake завершает watch-host через существующий `onFatal`.

## Ошибки и совместимость

Выбор и проверку версии выполняет MCP SDK v2. Поддержанная legacy-версия получает обычный `InitializeResult`; modern-клиент получает существующий `DiscoverResult`. Неподдержанная версия получает стандартную протокольную ошибку SDK.

Наблюдаемые ответы tools, resources и prompts сохраняют форму выбранной era. Бизнес-обработчики не ветвятся по версии протокола.

## Проверки

- заменить проверку отказа от legacy stdio на интеграционную проверку handshake `2025-06-18` и доступности зарегистрированного tool;
- сохранить интеграционную проверку modern stdio `2026-07-28`;
- добавить HTTP-проверку legacy `initialize` и последующего stateless-запроса, сохранив modern HTTP-проверки;
- расширить unit-тесты watch-host: успешный `initialize` сохраняется и повторяется после reload, очередь освобождается только после ответа нового worker;
- расширить packed smoke проверкой legacy stdio и HTTP наряду с modern-проверками;
- обновить README: сервер поддерживает legacy-линейку SDK v2 и modern `2026-07-28`.

Полная проверка перед завершением выполняется командами проекта, включая `pnpm test`, `pnpm duplicates -- --base <commit>`, `pnpm test:architecture:rules` и `pnpm test:architecture`. На исходной ревизии worktree функциональные тесты `@nkdk/platform` прошли (`244/244`), но существующий контроль длительности setup превысил лимит; это зафиксированная базовая проблема, не относящаяся к MCP.

## Критерии готовности

1. Codex-клиент с MCP `2025-06-18` подключается к `nkdk` через stdio и видит инструменты.
2. Legacy-клиент подключается к локальному HTTP `/mcp` без отдельной конфигурации.
3. Modern-клиент `2026-07-28` продолжает проходить существующие stdio и HTTP проверки.
4. Watch-mode восстанавливает выбранный legacy или modern handshake после reload.
5. Документация и packed smoke отражают dual-era режим.
