# Дизайн: ссылочные типы TypeDescription только как ребра

Тип: дизайн-документ.

## Контекст

Граф уже создаёт `TYPE`-ребра для ссылочных значений внутри `TypeDescription.type`.
Например, `Перечисление.СтатусыОрганизацийПодразделений` в YAML модели
становится внутренним типом `EnumRef.СтатусыОрганизацийПодразделений`, а
`extractTypeDescriptionGraph` создаёт ребро на узел
`Enum.СтатусыОрганизацийПодразделений`.

Сейчас тот же `TypeDescription` затем сплющивается в свойства узла через
`flattenItem`, поэтому у реквизита может появиться свойство:

```text
p_type_type: EnumRef.СтатусыОрганизацийПодразделений
```

Это дублирует графовую связь и делает ссылочный тип свойством, хотя для
ссылочных значений источником истины в графе должно быть ребро.

## Решение

`TypeDescription` остаётся смешанным случаем, но правило становится точнее:

- ссылочные элементы `type`, для которых создаётся графовое ребро, не попадают в
  `p_*` свойства узла;
- простые элементы `type`, которые не создают ребро, остаются в `p_type_type`;
- qualifiers и остальные простые поля `TypeDescription` сохраняются как сейчас.

Для примера:

```yaml
Тип:
  - Строка
  - Перечисление.СтатусыОрганизацийПодразделений
```

В графе должно получиться:

```text
(:MetadataAttribute {p_type_type: ["string"]})
  -[:TYPE {yaml: "Тип"}]->
(:Enum {id: "Enum.СтатусыОрганизацийПодразделений"})
```

Если `Тип: DynamicList`, ребро не создаётся и `p_type_type: ["DynamicList"]`
остаётся, как сейчас.

## Архитектура

В графовом слое нужна возможность не только пропускать весь ключ модели через
`flattenSkipKeys`, но и точечно преобразовывать значение перед `flattenItem`.
Эта возможность применяется к `TypeDescription`: перед выгрузкой свойств из
`type` удаляются только те элементы, которые распознаны той же логикой, что
создаёт `TYPE`-ребра.

Логика распознавания ссылочного типа должна быть общей или явно согласованной с
`extractTypeDescriptionGraph`, чтобы фильтрация свойств и создание ребер не
разъехались. Если тип игнорируется экстрактором (`string`, `DynamicList`,
`ReportObject.X`, неизвестный тип), он не должен удаляться из свойств только
из-за наличия точки в строке.

## Границы

Этот дизайн не меняет восстановление `граф -> модель`.

Этот дизайн не выносит весь `TypeDescription` в отдельные узлы и не скрывает
полностью `type`, если внутри есть хотя бы одна ссылка. Смешанные типы должны
сохранять примитивную часть в свойствах, потому что иначе граф потеряет
информацию, которая не выражена ребрами.

Этот дизайн не меняет YAML/XML round-trip и не требует изменений XML-фикстур.

## Проверка

Нужны тесты на контракт:

1. Реквизит с `Тип: Перечисление.X` создаёт `TYPE`-ребро на `Enum.X` и не
   содержит `p_type_type: EnumRef.X`.
2. Смешанный тип вроде `["string", "CatalogRef.Контрагенты"]` сохраняет
   `p_type_type: ["string"]` и создаёт `TYPE`-ребро на `Catalog.Контрагенты`.
3. Нессылочный тип `DynamicList` остаётся в `p_type_type` и не создаёт
   `TYPE`-ребро.
4. Qualifiers `TypeDescription` сохраняются в `p_type_*`, если они были в
   модели.
