# Классифицированные теги XML-аномалий

## Цель

Заменить общий YAML-тег `!xml` закрытым набором тегов, каждый из которых
объясняет причину сохранения точной формы XML. По YAML должно быть видно, чем
исходный XML отличается от канонического представления NKDK: присутствием или
отсутствием узла, именем, типом, значением либо ссылкой.

Миграция несовместимая и атомарная. Старый `!xml` после перехода не
поддерживается ни при чтении, ни при записи. Автоматическая совместимость,
предупреждения об устаревании и двойная запись тегов не требуются.

## Границы

В работу входят:

- локальные скалярные YAML-теги для всех уже зарегистрированных XML-аномалий;
- строгая проверка допустимого тега, payload и места применения;
- перенос всех существующих emitters, consumers, JSON Schema, проверок,
  снимков и тестовых ожиданий со старого `!xml`;
- договор отсутствующей и нестандартно именованной расширенной подсказки Popup;
- обновление реестра XML-аномалий после реализации.

В работу не входят:

- универсальное сохранение произвольных XML-фрагментов;
- использование тегов вместо неисследованного rules.ts или resolver;
- сохранение reference XML помимо UUID и уже согласованного порядка полей;
- выбор YAML-свойства и структуры для отсутствующих и лишних объявлений
  пространств имён;
- автоматическое исправление XML-аномалий.

## Словарь тегов

| Тег | Смысл | Payload |
|---|---|---|
| `!xml/present` | XML-узел явно присутствует, хотя канонический экспорт его опускает либо вычисляет иначе | запрещён |
| `!xml/absent` | XML-узел отсутствует, хотя канонический экспорт его создаёт | запрещён |
| `!xml/name` | точное нестандартное XML-имя | обязателен; пустое имя записывается как `""` |
| `!xml/type` | нестандартное XML-представление смыслового типа | обязателен |
| `!xml/value` | пустое, несовместимое или лексически нестандартное XML-значение | обязателен |
| `!xml/reference` | битая либо неразрешимая metadata- или локальная ссылка | обязателен и проверяется грамматикой конкретного переносчика |

Общего резервного тега нет. Если наблюдаемая форма XML не выражается этим
словарём, сначала исследуется новый класс аномалии и отдельно согласуется его
договор.

## Регистрация и проверка

Каждое место применения объявляет в собранных metadata rules:

- допустимую категорию тега;
- допустимость или обязательность payload;
- грамматику payload;
- действие XML → YAML и YAML → XML;
- внутреннюю validation-схему.

Тег, известный парсеру, но не зарегистрированный для текущего свойства,
является ошибкой. Неверная категория также является ошибкой: например,
`!xml/value` не заменяет `!xml/reference`, даже если их payload совпадает как
строка. Незнакомый локальный тег, включая старый `!xml`, является синтаксической
ошибкой YAML.

В пользовательской JSON Schema теги не предлагаются как обычные предметные
значения. Во внутреннем validation graph разрешается только точный маркер или
шаблон, зарегистрированный для свойства. Межфайловая проверка пропускает
ссылку только при наличии `!xml/reference` и успешном совпадении переносчика с
контекстным PropertyRule.

Диагностика называет категорию и причину, например:

- `РасширеннаяПодсказка: !xml/name допустим только для нестандартного XML-имени`;
- `ПутьКДанным: ожидался !xml/reference для битой локальной ссылки`;
- `!xml/present не допускает значение после тега`.

Старый `!xml` не распознаётся схемой YAML и получает обычную ошибку неизвестного
тега без специальной ветки совместимости.

## Миграция существующих случаев

| Существующий случай | Новый тег |
|---|---|
| Явно пустые `Attributes`, `AdditionalFields`, `Title`, `ExtDimensionTypes`, `panelDef`, корневой `ClientApplicationInterface` | `!xml/present` |
| Явный вычисляемый `HeaderHorizontalAlign=Auto` или `RowFilter` | `!xml/present` |
| Материализуемая коллекция стандартных реквизитов | `!xml/present` |
| Отсутствующие `Settings` у `ValueListType` и вычисляемые поля `CharacteristicsDescription` | `!xml/absent` |
| Нестандартное имя одиночного встроенного элемента формы | `!xml/name <имя>` |
| Пустые значения `FillValue`, `Undefined`, `Nil`, `String`, `TypeDescription`, `Null` | `!xml/value <маркер>` |
| Неканонический префикс типа в `TypeDescription` | `!xml/type <префикс>:<предметное имя типа>`, например `!xml/type d7p1:Диаграмма` |
| Строка СКД с `xsi:type="xs:string"` вместо `LocalStringType` | `!xml/type String <текст>` |
| Ошибочный булевый FillValue и иной несовместимый смысловой скаляр | `!xml/value <значение>` |
| `MinMaxValue` с неканоническим `xsi:type` либо без требуемого `xsi:type` | `!xml/type <исходный xsi:type или -> <исходный текст>` |
| `MinMaxValue` с каноническим `xsi:type`, но нестандартным исходным текстом | `!xml/value <исходный текст>` |
| Успешно разрешённый `DataPath`, конечный тип которого несовместим с видом элемента формы | `!xml/value <исходный внутренний путь>` |
| Битые `MDObjectRef`, `DesignTimeRef`, metadata-ссылки и локальные ссылки формы | `!xml/reference <исходная ссылка>` |
| Битый UUID внутри `SubsystemsOrder` | `!xml/reference <UUID>`, поскольку аномалия состоит в ссылке, а не в позиции |

Для `FillValue` категория определяется причиной, а не именем XML-элемента:

```yaml
# Особое пустое значение
ЗначениеЗаполнения: !xml/value Nil
ЗначениеЗаполнения: !xml/value DesignTimeRef
ЗначениеЗаполнения: !xml/value String
ЗначениеЗаполнения: !xml/value TypeDescription
ЗначениеЗаполнения: !xml/value Null

# Ошибочное смысловое значение
ЗначениеЗаполнения: !xml/value Ложь

# Битая ссылка с исходным текстом
ЗначениеЗаполнения: !xml/reference <UUID>.<UUID>
```

`!xml/type` сохраняет нестандартный XML-префикс, но имя типа остаётся
предметным, как в обычном YAML. Например,
`<v8:Type>d7p1:Chart</v8:Type>` представляется как:

```yaml
Тип: !xml/type d7p1:Диаграмма
```

Rules.ts преобразует `Диаграмма` обратно в XML-имя `Chart`, а тег сохраняет
исходный префикс `d7p1`.

Для `MinMaxValue` категория сначала сравнивает XML-тип с `typedXML` конкретного
rules.ts. Другой или отсутствующий `xsi:type` получает `!xml/type`; при
каноническом типе отличается только исходный текст, поэтому используется
`!xml/value`:

```yaml
МинимальноеЗначение: !xml/type xs:dateTime bad
МинимальноеЗначение: !xml/value 001.00
```

Если одновременно отличаются тип и текст, выбирается `!xml/type`, а payload
сохраняет оба исходных значения.

Ссылка в значении заполнения получает категорию по характеру ошибки:

```yaml
# Ссылка не разрешается либо имеет битое внутреннее представление
ЗначениеЗаполнения: !xml/reference Справочник.РолиИсполнителей.ПустаяСсылка
ЗначениеЗаполнения: !xml/reference <UUID>.<UUID>

# Ссылка разрешается, но недопустима для типа или политики реквизита
ЗначениеЗаполнения: !xml/value Справочник.РолиИсполнителей.ПустаяСсылка
```

Для `DataPath` категория также определяется причиной:

```yaml
# Путь разрешён, но его конечный тип несовместим с видом элемента формы
ПутьКДанным: !xml/value Объект.Description

# Локальная ссылка пути бита или не разрешается
ПутьКДанным: !xml/reference 1/0:<UUID>
```

`!xml/value` хранит исходную внутреннюю строку пути и не отключает resolver.
Тег допустим только после успешного разрешения несовместимого пути; совместимый
или неизвестный путь с таким тегом отклоняется.

## Popup.ExtendedTooltip

Для Popup каноническая пустая расширенная подсказка не выводится в YAML. При
отсутствии свойства exporter создаёт:

```xml
<ExtendedTooltip name="<ИмяPopup>РасширеннаяПодсказка" id="<индексный id>"/>
```

Остальные поддержанные состояния:

```yaml
# ExtendedTooltip отсутствует в исходном XML
РасширеннаяПодсказка: !xml/absent

# Пустой ExtendedTooltip имеет нестандартное точное имя
РасширеннаяПодсказка: !xml/name ФункцииExtendedTooltip
```

У прямого `ExtendedTooltip` Popup в исследованном корпусе нет других XML-полей,
поэтому scalar сохраняет всю отличающуюся информацию. Правила проверки:

- отсутствие YAML-свойства означает каноническую вычисляемую подсказку;
- `!xml/absent` разрешён только без payload;
- `!xml/name` требует точное непустое нестандартное имя;
- имя, совпадающее с вычисляемым каноническим, избыточно и отклоняется;
- обычный нетегированный scalar и другие XML-теги отклоняются;
- `id` восстанавливается существующим индексом и не входит в YAML.

## Пространства имён

Расхождение старых форм без `xmlns:dcssch` остаётся отложенным. До отдельного
исследования не определены:

- YAML-свойство, к которому относится тег;
- scalar, mapping или sequence представление;
- состав payload;
- правила восстановления места объявления namespace;
- проверка лишних, отсутствующих и изменённых деклараций.

Теги namespace в этой спецификации не вводятся.

## Обработка ошибок

- Парсер отклоняет старый `!xml` и неизвестные категории.
- Пустой payload отклоняется у всех тегов, кроме `present` и `absent`.
- Любой payload отклоняется у `present` и `absent`.
- Переносчики ссылок не перехватывают payload другой грамматики и продолжают
  поиск следующего переносчика.
- Два переносчика, принявшие один `!xml/reference`, сохраняют существующую
  диагностику неоднозначности.
- Ни один тег не отключает смысловую проверку соседних обычных свойств.

## Проверки

Минимальные уровни защиты:

1. YAML runtime: разбор и сериализация каждого тега, пустой и непустой payload,
   удаление старого `!xml`, сохранение sidecar при копировании структур.
2. Реестр свойств: разрешённая категория, чужая категория, payload и схема
   внутреннего validation graph.
3. Предметные правила: по одному представителю каждого класса миграции и
   содержательные отрицательные границы.
4. Popup: каноническое отсутствие поля, `!xml/absent`, `!xml/name`, избыточное
   каноническое имя и чужой тег.
5. Полный импорт и экспорт репрезентативной конфигурации без reference XML.
6. Round-trip Tester и Storekeeper после адресных reset соответствующих
   конфигураций; весь каталог XML не копируется.
7. `pnpm type-check`, `pnpm test`, архитектурные проверки и duplicates согласно
   проектным инструкциям. LMDB, e2e и round-trip запускаются вне песочницы.

Существующие XML-фикстуры не изменяются. Ожидания YAML и программно созданные
входные YAML переводятся на новые теги.

## Документация

После реализации требуется синхронно обновить:

- `.agents/architecture.md`: заменить общий принцип `!xml` ссылкой на
  классифицированное семейство тегов; обновление явно согласовано разработчиком;
- `.agents/xml-anomalies.md`: заменить колонку общего `!xml` точными тегами и
  добавить Popup; namespace обновляется только после отдельного согласования;
- `.agents/restrictions.md`: удалить общий договор пустого `!xml` и описать
  закрытый словарь;
- ранее созданные актуальные спеки и планы, если они используются как вход для
  дальнейшей реализации.

Исторические спеки не переписываются массово: они фиксируют принятые на тот
момент решения. Исполняемый план текущей ветки должен использовать только
новые теги.
