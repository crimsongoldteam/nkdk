# Отсутствующий стандартный реквизит в непустой коллекции

## Контекст

Полный round-trip Storekeeper добавляет `ExchangeDate` в
`ExchangePlans/ОбменСМобильнымиПриложениями.xml`. Исходный XML содержит семь
других стандартных реквизитов, но не содержит `ExchangeDate`. В YAML остаются
только смысловые изменения `Код` и `Наименование`, после чего действующий
`completeItemNames` дополняет коллекцию всеми каноническими именами.

Официальная документация 1С связывает смысл `ExchangeDate` с планом обмена,
выбранным для автономного мобильного клиента: реквизит хранит дату последнего
непустого обмена и используется при очистке неактивных узлов. Документация не
задаёт однозначное правило присутствия элемента в XML. В исследованных
конфигурациях встречаются оба состояния независимо от `DistributedInfoBase`.

## YAML-договор

Отсутствующий канонический элемент внутри присутствующей коллекции отмечается
на месте этого элемента:

```yaml
СтандартныеРеквизиты:
  ДатаОбмена: !xml/absent
  Наименование:
    ПроверкаЗаполнения: ВыдаватьОшибку
  Код:
    ПроверкаЗаполнения: ВыдаватьОшибку
```

Договор распространяется на любой отсутствующий канонический элемент свойства
точного типа `StandardAttributeDescriptions`. Он не разрешает
`!xml/absent` в произвольных коллекциях.

Маркер является транспортным описанием XML-формы. Стандартный реквизит остаётся
известен предметной модели, DataPath и индексам метаданных; маркер управляет
только наличием соответствующего `xr:StandardAttribute` при экспорте.

## Импорт XML → YAML

- Если `StandardAttributes` отсутствует целиком, YAML-свойство отсутствует по
  действующему договору.
- Если присутствует полная каноническая коллекция без смысловых отличий,
  сохраняется действующий маркер `СтандартныеРеквизиты: !xml/present`.
- Если присутствующая коллекция не содержит часть канонических элементов,
  импорт добавляет для каждого отсутствующего имени `!xml/absent`.
- Смысловые свойства присутствующих элементов и динамические неканонические
  элементы импортируются без изменений.

Таким образом, отображение может состоять только из маркеров отсутствия либо
сочетать их с обычными описаниями стандартных реквизитов.

## Экспорт YAML → XML

- Обычный `completeItemNames` продолжает определять канонический набор.
- Имена с `!xml/absent` исключаются из материализуемого набора.
- Остальные канонические элементы восстанавливаются по действующим правилам,
  включая элементы со значениями по умолчанию.
- Непустой payload маркера, неканоническое имя или применение маркера вне
  `StandardAttributeDescriptions` является ошибкой валидации.
- Reference XML и configuration index для определения присутствия элементов не
  используются.

## Границы

- Не вычислять XML-присутствие по `DistributedInfoBase`, содержимому автономной
  конфигурации или имени плана обмена.
- Не менять декларации стандартных членов и разрешение DataPath.
- Не добавлять поля в общие типы rules.ts и параметры построителей без
  отдельного согласования.
- Не изменять существующие XML-фикстуры.
- Пустой XML-контейнер без единого стандартного реквизита не входит в этот
  договор.

## Проверки будущей реализации

1. Импорт непустой коллекции с отсутствующим каноническим элементом создаёт
   вложенный `!xml/absent`.
2. Экспорт исключает отмеченный элемент и материализует остальные канонические
   элементы.
3. Отображение только из маркеров отсутствия восстанавливает оставшиеся
   дефолтные элементы.
4. Полная дефолтная коллекция продолжает использовать `!xml/present`.
5. Отсутствующий контейнер не создаёт YAML-свойство.
6. Неканоническое имя, payload и применение в другой коллекции отклоняются.
7. Стандартный член с маркером остаётся доступен DataPath и индексам.
