# Адреса вложенных значений по структуре YAML

Статус: согласован 2026-10-10; пользователь поручил продолжить. Это продолжение приёмки DynamicList,
а не новый преобразователь или отдельный обработчик его свойств.

## Цель

Автоматически передавать адрес вложенного значения через записи, коллекции
и сокращения. По этому адресу операция связывает служебное XML-состояние
с правильным значением. Декларации описывают структуру; имена объектов 1С
в общем компиляторе и оркестраторе не используются.

Ранее принятые XML ↔ YAML-преобразования и внешний QueryText сохраняются.
Восемь отложенных требований DynamicList не считаются исполненными по наличию
записи в отчёте или успешному неизменённому round-trip.

## Что установлено по исходникам

TypeScript включает yamlPath для всего поддерева выбранного свойства.
Ключ свойства добавляется к адресу родителя; обычный список добавляет позицию,
именованная коллекция — ключ строки. Вложенные свойства продолжают тот же режим.
Адрес применяется при импорте и экспорте к состоянию XML, а не только к проверке
ссылок. Источники договора:

- `packages/runtime/metadata/configurationIndex/logicalAddress.ts`;
- `packages/runtime/metadata/configurationIndex/collector/context.ts`;
- `packages/runtime/metadata/ruleRuntime/metadataCollection/fromXMLToYAML.ts`;
- `packages/runtime/metadata/configurationIndex/exportRuntime.ts`.

Rust уже содержит LogicalAddress и декларативное выражение logicalAddress.
Повторно реализовывать экранирование, числовые позиции или генерацию идентичности
не требуется. Требуется связать эти возможности с вложением значения.

## Автоматическое правило

Операция задаёт начальный адрес владельца один раз. Компилятор выводит переходы
из XML/YAML-представлений и передаёт адрес только потребителям служебного состояния.

| Конструкция | Переход |
|---|---|
| Поле mapping | Добавить фактическое YAML-имя поля |
| compose | Продолжить адрес записи; имя фрагмента не добавляется |
| projection | Продолжить адрес значения; техническое имя поля не добавляется |
| sequence | Добавить позицию элемента смыслового списка |
| record-mapping | Добавить ключ элемента, который используется в YAML |
| choice | Продолжить адрес выбранного значения; техническое имя варианта не добавляется |
| shorthand | Адресовать восстановленное смысловое значение по тому же договору, что полную форму |
| Отсутствующее поле/коллекция | Не создавать несуществующие элементы |

Имена экранируются существующим LogicalAddress ровно один раз. Числовой индекс
и строковый ключ различаются: `[0]` и `.0` — разные адреса. Соседние повторные
элементы списка имеют разные позиции. Повтор ключа именованной коллекции не даёт
права выбрать первую строку: неоднозначность сохраняется существующим механизмом
аномалий/состояний индекса.

Передача адреса не требует повторного разбора YAML или XML. Обычный конвертер
не обходит граф деклараций во время преобразования. Переходы подготавливаются
при сборке; общий код адресов используется повторно. Не добавлять адресную строку
к каждому смысловому объекту или второй полный контекст операции.

## Восемь реальных границ

Имена извлечены из опубликованной декларации common.dynamic-list, виды — из
подключённых деклараций. Этот перечень является приёмочным примером общего
правила, а не таблицей условий оркестратора.

| Исходное свойство | YAML-граница | Продолжение |
|---|---|---|
| fields | Поля | Позиции списка |
| calculatedFields | ВычисляемыеПоля | Позиции списка |
| parameters | Параметры | Ключи именованной коллекции |
| conditionalAppearance | УсловноеОформление | Поля записи и её вложенные коллекции |
| dataParameters | ПараметрыДанных | Ключи именованной коллекции |
| filter | Отбор | Поля записи и её вложенные коллекции |
| group | Группировка | Позиции смыслового списка; XML-next не создаёт дополнительного адреса |
| order | Порядок | Поля записи, включая Элементы и позиции этой коллекции |

Примеры при адресе владельца `ОбщаяФорма.Форма.Реквизиты.Список.ДинамическийСписок`:

- первое поле: `…ДинамическийСписок.Поля[0]`;
- следующий элемент с тем же значением: `…ДинамическийСписок.Поля[1]`;
- именованный параметр: `…ДинамическийСписок.Параметры.СтроковыйПараметр`;
- строковый ключ `А.Б[0]`: `…ДинамическийСписок.Параметры.А%2EБ%5B0%5D`;
- первый элемент порядка: `…ДинамическийСписок.Порядок.Элементы[0]`.

## Связь с восстановлением XML

Сначала проверить каждое потребление старого индекса: сведения, уже полностью
сохраняемые новым смысловым значением и автоматически выведенной XML-аномалией,
не дублировать во втором хранилище. При этом запись о yamlPath нельзя просто
вычеркнуть: нужен тест, доказывающий замену её наблюдаемого поведения.

Сведения, остающиеся в индексе, получают адрес из общего подготовленного плана
и одинаково ищутся при импорте и экспорте. Прежний снимок и новое значение
проверяются раздельно. Неполный источник состояния или неоднозначный адрес
не заменяются выдуманным идентификатором либо необоснованным !xml.

## Проверки и приёмка

1. Нейтральный пример записи с двумя коллекциями: именованной и обычной,
   дополнительным полем и переименованными ключами. Проверить адреса с точками,
   скобками, процентами, числовым строковым ключом и повторным значением списка.
2. Те же значения в полной и сокращённой YAML-форме получают одинаковые адреса.
   compose, projection и XML-next не вносят технические сегменты.
3. Восстановление служебного состояния из снимка проверяется отдельно от чтения
   декларации: соседние записи не обмениваются состоянием. Для нового элемента
   без прежнего снимка действует ранее принятый договор генерации идентичности.
4. Все восемь реальных границ DynamicList проверяются на неизменных e2e-данных,
   включая вложенный FormAttribute, внешний QueryText и XML-аномалии.
5. Проверить источник адреса после правки YAML. Для позиционного списка адрес
   следует текущей позиции; не обещать устойчивую идентичность при перестановке
   без отдельного смыслового идентификатора.
6. Замерить обычное преобразование до/после без фоновой сборки. Замедление
   требует пересмотра реализации; отсутствие регрессии нельзя вывести из тестов.
7. Публикация, Clippy, архитектура, дубли, полный pnpm test. XML-фикстуры
   не менять. Флажок всего DynamicList остаётся снятым до выполнения этих условий.

Тесты общего механизма размещаются на его узком уровне; реальные объекты
добавляют данные к существующей матрице, а не копируют проверки механизма.

## Граница изменения

Новые предметные режимы, отдельный интерпретатор деклараций, преобразование
через TypeScript и изменение .agents/architecture.md не входят в это решение.
Перед реализацией согласовать этот договор и составить подробный план.

## Уточнение записи адресов и снимков (2026-10-10)

Внутри `logicalAddress.parts` можно ссылаться на смысловое поле:

```yaml
parent:
  logicalAddress:
    parent: {input: parent}
    parts: [{yamlField: list}]
```

Если поле `list` записано в YAML как `Список.А[0]%`, компилятор подставляет
это имя до генерации Rust. При переименовании YAML-ключа отдельно исправлять
адрес не требуется. Для поля projection и выбранного варианта choice дополнительный
сегмент не создаётся; compose ищет поле в подключённых фрагментах. Отсутствующее
или неоднозначное поле отвергается при сборке. Внешний файл имеет отдельную
границу и не адресуется этим селектором. `yamlField` не является самостоятельным
выражением во время выполнения. Передача родителя, позиции и ключа строки пока
использует существующие декларативные связи; автоматическое назначение всем
входам роли адреса этим изменением не объявляется выполненным.

Обычный YAML намеренно может не содержать служебного поля, например идентичности
строки. Такой YAML нельзя использовать как единственный сохранённый источник
индекса: при повторном открытии значение уже потеряно. Компилятор обнаруживает
XML-поля без YAML-представления во вложенном графе при сборке. Скрытое поле,
которое однозначно вычисляется из обычных входов и значений, не требует
такого сохранения. Восстановление через индекс или генерацию идентичности
требует удержать исходное значение. Для этих договоров
внутренний снимок содержит подготовленный XML с заголовком `NKDK-FACT-XML/1`
и переводом строки. XML создаётся из прочитанного значения; исходный полный
документ не копируется. Повторное чтение снимка выполняется через общий
`contribute_snapshot_file`; материализация также принимает этот формат.
Обычные YAML-снимки сохраняют прежний договор. Это внутреннее сохранение
состояния, а не новое поле пользовательского YAML и не аномалия `!xml`.

В отдельных AOT-пакетах таблица имён индексов и переходник ошибок принадлежат
одному общему пакету. Публичные функции сохраняют явную зависимость фасада,
даже если его внутренний код их не вызывает. Копировать эти функции в каждый
пакет значений не требуется.

Именованная коллекция также может потерять повторы при записи внутреннего
YAML-снимка: два элемента с одинаковым ключом не означают один элемент.
Для таких представлений при подготовке снимка проверяется обратимость
подготовленного XML через полученный YAML. Если она доказана, сохраняется
прежний YAML-снимок; если строки потеряны, сохраняется подготовленный XML
в существующем внутреннем формате. Ошибка чтения или записи не считается
доказательством потери и передаётся вызывающему коду. Эта проверка относится
только к подготовке снимка, а не к обычному преобразованию каждого свойства.
Сравнение основного XML не объявляется проверкой всех внешних документов:
границы внешних файлов требуют своей проверки.
