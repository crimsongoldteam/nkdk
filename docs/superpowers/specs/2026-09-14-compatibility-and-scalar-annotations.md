# Совместимость и аномалии скаляров с собственным тегом

Дополнение к единой спецификации деклараций. Декларация по-прежнему описывает
нормальные значения; отдельный перечень аномалий для объекта не вводится.

## Ограничения режима совместимости

Переносчик получает доступные режимы из system.CompatibilityMode, а доступность
состояний — из извлечённого реестра PropertyState. Начальные свойства и дельты
применяются в исходном порядке с объединением изменяемых параметров.
Нераспознанный профиль блокирует перенос, а не отбрасывается.

Для значения перечисления источник определяет заимствование начиная с 8.3.8
и уведомление начиная с 8.3.15. Эти номера не зашиты в Rust. Переносчик выпускает
обычные выражения над входом compatibilityMode и значениями записи; те же
ограничения участвуют в импорте XML и проверке YAML. Поддержаны XML- и
YAML-обозначения версии. DontUse/НеИспользовать соответствуют значению по
умолчанию действующего исходного реестра; оно извлекается при генерации.

В реальных проверках вход берётся из Configuration.xml. Контекст и его
источники входят в проверяемые данные, включая хеши файлов. Граничные проверки
заменяют режим только в памяти; XML-фикстуры не изменяются.

## Одно значение — два разных тега

Если смысловое значение уже использует YAML-тег, нельзя дописывать перед ним
тег аномалии: YAML запрещает два тега на одном узле. Общая форма в таком случае:

```yaml
ОбъектРасширяемойКонфигурации: !xml/invalid
  $значение: !проверять
```

Это уведомление, недопустимое для выбранной версии. Оно полностью обратимо:
`$xml` не нужен. При обычном скаляре без собственного тега сохраняется краткая
форма `Свойство: !xml/invalid Значение`.

Обёртка содержит ровно один скаляр `$значение`; null и пустая строка различаются.
Смысловой тег передаётся обычному читателю значения, а отметка аномалии —
существующему механизму проверки аннотаций. Пустая обёртка, дополнительные поля
и нескалярное содержимое не принимаются. Обёртка не разрешает новые важные
аннотации: правила регистрации `!xml/important` остаются прежними.

Отметка действительна только при соответствующем нарушении. Например, после
смены режима с 8.3.14 на 8.3.15 прежний `!xml/invalid` над уведомлением становится
лишним и проверка сообщает `xml/anomaly-tag-unnecessary`.

## Выполнение и проверки

Чтение скалярной обёртки работает в существующем потоке событий и держит только
один скаляр. Повторный разбор целого YAML и специальные обработчики объектов
не добавляются. Дополнительное строковое хранилище аннотации создаётся только
для отмеченного значения. Генератор и ядро не знают о перечислениях, базовых
ссылках или конкретных версиях платформы.

Общий договор проверяется в матрице conversion-core/tests/yaml_nodes.rs.
Привязки и граничные режимы проверяются в матрице полного значения перечисления
через рабочую операцию приложения: обычный YAML, точная диагностика недопустимого
YAML, сохранение аномалии, независимый экспорт и отсутствие `$xml` там, где
смысловых данных достаточно. Это не подтверждение производительности 10×.
