# Help YAML Round-Trip Design

## Контекст

`round-trip-yaml` показывает массовую потерю файлов `Ext/Help.xml` и `Ext/Help/*.html`.
Проверка `acc` показала, что `Help.xml` содержит только стандартный конверт справки:
пространства имен, `version="2.20"` и список страниц `<Page>ru</Page>`.
Содержательные данные справки лежат в HTML-страницах и связанных файлах.

## Решение

`Help.xml` не хранится в YAML как отдельный исходный файл.
Он остается производным манифестом, который восстанавливается из содержимого YAML-каталога справки.

Для объектов, где справка есть в XML, но теряется при YAML round-trip, добавляются явные свойства
`help: { type: "Help", ... }` в `rules.ts` соответствующих metadataItem.
Это продолжает существующий подход `Help`-обработчика, но закрывает объекты, у которых правило отсутствует.

## YAML-Контракт

Справка объекта хранится в каталоге `Справка`.
Страницы сохраняются как `Справка/<язык>.html`.
Связанные файлы сохраняются как `Справка/_files/*`.

`Ext/Help.xml` восстанавливается на XML-стороне по списку HTML-страниц.
Порядок и набор `<Page>` выводятся из фактически сохраненных страниц.

## Тестирование

Sync-фикстуры должны явно содержать объект со справкой:

- `Ext/Help.xml`;
- минимум одну страницу `Ext/Help/ru.html`;
- при необходимости файл из `Ext/Help/_files`.

Тест `syncToXML` должен ожидать восстановление `Ext/Help.xml` и HTML-страниц.
Точечный тест `Help` должен оставаться проверкой поведения общего обработчика.

## Вне Границ

Этот пункт не меняет формат `Help.xml`, не сохраняет его как YAML-файл и не расширяет
`rules.externalFiles`.
Отказ от `rules.externalFiles` для других типов внешних файлов разбирается отдельными пунктами.
