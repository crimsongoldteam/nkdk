# Диагностика process.log текущего импорта

## Цель

Исключить сообщения прошлых запусков и прошлых импортов из диагностики текущего импорта через агент Конфигуратора, сохранив повторное использование живого соединения.

## Решение

Новый процесс агента запускается с `/Out <process.log>` без `-NoTruncate`. Платформа очищает файл при запуске, поэтому ошибка подключения относится только к текущему процессу.

Перед каждой командой выгрузки сессия запоминает размер `process.log` в байтах. Если команда завершается ошибкой, в журнал операции переносится только диапазон от сохранённой позиции до актуального конца файла. Сам `process.log` не обрезается и не удаляется во время работы агента: платформа может продолжать писать в него, а пользователь — читать его для диагностики.

Если файл отсутствовал в начале операции, начальная позиция равна нулю. Если к моменту чтения файл стал короче сохранённой позиции или был создан заново, читается всё его актуальное содержимое. Ошибка чтения журнала не заменяет исходную ошибку платформы.

## Границы модулей

- Построитель команды отвечает только за отсутствие `-NoTruncate`.
- Файловая граница сессии агента предоставляет получение размера и чтение с байтовой позиции.
- Сессия агента фиксирует позицию непосредственно перед командой импорта и передаёт её в обработчик ошибки.
- Журнал операции `.nkdk/tmp/import-from-infobase/<operation-id>/platform.log` остаётся отдельным для каждого вызова MCP и содержит только диагностический фрагмент текущей операции.
- Формирование краткой ошибки MCP не меняется: оно использует текущий ответ SSH-протокола, а не содержимое `process.log`.

## Проверка

- Команда запуска нового агента не содержит `-NoTruncate`.
- Ошибка запуска или авторизации переносит журнал текущего процесса целиком.
- Ошибка повторного импорта через живой агент не переносит сообщения предыдущего импорта.
- При уменьшении или замене файла обработчик безопасно читает актуальное содержимое с начала.
- Недоступный `process.log` не скрывает исходную ошибку платформы.
- Полный набор `pnpm test` и проверка новых дублей проходят.
