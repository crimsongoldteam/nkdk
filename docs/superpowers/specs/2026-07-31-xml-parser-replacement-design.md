# Замена XML-парсера на saxes

## Контекст

Рабочий `importContentFromXML` использует `fast-xml-parser` с
`preserveOrder: true`, после чего локальная функция `compress` второй раз
обходит промежуточное дерево и формирует представление XML, принятое в NKDK.

Изолированный однопроходный прототип на `saxes` уже воспроизводит этот договор.
На корпусе из 704 репозиторных фикстур, 5000 маленьких XML compact ERP и
`Rights.xml` результаты обоих парсеров полностью совпали. Медиана времени
снизилась с 2434 до 939 мс, а медиана peak RSS — с 804 до 449 МиБ.

## Решение

Заменить рабочую реализацию разбора XML на `saxes` сразу, без переключателя,
двойного разбора и запасного пути через `fast-xml-parser`.

Публичный договор не меняется:

- сохраняются именованный и default export `importContentFromXML`;
- сохраняется тип `ImportContentFromXMLOptions`;
- все существующие места вызова продолжают использовать прежний путь импорта;
- `saxes` остаётся рабочей зависимостью `@nkdk/core`.

`fast-xml-parser` не удаляется из зависимостей, потому что XML-экспорт продолжает
использовать его `XMLBuilder`. Удаляется только основанная на `XMLParser`
реализация импорта.

## Архитектура

`packages/core/xml/import/importer.ts` становится тонкой публичной оболочкой. Он
объявляет публичные параметры и передаёт XML внутренней функции из
`packages/core/xml/import/saxesParser.ts`.

`saxesParser.ts` создаётся переносом проверенного прототипа из
`xml/import/experimental/saxesImporter.ts`. Модуль отвечает за:

- настройку и запуск `SaxesParser`;
- стек открытых элементов;
- накопление текста и атрибутов;
- формирование повторяющихся элементов и ordered `ChildItems`;
- создание неперечисляемого `Symbol.for("metadata").childOrder`;
- обработку XML declaration, PI, BOM и XML-фрагментов;
- защиту объектного результата от опасных имён свойств.

Каталог `xml/import/experimental` удаляется. Из `importer.ts` удаляются
`XMLParser`, `compress`, `defaultOptions`, `propName`, `assignAttributes` и
связанные с ними переходные настройки.

## Поток данных

`importContentFromXML` передаёт исходную строку и параметры в `saxesParser`.
Парсер последовательно обрабатывает события XML и хранит только стек ещё не
закрытых элементов. При закрытии элемента его окончательное значение сразу
добавляется родителю. Промежуточное полное дерево и второй рекурсивный проход не
создаются.

XML с declaration разбирается как документ. XML без declaration разбирается в
режиме fragment, поскольку некоторые поддерживаемые файлы содержат несколько
соседних корневых элементов.

## Договор результата

Для корректных поддерживаемых XML сохраняется существующее представление:

- XML declaration записывается под ключом `?xml`;
- префиксы пространств имён сохраняются;
- атрибуты получают префикс `_`;
- entity декодируются, text и CDATA объединяются без обрезки пробелов;
- комментарии игнорируются;
- единственный текстовый узел сворачивается в строку;
- повторяющиеся одноимённые элементы превращаются в массив;
- `ChildItems` сохраняет ordered-массив одноимённых записей;
- пустой элемент становится `undefined` либо `{}` при атрибутах или
  `preserveEmptyElements: true`;
- `xsi:nil` удаляется по умолчанию и сохраняется при
  `preserveXsiNil: true`;
- обычные объекты получают неперечисляемый `childOrder`.

Опасные имена свойств, включая `__proto__` и `constructor`, отклоняются до
записи в объект.

## Ошибки

Некорректный XML завершается исходной ошибкой `saxes`. Текст ошибки и
терпимость `fast-xml-parser` к отдельным некорректным конструкциям не являются
частью сохраняемого договора. Это намеренное ужесточение проверки входа.

## Тестирование

Проверки прототипа переносятся и объединяются с
`packages/core/xml/import/importer.test.ts`. Они обращаются только к публичному
`importContentFromXML` и защищают наблюдаемый договор, а не внутреннее устройство
парсера.

До удаления старой реализации повторяется сравнение результатов на полном
корпусе из 5705 XML. После переключения выполняются:

1. целевые тесты `importer.test.ts`;
2. `pnpm type-check`;
3. полный `pnpm test`;
4. повторный замер времени и peak RSS с фиксацией медиан трёх прогонов.

Автоматического порога производительности нет. Итоговые медианы сравниваются с
результатами прототипа вручную и передаются пользователю для решения.

Mutation testing в этот цикл не входит по решению пользователя.

## Уборка экспериментальной инфраструктуры

После подтверждения замены удаляются:

- старая реализация `fast-xml-parser + compress`;
- каталог `xml/import/experimental`;
- двойной измеритель и его worker;
- helper корпуса, предназначенный только для сравнения двух реализаций;
- команда `measure:xml-parsers`.

Старая реализация не сохраняется ни как запасной путь, ни как тестовый эталон. Итоговые
числа сравнения остаются в этой спецификации.

## Критерии завершения

Замена завершена, если:

1. публичный API `importContentFromXML` не изменился;
2. старая реализация разбора и экспериментальная инфраструктура удалены;
3. целевые тесты проверяют все перечисленные классы XML-входов;
4. `pnpm type-check` и полный `pnpm test` проходят;
5. итоговые медианы времени и peak RSS зафиксированы и представлены пользователю;
6. рабочий код разбора XML использует только `saxes`, без переключателя и двойного разбора.
