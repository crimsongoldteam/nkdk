# Диапазоны строк для mutation testing

## Цель

Сделать диапазон изменённых строк обычной целью локального mutation testing,
чтобы задача проверяла только затронутый production-код и не запускала мутации
всего изменённого файла без необходимости.

## Границы

В этой итерации запускатель принимает цели Stryker вида
`packages/core/path/file.ts:120-170` и полный формат с колонками
`packages/core/path/file.ts:120:4-170:8`. Поддержка `--incremental`, кеша CI и
расписания полных прогонов в изменение не входит.

## Запускатель

`validateMutationFiles` отделяет диапазон от пути перед проверкой безопасности.
Базовый путь обязан удовлетворять существующим ограничениям: находиться в
`packages`, указывать на существующий production-файл TypeScript, не быть
декларацией, тестом, фикстурой или сгенерированным файлом. После проверки
запускатель возвращает нормализованный путь вместе с исходным диапазоном и
передаёт его Stryker через `--mutate`.

Допустимый диапазон следует синтаксису Stryker
`:startLine[:startColumn]-endLine[:endColumn]`. Номера строк положительные,
номера колонок неотрицательные. Конечная позиция не может предшествовать
начальной. Цели без диапазона остаются допустимыми для явных полных прогонов.

Некорректный диапазон, путь за пределами репозитория и несуществующий базовый
файл отклоняются существующей ошибкой о недопустимой цели.

## Процесс тестирования

`.agents/testing.md` предписывает в обычной задаче передавать изменённые
диапазоны строк. Если изменённых несмежных участков несколько, один файл можно
указать несколько раз с разными диапазонами. Полный файл запускается только
явно, когда диапазон нельзя надёжно определить или требуется проверить влияние
изменения на весь файл.

Обязательная пара полных отчётов `before`/`after` удаляется из обычного процесса.
Она остаётся отдельным требованием только при объединении или удалении тестов,
когда задача проверяет сохранение их эффективности.

## Проверки

Существующий тест запускателя расширяется наблюдаемыми договорами:

- допустимые диапазоны строк и колонок сохраняются при нормализации;
- существование проверяется по базовому пути без диапазона;
- некорректные и обратные диапазоны отклоняются;
- прежние безопасные цели без диапазона продолжают работать.

После целевого теста выполняются `pnpm type-check` и `pnpm test` согласно
правилам проекта.
