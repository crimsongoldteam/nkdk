# Исключение implicitValueYAML из JSON Schema

## Задача

`implicitValueYAML` задает значение, которое не должно явно присутствовать в YAML. Сейчас TypeScript-тип YAML исключает такие значения, но runtime-валидация проекта через JSON Schema их допускает, потому что экспорт схемы вычитает `defaultValue`, а не `implicitValueYAML`.

Пример: у документа `Автонумерация` задано `implicitValueYAML: true`, поэтому YAML `Автонумерация: Истина` должен быть ошибкой валидации, а `Автонумерация: Ложь` должен оставаться допустимым.

## Решение

В общем экспорте property-схемы использовать только `implicitValueYAML` как источник исключаемого YAML-значения. `defaultValue` остается значением модели и не влияет на допустимые YAML-значения.

Для литеральных значений поддержать те же преобразования, что уже используются в YAML-типах:

- `boolean`: `true -> Истина`, `false -> Ложь`
- `number`: число как есть
- `string`: строка как есть, включая пустую строку
- `SystemEnumeration`: строка как есть

Если `implicitValueYAML` является функцией, схема не вычитает значение, потому что оно зависит от контекста объекта. Если экспортированная схема не является перечислением через `anyOf` с `const`, она остается без изменений.

## Границы

Изменение находится в `packages/core/metadata/orchestration/property/toJSONSchema.ts`. Правила конкретных объектов, включая `metadataDocument/rules.ts`, менять не нужно.

Не добавляем поддержку fallback на `defaultValue`: это снова смешает модельный default и YAML-договор.

## Проверки

Нужно добавить тесты, которые закрепляют договор:

- общий тест экспорта property-схемы: `implicitValueYAML: true` для boolean исключает `Истина`;
- общий тест экспорта property-схемы: `implicitValueYAML` для number, string и `SystemEnumeration` исключает соответствующее значение;
- schema/validation тест для документа: `Автонумерация: Истина` дает ошибку;
- schema/validation тест для документа: `Автонумерация: Ложь` проходит.

После реализации проверить точечные тесты и затем `pnpm test`.
