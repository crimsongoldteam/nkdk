# Color raw ref round-trip

## Контекст

Расхождение из `erp/DataProcessors/СопоставлениеПланФактОперацийМСФО/Forms/Форма/Ext/Form.xml`
находится внутри DCS typed value:

```xml
<dcscor:value xsi:type="v8ui:Color">0:615512b6-4378-4fce-86f1-a56725f945da</dcscor:value>
```

После XML -> модель -> XML значение теряет префикс `0:`:

```xml
<dcscor:value xsi:type="v8ui:Color">615512b6-4378-4fce-86f1-a56725f945da</dcscor:value>
```

Причина: текущий импорт `Color` считает часть до двоеточия префиксом типа цвета.
Для `style:`, `win:` и `web:` это корректно, но `0:` не является известным
префиксом `ColorType`. В модель попадает цвет без распознанного типа, а экспорт
уже не может восстановить исходную строку.

## Существующий аналог

В `packages/core/metadata/commonObjects/picture` уже есть решение для похожих
UID-ссылок:

- `xr:Ref` вида `0` и `0:<uuid>` импортируется как raw-ссылка;
- raw-ссылка хранит исходное значение в `rawRef`;
- экспорт пишет `rawRef` обратно без преобразования;
- доменные ссылки `StdPicture.*`, `CommonPicture.*` и абсолютные картинки
  продолжают обрабатываться обычными типами.

Для `Color` стоит повторить этот паттерн, чтобы UID-ссылка оставалась XML
round-trip деталью, а не превращалась в новый доменный тип цвета.

## Цель

Сохранять `v8ui:Color` со значением `0` или `0:<uuid>` буквально при
XML round-trip.

Границы задачи:

- не менять XML-фикстуры внешнего XML-репозитория;
- не менять поведение `style:`, `win:`, `web:` и абсолютных цветов;
- не пытаться разрешать `0:<uuid>` в имя цвета или ссылку на другой объект;
- не расширять YAML-представление цветов без отдельного решения.

## Дизайн

Добавить в модель `Color` отдельный вариант raw-ссылки, например:

```ts
type RawColorRef = {
  rawRef: string
}
```

Правила XML:

- `style:<value>` импортируется как `StyleItem`;
- `win:<value>` импортируется как `WindowsColor`;
- `web:<value>` импортируется как `WebColor`;
- значения `0` и `0:<uuid>` импортируются как `RawColorRef`;
- остальные значения без известного префикса сохраняют текущую обработку
  абсолютного цвета;
- `RawColorRef` экспортируется обратно как строка `rawRef`.

Паттерн распознавания raw-ссылки должен быть таким же узким, как у `Picture`:
`/^0(?::[0-9a-fA-F-]+)?$/`. Это сохраняет известный UID-случай и не начинает
молчаливо принимать любые неизвестные префиксы.

## YAML

YAML-представление цветов сейчас описывает обычные цвета, а найденное
расхождение относится к сохранению исходного XML. Поэтому raw-ссылку цвета не нужно
сразу выводить в публичную YAML-форму.

Если raw `Color` попадет на YAML-путь, поведение должно остаться
консервативным: либо существующая логика откажется от неподдержанного значения,
либо потребуется отдельное согласованное решение для YAML.

## Затронутый код

- `packages/core/metadata/commonObjects/color/types.ts`
- `packages/core/metadata/commonObjects/color/fromXML.ts`
- `packages/core/metadata/commonObjects/color/toXML.ts`
- точечные тесты `color` и, при необходимости, DCS typed value с `v8ui:Color`

## Риски

- Слишком широкий raw-паттерн может скрыть настоящую ошибку неизвестного
  префикса цвета. Поэтому raw-режим ограничен только `0` и `0:<uuid>`.
- Тип `Color` сейчас предполагает обязательный `ColorType`; добавление объединенного
  варианта потребует аккуратной проверки мест, где читается `color.type`.
- Если YAML-путь уже неявно ожидает любой `Color`, raw-вариант должен быть
  обработан явно, чтобы не получить `undefined` в YAML.

## Тестирование

Перед реализацией добавить точечные тесты:

- `fromXML` импортирует `0:<uuid>` как `RawColorRef` с тем же `rawRef`;
- `toXML` экспортирует `RawColorRef` обратно в `0:<uuid>`;
- обычные `style:`, `win:`, `web:` и абсолютные цвета экспортируются как раньше;
- DCS typed value с `xsi:type="v8ui:Color"` сохраняет `0:<uuid>` при
  XML -> модель -> XML.

После исправления запустить узкие тесты `color`/DCS, а перед закрытием всей
серии задач - полный `pnpm test` из корня.
