# Независимый от каталога запуска runtime source-workers

> Статус: согласовано.

## Цель

Сделать локальный запуск metadata-операций через MCP независимым от каталога, из которого запущен Node.js, сохранив два разных runtime-режима:

- разработка и диагностика выполняют актуальные TypeScript-исходники без предварительной сборки;
- production выполняет заранее собранный JavaScript без загрузчика TypeScript.

Дополнительно MCP-клиент должен показывать исходную ошибку дочернего процесса вместо одного сообщения `Connection closed`.

## Термины

`cwd` — текущий рабочий каталог процесса, то есть каталог, из которого запущена программа.

`tsx` — загрузчик для выполнения TypeScript-файлов в Node.js без предварительной сборки в JavaScript. Он нужен только source-режиму разработки.

Worker — отдельный поток Node.js, которому главный процесс передаёт тяжёлую часть metadata-операции.

## Причина текущего сбоя

Локальный MCP-клиент запускает TypeScript-сервер из корня репозитория. При импорте XML сервер создаёт worker и передаёт ему `--import tsx`.

`tsx` здесь указан как имя пакета без полного адреса. Node.js пытается разрешить такое имя относительно среды запуска. В корне репозитория пакет недоступен, хотя он является зависимостью `@nkdk/core` и `@nkdk/mcp`. Поэтому worker завершается с `ERR_MODULE_NOT_FOUND`, а MCP-клиент сообщает только следствие: `Connection closed`.

Такое поведение уже подтверждено прямыми проверками:

- `node --import tsx` из корня репозитория падает;
- та же команда из `packages/core` и `packages/mcp` выполняется;
- абсолютный путь к загрузчику работает из корня.

## Основной принцип

Worker не должен зависеть от `cwd` вызывающего процесса.

Компонент, которому нужен runtime-файл, сам разрешает его относительно собственного пакета и передаёт абсолютный `file:` URL. Вызывающий код не должен менять `cwd`, устанавливать копию зависимости в корень или знать внутреннюю раскладку зависимостей компонента.

## Runtime-режимы

### Source-режим

Source-режим используется локальными инструментами разработки и round-trip:

1. MCP запускает актуальный `server.ts`.
2. Общий helper core разрешает `tsx` относительно собственного модуля через стандартный механизм Node.js.
3. Helper возвращает аргументы запуска worker с абсолютным `file:` URL загрузчика.
4. Все TypeScript worker-пулы используют этот helper.
5. Изменения исходников становятся доступны без отдельной сборки.

Общий helper устраняет три независимых копии `["--import", "tsx"]`:

- worker импорта XML;
- worker подготовки YAML-проекта;
- worker полной синхронизации в XML.

Worker подготовки YAML дополняет общий список своим регистрационным модулем validation. Этот модуль также передаётся абсолютным `file:` URL.

### Production-режим

Production использует сборку `@nkdk/mcp`:

1. TypeScript заранее преобразуется в JavaScript.
2. Сервер запускает отдельные собранные JavaScript-файлы worker.
3. `tsx` и другие загрузчики TypeScript не участвуют в runtime.
4. Пути worker формируются относительно собранного модуля как абсолютные пути или `file:` URL.

Существующее различие по расширению текущего модуля сохраняется: `.ts` включает source-runtime, `.js` использует собранные workers без дополнительных `execArgv`.

## Диагностика ошибок

MCP-клиент продолжает отделять stdout протокола от stderr сервера.

При успешной операции stderr не печатается без `--debug`. При неуспешной операции клиент:

1. дожидается закрытия транспорта;
2. сохраняет накопленный stderr в указанный диагностический файл, включая путь аварийного завершения;
3. выводит stderr один раз перед итоговой ошибкой клиента.

Поэтому пользователь видит исходную ошибку worker, а `Connection closed` остаётся дополнительным описанием разрыва MCP-соединения.

## Проверки

Исправление разрабатывается через TDD.

### Source-runtime

Тест запускает Node.js с аргументами общего helper из временного каталога вне пакетов `core` и `mcp`. Он должен успешно загрузить `tsx`. До исправления эквивалентный запуск с голым именем `tsx` воспроизводит `ERR_MODULE_NOT_FOUND`.

Отдельная проверка гарантирует, что все три TypeScript worker-пула используют общий helper и не содержат собственный голый specifier `tsx`.

### Production-runtime

Существующий build и smoke test собранного `@nkdk/mcp` подтверждают, что JavaScript workers включены в пакет и запускаются без `tsx`.

### MCP-диагностика

Тест аварийного дочернего процесса подтверждает, что MCP-клиент сохраняет и показывает его stderr до сообщения об ошибке соединения.

### Приёмочная проверка

После локальных тестов повторно выполняется `round-trip-yaml` для `/Users/nikita/git/round-trip/cf/all` с YAML-каталогом `/Users/nikita/git/nkdk-yaml/cf`.

Успешный импорт и переход к синхронизации подтверждают исправление source-runtime. Результат round-trip анализируется по исходному договору skill.

## Не цели

- Не добавлять `tsx` в зависимости корневого пакета ради доступности из одного `cwd`.
- Не менять `cwd` MCP-клиента как способ разрешения зависимостей.
- Не запускать TypeScript в production.
- Не менять metadata-модели, rules.ts или договоры XML/YAML.
- Не исправлять XML round-trip расхождения в рамках этого изменения.

## Риски

- Новый source-worker может снова обойти общий helper. Проверка отсутствия локальных голых specifier предотвращает такое расхождение.
- Source- и production-режимы могут расходиться. Поэтому нужны обе проверки: TypeScript из постороннего каталога и smoke test собранного пакета.
- Потеря stderr может скрыть следующую независимую ошибку. Диагностический тест фиксирует обязательное сохранение исходной причины.
