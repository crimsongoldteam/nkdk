# ClientApplicationInterface YAML Design

## Цель

Реализовать полноценный YAML round-trip для корневого внешнего файла `Ext/ClientApplicationInterface.xml`.
YAML-представление должно жить внутри `Конфигурация.yaml` в ключе `ИнтерфейсКлиентскогоПриложения`, а XML должен по-прежнему читаться из и записываться в `Ext/ClientApplicationInterface.xml`.

## Источники

- `mngapp.xsdmngcore_root.res`: `ClientApplicationInterface` имеет тип `InterfaceLayouter`.
- `model.xdtomngcore_root.res`: `InterfaceLayouter` содержит повторяемые секции `top`, `left`, `right`, `bottom` и `panelDef`.
- `/Users/nikita/git/roundTripElements/ext/ClientApplicationInterface.xml`: фикстура с повторяющимися секциями, прямыми панелями, пустой группой и вложенной группой.
- `/Users/nikita/git/round-trip-source/doc/Ext/ClientApplicationInterface.xml`: реальный пример `panelDef` с `spr`.

## YAML-форма

Используем русские секции, близкие к дереву интерфейса 1С:

```yaml
ИнтерфейсКлиентскогоПриложения:
  Верх:
    - Панель: ПанельФункцийТекущегоРаздела
    - Панель: ПанельОткрытых
    - Панель: СтандартнаяПанель
  Лево:
    - Панель: ПанельИстории
    - Группа:
        Элементы: []
  Право:
    - Панель: СтандартнаяПанель
  Низ:
    - Панель: ПанельРазделов
    - Панель: ПанельИзбранного
    - Группа:
        Элементы:
          - Панель: СтандартнаяПанель
```

Короткая форма `Панель: ИмяПанели` используется, когда у панели нет дополнительных свойств.
Если есть `height`, `kind` или настройка из `panelDef.spr`, панель разворачивается:

```yaml
Панель:
  Имя: ПанельИстории
  Высота: 1
  Представление: КартинкаСлеваИТекст
```

## Панели

Стандартные UUID панелей скрываются за именованными значениями:

- `ПанельИстории` -> `b553047f-c9aa-4157-978d-448ecad24248`
- `ПанельРазделов` -> `13322b22-3960-4d68-93a6-fe2dd7f28ca3`
- `ПанельФункцийТекущегоРаздела` -> `c933ac92-92cd-459d-81cc-e0c8a83ced99`
- `ПанельОткрытых` -> `cbab57f2-a0f3-4f0a-89ea-4cb19570ab75`
- `ПанельИзбранного` -> `b2735bd3-d822-4430-ba59-c9e869693b24`
- `СтандартнаяПанель` -> `00000000-0000-0000-0000-000000000000`

Если в XML встретится неизвестный `uuid`, YAML должен сохранить его явно через развернутую форму `UUID`.
Если в XML встретится `<panel><name>...</name></panel>`, YAML должен сохранить его как `Имя`.

## Служебные идентификаторы

Атрибуты `id` у `panel`, `group` и `panelDef` не попадают в YAML.
При экспорте в XML они восстанавливаются из reference по структурной позиции.
Для новых узлов без reference генерируются новые UUID.

## panelDef

Пустые стандартные `panelDef` не выводятся в YAML.
При экспорте они восстанавливаются из reference; без reference создается набор для использованных стандартных панелей.

Если `panelDef` содержит `spr`, эта настройка отражается на соответствующей панели как `Представление`.
Пример:

```yaml
Панель:
  Имя: ПанельИстории
  Представление: КартинкаСлеваИТекст
```

Если `panelDef.name` относится к панели, которая присутствует в дереве, YAML сохраняет его через развернутую форму этой панели, чтобы не терять данные.
Непривязанные непустые `panelDef` не встречались в исследованных фикстурах; если такой случай появится, импорт должен сохранить его в reference для XML round-trip и остановиться с диагностикой перед YAML-экспортом, чтобы отдельно согласовать человекочитаемую форму.

## Архитектура

Добавить отдельные rule-driven типы для `ClientApplicationInterface`:

- `InterfaceLayouter`: контейнер секций и `panelDef`.
- `PanelLayouter`: choice `Панель` или `Группа`.
- `PanelGroup`: список `Элементы`.
- `Panel`: имя стандартной панели, `UUID` или XML `name`, плюс `Высота` и `Представление`.
- `PanelDef`: служебное описание панели, не выводится напрямую для стандартного случая.

Подключить свойство `clientApplicationInterface` в `MetadataConfigurationRules` с `filePath: "Ext/ClientApplicationInterface.xml"`, чтобы корневой YAML конфигурации управлял внешним XML-файлом.

## Проверка

Порядок реализации должен идти через XML-барьер:

1. XML -> модель -> XML для фикстур `roundTripElements/ext`, `acc`, `doc`.
2. YAML-форма для коротких панелей и развернутых панелей с `Представление`.
3. YAML -> модель -> XML с reference, чтобы проверить восстановление `id`.
4. Полный `round-trip-yaml` для выбранной конфигурации.
