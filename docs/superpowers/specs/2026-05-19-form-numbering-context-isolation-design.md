# Изоляция контекста нумерации форм в YAML -> XML

## Контекст

Профиль полного `round-trip-yaml` показал, что стадия `YAML -> XML` растягивается до десятков минут не из-за чтения reference XML. Сравнение обычного и reference-импорта форм дало близкие времена, а профиль CPU указал на `packages/core/metadata/forms/clientApplicationForm/toXML.ts`: цепочку `exportClientApplicationFormToXML -> setIdsToElements -> setIdsToElementsGroup`.

Причина в состоянии экспорта. В `round-trip-xml` для каждой формы создаётся свежий `exportToXML.context.metadataForNumbering`. В `YAML -> XML` формы одного объекта получают общий вложенный `exportToXML.context`, поэтому `metadataForNumbering` накапливает элементы предыдущих форм. Каждая следующая форма повторно нумерует всё больший список, хотя `_id` должен назначаться только элементам текущей формы.

## Цель

Сделать нумерацию XML-элементов формы локальной для одной формы и убрать лавинообразный рост времени `YAML -> XML` минимальной правкой.

Критерий успеха:

- `metadataForNumbering` не протекает между формами;
- XML-результат остаётся совместимым с текущими тестами и reference-данными;
- полный `round-trip-yaml` заметно ускоряется на стадии `YAML -> XML`.

## Границы

В задачу входит только исправление протекания состояния формы.

Не входит:

- изменение XML-фикстур;
- изменение YAML-формата;
- переписывание `setIdsToElementsGroup`;
- настройка параллельности или файлового ввода-вывода;
- оптимизация `fast-xml-parser`.

## Рассмотренные подходы

Выбранный подход: изолировать вложенный `exportToXML.context` в `syncFormToXML` для каждой формы. Новый контекст сохраняет `forms`, `templates` и `parentName`, но получает пустые `metadataForNumbering` и `propertiesItemXmlStack`.

Альтернатива на уровне `syncAppliedObjectToXML` полезна как страховка между объектами, но не решает накопление между формами одного объекта. Оптимизация `setIdsToElementsGroup` лечит последствие, а не ошибочное время жизни состояния.

## Дизайн

В `packages/core/metadata/forms/clientApplicationForm/syncToXML.ts` при создании `contextWithFormDir` нужно создать свежий вложенный `exportToXML.context`:

- `forms`, `templates`, `parentName` копируются из входного контекста;
- `metadataForNumbering` всегда начинается как пустой массив;
- `propertiesItemXmlStack` не переиспользуется из входного контекста и начинается пустым;
- остальные поля `exportToXML` сохраняются как есть.

Этот контекст должен использоваться и для `importClientApplicationFormFromYAML`, и для `exportClientApplicationFormToXML`, и для `exportFormMetadataToXML`. Тогда все обработчики, которые добавляют элементы в `metadataForNumbering`, работают только в пределах текущей формы.

## Ошибки и совместимость

Если во входном контексте отсутствует `exportToXML.context`, поведение должно оставаться явным: форма не должна тихо создавать неполный контекст без `forms`, `templates` и `parentName`. Текущие вызовы `syncFormToXML` идут из `syncAppliedObjectToXML`, где эти поля уже устанавливаются.

Назначение `_id` должно сохранить текущую семантику:

- если у reference-элемента есть `id`, он переиспользуется;
- новые элементы получают свободные номера внутри своей группы;
- разные формы не влияют на номера друг друга.

## Проверка

Нужен постоянный тест, который воспроизводит протекание состояния без полного каталога:

- дважды вызвать синхронизацию форм с одним общим родительским контекстом;
- убедиться, что после второй формы общий `metadataForNumbering` не содержит элементы первой формы;
- проверить, что XML второй формы получает собственную нумерацию, а не продолжение списка первой.

После реализации запустить точечные тесты для формы и `syncToXML`. Затем сделать контрольный замер `round-trip-yaml` на той же конфигурации, чтобы сравнить время стадии `YAML -> XML` с предыдущими 14-15 минутами.

## Риски

Главный риск - скрытая зависимость какого-то обработчика формы от накопленного `metadataForNumbering`. По смыслу такой зависимости быть не должно: `_id` элементов формы локальны для XML одной формы. Тест на две формы с общим родительским контекстом должен закрепить это ожидание.

Второй риск - перепутать контекст импорта YAML и экспорта XML. Поэтому реализация должна быть небольшой и локальной: создать отдельный helper или локальный объект только в `syncFormToXML`, не меняя общий контракт `ConfigurationContextWithExportToXML`.
