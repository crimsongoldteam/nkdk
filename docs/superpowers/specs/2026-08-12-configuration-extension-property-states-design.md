# Контроль свойств расширения конфигурации в YAML

## Цель

Значимые режимы свойств заимствованных объектов хранятся в YAML. Снимок
конфигурации не хранит эти режимы и не участвует в их восстановлении.

Спецификация не меняет устройство снимка, его файловый формат или используемое
хранилище.

## Пользовательская модель

Конфигуратор показывает режим свойства значком. YAML сохраняет именно этот
режим, а не буквальное устройство `xr:PropertyState`:

| Значок в Конфигураторе | Смысл | YAML |
|---|---|---|
| Сине-красный | Значение контролируется | Обычное значение без тега |
| Синий | Значение проверяется с предупреждением | `!проверять` |
| Оранжевый | Значение изменяется расширением | `!изменять` или раздел `Изменять` |
| Флажок снят | Свойство не участвует в расширении | Свойство отсутствует |

Набор доступных значков зависит от свойства. YAML проверяется по той же модели:

- `ОбъектРасширяемойКонфигурации` допускает отсутствие, обычный контроль и
  `!проверять`; изменять это свойство нельзя;
- основные формы и другие свойства, для которых Конфигуратор показывает только
  оранжевый значок, допускают лишь отсутствие или `!изменять`;
- `Тип` допускает отсутствие, обычный контроль, `!проверять`, `!изменять` и
  разные режимы для отдельных подтипов; особый режим типа всегда ставится на
  элементы списка подтипов;
- для остальных свойств допустимые режимы определяются видом metadata-объекта и
  версией платформы.

Недопустимый для свойства режим является ошибкой валидации YAML.

## Теги YAML

`!проверять` и `!изменять` — локальные теги формата NKDK, как и существующий
`!xml`. Тег добавляет к смысловому значению режим свойства и не меняет тип
самого значения:

```yaml
ОбъектРасширяемойКонфигурации: !проверять РеквизитСсылка
ОсновнаяФормаОбъекта: !изменять ФормаЭлемента
Формат: !проверять "ДФ=dd.MM.yyyy"
```

Пустое изменяемое значение записывается без искусственного значения:

```yaml
ОсновнаяФормаОбъекта: !изменять
```

Разборщик и сериализатор YAML поддерживают кириллицу в именах этих тегов как
расширение формата NKDK. Новый YAML всегда записывает канонические имена
`!проверять` и `!изменять`.

Обычный сине-красный контроль отдельного тега не имеет:

```yaml
Тип: ХранилищеЗначения
```

Существующий `!xml` сохраняет прежний смысл: это исключительное точное
XML-значение, которое нельзя восстановить из смыслового YAML. Он не обозначает
режим контроля свойства.

## Составной тип

Если у подтипов разные значки, `Тип` записывается списком. Тег ставится на тот
подтип, к которому относится соответствующий режим.

Проверяемый и изменяемый подтипы:

```yaml
Тип:
  - !проверять Дата
  - !изменять Булево
```

Контролируемый и изменяемый подтипы:

```yaml
Тип:
  - Справочник.СправочникПолный
  - !изменять Справочник.СправочникРеквизит
```

Даже единственный изменяемый подтип записывается списком:

```yaml
Тип:
  - !изменять Строка(10)
```

Эта форма означает `MultiState`, содержащий только `ExtendValue`, и точно
восстанавливает выгрузку Конфигуратора.

Пустая контролируемая часть сохраняется пустым элементом списка без тега:

```yaml
Тип:
  - []
  - !изменять Справочник.ПроектныеЗадачи
```

## Вынесенное содержимое

У форм, модулей, прав, командных интерфейсов, картинок и другого вынесенного
содержимого значение находится в отдельном YAML-, BSL-, XML- или двоичном
файле. Оранжевый режим относится к свойству metadata-объекта, а не к внешнему
файлу.

Такие свойства перечисляются в разделе `Изменять` YAML-файла самого объекта:

```yaml
Изменять:
  - Форма
  - МодульОбъекта
```

Содержимое продолжает храниться отдельно, например:

```text
Формы/ФормаЭлемента/Форма.yaml
МодульОбъекта.bsl
```

Наличие имени в разделе `Изменять` означает оранжевый режим. Отсутствие имени
означает, что специальный режим для свойства не задан. Синий и сине-красный
режимы этим разделом не представляются.

Подтверждённые имена вынесенных свойств:

| YAML-имя | XML-имя |
|---|---|
| `Форма` | `Form` |
| `Модуль` | `Module` |
| `МодульОбъекта` | `ObjectModule` |
| `МодульМенеджера` | `ManagerModule` |
| `Права` | `Rights` |
| `Состав` | `Content` |
| `ПредопределенныеДанные` | `Predefined` |
| `КомандныйИнтерфейс` | `CommandInterface` |
| `РабочаяОбластьНачальнойСтраницы` | `HomePageWorkArea` |
| `КомандныйИнтерфейсОсновногоРаздела` | `MainSectionCommandInterface` |
| `КартинкаОсновногоРаздела` | `MainSectionPicture` |
| `Логотип` | `Logo` |
| `Заставка` | `Splash` |

Перечень не является общей матрицей возможностей платформы. Допустимость имени
определяется правилами конкретного вида metadata-объекта и версией платформы.

## XML-модель

Платформа определяет пять значений `xr:PropertyState`:

| XML-состояние | Смысл |
|---|---|
| `NotSet` | Режим не задан |
| `Checked` | Значение контролируется |
| `Notify` | Значение проверяется с предупреждением |
| `Extended` | Значение изменяется расширением |
| `MultiState` | Части значения имеют разные режимы |

Соответствие пользовательского режима XML не всегда буквальное:

- обычный сине-красный контроль обычно хранится обычным XML-значением без
  `xr:PropertyState`;
- синий режим хранится как `xr:State=Notify`;
- оранжевый режим обычного свойства хранится как `xr:State=Extended`;
- у свойств, допускающих только оранжевый режим, платформа может выводить режим
  из самого присутствия XML-свойства без `xr:PropertyState`;
- разные режимы частей типа хранятся как `xr:State=MultiState` и значение
  `xr:ExtendedProperty` с `xr:CheckValue`, `xr:NotifyValue` и
  `xr:ExtendValue`.

Например, пустая изменяемая основная форма объекта выгружается без
`xr:PropertyState`:

```xml
<DefaultObjectForm/>
```

Синий режим свойства выгружается явно:

```xml
<xr:PropertyState>
  <xr:Property>ExtendedConfigurationObject</xr:Property>
  <xr:State>Notify</xr:State>
</xr:PropertyState>
```

Составной тип с контролируемой и изменяемой частями:

```xml
<xr:PropertyState>
  <xr:Property>Type</xr:Property>
  <xr:State>MultiState</xr:State>
</xr:PropertyState>
<Type xsi:type="xr:ExtendedProperty">
  <xr:CheckValue xsi:type="v8:TypeDescription">
    <v8:Type>cfg:CatalogRef.СправочникПолный</v8:Type>
  </xr:CheckValue>
  <xr:ExtendValue xsi:type="v8:TypeDescription">
    <v8:Type>cfg:CatalogRef.СправочникРеквизит</v8:Type>
  </xr:ExtendValue>
</Type>
```

## Предопределённые данные

`Изменять: [ПредопределенныеДанные]` относится ко всему свойству `Predefined`.
Режимы отдельных заимствованных предопределённых элементов хранятся внутри их
смысловой YAML-структуры и не подменяются этим разделом.

## Импорт XML → YAML

1. Отсутствующее XML-свойство не создаёт YAML-поля.
2. Обычное контролируемое XML-значение импортируется без тега.
3. `Notify` превращается в `!проверять` на значении.
4. Обычный `Extended` превращается в `!изменять` на значении.
5. Оранжевый режим вынесенного свойства добавляет его имя в раздел `Изменять`.
6. `MultiState` разбирается в список обычных, `!проверять` и `!изменять`
   частей.
7. Ни один режим не записывается в снимок конфигурации.

## Экспорт YAML → XML

1. Обычное значение создаёт контролируемое XML-свойство в платформенном
   представлении этого свойства.
2. `!проверять` создаёт синий режим в платформенном XML-представлении.
3. `!изменять` создаёт оранжевый режим в платформенном XML-представлении.
4. Список частей типа создаёт `xr:ExtendedProperty` и
   `xr:State=MultiState`.
5. Имена из раздела `Изменять` создают оранжевый режим вынесенных свойств.
6. Порядок `xr:PropertyState` определяется порядком XML-свойств в `rules.ts`, а
   не порядком YAML.

## Диагностики

- Неизвестный локальный тег является ошибкой YAML.
- Режим, недоступный для данного свойства, является ошибкой валидации.
- Имя в разделе `Изменять`, не зарегистрированное для данного вида
  metadata-объекта, является ошибкой валидации.
- Тег на части значения разрешён только правилам, поддерживающим составное
  представление.
- Одно свойство нельзя одновременно пометить `!изменять` и добавить в раздел
  `Изменять`.
- Значимый режим, который импорт ещё не умеет представить в YAML, нельзя молча
  пропускать или сохранять в снимке: импорт завершается диагностикой.
