# Состояния свойств расширения конфигурации в YAML

## Цель

Все значимые `xr:PropertyState` расширения хранятся в YAML. Снимок
конфигурации не хранит состояния свойств и не участвует в их восстановлении.

Спецификация не меняет устройство снимка, его файловый формат или используемое
хранилище.

## XML-модель платформы

Платформа определяет пять значений `xr:PropertyState`:

| XML-состояние | Смысл | YAML-представление |
|---|---|---|
| `NotSet` | Особый режим не задан | Не записывается |
| `Checked` | Несовпадение запрещает применение расширения | `!контролируется` |
| `Notify` | Несовпадение вызывает предупреждение | `!проверяется` |
| `Extended` | Значение берётся из расширения | `!изменяется` либо `МодифицируемыеСвойства` |
| `MultiState` | Части одного значения имеют разные режимы | Теги на отдельных частях значения |

XML-запись состояния содержит имя свойства и одно значение перечисления:

```xml
<xr:PropertyState>
  <xr:Property>Type</xr:Property>
  <xr:State>MultiState</xr:State>
</xr:PropertyState>
```

При `MultiState` само свойство имеет тип `xr:ExtendedProperty` и может
содержать `xr:CheckValue`, `xr:NotifyValue` и `xr:ExtendValue`.

## Обычные значения свойств

Режим записывается YAML-тегом непосредственно на значении свойства:

```yaml
Формат: !проверяется "ДФ=dd.MM.yyyy"
ОсновнаяФормаОбъекта: !изменяется ФормаЭлемента
Иерархический: !контролируется Истина
```

Тег не меняет смысловой тип значения. После разбора доступны обычное значение
и его режим. Кавычки применяются по обычным правилам YAML.

При экспорте теги преобразуются так:

| YAML-тег | `xr:State` | XML-значение |
|---|---|---|
| `!контролируется` | `Checked` | Обычное значение свойства |
| `!проверяется` | `Notify` | Обычное значение свойства |
| `!изменяется` | `Extended` | Обычное значение свойства |

Действующий раздел `Контроль` заменяется тегом `!проверяется`. Новый YAML его
не создаёт.

## Составные значения

Если режим относится к отдельным частям значения, тег ставится на каждую такую
часть. Например, XML с `NotifyValue=Дата` и `ExtendValue=Булево` представляется
так:

```yaml
Тип:
  - !проверяется Дата
  - !изменяется Булево
```

XML с `CheckValue=Дата` и `ExtendValue=Булево`:

```yaml
Тип:
  - !контролируется Дата
  - !изменяется Булево
```

Список тегированных частей означает `xr:ExtendedProperty` и
`xr:State=MultiState`, даже если в списке осталась одна часть:

```yaml
Тип:
  - !изменяется СправочникОбъект.Показатели
```

Это необходимо для точного восстановления реального XML определяемого типа, в
котором `MultiState` содержит только `ExtendValue`.

Пустой `CheckValue` сохраняется как пустая контролируемая часть, а не удаляется:

```yaml
Тип:
  - !контролируется []
  - !изменяется СправочникСсылка.ПроектныеЗадачи
```

## Вынесенные свойства объекта

У форм, модулей, прав, командных интерфейсов, картинок и других вынесенных
свойств значение находится в отдельном YAML-, BSL-, XML- или двоичном файле.
Состояние относится к свойству metadata-объекта, а не ко всему внешнему файлу.

Для таких свойств используется список `МодифицируемыеСвойства` в YAML самого
объекта:

```yaml
МодифицируемыеСвойства:
  - Форма
```

Содержимое формы продолжает храниться отдельно:

```text
Формы/ФормаЭлемента/Форма.yaml
```

Наличие имени в списке преобразуется в `xr:State=Extended`. Отсутствие имени
означает, что специальное состояние для свойства не задано. Другие состояния
в `МодифицируемыеСвойства` не представляются.

По исследованным расширениям список применяется к следующим свойствам:

| YAML-имя | XML-имя |
|---|---|
| `Форма` | `Form` |
| `Модуль` | `Module` |
| `МодульОбъекта` | `ObjectModule` |
| `МодульМенеджера` | `ManagerModule` |
| `Права` | `Rights` |
| `Состав` | `Content` |
| `ПредопределенныеДанные` | `Predefined` |
| `КомандныйИнтерфейс` | `CommandInterface` |
| `РабочаяОбластьНачальнойСтраницы` | `HomePageWorkArea` |
| `КомандныйИнтерфейсОсновногоРаздела` | `MainSectionCommandInterface` |
| `КартинкаОсновногоРаздела` | `MainSectionPicture` |
| `Логотип` | `Logo` |
| `Заставка` | `Splash` |

Перечень не является глобальной матрицей возможностей платформы. Допустимость
конкретного имени определяется правилами вида metadata-объекта и версией
платформы.

## Предопределённые данные

`МодифицируемыеСвойства: [ПредопределенныеДанные]` относится ко всему свойству
`Predefined`. Режимы отдельных заимствованных предопределённых элементов
хранятся внутри их смысловой YAML-структуры и не подменяются этим списком.

## Импорт и экспорт

### Импорт XML → YAML

1. `NotSet` не создаёт YAML-представления.
2. `Checked`, `Notify` и обычный `Extended` превращаются в тег на значении.
3. `Extended` вынесенного зарегистрированного свойства добавляет его YAML-имя
   в `МодифицируемыеСвойства`.
4. `MultiState` разбирает `CheckValue`, `NotifyValue` и `ExtendValue` в
   тегированные части значения.
5. Ни одно состояние не записывается в снимок конфигурации.

### Экспорт YAML → XML

1. Тег на обычном значении создаёт соответствующий `xr:PropertyState` и
   экспортирует обычное значение свойства.
2. Тегированные части составного значения создают `xr:ExtendedProperty` и
   `xr:State=MultiState`.
3. Имена из `МодифицируемыеСвойства` создают записи `Extended` для вынесенных
   свойств.
4. Порядок `xr:PropertyState` определяется порядком XML-свойств в `rules.ts`, а
   не порядком YAML-списка.

## Диагностики

- Неизвестный тег состояния является ошибкой YAML.
- Имя в `МодифицируемыеСвойства`, не зарегистрированное для данного вида
  metadata-объекта, является ошибкой валидации.
- Тег на части значения разрешён только правилам, поддерживающим составное
  представление.
- Одно свойство нельзя одновременно пометить тегом `!изменяется` и добавить в
  `МодифицируемыеСвойства`.
- Значимое состояние, которое импорт ещё не умеет представить в YAML, нельзя
  молча пропускать или сохранять в снимке: импорт завершается диагностикой.
