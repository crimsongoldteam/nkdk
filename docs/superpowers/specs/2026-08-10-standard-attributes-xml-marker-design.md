# Дефолтная коллекция стандартных реквизитов через `!xml`

## Контекст

Платформа 1С может сохранять в XML коллекцию `StandardAttributes`, даже если
все входящие в неё стандартные реквизиты имеют значения по умолчанию. Если
коллекция не была материализована платформой, блока в XML нет. Эти состояния
семантически равны и неразличимы после действующего импорта в YAML.

Если хотя бы один стандартный реквизит содержит смысловое отличие, 1С выводит
в XML всю коллекцию стандартных реквизитов данного владельца. Коллекции
основного объекта и каждой вложенной табличной части независимы.

Исследование `/Users/nikita/git/round-trip-compact/cf/small` подтвердило оба
варианта: из 2075 табличных элементов `LineNumber` 2053 имеют полностью
дефолтное XML-представление, а внутри одного объекта встречаются табличные
части как с таким блоком, так и без него.

## Цель

Сохранять присутствие полностью дефолтной коллекции `StandardAttributes`
явным транспортным тегом `!xml`, чтобы полный XML → YAML → XML round-trip не
зависел от reference XML или скрытого снимка конфигурации.

Новое применение `!xml` явно согласовано разработчиком 10 августа 2026 года.

## YAML-договор

### Коллекция отсутствует в XML

Поле отсутствует и в YAML:

```yaml
ТабличныеЧасти:
  История:
    Синоним: История
```

### Коллекция присутствует и полностью дефолтна

Импорт записывает пустой локальный тег:

```yaml
ТабличныеЧасти:
  Исполнители:
    СтандартныеРеквизиты: !xml
```

Тег означает только: «создать каноническую коллекцию стандартных реквизитов
этого владельца со значениями по умолчанию». Он не является смысловым
значением модели.

### Есть смысловые отличия

YAML сохраняет только изменённые свойства обычным способом:

```yaml
СтандартныеРеквизиты:
  Дата:
    ПроверкаЗаполнения: ВыдаватьОшибку
```

Экспорт продолжает дополнять коллекцию всеми каноническими стандартными
реквизитами владельца через существующий `completeItemNames`.

## Импорт XML → YAML

Обработчик `StandardAttributeDescriptions` сначала выполняет обычный
семантический импорт коллекции.

- Если результат содержит хотя бы одно смысловое свойство, возвращается
  обычное YAML-отображение.
- Если результат пуст, но `StandardAttributes` присутствует в XML, свойство
  получает транспортное значение `!xml`.
- Если `StandardAttributes` отсутствует в XML, YAML-свойство не создаётся.
- Действующее сохранение динамических `ExtDimension*` остаётся без изменений:
  эти элементы не заменяются маркером коллекции.
- Reference-импорт остаётся без изменений и не получает транспортный маркер.

## Экспорт YAML → XML

Для свойства типа `StandardAttributeDescriptions` действуют три состояния:

- отсутствующее YAML-свойство не создаёт `StandardAttributes`;
- `!xml` создаёт коллекцию из всех канонических имён, вычисленных действующим
  `completeItemNames`, и экспортирует их со значениями по умолчанию;
- обычное YAML-отображение проходит существующий путь экспорта коллекции.

Пустой маркер не должен создавать пустой `<StandardAttributes/>`: если для
конкретного владельца список канонических имён пуст, экспорт сообщает
диагностику недопустимого транспортного действия.

## Границы реализации

Поддержка располагается локально рядом с регистрацией
`StandardAttributeDescriptions` и не добавляет поля в `PropertyRule`,
`StandardAttributeDescriptionsPropertyRule` или параметры общих построителей
rules.ts.

Действующий реестр `!xml` адресует разрешения только парой
`itemType + propertyKey`. Для этой коллекции такое перечисление продублировало
бы одно правило во всех владельцах стандартных реквизитов. Реестр получает
узкое разрешение, адресованное точным `propertyType`. Оно применяется только к
`StandardAttributeDescriptions`, принимает только пустой `!xml` и передаёт
обработчику коллекции транспортное действие «материализовать канонические
элементы». Регистрация по `itemType + propertyKey` и остальные применения
`!xml` не меняются.

Это согласованное расширение договора транспортных тегов отражается в
`.agents/architecture.md`: фиксированное действие может регистрироваться либо
для `itemType + propertyKey`, либо для точного `propertyType`. Применение
`!xml` к отдельному стандартному реквизиту, к обычной коллекции или к
незарегистрированному свойству остаётся ошибкой.

Транспортная форма:

- не попадает в предметную модель;
- игнорируется semantic validation;
- разрешается внутренней validation-схемой;
- не показывается во внешней схеме подсказок;
- сохраняется операциями чтения и записи YAML без потери тега.

Снимок конфигурации и configuration index не используются для сохранения
присутствия коллекции.

## Диагностики

Одна локальная diagnostic создаётся, если:

- значение `СтандартныеРеквизиты` помечено `!xml`, но свойство не имеет тип
  `StandardAttributeDescriptions`;
- у зарегистрированного свойства невозможно получить ни одного канонического
  имени стандартного реквизита;
- тег имеет непустой payload.

Обычное YAML-отображение стандартных реквизитов проверяется существующими
правилами без изменений.

## Проверки

Модульные проверки обработчика коллекции покрывают:

1. отсутствие `StandardAttributes` в XML и отсутствие поля в YAML;
2. полностью дефолтную коллекцию и `СтандартныеРеквизиты: !xml`;
3. восстановление из `!xml` полного канонического XML-блока;
4. смысловое изменение одного реквизита без `!xml` и восстановление остальных
   канонических элементов;
5. сохранение действующего поведения `ExtDimension*`;
6. отказ для непустого payload и владельца без канонических имён;
7. внутреннюю validation-схему и отсутствие маркера в схеме подсказок.

Интеграционная проверка использует объект с двумя табличными частями: у первой
исходный XML содержит дефолтный `LineNumber`, у второй `StandardAttributes`
отсутствует. После полного XML → YAML → XML round-trip блок восстанавливается
только у первой части без участия reference XML и configuration index.

## Не входит в изменение

- вывод причины, по которой 1С материализовала дефолтную коллекцию;
- автоматическое добавление `StandardAttributes` всем владельцам;
- хранение отдельных пустых элементов как `НомерСтроки: !xml`;
- изменение смысловых значений или умолчаний стандартных реквизитов;
- изменение общей архитектуры `!xml` и формата configuration index.
