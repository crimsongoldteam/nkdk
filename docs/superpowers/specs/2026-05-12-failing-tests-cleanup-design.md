# Разбор падающих тестов и проверки типов

## Цель

Последовательно устранить текущие падения `pnpm test` и смежные ошибки `pnpm --filter @nakidka/core type-check`, не меняя существующие XML-фикстуры.

## Порядок работ

1. `MetadataItemLink` и `SettingsStorage`.
2. Тип правила `typedXML` для свойств, которые уже используют типизированный XML.
3. Обязательные поля `ClientApplicationForm` в TS/YAML фикстурах.
4. Несогласованные singleton-фикстуры формы с публичными типами элементов.
5. Литерал YAML в `DynamicList`, который не соответствует текущему типу.

## Решение для `MetadataItemLink`

`MetadataItemLink` должен читать оба XML-представления ссылки:

- строковое значение элемента;
- объект с `#text` и необязательным `_xsi:type`.

В модели и YAML ссылка остается строкой.

При экспорте формат XML задается правилом свойства:

- без `typedXML` экспортируется строковое значение;
- с `typedXML: "xr:MDObjectRef"` экспортируется объект с `#text` и `_xsi:type`.

Так `SettingsStorage` остается строковым XML, а свойства, которым нужен типизированный XML, явно указывают это в `rules.ts`. Коллекция `MetadataItemLinks` сохраняет текущий контейнерный формат с типизированными `xr:Item`, потому что он уже соответствует XML-фикстурам.

## Проверка

Для каждой группы исправлений запускается целевая проверка. После закрытия всех групп обязательно выполнить:

- `pnpm --filter nkdk-language langium:generate`
- `pnpm test`
- `pnpm --filter @nakidka/core type-check`
