# Исправление ожиданий тестов для implicitValueYAML

## Контекст

После добавления `implicitValueYAML` часть YAML-экспорта стала компактнее: значения, совпадающие с неявными, больше не записываются в YAML. Полный прогон `pnpm test` сейчас падает в `packages/core`: 21 тест в 15 файлах ожидает прежний полный YAML.

Рабочее дерево перед началом исправления чистое. XML-фикстуры менять нельзя: они остаются источником истины.

## Цель

Сохранить новое поведение компактного YAML и привести тестовые ожидания к нему. Исправление считается завершённым, когда затронутые тесты и полный `pnpm test` проходят.

## Границы

Входит:

- обновить ожидаемые YAML-объекты и строки в тестовых фикстурах;
- обновить точечные ожидания `toYAML`/`fromYAML`/`convertFromXML`/round-trip тестов, где они проверяют уже неявные значения;
- не менять XML-фикстуры.

Не входит:

- менять общий механизм `exportPropertyToYAML`;
- откатывать `implicitValueYAML`;
- добавлять новые правила `fromXML`/`toXML`/`fromYAML`/`toYAML`;
- расширять задачу на не связанные падения.

## Подход

Рекомендуемый подход: идти по фактическим падениям `pnpm test` и удалять из ожидаемых YAML-данных только те поля, которые теперь скрываются как `implicitValueYAML`. Это минимально меняет проект и сохраняет новый договор, закреплённый контрактным тестом `implicitValueYAMLContract.test.ts`.

Альтернативы отклонены:

- режим полного YAML для тестов усложнит договор экспорта;
- массовое изменение `rules.ts` рискованно отменит полезное сокращение YAML.

## Проверка

1. Запустить затронутые тесты `packages/core` после правок.
2. Запустить полный `pnpm test` из корня.
3. Если появятся падения не про скрытые implicit YAML значения, остановиться и диагностировать отдельно.
