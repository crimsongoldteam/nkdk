# Применение excludeIfEqualNameYAML ко всем synonym

## Цель

Расширить уже реализованный договор `excludeIfEqualNameYAML` на все production-правила metadata, где свойство называется `synonym`, является YAML-полем `Синоним` и имеет тип `I8nText`.

Такой `Синоним` не должен явно записываться в YAML, если его значение восстанавливается из имени объекта, а validation должна запрещать явное равное значение.

## Границы

Меняются только production `rules.ts` в `packages/core/metadata/**`.

Не меняются тестовые искусственные правила, фикстуры XML и сам механизм `excludeIfEqualNameYAML`.

## Подход

Проставить `excludeIfEqualNameYAML: true` в правилах `synonym`, которые описывают реальный metadata-объект или вложенный metadata-элемент и читают имя через стандартный контекст rules.

Не трогать похожие локализованные поля, которые не называются `synonym`, например заголовки, подсказки или форматированные тексты.

## Проверка

После изменения выполнить точечные тесты механизма и validation:

```sh
pnpm --filter @nakidka/core exec vitest run metadata/commonObjects/i8nText metadata/validation
```

Перед закрытием задачи выполнить полный прогон:

```sh
pnpm test
```

## Риски

Основной риск - правила с `synonym`, у которых при YAML-импорте недоступно имя. Такие места нужно выявить тестами; если они есть, флаг там не добавляется до появления корректного источника имени.
