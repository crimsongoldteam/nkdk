# Заготовки фикстур для неподдержанных applied-объектов

## Цель

Подготовить XML-фикстуры и каталог `sync` для applied-объектов из `/Users/nikita/git/roundTripElements`, которых ещё нет в `packages/core/metadata/appliedObjects`.

Работа создаёт только основу для будущих реализаций metadataItem. Она не добавляет `rules.ts`, типы, регистрации, тесты и YAML-контракт.

## Границы

Уже поддержанные каталоги исключаются:

- `Catalogs` -> `metadataCatalog`
- `Documents` -> `metadataDocument`
- `DocumentNumerators` -> `metadataDocumentNumerator`
- `Enums` -> `metadataEnumeration`
- `Sequences` -> `metadataSequence`

Остальные applied-каталоги из выгрузки считаются кандидатами на заготовки, если в них есть XML-файлы объекта.

Служебные и не applied-каталоги не переносятся: `.git`, `ext`, `.DS_Store`, `Configuration.xml`, `ConfigDumpInfo.xml`.

## Структура результата

Для каждого неподдержанного объекта создаётся каталог:

```text
packages/core/metadata/appliedObjects/<metadataName>/
  __fixtures__/
    full.xml
    minimal.xml
    sync/
      data.ts
      xml/<ИмяВсеСвойства>.xml
      xml/<ИмяВсеСвойства>/...
      nkdk/<ИмяВсеСвойства>/Свойства.yaml
```

`full.xml` берётся из файла `*ВсеСвойства*.xml`. `minimal.xml` берётся из `*ПоУмолчанию.xml`. Если минимальной фикстуры нет, файл не создаётся, а объект попадает в итоговый отчёт.

`sync/xml/<ИмяВсеСвойства>.xml` получает тот же XML, что и `full.xml`. Если рядом с sync-объектом есть связанные XML-файлы и внешние файлы в одноимённой папке (`Ext`, `Forms`, `Templates`, `Commands`, `Help`), они копируются в `sync/xml/<ИмяВсеСвойства>/...` с сохранением структуры.

`sync/nkdk/<ИмяВсеСвойства>/Свойства.yaml` остаётся пустым. `sync/data.ts` экспортирует пустую строку, потому что YAML-структура появится только после реализации правил объекта и прохождения XML-цикла.

## Имена каталогов

Каталоги в `appliedObjects` именуются в стиле существующего кода: `metadata` + единственное английское имя объекта, например `metadataDocumentJournal` для `DocumentJournals`.

Если однозначное единственное имя нельзя вывести из существующей схемы, имя фиксируется консервативно по названию XML-каталога и отмечается в отчёте для проверки перед реализацией объекта.

## Проверка

После создания заготовок нужно проверить:

- `git status --short` показывает только новые каталоги фикстур и сгенерированные ранее Langium-файлы, если они изменились при базовой подготовке;
- в заготовках нет `.DS_Store`;
- для каждого объекта есть `sync/data.ts` и пустой `Свойства.yaml`;
- XML-файлы из выгрузки скопированы без изменения содержимого.

Полный `pnpm test` для самих заготовок не обязателен, потому что тесты и регистрации не добавляются. Базовый прогон в рабочем дереве уже выполнен до изменений.
