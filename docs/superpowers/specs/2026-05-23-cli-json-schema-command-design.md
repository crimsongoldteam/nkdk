# CLI-команда JSON Schema для YAML-файла

## Цель

Добавить CLI-команду, которая по полному пути к YAML-файлу проекта возвращает JSON Schema для этого файла.
Основной потребитель - ИИ-агенты и редакторские инструменты, которым нужно понять допустимые поля, типы и значения при разработке конфигураций.

## Команда

```bash
nkdk schema <file> [--project <yaml-dir>]
```

- `<file>` может быть абсолютным или относительным путем к YAML-файлу.
- Если `<file>` абсолютный, команда использует его как есть.
- Если `<file>` относительный и `--project` не задан, команда разрешает путь от `process.cwd()`.
- Если `--project` задан, команда разрешает относительный `<file>` от корня YAML-проекта.
- `stdout` содержит только JSON Schema, отформатированную через `JSON.stringify(schema, null, 2)`.
- Диагностика и ошибки выводятся в `stderr`; при ошибке команда завершает работу с ненулевым кодом.

## Определение схемы по пути

Команда определяет тип файла по нормализованному пути внутри YAML-проекта:

- `.../Формы/<имя формы>/Форма.yaml` возвращает схему клиентской формы.
- `<вид объекта>/<имя объекта>/Свойства.yaml` возвращает схему объекта metadata.
- Поддержанные виды metadata соответствуют уже доступным JSON Schema в core: справочники, документы, перечисления, обработки, журналы документов, HTTP-сервисы, регистры сведений, регистры накопления и планы обмена.

Если путь не соответствует поддержанному YAML-файлу, команда сообщает, какие шаблоны путей ожидаются.

## Архитектура

Логику выбора схемы нужно держать в core, чтобы CLI был тонкой оболочкой.
Новая чистая функция принимает путь к файлу, необязательный корень проекта и контекст конфигурации, затем возвращает `TSchema`.

CLI-команда отвечает только за:

- разбор аргументов `commander`;
- построение контекста по текущим значениям проекта (`defaultLanguage: "ru"`, `version: "2.20"`);
- печать схемы в `stdout`;
- преобразование ошибок в короткие сообщения для пользователя.

Для форм можно переиспользовать `exportClientApplicationFormToJSONSchema`.
На первом шаге схема формы строится от пустой формы, как в extension-кеше; чтение YAML-файла формы не требуется.

Для metadata-файлов нужно переиспользовать существующие функции экспорта JSON Schema.
Если часть поддержанных видов пока не экспортирована из публичного `@nakidka/core`, добавить точечные экспорты или общий helper в core вместо прямых глубоких импортов из CLI.

## Ошибки

Команда должна различать:

- файл не является `.yaml`;
- путь не похож на поддержанный файл проекта;
- вид metadata распознан, но схема для него пока не поддержана;
- `--project` задан, но файл находится вне этого проекта.

Тексты ошибок должны быть короткими и пригодными для вывода агенту.

## Тестирование

Тесты core:

- абсолютный и относительный путь к `Справочник/<имя>/Свойства.yaml` дают схему справочника;
- путь к `Документ/<имя>/Свойства.yaml` дает схему документа;
- путь к `.../Формы/<имя>/Форма.yaml` дает схему формы;
- неподдержанный путь дает понятную ошибку;
- путь вне `--project` отклоняется.

Тесты CLI:

- `schema <file>` печатает валидный JSON в `stdout`;
- при `--project <dir> <relative-file>` путь разрешается от проекта;
- ошибка печатается в `stderr`, а `stdout` остается пустым.

## Вне границ

- Генерация `.schema.json` рядом с YAML-файлом.
- Автоматическая привязка схем к редакторам.
- Расширение самих JSON Schema новыми полями.
- Чтение текущего содержимого YAML-файла.
