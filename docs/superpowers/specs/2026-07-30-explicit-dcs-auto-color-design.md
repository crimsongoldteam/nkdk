# Явное представление автоматического DCS-цвета

## Цель

Представлять XML-значение цвета `auto` в DCS-параметрах
`SettingsParameterValue` с `valueType: "Color"` явным YAML-значением
`Авто`.

```yaml
ЦветТекста: Авто
```

Пустое значение не поддерживается:

```yaml
ЦветТекста:
```

## Граница изменения

Изменение относится ко всем DCS-параметрам `SettingsParameterValue` с
`valueType: "Color"`. Обычные свойства метаданных типа `Color` и другие
значения `SettingsParameterValue` не меняются. Частных условий по пути
формы или имени прикладного объекта не добавляется.

## Преобразования

- XML `v8ui:Color` со значением `auto` преобразуется в YAML-скаляр
  `Авто`.
- YAML-скаляр `Авто` преобразуется в XML `v8ui:Color` со значением
  `auto`.
- Пустое YAML-значение цвета не преобразуется в `auto` и считается
  недопустимым по JSON Schema.
- Старый пустой формат намеренно не поддерживается.

## Реализация

Поведение остаётся внутри DCS-слоя:

- `parameterValue/toYAML.ts` выдаёт маркер `Авто`;
- `parameterValue/fromYAML.ts` распознаёт маркер и строит внутреннее
  значение автоматического цвета;
- JSON Schema для цветового `SettingsParameterValue` разрешает `Авто`
  и запрещает пустое значение;
- существующее преобразование цвета в XML записывает `auto`.

Общий конвейер YAML → XML и правила конкретных прикладных объектов не
получают специальных условий.

## Проверка

Тесты должны закрепить:

1. XML `auto` → YAML `Авто`.
2. YAML `Авто` → XML `auto`.
3. JSON Schema принимает `Авто`.
4. JSON Schema отклоняет пустое значение.
5. Round-trip проблемной формы больше не падает на `ЦветТекста`.

Существующие XML-фикстуры не изменяются.

## Несовместимость

Это намеренное несовместимое изменение YAML-договора. Проекты со старым
пустым представлением автоматического DCS-цвета нужно повторно
импортировать из XML либо заменить пустое значение на `Авто`.
