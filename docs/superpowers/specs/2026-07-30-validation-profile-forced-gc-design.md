# Принудительный GC в профиле валидации

## Цель

Добавить в диагностический runner `validation-profile` необязательный режим, который помогает обнаруживать рост удерживаемой памяти между последовательными валидациями одного YAML-проекта.

Режим не должен менять продуктовый код, обычный путь валидации, настройки воркеров или поведение runner без нового флага.

## Интерфейс

Новый флаг:

```text
--gc-between-runs
```

Пример запуска:

```bash
node --expose-gc .agents/skills/validation-profile/validation-profile.mjs /path/to/yaml --runs 20 --gc-between-runs
```

Если флаг указан без `--expose-gc`, runner завершается до загрузки compiled core с ошибкой, содержащей правильную команду запуска.

## Поведение

При включённом режиме runner после каждой завершённой валидации:

1. останавливает измерение времени прогона;
2. синхронно вызывает `global.gc()`;
3. снимает `rssMiB` и `heapUsedMiB`;
4. сохраняет результат прогона.

Таким образом, принудительный GC не входит в `elapsedMs`. Однако показатели скорости из этого диагностического режима не следует сравнивать с обычным benchmark: освобождение памяти между прогонами меняет состояние процесса.

Пиковый RSS продолжает измеряться существующим таймером. Он остаётся вспомогательным показателем; основной сигнал возможной утечки — устойчивый рост `heapUsedMiB` после принудительного GC.

Текстовый и JSON-вывод явно отмечают, что режим принудительного GC включён. Без флага формат и значения существующего вывода остаются прежними.

Дополнительный `--timing`-прогон остаётся отдельным дочерним процессом и не использует принудительный GC.

## Границы изменений

Изменяются только:

- `.agents/skills/validation-profile/validation-profile.mjs`;
- `.agents/skills/validation-profile/SKILL.md`;
- тесты диагностического runner.

Файлы `packages/*` не изменяются. В продуктовый процесс Node.js не добавляются `--expose-gc`, вызовы `global.gc()` или новые переменные окружения.

## Проверка

Тесты должны подтвердить:

- справка содержит новый флаг;
- запуск с флагом без `--expose-gc` завершается понятной ошибкой;
- при включённом режиме GC вызывается перед каждым снимком памяти;
- без флага GC не вызывается;
- обычный формат результата не получает отметку диагностического режима.

После реализации выполняются тесты runner и проверочный запуск его справки в обоих режимах Node.js.
