Design spec

Более достоверный round-trip-yaml через замену XML-каталога

HTML-версия делает видимой главную идею: результат `sync` сначала собирается отдельно, и только успешный экспорт заменяет активный XML-каталог. Так потерянные XML-файлы становятся удалениями в `git diff`.

Граница изменения Только runner round-trip-yaml и его документация
Текущий порядок

Что маскируется

nkdk sync пишет прямо поверх исходного XML-каталога. Если импорт в YAML потерял файл, старый XML-файл остается на месте, и `git diff` не показывает удаление.

XML -> YAML Часть XML может не попасть в YAML.
YAML -> тот же XML Старые XML-файлы не удаляются автоматически.
git diff Потеря файла может остаться невидимой.
Новый порядок

Что станет видно

nkdk sync сначала пишет во временный XML-каталог. Затем его содержимое полностью заменяет активный XML-каталог, поэтому отсутствующие файлы становятся удалениями.

XML -> YAML YAML остается доступен для диагностики.
YAML -> временный XML Исходный XML пока не тронут.
Замена активного XML Diff отражает и изменения, и удаления.

Полный поток одного каталога

Критичная защита: активный XML-каталог очищается только после успешного `sync` во временный каталог.

1. restore git restore . в XML-репо
2. import XML -> YAML
3. sync YAML -> tmp XML
4. diff замена XML и git diff

Каталоги

  • YAML остается в текущем месте: ${TMPDIR:-/tmp}/round-trip-yaml/<config> или NKDK_ROUND_TRIP_YAML_DIR.
  • Временный XML живет отдельно: ${TMPDIR:-/tmp}/round-trip-yaml-xml/<config>.
  • Временный XML очищается перед прогоном и не считается диагностическим результатом.

Совместимость вывода

  • ACTIVE_XML_DIR, YAML_DIR и SELECTED_XML_FILE_ABS остаются прежними.
  • single и triage не меняют интерфейс.
  • Пользователь по-прежнему анализирует diff в исходном XML-репо.

Поведение при ошибках

Падает import

Активный XML-каталог не меняется. Скрипт останавливается на стадии import.

Падает sync

Активный XML-каталог не меняется, потому что запись шла во временный XML-каталог.

Падает перенос

Скрипт останавливается. Это стадия применения диагностического результата к XML-репо.

Минимальная проверка реализации

1

bash -n .agents/skills/round-trip-yaml/round-trip.sh

2

Пробный запуск round-trip-yaml в обычном режиме на доступном XML-репо.

3

Проверить, что диагностические секции прежние, а потерянные файлы могут появиться как удаления в git diff.

Полный pnpm test не входит в эту проверку: skill является диагностическим и не должен запускать весь набор тестов.
