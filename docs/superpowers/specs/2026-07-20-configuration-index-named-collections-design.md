# Адресация именованных коллекций в файле индекса конфигурации

## Контекст

Новый импорт из XML строит файл индекса конфигурации. В индекс попадают идентификаторы объектов и вложенных элементов 1С, а также служебные XML-данные, необходимые для последующего восстановления XML при синхронизации.

При импорте ERP-выгрузки обнаружилась проблема: несколько вложенных XML-элементов одной коллекции записывают `uuid`, порядок и другие XML-данные в один и тот же `logicalAddress`. Например, `URLTemplate` и `Method` внутри HTTP-сервиса имеют разные `Name`, но сборщик индекса видит их на адресе владельца HTTP-сервиса и получает конфликты.

Это не ошибка XML-выгрузки. Это недостаток текущего договора между правилами коллекций и сборщиком файла индекса конфигурации.

## Цель

Сделать общий механизм, который позволяет адресовать именованные metadata-item коллекции в файле индекса конфигурации без частных условий в общих слоях.

Общие слои не должны знать про HTTP-сервисы, формы, папки 1С или конкретные `itemType`. Конкретные правила и регистрации должны декларативно сообщать только то, что нужно для построения стабильного адреса элемента коллекции.

## Решение

`registerMetadataItemCollectionRule` получает необязательное поле `configurationIndexUidSegment`.

Если поле задано, стандартный `fromXML` коллекции при импорте каждого элемента строит дочерний `logicalAddress`:

```text
<адрес владельца>.<configurationIndexUidSegment>.<имя элемента>
```

Имя элемента определяется существующей общей логикой:

1. `_name`, если он есть и не пустой.
2. XML-поле, описанное правилом свойства `name`, включая его `xmlParents`, например `Properties/Name`.
3. Алиасы XML-поля `name`, если они описаны в правиле.

Если `configurationIndexUidSegment` не задан, поведение остаётся прежним.

Если `configurationIndexUidSegment` задан, но имя элемента не найдено, стандартный импорт коллекции не создаёт индексный адрес по порядковому номеру. Для первой версии такая ситуация считается ошибкой настройки правил: коллекция объявлена адресуемой, но не имеет стабильного ключа.

## Пример

Регистрация коллекции шаблонов URL HTTP-сервиса:

```ts
registerMetadataItemCollectionRule({
  propertyType: "MetadataHTTPServiceURLTemplates",
  itemRule: MetadataHTTPServiceURLTemplateRules,
  xmlElement: "URLTemplate",
  keyField: "name",
  configurationIndexUidSegment: "ШаблонURL",
})
```

Регистрация коллекции методов HTTP-сервиса:

```ts
registerMetadataItemCollectionRule({
  propertyType: "MetadataHTTPServiceMethods",
  itemRule: MetadataHTTPServiceMethodRules,
  xmlElement: "Method",
  keyField: "name",
  configurationIndexUidSegment: "Метод",
})
```

Для файла `HTTPServices/exchange_dsl_1_0_0_1.xml` адреса будут различаться по именам элементов:

```text
HTTPСервис.exchange_dsl_1_0_0_1.ШаблонURL.Версия
HTTPСервис.exchange_dsl_1_0_0_1.ШаблонURL.Версия.Метод.get
```

В эти адреса записываются `uuid`, порядок XML-свойств, XML-алиасы и другие данные файла индекса конфигурации, относящиеся к конкретному XML-элементу.

## Границы первой версии

- Механизм покрывает только именованные metadata-item коллекции.
- Безымянные повторяющиеся XML-элементы не адресуются автоматически по порядковому номеру.
- Частные условия по `itemType`, XML-папкам, именам объектов 1С или структуре HTTP-сервисов в общие слои не добавляются.
- Родительскому свойству не нужно повторно объявлять сегмент, если его тип коллекции уже зарегистрирован с `configurationIndexUidSegment`.

## Обработка ошибок

Если коллекция зарегистрирована с `configurationIndexUidSegment`, но элемент XML не содержит имени, импорт должен завершить задание диагностикой настройки правил. Это лучше, чем silently записать данные элемента на адрес владельца и получить конфликт позже при обобщении фрагментов индекса.

Конфликты значений в одном `logicalAddress` после этой правки по-прежнему остаются ошибкой. Они означают либо реальное противоречие данных, либо неадресованную вложенную структуру, для которой нужно добавить декларативный договор.

## Тестирование

Нужны тесты на двух уровнях:

1. Общий тест `registerMetadataItemCollectionRule`: два XML-элемента одной коллекции с разными `Name` должны записывать `uuid` в разные `logicalAddress`.
2. Прикладной тест HTTPService: `URLTemplate` и вложенные `Method` из XML должны попадать в адреса с сегментами `ШаблонURL` и `Метод`, без конфликтов `uuid`.

Дополнительно нужен тест на ошибку настройки: если коллекция зарегистрирована с `configurationIndexUidSegment`, но имя элемента не найдено, импорт возвращает диагностическую ошибку.
