# Значения документа по умолчанию

## Цель

Привести правила `MetadataDocument` к значениям нового пустого документа,
созданного Конфигуратором, чтобы эти значения не попадали в YAML и точно
восстанавливались в XML без reference.

## Источник истины

Источником истины остаётся существующая XML-фикстура
`packages/core/metadata/appliedObjects/metadataDocument/__fixtures__/minimal.xml`.
Она совпадает со свойствами на предоставленных снимках и не изменяется.
История Git используется только для выяснения происхождения ошибки: она не
может подтвердить корректность значения по умолчанию.

## Изменение правил

В `MetadataDocumentRules` исправляются следующие договоры:

| Свойство модели | XML-default | Неявное значение YAML |
| --- | --- | --- |
| `numberLength` | `9` | `9` |
| `numberPeriodicity` | `Nonperiodical` | `Nonperiodical` |
| `checkUnique` | `true` | `true` |
| `posting` | `Allow` | `Allow` |
| `realTimePosting` | `Allow` | `Allow` |
| `registerRecordsDeletion` | `AutoDeleteOnUnpost` | `AutoDeleteOnUnpost` |
| `actionsWritingOnPost` | `WriteSelected` | `WriteSelected` |
| `privilegedPostingMode` | `true` | `true` |
| `privilegedUnpostingMode` | `true` | `true` |

Для `inputByString` значение зависит от имени документа. Правило вычисляет
модельное значение `Document.<Имя>.StandardAttribute.Number`, а неявным
значением YAML считает `["СтандартныйРеквизит.Номер"]`. Это позволяет получить
точный XML без добавления частного условия в общую orchestration.

Неиспользуемый `metadataDocument/defaults.ts` удаляется: файл нигде не
импортируется и создаёт второй, уже расходящийся источник значений.

## Проверка

Существующий случай `minimal.xml` становится регрессионной проверкой сразу на
двух направлениях:

- XML → YAML оставляет только явный пустой `Синоним`, исключая все значения
  пустого документа по умолчанию;
- YAML → XML восстанавливает исходную `minimal.xml` точно, включая вычисляемую
  ссылку стандартного реквизита `Number`.

Новый отдельный тест не создаётся: существующая параметризованная проверка
является самым узким стабильным уровнем и уже защищает оба наблюдаемых договора.

## Поиск других ошибочных defaults

Для каждого metadataItem следует брать минимальную XML-фикстуру, созданную в
той же поддерживаемой версии платформы, и сопоставлять каждое присутствующее
значение с `defaultValueXML` и `implicitValueYAML` соответствующего правила.
Затем пустой YAML должен без reference восстановить XML точно. Расхождение в
любом направлении показывает неверный или отсутствующий default; `git blame`
после этого отвечает только на вопросы «кто и когда», но не «правильно ли».
