# Сокращенные JSON Schema через внешние ссылки

## Цель

Сделать вывод `nkdk schema` пригодным для LLM: основной ответ должен показывать форму YAML-файла без разворота крупных повторяющихся составных объектов. Детали таких объектов агент запрашивает отдельно по ссылке.

## Команды

Основной режим становится сокращенным:

```bash
nkdk schema "<relative-yaml-file>" --project "<yaml-project-dir>"
```

Он возвращает JSON Schema с внешними `$ref` вида `nkdk://schema/<Name>`.

Получение подсхемы:

```bash
nkdk schema --ref "nkdk://schema/MetadataAttribute"
```

Этот вызов тоже возвращает сокращенную схему: простые поля раскрыты, а вложенные составные объекты снова представлены внешними `$ref`.

Полный разворот остается явным режимом для отладки и совместимости:

```bash
nkdk schema "<relative-yaml-file>" --project "<yaml-project-dir>" --inline
nkdk schema --ref "nkdk://schema/MetadataAttribute" --inline
```

## Форма сокращенной схемы

Составное поле заменяется контейнером со ссылкой на подсхему. Например, поле `Реквизиты`:

```json
{
  "Реквизиты": {
    "type": "object",
    "additionalProperties": {
      "$ref": "nkdk://schema/MetadataAttribute"
    }
  }
}
```

В каждый сокращенный ответ добавляется проектное поле `x-nkdk-schemaRefs` со списком ссылок, которые есть в этой схеме. Это подсказка для LLM, какие подсхемы можно запросить следующим вызовом.

## Определение ссылочных полей

Решение о выносе в подсхему принимается по `PropertyRule.type`, а не по названию YAML-поля. В `rules.ts` новые признаки не добавляются.

В core появляется отдельный реестр ссылочных схем рядом со слоем экспорта JSON Schema. Он сопоставляет тип свойства с формой контейнера и ссылкой:

```ts
MetadataCatalogAttributes -> record of nkdk://schema/MetadataAttribute
MetadataDocumentAttributes -> record of nkdk://schema/MetadataAttribute
FormAttributes -> record of nkdk://schema/FormAttribute
FormAttributeColumns -> record of nkdk://schema/FormAttributeColumn
FormCommands -> record of nkdk://schema/FormCommand
```

Если `PropertyRule.type` найден в реестре и экспорт идет в сокращенном режиме, экспортёр возвращает контейнер с `$ref`. Если типа нет в реестре, схема строится inline как сейчас.

На первом этапе в реестр попадают только крупные повторяемые составные части, полезные при создании YAML: реквизиты, табличные части, команды, реквизиты формы, колонки реквизитов формы, параметры и элементы формы.

## Элементы формы

Для `Элементы` нельзя использовать одну общую схему. Каждый вид элемента формы получает отдельную подсхему:

```json
{
  "Элементы": {
    "type": "object",
    "additionalProperties": {
      "oneOf": [
        { "$ref": "nkdk://schema/FormElement/InputField" },
        { "$ref": "nkdk://schema/FormElement/Table" },
        { "$ref": "nkdk://schema/FormElement/UsualGroup" }
      ]
    }
  }
}
```

Список допустимых ссылок зависит от типа контейнера и берется из уже существующей логики дерева элементов:

- `GroupChildItems` — элементы обычной группы или корня формы;
- `CommandBarChildItems` — элементы командной панели;
- `TableChildItems` — элементы таблицы;
- `PagesChildItems` — страницы.

Подсхема конкретного элемента строится из его `ElementRule` и содержит обязательный дискриминатор `Вид` с `const`, например `ПолеВвода`. Вложенные поля элемента, такие как его собственные `Элементы` или `Команда`, снова сокращаются через `$ref`.

## Архитектура

Экспорт JSON Schema получает режим:

- `externalRefs` — режим по умолчанию для CLI, возвращает внешние ссылки;
- `inline` — полный разворот, близкий к текущему поведению.

Реестр ссылочных схем отвечает за:

- выбор, какие `PropertyRule.type` заменяются ссылками;
- построение контейнера вокруг `$ref` (`record`, `oneOf`, одиночный объект);
- экспорт подсхемы по URI;
- сбор `x-nkdk-schemaRefs` для текущего ответа.

CLI остается тонким слоем: разбирает `schema <file>`, `--project`, `--ref` и `--inline`, вызывает core и печатает JSON в `stdout`.

## Ошибки

Если `--ref` указывает на неизвестный URI, команда завершает работу с ошибкой и сообщает, что известные ссылки можно увидеть в `x-nkdk-schemaRefs` сокращенной схемы.

Если пользователь передает `<file>` и `--ref` одновременно, команда сообщает, что нужно выбрать один источник схемы.

Ошибки определения схемы по пути остаются такими же короткими, как в текущей команде.

## Тестирование

Core:

- обычный экспорт схемы файла возвращает внешние `$ref` для ссылочных типов;
- `--inline`-экспорт сохраняет полный разворот;
- экспорт подсхемы по URI возвращает сокращенную схему и не разворачивает вложенные составные объекты;
- неизвестный URI дает понятную ошибку;
- `Элементы` возвращают `oneOf` ссылок только на разрешенные виды элементов для текущего контейнера;
- подсхема элемента формы содержит `Вид` с корректным `const`.

CLI:

- `schema <file> --project <dir>` печатает сокращенную схему;
- `schema --ref <uri>` печатает сокращенную подсхему;
- `schema <file> --inline` печатает полную схему;
- `schema --ref <uri> --inline` печатает полную подсхему;
- одновременные `<file>` и `--ref` отклоняются.

Инструкции агента:

- `config-add-item` документирует дозапрос `$ref` через `nkdk schema --ref`.

## Вне границ

- Генерация отдельных `.schema.json` файлов на диск.
- Загрузка `nkdk://schema/...` валидатором без участия CLI.
- Переписывание `rules.ts` ради настроек JSON Schema.
- Полное покрытие всех мелких общих объектов отдельными подсхемами на первом этапе.
