# E2E-проверки импорта, validation и YAML round-trip

## Контекст

Текущий набор `pnpm test` содержит проверки, которые называют модульными, но
которые поднимают реальные worker, работают с файловой системой и выполняют
полные операции импорта или экспорта на небольших искусственных фикстурах.
Такие проверки замедляют быстрый контур и частично повторяют один и тот же
дорогой путь.

Для сквозной проверки доступны компактные XML-каталоги:

- основная конфигурация `cf/all`;
- расширение `cfe/all-extension` с именем `Расширение_All`;
- расширение `cfe/control` с именем `РасширениеКонтроль`;
- расширение `cfe/default` с именем `РасширениеПоУмолчанию`.

Каталоги вместе занимают около 10 МБ и содержат около 1 400 файлов. Они
достаточно малы для отдельного обязательного задания CI и достаточно
представительны, чтобы заменить дублирующие полные прогоны на искусственных
наборах.

## Цели

- добавить воспроизводимый сквозной контур для реальных `cf` и `cfe`;
- проверить импорт, validation и полный XML → YAML → XML;
- проверять как инкрементальную validation относительно `.nkdk`, так и холодную
  validation без `.nkdk`;
- требовать побайтового восстановления XML;
- отделить медленный контур от обычного `pnpm test`;
- создать основание для последующего удаления только тех медленных тестов,
  договоры которых доказанно перекрыты.

## Не входит в границы

- массовое удаление существующих тестов в той же задаче;
- повторный полный прогон конфигурации через MCP-протокол;
- снимок всего сгенерированного YAML-проекта;
- изменение исходных XML-фикстур во время теста;
- ослабление побайтового договора до семантического равенства.

## Размещение

Версионируемые исходные данные размещаются отдельно от локальных фикстур
пакетов:

```text
e2e/
  fixtures/xml/
    cf/
    cfe/
      all-extension/
      control/
      default/
  metadata-project.test.ts
```

В `e2e/fixtures/xml` копируется обычное содержимое указанных каталогов. Файлы
`.DS_Store` и другие посторонние служебные файлы не копируются. После добавления
фикстуры считаются неизменяемым источником истины.

E2E-набор не входит в шаблоны обычного Vitest-запуска пакетов. Корневая команда
`pnpm test:e2e` запускает его отдельно и последовательно.

## Точка входа

Metadata-e2e вызывают публичный API `@nkdk/core`. Это проверяет настоящие
worker, файловую систему, состав metadata и общую композицию, но не смешивает
неисправность metadata-конвейера с упаковкой или MCP-транспортом.

MCP остаётся защищён существующими тестами сервисов и `smoke:packed`. Большой
XML-набор не прогоняется через MCP повторно: такой прогон не добавляет нового
metadata-договора и затрудняет определение причины сбоя.

## Подготовка данных

Одна общая подготовка создаёт временный эталонный NKDK-проект:

1. импортирует `fixtures/xml/cf` в компонент `cf`;
2. последовательно импортирует три каталога `fixtures/xml/cfe` в тот же корень;
3. проверяет отсутствие ошибок каждого импорта;
4. проверяет определённые core пути `cf`, `cfe/Расширение_All`,
   `cfe/РасширениеКонтроль` и `cfe/РасширениеПоУмолчанию`;
5. проверяет наличие созданных YAML-компонентов и состояния `.nkdk`.

Подготовленный проект после импорта не изменяется. Каждая последующая проверка
получает отдельную копию, поэтому validation и экспорт не зависят от порядка и
не загрязняют состояние друг друга. Дорогой импорт при этом выполняется один
раз за запуск.

Если общая подготовка не завершилась, набор сообщает об ошибке импорта как об
ошибке предусловия, а не создаёт несколько ложных расхождений последующих фаз.

## Сценарии

### Импорт конфигурации и расширений

Первый сценарий защищает публичный договор полного импорта реальными worker:

- все четыре компонента успешно импортированы;
- каждый компонент определён по содержимому `Configuration.xml`;
- результат не содержит ошибок;
- ожидаемые YAML-каталоги и `.nkdk` созданы.

Полный снимок YAML не хранится. Его изменение само по себе не является ошибкой,
если проект проходит validation и побайтово восстанавливает исходный XML.

### Validation полного проекта

Проверка использует отдельную копию импортированного проекта:

1. неизменённый проект проходит validation без ошибок;
2. в корень `cf/Конфигурация.yaml` добавляется неизвестное свойство
   `НеизвестноеПолеE2E: true`, чтобы создать стабильную ошибку схемы;
3. validation при существующем `.nkdk` обнаруживает ошибку по изменению;
4. каталог `.nkdk` удаляется только из временной копии;
5. холодная validation заново строит состояние и возвращает ту же диагностику.

Сравниваются существенные поля диагностики: компонентный путь, источник,
позиция или YAML-путь и сообщение. Инкрементальный и холодный режимы должны быть
эквивалентны для наблюдаемой ошибки.

### Полный YAML round-trip

Каждый компонент из отдельной копии импортированного проекта экспортируется в
свой временный XML-каталог. Для каждого компонента сравниваются:

- полный отсортированный список относительных путей;
- отсутствие лишних и пропавших файлов;
- байты каждого файла без преобразования переводов строк, кодировки или XML.

Любое расхождение является ошибкой. Отдельный тест экспорта не нужен: экспорт
уже является второй половиной полного XML → YAML → XML.

## Диагностика расхождений

При несовпадении round-trip создаётся отчёт в `reports/e2e/`:

- перечень добавленных, удалённых и изменённых файлов;
- обычный diff исходного и полученного содержимого;
- дополнительный нормализованный diff, который помогает отличить
  форматирование XML от смыслового расхождения.

Нормализованный diff служит только объяснением. Он не меняет результат строгой
побайтовой проверки. CI сохраняет каталог отчёта как результат задания, а
локальный запуск печатает его путь.

## Изоляция и очистка

Все изменяемые данные создаются во временном каталоге. Исходные фикстуры не
передаются production-коду как цель записи. Временные каталоги удаляются после
успешного запуска; при падении сохраняются только компактные отчёты, а не полные
копии проекта и XML.

Worker pool и project state закрываются в `finally`, чтобы падение одной фазы не
оставляло процессы и дескрипторы.

## Команды и CI

`pnpm test` остаётся быстрым контуром пакетов. `pnpm test:e2e` запускается
отдельным обязательным заданием `e2e` в PR CI после установки зависимостей.

К E2E не применяется существующий предел одной секунды на test file. Задание
получает общий предел 10 минут и выводит длительность подготовки, validation и
экспорта по фазам. Начальная реализация запускается одним процессом без
разделения на параллельные части; распараллеливание возможно только после
измерений и без повторного импорта.

## Последующее сокращение медленных тестов

Удаление существующих проверок выполняется отдельным этапом после появления
стабильно зелёного E2E и профиля трёх последовательных запусков.

Для каждого кандидата составляется таблица:

| Существующий тест | Уникальный наблюдаемый договор | Оставшаяся защита | Решение |
| --- | --- | --- | --- |
| путь и имя теста | что именно может сломаться | точный e2e или узкий тест | оставить, объединить или удалить |

Удалять можно полный импорт, экспорт или validation с реальными worker, если
все его наблюдаемые договоры покрыты новым E2E либо отдельной более узкой
проверкой. Само время выполнения не является достаточным основанием.

Сохраняются:

- проверки rules и чистых преобразований;
- ошибки, отмена, освобождение ресурсов и жизненный цикл worker;
- координаторы с подменёнными зависимостями и проверки редких ветвей отказа;
- архитектурные, snapshot- и связанные с issue регрессионные тесты;
- любой договор, для которого нельзя назвать точную оставшуюся защиту.

После сокращения сравниваются медианы трёх профилей `pnpm test:profile`, а также
повторно выполняются `pnpm test` и `pnpm test:e2e`.

## Критерии готовности

- фикстуры `cf` и всех трёх `cfe` находятся в репозитории без посторонних файлов;
- `pnpm test:e2e` воспроизводимо проходит локально и в отдельном задании CI;
- чистый проект проходит validation;
- одна ошибка одинаково обнаруживается по diff и без `.nkdk`;
- XML после YAML round-trip совпадает с источником по путям и байтам;
- при намеренном расхождении сохраняются обычный и нормализованный diff;
- обычный `pnpm test` не запускает E2E;
- удаление прежних медленных тестов отложено до отдельного аудита покрытия.
