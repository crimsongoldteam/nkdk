# Языковые аномалии локализованных XML-строк

## Контекст

Локализованная строка 1С хранится в XML как упорядоченная коллекция
`v8:item`, где каждый элемент содержит пару `v8:lang` и `v8:content`.
Объекты `Language` конфигурации задают зарегистрированные коды и их порядок,
но XML может содержать текст для кода, которому объект `Language` не
соответствует.

Документация 1С подтверждает, что локализованные строки связываются с языком по
коду. После изменения или удаления кода старые пары остаются в строках и
становятся недоступными через обычный редактор, но не перестают быть допустимым
XML: <https://its.1c.ru/db/content/metod8dev/src/developers/platform/metod/devtools/i8102288.htm>.

Проверка 35 конфигураций из `/Users/nikita/git/round-trip-compact/cf`, кроме
`all`, показала:

- 29 конфигураций содержат незарегистрированные языковые коды;
- найдено 4 796 языковых элементов с такими кодами;
- в Storekeeper зарегистрирован только `ru`, но присутствует 61 элемент `en`;
- три локализованные строки в двух конфигурациях нарушают порядок двух
  зарегистрированных языков: две в SMTL и одна в ERP.

Дополнительно обнаружен 121 элемент с кодом `#` и 70 элементов с пустым кодом.
Они не классифицировались как языковые коды в этом исследовании и исключены из
приведённых выше 29 конфигураций и 4 796 элементов.

Импорт не должен удалять или молча нормализовывать эти состояния. YAML должен
сохранять их явно и классифицировать причину.

## Термины

**Зарегистрированный язык** — код `LanguageCode` объекта `Language`,
перечисленного в `Configuration.xml`.

**Реестр языков** — обязательное для импорта и валидации неизменяемое значение
с кодом основного языка и множеством кодов зарегистрированных языков
конфигурации.

**Канонический порядок XML** конкретной локализованной строки — присутствующий
среди `v8:item` основной язык первым, затем все остальные присутствующие коды по
возрастанию кода без зависимости от системной локали. Регистрация кода на его
место в порядке не влияет.

**Канонический порядок YAML** без `!xml/order` — пустой маркер отсутствующего
основного языка первым, если он нужен для запрета свёртки, затем явно записанные
коды по возрастанию. Пустой маркер не входит в последовательность создаваемых
`v8:item`.

**Сворачиваемое значение** — значение свойства с
`excludeIfEqualNameYAML: true`, текст основного языка которого однозначно
восстанавливается из имени через `canConvertToPascalCase` и
`splitPascalCase`.

## Новые категории `!xml`

Эта спецификация расширяет закрытый словарь из
[`2026-08-14-classified-xml-anomaly-tags-design.md`](2026-08-14-classified-xml-anomaly-tags-design.md).
До реализации `!xml/language` и `!xml/order` остаются неизвестными тегами и
должны отклоняться текущим парсером.

### `!xml/language`

Тег ставится на scalar-значение конкретного языка, если его непустой код,
отличный от служебного `#`, отсутствует среди зарегистрированных языков
конфигурации:

```yaml
Заголовок:
  en: !xml/language Buttons
```

Код языка остаётся YAML-ключом, payload тега содержит исходный текст. Тег не
означает ошибку XML: он классифицирует сохранённый текст, недоступный через
текущий набор объектов `Language`.

### `!xml/order`

Тег ставится на mapping всей локализованной строки, если порядок языков в XML
отличается от канонического:

```yaml
Заголовок: !xml/order
  en: Other text
  ru: Другой текст
```

Тег относится к коллекции, а не к отдельному тексту. Порядок ключей mapping
становится исходным порядком `v8:item`. Это первое согласованное применение
классифицированного XML-тега к mapping; scalar-механизм недостаточен, потому
что нарушение относится к взаимному расположению элементов.

`!xml/language` и `!xml/order` независимы и могут применяться одновременно:

```yaml
Заголовок: !xml/order
  en: !xml/language Dont exit
  ru: Не выходить
```

При `!xml/order` свёртка полностью запрещена. Каждый присутствующий в XML текст,
включая совпадающий с вычисляемым текстом основного языка, остаётся явным
YAML-полем. Отсутствующий основной язык не восстанавливается из имени.

## Пустая строка языка

Для сворачиваемого свойства пустая строка основного языка означает, что
соответствующего `v8:item` в XML нет и вычисляемое значение восстанавливать не
нужно:

```yaml
Заголовок:
  ru: ""
  en: !xml/language Buttons
```

У свойства без сворачивания отсутствующий язык не появляется в YAML. Пустая
строка языка для такого свойства не используется как маркер отсутствия и
отклоняется validation. Настоящий пустой `v8:content` в исследованном корпусе,
кроме `all`, не найден; отдельное представление для него в этой спецификации не
вводится.

Если пустой маркер основного языка присутствует в обычном mapping без
`!xml/order`, он записывается первым. Остальные поля следуют по каноническому
порядку. При `!xml/order` свёртка уже запрещена, поэтому маркер отсутствующего
основного языка не требуется и считается избыточным.

## Архитектурные границы

`ConfigurationContext` заменяет отдельный `defaultLanguage` единым обязательным
реестром:

```ts
languages: {
  default: "ru",
  registered: ["ru", "en"],
} as const
```

XML-импорт строит реестр до первого прохода: читает `DefaultLanguage` и
последовательность `Language` из `Configuration.xml`, затем `LanguageCode` из
соответствующих `Languages/*.xml`. Проектная валидация до полной проверки файлов
читает `ОсновнойЯзык` конфигурации и `КодЯзыка` объектов `Язык`. После этого все
воркеры операции получают одно неизменяемое значение. Невозможность построить
полный реестр останавливает импорт или полную проектную валидацию до обработки
локализованных строк.

Полный реестр требует, чтобы основной язык разрешался ровно в один объект
`Language`, его код входил в `registered`, а все зарегистрированные
`LanguageCode` были непустыми и уникальными. Нарушение любого инварианта —
ошибка построения реестра.

Предварительное чтение извлекает только ссылки и коды, необходимые для реестра;
оно не заменяет последующую обычную проверку этих YAML- или XML-объектов.
Базовые типы `PropertyRule` новых полей не получают.

Runtime YAML расширяет существующий sidecar классифицированных тегов поддержкой
mapping-тега. Runtime знает только категорию и YAML-узел; он не знает о языках,
`I8nText`, `Language` или каноническом порядке. При копировании mapping sidecar
переносится так же, как уже переносится scalar sidecar.

Классификация языков и порядка остаётся в concrete-модуле локализованных
текстов. Нейтральные слои validation и projectState только переносят реестр и
не получают частных условий по `Language` или YAML-ключам языков.

## Импорт XML → YAML

Импорт получает обязательный реестр языков из контекста операции. Для каждой
локализованной строки он:

1. сохраняет порядок `v8:item`;
2. помечает текст каждого незарегистрированного кода тегом
   `!xml/language`;
3. сравнивает последовательность с каноническим порядком и помечает mapping
   тегом `!xml/order` при расхождении;
4. полностью запрещает сворачивание при `!xml/order`, а при каноническом
   порядке применяет обычное сворачивание основного языка;
5. при каноническом порядке записывает основной язык первым как `""`, если он
   отсутствовал в XML, но без маркера был бы восстановлен из имени; при
   `!xml/order` маркер не добавляет, поскольку свёртка уже запрещена.

## Экспорт YAML → XML

Экспорт:

1. принимает `!xml/language` только у кода, отсутствующего среди объектов
   `Language`;
2. принимает `!xml/order` только у mapping, последовательность явно записанных
   непустых значений которого отличается от канонического порядка XML;
3. без `!xml/order` читает YAML-поля в каноническом порядке, пропускает пустые
   маркеры и создаёт оставшиеся `v8:item` в каноническом порядке;
4. с `!xml/order` сохраняет порядок mapping и не восстанавливает основной язык
   из имени;
5. не создаёт `v8:item` для пустой строки языка;
6. без `!xml/order` восстанавливает свёрнутый основной текст из имени только
   при отсутствии запрещающего значения `""`.

## Validation и JSON Schema

- Незарегистрированный код без `!xml/language` — ошибка с путём до значения
  языка.
- `!xml/language` у зарегистрированного кода — избыточный тег и ошибка.
- Неканонический порядок без `!xml/order` — ошибка на mapping локализованной
  строки.
- Для проверки обычного сворачиваемого mapping отсутствующий ключ основного
  языка сначала восстанавливается как вычисляемый; пустой маркер запрещает это
  восстановление. Полученная последовательность `v8:item` сравнивается с
  каноническим порядком XML.
- `!xml/order` при каноническом порядке — избыточный тег и ошибка.
- При `!xml/order` свёртка запрещена: присутствующий основной текст обязан быть
  записан явно, а отсутствующий не выводится из имени.
- Пустой маркер основного языка при `!xml/order` избыточен и является ошибкой.
- Пустой маркер отсутствующего основного языка в обычном mapping обязан стоять
  первым. Его положение проверяется как каноническая форма YAML, но сам маркер
  исключается из последовательности создаваемых `v8:item`.
- Неканоническое положение пустого маркера — обычная ошибка формы YAML; тег
  `!xml/order` её не исправляет.
- Пустое значение языка у свойства без сворачивания отклоняется: представление
  настоящего пустого `v8:content` этим договором не определено.
- Оба тега проверяются независимо, поэтому одна строка может получить две
  диагностики.
- `!xml/order` разрешён только на mapping, `!xml/language` — только на scalar
  текста языка.
- JSON Schema описывает допустимые формы scalar- и mapping-тегов, но не
  проверяет порядок ключей объекта: стандартная семантика JSON Schema порядок
  не сохраняет.
- Фактическую регистрацию кода, избыточность тегов и порядок проверяет
  проектный validation-проход по разобранному YAML с sidecar и insertion order.
- Общая schema типа `I8nText` не определяет зарегистрированные коды без
  контекста проекта.
- Отсутствие реестра языков — ошибка операции, а не режим без языковых
  диагностик.

## Границы

- Теги применяются к `I8nText` и текстовой части `FormattedI8nText`.
- XML-фикстуры не изменяются.
- Незарегистрированный язык не удаляется и не преобразуется в
  зарегистрированный.
- Порядок языков не хранится в reference XML или `configuration-index.bin`:
  его полностью выражает YAML mapping и `!xml/order`.
- Локализованная строка, содержащая служебный `v8:lang` со значением `#` или
  пустой `v8:lang`, целиком исключается из классификации языка и порядка этой
  спецификацией. Эти два случая исследуются отдельно.
- Новое представление настоящего пустого `v8:content` не входит в задачу.
- Другие категории `!xml` эта спецификация не меняет.
- Согласованное правило порядка и обязательность реестра языков после
  реализации фиксируются также в `.agents/restrictions.md`, поскольку исходный
  XML хранит порядок `v8:item`, а его молчаливая нормализация нарушает
  round-trip.

## Проверки

Нужны точечные тесты:

- XML → YAML и YAML → XML для каждой строки матрицы;
- сочетание `!xml/order` и `!xml/language`;
- разбор, сериализация и копирование mapping-sidecar `!xml/order`;
- сворачиваемый основной язык: присутствует, отсутствует и расположен после
  другого языка;
- основной язык отсутствует: пустой маркер стоит первым перед
  зарегистрированным и незарегистрированным языком;
- у свойства без сворачивания отсутствующий основной язык не создаёт YAML-поля,
  а пустое значение отклоняется;
- запрет свёртки при `!xml/order`, включая явный вычисляемый текст основного
  языка;
- построение обязательного реестра до XML-импорта и полной проектной
  валидации, а также отказ операции при неполном реестре;
- зарегистрированный и незарегистрированный код с правильным и избыточным
  тегом;
- участие незарегистрированного кода в каноническом порядке;
- канонический и неканонический порядок с правильным и избыточным тегом;
- JSON Schema допустимых форм тегов и проектный validation с реестром языков;
- отсутствие проверки порядка обычным JSON Schema object;
- ошибка операции при отсутствии реестра языков;
- исключение всей строки со служебным `#` или пустым `v8:lang` из языковой
  классификации;
- round-trip Storekeeper, SMTL и ERP на исследованных примерах.

Перед завершением реализации выполняются `pnpm test`, `pnpm test:e2e`,
архитектурные проверки и `pnpm duplicates -- --base <commit>` согласно
проектным инструкциям.
