# Единый YAML-формат форм

## Контекст

Сейчас клиентская форма хранится в двух проектных файлах:

- `Форма.yaml` — свойства формы, реквизиты, команды, параметры и partial-свойства элементов;
- `Форма.nkdk` — визуальное дерево формы, командные панели и краткое представление элементов.

Такой раскол появился, чтобы человек мог глазами представить будущую форму. Целевой способ работы меняется: форму в основном меняет агент, человек проверяет результат в 1С и при необходимости правит форму в конфигураторе. После ручной правки `import` возвращает состояние обратно в YAML.

Совместимость со старым `Форма.nkdk` не является целью: проект находится на ранней стадии, поэтому формат можно упростить радикально.

## Решение

`Форма.yaml` становится единственным проектным источником формы. `Форма.nkdk` и язык NKDK удаляются полностью из `import`, `sync`, graph/watch и расширения.

Визуальное дерево хранится прямо в `Форма.yaml` как вложенный словарь:

- имя элемента — YAML-ключ;
- `Вид` — обязательный русский тип элемента, близкий к терминам 1С;
- свойства элемента лежат в том же узле;
- дочерние элементы лежат в ключе `Элементы`;
- порядок элементов определяется физическим порядком YAML-ключей;
- `ПутьКДанным` всегда пишется явно, без сокращений.

`КоманднаяПанель` у формы, таблицы и других владельцев командной панели остаётся отдельным свойством владельца. Внутри неё команды и группы описываются тем же паттерном через `Элементы`.

Пример целевого YAML:

```yaml
Реквизиты:
  Товар:
    Тип: СправочникСсылка.Товары
  Количество:
    Тип: Число

КоманднаяПанель:
  АвтоЗаполнение: Истина
  Элементы:
    Записать:
      Вид: Кнопка
      Команда: Записать
    Провести:
      Вид: Кнопка
      Команда: Провести

Элементы:
  Основное:
    Вид: ОбычнаяГруппа
    Заголовок: Основное
    Ориентация: Вертикальная
    Элементы:
      Товар:
        Вид: ПолеВвода
        ПутьКДанным: Объект.Товар
      Количество:
        Вид: ПолеВвода
        ПутьКДанным: Объект.Количество
      Товары:
        Вид: Таблица
        ПутьКДанным: Объект.Товары
        КоманднаяПанель:
          АвтоЗаполнение: Истина
          Элементы:
            Добавить:
              Вид: Кнопка
              Команда: ТоварыДобавить
        Элементы:
          Номенклатура:
            Вид: ПолеВвода
            ПутьКДанным: Объект.Товары.Номенклатура
```

## Архитектура

### Синхронизация формы в XML

`syncFormToXML` читает только `Форма.yaml`. Вместо слияния `Форма.yaml` с моделью, разобранной из `Форма.nkdk`, YAML импортируется сразу в полную модель `ClientApplicationForm`.

Из `syncFormToXML` удаляются:

- чтение `Форма.nkdk`;
- парсинг через `nkdk-language`;
- `parseNKDK`;
- `importClientApplicationFromFromNKDK`;
- логика пустой формы как fallback для отсутствующего NKDK.

### Импорт формы из XML

`convertFormFromXML` пишет только `Форма.yaml`. Экспорт модели в NKDK и запись `Форма.nkdk` удаляются.

Если XML содержит элемент или свойство, которые нельзя выразить новым YAML-контрактом, импорт падает с понятной ошибкой. Сырые блоки для неподдержанных элементов не сохраняются.

### YAML элементов

Текущий partial-подход исчезает: `Элементы` больше не является отдельным плоским словарём свойств, который накладывается на дерево из NKDK. Он хранит и структуру, и свойства элементов.

Нужен единый сериализатор/импортёр дерева элементов для:

- `GroupChildItems`;
- `TableChildItems`;
- `CommandBarChildItems`;
- `PagesChildItems`;
- `AutoCommandBar` и других владельцев командной панели.

Каждый узел должен импортироваться через `Вид`, затем через существующие правила свойств элемента. Имя элемента берётся из YAML-ключа.

### Graph/watch

Форма становится однофайловым graph source:

- `Форма.yaml` владеет корнем `ClientApplicationForm`;
- `Форма.yaml` владеет визуальными элементами, командными панелями и связями формы;
- `Форма.nkdk` больше не поддерживается как проектный файл;
- `pairedText`, `pairedProjectGraphFile` и tombstone-логика для удаления `Форма.nkdk` удаляются.

Изменение `Форма.yaml` пересобирает весь сегмент формы. Удаление `Форма.yaml` удаляет форму и все её узлы.

### Удаление NKDK-пакета

Пакет `packages/language` удаляется из workspace. Вместе с ним удаляются:

- `nkdk-language` alias в core/cli/extension;
- NKDK-грамматика и generated-файлы;
- тесты языка;
- `fromNKDK`/`toNKDK` модули и тесты;
- требование запускать `pnpm --filter nkdk-language langium:generate` в свежем worktree.

## Валидация

Импорт YAML должен падать с ошибкой, если:

- у элемента нет `Вид`;
- `Вид` неизвестен;
- ключ `Элементы` имеет не словарную форму;
- `КоманднаяПанель` имеет неверную форму;
- в одном контейнере повторяется имя элемента;
- свойство элемента не соответствует правилам этого `Вид`.

Повторы имён между разными контейнерами допустимы только если модель формы уже допускает такую область видимости. Если текущая модель требует глобальную уникальность, валидация должна сохранять глобальное требование.

Проверка повторов ключей должна выполняться на уровне YAML-парсера или AST до преобразования в обычный JS-объект, потому что после такого преобразования повторный ключ уже потерян.

## Тестирование

Обновить и добавить покрытие:

- `convertFormFromXML` пишет один `Форма.yaml` с вложенным деревом и без `Форма.nkdk`;
- `syncFormToXML` читает один `Форма.yaml` и восстанавливает XML формы;
- round-trip формы `XML -> YAML -> XML` сохраняет порядок элементов и командных панелей;
- YAML import/export элементов покрывает группу, страницу, таблицу, командную панель, кнопку и поле ввода;
- graph discovery видит только `Форма.yaml`;
- `updateGraph` и `watch` не читают и не отслеживают `Форма.nkdk`;
- удаление `Форма.yaml` удаляет весь сегмент формы;
- неизвестный `Вид` и некорректная форма `Элементы` дают понятные ошибки;
- workspace больше не содержит `nkdk-language`, а полный `pnpm test` проходит без Langium-генерации.

## Границы

В задачу входит удаление NKDK как проектного формата и переход форм на единый YAML.

В задачу не входит:

- HTML-предпросмотр формы;
- автоматическая миграция старых `Форма.nkdk`;
- сохранение неподдержанных элементов сырыми блоками;
- ручный редактор YAML для человека;
- изменение XML-фикстур как источника истины.
