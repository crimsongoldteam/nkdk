# Извлечение записи и обратимое разделение коллекции

Продолжение общего выбора: `select` возвращает единственную подходящую запись,
чтобы обычное выражение `match` могло прочитать её поле.

```yaml
match:
  value:
    select:
      in: {field: rows}
      as: item
      where: {eq: [{get: {of: {var: item}, field: name}}, {literal: Second}]}
  present:
    as: selected
    then: {get: {of: {var: selected}, field: mode}}
  absent: {literal: missing}
```

Полный проверочный пример —
[`selected-record-row.yaml`](../../../rust/crates/rule-compiler/tests/fixtures/selected-record-row.yaml).

Нулевое число совпадений и неоднозначность дают отсутствие выбранного значения;
произвольного выбора первого дубля нет. Исходные строки остаются в коллекции.
`exists` позволяет отличить отсутствие совпадений от неоднозначности, если это
нужно нормальному договору. Само чтение значения не регистрирует аномалию и
не заменяет окончательный договор обратного преобразования.

Переменная выбранной записи доступна только внутри `present`; её поля проверяются
по объявленному типу. Во время выполнения используется ссылка на хранилище,
без копии записи или повторного разбора форматов. Общий доступ поддерживает
текст, boolean, точные числа и перечисления; он учитывает смысловой тип после
связывания импортов. Первый исполняемый вариант
работает с заимствованными коллекциями объявленных записей. Иные представления
должны получить тот же договор, а не частные обработчики предметных объектов.

## Передача владения и обратная сборка

Ядро отдельно поддерживает перемещение единственного вхождения из исходного
вектора. Сохраняются выбранное значение, его позиция и упорядоченный остаток.
Обратная сборка вставляет значение на прежнее место. `Clone` не требуется,
буфер вектора и данные строк не копируются. Для извлечения и вставки требуется
линейное перемещение элементов вектора; обещание постоянного времени не даётся.

Неоднозначный выбор или недопустимый индекс возвращают исходный вектор целиком.
Длина остатка закрыта от изменения, поэтому восстановление не может потерять
позицию. Значения выбранной записи и соседних записей можно изменять отдельно.

Это две подготовленные границы: заимствованное чтение подключено к выражениям,
а передача владения и сборка проверены в ядре. Их соединение с таблицей состояний,
сокращённым YAML и сохранением аномалий общей коллекции `PropertyState` остаётся
условием полной приёмки. Пример не разрешает скрывать неперенесённые нормальные
строки за raw.

## Коллекция без отдельного ключа YAML

Поле коллекции может иметь XML-путь и отсутствовать в `yaml.fields`, как любое
другое восстанавливаемое поле. Для него обязательно обычное правило
`presence` с `yaml.missing.denotes`; оно создаёт записи через `sequence`/`record`.
Новых параметров языка для этого не требуется.

Сгенерированный код не пишет пустой служебный ключ и не ожидает коллекцию при
чтении YAML. Выражение восстановления использует уже прочитанные поля владельца.
Проверочный пример связывает выбранный `mode` с полем `Found`: XML → `Found`
и `Found` → конструктор записи. Другой пример восстанавливает фиксированную
запись из пустого YAML.

Это применимо только к данным, полностью восстанавливаемым объявленным правилом.
Оно не позволяет скрыть произвольный остаток общей коллекции: для `PropertyState`
соседние нормальные строки всё ещё требуют отдельного обратимого распределения.
Отклонение формы, например неизвестный XML-атрибут, сохраняется существующим
механизмом аномалий; скрытое поле не должно мешать прочитать такое сохранение.
