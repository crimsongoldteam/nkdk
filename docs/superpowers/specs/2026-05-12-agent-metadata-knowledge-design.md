# Дизайн: обязательная база знаний для metadata-агентов

## Цель

Разделить два разных слоя агентских инструкций:

- устойчивые правила и инварианты работы с `packages/core/metadata/**`;
- запускаемые сценарии (`skills`), которые ведут агента через конкретную задачу.

Текущие `new-metadata-item` и `new-applied-object` фактически содержат оба слоя сразу. Из-за этого они работают как стандарты, но доступны агенту только когда явно срабатывает skill. Новая структура должна сделать базовые правила обязательными для любой работы с metadata, включая починку существующих объектов без запуска `new-*` skill.

## Архитектура

Вводится каталог `.agents/knowledge/metadata/`.

Главная точка входа:

```text
.agents/knowledge/metadata/INDEX.md
```

`INDEX.md` должен быть коротким маршрутизатором. Он не дублирует все правила, а говорит, какие документы читать в зависимости от задачи и изменяемых файлов.

Рекомендуемые документы первого уровня:

```text
.agents/knowledge/metadata/
  INDEX.md
  sources-of-truth.md
  object-research.md
  metadata-item-implementation.md
  round-trip-cycle.md
  yaml-contract.md
  registries.md
```

Существующие `.agents/skills/_shared/metadata/*.md` на первом шаге остаются на месте и подключаются из `INDEX.md` как временные источники. Затем их содержимое переносится в `knowledge` по одному документу. Долгосрочно устойчивые нормы живут в `knowledge`, а `_shared` остаётся только для шаблонов и вспомогательных фрагментов, если они действительно нужны skills.

## Обязательная Точка Входа

В `AGENTS.md` добавляется правило:

> Перед изменениями в `packages/core/metadata/**` обязательно прочитай `.agents/knowledge/metadata/INDEX.md` и следуй указанным там документам для текущей задачи.

Это правило широкое по пути, но дешёвое по контексту: агент всегда читает только короткий индекс, а подробные документы открывает выборочно.

## Роль Skills

Skills становятся тонкими сценариями:

- `new-applied-object` описывает порядок исследования нового прикладного объекта и ссылается на `knowledge/metadata/object-research.md`;
- `new-metadata-item` описывает цикл реализации и ссылается на `metadata-item-implementation.md`, `round-trip-cycle.md`, `yaml-contract.md`, `registries.md`;
- `round-trip-xml` остаётся диагностическим сценарием и ссылается на `round-trip-cycle.md` и правила фикстур.

Внутри skills не должно оставаться крупных стандартов, которые обязаны действовать вне этого skill. Если правило нужно при любой metadata-работе, оно живёт в `knowledge`.

## Границы Переноса

Переносим в `knowledge`:

- источники истины: XML-фикстуры, XSD, MCP, ru-en-map, соседние объекты;
- инварианты round-trip;
- запрет на правку XML-фикстур;
- правила разделения XML-цикла и YAML-цикла;
- правила регистрации metadataItem/property типов;
- требования к `rules.ts`, `types.ts`, TS-фикстурам и тестам;
- протокол действий при расхождении в подчинённом объекте.

Оставляем в skills:

- триггер сценария;
- порядок шагов;
- условия остановки;
- формат результата сценария;
- ссылки на обязательные knowledge-документы.

## Проверка Качества

После реорганизации нужно проверить три сценария чтения:

1. Агент меняет существующий `rules.ts` в `packages/core/metadata/**` без явного skill — через `AGENTS.md` он обязан открыть `INDEX.md`.
2. Агент добавляет новый metadataItem — skill остаётся маршрутом выполнения, но нормы берёт из `knowledge`.
3. Агент чинит round-trip — диагностический skill не дублирует общую методологию, а применяет общий `round-trip-cycle.md`.

## Риски

- Если `INDEX.md` станет длинным, он снова превратится в большой стандарт и будет съедать контекст. Нужно держать его как карту, а не как учебник.
- Если перенести всё сразу, легко потерять детали из текущих skills. Перенос лучше делать по документам: сначала создать `knowledge` рядом со старыми skills, затем сократить skills после проверки.
- Если оставить `_shared/metadata` и `knowledge/metadata` с пересекающимися правилами, появится два источника истины. На переходный период в `INDEX.md` нужно явно пометить, какие старые документы ещё являются источником.

## Следующий Шаг

Сначала написать план миграции:

1. Создать `.agents/knowledge/metadata/INDEX.md`.
2. Разложить текущие правила из `new-applied-object`, `new-metadata-item` и `_shared/metadata` по knowledge-документам.
3. Добавить обязательное защитное правило в `AGENTS.md`.
4. Упростить `new-applied-object` и `new-metadata-item` до сценариев со ссылками на `knowledge`.
5. Проверить, что ссылки не битые и что в проекте не осталось противоречащих источников истины.
