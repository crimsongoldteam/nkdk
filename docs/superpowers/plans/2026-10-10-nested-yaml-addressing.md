# Адреса вложенных значений: план реализации

> Исполнитель: superpowers:executing-plans, в текущей сессии без субагентов.

**Цель:** закрыть наблюдаемые обязанности yamlPath, сохранив служебное состояние
правильных вложенных значений при чтении, правке YAML и экспорте XML.

**Архитектура:** переиспользовать LogicalAddress и выражения logicalAddress.
Сначала доказать, какие потребления прежнего индекса уже заменены смысловыми
значениями и XML-аномалиями. Для оставшихся потребителей готовить переходы
по декларациям при сборке; не добавлять второй полный контекст операции.

**Технологии:** Rust, YAML-декларации, существующий Node-переносчик и AOT-запускатель.
**Спецификация:** [договор](../specs/2026-10-10-nested-yaml-addressing-design.md).

## Ограничения

- Нет частных условий по DynamicList или именам его свойств в общем механизме.
- compose/projection/choice не создают служебных сегментов адреса.
- Списки используют позицию, именованные коллекции — YAML-ключ.
- Повтор ключа не разрешает выбрать первую строку.
- XML-фикстуры не менять; не дублировать сведения восстановления в индексе и !xml.
- Нет обхода графа деклараций и второго разбора XML/YAML во время преобразования.
- Не ставить флажок всего DynamicList до полной приёмки; не создавать коммиты/PR.

## Особое внимание при проверке

- Неизменённый round-trip не доказывает правильный экспорт после правки YAML.
- Позиционный список не обещает устойчивую идентичность после перестановки.
- Числовая строка ключа отличается от числовой позиции.
- Служебная оболочка !xml не должна скрывать изменённый соседний смысловой узел.
- Отсутствие индекса не даёт права выдумывать прежнюю идентичность.

## Этап 2. Проверка правок YAML общим запускателем

Файлы: tools/rules-migration/runtime/src/main.rs и отдельный нейтральный модуль
проверок редактирования; dynamic-list-collection-composition.mjs;
существующие тесты общего запускателя и family-check.test.mjs.

Интерфейс: необязательный массив yamlEdits в проверочном примере. Каждая запись
содержит YAML-замены и независимые XML-замены в исходной фикстуре. Замена должна
явно указывать исходный/новый текст и требуемое число вхождений; неоднозначная
проверка отвергается. Ожидаемый XML не получают из результата конвертера.

- [x] RED: проверка правки обычного соседнего значения сейчас не выполняется;
  ошибочное ожидаемое XML обязано вызывать отказ проверки.
- [x] Добавить общий запуск правок после XML → YAML: готовые внешние документы
  передать прежним переходником; затем YAML → XML и существующее строгое сравнение.
- [x] Проверить минимум, полный объект и повреждённого соседа. Не превращать
  учебный запускатель в отдельный преобразователь и не изменять production XML.

Перед полной сборкой FormAttribute подключать существующие профили имени,
служебного номера и коллекций к автоматическому переносу, не писать их повторно.
Первичный emitCandidates без этих профилей оставляет девять свойств; пять
специальных типов Settings требуют отдельной проверки доступных деклараций.
Ошибки этого предварительного этапа не считать окончательным отчётом
полного переноса. Подробности —в разделе «Проверка полной сборки FormAttribute»
[отчёта](../reports/2026-10-10-nested-address-snapshots.md).

Две коллекции колонок теперь подключаются к реальным параметрам FormAttributeRules
через sourceProjection:2 нативных сценария с независимым YAML, правкой типа
и сохранением неверного ID прошли. Распознанные source-параметры fromYAML:false
и defaultValue:[] сопоставлены полной декларации коллекции, а не отдельному
обработчику. Это не закрывает остальные19 свойств или полную операцию.
Пять типов Settings оказались одним механизмом SettingsFragment; проект
[общего XML-фрагмента](../specs/2026-10-10-xml-fragment-values-design.md)
ожидает согласования до составления плана и реализации нового представления.
