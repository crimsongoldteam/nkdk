# Составные ссылки на таблицы

Продолжение утверждённого плана Rust/YAML. Справочники корней, вложенных объектов
и виртуальных таблиц остаются данными деклараций. Компилятор не знает dataTable.

- [x] Общий поток текстовых записей допускает различную ширину вариантов; выбор ширины однозначно определяется первой частью. Общие границы: неполная запись, неизвестный вариант, пустота и ограничения размеров. Старый путь одинаковой ширины сохраняется.
- [x] Компилятор заранее проверяет непересечение первой части вариантов для XML и YAML, создаёт готовые автоматы и использует поток без промежуточного списка строк. Связь с фиксированной головой последовательности сохраняется.
- [x] Декларация ссылки: корень и имя владельца, произвольная последовательность вложенных объектов/табличных частей и необязательная завершающая виртуальная таблица. Порядок видов сегментов проверяется декларацией. Названия объектов никогда не переводятся как служебные слова.
- [x] Автоматически подключить metadataTarget.kind=dataTable к исходным правилам; ограничения корней задаются параметрами, не именами объектов. Перенести восемь независимых примеров старого парсера и настоящее MainTable DynamicList, включая аномалии и соседей.
- [x] Приёмка: нативные проверки обоих путей, архитектура, Clippy, дубли, полный pnpm test; обновить чеклист без флажка полного DynamicList до приёмки внешнего запроса.

Не расширяем TypeScript-типы правил, не меняем XML-фикстуры, не создаём предметных
обработчиков в Rust. Неоднозначная декларация отклоняется при сборке; неверные
данные сохраняются общим механизмом аномалий. Фиксированная ширина не получает
дополнительного выбора варианта при исполнении.
