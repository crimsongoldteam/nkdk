# Исправления пакетного round-trip: единый план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans`
> through `executing-plans-with-review`. Реализацию и исправления выполняет
> основной агент; единственный независимый агент проверяет итоговый полный diff.
> Не использовать implementation-subagents. Шаги отмечаются флажками.

**Goal:** реализовать все согласованные решения по ошибкам отчёта 34 конфигураций,
сохранив XML, компактное YAML-представление и полезную диагностику.

**Architecture:** предметные свойства и допустимые цели объявляются в `rules.ts`;
ссылки, аннотации и снимки используют существующие общие механизмы runtime.
Первый проход импорта собирает факты, второй строит YAML с точными аннотациями
до контрольного экспорта. Скрипты подготовки и отчёта не изменяют этот договор.

**Tech Stack:** TypeScript, Node.js, pnpm, Vitest, js-yaml, XML runtime, LMDB.

**Spec:** `docs/superpowers/specs/2026-09-03-round-trip-errors-design.md`, пункты 1–16.

## Команды проверки слоёв

Из корня worktree для runtime unit-теста:

```sh
pnpm --filter @nkdk/runtime exec vitest run <путь-теста-в-пакете>
```

Для rules unit-теста выбирать `unit` и `core-metadata`: наборы не пересекаются,
а конкретный файл отбирается фильтром пути. Для интеграционного — `integration`.
Общая регистрация rules требует `--no-isolate`:

```sh
pnpm --filter @nkdk/rules exec vitest run --no-isolate --project unit --project core-metadata <путь-теста-в-пакете>
pnpm --filter @nkdk/rules exec vitest run --no-isolate --project integration <путь-теста-в-пакете>
pnpm duplicates -- --base 8cfe9c6c1619b6085e5e2f0c07b5a28253935078
```

В каждой задаче ниже указаны конкретные файлы тестов. Не подменять их проверкой
одного импорта модуля. Для широких изменений дополнительно запускать соседние
тесты соответствующей операции и `pnpm type-check`.
