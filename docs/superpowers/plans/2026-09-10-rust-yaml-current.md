- Типизированные составные ключи без склейки строк, общее хранилище строк поколения, подготовка индексов порциями, неизменяемые поколения. Граф объединений и DependencyPlan нерекурсивны, имеют бюджеты и проверены на цепочках 20 000 шагов.

- Фиксированные `text-pattern`, открытый `text-table`, типизированный `choice`. Ограничения полей/вариантов наследуются физическим свойством. Выбор учитывает закрытые словари и точное чтение до первого разделителя, включая многосимвольные; преобразуется только выбранный вариант.

## Интеграция владельцев — текущая работа

Общие источники XML/YAML передают события одного разбора скалярам,
коллекциям и поддержанным составным записям. QName получает текущую область
пространств имён через ScopedSource. PartitionSource и RecordEventsSource
маршрутизируют YAML-свойства без копирования узлов и промежуточных документов;
позиции ошибок остаются позициями исходного документа.

Общий вывод XML поддерживает скаляры, QName, коллекции и составные записи,
включая исключительную форму всей вложенной записи. Пространства имён
собираются до открытия корня из деклараций, значений QName и сохранённых

### Порядок подключения внешних XML-свойств

1. Источник принадлежит XML-представлению поля: относительный путь файла
   задаётся декларацией file постоянными сегментами. Common описывает значение и XML-узлы,
   не открывает файл и не знает каталог владельца.
2. Подготовка ресурсов предоставляет неизменяемый набор источников и имён
   файлов. Выбор HTML производится по путям этого набора без повторного обхода
   исходного каталога; порядок имён — сравнение байтов UTF-8.
3. Сборка выбирает источник до чтения свойства. YAML владельца разбирается один
   раз и распределяется между обычными и внешними свойствами тем же маршрутизатором.
4. Экспорт возвращает группу XML-файлов вместе с обычными ресурсами. Каждый
   внешний XML-файл имеет собственную проверку восстановления и область аномалий;
   публикация всей группы начинается только после успешной подготовки.
5. Отсутствующий файл, пустой корень и пустая коллекция различаются. Совпадение
   списка страниц с подготовленным списком файлов позволяет опустить свойство
   YAML; несовпадения, порядок и повторы остаются явно, неизвестная XML-форма
   сохраняется существующим механизмом аномалий.
6. Один и тот же механизм затем используется для AdditionalIndexes; отдельные
   функции обработки справки и дополнительных индексов в общем исполнителе
   запрещены. Проверку полного Help нельзя заменить проверкой его проекции.

### Подготовка общего элемента коллекции

Составная запись принимает готовый поток XML/YAML-событий; обычный вход из байтов
использует тот же путь. XML-подготовка отделена от записи в переданный буфер:
внешний сборщик может использовать общий writer и пространства имён. Проверка
передаёт пустые исходные байты вместе с настоящими событиями, подтверждая отсутствие
повторного разбора; обратная запись создаёт только один writer.

Для произвольной вложенности следующий шаг — общее состояние чтения элемента:
создание, приём события, завершение. Вложенные записи должны получать события
от того же парсера, что и владелец. Готовые потоковые адаптеры и общий writer
сохраняются; отдельный XML Cursor в этот блок не входит. Не допускается заменять
состояние элемента повторным разбором XML или промежуточным деревом на обычном пути.
Это подготовка общего механизма, а не приёмка AdditionalIndexes. До приёмки
нужны также подготовленные идентичности и граница аномалии каждого элемента.


XML-состояние скалярной записи выделено в общий генератор `record/xml_read.rs`:
данные и позиции остаются в записи, приём события отделён от завершения и
преобразования значений. Проверены независимые записи с завершением в обратном
порядке. Для аномалий одного из повторяющихся полей добавлен выбор XML-вхождения
по исходной позиции; две разные неправильные записи восстанавливаются независимо.
Нормальный путь не создаёт дерево XML. Проверки ядра и компилятора прошли;
после скалярного XML-состояния нужны также состояния YAML и вложенных коллекций. Флажки объектов не изменены.


Состояние скалярных YAML-полей также отделено от завершения записи:
`record/yaml_read.rs` использует прежние преобразователи и отметки аномалий.
Ядро `ScalarMapping` хранит границы отображения и проверяет повторные ключи;
существующий `visit_scalar_events` использует его. Два независимых отображения
проверены вместе с тегом значения. Вложенная оболочка по-прежнему обрабатывается
существующим общим потоком; для полного элемента коллекции ещё нужны состояния
его вложенных коллекций и сборка жизненного цикла, затем проверка AdditionalIndexes.
