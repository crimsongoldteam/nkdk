# Unified xmlOrder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить единый `MetadataItemRule.xmlOrder`, собрать его из семи XML-конфигураций для всех наблюдавшихся объектов, включая элементы форм, и удалить числовой `PropertyRule.order`.

**Architecture:** `properties` продолжает описывать состав правила и переиспользовать общие spread, а `xmlOrder` независимо задаёт порядок XML-полей конкретного объекта. XML-export один раз компилирует и кэширует итоговый порядок по identity правила; временный анализатор собирает точные наблюдения, а транзакционный переписчик добавляет `xmlOrder` в rules.ts без перестановки `properties`.

**Tech Stack:** TypeScript 6, Node.js 26, TypeScript Compiler API, Vitest 4, Piscina, существующие XML-import/XML-export и configuration index NKDK.

## Global Constraints

- Работать в `/Users/nikita/git/nkdk/.worktrees/rule-order-analysis` на ветке `codex/rule-order-analysis`.
- Источники: непосредственные подкаталоги `/Users/nikita/git/round-trip/cf`: `acc`, `all`, `clean`, `doc`, `erp`, `small`, `trade`.
- XML-фикстуры и `/Users/nikita/git/round-trip/cf` не изменять.
- `xmlOrder` задаёт порядок полей объекта; порядок элементов коллекций остаётся в YAML или специальном `ConfigurationXmlNode.order`.
- Свойство коллекционного типа, например `childItems`, является допустимым ключом `xmlOrder`.
- Общие словари свойств не получают `xmlOrder`; объект, используемый элементом коллекции, получает собственный `xmlOrder`.
- В `xmlOrder` входят только наблюдавшиеся свойства; остальные экспортируются в конце в порядке `properties`.
- Обычный снимок хранит присутствие через `present`, но не порядок полей.
- YAML продолжает сортироваться через `sortYamlRuleProperties`.
- Любой конфликт, цикл, неизвестный ключ или неоднозначное сопоставление прекращает миграцию до записи.
- Перед завершением обязательно выполнить `pnpm test` из корня worktree.

В `xmlPropertyOrder.ts` использовать модульный `WeakMap`:

```ts
const cache = new WeakMap<MetadataItemRule, readonly string[]>()

export function getCompiledXMLPropertyOrder(rule: MetadataItemRule): readonly string[] {
  const cached = cache.get(rule)
  if (cached !== undefined) return cached

  const declaration = Object.keys(rule.properties)
  const declarationSet = new Set(declaration)
  const explicit = rule.xmlOrder ?? []
  const seen = new Set<string>()
  for (const key of explicit) {
    if (!declarationSet.has(key)) throw new Error(`${rule.itemType}: неизвестный ключ xmlOrder ${key}`)
    if (seen.has(key)) throw new Error(`${rule.itemType}: ключ xmlOrder ${key} повторяется`)
    seen.add(key)
  }
  const compiled = Object.freeze([...explicit, ...declaration.filter((key) => !seen.has(key))])
  cache.set(rule, compiled)
  return compiled
}
```
