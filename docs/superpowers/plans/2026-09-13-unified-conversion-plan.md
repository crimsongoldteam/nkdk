# Единый план преобразования — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Работать в текущей задаче без субагентов и таймеров; после законченного блока переходить к следующему. Чекпоинт проверки и коммит не требуют завершения хода.

**Goal:** Объединить смысловую подготовку записей, вложенности и коллекций, полностью перенести значения перечислений и проверить повторное использование механизма на реквизитах документа.

**Architecture:** После разбора и связывания YAML компилятор один раз строит типизированный план значений, привязок, зависимостей и маршрутов. Rust и JSON Schema используют его; во время преобразования выполняется сгенерированный код с обычным типизированным состоянием. Готовые преобразователи значений и существующие публичные операции сохраняются.

**Tech Stack:** Rust 1.98.1, edition 2024; существующие `rule-model`, `rule-compiler`, `conversion-core`, `compiled-rules`; Node.js 26.4.x и pnpm 10.33.0 для инструмента переноса; существующие XML/YAML-библиотеки, jsonschema, Clippy, jscpd и архитектурные проверки. Новые внешние зависимости не нужны.

**Spec:** [Единый план преобразования в компиляторе деклараций](../specs/2026-09-13-unified-conversion-plan-design.md). Прочитать вместе с [языком](../specs/2026-09-10-declaration-language-design.md) и [массовым переносом](../specs/2026-09-12-rules-bulk-migration-design.md).

## Global Constraints

- «Во время преобразования нет интерпретатора плана и обязательного второго дерева всего документа».
- «Декларация описывает нормальные значения»: аномалии выводятся общим механизмом; неизвестное правило не становится поддержанным через `!xml/raw`.
- «Служебный идентификатор не превращается в обычное поле YAML или скрытый ключ для обхода ограничения компилятора».
- «Индексы не копируются для каждого элемента». Ошибка подготовки индекса не маскируется под аномалию исходных данных.
- «XML-фикстуры не изменяются». Реальные данные для проверки проекта и измерений берутся только из `e2e/fixtures/xml`; синтетические данные допустимы для общих механизмов.
- «Пользовательский чеклист сохраняет только флажок полной готовности объекта». Системные перечисления остаются одним пунктом.
- «Цель проекта — 10× по скорости и 10× по памяти — сохраняется», но для её подтверждения нужны сопоставимые измерения; принятие данного плана её не подтверждает.
- Итоговая система полностью на Rust; TypeScript используется как источник правил и проверенных ожиданий во время миграции. Enterprise не реализуется: преобразования XML ↔ YAML.
- Сохраняются согласованные точные десятичные числа и записанное время даты, независимо от часового пояса компьютера.
- В нейтральных модулях нет условий по именам common, объектов и свойств. Предметные соответствия находятся в декларациях и данных переноса.
- `.agents/architecture.md` не редактируется этим планом: границы metadata-операций не меняются. При необходимости менять их требуется отдельное согласование согласно AGENTS.md.

## Условия выполнения

Незаполненные флажки обозначают ещё не выполненную работу. При выполнении
продолжать следующий доступный пункт без отдельного запроса после коммита
или зелёного теста. Вопрос пользователю нужен только для нового смыслового
договора, который нельзя установить по коду, спецификации и проверенным
источникам. При таком вопросе выполнять независимые пункты, сохраняя
зависимую часть открытой. Известная исходная ошибка схемы не требует нового
согласования на исправление: она включена в блок 2.
