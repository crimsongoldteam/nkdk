# План исправления производительности validation-схем

1. Добавить регрессионный тест `RuleSchemaRuntime`: граф для metadata rule
   содержит ссылки и отдельно собранные общие схемы.
2. Перенести нейтральную сборку ссылочного графа в `@nkdk/runtime/rule-kit`,
   используя одну экземплярную export-сессию.
3. Переключить `createValidationSchemaCache` на новый экспорт графа для форм и
   свойств, сохранив варианты required policy и explicit XML values.
4. Запустить точечные тесты runtime/rules и профиль компиляции схем.
5. Повторить compiled MCP stdio профиль на `e2e/fixtures/xml/cf`, разобрать
   оставшиеся стадии импорта и сравнить с исходным уровнем.
6. Выполнить type-check, полный `pnpm test`, архитектурные проверки и поиск
   новых дублей относительно исходного коммита ветки.

## Что сделано

- Экземплярный `RuleSchemaRuntime` экспортирует компактный граф со ссылками;
  глобальные реестры не возвращены.
- Validation cache снова компилирует общие схемы один раз. Время `compileAll`
  снизилось с 6,24 до 0,335 секунды, RSS после прогрева — с 1,60 ГиБ до
  340 МиБ.
- Точная e2e-фикстура после исправления: cold 5,61 секунды, warm в среднем
  0,87 секунды, 264 успешных файла без предупреждений и ошибок.
- Других регрессий после слияния профиль не показал. Следующая крупнейшая
  стадия — полезная работа первого прохода, около 0,63 секунды в warm-запуске.
- Полный `pnpm test`, обе архитектурные проверки и проверка новых дублей
  прошли успешно. Предупреждения о тестовых таймингах не исправлялись по
  отдельному указанию разработчика.
