# Файл индекса конфигурации

## Спецификация двоичного формата 2.0

Статус: реализован.

## 1. Область применения

Файл `.nkdk/components/<componentPath>/configuration-index.bin` хранит самостоятельный снимок одного
компонента Проекта: `cf`, `cfe/<Имя>` либо другого зарегистрированного компонента.

Формат 2.0 сохраняет данные восстановления XML формата 1.0 и дополнительно хранит:

- локальный двоичный metadata-индекс компонента;
- локальный двоичный индекс владельцев data path;
- сериализуемые metadata-зависимости только этого компонента.

Снимок зависимого компонента НЕ ДОЛЖЕН содержать общий индекс `cf`, составное `layered`-представление,
абсолютные пути или данные другого зависимого компонента.

## 2. Несовместимость с 1.0

Формат контейнера имеет версию `2.0` и одиннадцать обязательных секций. Читатель 2.0 отклоняет
контейнер 1.0 как несовместимый и требует повторный import. Подстановка пустых локальных секций в
старый снимок не допускается.

Секции 1–7 сохраняют двоичное представление версии 1.0:

1. `BINDING`;
2. `STRINGS`;
3. `PROJECT_FILES`;
4. `IDENTITIES`;
5. `XML_ORDERS`;
6. `XML_NODES`;
7. `XML_VALUES`.

Поле по смещению `12` секции `BINDING` содержит `componentPathStringId`, а не прежний `baseId`.
`componentPath` ДОЛЖЕН точно совпадать с адресом компонента, через который читается снимок.

## 3. Заголовок

Заголовок занимает 64 байта.

| Смещение | Размер | Поле | Значение 2.0 |
|---:|---:|---|---|
| 0 | 8 | `magic` | ASCII `NKDK1CIX` |
| 8 | 2 | `majorVersion` | `2` |
| 10 | 2 | `minorVersion` | `0` |
| 12 | 4 | `headerLength` | `64` |
| 16 | 1 | `byteOrder` | `1`, little-endian |
| 17 | 1 | `stringEncoding` | `1`, UTF-8 |
| 18 | 1 | `checksumAlgorithm` | `1`, XXH3-128 |
| 19 | 1 | `fileHashAlgorithm` | `1`, XXH3-64 |
| 20 | 4 | `directoryEntryLength` | `64` |
| 24 | 4 | `sectionCount` | `11` |
| 28 | 4 | `flags` | `0` |
| 32 | 8 | `directoryOffset` | `64` |
| 40 | 8 | `fileLength` | точный размер файла |
| 48 | 16 | `directoryChecksum` | XXH3-128 каталога |

Каталог занимает `11 × 64 = 704` байта и заканчивается по смещению `768`. Все секции обязательны,
имеют версию `1.0`, флаг `1`, располагаются по возрастанию типа и защищены собственной контрольной
суммой XXH3-128.

## 4. Каталог секций

| Тип | Секция | `recordCount` |
|---:|---|---:|
| 1 | `BINDING` | `1` |
| 2 | `STRINGS` | число строк |
| 3 | `PROJECT_FILES` | число файлов |
| 4 | `IDENTITIES` | число идентификаторов |
| 5 | `XML_ORDERS` | число порядков |
| 6 | `XML_NODES` | число XML-узлов |
| 7 | `XML_VALUES` | число XML-значений |
| 8 | `LOCAL_REFERENCE_INDEX` | `1` |
| 9 | `LOCAL_OWNER_STRINGS` | `1` |
| 10 | `LOCAL_OWNER_TABLE` | `1` |
| 11 | `LOCAL_DEPENDENCIES` | число зависимостей |

Поля записи каталога, выравнивание, контрольные суммы и правила размещения совпадают с форматом 1.0.
Файл заканчивается последним байтом секции `LOCAL_DEPENDENCIES`.

## 5. Локальный validation snapshot

Секции 8–10 содержат три непрозрачных блока `PersistedSharedValidationSnapshot`:

| Секция | Поле |
|---|---|
| `LOCAL_REFERENCE_INDEX` | `reference` |
| `LOCAL_OWNER_STRINGS` | `ownerStrings` |
| `LOCAL_OWNER_TABLE` | `ownerTable` |

Внешний codec индекса проверяет границы, контрольную сумму и `recordCount = 1`, но не разбирает
внутреннее представление блока. При восстановлении validation snapshot потребитель отдельно
проверяет magic, версию, размеры, счётчики, диапазоны и UTF-8 существующих shared-форматов.

Блоки описывают только локальные факты выбранного компонента. Данные `cf` или составного поиска
перед сериализацией в них не добавляются.

## 6. Секция `LOCAL_DEPENDENCIES`

Каждая запись имеет переменную длину:

| Поле | Кодирование |
|---|---|
| `byteLength` | `u32` |
| `json` | `byteLength` байт UTF-8 |
| `padding` | нулевое выравнивание записи до 8 байт |

`json` является объектом с точным набором полей:

```json
{
  "sourceProjectPath": "Справочник/Товары/Свойства.yaml",
  "yamlPath": ["Реквизиты", 0, "Тип"],
  "rulePath": [
    { "propertyKey": "attributes", "nestedItemType": "Attribute" },
    { "propertyKey": "type" }
  ],
  "kind": "metadataTarget",
  "canonical": "Catalog.Товары.Attribute.Артикул"
}
```

Ограничения:

- `sourceProjectPath` является относительным путём Проекта по правилам `PROJECT_FILES`;
- `sourceProjectPath` ДОЛЖЕН присутствовать в секции `PROJECT_FILES` этого же снимка;
- `yamlPath` содержит только непустые строки и неотрицательные безопасные целые числа;
- `rulePath` содержит объекты с непустым `propertyKey` и необязательным непустым
  `nestedItemType`;
- `kind` в версии 2.0 равен `metadataTarget`;
- `canonical` является непустой строкой;
- неизвестные поля запрещены;
- записи уникальны и отсортированы лексикографически по UTF-8 байтам их канонического JSON.

Писатель формирует канонический JSON в порядке полей из примера. Точная повторная зависимость
является ошибкой, а не дополнительной записью.

## 7. Проверка файла

Читатель выполняет проверки в следующем порядке:

1. magic, версию 2.0, алгоритмы, размеры и `fileLength`;
2. каталог и его контрольную сумму;
3. наличие всех одиннадцати обязательных секций и их версии;
4. размещение, выравнивание, границы и отсутствие пересечений;
5. контрольные суммы секций;
6. структурные ограничения секций 1–11;
7. уникальность записей;
8. внутренние ссылки секций 1–7;
9. принадлежность каждой локальной зависимости `PROJECT_FILES`;
10. ожидаемые `componentPath` и версию производителя.

Повреждение любой секции делает весь снимок непригодным.

## 8. Transient fragment codec

Передача вкладов first-pass между worker и координатором использует несовместимый конверт
`NKDKCIF2`, `version = 2`. Каждый фрагмент всегда содержит массив `localDependencies`; публичный
`ConfigurationIndexFragment` может опустить поле, когда массив пуст.

При merge точные повторы локальных зависимостей удаляются, а результат сортируется по тому же
каноническому ключу. Это делает результат независимым от разбиения файлов между worker. Metadata
блоки секций 8–10 создаются координатором из локальных first-pass вкладов и через fragment codec не
передаются.
