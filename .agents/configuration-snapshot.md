# Таблицы

## `meta`

| Поле | Описание | Пример |
|---|---|---|
| `schemaVersion` | Версия формата снимка | `1` |

## `hashes`

| Поле | Описание | Пример |
|---|---|---|
| `<путь проектного файла>` | Ключ записи | `Документы/Заказ.yaml`, `Документы/Заказ/Модуль.bsl` |
| `contentHash` | Хэш фактических байтов проектного файла | `0x37…` |

## `blocks`

| Поле | Описание | Пример |
|---|---|---|
| `<путь YAML-файла>` | Ключ записи | `Документы/Заказ.yaml` |
| `block` | Сведения для восстановления XML из этого YAML-файла | Блок файла |

## `pendingHashes`

| Поле | Описание | Пример |
|---|---|---|
| `<путь проектного файла>` | Ключ изменённого или удалённого файла | `Документы/Заказ.yaml`, `Документы/Заказ/Модуль.bsl` |
| `hash` | Новый хэш файла | `{ contentHash }` |
| `deleted` | Признак удаления файла | `true` |

## `pendingBlocks`

| Поле | Описание | Пример |
|---|---|---|
| `<путь YAML-файла>` | Ключ изменённого или затронутого файла | `Документы/Заказ.yaml`, `Конфигурация.yaml` |
| `block` | Новый блок файла | Блок файла |
| `deleted` | Удалить прежний активный блок | `true` |

# Формат блока (`block`)

| Имя ключа | Пример | **Объект с аномалией** | **Свойство** | **Текст в XML** | Зачем храним |
|---|---|---|---|---|---|
| `entities[].logicalAddress` | `ОбщаяФорма.КонстантаВсеСвойства.Элемент.КонстантаВсеСвойства` | Элемент формы `КонстантаВсеСвойства` | Смысловой адрес | — | Связывает сохранённые данные с элементом YAML без хранения пути внутри каждой записи. |
| `entities[].uuid` | `0f4c2a9b-1d3e-4b6f-8a7c-9e1d2c3b4a5f` | Справочник `Контрагенты` | `uuid` | `<Catalog uuid="0f4c2a9b-1d3e-4b6f-8a7c-9e1d2c3b4a5f">` | Каждый импортированный или созданный UUID сохраняется: он нужен XML, отсутствует в YAML и не вычисляется повторно. |
| `entities[].xmlId` | `1` | Реквизит формы `Объект` | `id` | `<Attribute name="Объект" id="1">` | Каждый импортированный или созданный XML-id сохраняется для внутренних ссылок и не вычисляется повторно. |
| `entities[].children[]` | `[{ xmlName: "Form", name: "ФормаСписка" }, { xmlName: "Form", name: "ФормаЭлемента" }]` | Родитель вынесенных дочерних объектов | Невосстанавливаемый порядок дочерних объектов | `<Form>ФормаСписка</Form><Form>ФормаЭлемента</Form>` | Дочерние объекты лежат в отдельных YAML-файлах; полный список сохраняется только тогда, когда его исходный порядок нельзя восстановить сортировкой проекта. |

# Списки в `children`

| Список | Где находится | Порядок без снимка | Что хранится |
|---|---|---|---|
| Корневые объекты конфигурации | `Configuration/ChildObjects` | Фиксированный порядок XML-видов; имена внутри вида — по русскому алфавиту | Полный список имён только для XML-вида с другим порядком; при другом порядке самих видов — полная плоская последовательность корня |
| Формы (`Form`) | `ChildObjects` прикладных объектов и объектов внешнего источника данных | По UTF-8-байтам имени | Полный список форм только при отличии |
| Макеты (`Template`) | `ChildObjects` прикладных объектов и объектов внешнего источника данных | По UTF-8-байтам имени | Полный список макетов только при отличии |
| Таблицы внешнего источника данных (`Table`) | `ChildObjects` внешнего источника данных | По UTF-8-байтам имени | Полный список таблиц только при отличии |
| Кубы внешнего источника данных (`Cube`) | `ChildObjects` внешнего источника данных | По UTF-8-байтам имени | Полный список кубов только при отличии |
| Таблицы измерений (`DimensionTable`) | `ChildObjects` куба внешнего источника данных | По UTF-8-байтам имени | Полный список таблиц только при отличии |

# Изменение данных блока

| Случай | Результат |
|---|---|
| Rename через migration | `uuid` и `xmlId` переносятся на новый `logicalAddress`; позиция в `children` не переносится |
| Ручное переименование | Прежняя запись удаляется, для нового элемента создаются новые идентификаторы |
| Новый элемент в восстанавливаемом списке | Занимает место согласно сортировке; `children` не создаётся |
| Новый элемент в сохранённом списке | Добавляется в конец; новые элементы между собой упорядочиваются по правилам списка |
| Изменение вынесенного дочернего объекта | Повторно строятся XML и блок владельца, даже если YAML владельца не изменился |
