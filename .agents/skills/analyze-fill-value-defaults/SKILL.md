# Исследование значений заполнения

## Запуск

Получи от пользователя корневой каталог с конфигурациями и каталог для отчёта. Запусти из корня репозитория:

```shell
node .agents/skills/analyze-fill-value-defaults/analyze-fill-value-defaults.mjs \
  <каталог-конфигураций> \
  --output <каталог-отчёта>
```

Чтобы исследовать только отдельные конфигурации, повторяй `--configuration <имя>`. Число параллельно читаемых файлов задаётся через `--concurrency`, число примеров в сводной строке — через `--examples`.

## Анализ результата

1. Сначала прочитай счётчики в `fill-value-defaults.md`.
2. Затем найди строки со статусами `противоречит rules`, `варианты` и `тип не определён`.
3. Для выводов обращайся к точным вариантам из `fill-value-defaults.json` и указывай относительные пути примеров.
4. Разделяй три уровня: XML-факт (`raw`), смысловую категорию (`valueCategory`) и оценку действующих `rules.ts` (`rulesClassification`). Не выдавай оценку rules за наблюдаемый факт.
5. Для массовых ссылочных значений рассуждай по категории и типу, а конкретные значения используй как доказательства исключений.

До изменения metadata rules или добавления `!xml` явно запроси согласие пользователя. Неразобранное значение сначала исследуй по исходному XML и текущему resolver; `!xml` не используй как обход неполного правила.
