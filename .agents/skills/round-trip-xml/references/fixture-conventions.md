# Конвенции фикстур reproducer'а

## Один slug — один набор файлов

| Артефакт | Правило именования |
|----------|-------------------|
| XML-файл | `<slug>.xml` |
| TS-файл | `<slug>.ts` |
| TS-экспорт | `<slug>` (camelCase) |
| Ветка | `round-trip/<kebab-slug>` |
| Тест-блоки | `it("import <slug>")`, `it("export <slug>")` |

## Размещение

`packages/core/metadata/<module>/__fixtures__/<slug>.{xml,ts}`

`<module>` — наименьший значимый metadataItem, владелец правила. Не родитель, не коллекция — модуль того `rules.ts`, который должен быть поправлен.

## XML-фикстура

- Корневой тег = `xmlRootTag`, которое использует существующий `fromXML.test.ts` / `toXML.test.ts` модуля. Подсмотри рядом.
- **Полный объект-обёртка** (`xr:StandardAttribute` / `xr:Parameter` / аналог) со всеми дефолтными полями, которые эмитит `toXML` для TS-формы. Минимальный chunk только на уровне property-поля не подходит: `export <slug>` тогда падает не на баге, а на отсутствующих дефолтах.
- Форматирование (отступы, переносы, кавычки, пространства имён) — как в соседних `full.xml` / `multiple.xml` модуля. XML-фикстуры сравниваются **строкой**, без канонизации — любое расхождение в форматировании сломает round-trip.
- Не перезаписывай существующий `<slug>.xml` в целевом модуле. Коллизия → стоп, спрашивай slug заново.

### Как выйти на полный вид

Руками такую фикстуру точно не собрать (порядок полей задаётся `rules.ts`, пустые числа эмитятся как `xsi:nil="true"`, и т.д.). Процедура:

1. Напиши черновую фикстуру: корневой тег + `xr:StandardAttribute name="..."` + только bug-триггерные узлы.
2. Создай TS-фикстуру и оба тест-блока (`fromXML.test.ts`, `toXML.test.ts`).
3. Запусти **только** export-тест: `pnpm exec vitest run -t "export <slug>"` (из пакета целевого модуля, обычно `packages/core`).
4. Vitest покажет diff `Expected` (черновик) vs `Received` (выход `toXML`):
   - bug в `fromXML` → `Received` = правильный XML, **скопируй его целиком** в фикстуру;
   - bug в `toXML` → `Received` содержит баг, сохрани в фикстуре **правильную** версию из исходного 1C XML (export-тест останется красным до фикса);
   - смешанный случай — скопируй `Received` и руками откорректируй bug-триггерные узлы.
5. Перезапусти export-тест. Итог: красной остаётся ровно одна сторона (fromXML **или** toXML).

См. также раздел «Шаг 5» в `SKILL.md`.

## TS-фикстура

Один файл `<slug>.ts` с единственным именованным экспортом — имя экспорта совпадает со slug'ом:

```typescript
import type { <ModuleType> } from "../types"

export const <slug> = {
  // ожидаемая форма объекта — что должен вернуть fromXML после фикса rules.ts
} as const satisfies <ModuleType>
```

Правила:

- Строй объект **от `types.ts`** модуля. Если поле есть в `types.ts`, но не покрыто XML-фикстурой — не указывай.
- **Не** снимай форму с текущего (сломанного) вывода `fromXML`. Фикстура = спецификация правильного поведения.
- `satisfies <ModuleType>` обязателен — ловит несоответствие формы типу на шаге компиляции, до запуска тестов.
- Если тип недоступен напрямую (например, нужен `Partial` или литеральный под-объект) — спроси пользователя, не подменяй тип молча.

## Round-trip — не пишем

Парные `it("import <slug>")` и `it("export <slug>")` эквивалентны round-trip блоку для целей reproducer'а. Отдельный round-trip блок не нужен.
