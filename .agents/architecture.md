## Правила документа

| Правило | Требование |
|---|---|
| Основная форма | Архитектурные решения, договоры, ограничения, состояния и потоки данных описываются преимущественно таблицами. |
| Дополнительные формы | Списки используются для коротких перечислений, Mermaid-диаграммы — для связей и потоков, которые понятнее в графическом виде. |
| Свободный текст | Допускается только как короткая вводная связка, если таблица, список или диаграмма сделали бы смысл менее ясным. Длинные повествовательные абзацы не используются. |
| Строка таблицы | Описывает одно проверяемое утверждение или один архитектурный элемент. Несвязанные решения разносятся по разным строкам. |
| Именование | Названия шагов и артефактов должны совпадать во всех таблицах и диаграммах. |

### Чтение проекта

Находит и распределяет YAML-файлы. Каждый worker последовательно читает по одному файлу, проверяет его, одним обходом правил собирает локальные индексы и освобождает разобранные YAML-данные до перехода к следующему файлу.
| Действие | Описание | Входящие артефакты | Исходящие артефакты | Worker |
|---|---|---|---|---:|
| Распределение файлов | Находит и классифицирует YAML и внешние файлы проекта, затем делит YAML-файлы между worker. | [Корень проекта](#artifact-koren-proekta)<br>[Правила структуры проекта](#artifact-pravila-struktury-proekta) | [Список файлов проекта](#artifact-spisok-failov-proekta)<br>[Worker список YAML-файлов](#artifact-worker-spisok-yaml-failov) |  |
| Чтение и разбор YAML | Читает и разбирает один назначенный YAML-файл. Одновременно worker удерживает не более одного разобранного файла. | [Worker список YAML-файлов](#artifact-worker-spisok-yaml-failov) | [Worker данные YAML](#artifact-worker-dannye-yaml) | ✓ |
| Извлечение локальных индексов | Во время единственного обхода текущего YAML по [rules.ts](#artifact-rules-ts) передаёт окончательные значения в тот же накопитель, что импорт. Накопитель формирует индекс метаданных, validation-зависимости и компактные позиции диагностик. После проверок ссылки на YAML удаляются до чтения следующего файла. | [Worker данные YAML](#artifact-worker-dannye-yaml)<br>[rules.ts](#artifact-rules-ts) | [Факты владельца](#artifact-fakty-vladeltsa)<br>[Worker индекс метаданных](#artifact-worker-indeks-metadannyh)<br>[Worker индекс зависимостей](#artifact-worker-indeks-zavisimostei) | ✓ |
| Обобщение индексов | Объединяет worker индексы метаданных в глобальный индекс метаданных, а worker индексы зависимостей — во временный глобальный индекс зависимостей. | [Worker индекс метаданных](#artifact-worker-indeks-metadannyh)<br>[Worker индекс зависимостей](#artifact-worker-indeks-zavisimostei) | [Глобальный индекс метаданных](#artifact-globalnyi-indeks-metadannyh)<br>[Глобальный индекс зависимостей](#artifact-globalnyi-indeks-zavisimostei) |  |

### Проверка по схеме

Проверяет текущие worker данные YAML по JSON Schema до освобождения разобранного файла. Между worker-проходами сохраняются только диагностики, а не YAML.

### Построение модели

Преобразует worker данные YAML в metadata-модель по [rules.ts](#artifact-rules-ts) для операций, которым требуется модель; validation и импорт из XML этот шаг не выполняют.

### Проверка зависимостей

Проверяет индексы, отложенные проверки и `ПутьКДанным` по типизированным фактам глобального индекса метаданных. Обходит обычные и single-элементы формы по зарегистрированным правилам; одинаковые координаты свойств с import строятся общим нейтральным механизмом. Metadata-модель и совместимое модельное представление не создаются.

### Вычисление хэшей файлов проекта

Вычисляет хэш YAML по тем же байтам, которые worker прочитал и разобрал, а хэш внешнего файла — по тем же байтам, которые главный процесс копирует в XML-результат.

### Проверка соответствия версии конфигурации

Проверяет совпадение текущей и ожидаемой версий конфигурации.

### Применение изменений в 1С

Передаёт через подключение только изменённые XML и внешние файлы, не создавая локальную XML-выгрузку, и получает новую версию после успешного применения всего набора.

### Формирование данных файла индекса конфигурации

Создаёт полное новое содержимое единого файла после успешного формирования результата операции.

### Запись файла индекса конфигурации

Кодирует новое содержимое и пишет единый двоичный файл напрямую в итоговый путь без временного файла, повторного чтения, переименования и принудительной синхронизации с диском.

### Запись YAML

При импорте сериализует уточнённый [Worker YAML-результат импорта](#artifact-worker-yaml-rezultat-importa); в остальных модельных операциях сериализует YAML-представление metadata-модели. Пишет YAML и связанные файлы напрямую в целевой компонент Проекта.

### Переименование путей

Переименовывает файл или каталог согласно плану операции.
