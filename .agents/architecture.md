# Архитектура

## Термины

| Термин | Значение |
|---|---|
| Проект | NKDK-проект в YAML-представлении, включая связанные внешние файлы. |
| Конфигурация | Конфигурация внутри информационной базы «1С:Предприятие». |

## Операции

Флажок означает, что операция может выполнять соответствующий шаг. Порядок столбцов не задаёт порядок выполнения: при синхронизации подключение к 1С, проверка соответствия версии конфигурации и применение изменений выполняются только после обнаружения локальных изменений.

|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| Импорт из 1С | ✓ | ✓ |  |  |  | ✓ |  | ✓ | ✓ |  | ✓ | ✓ | ✓ |  |
| Синхронизация в 1С | ✓ |  | ✓ | ✓ |  | ✓ |  | ✓ | ✓ | ✓ | ✓ | ✓ |  |  |
| Валидация |  |  |  | ✓ | ✓ |  | ✓ |  |  |  |  |  |  |  |
| Подсказка схем |  |  |  | ✓ |  |  |  |  |  |  |  |  |  |  |

Переименование и поиск ссылок временно используют построение модели, но не запускают шаги validation. Полная validation остаётся отдельной операцией.

Валидация не выполняет `Построение модели` в worker: проверки строятся по `Worker данные YAML`, YAML-фактам, `Глобальный индекс метаданных` и `Worker индекс зависимостей`.

## Подготовка импорта конфигурации

Этап получает XML-выгрузку из 1С и подготавливает данные, используемые общими шагами импорта.

| Шаг | Описание | Входящие артефакты | Исходящие артефакты | Worker |
|---|---|---|---|---:|
| Выгрузка конфигурации из 1С в XML | Фиксирует текущую версию конфигурации и выгружает конфигурацию подключённой базы в XML. | `Подключение к 1С` | `Корень XML-выгрузки`<br>`Ожидаемая версия конфигурации` |  |
| Поиск XML-файлов выгрузки | Находит XML-файлы объектов метаданных в исходной XML-выгрузке. | `Корень XML-выгрузки`<br>`rules.ts` | `Список путей XML-файлов выгрузки` |  |
| Классификация XML-файлов выгрузки | Определяет роль XML-файла, правила соответствующего объекта метаданных и связанные внешние файлы выгрузки. | `Список путей XML-файлов выгрузки`<br>`rules.ts` | `Описание XML-файла выгрузки`<br>`Описание внешнего файла XML-выгрузки` |  |
| Чтение XML | Читает текст XML-файла из исходной выгрузки. | `Описание XML-файла выгрузки` | `XML-текст` |  |
| Парсинг XML | Преобразует XML-текст в структурированные XML-данные. | `XML-текст` | `XML-данные` | ✓ |
| Копирование внешних файлов из XML-выгрузки в проект | Копирует связанные модули, изображения, макеты и другие внешние файлы из выгрузки в проект без включения их содержимого в metadata-модель. | `Описание внешнего файла XML-выгрузки`<br>`Целевой путь` | `Внешний файл проекта` |  |
| Извлечение данных для индекса конфигурации | Извлекает из XML идентификаторы и скрытые данные, необходимые для файла индекса конфигурации. | `XML-данные`<br>`rules.ts` | `Идентификаторы и reference-данные конфигурации` | ✓ |

## Чтение проекта

Этап читает проект для синхронизации, валидации, подсказки схем, переименования и поиска ссылок. Проверка по схеме, построение metadata-модели и проверка зависимостей выполняются позднее.

| Шаг | Описание | Входящие артефакты | Исходящие артефакты | Worker |
|---|---|---|---|---:|
| Распределение файлов | Находит и классифицирует YAML и внешние файлы проекта, затем делит YAML-файлы между worker. | `Корень проекта`<br>`Правила структуры проекта` | `Список файлов проекта`<br>`Worker список YAML-файлов` |  |
| Чтение и разбор YAML | Читает назначенные YAML-файлы и разбирает их без построения позиций YAML-узлов. | `Worker список YAML-файлов` | `Worker данные YAML` | ✓ |
| Сохранение worker данных YAML | Сохраняет `Worker данные YAML` в памяти worker для последующих шагов операции. | `Worker данные YAML` | `Worker данные YAML` | ✓ |
| Извлечение локальных индексов | Извлекает worker индексы метаданных и worker индексы зависимостей из worker данных YAML. | `Worker данные YAML` | `Worker индекс метаданных`<br>`Worker индекс зависимостей` | ✓ |
| Обобщение индексов | Объединяет worker индексы метаданных в глобальный индекс метаданных, а worker индексы зависимостей — во временный глобальный индекс зависимостей. | `Worker индекс метаданных`<br>`Worker индекс зависимостей` | `Глобальный индекс метаданных`<br>`Глобальный индекс зависимостей` |  |
| Распределение индекса зависимостей | Делит глобальный индекс зависимостей между worker и передаёт каждому worker глобальный индекс метаданных и worker индекс зависимостей. | `Глобальный индекс метаданных`<br>`Глобальный индекс зависимостей` | `Глобальный индекс метаданных`<br>`Worker индекс зависимостей` |  |

После обобщения worker удаляет `Worker индекс метаданных` и `Worker индекс зависимостей`. После распределения координатор удаляет `Глобальный индекс зависимостей`. Каждый worker продолжает хранить `Worker данные YAML`, `Глобальный индекс метаданных` и свой `Worker индекс зависимостей`.

Целевое состояние: `Worker данные YAML` не покидают worker, а операции выполняют последующие шаги командами worker. Временное состояние реализации: для validation распарсенные YAML-данные уже не передаются в главный поток; синхронизация в XML, переименование и поиск ссылок ещё используют переходную передачу YAML-данных и должны быть переведены на worker-команды отдельно.

## Подготовка синхронизации конфигурации

Этап определяет изменённые файлы проекта и подготавливает XML для применения в конфигурации.

| Шаг | Описание | Входящие артефакты | Исходящие артефакты | Worker |
|---|---|---|---|---:|
| Чтение файла индекса конфигурации | Проверяет и разбирает единый двоичный файл выбранной привязки. | `Файл индекса конфигурации` | `Данные файла индекса конфигурации`<br>`Ожидаемая версия конфигурации` |  |
| Сравнение хэшей проекта с индексом конфигурации | Сравнивает текущие хэши с хэшами из файла индекса конфигурации. | `Хэши файлов проекта`<br>`Данные файла индекса конфигурации` | `Список изменений проекта` |  |
| Построение XML | Преобразует изменённые metadata-модели в XML, используя данные из файла индекса конфигурации. | `Metadata-модель`<br>`rules.ts`<br>`Данные файла индекса конфигурации`<br>`Список изменений проекта` | `XML-данные` | ✓ |
| Сериализация XML | Преобразует структурированные XML-данные в текст для передачи в 1С без записи локальной XML-выгрузки. | `XML-данные` | `XML-текст` | ✓ |

## Именование данных

- Материализованная коллекция явно называется списком; независимо обрабатываемые элементы называются в единственном числе.
- Создающий и потребляющий шаги используют одно и то же точное название.
- Каждое название записывается отдельно и выделяется как код.

## Артефакты

| Артефакт | Описание |
|---|---|
| `Корень проекта` | Каталог, относительно которого выполняется операция. |
| `Правила структуры проекта` | Правила обнаружения, классификации и размещения YAML и внешних файлов проекта. |
| `Список файлов проекта` | Найденные YAML и внешние файлы проекта с их ролями и правилами. |
| `Worker список YAML-файлов` | YAML-файлы, назначенные одному worker для локальной обработки. |
| `Worker данные YAML` | Назначенные worker YAML-файлы с YAML-данными и синтаксическими диагностиками без хранения исходного текста. |
| `Worker индекс метаданных` | Индекс метаданных, собранный worker из назначенных ему YAML-файлов. |
| `Worker индекс зависимостей` | Индекс ссылок, DataPath и других зависимостей, собранный worker или назначенный worker после распределения глобального индекса. |
| `Глобальный индекс метаданных` | Объединённый индекс метаданных всех YAML-файлов проекта, переданный каждому worker. |
| `Глобальный индекс зависимостей` | Временный объединённый индекс ссылок, DataPath и других зависимостей всех YAML-файлов до распределения между worker. |
| `Привязка к базе 1С` | Локальный идентификатор базы и ссылка на настройки подключения; секреты в файл индекса конфигурации не входят. |
| `Подключение к 1С` | Установленное через SSH подключение к базе 1С в агентском режиме. |
| `Файл индекса конфигурации` | Единый двоичный файл с хэшами файлов проекта и идентификаторами объектов и вложенных элементов 1С для одной привязки к базе. |
| `Данные файла индекса конфигурации` | Разобранное в памяти содержимое файла индекса конфигурации; отдельным файлом не хранится. |
| `Хэши файлов проекта` | Пути и хэши всех описанных правилами YAML и внешних файлов проекта. |
| `Список изменений проекта` | Добавленные, изменённые и удалённые файлы, определённые сравнением текущих хэшей с файлом индекса конфигурации. |
| `Ожидаемая версия конфигурации` | Версия конфигурации, зафиксированная перед импортом либо прочитанная из файла индекса конфигурации. |
| `Подтверждённая версия конфигурации` | Версия конфигурации, подтверждённая 1С после проверки или успешного применения изменений. |
| `Корень XML-выгрузки` | Каталог исходной XML-выгрузки конфигурации. |
| `Список путей XML-файлов выгрузки` | Пути XML-файлов, найденных в исходной XML-выгрузке. |
| `Описание XML-файла выгрузки` | Путь XML-файла, его роль и правила соответствующего объекта метаданных. |
| `Описание внешнего файла XML-выгрузки` | Путь внешнего файла XML-выгрузки, его роль и правила соответствующего свойства метаданных. |
| `XML-текст` | Исходное или подготовленное текстовое содержимое XML-файла. |
| `XML-данные` | Разобранные структурированные данные XML-файла. |
| `Идентификаторы и reference-данные конфигурации` | Извлечённые из XML идентификаторы объектов и вложенных элементов 1С и минимальные reference-данные, необходимые для экспорта в конфигурацию. |
| `JSON Schema` | Схема допустимой структуры разобранного YAML-файла. |
| `Диагностики YAML-схемы` | Ошибки соответствия worker данных YAML своей JSON Schema. |
| `rules.ts` | Декларативные правила преобразования metadata-модели. |
| `Metadata-модель` | Внутреннее представление объекта метаданных. |
| `ValidationPendingCheck` | Отложенная проверка metadata-модели, сформированная правилами и выполняемая после построения индексов. |
| `Диагностики зависимостей метаданных` | Ошибки ссылок на метаданные и путей к данным. |
| `Целевой путь` | Путь, по которому должен быть записан или перемещён файл. |
| `YAML-файл` | YAML-файл, записанный на диск. |
| `Внешний файл проекта` | Модуль, бинарный или другой внешний файл, записанный в проект. |
| `Исходный путь` | Текущий путь переименовываемого файла или каталога. |
| `Переименованный путь` | Новый путь переименованного файла или каталога. |

## Шаги

| Шаг | Описание | Потребляет | Создаёт | Worker |
|---|---|---|---|---:|
| Подключение к 1С | Устанавливает через SSH подключение к выбранной базе 1С в агентском режиме. | `Привязка к базе 1С` | `Подключение к 1С` |  |
| Подготовка импорта конфигурации | Выгружает конфигурацию из 1С, разбирает XML, копирует внешние файлы в проект и извлекает данные для файла индекса конфигурации. | `Подключение к 1С`<br>`rules.ts`<br>`Целевой путь` | `XML-данные`<br>`Внешний файл проекта`<br>`Идентификаторы и reference-данные конфигурации`<br>`Ожидаемая версия конфигурации` | частично |
| Подготовка синхронизации конфигурации | Читает файл индекса конфигурации, определяет изменённые файлы проекта и подготавливает XML для применения. | `Файл индекса конфигурации`<br>`Хэши файлов проекта`<br>`Metadata-модель`<br>`rules.ts` | `Данные файла индекса конфигурации`<br>`Ожидаемая версия конфигурации`<br>`Список изменений проекта`<br>`XML-данные`<br>`XML-текст` | частично |
| Чтение проекта | Находит, распределяет и разбирает YAML-файлы, затем строит глобальный индекс метаданных и worker индексы зависимостей. | `Корень проекта`<br>`Правила структуры проекта` | `Worker данные YAML`<br>`Глобальный индекс метаданных`<br>`Worker индекс зависимостей` | частично |
| Проверка по схеме | Проверяет worker данные YAML по JSON Schema. | `Worker данные YAML`<br>`JSON Schema` | `Диагностики YAML-схемы` | ✓ |
| Построение модели | Преобразует worker данные YAML или XML-данные в metadata-модель по rules.ts; validation worker этот шаг не выполняет. | `Worker данные YAML`<br>`XML-данные`<br>`rules.ts` | `Metadata-модель` | ✓ |
| Проверка зависимостей | Проверяет YAML-first индексы, отложенные проверки и DataPath по глобальному индексу метаданных. | `Worker данные YAML`<br>`Глобальный индекс метаданных`<br>`Worker индекс зависимостей`<br>`ValidationPendingCheck` | `Диагностики зависимостей метаданных` | ✓ |
| Вычисление хэшей файлов проекта | Находит описанные правилами YAML и внешние файлы проекта и вычисляет хэш каждого файла. | `Корень проекта`<br>`Правила структуры проекта` | `Хэши файлов проекта` |  |
| Проверка соответствия версии конфигурации | Проверяет, что текущая версия конфигурации совпадает с ожидаемой. | `Подключение к 1С`<br>`Ожидаемая версия конфигурации` | `Подтверждённая версия конфигурации` |  |
| Применение изменений в 1С | Передаёт через подключение только изменённые XML и внешние файлы по путям из списка изменений, не создавая локальную XML-выгрузку, и получает новую версию конфигурации после успешного применения всего набора. | `Подключение к 1С`<br>`Подтверждённая версия конфигурации`<br>`Список изменений проекта`<br>`XML-текст` | `Подтверждённая версия конфигурации` |  |
| Формирование данных файла индекса конфигурации | После успешной операции с 1С и записи файлов проекта формирует полное новое содержимое единого файла. | Запись файла индекса конфигурации | Проверяет новое содержимое и атомарно заменяет единый двоичный файл выбранной привязки. | `Данные файла индекса конфигурации`<br>`Привязка к базе 1С` | `Файл индекса конфигурации` |  |
| Запись YAML | Сериализует и записывает metadata-модель в YAML-файл. | `Metadata-модель`<br>`rules.ts`<br>`Целевой путь` | `YAML-файл` |  |
| Переименование путей | Переименовывает файл или каталог согласно плану операции. | `Исходный путь`<br>`Целевой путь` | `Переименованный путь` |  |
