# Итоговые исправления по review

Статус: **DONE**

## Что исправлено

1. Полная синхронизация расширения в XML запрещена на обеих публичных
   границах: core и MCP возвращают
   `full_xml_sync_component_not_supported` до чтения Проекта, создания
   XML-каталога и изменения снимка.
2. MCP-подтверждение импорта больше не показывает `cf`, если компонент
   определяет `auto`.
3. Холодный снимок базовой `cf` собирается fact-only командами в уже
   подготовленных физических YAML-worker. Worker сам читает и разбирает
   файл, извлекает индексные факты без схем, валидаторов и второго прохода;
   ошибки чтения, синтаксиса и извлечения прерывают импорт.
4. Индекс конфигурации переведён на формат 2.0. В нём обязательно хранятся
   локальные reference/owner-индексы и локальные зависимости компонента.
   Фрагментный codec переносит этот вклад через worker, детерминированно
   объединяя и сортируя зависимости.
5. XML-import собирает локальный validation-вклад во время первого
   XML → YAML обхода, без повторного чтения созданного YAML. Для `Picture`
   сохраняются только явно квалифицированные ссылки
   `ОбщаяКартинка.*`; стандартные картинки не становятся зависимостями.
6. При импорте `cfe` второй проход использует слоёный снимок
   `local + base`, но на диск записываются только локальные данные
   расширения. Базовые владельцы и индексы в снимок `cfe` не протекают.
7. Полная XML-синхронизация `cf` сохраняет существующий локальный вклад
   индекса 2.0 без изменений.
8. Fact-only режим продолжает собирать валидные ссылки при отключённых
   диагностиках. Договор `metadata/project` при этом не импортирует
   конкретные реализации metadata: типы выводятся из нейтрального
   `LocalYamlFact`.
