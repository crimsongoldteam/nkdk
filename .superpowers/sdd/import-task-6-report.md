# Task 6: worker pool, барьеры и аварийное завершение

## Итог

- Добавлен `createXmlImportWorkerPool`: задания один раз распределяются по кругу, а каждый активный раздел закреплён за отдельным однопоточным Piscina worker на оба прохода.
- `initialize`, `firstPass` и `secondPass` отправляются через `pool.run` даже при `concurrency: 1`; пустые разделы не создают физических worker.
- Первый проход ожидает все активные worker, объединяет диагностики и owner facts, проверяет и объединяет переданные буферы фрагментов configuration index.
- Второй проход блокируется после любой error-диагностики первого прохода и агрегирует диагностики, предупреждения и файлы только после общего барьера.
- Отказ `pool.run` считается аварией: все созданные worker уничтожаются один раз, задания не повторяются, временные данные не удаляются.
- Core и MCP теперь собирают `metadata/importFromXml/worker.ts` в отдельный `importFromXmlWorker.js`.
