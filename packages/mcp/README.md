# Работа с конфигурацией 1С в YAML

Инструмент преобразует XML-выгрузку конфигурации 1С в набор YAML-файлов и обратно.

## Идея

Проект создаёт читаемый и однозначный YAML-формат для работы с конфигурацией 1С, в первую очередь для ИИ-агентов.

Для YAML-файлов доступны схемы, контекстные подсказки и валидация структуры, ссылок и связей конфигурации.

> [!WARNING]
> Проект находится на ранней стадии разработки.

Новости и заметки по проекту публикуются в [Telegram-канале](https://t.me/overlay1c).

## Что даёт

- понятное YAML-представление конфигурации;
- двустороннее преобразование между XML-выгрузкой 1С и YAML-файлами;
- схемы YAML-файлов для ИИ-агента;
- проверку структуры и ссылок в YAML-проекте;

## Совместимость

Поддерживаемая версия платформы: `8.3.27`.

Тестирование выполнялось на XML-выгрузках конфигураций:

- Бухгалтерия предприятия КОРП, редакция 3.0, версия `3.0.193.19`;
- Управление торговлей, редакция 11, версия `11.5.25.109`;
- 1С:ERP. Управление холдингом, версия `3.2.11.3`;
- Документооборот государственного учреждения, редакция 3.0, версия `3.0.19.30`;
- Управление нашей фирмой, редакция 3.0, версия `3.0.12.261`;
- Тестовая конфигурация со всеми элементами и объектами.

## Подключение MCP-сервера

NKDK подключается к агенту как MCP-сервер из npm.

Укажите агенту команду запуска сервера:

```json
{
  "mcpServers": {
    "nkdk": {
      "command": "npx",
      "args": ["-y", "@nkdk/mcp"]
    }
  }
}
```

После подключения агенту доступны MCP tools:

| Tool                              | Назначение                                                                  | Запись файлов                |
| --------------------------------- | --------------------------------------------------------------------------- | ---------------------------- |
| `nkdk.get_schema`                 | Получить схему по `metadataRef` или `structurePath` компонента.             | Нет                          |
| `nkdk.describe_project_structure` | Узнать структуру выбранного компонента YAML-проекта.                        | Нет                          |
| `nkdk.validate_project`           | Проверить компонент `cf` на ошибки.                                         | Нет                          |
| `nkdk.import_from_xml`            | Импортировать XML-выгрузку одного компонента в пустой компонент проекта.    | Только при `allowWrite=true` |
| `nkdk.sync_to_xml`                | Выгрузить один YAML-компонент в заданный XML-каталог.                       | Только при `allowWrite=true` |
| `nkdk.init_sync_state`            | Создать `.nkdk-sync.yaml` для выбранного компонента.                        | Только при `allowWrite=true` |
| `nkdk.rename_item`                | Переименовать объект или реквизит с сохранением внутреннего идентификатора. | Только при `allowWrite=true` |
| `nkdk.find_references`            | Найти внешние ссылки на объект или реквизит в выбранном компоненте.         | Нет                          |

MCP tools принимают `projectDir` как корень NKDK-проекта. Папка `.nkdk` находится только в этом корне, а компоненты лежат в `cf`, `cfe/<Имя>`, `erf/<Имя>` и `epf/<Имя>`; если `componentPath` не указан, используется `cf`.

`nkdk.import_from_xml` и `nkdk.sync_to_xml` работают с одним компонентом за вызов и принимают готовый `xmlDir`. MCP-сервер не подключается к 1С, не импортирует все компоненты проекта за один вызов и не вычисляет `xmlDir` как `xmlRootDir/componentPath`.

### Локальная разработка MCP-сервера

Для проверки изменений из локального клона:

```sh
git clone https://github.com/crimsongoldteam/nkdk.git
cd nkdk
pnpm install
pnpm --filter @nkdk/mcp dev
```

В конфигурации агента для локальной разработки можно указывать абсолютный путь к `packages/mcp/bin/nkdk-mcp`.
Для обычного использования предпочтителен npm-вариант через `npx`.
