# Синхронизация конфигурации в XML

Скилл помогает экспортировать конечную YAML-конфигурацию 1С в XML-выгрузку. Команда `sync` пишет файлы в XML-каталог, поэтому без явного пути назначения синхронизацию не запускай.

## Входные данные

Если пользователь не дал всё сразу, выясняй по одному пункту и сначала исследуй проект:

1. Каталог YAML-проекта, откуда читать конфигурацию.
2. Каталог XML-выгрузки, куда писать результат.
3. Каталог XML-reference, откуда читать reference-данные; если не указан, используй XML-каталог записи как reference и явно проговори это.

Если YAML-каталог не указан, остановись и попроси путь к нему. Не подставляй каталог по догадке.
Если XML-каталог записи не указан, остановись и попроси путь к нему: `sync` может перезаписать важные файлы.

## Проверка YAML-каталога

Перед синхронизацией проверь, что путь существует и похож на YAML-проект конфигурации:

- внутри есть `Конфигурация.yaml` или каталоги объектов (`Справочник`, `Документ`, `Перечисление`, `Обработка` и т.п.);
- YAML-файлы доступны для чтения;
- если рядом есть git-репозиторий, посмотри `git status --short` и покажи незавершённые изменения пользователю.

Если каталог не похож на YAML-проект, покажи найденные верхние файлы/каталоги и спроси корректный путь.

## Проверка XML-каталога

Перед записью проверь XML-каталог:

- если каталог существует и не пустой, предупреди, что `sync` обновит XML-файлы и удалит лишние поддержанные файлы внутри известных каталогов метаданных;
- если рядом есть git-репозиторий, посмотри `git status --short` и не запускай `sync` при незавершённых правках без явного подтверждения;
- если каталог не существует, можно дать `sync` создать его, но сначала явно проговори абсолютный путь.

Для `reference` используй существующий XML-каталог. Если отдельный reference не указан, передавай XML-каталог записи:

```bash
nkdk sync "<yaml-dir>" "<xml-dir>" --reference "<xml-dir>"
```

## Команда синхронизации

Предпочитай установленную команду:

```bash
nkdk sync "<yaml-dir>" "<xml-dir>" --reference "<reference-xml-dir>"
```

Если `nkdk` недоступен, запускай CLI из workspace проекта:

```bash
pnpm --filter @nakidka/cli dev sync "<yaml-dir>" "<xml-dir>" --reference "<reference-xml-dir>"
```

Если целевой YAML-каталог не является pnpm workspace, всё равно выполняй `pnpm` из workspace `nakidka-core`, а пути `yaml-dir`, `xml-dir` и `reference-xml-dir` передавай абсолютными.

## После синхронизации

1. Проверь вывод команды: строка `Готово: <N> успешно, 0 с ошибкой` означает успешную синхронизацию.
2. Если есть ошибки, перечисли проблемные объекты из stderr и не называй экспорт завершённым.
3. Для XML-каталога в git-репозитории покажи `git status --short`, чтобы пользователь видел результат.
4. Если XML-каталог не под git, кратко покажи изменённые верхние каталоги или ключевые созданные файлы.

## Важные ограничения

- Не запускай `sync` без явного XML-каталога записи.
- Не запускай `sync` поверх грязного XML-репозитория без подтверждения пользователя.
- Не делай `git stash`, `git restore`, `git clean` или удаление файлов сам, если пользователь явно этого не просил.
- Не используй исходную XML-выгрузку как временный проверочный каталог без явного согласия пользователя.
