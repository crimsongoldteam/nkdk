# Импорт конфигурации из XML

Скилл помогает импортировать конечную конфигурацию 1С из XML-выгрузки в YAML-проект. Главный вход — каталог XML-выгрузки; без него импорт не запускается.

## Входные данные

Если пользователь не дал всё сразу, выясняй по одному пункту и сначала исследуй проект:

1. Каталог XML-выгрузки 1С.
2. Каталог YAML-проекта, куда писать результат; если не указан, используй текущий каталог.
3. Нужно ли импортировать в пустой каталог или обновлять существующий YAML-проект.

Если XML-каталог не указан, остановись и попроси путь к нему. Не подставляй каталог по догадке.
Если YAML-каталог не указан, явно проговори, что импорт пойдёт в текущий каталог, и покажи его абсолютный путь.

## Проверка XML-каталога

Перед импортом проверь, что путь существует и похож на XML-выгрузку конфигурации:

- внутри есть один или несколько каталогов верхнеуровневых объектов (`Catalogs`, `Documents`, `Enums`, `CommonModules`, `Reports` и т.п.);
- либо есть `Configuration.xml`;
- XML-файлы доступны для чтения.

Если каталог не похож на XML-выгрузку, покажи найденные верхние файлы/каталоги и спроси корректный путь.

## Подготовка YAML-каталога

Если YAML-каталог уже существует, перед импортом проверь его содержимое:

- если он не пустой, предупреди, что импорт может обновить файлы;
- не удаляй существующие файлы сам;
- если рядом есть git-репозиторий, посмотри `git status --short` и не перезаписывай чужие незавершённые правки без явного подтверждения.

Если YAML-каталога нет, можно создать его родительским инструментом импорта; отдельно создавать пустую структуру не нужно.

## Команда импорта

Предпочитай установленную команду:

```bash
nkdk import "<xml-dir>" "<yaml-dir>"
```

Если пользователь не указал YAML-каталог, передавай текущий каталог:

```bash
nkdk import "<xml-dir>" "."
```

Если `nkdk` недоступен, запускай CLI из workspace проекта:

```bash
pnpm --filter @nakidka/cli dev import "<xml-dir>" "<yaml-dir>"
```

Если целевой YAML-каталог не является pnpm workspace, всё равно выполняй `pnpm` из workspace `nakidka-core`, а пути `xml-dir` и `yaml-dir` передавай абсолютными.

## После импорта

1. Проверь вывод команды: строка `Готово: <N> успешно, 0 с ошибкой` означает успешный импорт.
2. Если есть ошибки, перечисли проблемные объекты из stderr и не называй импорт завершённым.
3. Покажи кратко, какие YAML-каталоги появились или изменились.
4. Для существующего YAML-проекта проверь `git status --short`, чтобы пользователь видел результат.

## Проверка результата

После успешного импорта предложи ближайшую безопасную проверку:

```bash
pnpm --filter @nakidka/cli dev sync "<yaml-dir>" "<xml-check-dir>" --reference "<xml-dir>"
```

Не запускай `sync`, если пользователь не дал отдельный каталог `xml-check-dir`: команда пишет XML и не должна перезаписывать исходную выгрузку без явного согласия.
