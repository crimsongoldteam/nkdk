# Nakidka Core — контекст проекта

## Назначение

Редактор конфигурации **1С:Предприятие** в формате **YAML**: расширение VS Code с проверками и автодополнением. Обмен с конфигуратором — через **XML**. Формы описываются отдельным языком (NKDK); предпросмотр — через клиент 1С и обработку.

## Импорт и экспорт (пользовательский поток)

Рабочий цикл в IDE — не путать с функциями `from*` / `to*` в коде ядра (см. ниже).

| Действие                    | Как в VS Code                                        | Смысл                                                                                           |
| --------------------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **Импорт**                  | Команда **«nkdk: Импорт конфигурации из XML»** (F1)  | Выгруженная из конфигуратора папка с **XML** преобразуется в проект **YAML** в рабочей области. |
| **Экспорт / синхронизация** | Команда **«nkdk: Синхронизация конфигурации с XML»** | Изменения в YAML записываются обратно в **XML** для загрузки в конфигуратор.                    |

Перед импортом конфигурацию нужно выгрузить из конфигуратора в XML. Подробности установки и сценария — в корневом `README.md`.

## Сериализация в коде ядра (импорт/экспорт на уровне типов)

Имена файлов отражают **направление данных** относительно TypeScript:

| Файл          | Направление                                            |
| ------------- | ------------------------------------------------------ |
| `fromXML.ts`  | XML → внутреннее представление (разбор, «вход» из XML) |
| `toXML.ts`    | внутреннее представление → XML (запись, «выход» в XML) |
| `fromYAML.ts` | YAML → внутреннее представление                        |
| `toYAML.ts`   | внутреннее представление → YAML                        |

Фрагменты **системы компоновки данных (DCS)** в XML, которые не совпадают по обёртке с обычным объектом метаданных, разбираются и собираются отдельными парами **`fromDcsXML.ts` / `toDcsXML.ts`** (не путать с общим `fromXML`/`toXML`).

Типичный набор для правила метаданных:

1. `types.ts` — типы
2. `fromXML.ts` / `toXML.ts` — обмен с XML (или `fromDcsXML` / `toDcsXML` для DCS)
3. `fromYAML.ts` / `toYAML.ts` — обмен с YAML

Для объектов с большим числом однотипных свойств используется слой **правил** в `rules.ts` (свойства описываются через `properties`). Подробно: [скил `rules/`](../rules/SKILL.md) (в Cursor: `nakidka-core-rules`).
