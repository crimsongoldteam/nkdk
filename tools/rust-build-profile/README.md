# Измерение и ограниченная параллельная сборка Rust

Из корня рабочего дерева:

```sh
python3 tools/rust-build-profile/build.py build
python3 tools/rust-build-profile/build.py test --test facts --test resources -- --test-threads=1
```

Сборщик выбирает зависимости рабочего фасада по Cargo metadata. За один шаг
собираются максимум два пакета деклараций; четыре разрешения Cargo позволяют
компилятору использовать свободные CPU для LLVM. Затем собирается приложение.
Команды используют закреплённый Rust 1.98.1, `--offline` и `--locked`.
Обычный профиль разработки сохраняет свой уровень оптимизации; генератор
деклараций и его зависимости оптимизируются отдельно как build dependencies.

Параметры профиля, target и features через этот сборщик пока не поддерживаются:
они отклоняются, чтобы предварительная сборка и приложение не использовали
разные настройки. Для release используйте обычный Cargo. В release парсеры
сохраняют статическую специализацию обработчиков; в профилях с
`debug_assertions` большой парсер компилируется один раз. Семантика общая.

Для холодного измерения укажите **новый пустой** target и отдельный отчёт:

```sh
python3 tools/rust-build-profile/build.py \
  --target-dir rust/target/cold-measurement \
  --output rust/target/build-reports/cold-measurement \
  build
```

Само указание `--target-dir` не очищает каталог. Отчёт нельзя называть холодным,
если каталог уже содержит результаты. Сборщик ничего не удаляет; существующий
каталог отчёта также не перезаписывается.

`result.json` содержит команды и длительность шагов; `rustc.jsonl` —
процессорное время, длительность и пик памяти каждого процесса rustc;
`generation.jsonl` — длительность и объём генерации. В `OUT_DIR` пакетов
сохраняется `generation-sizes.tsv` с размерами отдельных механизмов.
Профилирующая обёртка передаёт дочернему rustc дескрипторы Cargo jobserver.
Итоговый `compiler_resources` содержит число одновременно работающих
компиляторов и верхнюю границу их совместного RSS: для каждого перекрывающегося
интервала складываются индивидуальные пики. Это консервативная оценка,
а не непрерывное измерение фактической памяти операционной системы.

Проверки самого сборщика:

```sh
python3 -m unittest discover -s tools/rust-build-profile -p test_build.py
```

## Параллельный анализ Rust

Отдельный режим разработки использует закреплённый `nightly-2026-10-02`:

```sh
rustup toolchain install nightly-2026-10-02 --profile minimal
pnpm build:rust:fast
pnpm test:rust:app:fast
```

Сборщик передаёт `-Zthreads=4`, ограничивает Cargo тремя заданиями и
использует отдельный target, чтобы не смешивать результаты с Rust 1.98.1.
В этом режиме Cargo получает все пакеты рабочего фасада одним шагом:
следующий пакет начинает собираться сразу после освобождения задания,
без ожидания более медленного соседа. Число одновременно работающих
компиляторов ограничено; перед увеличением требуется новый замер памяти.
`RUSTC_BOOTSTRAP` не включается; конфликтующие флаги компилятора отклоняются.
Обычные команды `build:rust` и `test:rust:app` сохраняют стабильный компилятор.
Рабочий release также остаётся на Rust 1.98.1.

Этот режим ускоряет проверку типов и заимствований внутри одного процесса;
это отдельный параллелизм от числа пакетов Cargo. Он пока доступен через
nightly-флаг — см. [руководство компилятора Rust](https://rustc-dev-guide.rust-lang.org/parallel-rustc.html).
