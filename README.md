# Работа с конфигурацией 1С в YAML

Инструмент преобразует XML-выгрузку конфигурации 1С в набор YAML-файлов и обратно.

## Идея

Проект создаёт читаемый и однозначный YAML-формат для работы с конфигурацией 1С, в первую очередь для ИИ-агентов.

Для YAML-файлов доступны схемы, контекстные подсказки и валидация структуры, ссылок и связей конфигурации.

> [!WARNING]
> Проект находится на ранней стадии разработки.

Новости и заметки по проекту публикуются в [Telegram-канале](https://t.me/overlay1c).

## Что даёт

- понятное YAML-представление конфигурации;
- двустороннее преобразование между XML-выгрузкой 1С и YAML-файлами;
- схемы YAML-файлов для ИИ-агента;
- проверку структуры и ссылок в YAML-проекте;

## Совместимость

Поддерживаемая версия платформы: `8.3.27`.

Тестирование выполнялось на XML-выгрузках конфигураций:

- Бухгалтерия предприятия КОРП, редакция 3.0, версия `3.0.193.19`;
- Управление торговлей, редакция 11, версия `11.5.25.109`;
- 1С:ERP. Управление холдингом, версия `3.2.11.3`;
- Документооборот государственного учреждения, редакция 3.0, версия `3.0.19.30`;
- Управление нашей фирмой, редакция 3.0, версия `3.0.12.261`;
- Тестовая конфигурация со всеми элементами и объектами.

## Подключение MCP-сервера

Сервер поддерживает modern MCP `2026-07-28` и legacy-версии MCP, доступные в SDK v2, включая используемую Codex версию `2025-06-18`. Клиент использует штатный handshake своей эпохи — `server/discover` или `initialize`; отдельная настройка сервера не требуется.

Укажите агенту команду запуска сервера:

```json
{
  "mcpServers": {
    "nkdk": {
      "command": "npx",
      "args": ["-y", "@nkdk/mcp"]
    }
  }
}
```

Без параметров сервер, как и раньше, работает через stdio.

Для локального Streamable HTTP запустите:

```sh
npx -y @nkdk/mcp --http --port 3000
```

Endpoint будет доступен по адресу `http://127.0.0.1:3000/mcp`. Он слушает только loopback-интерфейс и принимает локальные `Host`/`Origin`.

> HTTP-режим не имеет авторизации и TLS. Не публикуйте endpoint во внешнюю сеть и не размещайте его за reverse proxy без отдельного защищённого контура.

После подключения агенту доступны MCP tools:

| Tool                                  | Назначение                                                                  | Запись файлов                |
| ------------------------------------- | --------------------------------------------------------------------------- | ---------------------------- |
| `nkdk.get_schema`                     | Получить схему по `metadataRef` или `structurePath` компонента.             | Нет                          |
| `nkdk.describe_project_structure`     | Узнать структуру выбранного компонента YAML-проекта.                        | Нет                          |
| `nkdk.list_infobases`                 | Получить дерево баз из личного и общих списков 1С.                          | Нет                          |
| `nkdk.validate_project`               | Проверить компонент `cf` на ошибки.                                         | Нет                          |
| `nkdk.import_from_xml`                | Импортировать XML-выгрузку одного компонента в пустой компонент проекта.    | Только при `allowWrite=true` |
| `nkdk.import_from_infobase`           | Импортировать основную конфигурацию базы 1С в пустой `cf`.                  | Только при `allowWrite=true` |
| `nkdk.sync_to_infobase`               | Частично загрузить изменения `cf` или `cfe/<Имя>` в Конфигуратор.           | Только при `allowWrite=true` |
| `nkdk.close_platform_connection`      | Закрыть сохранённое соединение проекта с платформой.                        | Нет                          |
| `nkdk.close_all_platform_connections` | Закрыть все сохранённые соединения с платформой.                            | Нет                          |
| `nkdk.sync_to_xml`                    | Выгрузить один YAML-компонент в заданный XML-каталог.                       | Только при `allowWrite=true` |
| `nkdk.init_sync_state`                | Создать `.nkdk-sync.yaml` для выбранного компонента.                        | Только при `allowWrite=true` |
| `nkdk.rename_item`                    | Переименовать объект или реквизит с сохранением внутреннего идентификатора. | Только при `allowWrite=true` |
| `nkdk.find_references`                | Найти внешние ссылки на объект или реквизит в выбранном компоненте.         | Нет                          |

MCP tools принимают `projectDir` как корень NKDK-проекта. Папка `.nkdk` находится только в этом корне, а компоненты лежат в `cf`, `cfe/<Имя>`, `erf/<Имя>` и `epf/<Имя>`; если `componentPath` не указан, используется `cf`.

`nkdk.import_from_xml` и `nkdk.sync_to_xml` работают с одним компонентом за вызов и принимают готовый `xmlDir`. Эти операции не подключаются к 1С, не обрабатывают все компоненты проекта за один вызов и не вычисляют `xmlDir` как `xmlRootDir/componentPath`.

### Импорт из информационной базы 1С

`nkdk.import_from_infobase` поддерживает платформу `8.3.27` и импортирует `cf` либо одно расширение `cfe/<Имя>` в отсутствующий или пустой компонент. Агентный и автономный режимы работают с файловыми и клиент-серверными базами; для клиент-серверного автономного режима нужны параметры СУБД в `database`.

`nkdk.sync_to_infobase` передаёт ZIP только с изменёнными файлами и поддерживает основную конфигурацию `cf` и расширения `cfe/<Имя>`. Точный состав загрузки всегда ограничивается через `load.lst`; ключ `--partial` используется только для пакета, состоящего исключительно из модулей `.bsl`. После загрузки операция по умолчанию обновляет конфигурацию базы данных; `updateDatabaseConfiguration=false` оставляет изменения только в сохранённой конфигурации. Автономная частичная загрузка пока доступна только для файловых баз; для клиент-серверной базы следует использовать режим `designer-agent`. Повторная передача запрещена, если результат предыдущей команды неизвестен.

Параметры последнего успешного подключения сохраняются в `.nkdk/project.yaml`:

```yaml
infobase:
  connectionString: 'Srvr="cluster";Ref="production";'
  user: Администратор
  password: secret
  sessionIdleTimeout: 900
  database:
    dbms: PostgreSQL
    server: db.example.local
    name: production
    user: dbuser
    password: dbsecret
  operations:
    import:
      mode: standalone-server
      unresolvedReferences: include
```

`database` обязателен только для сочетания `Srvr`/`Ref` и `operations.import.mode: standalone-server`; поддерживаются `MSSQLServer`, `PostgreSQL`, `IBMDB2` и `OracleDatabase`. Для `File` параметры СУБД запрещены. `sessionIdleTimeout` задаётся целым числом секунд. Учётные данные информационной базы и пароль СУБД необязательны там, где их допускает платформа; пароли хранятся открытым текстом, поэтому содержимое `.nkdk` нельзя добавлять в git. На Unix файл настроек записывается с правами `0600`.

Агент использует отдельный проверяемый SSH-ключ. В режиме `ibcmd` платформа 8.3.27 принимает пароли информационной базы и СУБД только как параметры процесса, поэтому во время подготовки и выгрузки они могут быть видны локальному пользователю с правом просмотра аргументов чужих процессов.

Сеанс переиспользуется до истечения таймаута простоя или явного вызова `nkdk.close_platform_connection` / `nkdk.close_all_platform_connections`. Для агента это живое SSH-соединение; для автономного режима — запущенный NKDK процесс `ibsrv` и подготовленный приватный `config.yaml` (`0600` на Unix), который удаляется при закрытии. MCP завершает только процессы 1С, которые запустил сам. При ошибке импорта временная XML-выгрузка сохраняется, а её путь возвращается в `temporaryDirectory`.

Сама выгрузка конфигурации не ограничена по времени. При отмене MCP-запроса
nkdk останавливает только запущенный им процесс 1С: сначала отправляет
`SIGTERM`, а через 5 секунд при необходимости — `SIGKILL`. Внешний MCP-клиент
должен разрешать длительные вызовы; локальный helper проекта ожидает ответ
практически без ограничения времени.

### Локальная разработка MCP-сервера

Для проверки изменений из локального клона:

```sh
git clone https://github.com/crimsongoldteam/nkdk.git
cd nkdk
pnpm install
pnpm --filter @nkdk/mcp dev
```

В конфигурации агента для локальной разработки можно указывать абсолютный путь к `packages/mcp/bin/nkdk-mcp`.
Для обычного использования предпочтителен npm-вариант через `npx`.
